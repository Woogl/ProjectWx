# 사용자 결정

2026-09-26 첫 실제 Codex 처리에서 무관한 lint 경고가 완료를 막고 AI의 완료 문장이 구현 계획 절로 들어간 뒤, AI가 "완료로 확정" 버튼을 제안했다. 사용자는 이를 거절하고 "이 과정에서 문제가 없도록 워크플로우를 직관적으로 다듬어야한다고 생각합니다."라고 했다. AI가 원인과 다듬는 방향을 제안하자 "AI가 무관한지 판단하는게 많은 실수를 일으킬까요?"라고 물었고, 답을 들은 뒤 "네."로 승인했다.

# 원인

- AI 결과의 여러 칸(남은 확인 blockers, 검사 상태 checks, 구현 계획, 질문)이 모두 상태를 바꾸는 통로였다. AI가 한 칸만 잘못 채워도 상태가 틀어졌다.
- 완료가 사람의 판단 뒤 AI 정리 처리의 성공에 걸려 있었다.
- 여러 세션이 한 체크아웃을 동시에 고쳐 git diff·빌드·lint에 다른 작업의 변경이 섞인다. 작업별 변경 추적이 없어 AI가 관련 여부를 확실히 가를 수 없다. 첫 처리에서 AI는 관련 없음을 맞게 판단했지만, 지시가 범위 밖 문제를 blockers에 넣게 해 완료가 막혔다.

# 바뀐 규칙

- AI가 사람에게 넘기는 것은 질문(판단 필요, 선택지와 추천)·구현 계획(승인 필요)·테스트 체크리스트(테스트 필요) 셋뿐이다. 상태는 기록의 이 세 절에서만 정한다: 미답변 질문 → 질문 답변 필요, 미승인 계획 → 구현 승인 필요, 체크리스트 전부 통과 → 완료, 실패 행 → 실패 확인 필요, 나머지 → 사람 확인 필요. 셋 다 없으면 처리 결과 확인이다.
- 단계마다 AI 결과 칸을 제한한다(모두 요약 summary·근거 evidence 포함): 정하기 = 질문·계획, 구현 = 변경·질문·체크리스트, 수정 = 변경·질문·체크리스트, 추가 요청 = 변경·질문·계획·체크리스트, 정리 = 변경. CLI에 넘기는 JSON 스키마도 단계별로 만들고, 서버는 허용된 칸만 읽는다.
- 테스트 결과 전달: 실패가 있으면 AI 수정, 실패 없이 일부만 통과하면 AI 없이 기록만, 모두 통과하면 서버가 즉시 완료하고 이어서 AI 정리(Wiki 반영)를 맡긴다. 정리는 상태를 바꾸지 않고, 실패·중단해도 완료가 유지된다. AI 처리로 모든 항목이 통과해도 같은 정리가 이어진다.
- AI의 미실행·대기 항목은 사람 항목으로 넘긴다(근거 "AI가 실행하지 못함: …"). 사람 항목이 하나도 없으면 결과 확인 항목을 더해, 완료는 항상 사람의 확인으로 끝난다.
- 구현 중 판단이 필요하면 AI는 질문으로 묻는다. 답하면 정하기로 돌아가 새 계획과 승인을 거친다.
- 처리 중 기록이 바뀌면 기록 충돌로 두고 AI 결과를 반영하지 않는다(다음 행동: 최신 기록을 확인하고 다시 전달).
- 지시문에서 blockers·checks를 없앴다. 무관한 문제(다른 작업의 파일·변경, 관계없는 문서의 검사 경고)는 요약에 한 줄로만 알리고, 다른 작업의 변경 때문으로 보이는 실패는 고치지 않는다.
- 이력: 사람의 테스트 결과는 전달 즉시 "사용자 테스트 결과"로 남기고, AI 결과는 단계별 제목(AI 조사 결과·AI 구현 결과·AI 추가 요청 처리·AI 수정 결과·AI 완료 정리)으로 남긴다.
- 화면: 모두 통과한 작업은 완료 단계로 보이고 전달할 것이 없다. 전달 뒤 결과 기록·즉시 완료 안내를 보여주며 자동 새로고침은 안내를 덮지 않는다.
- 규칙 문서는 작업 절차(`.agents/workflow/process/index.md`) 한 장에만 적는다. 같은 날 AGENTS.md와 tasks 안내는 링크만 두도록 바뀌었다.

- 바뀐 흐름을 실제 AI 요청으로는 다시 돌리지 않았다.
