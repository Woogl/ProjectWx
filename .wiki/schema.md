# WX 프로젝트 용어와 근거 가이드

## State

사용자가 승인한 순정 구조 전환에 따라 작성했다. 사람 소유의 보조 가이드이며 순정의 필수 필드·분류·경로를 재정의하지 않는다.

## Entity Types

| 순정 분류 | WX에서 다루는 내용 |
|---|---|
| `topic` | 전투·AI·UI 등 시스템의 책임·경계·진입점 |
| `concept` | 피해 처리·그로기·자원 등 개별 기능과 계약 |
| `reference` | 개발 도구·Wiki 운영 등 참조 지식 |

모듈 이름(`WxCombat`, `WxAI` 등)은 제목·태그·본문의 탐색 정보로 유지한다. 같은 규칙의 상세 설명은 대표 문서 한 곳에 두고 관련 문서는 연결한다.

모듈 설명은 `.uproject`·`.uplugin`·`*.Build.cs`에서 실제 대상을 확인하고 공개 헤더·핵심 cpp로 책임·경계·진입점·권한·수명을 대조한다. WxCore·Config·기획 등 모듈 밖 근거도 확인하며, 단순 타입 목록 대신 기능과 계약을 설명한다.

## Relationship Verbs

- `implements`: 코드가 기획 요구를 구현함. 근거 없이 구현 완료로 표시하지 않는다.
- `depends-on`: 모듈·설정·에셋·런타임 계약에 의존함.
- `supports` / `contradicts`: 원자료가 주장을 지지하거나 충돌함.
- `supersedes`: 사람의 결정 또는 명시된 근거가 이전 설명을 대체함.

## Source Conventions

- 코드·기획·Workflow 근거는 실제 저장소 상대경로로 연결하고 버전·필요한 심볼·확인 범위를 남긴다. 수집·편찬·기사 간 링크 형식은 순정 플러그인 규약을 따른다.
- `raw/notes/*current*`는 현재 저장소의 선택된 계약·실행 경로를 조사한 기록이다. 파일별 SHA-256과 행 번호가 붙은 원문 발췌로 확인 범위를 남긴다. 전체 소스 결함 검토나 실행 증거가 아니며, 실제 정본은 기록에 연결된 코드·설정·기획이다. 기존 이관 자료는 2026-09-22 전체 재편찬에서 대체·정리했다.
- 날짜 필드 `created`·`updated`는 문서 작성·갱신 시점이다. `verified`는 순정 의미에 맞는 인간 확인 근거가 있을 때만 기록하며, 이관 날짜를 넣지 않는다.
- 과거 상태와 확인 범위를 새 검증 결과로 승격하지 않는다. 재편찬한 문서는 현재 확인 범위와 남은 미결정을 본문에 기록한다. 순정 `confidence`나 최신성 점수는 구현 완료·게임 동작 보증과 동일한 뜻이 아니다.
- 요구사항·구현 관찰·확정 결정·추론·미결정을 구분한다. 코드 정적 확인과 에셋 내부·빌드·실행·멀티플레이 검증을 구분한다. C++ 기본값이나 파일명만으로 Blueprint·DataTable·BT·StateTree 실제 설정을 단정하지 않는다.

## Boundaries

작업 상태·승인·확정본은 [Workflow](../.agents/workflow/index.md)에 유지한다. Wiki의 `inventory/`·`output/projects/`로 자동 이관하지 않는다. `inventory/`·`datasets/` 등 선택 계층은 실제 필요할 때 순정 명령으로 만든다.

프로젝트 내부 모듈의 README는 두지 않고 모듈 설명과 탐색은 Wiki로 통합한다. 루트 README는 프로젝트 안내와 Wiki 진입점으로 유지한다. 다이어그램은 이해에 도움이 될 때 작성하고 본문·근거의 조건과 순서를 따른다. 뷰어 표시 규칙은 지식의 검증 상태를 바꾸지 않는다.
