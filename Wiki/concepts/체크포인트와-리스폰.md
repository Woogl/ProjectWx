# 체크포인트와 리스폰

사망 후 부활, 적 리젠, 체크포인트 규칙을 모은 문서다.

## 기획

### 용어 (04-25)
- 리스폰·리젠: 적 같은 배치물이 체크포인트 상호작용 때 다시 생성되는 것이다.
- 부활: 플레이어가 가장 최근에 활성화한 체크포인트에서 다시 시작하는 것이다. 사망으로만 일어난다.
- `Respawn_System`은 '리스폰'을 부활과 리젠을 묶는 말로 쓴다.

### 부활과 리젠 (`Respawn_System`, 05-02)
- 리젠은 사망 후 부활할 때와 체크포인트에서 F를 눌렀을 때 일어나며, 대상과 유지 규칙이 같다.
- 부활 순서: HP 0 감지 → 페이드 아웃 → 마지막 체크포인트 기준 로드 → 일반 적 재배치 → 체크포인트로 이동 → HP·MP 전량 회복 → 페이드 인.
- 일반 적은 리젠한다. 네임드는 처치하면 영구 제거된다. 보스는 리젠하지 않지만 재도전하면 HP가 초기화된다.
- 유지되는 것: 장치 상태(문·엘리베이터), 네임드 처치, 상자 개봉, 체크포인트 활성화.
- 던전에 다시 들어올 때도 저장 데이터로 복원하고 일반 적은 재등장한다.

### 체크포인트 (`Object_Design`, 06-12)
- 비활성 상태로 배치되고 첫 상호작용 때 활성화된다. 사망하면 가장 최근에 상호작용한 체크포인트에서 부활한다.
- 화면 빛 ON/OFF로 상태를 구분한다(키오스크 레퍼런스). 활성 전에는 "체크포인트 활성화", 활성 후에는 "F — 휴식"이 뜬다.
- 휴식하면 HP·MP 전량 회복, 포션 충전, 일반 적 리젠이 일어나고 횟수 제한은 없다.
- 체크포인트는 번호 변수 대신 엔진 GUID로 식별한다(04-25).
- 세계관에서는 세이브 포인트가 공공 단말이다([세계관과 시나리오](세계관과-시나리오.md)).

## 구현
### 적 리젠
- 적은 `AWxSpawner`로 배치하고, 리젠 제외는 `bNeverRevive`(기본 false)로 정한다. 04-25 기획의 `bShouldRegen`(기본 true)과 반대 의미의 이름이다.
- `bNeverRevive`는 처치된 뒤의 리젠만 건너뛰고, 살아 있으면 다른 대상처럼 리셋된다. `SpawnMode`가 Manual인 스포너는 `RespawnAll`에서 빠진다.
- 처치 기록(`bIsKilled`)은 서버 런타임 값이라 셀이 스트림 아웃되면 사라진다.

### 체크포인트
- 07-05 'PlayerStart 기반' 결정과 달리 지금 체크포인트는 장치다(`BP_CheckPoint`·`ST_CheckPoint`, 상태 태그 `Device.CheckPoint.Unlit`·`Lit`·`Resting`). 08-22 장치 재편에서 자체 완결 장치로 분류됐다. Source에는 PlayerStart 참조가 없다.
- 휴식 때 `ST_CheckPoint`는 HP를 최대로 채우고(`UWxEffect_FullHP`), 포션을 충전하고(`RefillItemCharges`), 적을 리젠하고(`RespawnSpawners`), 위치를 저장한다(`SaveCheckpoint`). 기획과 달리 MP는 회복하지 않는다.
- `WxStateTreeTask_SaveCheckpoint`는 라이브 진입·서버 권위·플레이어 상호작용·Standalone일 때만 RespawnPoint 컴포넌트의 트랜스폼을 저장한다.

### 부활
- 부활(`UWxRespawnLibrary::RequestRespawn`)은 Standalone 전용이고, 사망 화면이 호출한다.
- 순서는 저장된 위치에서 새 폰 생성(저장이 없으면 엔진 `RestartPlayer`) → 옛 폰 파괴 → 포션 전량 충전 → HP·MP 최대 → 스트리밍 완료 대기 → `AWxSpawner::RespawnAll` → 사망 화면 닫기다.
- KillZ 아래로 떨어져도 폰을 파괴하지 않고 `Event.Death`로 같은 사망·부활 경로를 탄다(019324c8b).

### 저장
- 체크포인트 저장(`UWxCheckpointSaveGame`)은 `LevelPackage`와 `RespawnTransform`만 담고, 새 게임을 시작할 때 지운다. 프로젝트의 SaveGame은 이것 하나다.
- 기획의 장치 상태·네임드 처치·상자 개봉 유지와 재진입 복원은 디스크에 저장하지 않는다. 장치 복원은 세이브와 별개로 `UWxDeviceStateTreeComponent`가 한다([장치와 배치물](장치와-배치물.md)). 셀이 다시 로드되면 장치는 `InitialState`로, 스포너는 처치 기록 없이 처음 상태로 돌아간다. 09-01 세이브 제거로 세션 안의 스트리밍 영속도 없어진 결과다([게임 프레임워크 구조](게임-프레임워크-구조.md#결정)).

## 결정
- 2026-04-25 배치물을 스포너블과 기믹으로 나누고, 리젠·부활 용어와 GUID 식별을 정했다. (`system_design_feedback.md`)
- 2026-05-02 사망·부활 구현을 배치물·PC·적 작업 뒤로 미뤘다. (`meeting.md`)
- 2026-07-05 체크포인트를 기믹 기반에서 PlayerStart 기반으로 바꿨다. (07-05 회의)
- 2026-08-22 기믹을 장치 조립형으로 바꾸며 체크포인트를 자체 완결 장치로 분류했다. 지금 구현은 이쪽이다. (08-22 회의)
- 2026-09-01 세이브 모듈 WxSave를 삭제했다. 지운 범위와 이유, 다시 넣을 때의 방침은 [게임 프레임워크 구조](게임-프레임워크-구조.md#결정)에 있다. (커밋 b3f982b0d)
- 2026-09-25 체크포인트를 단일 SaveGame 슬롯으로 저장하게 했다. (커밋 b94ebbc84)

- 체크포인트 거점화(첫 상호작용 때 주변을 보여 주고 임시 월드맵을 띄움)를 07-31에 제안했지만, 07-26 검토의 '월드맵 없음'과 어긋나고 채택 여부가 없다.
