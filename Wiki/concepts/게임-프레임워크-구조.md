# 게임 프레임워크 구조

모듈 구성, 게임모드·컨트롤러·GameState의 구성, 프론트엔드 진입, 폰 초기화 시점, 세이브 범위를 모은 문서다.

## 구현

### 모듈
- 게임 코드는 런타임 모듈 `WxGame` 하나에 기능별 폴더로 있다: `AI`, `AbilitySystem`, `Animation`, `Character`, `Combat`, `Development`, `Device`, `Dialogue`, `FrontEnd`, `GameModes`, `Input`, `Interaction`, `Inventory`, `Minion`, `Player`, `Quest`, `Save`, `Spawner`, `System`, `Targeting`, `UI`, `Weapons`.
- 모듈 최상위에는 게임플레이 태그(`WxGameplayTags`)와 콜리전 채널(`WxCollisionChannels.h`)만 있다. `System/`에는 저작 도구용 로케이터 표시 헬퍼(`FWxLocatorUtils`) 하나만 있다.
- 게임 타입에 의존하는 에디터 기능은 에디터 모듈 `WxEditor`에 있다. 디테일 패널 사용자화(액터 로케이터·DataTable 행 핸들·State Tree 컴포넌트 이름), 장치 연결 비주얼라이저, 아이템·UI 데이터 썸네일 렌더러다.
- 프로젝트 `Plugins/`에는 에디터 도구 플러그인 3개(`WxToolset` MCP 저작 도구, `DataTableRowFixup`, `BoxComponentVisualizer`)만 있다.

### 게임모드와 맵 구성
- `AWxGameMode`는 GameState·PlayerState 클래스만 정하고, 폰 클래스는 프론트엔드에서 고른 것을 먼저 쓴다(`GetDefaultPawnClassForController`). 고른 것이 없으면 GameMode BP의 `DefaultPawnClass`다.
- 맵별 구성은 GameMode BP 두 개다. `GM_Combat`은 `BP_PlayerController`를, `GM_FrontEnd`는 기본 폰 `SpectatorPawn`과 `BP_FrontEndPlayerController`를 쓴다(에셋 참조 문자열로 확인).
- `Config/DefaultEngine.ini`의 `GlobalDefaultGameMode`는 `GM_Combat`이고, `LV_FrontEnd`만 WorldSettings의 GameModeOverride로 `GM_FrontEnd`를 쓴다. 시작 맵(`GameDefaultMap`·`EditorStartupMap`)은 `LV_FrontEnd`다.
- WorldSettings는 엔진 순정이다.
- `AWxPlayerState`에는 상태가 없다. 스탯은 캐릭터 ASC가 들고 리스폰마다 새로 초기화한다.

### 컨트롤러와 GameState의 컴포넌트

| 소유자 | 컴포넌트 | 하는 일 |
|---|---|---|
| `AWxPlayerController` | `UWxInventoryComponent` | 인벤토리. 시작 아이템(`StartingItems`)을 BeginPlay에서 권한 측이 지급한다(`BP_PlayerController`는 `DA_Potion`) |
| | `UWxInteractionScannerComponent` | 상호작용 대상 탐색 |
| | `UWxDialogueSessionComponent` | 대화 세션 |
| | `UWxPlayerLayoutComponent` | 로컬 플레이어의 HUD·사망·대화 화면. 빙의 교체 신호(`OnPossessedPawnChanged`)로 띄운다 |
| | `UWxNameplateManagerComponent` | [네임플레이트](네임플레이트.md) |
| `AWxGameState` | `UWxSkillCutsceneComponent` | 스킬 컷신 전원 재생 |
| | `UWxQuestComponent` | 퀘스트 |

- 모두 생성자가 만드는 기본 서브오브젝트라 서버·클라이언트 양쪽에 있다. 컨트롤러 컴포넌트는 폰 리스폰에도 살아남아야 하는 플레이어 단위 상태라 컨트롤러가 소유한다.
- 프론트엔드 컨트롤러에도 같은 컴포넌트가 붙지만 인벤토리는 비어 있고 스캐너·대화는 자기 가드로 동작하지 않는다. 프론트엔드 메뉴(`WBP_FrontEnd`)는 컨트롤러 BP가 띄운다.
- 스킬 컷신은 서버가 세션을 복제하면 각 머신이 같은 시퀀스를 처음부터 재생하는 방식이다. 서버는 시퀀스 길이 동안 월드 배율(`UWxTimeDilationSubsystem` 요청), 시전자 무적(`UWxEffect_Invincible`), 모든 플레이어의 입력형 어빌리티 차단(`UWxEffect_SkillCutscene`), 시전자 관련성(`bAlwaysRelevant`)을 걸었다가 되돌린다.
- 컷신을 요청하는 쪽은 궁극기(`UWxAbility_Ultimate`)이고, 시퀀스는 몽타주의 `UWxAnimNotify_SkillCutscene`에서 읽는다.

### 프론트엔드 진입
- 프론트엔드는 폰 없는 화면이다. `GM_FrontEnd`가 `SpectatorPawn`을 스폰해 빙의시키고, 시점은 `LV_FrontEnd`의 `CameraActor_0`이다.
- 캐릭터·레벨 선택지는 `UWxFrontEndDeveloperSettings`의 `CharacterOptions`·`LevelOptions`(`Config/DefaultGame.ini`)다.
- `UWxGameFlowSubsystem::RequestNewGame`은 Standalone에서만 받는다. 체크포인트 저장을 지우고 레벨을 열며, 목적지 월드에 있는 동안 고른 폰 클래스를 GameMode에 준다. 다른 맵이 열리면 선택을 버린다.
- 도착하면 첫 틱 전에 카메라를 갱신하고 스트리밍 완료까지 기다려, 폰이 지형 없이 떨어지지 않게 한다.

### 세이브
- `Save/`에는 체크포인트 위치 저장 `UWxCheckpointSaveGame` 하나만 있다. 담는 값과 쓰는 곳은 [체크포인트와 리스폰](체크포인트와-리스폰.md#저장)에 있다.

### 엔진 동작에 기댄 곳
- 폰 `BeginPlay`는 빙의보다 먼저 돌 수 있다. `RestartPlayer`가 스폰한 뒤 빙의시키므로, 월드 BeginPlay 뒤에 스폰되는 폰(부활 등)은 BeginPlay 때 컨트롤러가 없다.
  - 그래서 컨트롤러·로컬 여부에 따른 폰 초기화는 `APawn::NotifyControllerChanged`에 둔다. 엔진이 서버 `PossessedBy`·`UnPossessed`와 소유 클라이언트 `OnRep_Controller`에서 모두 부른다.
  - `AWxPlayerCharacter`는 여기서 스태미나 위젯 표시에 `IsLocallyControlled()` 결과를 그대로 대입하고, 떠난 컨트롤러의 입력 매핑을 걷는다. 켜기만 하지 않고 대입하면 빙의 해제 정리도 같은 줄이 맡는다.
  - `UWxPlayerLayoutComponent`는 BeginPlay가 빙의보다 늦으면 빙의 신호가 다시 오지 않아, BeginPlay에서 지금 폰으로 한 번 따라잡는다.
- 월드 배율은 서버에서만 건다. 엔진이 WorldSettings의 배율을 클라이언트로 복제하고 늦게 들어온 클라이언트도 맞춘다.
- `Config/DefaultGame.ini`의 `GameFeatureData` 스캔 줄은 Experience 잔재처럼 보이지만 남긴다. 켜 둔 엔진 `AllToolsets` 플러그인이 GameFeatures 플러그인을 끌어와, 이 줄이 없으면 시작할 때 Error 로그가 난다(09-07 확인).

## 결정
- 2026-10-01 게임 콘텐츠 플러그인 8개(WxCore·WxCombat·WxAI·WxUI·WxWorld·WxQuest·WxDialogue·WxInventory)를 `WxGame` 모듈의 기능 폴더로 합쳤다. 코드 품질을 앞세워, 모듈 경계를 지키려고 만든 복잡한 인터페이스·딜리게이트를 단순화하자는 요청이었다. (사용자 결정, 커밋 d37e1dd32)
  - 경계 때문에 생긴 우회(뷰모델 주입 딜리게이트, 컨트롤러가 대신 채우던 뷰모델, 디자이너가 지정하던 이동 속도 GE, 경계용 상태 태그 `State.Engaged`)는 같은 날 걷어냈다. 새 코드는 직접 참조가 기본이고, '다른 모듈을 모르니까' 식의 인터페이스·딜리게이트·태그 중계는 다시 제안하지 않는다.
  - 09-30 MVVM 원칙 중 '뷰모델은 도메인 타입을 쓰지 않는다'와 '도메인 명령은 딜리게이트로 내보낸다'는 플러그인 규칙에서 나온 것이라 함께 폐기됐다.
  - 태그 발행 자체가 상태 모델인 곳(`State.Dialogue`, `Ability.Death` 관찰 등)은 경계와 무관해 그대로 둔다.
  - `IWxSpawnable`(스포너 전용)과 `AWxDialogueActor`·`AWxNpc` 분리(메시만 있는 대화 대상을 위한 베이스)는 유지하고, 걷어내자고 다시 제안하지 않는다.
- 2026-09-07 Lyra Experience·GameFeature·ModularGameplay를 모두 지우고 전통 GameMode 구성으로 돌아갔다. 07-27부터 들였지만 확장 축을 6주간 한 번도 쓰지 않았고(GameFeature 플러그인 0개, Experience 2개), 주입 경로는 부착 지점이 grep에 잡히지 않아 코드 파악을 막았으며, 비동기 로드가 폰 스폰 보류·정적 델리게이트 지급·HUD 역통로 같은 우회를 낳았다. (사용자 결정, 커밋 97eb35f97)
  - 멀티플레이는 유지 근거가 아니었다. 기본 서브오브젝트는 서버·클라이언트에 원래 있고, 07-27의 '클라이언트 전용 컴포넌트가 생기지 않는' 문제는 서버 GameMode가 주입하는 방식에서만 생겼다.
  - 새 플레이어 단위 컴포넌트는 컨트롤러 생성자에, 판 단위 컴포넌트는 GameState 생성자에 넣는다. 맵별 구성은 GameMode BP와 GameModeOverride로, 같은 맵의 다른 구성은 순정 `?game=`으로 한다.
  - Experience·GameFeature·ModularGameplay 수신자·AddComponents 액션은 다시 제안하지 않는다. 상시 콘텐츠 플러그인이 필요하면 순정 GameFeatureData를 InitialState Active로 두면 Experience 없이 된다.
  - 같은 날 `AWxWorldSettings`를 지우고 WorldSettings를 엔진 순정으로 되돌렸다.
- 2026-09-07 폰 없는 프론트엔드는 `GM_FrontEnd`의 기본 폰을 `SpectatorPawn`으로 두어 표현한다. 08-26 '빈 값이면 스펙테이터' 결정과 같은 결과를 코드 폴백 없이 낸다. (사용자 결정, 커밋 97eb35f97)
  - 스펙테이터로만 남기고(`MustSpectate`, `bStartPlayersAsSpectators`) UI 매니저에 빙의 여부 플래그를 발행하는 안은, 스펙테이터 폰 스폰이 UI 변경 없이 같은 결과를 내서 버렸다. 다시 제안하지 않는다.
  - 프론트엔드는 Standalone 전제다.
- 2026-09-01 세이브 시스템을 모두 지웠다. WxSave 플러그인, `IWxSavable`, 각 도메인의 저장 구현, 엔진 LevelStreamingPersistence·InstancedActors 플러그인, `Effect.Savable` 태그, 관련 ini 섹션이다. 아직 세이브를 고려할 단계가 아니라고 봤고, LSP 후처리 훅을 WxSave가 부르는 구조라 일부만 지우면 반쪽 동작이 됐다. (사용자 결정, 커밋 b3f982b0d)
  - 세션 안의 스트리밍 영속도 함께 없어졌다. 셀이 스트림 아웃되면 처치한 적·장치 상태·바닥 픽업이 배치 기본값으로 돌아가는 것은 버그가 아니다.
  - 세이브는 다시 넣을 때 통째로 다시 설계한다. 넘길 교훈은 하나다: `FJsonObjectConverter`는 `FGameplayTag`의 PostSerialize를 부르지 않아 태그 리다이렉트가 무시된다.
  - 09-25에 체크포인트 위치만 단일 SaveGame 슬롯으로 저장하게 했다([체크포인트와 리스폰](체크포인트와-리스폰.md#결정)).
- 2026-09-16 스킬 컷신은 멀티플레이에서 모든 플레이어가 멈춘 월드 속에서 같은 장면을 함께 보도록 GameState 컴포넌트가 재생한다. 06월의 임시 구현(GameState의 배율 복제 컴포넌트와 멀티캐스트 재생, 컷신 트리거 액터의 머신별 정지)과 전용 시네마틱 플러그인으로 떼어 낼 계획은, 09-01 배율 컴포넌트 제거(cdaa90bb0)와 이 재설계, 10-01 플러그인 통합으로 없어졌다. (커밋 9604e2d13)

## 미결
- 게임 시작 직후 한 프레임 동안 카메라가 캐릭터 머리 가까이 튀던 현상은 Experience의 지연 스폰(폰 스폰과 뷰 타깃 전환 사이 한 프레임)이 원인이었다. 09-07에 지연 스폰을 지워 사라졌을 것으로 보지만 재현 여부는 확인하지 않았다. 다시 보이면 스프링암이 아니라 스폰·빙의 시점부터 본다.
