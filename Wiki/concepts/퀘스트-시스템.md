# 퀘스트 시스템

퀘스트 하나를 StateTree 에셋 하나로 저작하고 GameState의 컴포넌트가 돌리는 구조, 스텝 재사용, 멀티플레이 보류를 모은 문서다.
초반 구간의 메인 퀘스트 기획은 [초반 구간과 퀘스트](초반-구간과-퀘스트.md)에, StateTree 공통 작성 규칙(완료 판정·바인딩·UOL 액터 지정)은 [State Tree 작성 규칙](State-Tree-작성-규칙.md)에 있다.

## 구현

### 실행
- 퀘스트 하나는 엔진 순정 `UStateTree` 에셋 하나다(`Content/Quest/ST_Quest_Main1`·`ST_Quest_Main2`).
- `UWxQuestComponent`는 `AWxGameState` 생성자의 기본 서브오브젝트다. 권위 측 `BeginPlay`에서 순정 `UStateTreeComponent` 러너를 만들어 소유하고 실행을 맡긴다.
- 활성 퀘스트는 동시에 하나다. `ActivateQuest`는 `StopLogic`→`SetStateTreeReference`→`StartLogic` 순서로 교체한다. 러너가 Running 중이면 에셋 교체를 거부하기 때문이다.
- 러너 실행 콜스택 안(ST 태스크)에서는 재진입이 막혀 `RequestActivateQuest`가 다음 틱에 소프트 참조를 로드해 활성화한다.
- 컴포넌트는 어떤 퀘스트 에셋도 모른다. 무엇을 실행할지는 데이터가 정한다.
  - 수주: 레벨에 놓은 수주 볼륨 `AWxQuestVolume`(`ATriggerBox` 파생)이 `UWxQuestLibrary::StartQuest`에 `QuestAsset`을 넘긴다. `NotifyActorBeginOverlap`에서 서버 권위와 `AWxPlayerCharacter`인지 확인해 부르고, 콜리전을 꺼 한 번만 받는다.
  - 배치용 `Content/Quest/BP_QuestVolume`은 이 클래스를 부모로 둔 데이터 전용 BP다. 표시용 텍스트 컴포넌트와 콜리전 설정만 갖고 그래프는 없다. 배치는 LV_DevCombat(`ST_Quest_Main1`)과 LV_OpenWorld(`ST_Quest_Main2`) 두 곳이다.
  - 체인: `Start Next Quest`(`FWxStateTreeTask_StartNextQuest`)가 소프트 참조로 다음 퀘스트를 예약한다.
- 컴포넌트에는 재진입 가드가 없다. 같은 퀘스트를 다시 넘기면 처음부터 다시 시작하므로, 한 번만 받는 것은 배치의 몫이다.
- `UWxQuestLibrary`의 함수는 `StartQuest` 하나다.

### 저널과 HUD
- 저널은 제목과 목표 목록이다. `Set Quest Title`이 제목을 걸며 목표를 비우고, `Set Quest Objective`가 상태 진입에 목표를 걸고 이탈에 걷는다. 목표는 문구가 아니라 발급 핸들로 지목한다.
- 저널 정리는 러너의 `OnStateTreeRunStatusChanged`를 컴포넌트가 스스로 구독해서 한다. 완료·실패·교체 세 종료가 한 곳으로 모인다.
- 두 설정 태스크는 완료 판정에서 빠져 있어, 상태 완료는 같은 상태의 대기 태스크가 낸다.
- 퀘스트 HUD는 리졸버가 `OnJournalChanged`를 구독해 뷰모델에 싣는다([UI 뷰모델](UI-뷰모델.md)).
- 러너와 저널은 권위(싱글·리슨 호스트)에만 있고 복제되지 않는다.

### 스텝 재사용
- 스텝은 `Content/Quest/Steps`의 독립 StateTree 에셋이다.

| 스텝 | 대기 태스크 | 대상 |
|---|---|---|
| `ST_QuestStep_InteractTarget` (기획의 'NPC 대화') | `Wait For Interaction` | UOL 하나 |
| `ST_QuestStep_MoveToTarget` | `Wait Move To Target`(반경 기본 300cm) | UOL 하나 |
| `ST_QuestStep_KillEnemies` | `Wait Spawners Killed` | 스포너 UOL 배열 |

- 스텝 안의 태스크 구성은 08-14 작업 기록 기준이다(에셋 내부는 미확인). 대상 형태는 태스크 코드에서 확인했다.

- 퀘스트는 스텝 상태를 Linked Asset으로 링크하고, 값(목표 문구·대상 액터·반경 등)을 링크 상태의 파라미터 오버라이드에 저장한다.
- 스텝 에셋은 일반 StateTree다. 루트 상태 하나의 대기 태스크가 끝나면 서브트리 완료가 링크 상태 완료로 올라가 부모의 완료 전이가 돈다(08-13 PIE 기록).
- 한 스텝의 대상 파라미터 하나가 대기 태스크와 `Mark Indicator`를 함께 먹이므로 둘의 개수 형태가 같아야 한다. ST 바인딩은 단일과 배열을 잇지 못한다. 그래서 상호작용·도달 대기와 인디케이터는 단일 UOL이다.
- 옵션 파라미터는 비우면 그 기능을 쓰지 않는다. `Print Subtitle`은 시작 행이 비면 경고 없이 Succeeded다. 반면 대상이 빈 대기 태스크는 완료될 수 없는 오조립이라 경고한다.
- 장치 트리의 복원 판정(`UWxDeviceStateTreeComponent::IsRestoring`)은 퀘스트 트리에 없다. 퀘스트 태스크에 장치의 초기 진입 건너뛰기를 옮겨 오지 않는다.
- `Wait Move To Target`·`Play Dialogue`·`Give Rewards`는 0번 플레이어 컨트롤러를 쓰고, `Mark Indicator`는 그 노드를 도는 머신에만 뜬다(v1 싱글·리슨 호스트 전제).
- 상호작용 대기는 [상호작용](상호작용.md), 대화 재생은 [대화 시스템](대화-시스템.md)에 있다.

## 결정
- 2026-08-03 에셋의 자기선언 자동 시작(`bAutoStart`)과 레지스트리 스캔을 지우고 탑재 지정을 레벨 배치로 돌렸다. (사용자 결정)
- 2026-08-13 수주는 볼륨 BP와 `UWxQuestLibrary::StartQuest`로 한다. 같은 날 새벽 부착형 `UWxQuestActivationComponent`로 옮겼다가 밤에 폐기하고 돌아왔으니 다시 제안하지 않는다. (사용자 결정, 커밋 f37651929)
  - 함께 기각한 대안: 퀘스트 트리 앞단의 대기 게이트와 시작 퀘스트 지정(러너가 하나라 선형 체인만 된다), 네이티브 볼륨 액터(10-06에 뒤집혔다), 대화 완료로 수주(대화→퀘스트 의존이 생겨 범위가 크다).
  - `SendQuestEvent` 진입점과 `Quest.Fail` 태그는 호출자가 없어 지웠다. 실패를 내는 쪽이 생기면 진입점과 태그를 함께 만든다.
- 2026-10-06 수주 볼륨의 로직을 BP 그래프에서 C++ `AWxQuestVolume`으로 옮겼다. 08-13에 기각한 '네이티브 볼륨 액터'를 되살린 것이다. 에셋 레퍼런스 말고는 로직을 C++에 두어 AI가 읽고 검증할 수 있게 하는 방향에 따랐다. 수주 경로(`StartQuest`)와 배치 방식은 그대로다. (사용자 결정, 커밋 85731316d)
- 2026-08-13 퀘스트의 첫 상태는 게이트가 아니다. 제목 설정 뒤 바로 진행 상태로 넘어가므로 수주 시점은 `StartQuest` 호출 자체다. '첫 상태에서 2차 조건을 기다린다'는 07-27 서술을 코드·주석에 다시 쓰지 않는다. (08-13 에셋 실측 기록)
- 2026-08-13 스텝 값은 리터럴과 레벨 액터(UOL) 모두 퀘스트 에셋의 링크 상태 오버라이드에 둔다. UOL을 고른 이유와 기각한 대안은 [State Tree 작성 규칙](State-Tree-작성-규칙.md#결정)에 있다. (사용자 결정, 커밋 e263e2bcd)
  - 대가로 퀘스트 에셋이 레벨에 묶여 레벨 간 재사용을 포기했고, 사용자가 받아들였다.
  - 루트 파라미터→링크 상태 바인딩은 두지 않는다. 남아 있으면 런타임에 오버라이드 값을 덮어쓴다.
- 2026-08-13 이름 규칙: 저작자가 보는 노드는 Start(`StartQuest`, `Start Next Quest`), 컴포넌트 내부는 Activate(`ActivateQuest`·`RequestActivateQuest`)다. (사용자 지정)
- 저널 태스크는 제목과 목표를 나누고, 정리는 러너 실행 상태 통지로 한다. 정리 전용 태스크(Unregister류)는 두지 않는다. (사용자 결정, 날짜 미상)
- 2026-08-28 퀘스트 전용 마커 타입 `UWxQuestStateTree`를 지우고 순정 `UStateTree`로 통일했다. 마커가 주던 것은 퀘스트 지정 픽커의 필터뿐이었고, 대가로 순정 생성 경로(팩토리·MCP 툴셋)를 잃고 있었다. 픽커에 모든 StateTree가 뜨는 것은 감수했고, 필터가 다시 필요하면 마커 부활이 아니라 메타로 건다. (커밋 d0cc4d7c2)
- 2026-07-28 멀티플레이 정책(공유 퀘스트·개인별 퀘스트)이 정해지지 않아 저널 복제와 인디케이터 복제를 보류했다. 정책이 데이터의 복제 위치(GameState 전역·플레이어별)를 정하므로 먼저 만들면 되돌릴 위험이 있다. (사용자 결정)

## 미결
- 멀티플레이 정책이 정해지지 않았다. 정해지면 저널 복제, 인디케이터 표시, 0번 컨트롤러를 쓰는 노드(목표 지점 도달 대기·대화 재생·보상 지급)를 함께 정리한다. 07-28에 확인해 둔 설계 요점은 아래와 같다.
  - 저널은 필드를 `ReplicatedUsing`으로 복제하면 된다. FText는 넷 직렬화되고(로컬라이즈 텍스트는 키 왕복), OnRep은 번치 전체를 적용한 뒤 불려 찢어진 상태가 없다(엔진 5.8 소스 확인). 러너는 복제하지 않는다.
  - 대상 액터를 복제할 때 `FSoftObjectPath`는 PIE 접두사 리매핑이 없어 서버 경로가 클라에서 풀리지 않고, UOL은 UPROPERTY 복제가 안 된다. UOL 문자열(`ToString`/`FromString`) 왕복과 클라 로컬 `SyncFind`가 확인된 대안이다.
- 독립 퀘스트를 동시에 기다리려면 러너를 여럿 둬야 한다. 지금은 활성 하나와 체인뿐이다.
- 완료 이력이 없어 레벨을 다시 열면 수주 볼륨이 퀘스트를 다시 건다. 세이브가 없으니(09-01 제거) 영속과 함께 다룬다.
