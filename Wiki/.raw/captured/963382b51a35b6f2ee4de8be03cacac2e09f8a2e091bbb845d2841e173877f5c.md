# 사용자 요청

2026-09-26 사용자가 "작업 절차 다이어그램이 보자마자 이해되게 직관적으로 개선하고 싶어요. 몇가지 시안을 주세요."라고 했다. 시안 네 개를 비교한 뒤 기존 도식의 문구 개선을 거쳐 "시안 B에서 가독성 개선하고 문구도 잘 읽히게 고친 버전"을 골랐다. 이어 "이 다이어그램이 이 프로젝트의 실제 워크플로우를 잘 반영하고 있는지 점검해주세요."라고 요청했고, 점검 결과를 반영한 도식으로 작업 절차 페이지의 도식을 바꾸라고 지시했다.

# 변경

- `.agents/workflow/process/index.md`의 도식을 단계 상자 배치로 바꿨다. 새 작업 → ① 정하기(AI 조사·질문 → 구현 계획, 사람 질문 답변 → 구현 승인) → ② 만들기(AI 구현·자체 검증) → ③ 확인하기(AI 테스트 체크리스트 작성·AI 항목 직접 테스트, 사람 코드 리뷰·사람 항목 테스트) → 모두 통과하면 완료(이어서 AI가 Wiki 정리) 순서다.
- 상자 안은 AI(초록) → 사람(주황)을 한 줄로 두었다. 화살표는 정하기 안의 "답변 · 추가 요청", 정하기 → 만들기의 "구현 승인", 만들기 → 정하기의 "판단이 필요하면 질문", 확인하기 → 만들기의 "실패 · 추가 요청", 확인하기 → 완료의 "모두 통과하면"이다.
- 시작 원의 이름을 "작업 요청"에서 "새 작업"으로 바꾸고 단계 제목·새 작업·완료를 굵게 했다.
- 옛 도식의 "승인된 범위 안의 수정"(작업 요청 → 만들기) 지름길은 그리지 않았다. 문서의 작은 수정 규칙과 명확한 지시 규칙은 본문에 그대로 있다.

# 점검에서 확인한 서버·화면 동작

근거는 `.agents/scripts/Workflow-TestFeedback.cjs`와 `.agents/scripts/wiki-viewer/test-feedback.js`·`workflow.js`다.

- 질문 답변은 정하기(읽기 전용 조사)를 다시 실행한다(`kinds.answer`가 `plan`). 구현 승인은 미답변 질문이 없고 승인 안 된 계획이 있을 때만 받으므로, 답변과 구현 승인 사이에는 항상 AI 조사가 끼어 있다. 옛 도식의 "새 질문이 생기면" 되돌림은 조건을 잘못 그렸다.
- AI가 돌려준 계획은 승인 줄 없이 기록된다. 웹 새 작업은 항상 읽기 전용 정하기로 시작해 구현 승인 버튼을 거친다. 추가 요청 처리 지시도 범위를 바꾸는 요청이면 새 계획을 다시 승인받게 한다. 작업 절차의 "사람이 구현 내용을 명확히 지시한 요청은 그 지시를 구현 승인으로 봅니다"는 AI 대화에서만 동작한다. 문서 문장의 범위 수정은 사용자가 정하지 않았다.
- 사람이 적은 실패는 바로 수정 처리를 시작한다. AI 항목의 실패는 자동으로 고치지 않고 `확인 대기 · 실패 확인` 상태로 멈추며, 다음 행동은 추가 요청으로 방향을 정하는 것이다.
- 구현·수정·추가 요청 처리는 계획을 바꿔야 하면 구현하지 않고 질문을 돌려준다. 답하면 정하기가 새 계획을 만들고 구현 승인을 다시 받는다.
- 미결 1: 정하기 중(미답변 질문이나 미승인 계획)에 보낸 추가 요청도 모든 명령 허용으로 실행된다(작업 파일의 실행 모드는 `plan` 종류만 읽기 전용). 승인 전 구현 금지는 처리 지시에만 기댄다. 제안: 그때의 추가 요청은 읽기 전용으로 실행한다.
- 미결 2: 완료 직후 열려 있는 작업 진행 패널에서는 완료 뒤 정리가 끝나면 추가 요청 전달 버튼이 다시 켜진다. 대시보드는 완료 행에 작업 진행을 주지 않고 "새 문제는 새 작업으로"라고 안내하며, 작업 절차는 "AI에게 추가 요청(항상)"이라고 적는다. 제안: 완료 단계에서 추가 요청을 숨기고 문서를 "(완료 전까지)"로 고친다.

# Mermaid 배치 관찰

Mermaid 11.12.0, 뷰어 설정(`theme: neutral`, `flowchart.htmlLabels: false`)에서 헤드리스 Edge 렌더를 비교해 확인했다.

- 서브그래프 안의 `direction LR`은 안의 노드가 밖의 노드와 직접 이어지면 무시된다. 화살표를 서브그래프 id끼리 이으면 상자 안 방향이 지켜지고, 화살표가 상자 테두리에서 끝나 단계 제목을 가로지르지 않는다. 노드끼리 이은 세로 배치에서는 들어오는 화살표가 상자 제목 위를 지나갔다.
- 상자끼리 되돌림 화살표가 있을 때 상자를 위 단계부터 선언하면 확인하기가 만들기보다 위로 올라가 순서가 뒤섞였다. 아래 단계부터 선언하면 위에서부터 차례로 놓였다. 서브그래프 삽입 순서와 dagre의 순환 제거 순서 때문으로 추정하며 내부 코드는 확인하지 않았다. 도식 원문에 주석 한 줄로 남겼다.
- 마크다운 문자열 라벨(`"`**굵게**`"`)은 굵게와 줄바꿈이 SVG 라벨에 그대로 그려지고 가운데 정렬된다. 같은 렌더에서 일반 문자열 라벨은 상자 안에서 왼쪽으로 쏠렸다. classDef의 `font-size`는 서브그래프 제목에 적용되지 않았다.
- 뷰어는 `%%{` 설정 지시문과 frontmatter가 있는 도식을 거부하지만 일반 `%%` 주석은 허용한다.
