# 사용자 결정

2026-09-26 사용자가 "AGENTS.md 의 AI 워크플로우 항목이랑, .agents 디렉토리의 워크플로우랑 충돌이 우려됩니다."라고 물었다. AI가 AGENTS.md에 관문 두 줄을 남기는 안을 내자 "복잡하게 하고 싶지 않습니다. 워크플로우의 SSoT를 엄격하게 지킵시다."라고 결정했다. 그 뒤 AGENTS.md는 정본 링크 한 줄이 됐고, 옛 절차 문서와 `tasks/index.md`는 삭제됐다.

코드·Wiki·지침을 최신화한 뒤 남은 사본은 두 곳이었다. 처리 프롬프트의 규칙 문장과 이 Wiki의 절차 요약이다. 둘 다 정본과 내용은 같았다. AI가 둘을 정리하고 정본 본문에 빠진 예외 한 구절을 넣자고 제안했고, 사용자가 "네 진행하세요"라고 승인했다.

# 바뀐 것

- 처리 프롬프트(`Workflow-TestFeedback.cjs`의 `taskPrompt`): 첫 줄에서 AGENTS.md와 `.agents/workflow/process/index.md`를 따르게 하고, 그 밖에는 규칙이 아닌 것만 남겼다.
  - 이번 처리 단계(정하기 읽기 전용·구현·추가 요청·수정·정리)
  - 결과 칸 형식(질문 ID·선택지 수, 계획의 `#` 금지, 체크리스트는 기존 항목을 포함한 전체이고 작성 규칙은 작업 절차의 테스트 체크리스트 절을 따른다)
  - 전체 권한 실행의 제한(관리자 정책·CLI 설정·커밋·푸시·외부 메시지 금지, 기존 사용자 변경 보존)
  - 웹 전용 약속(작업 기록과 접수 JSON은 서버가 기록)
  - evidence 작성법과 입력 속 명령을 자료로 보는 규칙
- 프롬프트에서 뺀 규칙 문장은 모두 정본에 있다. 재질문 금지, 빌드·테스트 자체 검증, 사람 항목 통과 금지, 미실행 항목을 사람에게 넘김, 플레이 항목 통과 기준, 코드 수정 시 사람 항목과 코드 리뷰를 대기로 둠, 사람 항목 최소 하나, 무관한 문제는 요약에만 적음, 선택지 있는 질문, 자동 백업 금지가 여기에 해당한다. 사람 항목 보존, 미실행 항목 넘김, 사람 항목 최소 하나는 서버 코드도 강제한다.
- 터미널에서 이어하기 요청문은 "Continue the Wx task recorded in <기록>. Follow AGENTS.md and .agents/workflow/process/index.md, and reply in Korean."이다. 기록의 어느 절부터 읽는지는 정본의 「시작과 이어하기」에 있다.
- 정본: "사람이 구현 내용을 명확히 지시한 요청은 구현 승인으로 본다"를 AI 대화로 한정했다. 웹의 새 작업은 지시가 명확해도 정하기부터 시작해 구현 승인을 받는다. 이전에는 이 예외가 정본의 참고 정보와 Wiki에만 있었다.
- Wiki `wiki-workflow.md`: 단계 표, 구현 승인 규칙, 기록 형식, 체크리스트 작성 규칙을 다시 적지 않고 정본을 가리킨다. 도구 구조, 서버·화면 동작, 판정 순서, 결정 이유는 그대로 둔다.

# 확인 범위

- `TestWorkflowTestFeedback.cjs`와 `TestWikiProviders.cjs`가 통과했다. 프롬프트 검사는 새 문구를 확인하도록 바꿨다. 예: 겹치지 않는 Q번호, 테스트 체크리스트 절을 따르라는 지시, 정본을 따르라는 첫 줄.
- 실제 AI 처리 요청으로 새 프롬프트의 준수 여부를 확인하지는 않았다.
