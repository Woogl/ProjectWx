# 관찰

- 2026-09-26 첫 실제 Codex 처리(AnimNotify 카테고리와 색상 정리의 테스트 결과)에서 결과 스키마가 모든 칸을 요구하므로 Codex가 `plan`에 "이번 작업은 완료입니다. 서버가 완료 상태와 처리 결과를 기록합니다."를 채웠다.
- 서버는 결과에 계획이 있으면 동작 종류와 관계없이 `## 구현 계획` 절(승인 줄 없음)로 썼다. 이번에는 다른 이유(무관한 lint 경고 blocker)로 확인 필요가 먼저 판정돼 드러나지 않았지만, 막힘이 없었다면 "구현 승인 필요" 상태와 구현 승인 버튼이 나오는 가짜 단계가 됐다.
- 테스트 결과 처리 지시는 구현 지시와 달리 questions·plan을 비우라는 문장이 없었다.

# 조치

- 서버 결과 반영: 질문과 새 계획은 정하기(새 작업·질문 답변)와 추가 요청 결과에서만 받는다. 구현·테스트 결과 처리에서 온 질문·계획은 쓰지 않고, 사람의 판단이 필요하면 blockers로 받는다. AI가 지시를 어겨도 기록이 바뀌지 않는다.
- 테스트 결과 처리 지시에 "사람의 판단이 필요하면 blockers에, questions는 비우고 plan은 빈 문자열로"를 더했다.
- 사용자 요청("지금 완료로 바꿔주세요.")으로 AnimNotify 기록의 잘못 들어간 절을 지우고 상태를 완료로 바꿨다. 확정 근거는 그 기록 이력에 남겼다.
- 대시보드 목록: 완료·리뷰·참고 행에는 AI 처리 상태 배지를 붙이지 않는다. 사람이 완료로 확정한 기록에 마지막 AI 상태("AI 확인 요청")가 남아 완료와 어긋나 보였다. 배지는 확인 대기·진행 중 행에만 있다.
