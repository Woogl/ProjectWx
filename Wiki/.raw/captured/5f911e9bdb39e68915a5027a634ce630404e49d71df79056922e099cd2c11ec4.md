# 사용자 요청과 결정

2026-09-25 사용자는 "지금 워크플로우를 확인해서 작업하기 편한지 점검해주세요. AI 입장과 사람 입장 모두요"라고 요청했다. 점검 결과를 본 뒤 네 개선(식별값 검사 제거, 코드 리뷰를 체크리스트로, 옛 기록 정리, 작업 현황 자동 생성)을 모두 선택했다.

# 점검 근거

- 다른 세션 두 곳이 새 테스트 체크리스트 형식을 그대로 썼고 서버 파서가 정상으로 읽었다. 한 세션은 코드 리뷰를 체크리스트 사람 항목으로 넣었다.
- 체크포인트 테스트 결과 전달은 두 번 모두 확인 필요로 끝났다(남은 확인 8개씩). 원인에는 외부 Workflow 스크립트 변경으로 바뀐 코드 식별값과, 처리 AI(Codex)가 Git 저장소 소유권 보호로 버전을 대조하지 못한 것이 있었다.
- 점검 시점 최근 60분 동안 코드·설정·에셋 파일 64개가 바뀌었고, 커밋되지 않은 코드 변경이 34개였다. 저장소 전체 식별값은 창을 연 시점과 전달 시점만 비교해, 사람이 실제로 테스트한 빌드를 보장하지 못했다.
- `tasks/index.md` 표는 여러 세션과 테스트 결과 서버가 동시에 고치는 파일이었다. 작업 기록 27건 중 제목 아래에 다음 행동이 있는 기록은 5건이었다.
- 옛 절차 문서(`implementation.md` 등)가 삭제 대기 중에도 "승인자 이름 입력 후 코드 리뷰 승인"을 지시했다.

# 구현 관찰

- 공용 해석기 `.agents/scripts/wiki-viewer/task-records.js`: 제목(`# `) 아래부터 첫 `## ` 전까지에서 `상태: <확인 대기|진행 중|완료>[ · 설명]`과 `다음 행동:` 줄을 읽는다. 앞의 `- ` 표기는 허용하고, 상태 단어가 셋 중 하나가 아니면 상태로 보지 않는다. 테스트 체크리스트 표 파서도 여기에 둔다. 목록 한 줄은 제목·상태·확인된 범위(체크리스트가 있으면 "체크리스트 n/m 통과", 없으면 상태 줄 설명)·다음 행동·수정 시각이다.
- 서버 `Workflow-TestFeedback.cjs`: 코드 식별값 계산·비교를 없앴고 작업 기록 해시 대조는 유지한다. `list`는 기록에서 만든 목록(`tasks`)을 수정 시각 내림차순으로 돌려준다. 처리 결과에 따라 기록의 상태 두 줄을 고친다(완료 또는 확인 대기, 첫 미통과 항목). 상태 줄이 없으면 제목 아래에 만든다. 체크리스트가 없는 기록은 다음 행동(없으면 제목)을 사람 항목 하나로 보여준다. 목차 등록 여부는 더 이상 검사하지 않는다.
- 처리 프롬프트: 코드를 수정했다면 영향받는 사람 항목을 대기로 되돌리고 담당 사람의 코드 리뷰 항목을 대기로 둔다(없으면 추가). 다른 작업의 변경이나 코드 버전은 대조하지 않는다.
- 화면: 대시보드 분류는 확인 대기·진행 중·완료·리뷰·참고 네 개다. 서버가 없으면 생성 문서의 기록을 같은 해석기로 읽고, 연결되면 서버 목록으로 바꾼다. 리뷰·참고 기록에는 체크리스트 버튼이 없다. 생성 문서에 수정 시각을 싣는다.
- `node .agents/scripts/Wiki-AI.cjs --tasks`가 같은 목록을 터미널에 출력한다. 서버 재시작 판단 파일은 6개다(`task-records.js` 추가).
- 절차: 코드 리뷰는 확인하기 체크리스트의 사람 항목이다(이번 작업에서 코드를 바꿨으면 둔다). 사람 판단은 정하기의 답변·구현 승인과 확인하기의 코드 리뷰·사람 항목 테스트 두 곳이다. `tasks/index.md`는 표 없는 안내 문서다. AGENTS.md와 module-review 스킬도 이 규칙으로 바꿨다(리뷰 문서는 상태 줄 없음).
- 이관: 작업 현황 표의 상태·확인된 범위·다음 행동을 기록 15건의 상태 두 줄로 옮겼다. 이미 새 형식인 7건은 두었고, 옛 자유 형식 `상태:` 줄은 `이전 상태:`로 이름만 바꿨다. 모듈 리뷰 5건과 후속 작업이 이어받은 Ability Resolver 기록은 리뷰·참고다. 옛 기록 11건에는 기록 안의 미확인·인게임 확인 항목만 체크리스트로 옮겼다.

# 검증과 제한

TestWorkflowTestFeedback(상태 줄 읽기·쓰기, 체크리스트, 코드 리뷰 항목, 결과 분류, 기록에서 만든 목록, 재시도·재시작, HTTP 경계), TestWorkflowFeedbackUI, TestWikiProviders, TestWikiViewer·TestWikiSpaces(재생성 후)가 통과했다. CheckWikiLinks는 66문서에서 오류 0건이다. 로컬 서버 재시작 뒤 protocol 4를 확인했다. 헤드리스 Edge로 대시보드 네 분류·보스 표시 체크리스트 창·작업 절차 도식을 캡처했다. 이관 뒤 작업 현황 표와 기록 상태를 행마다 대조해 의도한 6건만 달랐다.

실제 AI 처리 요청과 사람의 화면 확인은 하지 않았다. 목록 제목은 작업 현황 표의 짧은 이름 대신 기록 제목이다. 다른 작업의 코드 변경은 자동으로 감지하지 않는다. 작업 중 다른 세션이 같은 체크아웃의 작업 기록·Wiki를 수정했고, 그 세션들이 이미 쓰던 새 형식 기록은 건드리지 않았다.
