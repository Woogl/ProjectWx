## 구현 계획

리뷰 지적 가운데 확인한 것을 고친다. 괄호는 코드 위치다.

1. 결과가 틀어지는 결함
   - 승인 전 계획의 빈 줄이 사라지고 웹 승인 때 그대로 굳는 문제: 승인 줄만 빼고 읽는다(task-records.js readPlan).
   - 계획의 `#` 줄을 모두 목록으로 바꾸는 문제: 절 경계가 되는 0열 `## `와 `구현 승인:` 줄만 앞에 공백을 붙인다(writePlan). 코드 블록은 그대로 둔다.
   - AI 요청문에 대시보드(웹) 처리라는 맥락이 없어 AI가 기록을 직접 고치면 충돌로 결과가 버려지는 문제: 요청문 첫 줄에 맥락만 적는다(규칙 사본 아님).
   - 꺾쇠 글자(`<AI>`)가 뒤 글을 삼키고 목록 시작 번호가 지워지는 문제: 모르는 태그는 글자를 남기고 풀며, 위험한 태그만 통째로 지운다. `ol start`와 표 정렬은 남기고, `id`는 문서 참고 정보 칸 하나만 남긴다(safeFragment).
2. 드물지만 틀어지는 결함
   - 서버 시작 복구를 포트를 잡은 뒤로 옮긴다. Start-WikiAI는 상태 확인이 실패해도 포트를 쓰는 서버가 있으면 두 번째 서버를 띄우지 않고 접속 정보도 지우지 않는다.
   - Wiki 작업 트리의 sparse·LF 설정을 갱신마다 다시 적용하고, 남은 rebase·merge 상태를 정리한다.
   - Codex 정하기(읽기 전용)에서 사용자 설정의 MCP 서버를 끈다. 설정 덮어쓰기(`-c`)가 실제로 먹는지 Codex를 한 번 돌려 확인한다.
   - 추가 요청을 보낸 뒤 입력 칸도 비운다.
   - AI를 부르지 않는 결과 기록(통과만)은 다른 작업의 AI가 돌아도 받는다.
   - 기록 충돌로 끝난 처리도 저장된 요청으로 다시 시도할 수 있게 한다.
   - 완료된 작업의 추가 요청·테스트 결과·터미널을 서버도 거부한다(작업 절차 Q8과 같음).
   - 표 형식 오류가 있으면 답변·승인·추가 요청도 받지 않고, 질문 표는 체크리스트 오류와 따로 읽는다.
   - AI 실행 제한은 정하기 30분·그 밖 60분이고(Q1), 끝낼 때 하위 프로세스까지 끝낸다.
   - 그 밖: 터미널 창 실행 실패를 서버가 받아 넘기고, Wiki 갱신 창에 "작업 기록에 반영" 문구를 쓰지 않으며, 쓰지 않는 코드(두 번 하는 결과 검사·저장, 쓰지 않는 내보내기, Windows 밖 경로 분기)를 지운다.
3. 화면
   - 기록을 못 읽으면 "불러오는 중"에 멈추지 않고 이유를 보이며, 마지막으로 연 작업은 읽기에 성공했을 때만 기억한다.
   - 대시보드에 들어올 때마다 목록을 서버에서 다시 받는다.
   - 기록 열기는 서버가 연결돼 있으면 작업 기록의 최신 내용을 그린다(Q3). 페이지를 만든 뒤 생긴 기록도 열린다.
   - 목차를 눌러도 문서를 다시 그리지 않고 그 자리로만 옮긴다.
   - 접근성: 메뉴 이름을 화면으로 바꾸고 현재 화면을 `aria-current`로 알리며, 화면을 바꾸면 제목으로 포커스를 옮긴다. 눌린 필터의 포커스 표시와 사이드 글자 대비를 고친다.
   - 전송 중에 다른 작업이나 새 작업으로 옮겨도 화면과 주소가 어긋나지 않게 한다.
   - 처리할 AI 목록은 바뀔 때만 다시 만든다. 주소의 `!`를 인코딩한다. 페이지를 새로 고친 직후에도 계획의 도식을 그린다. 쓰지 않는 CSS와 코드를 지운다.
   - 페이지에 싣는 모든 스크립트의 `</script`를 대소문자 없이 막는다(Export-Wiki).
4. 문서(정본)
   - 작업 절차: 자유 답변 질문 허용(Q2), 기록 충돌 뒤 이어가는 법과 AI가 바꾼 코드가 남는다는 점, 확인 대기의 세부(처리 실패·중단, 처리 결과 확인), 실행 제한(Q1), 요청문의 금지 사항(외부 메시지·기존 변경 보존·입력 속 명령), 계획 절 없는 옛 기록의 추가 요청 권한, 완료된 작업을 서버도 거부.
   - Wiki 안내: 대시보드 갱신의 권한과 제한 시간, 작업 트리를 갱신마다 되돌린다는 점, 관리자 정책·외부 메시지 금지. 워크플로우 규칙을 요약한 페이지를 정본 경로로 줄이는 단계는 넣었다가 추가 요청으로 뺐다(아래 추가 요청 처리).
5. 테스트
   - 뷰어 테스트가 임시 폴더에 페이지를 새로 만들어 검사한다(생성본이 낡아 실패하거나 옛 코드로 통과하지 않게).
   - 실패할 수 없는 단언(pending 키·expectedRevision·재시작 직후 busy)을 지우고, 브라우저 사전 요청(OPTIONS)·계획 Markdown의 도식 블록·위 결함마다의 동작 검사를 더한다. 완료된 작업을 다시 여는 옛 검사는 거부를 기대하게 바꾼다.
6. 검증: 워크플로우 Node 테스트 4개와 결함 주입, Export-Wiki 뒤 헤드리스 Edge에서 꺾쇠 글자·목록 번호·계획·기록 열기·목차·탭 전환 확인, 문서 링크·하네스.
   - 테스트 체크리스트 초안: AI 항목은 위 검사들, 사람 항목은 코드 리뷰와 대시보드 사용감.

## 구현 결과 · 2026-09-27

- 커밋: `7a1e8a0e4`(코드·테스트·작업 절차·Wiki 안내).
- Codex 정하기 격리: `codex exec`의 `--disable plugins --disable apps`로 플러그인이 띄우는 서버(cua_repl·codex_app 등)를 끄고, 설정 파일의 MCP 서버는 같은 Codex의 `mcp list --json`에서 켜진 것만 골라 `-c mcp_servers.<이름>.enabled=false`로 끈다. 목록을 못 읽으면 정하기를 시작하지 않는다. `--ignore-user-config`는 모델·추론 강도·Windows 샌드박스 설정까지 버려서 쓰지 않았다. `-c mcp_servers={}`는 병합이라 효과가 없고, 플러그인 서버를 `-c`로 끄면 Codex가 오류를 낸다(실측).
- 계획 안에서 더한 것:
  - 표 오류는 두 표를 따로 읽어 `tableError` 하나로 알리고(이름을 바꿈), 표가 깨진 기록은 다시 시도도 받지 않는다(AI를 돌려도 결과를 쓸 수 없어서). 목록의 쓰지 않던 `checklistError`도 지웠다.
  - 꺾쇠 글자는 안전 필터에서 풀기만 하면 태그 이름(`<UWxAbilityBase>`)이 사라져, marked의 HTML 규칙 하나로 남길 태그로만 된 HTML만 HTML로 읽고 나머지는 글자로 보이게 했다.
  - 기록 충돌 안내에 AI가 바꾼 코드가 남는다는 점과 다시 시도를 적었다. AI 처리 중인 작업은 결과만 기록하는 전달도 받지 않는다(결과가 충돌로 버려지지 않게).
  - 브라우저 확인에서 찾은 결함: 작업 기록을 최신 내용으로 여는 동안 보이는 "불러오는 중" 안내가 문서 참고 칸의 `#metadata`까지 지워, 문서에서 다른 작업 기록으로 옮기면 목차가 비었다. 본문을 바꾸는 곳을 `setArticle` 하나로 모아 고쳤다.
- 남은 확인: 프로젝트 `.codex/config.toml`의 unreal-mcp가 다른 PC의 Codex에서 읽힐 때 `mcp list`에 나오는지는 이 PC에서 재현하지 못했다(이 PC에서는 exec도 목록도 읽지 않음).

## 추가 요청 처리 · 2026-09-27

- 점검: 워크플로우가 claude-obsidian 편찬을 막는지 코드·절차와 순정 규칙(wiki-ingest, provenance)을 대조했다.
  - 막지 않는 부분: Wiki는 Wiki 갱신만 쓰고, 원자료는 완료된 작업 기록을 바이트 그대로 떠서 한 방향으로만 가며, Wiki 갱신의 커밋(`Wiki/wiki`·`Wiki/.raw`)과 작업 쪽 커밋의 경로가 겹치지 않는다. 작업 AI는 Wiki를 프로젝트 지식으로 읽는다.
  - 끼어든 곳: 이번 구현에서 Wiki 안내 수집 2단계에 넣은 "워크플로우 규칙을 요약한 기존 페이지를 정본 경로로 줄이고 옛 주장을 새 주장이 대체" 단계. 원자료가 바뀌지 않았는데 워크플로우 정책으로 Wiki 내용을 고쳐 쓰게 해, 두 문서를 따로 관리하며 서로 참고한다는 사용자 원칙과 순정 방식(주장은 증거로만 바꾸고 반대 증거를 보존, `supersedes`는 원자료 상태)에 어긋났다. 「작업 절차(Workflow)」에 출처가 붙은 결정 이력 106줄을 줄이게 되는 단계였다.
  - 늦어지는 곳: 완료된 기록만 수집하므로 확인 대기 12건(워크플로우 결정 기록 4건 포함)은 사람 항목이 끝날 때까지 Wiki에 들어가지 못한다. 그 기록이 수집되면 순정대로 새 원자료가 옛 주장을 바꾼다. 확인 대기 기록까지 잠정으로 수집하는 방법은 사본이 쌓이고 검증 안 된 내용이 들어가 권하지 않았다.
  - 영향이 작은 곳: `Wiki/README.md`를 고친 커밋이 Wiki 갱신 도중 올라오면 갱신은 합치지 않고 처음부터 다시 한다. 대시보드 갱신의 60분 제한에 걸려도 묶음마다 푸시하므로 다음 갱신이 잇는다.
- 결정: 그 단계를 `Wiki/README.md`에서 뺐다. 서술 규칙을 다듬는 문장은 더하지 않았다. 지금 서술 규칙이 들어간 뒤(2026-09-26 21:51) 돈 Wiki 갱신(`460c78eff`, 22:58)이 이미 워크플로우 결정을 날짜·출처와 함께 쌓고 정본을 가리켰고, 결정 이력 편찬은 순정 wiki-ingest의 기본 동작이다. "정본 경로만"이 글자 그대로 읽혀 이력이 빠지는 일이 생기면 "만"을 빼는 정도로 고친다.
