# 작업 - workflow-table-error-recurrence

## 개요

woogle이 워크플로우의 버튼이 자꾸 안 나온다며 점검을 요청하고(2026-09-30) 점검 결과의 계획에 "진행하세요."로 승인한 작업 기록이다. 상태는 완료(체크리스트 7/7 통과)다. 지금 지킬 규칙은 정본 `.agents/workflow/process/index.md`를 본다.

## 원인

- 대화·터미널에서 AI가 기록을 손으로 고치다 표를 깨뜨리면 웹은 그 작업의 입력(체크리스트·전달 버튼)을 통째로 숨겼다. 2026-09-30에만 세 건이었다: 질문 절에 표 없이 "추가 질문 없음."만 적은 두 건(작업 절차 문구와는 맞지만 서버는 머리글 오류로 읽음)과 질문 행의 `||` 오타 한 건.
- 표가 깨져도 대시보드와 `--tasks`는 정상처럼 보여 작업 탭을 열기 전에는 드러나지 않았고, 작업 탭 상태 칸은 지난 웹 처리 결과(예: 구현 승인 필요)를 지금 상태처럼 제목으로 보였다.
- 세 기록 모두 대화·터미널에서 AI가 쓴 기록이었고, 웹 처리는 서버가 표를 쓰므로 깨지지 않는다. 승인 전에 두 기록의 표 형식만 바로잡아 버튼을 되살렸다.

## 구현 결과

- 표 읽기(`task-records.js`): 질문·체크리스트 절에 `|`로 시작하는 줄이 하나도 없으면 표가 없는 것으로 읽는다. 표 줄이 있으면 전처럼 절 제목 바로 아래 머리글부터 검사하므로 글 아래 둔 표는 여전히 오류다. 서버가 새 질문을 쓸 때는 그 절 내용을 질문 표로 바꾼다.
- 목록 요약: 두 표 중 먼저 찾은 오류를 `표 오류 · …`로 대시보드와 `--tasks`에 보인다.
- 상태 칸: 웹 처리 상태 제목은 처리 중·실패·중단·충돌일 때만 보이고, 끝난 처리는 "최근 전달 · …" 줄로만 남으며, 웹 전달이 없던 작업은 칸을 숨긴다. 대시보드 목록 옆 표시도 같은 기준이다.
- 표 오류 화면은 서버가 거절하는 추가 요청을 숨기고 터미널에서 이어하기로 고치는 법을 보인다. 서버 안내 3곳의 "최신 상태를 불러와·다시 불러오세요"를 브라우저 새로고침으로 바꿨다.
- 작업 절차 정본에 표 없는 "추가 질문 없음" 허용, 대화·터미널에서 기록을 고친 AI의 `--tasks` 확인, 표 오류가 보이는 곳을 적었다.

## 검증 범위

- AI: 워크플로우 Node 테스트 4개 exit 0, 스크래치 사본을 옛 동작으로 되돌린 결함 주입이 모두 실패로 잡힘, 서버 재시작·페이지 재생성 뒤 실제 기록 전체 읽기(표 오류 0건, 확인 대기 4건 모두 체크리스트 단계와 전달 버튼).
- 사람: woogle 2026-09-29 코드 리뷰와 작업 탭 화면 확인 통과.
