# 작업 - 이동속도의-어트리뷰트화

- 원본: `.agents/workflow/tasks/이동속도의-어트리뷰트화.md`
- 원자료 사본: `.raw/captured/de7a66490ad501e11e4211b5678afbcb64ab8e64ad9e16e33eddc0597ea7abc9.md` (수집 2026-09-27, 재확인 기한 2027-03-25)

## 개요

캐릭터 이동 속도를 CharacterMovementComponent 속도 × 배율에서 MOV 어트리뷰트(cm/s) 자체로 바꾼 작업 기록이다. 웹 작업으로 정하기(읽기 전용 조사) → 구현 승인 → 만들기 → 확인하기를 거쳤고, 상태는 완료(체크리스트 9/9 통과)다.

## 요청과 결정

> woogle 2026-09-27: "현재 캐릭터의 이동속도를 처리할 때 CharacterMovementComponent의 이동속도에 MOV 스탯을 배율로 곱하는 방식으로 구현이 되어있습니다. MOV 스탯을 아예 CharacterMovementComponent의 이동속도를 대신하는 스탯으로 바꿔주세요. 그러니까 MOV 스탯이 500 이면, 500 cm/s로 이동할 수 있는 상태인 것입니다. 어트리뷰트 테이블에도 MOV 스탯 입력을 추가합니다."

- 조사 시점 코드에는 MOV라는 이름이 없었고, 요청한 스탯은 `UWxCombatAttributeSet::SPD`(MaxWalkSpeed에 곱하는 배율, 기본 1.0)였다. AI는 요청 용어대로 이름을 MOV로 바꾸는 계획을 냈다.
- 구현 승인: woogle 2026-09-27.
- 범위 밖: 앉은 속도(`MaxWalkSpeedCrouched`)와 공격 속도 배율 `ASPD`.
- 코드 리뷰 지적(woogle 2026-09-27): "WxCombatAttributeInitTableRow.h 에서 Units 쓰지 마세요." → MOV 열의 `Units = "cm/s"` 메타를 지우고 `ClampMin`만 남겼다.

## 구현 결과

- `WxCombatAttributeSet.h/.cpp`: SPD → MOV(접근자·`OnRep_MOV`·복제 등록), 기본값 0(`InitSPD(1.f)` 삭제).
- `WxCombatAttributeInitTableRow.h`: `float MOV = 0.f` 열 추가. `WxAbilitySet.cpp`가 행의 MOV를 베이스 값에 기록한다.
- `WxCharacterBase.h/.cpp`: `HandleMOVAttributeChanged`로 `MaxWalkSpeed = MOV`. 클래스 기본값을 읽던 코드와 `WxPlayerCharacter`·`WxEnemyCharacter` 생성자의 MaxWalkSpeed 500/400 줄을 지웠다.
- 계획과 다른 점: 네트워크 PIE에서 클라이언트 월드의 적이 MaxWalkSpeed 600(엔진 기본값)인 회귀가 나왔다. 클라이언트에서 적은 InitAbilitySystem을 거치지 않고 예전에는 생성자의 400이 이를 가렸다. MOV 구독과 1회 적용을 `PostInitializeComponents`로 옮겼다. AI는 승인 범위 안의 회귀 수정이라 다시 묻지 않고 코드 리뷰 볼 점에 적었다.
- `WxEffect_MoveSpeedScale`: 대상 어트리뷰트를 MOV로. `WxEffect_MoveSpeedOverride`: MOV를 `SetByCaller.Magnitude` 절대 속도로 덮어쓴다(새 태그 없음).
- `WxBTService_MirrorMovement`: 도플갱어 추적 속도 = Master MaxWalkSpeed × 1.25를 절대값으로 보낸다. CDO로 나눠 배율을 만들던 계산은 지웠다.
- 데이터 이관(`Content/DesignerTables/DT_CharacterAttribute`): TemplatePlayer·HGTest 500, TemplateEnemy·Sandbag·Boss·Minion 400. 헤드리스 Python 커맨드릿으로 쓰고 새 프로세스로 다시 읽어 확인했다.
- 기획서 수정 제안(고치지 않음): `Docs/CombatDesign/캐릭터 스탯 명세서.md` §3.3 표의 SPD 이동 속도 계수를 MOV 이동 속도(cm/s)로, §5.11 SPD 설명을 MOV 절대 속도와 곱하는 배율 효과로 바꾸자는 제안.

## 검증 범위

- AI(도구 실행): WxEditor Development 빌드 3회 성공, Content 전체 uasset·umap 문자열·FName 표 스캔에서 MaxWalkSpeed 덮어쓰기·SPD 참조 0건(대조군은 검출), DT 이관 값과 `Export-AbilitySystemLists.ps1`의 MOV 열, MCP 네트워크 PIE(리슨 서버 + 클라이언트 1명, LV_DevCombat)에서 플레이어 500·적 400(서버·클라이언트), 적 배회 감속 중 MOV·MaxWalkSpeed 200 → 해제 뒤 400.
- 질주 750은 MCP 키 입력이 누른 채로 둘 수 없어 AI가 확인하지 못해 사람 항목으로 넘겼다.
- 사람(woogle 2026-09-27 통과): 코드 리뷰(Units 지적 수정 뒤), 플레이어 걷기·질주 속도, 적 추격·정찰·배회와 도플갱어 추적 속도, DT의 TemplatePlayer MOV 1000에서 두 배 속도.
