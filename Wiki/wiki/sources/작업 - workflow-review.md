- 테스트 체크리스트: 작업 기록의 `## 테스트 체크리스트` 표(항목·확인 방법·담당·결과·근거). AI는 사람 항목을 통과로 바꾸거나 지우거나 담당을 바꿀 수 없고, 모든 항목이 통과해야 완료다.

## 웹 새 작업·이어하기 (2026-09-25~26)

- 사용자 결정: 웹 안에서 처리, AI 대화는 터미널만, 웹에서 맡긴 구현은 모든 명령 허용, 진행 과정은 터미널 창에 보이며 실행.
- 정하기는 읽기 전용, 구현 승인·추가 요청·테스트 결과 처리는 모든 명령 허용(Codex danger-full-access, Claude bypassPermissions, Gemini yolo)이다. `Workflow-Runner.cjs`(신규)가 `cmd start` 터미널 창에서 AI를 실행한다. AI가 준 계획의 승인 줄은 목록으로 바꿔 AI가 스스로 승인할 수 없다.
- 후속: 기록 이름을 한글 제목으로(`보스-체력바-지연-감소.md`), 목록 행 버튼 정리, 체크리스트 박스 표시, 기록 작성 규칙 버튼과 `tasks/index.md` 삭제.
- 첫 실제 처리(AnimNotify 작업)에서 결함 두 개가 드러났다: 다른 세션의 일시적 lint 경고를 blocker로 보고해 완료가 막힘, AI의 완료 문장이 plan 칸으로 들어가 승인 없는 `## 구현 계획` 절이 생김.

## 상태는 질문·계획·체크리스트에서만 (2026-09-26)

- 원인 분석: 여러 세션이 한 체크아웃을 고쳐 AI가 이 작업의 변경만 가려낼 수 없으므로, 관련 여부 판단이 상태를 바꾸지 않게 하는 것이 근본 해결이다.
- 서버가 단계마다 AI 결과 칸을 제한한다(정하기 = 질문·계획, 구현·수정 = 변경·질문·체크리스트, 정리 = 변경만). 상태는 기록의 질문·계획·체크리스트에서만 정한다. 모두 통과하면 즉시 완료하고 뒤이은 AI 정리는 상태를 바꾸지 않는다. blockers·checks 칸은 evidence로 바꿨다.

## 워크플로우 SSoT·도식·잔재 제거 (2026-09-26)

- SSoT: AGENTS.md의 절차 요약을 작업 절차 링크 한 줄로 바꾸고, 자동 백업 금지와 모듈 리뷰 재대조 규칙을 정본으로 옮겼다.
- 도식: 단계 상자(① 정하기·② 만들기·③ 확인하기) 도식으로 교체했다.
- 잔재 제거: 옛 웹 경로 스크립트 8개, 테스트 5개, 옛 절차 문서 5개, `assets/ai-workflow.png`를 `git rm`했다. 문서 이미지 기능(`Export-Wiki.ps1` PNG 묶기, `wikiImageSource` 등)도 지웠다.
- 규칙 사본 정리: 처리 프롬프트(`taskPrompt`)의 규칙 문장을 정본 참조로 줄이고, "명확한 지시는 구현 승인"을 AI 대화로 한정했다.
- 후속(2026-09-26 원본 갱신): 도식 교체 때 남긴 미결 셋 중 남은 둘(정하기 중 추가 요청의 실행 권한, 완료 직후 추가 요청 버튼 재활성과 문서의 "(항상)" 문구)은 워크플로우 종합 점검 기록(`.agents/workflow/tasks/workflow-inspection.md`)의 Q7·Q8로 정해졌다. 그 기록은 이 갱신 시점에 완료 상태가 아니라 수집 대상이 아니며, 현재 규칙은 정본 `.agents/workflow/process/index.md`를 본다.
