## 개요

- 원자료: 옛 LLM Wiki 결정 노트 `.wiki/raw/notes/2026-09-26-workflow-process-diagram.md`(frontmatter `ingested: 2026-09-26`, `source: "MANUAL"`).
- 사용자가 시안 네 개를 비교한 뒤 시안 B를 골라 작업 절차(`.agents/workflow/process/index.md`) 도식을 바꿨고, 도식이 실제 서버·화면 동작과 맞는지 코드로 점검했다.

## 사람의 판단 원문

> 사용자 2026-09-26: "작업 절차 다이어그램이 보자마자 이해되게 직관적으로 개선하고 싶어요. 몇가지 시안을 주세요."

> 사용자 2026-09-26: "시안 B에서 가독성 개선하고 문구도 잘 읽히게 고친 버전"

> 사용자 2026-09-26: "이 다이어그램이 이 프로젝트의 실제 워크플로우를 잘 반영하고 있는지 점검해주세요."

이어 점검 결과를 반영한 도식으로 작업 절차 페이지의 도식을 바꾸라고 지시했다(지시 원문은 원자료에 없음).

## 새 도식(확정 결정)

- 새 작업 → ① 정하기(AI 조사·질문 → 구현 계획, 사람 질문 답변 → 구현 승인) → ② 만들기(AI 구현·자체 검증) → ③ 확인하기(AI 체크리스트 작성·AI 항목 테스트, 사람 코드 리뷰·사람 항목 테스트) → 모두 통과하면 완료(이어서 AI가 Wiki 정리).
- 상자 안은 AI(초록) → 사람(주황) 한 줄. 화살표: 정하기 안 "답변 · 추가 요청", 정하기→만들기 "구현 승인", 만들기→정하기 "판단이 필요하면 질문", 확인하기→만들기 "실패 · 추가 요청", 확인하기→완료 "모두 통과하면".
- 시작 원 이름을 "작업 요청"에서 "새 작업"으로 바꿨다.
- **이전 도식을 바꿈**: 옛 도식의 "승인된 범위 안의 수정"(작업 요청 → 만들기) 지름길은 그리지 않는다. 작은 수정·명확한 지시 규칙은 본문에 그대로 둔다. 옛 도식의 "새 질문이 생기면" 되돌림은 조건을 잘못 그린 것으로 판정했다.

## 점검에서 확인한 서버·화면 동작(구현 관찰, 정적 읽기)

근거: `.agents/scripts/Workflow-TestFeedback.cjs`, `.agents/scripts/wiki-viewer/test-feedback.js`·`workflow.js`.

- 질문 답변은 정하기(읽기 전용 조사)를 다시 실행한다(`kinds.answer`가 `plan`). 구현 승인은 미답변 질문이 없고 미승인 계획이 있을 때만 받으므로 답변과 승인 사이에 항상 AI 조사가 낀다.
- 웹 새 작업은 항상 읽기 전용 정하기로 시작해 구현 승인을 거친다. "사람이 구현 내용을 명확히 지시한 요청은 그 지시를 구현 승인으로 봅니다"는 AI 대화에서만 동작한다.
- 사람이 적은 실패는 바로 수정 처리를 시작한다. AI 항목의 실패는 자동으로 고치지 않고 `확인 대기 · 실패 확인`에서 멈추며, 다음 행동은 추가 요청이다.
- 구현·수정·추가 요청 처리는 계획을 바꿔야 하면 구현하지 않고 질문을 돌려준다.

## Mermaid 배치 관찰

Mermaid 11.12.0, 뷰어 설정(`theme: neutral`, `flowchart.htmlLabels: false`)에서 헤드리스 Edge 렌더로 비교했다.

- 서브그래프 안 노드가 밖과 직접 이어지면 `direction LR`이 무시된다. 화살표를 서브그래프 id끼리 이으면 상자 안 방향이 지켜지고 단계 제목을 가로지르지 않는다.
- 되돌림 화살표가 있으면 아래 단계부터 선언해야 위에서부터 차례로 놓인다(dagre 순환 제거 순서 때문으로 추정, 내부 코드 미확인).
- 마크다운 문자열 라벨은 굵게·줄바꿈이 그려지고 가운데 정렬되며, 일반 문자열 라벨은 왼쪽으로 쏠렸다. classDef `font-size`는 서브그래프 제목에 적용되지 않았다.
- 뷰어는 `%%{` 설정 지시문과 frontmatter가 있는 도식을 거부하고 일반 `%%` 주석은 허용한다.

## 미결정·충돌

- 미결 1: 정하기 중(미답변 질문·미승인 계획)에 보낸 추가 요청도 모든 명령 허용으로 실행된다(실행 모드는 `plan` 종류만 읽기 전용). 승인 전 구현 금지는 처리 지시에만 기댄다. AI 제안: 그때의 추가 요청은 읽기 전용으로 실행.
- 미결 2: 완료 직후 열린 작업 진행 패널에서 완료 뒤 정리가 끝나면 추가 요청 버튼이 다시 켜진다. 대시보드는 "새 문제는 새 작업으로"라고 안내하고 작업 절차는 "AI에게 추가 요청(항상)"이라 적어 어긋난다. AI 제안: 완료 단계에서 숨기고 문서를 "(완료 전까지)"로 고침.
- 명확한 지시를 승인으로 보는 문장의 범위는 이 노트 시점에 사용자가 정하지 않았다. 이후 [[결정 노트 - 2026-09-26-workflow-ssot-copies]]에서 정본에 AI 대화로 한정하는 구절이 들어갔다.
