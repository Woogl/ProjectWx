# 체크포인트와 리스폰

체크포인트 저장(SaveGame)과 리스폰 규칙에 관한 원자료 요약을 모은 주제 페이지입니다. 문장마다 끝의 링크가 출처이며, 절 이름으로 기획 요구사항·사람의 확정 결정·코드 구현 관찰·검증 범위·미결정을 구분합니다. 구현 관찰은 원자료 작성 시점의 코드 기준이고, 문서 갱신이나 Wiki lint 통과는 게임 동작 검증이 아닙니다.

## 요구사항

- 에스트병 기획서는 화톳불, 보스전 재도전, 사망 후 재시작에서 포션을 최대 수량으로 충전하도록 요구한다. ([[기획서 - 에스트병 기획서]])
- Object_Design 기획서는 스포너블을 체크포인트 상호작용 시 최초 위치로 리젠하고, 기믹은 레벨 이동·재접속·월드 파티션 스트리밍에도 상태를 유지하도록 요구한다. ([[기획서 - Object_Design]])
- Object_Design 기획서는 체크포인트를 비활성으로 배치해 첫 상호작용 때 활성화하고, 상호작용마다 HP/MP 전량 회복·포션 리젠·일반 적 리젠을 횟수 제한 없이 일으키도록 요구한다. ([[기획서 - Object_Design]])
- Respawn_System 기획서는 사망 시 HP 0 감지, 페이드 아웃, 마지막 활성 체크포인트 기준 저장 데이터 로드, 일반 적 재배치, 체크포인트 위치 이동, HP/MP 전량 회복, 페이드 인 순서로 부활을 처리하도록 요구한다. ([[기획서 - Respawn_System]])
- Respawn_System 기획서는 사망 부활과 체크포인트 F 상호작용 모두에서 같은 규칙으로 스포너블을 리젠하도록 요구한다. ([[기획서 - Respawn_System]])
- Respawn_System 기획서는 일반 적만 리젠하고 스포너(레버) 소환 적과 네임드 적은 리젠하지 않으며, 보스는 재생성 없이 재도전 시 HP만 전량 초기화하도록 요구한다. ([[기획서 - Respawn_System]])
- Respawn_System 기획서는 던전 재진입을 사망 부활과 같은 규칙으로 저장 데이터에서 복원하도록 요구한다. ([[기획서 - Respawn_System]])
- 레버_증기_사양서는 증기의 마지막 ON/OFF 상태를 세이브 로드와 리스폰 후에도 유지하도록 요구한다. ([[기획서 - 레버_증기_사양서]])

## 확정 결정

- 사용자는 2026-09-25에 PIE와 일반 플레이가 WxCheckpoint 저장 슬롯 하나를 공유하고 슬롯 세분화는 나중에 하기로 결정했다. ([[결정 노트 - 2026-09-25-checkpoint-single-slot]])
- 사용자 후속 요청으로 체크포인트 저장 API와 StateTree 태스크 이름은 RecordCheckpoint에서 SaveCheckpoint로 통일되었고 저장 동작은 유지된다. ([[결정 노트 - 2026-09-25-save-checkpoint-rename]])

## 구현 관찰

- 부활은 폰을 교체하므로 UWxPlayerLayoutComponent는 폰 교체 때 관찰 대상을 새 폰으로 바꾸고 대화 창만 닫으며, 사망 화면은 부활 요청 완료 때 스스로 비활성화된다. ([[작업 - player-screen-classes-to-layout-component]])
- 2026-09-25 ST_CheckPoint가 새 SaveCheckpoint 구조체 이름으로 리세이브되어 RecordCheckpoint 계열 StructRedirects가 필요 없어졌다. ([[결정 노트 - 2026-09-25-checkpoint-redirect-cleanup]])
- 2026-09-25 정적 확인 기준 UWxCheckpointSaveGame은 레벨 패키지와 부활 Transform을 WxCheckpoint 슬롯(PIE는 WxCheckpoint_PIE, 사용자 인덱스 0)에 저장하고 UWxCheckpointSubsystem은 제거됐다. ([[결정 노트 - 2026-09-25-checkpoint-savegame]])
- 체크포인트 기록 StateTree 태스크는 복원·비플레이어·멀티플레이에서 저장하지 않고 저장 실패를 경고와 Failed로 전달한다. ([[결정 노트 - 2026-09-25-checkpoint-savegame]])
- 부활은 저장 없음·로드 실패·다른 맵·유효하지 않은 Transform이면 PlayerStart 경로로 돌아가고, 새 게임은 슬롯 삭제 실패 시 맵 이동을 시작하지 않는다. ([[결정 노트 - 2026-09-25-checkpoint-savegame]])
- 체크포인트 SaveGame은 체크포인트 한 개만 저장하며 캐릭터·인벤토리·장치 상태와 이어하기 UI는 구현하지 않는다. ([[결정 노트 - 2026-09-25-checkpoint-savegame]])
- 노트 시점 UWxCheckpointSaveGame::GetSlotName()은 항상 WxCheckpoint를 반환하며 저장·조회·새 게임 초기화가 같은 슬롯과 사용자 인덱스 0을 쓴다(정적 조사). ([[결정 노트 - 2026-09-25-checkpoint-single-slot]])
- SaveCheckpoint 이름 변경 시 이전 두 StateTree 구조체 경로는 DefaultEngine.ini CoreRedirects로 새 경로에 매핑되었고 에셋 재저장은 수행하지 않았다. ([[결정 노트 - 2026-09-25-save-checkpoint-rename]])
- 노트 시점 플레이어 부활 성공 후 스트리밍 완료 시점과 StateTree 라이브 진입 시점에 AWxSpawner::RespawnAll이 직접 호출되어 BP에서 별도 스포너 재생성 노드가 필요 없다. ([[결정 노트 - 2026-09-25-spawner-library-removal]])
- AWxSpawner::RespawnAll은 Manual 스포너를 제외하고 클라이언트 월드를 건너뛰며 스포너 목록을 약참조로 보관해 호출 직전 유효성을 확인한다. ([[결정 노트 - 2026-09-25-spawner-library-removal]])

## 검증 범위

- 체크포인트 리다이렉트 제거는 새 프로세스 재로드·StateTree 컴파일·저장 성공까지 확인됐고 인게임 플레이는 검증하지 않았다. ([[결정 노트 - 2026-09-25-checkpoint-redirect-cleanup]])
- 체크포인트 SaveGame 전환은 코드 정적 확인만 기록됐고 인게임 저장·부활 동작은 검증되지 않았다. ([[결정 노트 - 2026-09-25-checkpoint-savegame]])

## 미결정·충돌

- Object_Design 기획서는 레이저 통로를 레버로 끌 수 있다고 적지만 Respawn_System 기획서는 레이저 통로가 리스폰과 무관하게 항상 작동한다고 적어, 끈 상태의 리스폰 처리가 정해져 있지 않다. ([[기획서 - Object_Design]])
- Respawn_System 기획서는 체크포인트 효과로 포션 리필을 적지 않지만 Object_Design 기획서는 포션 리필을 포함하며, 사망 부활 시 포션 리필 여부는 정해져 있지 않다. ([[기획서 - Respawn_System]])
- 레버_증기_사양서의 증기 레버는 무한 반복형이어서, Respawn_System 기획서가 레버 일반 규칙처럼 적은 작동한 레버는 되돌아오지 않음과 다르다. ([[기획서 - 레버_증기_사양서]])
- 기존 WxCheckpoint_PIE 저장 파일의 자동 이관·삭제는 구현되지 않았고 슬롯 세분화 방식도 미정이다. ([[결정 노트 - 2026-09-25-checkpoint-single-slot]])
- 플레이어 부활 요청 진입점 자체의 UI 연결은 SpawnerLibrary 제거 작업 범위 밖으로 남았다. ([[결정 노트 - 2026-09-25-spawner-library-removal]])
