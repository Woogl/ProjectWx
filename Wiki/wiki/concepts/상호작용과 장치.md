# 상호작용과 장치

상호작용 계약, 레버·장치 StateTree, 오브젝트 기획에 관한 원자료 요약을 모은 주제 페이지입니다. 문장마다 끝의 링크가 출처이며, 절 이름으로 기획 요구사항·사람의 확정 결정·코드 구현 관찰·검증 범위·미결정을 구분합니다. 구현 관찰은 원자료 작성 시점의 코드 기준이고, 문서 갱신이나 Wiki lint 통과는 게임 동작 검증이 아닙니다.

## 요구사항

- 조작키 문서는 상호작용을 키보드 F, 패드 RB에 두고 같은 키로 그로기 피니시도 처리한다. ([[기획서 - 조작키]])
- Object_Design 기획서는 모든 배치물에 구형 상호작용 범위와 F — [행동] 형태의 안내 UI를 두고, 범위가 겹치면 가장 가까운 배치물을 우선하도록 요구한다. ([[기획서 - Object_Design]])
- Object_Design 기획서는 경보 레버·스포너 레버·문 레버·엘리베이터 활성화 레버를 1회용으로 정하고, 엘리베이터 층 불러오기 레버는 엘리베이터가 그 층에 없을 때만 반복 사용하게 한다. ([[기획서 - Object_Design]])
- Object_Design 기획서는 엘리베이터를 스플라인 경로로 만들고, 비활성 시 문을 닫아 탑승을 막으며, 이동 중 문을 닫고 도착 시 여는 동작을 요구한다. ([[기획서 - Object_Design]])
- Object_Design 기획서는 CCTV 관측기가 지정 Level Sequence를 재생해 퍼즐 힌트를 주고, 재생 종료·재입력·피격 시 플레이어 시점으로 돌아오도록 요구한다. ([[기획서 - Object_Design]])
- Object_Design 기획서는 레이저 통로가 1회성 충돌 영역을 가진 전진 레이저 벽으로 방어력 무시 고정 피해를 주고, 극한 회피로 통과한 뒤 레버로 끌 수 있도록 요구한다. ([[기획서 - Object_Design]])
- Respawn_System 기획서는 레버, 레버로 열린 문, 활성화된 엘리베이터, 체크포인트, CCTV 관측기, 개봉한 상자의 상태를 리스폰 후에도 유지하도록 요구한다. ([[기획서 - Respawn_System]])
- Wx_Quest 기획서는 밸브를 순서 무관하게 작동하면 회전하고 옆 파이프 머티리얼이 바뀌며, 작동 후 상호작용할 수 없도록 요구한다. ([[기획서 - Wx_Quest]])
- 레버_증기_사양서는 레버를 당기면 연결된 증기가 ON/OFF로 토글되고, 레버는 무한히 쓸 수 있되 조작 중에는 재조작을 막으며 1초 뒤 원래 자세로 돌아오도록 요구한다. ([[기획서 - 레버_증기_사양서]])
- 레버_증기_사양서는 레버와 증기를 1:N과 N:1로 연결할 수 있고, 증기가 ON 또는 OFF로 시작할 수 있도록 요구한다. ([[기획서 - 레버_증기_사양서]])
- 레버_증기_사양서는 증기를 데미지·튕김 없는 통행 차단 벽으로 두고, ON/OFF 전환 시 증기가 즉시 분출하거나 사라지도록 요구한다. ([[기획서 - 레버_증기_사양서]])
- 그로기 피니시 기획서는 피니시 프롬프트를 상호작용 UI로 표시하고 다른 상호작용 오브젝트와 겹치면 맨 위에 두고 기본 선택되도록 요구한다. ([[기획서 - 그로기_피니시_시스템_기획서]])
- 뒤잡_시스템 기획서는 뒤잡 조건 충족 시 상호작용 프롬프트 F - 암살을 표시하고, 뒤잡이 일반 상호작용보다 우선하도록 요구한다. ([[기획서 - 뒤잡_시스템]])

## 확정 결정

- 엘리베이터는 사용자 확정 B안에 따라 비활성 상태에서 탑승칸 버튼을 잠그고 탑승칸 목록에서 항상 현재 층을 빼며, 기획서의 활성화 레버 방식은 보류되었다. ([[작업 - interaction-list-vm-simplification]])
- 상호작용 문구는 행동의 주인이 가진다는 기준으로 Device는 StateTree, 대화 액터는 대화 컴포넌트, 픽업은 아이템 데이터, 피니시는 피니시 어빌리티가 가진다. ([[작업 - interaction-list-vm-simplification]])
- 사용자는 상호작용 문구를 실제 행동의 주인(장치는 StateTree, 대화 액터는 대화 컴포넌트, 픽업은 아이템 데이터, 피니시는 피니시 어빌리티)이 갖도록 정하고 모든 문구를 StateTree로 옮기는 안을 기각했다. ([[결정 노트 - 2026-09-23-interaction-list-vm]])
- 겹친 상호작용 대상을 목록으로 보여 주고 휠로 선택하는 동작은 유지하기로 했다. ([[결정 노트 - 2026-09-23-interaction-list-vm]])
- 장치 트리를 InitialState에서 바로 시작하는 순정 해법은 UStateTreeComponent가 인자를 넘길 수 없어 엔진 지원 전까지 보류하기로 2026-09-24 사용자가 정했다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 사용자는 2026-09-24 상호작용 자격까지 선택지로 합치는 안을 승인해 IWxInteractable에서 CanInteract와 GetInteractionPrompt를 없애기로 했다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])

## 구현 관찰

- FWxDeviceTriggerRule_SplineStops의 bAcceptCurrentStop은 bWakeOnCall로 이름이 바뀌었고, StopPrompt는 C++ 기본값 없이 ST_Elevator에서 Floor {0}으로 입력된다. ([[작업 - interaction-list-vm-simplification]])
- StateTree 인스턴스 구조체의 FText에 C++ 기본값을 두면 기본값과 같은 값일 때 에셋 저장이 FortniteMain 커스텀 버전 불일치로 실패한다. ([[작업 - interaction-list-vm-simplification]])
- 2026-09-23 정적 조사 기준 UWxInteractionScannerComponent는 기존 대상 순서를 보존하고 새 후보를 거리순으로 붙이며, 대상·선택지 값·문구가 바뀔 때와 선택 변경 때 OnRowsChanged를 발행한다. ([[결정 노트 - 2026-09-23-interaction-list-vm]])
- UWxDeviceStateTreeComponent::IsRestoring은 SourceStateID가 무효하거나 컴포넌트가 요청한 복원 전이일 때 복원으로 보고, 상태 적용은 복원에서도, 일회성 효과는 실제 진입에서만 실행하게 한다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 장치 레벨 시퀀스 재생의 카메라 컷은 당사자를 조종하는 피어에서만 켜지고, 사운드 재생은 라이브 발동 1회 원샷이며, 스포너 발동은 장치 복원 전이에서 스폰하지 않는다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- IWxInteractable은 순수 가상 GetInteractionOptions와 OnInteracted만 가지며 선택지가 빈 대상은 스캐너 행이 생기지 않는다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])
- UWxAbility_Interact는 거리 검사 후 선택지 값 대조로 빈 목록을 거절해 서버 자격 검증을 유지한다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])
- AWxItemPickup은 ItemDef가 비어도 빈 문구 선택지를 내어 OnInteracted로 픽업을 치우는 경로를 보존한다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])
- 2026-09-24 참조가 0건이던 Device.Locked 태그가 삭제됐고 장치 잠금은 받는 쪽 대기 태스크 활성 여부로 판단한다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])

## 검증 범위

- 엘리베이터 탑승칸 버튼 잠금과 Floor N 표시는 2026-09-25 이우성이 인게임에서 통과로 확인했다. ([[작업 - interaction-list-vm-simplification]])
- 상호작용 목록 VM 단순화는 노트 시점에 Development 빌드와 관련 WBP 컴파일만 확인했고 인게임 동작은 인간 확인 대상으로 남았다. ([[결정 노트 - 2026-09-23-interaction-list-vm]])
- 장치 StateTree 정리는 HEAD 142fab5d6에서 코드를 다시 읽은 정적 조사이며 뒤의 세 커밋은 빌드 기록이 없고 인게임 동작은 확인하지 않았다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 상호작용 계약 통합은 WxEditor Win64 Development 빌드만 성공했고 인게임 동작은 확인하지 않았다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])

## 미결정·충돌

- Object_Design 기획서의 1회용 레버 규칙과 레버_증기_사양서의 무한 상호작용 증기 레버는 레버 종류별로 재사용 규칙이 따로 정의되어 있다. ([[기획서 - Object_Design]])
- Respawn_System 기획서는 작동한 레버가 되돌아오지 않는다고 적지만, 레버_증기_사양서의 증기 레버는 무한히 상호작용하고 1초 뒤 원래 자세로 돌아온다. ([[기획서 - Respawn_System]])
- Respawn_System 기획서는 레이저 통로가 리스폰과 무관하게 항상 작동한다고 적지만, Object_Design 기획서는 레버로 레이저 통로를 비활성화할 수 있다고 적어 비활성화 상태의 리스폰 처리가 정해져 있지 않다. ([[기획서 - Respawn_System]])
- Wx_Quest 기획서의 상호작용 문구는 F - (하이픈) 형식이어서 Object_Design 기획서의 F — [행동] 형식과 다르고, 밸브와 공성포 발전기 패널은 Object_Design 배치물 목록에 없다. ([[기획서 - Wx_Quest]])
- 레버_증기_사양서의 문서 제목은 레버 / 피스톤 기믹이지만 본문 구성 요소는 레버와 증기뿐이다. ([[기획서 - 레버_증기_사양서]])
- 레버_증기_사양서는 여러 레버가 한 증기에 연결될 때의 토글 규칙과 조작 중 잠금 공유 여부를 정하지 않았다. ([[기획서 - 레버_증기_사양서]])
- 뒤잡_시스템 기획서와 그로기 피니시 기획서는 둘 다 상호작용 키를 쓰고 상호작용보다 우선하지만, 둘 사이의 우선순위는 어느 문서도 정하지 않았다. ([[기획서 - 뒤잡_시스템]])
- IsRestoring을 모르는 다른 도메인 태스크는 서버의 InitialState 전이를 실제 진입으로 보므로 InitialState 상태에 보상 같은 일회성 효과를 두면 레벨 시작 때 실행된다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 보이지만 누를 수 없는 비활성 선택지가 필요해지면 FWxInteractionOption 필드와 UWxAbility_Interact 대조 조건을 함께 바꿔야 하며 지금 빈 선택지 목록은 숨김이다. ([[결정 노트 - 2026-09-24-interaction-contract-options-only]])
