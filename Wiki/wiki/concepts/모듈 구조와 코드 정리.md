# 모듈 구조와 코드 정리

모듈 배치 원칙과 모듈별 정리 결정에 관한 원자료 요약을 모은 주제 페이지입니다. 문장마다 끝의 링크가 출처이며, 절 이름으로 기획 요구사항·사람의 확정 결정·코드 구현 관찰·검증 범위·미결정을 구분합니다. 구현 관찰은 원자료 작성 시점의 코드 기준이고, 문서 갱신이나 Wiki lint 통과는 게임 동작 검증이 아닙니다.

## 요구사항

- 아직 없음

## 확정 결정

- AnimNotify 색상 설정 정의는 도메인 모듈 사이 의존 없이 공유하도록 WxCore에 두고, UWxCombatDeveloperSettings에서는 색상 데이터를 제거하고 피해 계산용 DefenseConstant만 남겼다. ([[작업 - animnotify-categories]])
- DataTableRowFixup 플러그인은 프로젝트 범위를 넘는 범용 플러그인이라 클래스·모듈·로그 이름에서 Wx 접두사를 빼는 AGENTS.md 코딩 규칙 1의 예외로 정했다. ([[작업 - datatable-row-rename-reference-update]])
- 대화 VM 분리 작업은 WxCore를 제외한 Wx 기능 모듈 간 신규 의존성을 추가하지 않고 WxGame 조립 계층이 WxUI와 WxDialogue를 연결하도록 했다. ([[작업 - dialogue-presentation-vm]])
- Nameplate 판정 규칙은 게임 규칙이라 WxGame에 두기로 했고, WxUI가 WxCombat을 모르게 하려던 LockOnTargetQuery 델리게이트와 WxCore 계약 인터페이스 안은 채택되지 않았다. ([[작업 - nameplate-manager]])

## 구현 관찰

- AnimNotify 색상 이동으로 WxCore에는 엔진 DeveloperSettings 의존성만 추가됐고 WxAI·WxInventory는 WxCombat을 참조하지 않는다. ([[작업 - animnotify-categories]])
- 2026-09-24 DefaultEngine.ini의 [CoreRedirects] 섹션은 참조 에셋 재저장 뒤 모두 제거되었고, 리다이렉트 없이 관련 BP가 오류·경고 0으로 컴파일되었다. ([[작업 - nameplate-manager]])
- BP 썸네일 코드는 IWxUIData 없이 WxEditor에서 WxCombat·WxGame 타입을 직접 읽으며, 이 두 의존성은 WxEditor에만 추가되었다. ([[작업 - ui-data-interface-removal]])

- 상호작용 대상 락온과 UWxAbility_Interact 모듈 이전은 사용자가 나중에 고민하겠다고 보류했다. ([[작업 - nameplate-manager]])

- [[작업 - ui-data-interface-removal]] — 공용 IWxUIData 인터페이스를 없애고 WxCombat 데이터·규칙, WxUI VM, WxGame 리졸버 연결로 역할을 나눈 완료 작업 기록
