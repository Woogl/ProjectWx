# 모듈 구조와 코드 정리

모듈 배치 원칙과 모듈별 정리 결정에 관한 원자료 요약을 모은 주제 페이지입니다. 문장마다 끝의 링크가 출처이며, 절 이름으로 기획 요구사항·사람의 확정 결정·코드 구현 관찰·검증 범위·미결정을 구분합니다. 구현 관찰은 원자료 작성 시점의 코드 기준이고, 문서 갱신이나 Wiki lint 통과는 게임 동작 검증이 아닙니다.

## 요구사항

- 아직 없음

## 확정 결정

- AnimNotify 색상 설정 정의는 도메인 모듈 사이 의존 없이 공유하도록 WxCore에 두고, UWxCombatDeveloperSettings에서는 색상 데이터를 제거하고 피해 계산용 DefenseConstant만 남겼다. ([[작업 - animnotify-categories]])
- DataTableRowFixup 플러그인은 프로젝트 범위를 넘는 범용 플러그인이라 클래스·모듈·로그 이름에서 Wx 접두사를 빼는 AGENTS.md 코딩 규칙 1의 예외로 정했다. ([[작업 - datatable-row-rename-reference-update]])
- 대화 VM 분리 작업은 WxCore를 제외한 Wx 기능 모듈 간 신규 의존성을 추가하지 않고 WxGame 조립 계층이 WxUI와 WxDialogue를 연결하도록 했다. ([[작업 - dialogue-presentation-vm]])
- Nameplate 판정 규칙은 게임 규칙이라 WxGame에 두기로 했고, WxUI가 WxCombat을 모르게 하려던 LockOnTargetQuery 델리게이트와 WxCore 계약 인터페이스 안은 채택되지 않았다. ([[작업 - nameplate-manager]])
- 범용 플러그인 DataTableRowFixup은 식별자에서 Wx 접두사를 빼는 코딩 규칙 1의 예외로 정해졌다. ([[결정 노트 - 2026-09-23-datatable-row-fixup]])
- 사용자는 Wx 기능 모듈 사이 의존성 추가를 WxCore 외에는 금지하되 WxCore에 게임 로직을 넣거나 공용 계약에 과도하게 의존하는 구조도 원하지 않는다고 정했다. ([[결정 노트 - 2026-09-23-dialogue-presentation-vm]])
- 상호작용자 몽타주 재생 태스크는 도메인 간 의존 금지 때문에 WxWorld에서 효과 도메인인 WxCombat의 몽타주 1회 재생 태스크로 옮겼다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 2026-09-24 Wx 플러그인 구조의 목적은 다른 프로젝트 재사용이 아니라 게임 내부 도메인 경계를 컴파일 단계에서 강제하는 것으로 다시 정해졌고 구조는 유지된다. ([[결정 노트 - 2026-09-24-module-principles]])
- 모듈 배치는 책임으로 정하며, 시험 질문은 이 코드를 고치게 만드는 기획 변경이 어느 도메인의 것인가이다. ([[결정 노트 - 2026-09-24-module-principles]])
- 계약 인터페이스 조건은 소비자의 책임이 한 도메인 안에 있는 것으로 바뀌었고, 기능 단위 플러그인은 조립 계층으로 허용된다. ([[결정 노트 - 2026-09-24-module-principles]])
- WxCore는 정의 외에 여러 도메인이 쓰는 상태 없는 헬퍼(예: FWxLocatorUtils)를 둘 수 있다. ([[결정 노트 - 2026-09-24-module-principles]])
- 사용자는 락온 계약 인터페이스를 WxCore에 추가하는 안을 원치 않았고, UI와 Combat을 함께 아는 NameplateManager는 의존 팬아웃 원칙에 따라 WxGame으로 옮겨졌다. ([[결정 노트 - 2026-09-24-nameplate-manager-wxgame]])
- 사용자는 2026-09-24 WxCore에서 게임플레이 로직을 구현하지 않고 순수 정의만 두겠다고 밝혀 빈 FWxCoreModule이 제거됐다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])
- 사용자 요청으로 UWxSpawnerLibrary를 제거하고 가능하면 BP 작업이 없도록 C++ 전용 AWxSpawner::RespawnAll로 대체했다. ([[결정 노트 - 2026-09-25-spawner-library-removal]])
- UI 데이터 인터페이스 제거 결정에서 WxCombat은 어빌리티·이펙트 데이터와 규칙, WxUI는 VM·GAS 공통 구독과 갱신, WxGame은 리졸버 연결을 맡으며 도메인 플러그인 간 의존성은 추가하지 않는다. ([[결정 노트 - 2026-09-25-ui-data-interface-removal]])

## 구현 관찰

- AnimNotify 색상 이동으로 WxCore에는 엔진 DeveloperSettings 의존성만 추가됐고 WxAI·WxInventory는 WxCombat을 참조하지 않는다. ([[작업 - animnotify-categories]])
- 2026-09-24 DefaultEngine.ini의 [CoreRedirects] 섹션은 참조 에셋 재저장 뒤 모두 제거되었고, 리다이렉트 없이 관련 BP가 오류·경고 0으로 컴파일되었다. ([[작업 - nameplate-manager]])
- BP 썸네일 코드는 IWxUIData 없이 WxEditor에서 WxCombat·WxGame 타입을 직접 읽으며, 이 두 의존성은 WxEditor에만 추가되었다. ([[작업 - ui-data-interface-removal]])
- 2026-09-23 Ability Resolver를 WxUI로 옮길 때 WxUI.Build.cs에 GameplayAbilities·GameplayTags·ModelViewViewModel 의존성이 이미 있어 추가 의존성이 필요 없었다. ([[결정 노트 - 2026-09-23-ability-resolver-module]])
- 장치 정리에서 FWxDeviceExecutionPolicy, IsRunning 오버라이드, InitialState 사전 검증, TWxStateTreeWaitRegistry 템플릿이 제거되었다. ([[결정 노트 - 2026-09-24-device-statetree-cleanup]])
- 2026-09-24 정적 조사에서 도메인 플러그인 7개는 Wx 모듈 중 WxCore만 의존하고 WxGame은 7개 모두와 WxCore를 의존했다. ([[결정 노트 - 2026-09-24-module-principles]])
- 2026-09-24 BP_PlayerController 재저장 뒤 Nameplate ClassRedirect를 지워 DefaultEngine.ini의 [CoreRedirects] 섹션이 없어졌다. ([[결정 노트 - 2026-09-24-nameplate-manager-wxgame]])
- 2026-09-24 이후 WxCore는 IMPLEMENT_MODULE(FDefaultModuleImpl, WxCore)로 등록된다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])
- 2026-09-24 WxAI의 자동화 테스트 두 개(MirrorMovement 순간이동, 정찰 경로 스폰)와 테스트용 friend 선언이 삭제됐다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])
- 2026-09-25 체크포인트 구조체 StructRedirects 두 개와 빈 [CoreRedirects] 섹션이 DefaultEngine.ini에서 제거됐다. ([[결정 노트 - 2026-09-25-checkpoint-redirect-cleanup]])
- IWxUIData 제거 후 WxEditor 썸네일이 UWxAbilityBase·AWxCharacterBase·UWxEffectComponent_UIData 아이콘을 직접 읽도록 WxEditor에 WxCombat·WxGame 의존성이 추가되었다. ([[결정 노트 - 2026-09-25-ui-data-interface-removal]])

## 미결정·충돌

- 상호작용 대상 락온과 UWxAbility_Interact 모듈 이전은 사용자가 나중에 고민하겠다고 보류했다. ([[작업 - nameplate-manager]])
- UWxAbility_UseItem·UWxAbility_Interact처럼 책임은 다른 도메인이지만 WxCombat UWxAbilityBase를 상속해야 해 WxGame에 있는 코드의 배치 원칙은 사용자가 보류했다. ([[결정 노트 - 2026-09-24-module-principles]])
- Ability.Skill.4·Cooldown.Skill.4·Ability.Pattern.4~9 태그는 참조 0건으로 보였지만 FName 숫자 분리 때문에 에셋 참조를 확정할 수 없어 남겨 두었다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])
