# 피해 파이프라인

피해 요청·계산·결과 반환과 히트 처리 구조에 관한 원자료 요약을 모은 주제 페이지입니다. 문장마다 끝의 링크가 출처이며, 절 이름으로 기획 요구사항·사람의 확정 결정·코드 구현 관찰·검증 범위·미결정을 구분합니다. 구현 관찰은 원자료 작성 시점의 코드 기준이고, 문서 갱신이나 Wiki lint 통과는 게임 동작 검증이 아닙니다.

## 요구사항

- 명조 PC 시스템 역기획서는 피해를 사용 계수×스킬 계수×방어 계수×치명타 피해×피해 증가×속성 저항×부스트로 계산하고 HP·스태거·부조화 3종 피해를 둔다. ([[기획서 - 명조 PC 시스템 역기획서]])
- 명조 PC 시스템 역기획서는 방어 계수를 (800+8×PC레벨)/(800+8×공명자 레벨+적 방어력)×(1−방어무시%)×(1−방어감소)로, 적 방어력을 레벨×8+792로 정의한다. ([[기획서 - 명조 PC 시스템 역기획서]])
- 캐릭터 스탯 명세서는 치명타를 0~100 난수가 CritRate 이하일 때 발생시키고 피해를 기본 피해×(1+CritDMG/100)로 계산하도록 제안한다. ([[기획서 - 캐릭터 스탯 명세서]])
- 캐릭터 스탯 명세서는 피해 처리 순서를 ATK·계수, DEF, 치명타, 가드/패링/회피 확인, 최종 피해, HP 감소, PP 비교, DP 증가, 상태 전환으로 제안한다. ([[기획서 - 캐릭터 스탯 명세서]])
- WX_AM_기능정리 문서는 WX_Spawn_Projectile(투사체 생성), WX_Area_Attack(타게팅 프리셋 범위 피해), WX_Weapon_Attack(무기 피격 판정)을 피해를 주는 노티파이로 정의한다. ([[기획서 - WX_AM_기능정리]])
- WX_AM_기능정리 문서는 피해 노티파이의 데미지 계수·피격 판정·히트 리액션을 DamageDataRow 테이블 행 또는 DamageInfo 에셋 설정으로 지정할 수 있다고 적는다. ([[기획서 - WX_AM_기능정리]])
- 명조 적 시스템 역기획서는 적 공격 피해를 공격력 × 스킬 계수 × 방어 계수 × 치명타 피해 × 피해 증가 × 속성 저항 × 부스트로 계산하고, PC와 적이 같은 방어 계수 공식을 쓰도록 정리한다. ([[기획서 - 명조 적 시스템 역기획서]])
- 명조 적 시스템 역기획서는 적 치명타 피해 증가를 0으로 두고 피해 증가·속성 저항·피해 부스트를 구현 불필요 항목으로 표시한다. ([[기획서 - 명조 적 시스템 역기획서]])

## 확정 결정

- 사용자는 2026-09-23 bool ApplyDamage와 ApplyDamageWithResult의 통합을 요청했고, ApplyDamage가 FWxDamageResult를 반환하는 형태로 합쳐졌다(같은 날 이후 결정에서 다시 변경됨). ([[결정 노트 - 2026-09-23-apply-damage-unification]])
- 사용자는 2026-09-23 구조가 단순하고 직관적인 쪽을 선호하며 Hit Wrapper GE와 전용 EffectContext를 없애고 결과가 앞으로만 흐르는 피해 재설계를 승인했다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
- 사용자는 2026-09-23 Damage GE 내부를 컴포넌트로 나누는 B안을 택했고, 반응 순서는 DamageReaction → PerfectGuard → HitStop → AdditionalEffects다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
- 사용자는 2026-09-23 ApplyDamage가 Damage GE 적용 여부를 bool로 반환하도록 제안했고 FWxDamageResult는 삭제됐다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
- 사용자는 2026-09-23 적대 판정은 ApplyDamage에 두고 사망 확인·방어 판정·추가 효과는 Damage GE 안으로 옮기도록 판단했다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
- 사용자는 2026-09-23 이전 인자의 편의성을 선호해 FWxDamageRequest를 없애고 ApplyDamage를 Causer·Target·피해 행·HitResult 네 인자로 되돌리는 변경을 승인했다. ([[결정 노트 - 2026-09-23-damage-four-arguments]])
- 사용자는 2026-09-23 0 피해 히트스톱 조건 정정과 낡은 주석 정정 제안을 적용하라고 지시했다. ([[결정 노트 - 2026-09-23-zero-damage-hitstop]])

## 구현 관찰

- 2026-09-23 ApplyDamage 통합 당시 출처를 직접 지정하는 C++ ApplyDamageRequest는 유지됐고 출처 추론·피해 처리 정책은 바뀌지 않았다. ([[결정 노트 - 2026-09-23-apply-damage-unification]])
- 2026-09-23 Damage Context 정리에서 소비자가 없던 DamageTable·DamageRowName 필드와 행 이름 직렬화가 제거됐다. ([[결정 노트 - 2026-09-23-damage-context-cleanup]])
- 2026-09-23 Damage Context 정리에서 Context와 FWxDamageResult에 중복되던 피해·반사 수치는 Result 쪽으로 합쳐졌다(같은 날 이후 Context·Result 자체가 삭제됨). ([[결정 노트 - 2026-09-23-damage-context-cleanup]])
- 2026-09-23 Damage Context 정리 후 네트워크 형식은 기본 GameplayEffectContext와 방어 2비트만 남아 서버·클라이언트가 같은 빌드여야 한다. ([[결정 노트 - 2026-09-23-damage-context-cleanup]])
- 2026-09-23 기준 방어 판정은 Damage ExecCalc가 대상 태그로 내리고 Damage.Guarded/Damage.PerfectGuarded 결과 태그를 붙이며, 퍼펙트 가드면 IncomingReflect만 출력한다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
- 2026-09-23 네 인자 ApplyDamage는 Causer의 ASC를 먼저 찾고 없으면 Owner의 ASC를 쓰며 출처 권위 검사를 유지한다. ([[결정 노트 - 2026-09-23-damage-four-arguments]])
- 2026-09-23 네 인자 ApplyDamage에서 투사체는 저장된 발사 레벨을 유지하고 반사로 Owner가 바뀌면 현재 Owner의 ASC를 쓰며, 일반 공격은 AnimatingAbility의 레벨(없으면 1)을 쓴다. ([[결정 노트 - 2026-09-23-damage-four-arguments]])
- 2026-09-23 기준 UWxEffectComponent_Hit의 OnGameplayEffectApplied는 Context 검사, 회피 조기 종료, 피해 적용, 결과 보존, 반응, 추가 효과 적용 순서로 처리한다. ([[결정 노트 - 2026-09-23-hit-processing-functions]])
- UWxEffectComponent_Hit의 EvaluateDefense는 무적·가드 태그만 읽어 EWxDamageDefense를 반환하고 이벤트나 자원 변경을 하지 않는다. ([[결정 노트 - 2026-09-23-hit-processing-functions]])
- UWxEffectComponent_Hit의 ProcessHitReactions는 확정된 FWxDamageResult를 읽어 Hit Cue, 피격/가해 이벤트, 퍼펙트 가드 반응을 처리한다. ([[결정 노트 - 2026-09-23-hit-processing-functions]])
- UWxEffectComponent_HitStop은 Hit Cue와 같은 조건(IncomingDamage 0 초과 또는 Damage.PerfectGuarded)일 때만 히트스톱을 건다. ([[결정 노트 - 2026-09-23-zero-damage-hitstop]])
- UWxEffectComponent_AdditionalEffects는 피해 없는 디버프 행을 위해 0 피해에도 추가 효과를 적용하고 퍼펙트 가드일 때만 생략한다. ([[결정 노트 - 2026-09-23-zero-damage-hitstop]])
- Hit Cue는 UWxEffectComponent_DamageReaction이 서버에서 빈 예측 키로 발행하므로 공격자 클라도 서버 판정 뒤에 받는다. ([[결정 노트 - 2026-09-23-zero-damage-hitstop]])
- 커밋 ca84c9aac로 GC_PerfectGuard는 UWxCueNotify_Hit를 부모로 쓰고 전용 UWxCueNotify_PerfectGuard 클래스가 삭제됐다. ([[결정 노트 - 2026-09-24-wxcombat-cleanup]])
- 커밋 74fc58853으로 피해 ExecCalc의 속성 캡처 정의가 FWxDamageStatics 하나로 합쳐졌고 계산 동작은 바뀌지 않았다. ([[결정 노트 - 2026-09-24-wxcombat-cleanup]])
- 2026-09-24 Damage.Guarded 태그와 ExecCalc의 부착 분기가 삭제됐고 가드 경감·SP 차감에 쓰는 bGuardHit 판정은 유지됐다. ([[결정 노트 - 2026-09-24-wxcore-cleanup]])

## 검증 범위

- 2026-09-23 ApplyDamage 통합의 사용처 확인은 C++·uasset 문자열 검색이며 전체 Blueprint 실행 검증이 아니다. ([[결정 노트 - 2026-09-23-apply-damage-unification]])
- 2026-09-23 Damage Context 정리는 GAS 회귀 테스트의 직렬화 왕복 검사로 확인했으며 실제 네트워크 세션 검증은 아니다. ([[결정 노트 - 2026-09-23-damage-context-cleanup]])
- 2026-09-23 네 인자 복원 당시 Content 문자열 검색에서 ApplyDamage 참조는 없었으며 외부 Blueprint 실행 검증은 하지 않았다. ([[결정 노트 - 2026-09-23-damage-four-arguments]])
- Hit 처리 함수 분리 노트는 빌드·실행 결과를 담지 않으며 실행 검증은 Workflow Task 기록에 맡긴다. ([[결정 노트 - 2026-09-23-hit-processing-functions]])
- 0 피해 히트스톱 변경은 WxEditor 전체 빌드(경고 0)만 통과했고 플레이 검증은 하지 않았다. ([[결정 노트 - 2026-09-23-zero-damage-hitstop]])

## 미결정·충돌

- 캐릭터 스탯 명세서는 DEF 방어 공식, 최소 1 피해 보장, 가드·치명타 대비 DEF 적용 순서, ATK·DEF·스킬 계수 최종 공식을 미정으로 남겼다. ([[기획서 - 캐릭터 스탯 명세서]])
- WX_AM_기능정리 문서는 DamageDataRow와 DamageInfo를 동시에 설정했을 때의 우선순위를 정하지 않았다. ([[기획서 - WX_AM_기능정리]])
- 2026-09-23 기준 히트스톱은 무기·투사체의 C++ 기본값을 쓰며, 공격별 히트스톱이 필요해지면 피해 행+SetByCaller로 옮기는 안을 검토하기로 남겼다. ([[결정 노트 - 2026-09-23-damage-forward-flow]])
