# UI 설계 원칙

UI(위젯·뷰모델·화면 흐름)를 만들거나 고칠 때 따르는, 지금 유효한 규칙만 모은 문서다.
규칙마다 그것을 정한 결정으로 링크한다.
이유·기각한 안·이력은 [UI 구조](UI-구조.md#결정)와 [UI 뷰모델](UI-뷰모델.md#결정)의 결정 절에, 구현 사실과 기대는 엔진 동작은 두 문서의 구현 절에 있다.
규칙이 바뀌면 이 문서의 줄과 해당 문서의 결정 항목을 함께 고친다.

## 원칙

### 출발점
- UI는 Lyra의 CommonUI 구조를 옮긴 것이다. 설계나 버그 수정은 Lyra 원본의 대응 클래스를 먼저 보고 그 방식을 따른다. ([UI 구조 10-06](UI-구조.md#결정))
- 로컬 플레이어는 하나로 전제한다. 화면 분할은 대비하지 않는다. ([UI 구조 09-30](UI-구조.md#결정))
- 코드가 내보내는 표시 문구는 영어다. 기획 데이터 값은 기획자가 에디터에서 필요에 따라 한국어로 바꾼다. 정본은 `AGENTS.md` 규칙 9다. ([UI 구조 10-06](UI-구조.md#결정))

### 층과 의존
- 의존은 모델 → 뷰모델 → 뷰 한 방향이다. 모델은 뷰모델을, 뷰모델은 위젯을 모른다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 모델을 관찰해 뷰모델에 값을 넣고 뷰에 넘기는 조립 층(로컬 PC, 리졸버, 위젯을 만드는 쪽)만 둘을 안다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 모델은 일어난 사실만 델리게이트·태그로 발행하고, 뷰모델을 만들거나 초기화하지 않는다. ([UI 뷰모델 09-05](UI-뷰모델.md#결정))
- 여러 액터에 걸친 게임 상황(보스전 등)은 UI가 신호를 모아 추론하지 않는다. 모델(월드 서브시스템 등)이 상태를 소유하고 발행한다. ([네임플레이트 09-23](네임플레이트.md#결정))
- 뷰모델은 모델 컴포넌트를 약참조로 들고 직접 부른다. 중간 델리게이트나 계약 인터페이스를 새로 만들지 않는다. ([UI 뷰모델 10-01](UI-뷰모델.md#결정))

### 뷰모델의 생성·소유·수명
- 위젯마다 만드는 뷰모델은 리졸버가, 플레이어 공유 뷰모델은 로컬 PC가, 월드 공간 위젯의 뷰모델은 그 위젯을 만든 쪽이 만든다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 만든 쪽이 정리한다. 리졸버는 `DestroyInstance`에서, 위젯을 만든 쪽은 위젯을 뗄 때 그 뷰모델의 모델 구독을 끊는다. 뷰모델이 스스로 모델을 구독하면(Character VM) `Deinitialize`까지 한다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 부모가 자식을 `UPROPERTY`로 들어 소유한다. Outer는 소유가 아니다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 조회로 얻는 뷰모델은 Global Collection에 둔 것(플레이어 공유 뷰모델, 앱 전체에 하나인 것)뿐이다. 나머지는 주인(부모 뷰모델, 조상 위젯의 Context, 목록 항목)에게서 받는다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 소스(모델)를 열쇠로 뷰모델을 찾는 저장소는 두지 않고, `UWxUIManagerSubsystem`도 개별 표시 뷰모델을 소유·등록하지 않는다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정), [UI 구조 10-06](UI-구조.md#결정))
- 공유는 여러 뷰의 표시가 어긋나면 안 되거나 다시 열어도 이어져야 할 때만 한다(플레이어 Character·Inventory). 따로 만들어도 어긋나지 않거나 공유하려면 조회·제거 규칙이 생기면 따로 만든다(적·보스 Character). ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 리졸버는 WBP 클래스가 공유하므로 상태를 두지 않고 배달만 하며, 자기가 만든 뷰모델만 정리한다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 뷰모델은 스스로 구독하고 스스로 갱신한다(자기 타이머 포함). 부모가 자식에게 갱신을 지시하거나 소유자가 공유 티커로 대신 돌리지 않는다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 새 표시·알림 채널은 새 뷰모델 클래스 대신 기존 뷰모델에 필드나 델리게이트를 더한다. 새 뷰모델 클래스가 정말 필요하면 이유를 설명하고 사용자 동의를 받는다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))

### 위젯과 바인딩
- 화면 요소는 WBP에 배치하고 뷰모델 필드에 View Binding으로 잇는다. 위젯 C++ 클래스는 새로 만들지 않고, 먼저 'VM 필드 + 스톡 위젯 바인딩'으로 되는지 따진다. ([UI 구조 08-03](UI-구조.md#결정))
- 위젯 그래프에는 뷰 안에서 끝나는 연출(애니메이션, 목록 항목 넣고 빼기, 표시 형식)과 화면 이동(push, 닫기, 포커스)만 둔다. 도메인 호출은 뷰모델 명령과 MVVM 이벤트 바인딩으로 한다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 목록 항목 위젯은 `OnListItemObjectSet`에서 받은 항목을 자기 뷰모델로 넣는다. 엔진 ListView 뷰모델 확장은 한 프레임 늦어 디자이너 기본값이 비치므로 쓰지 않는다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 상태는 FieldNotify 필드와 상태 바인딩으로 보낸다. 한 번만 반응해야 하는 신호는 뷰모델 델리게이트와 MVVM 이벤트 바인딩으로 보낸다. 상태 바인딩은 뷰 초기화 때 현재 값으로 다시 실행된다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 리졸버로 키별 자식을 받는 위젯은 부모가 다시 초기화될 때 Destruct→Construct를 거쳐야 한다. 아니면 자식을 프로퍼티 경로로 받는다. HUD는 빙의가 바뀔 때 다시 push되므로 앞의 경우다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 자동 갱신(`bGlobalViewModelCollectionUpdate`)은 등록보다 먼저 뜨거나 항목이 바뀌는 것을 따라가야 하는 소스에서만 켠다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 비는 것이 정상 흐름이 아닌 소스는 선택적(optional)으로 두지 않는다. 빙의 해제로 비는 플레이어 Character 소스는 선택적이다. ([UI 뷰모델 09-30](UI-뷰모델.md#결정))
- 변환 함수에서 디자이너가 리터럴로 채울 구조체 인자(태그·어트리뷰트)는 값으로 받는다. ([UI 뷰모델 08-23](UI-뷰모델.md#결정))

### 입력과 명령
- 게임플레이 입력(이동·시점·어빌리티·상호작용)은 캐릭터가 받는다. 위젯은 게임플레이 입력을 받지 않는다. ([UI 뷰모델 10-06](UI-뷰모델.md#결정))
- 메뉴 토글 같은 UI 입력은 CommonUI 액션으로 받는다. 게임 중 상주하는 HUD의 바인딩은 `InputMode=Game`이다. ([UI 구조 06-11](UI-구조.md#결정))
- 뷰가 도메인에 보내는 명령은 뷰모델의 `BlueprintCallable` 함수다. UI 안에서만 뜻이 있는 조작(대사 넘기기·탭 전환)과 마우스로 슬롯을 눌러 쓰는 클릭 사용에만 둔다. ([UI 뷰모델 07-23·10-06](UI-뷰모델.md#결정))
- 위젯 이벤트(버튼 클릭 등)는 이벤트 그래프 노드 대신 MVVM 이벤트 바인딩으로 뷰모델 명령에 잇는다. 창 닫기 같은 수명 문제는 뷰모델 플래그로 두지 않고, 창을 띄운 쪽이 도메인 종료 신호를 받아 닫는다. ([UI 뷰모델 07-29](UI-뷰모델.md#결정))

### 화면 흐름
- 모든 화면은 `UWxUIManagerSubsystem` 경로로 레이어에 push한다. 거치지 않은 위젯은 정지 재평가에서 빠진다. ([UI 구조 07-12](UI-구조.md#결정))
- UI 호출부(PC·어빌리티 등)는 서브시스템을 꺼내 부르지 않고 `UWxUILibrary` 파사드를 쓴다. 없으면 파사드를 더하고, 파사드는 조회 → 널이면 조기 반환 → 위임 순서로 쓰며 반환값을 그대로 넘긴다. 레이어 태그 인자에는 `UPARAM(meta = (Categories = "UI.Layer"))`를 붙인다. ([UI 구조 10-06](UI-구조.md#결정))
- 위젯은 정지를 직접 걸지 않고 `bPauseGame` 데이터만 갖는다. 서브시스템이 활성 위젯을 매번 재평가해 정지를 정하고, 엔진 `FCanUnpause` 대리자 규약에 참여한다. ([UI 구조 07-12·09-03](UI-구조.md#결정))
- 모달은 `Popup`이라 부른다. 전체화면 비모달 뷰는 `Screen`, 토스트·알림은 Toast·Notification이다. ([UI 구조 07-11](UI-구조.md#결정))

### 알려진 예외
- 자막은 StateTree 노드가 뷰모델을 직접 부른다. 자막 상태를 GameState 컴포넌트에 두는 안을 퀘스트 멀티플레이 정책과 함께 보기로 미뤘다. ([UI 뷰모델 미결](UI-뷰모델.md#미결))
- `WBP_FrontEnd`(새 게임 요청, 이동 상태 폴링)와 `WBP_DeathScreen`(부활 요청)은 그래프가 도메인을 직접 부른다. 각자 뷰모델을 두는 안을 검토 중이다. ([UI 뷰모델 미결](UI-뷰모델.md#미결))
