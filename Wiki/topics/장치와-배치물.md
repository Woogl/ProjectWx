# 장치와 배치물

레벨에 놓는 상호작용 오브젝트(장치)와 적 배치 규칙을 모은 문서다. 2026-08-22부터 '기믹' 대신 '장치(Device)'라고 부른다.

## 기획

### 분류 (04-25)
- 스포너블은 체크포인트 상호작용 때 기존 액터를 파괴하고 최초 위치에 다시 만든다. WxSpawner로만 배치하고 클래스 기본값만 쓴다. 예는 졸병·보스·장식물이다.
- 레벨의 모든 적은 WxSpawner로 배치한다.
- 기믹(지금의 장치)은 체크포인트의 영향을 받지 않고 상태를 유지한다. BP를 직접 배치하고 인스턴스마다 편집한다. 예는 문·엘리베이터다.

### 장치 조립 (08-22 회의)
- 기믹을 모듈식 액터인 장치(Device)로 바꿨다. 독립 장치를 배치·조립하고 외부에서 구동한다. 'Gimmick' 용어는 폐기했다.
- 조립 유형은 자체 완결(보물상자·체크포인트), 1:1(문), 1:N(엘리베이터), N:N(피스톤)이다.
- 확장성은 좋지만 조립 경우의 수가 늘어 작업이 복잡해진다. 기획서에 컨텐츠별 조립 예시를 적어 달라고 요청했다.

### 공통 (`Object_Design`, 06-12)
- 외형은 클래스 기본값이고, 상호작용 범위는 구형이다.
- 안내 UI는 "F — [행동]" 형식이고 상태에 따라 보이거나 숨는다.
- 상호작용 UI는 원신처럼 캐릭터 근처에 뜬다. 대상이 겹치면 마우스 휠로 고르고 선택 대상에 외곽선을 그린다(06-21).

### 장치별 규칙
- 문(레버형): 닫힌 동안 통로를 막는다. 레버는 문에 붙은 1회용이고, 한 번 열리면 리스폰 후에도 열려 있다.
- 엘리베이터:
  - 층 사이 경로는 스플라인이다. 1층↔2층만 지원한다(04-25).
  - 탑승 시 문이 열리고 이동 중 닫힌다. 비활성 상태는 형광등 ON/OFF로 보여 준다.
  - 설정은 이동 시간, 초기 활성화 여부, 스플라인이다.
  - 활성화 레버(1회용)와 층 불러오기 레버(층마다 1개, 반복 사용)가 있다. 처음부터 활성이면 활성화 레버가 없다.
- 보물상자: 닫힘·열림 외형이 다르고, Normal·Special은 외형과 효과음만 다르다. 열면 아이템을 주고 영구 개봉 상태로 남는다.
- 체크포인트: [체크포인트와 리스폰](체크포인트와-리스폰.md)에 있다.
- 레버·피스톤(`레버_증기_사양서`, 08-19):
  - 레버를 당기면 연결된 증기 벽이 ON↔OFF로 바뀐다.
  - 레버는 무한히 쓰고, 조작 중에는 다시 못 당기며, 1초에 걸쳐 원위치로 돌아온다.
  - 레버와 증기는 1:N·N:1로 잇고, 증기의 초기 상태는 ON·OFF 둘 다 된다.
  - 증기는 피해·튕김이 없는 벽이다. 세이브 로드와 리스폰 뒤에도 마지막 상태를 유지한다.
- 폐기: 레이저 통로, CCTV 관측기, 스폰 레버, 경보 레버(07-26 기획 답변, 07-31 회의).

### 편집 도구 (08-29)
- 박스 컴포넌트 꼭짓점 피벗 핸들, 연결된 장치 사이 연결선, 장치 초기 상태 인스턴스 편집을 추가했다.

## 구현
- 장치는 `AWxDevice`(`IWxInteractable`)와 기본 부착된 `UWxDeviceStateTreeComponent`로 구동한다(08-22 재편). 장치 종류별 C++ 서브클래스는 없고, 차이는 `AWxDevice` 파생 BP와 ST 에셋이 낸다.
- 에셋 폴더는 아직 `Content/WorldObject/Gimmick`이다. 버튼(`BP_ButtonDevice`·`ST_Button`)·체크포인트·문·엘리베이터·피스톤·보물상자마다 BP_와 ST_ 에셋이 있다. 레버·밸브 전용 장치 에셋은 없다(`SM_Valve`는 메시뿐).
- 상태 식별자는 ST 상태에 단 게임플레이 태그(`Device.<장치>.<상태>`, `WxGameplayTags`의 네이티브 선언)이고 루트 에셋 안에서 유일하다.

### 작동 신호
- 작동 신호는 `AWxDevice::NotifyDeviceInteracted` 하나다. 직접 눌리든 다른 장치가 밀든, 그 상태에서 기다리던 `Wait For Trigger`(`FWxStateTreeTask_WaitForTrigger`)가 Succeeded로 끝나고 그 상태의 「성공 시」 전이가 목적지를 정한다.
- `Wait For Trigger`는 진입에 장치에 등록하고 약한 실행 컨텍스트로 완료를 통보받는다(틱 없음). 받아들이면 바로 등록을 걷어 같은 프레임의 다음 신호는 받지 않는다.
- `Wait For Trigger`가 없는 상태는 작동도 플레이어 상호작용도 받지 않는다. 활성 경로에 하나만 둔다(겹치면 경고하고 나중 것만 받는다).
- 노드 설정은 `bPlayerInteraction`(플레이어 상호작용도 받기)과 `Prompt`, `bOnlyWhenLinkedAccepts`(버튼·레버용), 수락 규칙 `Rule`(`TInstancedStruct<FWxDeviceTriggerRule>`, 비우면 누구에게서든 받음)이다.
- 잠금은 받는 쪽이 정한다. `bOnlyWhenLinkedAccepts`를 켠 버튼은 `LinkedDevices` 중 하나라도 `Wait For Trigger`가 활성일 때만 선택지를 낸다. 클라에 로드되지 않은 연결 장치는 열어 두고 서버가 다시 검증한다.
- 장치끼리 잇기는 `Trigger Linked Devices`(`FWxStateTreeTask_TriggerLinkedDevices`) 하나다. 저작할 값 없이 오너의 `LinkedDevices` 전부에 당사자와 선택지 값을 넘기고, 복원 진입이면 보내지 않는다. 부착된 자식 장치는 `BeginPlay`에 부모 장치를 자기 `LinkedDevices`에 더한다.
- 엘리베이터는 수락 규칙 `Spline Stops`(`FWxDeviceTriggerRule_SplineStops`)를 쓴다. 정차 지점은 스플라인 포인트이고 선택지 값은 포인트 번호다. 밖 호출 버튼은 가장 가까운 지점 하나, 탑승칸 버튼은 지금 지점을 뺀 전부를 내놓는다. 받은 값은 `AWxDevice::SelectedOptionValue`에 남아 스냅샷으로 복제된다.
- 플레이어 쪽 감지·실행 경로는 [상호작용](상호작용.md)에 있다.

### 동기화와 복원
- 동기화: 서버는 활성 상태 태그가 바뀔 때마다 `StateSnapshot`(StateTag·EntrySerial·Interactor·SelectedOptionValue)을 복제한다. 클라는 OnRep에서 직전 번호의 다음이면 라이브 전이, 아니면 복원 전이로 따라간다. 트리를 시작할 때는 `InitialState`로 복원 전이한다.
- 같은 태그로의 재진입과 한 틱 안에 지나간 태그 상태는 발행되지 않는다. 클라에 보여야 할 연출은 잠깐이라도 머무는 별도 태그 상태에 둔다(체크포인트의 `Resting`).
- 복원 전이(`IsRestoring`)에서는 위치·표시 같은 상태 적용만 하고, 소리·몽타주·시퀀스·연결 장치 발동·GE·저장·보상·충전·스포너 같은 일회성 효과는 건너뛴다. 이동 태스크는 목표로 바로 스냅한다(3c4fb1adc).
- 나이아가라(`SpawnNiagara`)는 지속 FX라 진입 경로와 관계없이 재생하고, 상태를 떠나면 제거한다(e0accaab6).
- 장치 상태는 디스크에 저장하지 않는다([체크포인트와 리스폰](체크포인트와-리스폰.md)).
- 적 리젠 제외는 [체크포인트와 리스폰](체크포인트와-리스폰.md#적-리젠)에 있다.

## 결정
- 2026-04-25 배치물을 스포너블과 기믹으로 나눴다. 엘리베이터는 1↔2층만 지원하고, 조건부 활성화 대신 레버를 둔다. (`system_design_feedback.md`)
- 2026-04-30 외형은 클래스 기본값, 범위는 구형으로 정하고, 문 '초기 잠금'과 스포너 '소환 목록'을 지우고, 활성 여부를 '초기 활성화 여부'로 통일했다. (`object_design_feedback.md`)
- 2026-06-21 상호작용 UI 규칙을 정하고, 기믹 내부를 StateTree로 바꾸기 시작했다. (06-21 회의)
- 2026-06-28 장치 상태 어휘를 enum에서 ST 상태 태그로 바꿨다. 상태 어휘·저장 키·ST 진입점을 태그 하나로 합치면 장치마다 C++ 클래스나 상태 필드가 필요 없다. (사용자 결정)
- 2026-07-31 문·엘리베이터·보물상자·체크포인트만 남기고 레이저 통로·스폰 레버·경보 레버·CCTV를 지웠다. (07-31 회의)
- 2026-08-22 기믹을 장치 조립형으로 바꾸고 'Gimmick' 용어를 폐기했다. (08-22 회의, 커밋 cd691ee16)
  - 08-03의 '장치 C++ 액터 클래스 0개' 방침을 뒤집고 공통 호스트 `AWxDevice` 하나로 모았다. 종류별 C++ 서브클래스(`AWxDoor` 같은 것)는 만들지 않는다. (사용자 결정)
  - `Event.Interact`는 스캐너→상호작용 어빌리티의 GAS 트리거 전용으로 남기고 장치 프로토콜에서 뺐다. (사용자 결정)
- 2026-08-22 다른 장치를 잠글 때 활성 플래그를 건드리지 않고 목적지 상태 태그를 이벤트로 보냈다(`이벤트 보내기`, `Device.Button.Locked`). 발동 이벤트는 기본 `Event.Device.Triggered`, 갈래가 필요하면 목적지 상태 태그였다. 두 번째 잠금 플래그 `bInteractionLocked`(08-22)와 런타임 발신자 기억 `InstigatorDevice`(08-23)는 이때 지웠다. 이 방식은 09-21 재설계로 모두 대체됐다. (사용자 결정)
- 2026-08-25 스트리밍-인 복원에서 `InitialState`가 '기본→초기→저장' 홉을 하나 더 거치는 문제를 보류했다. 09-01 세이브 제거로 저장 복원 경로가 사라져 지금은 해당하지 않는다. 이 홉을 먼저 제안하지 않고, 세이브를 다시 넣은 뒤 플레이 중 거슬리면 `ResetTransitionRequests`를 '대기 요청이 모두 옛 상태를 향할 때만'으로 좁힌 형태부터 본다. 복원을 레벨 가시화 직전으로 당기는 안은 컴포넌트 초기화 전이라 너무 이르다고 기각했다. (사용자 결정)
- 2026-09-21 작동 신호를 하나로 합치고, 어디로 갈지는 받는 쪽의 `Wait For Trigger`와 「성공 시」 전이가 정하게 했다. 엔진 순정 규칙을 벗어난 자체 장치는 트리 디버거에 보이지 않아 추적이 어렵다는 이유다. 잠금 여부가 곧 '받는 장치의 대기 노드가 활성인가'라 디버거에 그대로 보인다. (사용자 결정, 커밋 f87b5e3ae)
  - ST 이벤트·델리게이트 전이, 상태 태그를 이벤트로 보내는 '그 상태로 가라' 명령, 다른 장치를 잠그는 노드·회신 신호·버튼의 Locked 상태, 활성 플래그는 다시 넣지 않는다.
  - 대기 노드는 종류별로 나누지 않는다. 다른 것은 설정뿐이라 장치 전용 설정은 수락 규칙 구조체에 두고, 새 규칙이 필요하면 `FWxDeviceTriggerRule` 파생을 더한다.
  - 목적지는 상태가 아니라 선택지 값(`SelectedOptionValue`)으로 나른다. 08-22에는 이동 상태 아래 방향별 자식을 두면 태그로 들어갈 때 첫 자식이 골라져 반대로 가서 `Device.Elevator.Moving`을 지웠는데, 지금은 방향을 값이 들고 `Moving` 태그가 다시 있다.
- 2026-09-22 동기화를 '서버는 태그 상태가 바뀔 때 발행, 클라는 통지받은 순간에만 판단'으로 줄였다. 클라가 통지 사이에 제 타이머로 앞서가도 되감지 않는다. 서버만 트리를 돌리고 결과를 복제하는 안은 이동·프롬프트·연출마다 복제 통로가 필요해 기각했다. (사용자 결정, 커밋 d7e384b50)

## 미결
- 장치 기준의 배치물 문서가 없다. 개별 동작 규칙은 아직 `Object_Design`(06-12)에만 있다. 08-22의 조립 예시 요청과 07-31의 기획서 갱신 요청이 반영되지 않았다.
- 증기와 피스톤 이름이 통일되지 않았다. 파일명만 '증기'다.
- 증기 경로에 캐릭터가 있을 때의 처리가 없다.
- 기획의 '레벨 이동·재접속·스트리밍에도 상태 유지' 요구는 09-01 세이브 제거 뒤 구현되지 않았다. 장치 상태는 디스크에 저장하지 않고, 레이트조인 클라 수렴만 있다.
