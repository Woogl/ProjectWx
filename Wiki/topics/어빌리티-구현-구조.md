# 어빌리티 구현 구조

어빌리티(GA)와 이펙트(GE)를 C++과 에셋에 어떻게 나눠 두는지, 순정 GAS와 다르게 도는 곳, 다시 꺼내지 않을 대안을 모은 문서다.
캔슬·차단·콤보 같은 게임 규칙은 [어빌리티 규칙](어빌리티-규칙.md)에 있다.

## 구현

### 코드와 에셋의 분담
- 어빌리티 하나는 C++ 타입(`UWxAbilityBase` 파생)을 부모로 둔 데이터 전용 `GA_` 에셋 하나다.
- 로직은 C++에만 있다. `GA_` 40개 모두 이벤트 그래프에 함수 호출 노드가 없다(10-05 에셋 확인).
- 값은 아래처럼 나뉜다.

| 무엇 | 어디 |
|---|---|
| 식별 태그, 차단·취소 태그, 기본 발동 조건, 인스턴싱(`InstancedPerActor`)·네트 실행(`LocalPredicted`) | C++ 타입 생성자 |
| 입력, 몽타주, 추가 발동 조건, 쿨다운 GE 지목, 비용, 활성 중 효과, 표시(제목·설명·아이콘) | `GA_` 에셋 |
| 쿨다운 시간·충전 수·쿨다운 태그 | 쿨다운마다 `GE_` 에셋(부모는 엔진 `GameplayEffect`) |
| 이동(회피·넉백 포함) | 몽타주의 애니메이션 루트모션. 대상까지 달려가는 돌진만 `UWxAbilityTask_Rush`(루트모션 소스)다 |
| 타격·캔슬·무적 시점 | 몽타주 노티파이(`WxAnimNotifyState_ComboWindow`, `WxAnimNotify_StartRecovery`, `WxAnimNotifyState_WeaponAttack`, `WxAnimNotify_AreaDamage`, `WxAnimNotifyState_ApplyGameplayEffect`) |
| 피해 계수와 반응 | `DT_Damage` 행(여러 노티파이·투사체가 골라 쓰는 수치라 표로 남았다) |
| 수치가 있는 GE | `GE_` 에셋(C++ 부모는 지속 정책·태그·모디파이어 배선만 쥐고 `UCLASS(Abstract)`다) |
| 수치가 없는 상태 GE | C++ 클래스(코드가 `StaticClass()`로 건다) |
| 부여 어빌리티, 상시 효과, 속성 초기값 행 | `WxAbilitySet`(`ABS_`)의 `GrantedAbilities`·`GrantedEffects`·`AttributeInitRow` |
| 세트 부여 순서 | 캐릭터 BP의 ASC `AbilitySets` |
| 게임플레이 태그 | `WxGameplayTags.h`·`WxGameplayTags.cpp`의 네이티브 선언(태그 ini 없음) |

- 몽타주는 베이스의 `AbilityMontage` 하나에 섹션 이름 규칙으로 갈래를 둔다. 8방향(`EWxAbilityDirection`), 반응 태그의 끝 이름, 착지 `Grounded`가 섹션 이름이다.
- 콤보 계열(Attack·Skill·Pattern)만 공통 부모 `UWxAbility_Combo`의 `ComboMontages` 배열을 쓴다.
- UI 슬롯은 어빌리티 에셋 태그로 어빌리티를 찾는다. `UWxViewModel_Ability`가 에셋 태그가 요청 태그를 모두 포함하는(`HasAll`) 어빌리티 중 소유자 발동 조건을 만족하는 첫 하나를 보이고, 아이콘은 소프트 참조라 뷰모델이 비동기로 읽는다.
- 슬롯 뷰모델은 태그 컨테이너가 정확히 같을 때만 공유하고, 빈 컨테이너는 아무 어빌리티나 맞으므로 거부한다(`UWxViewModel_AbilitySystem`).
- 에셋 값은 `.agents/scripts/Export-AbilitySystemLists.ps1`이 `Saved/AbilitySystemLists/`에 표로 뽑는다. 표의 빈 칸은 '없음'이 아니라 C++ 기본값을 따른다는 뜻이다.
- `UWxEffect_DrainSP`·`UWxEffect_RegenSP`·`UWxEffect_Exhaust`는 수치를 C++ 상수로 가진다. 탈진은 결정에 따른 것이다([스탯과 피해 계산](스탯과-피해-계산.md#결정)).

### 입력 라우팅
- 입력 키는 어빌리티 CDO의 `ActivationInputAction` 하나다.
- `AWxPlayerCharacter`가 ASC의 `GetAbilityInputActions`(세트가 부여하는 어빌리티의 IA)를 Triggered·Completed에 묶는다. Triggered는 `UWxInputBufferComponent`를 거쳐 ASC로 간다.
- ASC의 `TryActivateByInputAction`은 같은 IA의 활성 어빌리티에 InputPressed 이벤트를 먼저 보낸다. 콤보 창의 `WaitInputPress`가 받으면 입력은 거기서 끝난다.
- 받는 쪽이 없으면 부여 순서대로 발동을 시도해 처음 성립한 하나만 낸다. 그래도 실패하면 활성 어빌리티에 `AbilitySpecInputPressed`를 부른다(락온 해제).
- 키 상태는 순정 `AbilityLocalInputPressed`처럼 Triggered에서 같은 IA 스펙의 `Spec.InputPressed`를 활성 여부와 무관하게 세우고 Completed에서 내린다. 선입력 재시도(`TryActivateByInputAction`)는 세우지 않는다.
- 가드는 로컬 플레이어에서만 `CanActivateAbility`로 이 값을 본다. 그래서 키를 뗀 뒤 선입력 재시도로 가드가 켜지지 않는다.
- 같은 IA에 조건이 겹치는 어빌리티가 있으면 부여 순서가 이긴다. `UWxAbilitySet::IsDataValid`는 한 세트 안의 겹침만 경고하고 세트 사이는 보지 않는다.
- 어빌리티가 입력 처리를 오버라이드하는 곳은 락온의 `InputPressed`, 가드·질주의 `InputReleased`뿐이다.
- 처형·상호작용은 GameplayEvent로 발동해 입력 라우팅 대상이 아니다.
  상호작용 입력은 캐릭터가 컨트롤러의 스캐너에 직접 연결하고, 선택한 대상의 실행은 [상호작용](상호작용.md#흐름)의 서버 이벤트 경로를 따른다(2026-10-06, d9768ca8d).

### 순정 GAS와 다르게 도는 곳
- 쿨다운(10-05부터, e2eddf46c):
  - 쿨다운마다 `GE_` 에셋을 두고 `GA_`의 엔진 칸 `CooldownGameplayEffectClass`로 지목한다. 같은 GE를 지목한 어빌리티끼리 쿨다운을 나눠 쓴다([현광](../entities/현광.md) 궁극기1·2).
  - 각 GE는 지속시간과 `Cooldown` 아래 태그 하나를 직접 갖는다. 회피(2초, 충전 2)만 엔진 스택을 쓴다: 대상 기준으로 쌓고, 상한이 충전 수이며, 쌓일 때 시간을 갱신하지 않고, 만료되면 스택을 하나만 빼고 시간을 다시 잰다.
  - 남은 커스텀은 `CheckCooldown` 하나다. 엔진은 쿨다운 태그가 붙어 있기만 하면 막으므로, 스택이 충전 수보다 적으면 통과시킨다.
- 비용: 공용 GE `UWxEffect_Cost`의 자원별 MMC가 어빌리티 CDO의 `CostResource`·`CostAmount`를 읽는다. 검사와 지불은 순정 `CheckCost`·`ApplyCost`다. `CostGameplayEffectClass`는 `GA_`에서 커스텀 GE로 바꿀 수 있고, 쓰는 `GA_`는 아직 없다.
- 면제 GE는 셋이다. 분신·도플갱어 세트가 단다.
  - `UWxEffect_IgnoreCosts`: `Effect.IgnoreCosts` 태그로 비용 검사·지불을 건너뛴다.
  - `UWxEffect_IgnoreCooldowns`: 쿨다운 GE를 면역하고 걸려 있던 것도 걷는다.
  - `UWxEffect_IgnoreAbilityActivationTags`: 소유자 기준 발동 조건(Required·Blocked)을 면제한다.
- 발동 조건: `DoesAbilitySatisfyTagRequirements`를 오버라이드했다. 재생 중인 액션을 `CancelAbilitiesWithTag`로 지목한 어빌리티는 그 액션이 건 차단 1건을 빼고 판정한다.
- 어빌리티는 자기 `Ability.*` 태그를 `ActivationOwnedTags`로 발행하고, 다른 어빌리티의 Required·Blocked가 그것을 읽는다(회피 중에만 회피 반격, 가드 중이면 GuardReact).
- 활성 중 효과: `GA_`의 `ActivationOwnedEffects`를 활성화에서 걸고 종료에서 걷는다. `ActivationOwnedTags`의 GE판이다.
- 방향 섹션: `PlayMontage`가 이동 입력으로 8방향 섹션을 고른다. 원격 플레이어의 서버 실행은 클라이언트가 TargetData로 보낸 방향을 기다린다.
- 패시브: `UWxAbility_Passive` 하나에 순정 `AbilityTriggers`(언제)와 `TriggeredEffects`(무엇)를 조립한다. 트리거가 올 때마다 지급한다.
  - 서버 전용(`ServerOnly`)이고, 트리거를 여럿 두면 아무거나 와도 효과 묶음 전체를 건다. 트리거끼리 조상 관계면 한 이벤트에 두 번 걸리므로 데이터 검증이 오류를 낸다.
- GAS 전역 설정은 `Config/DefaultGame.ini`의 `[/Script/GameplayAbilities.AbilitySystemGlobals]` 섹션에 있다(`AbilitySystemGlobalsClassName`, `GameplayCueNotifyPaths`).

### 엔진 동작에 기댄 곳
- 애니메이션 루트모션이 도는 동안 이동 컴포넌트는 몸을 돌리지 않는다(`bAllowPhysicsRotationDuringAnimRootMotion` 엔진 기본값 false). 회피가 이동 방향 회전·락온 회전에 끌리지 않는 것은 이 동작 덕분이다.
- 마지막 섹션은 끝나기 블렌드아웃 시간(기본 0.25초) 전에 블렌드아웃을 시작하지만, 섹션 끝까지 재생하며 그동안 루트모션도 100% 들어간다. 블렌드아웃 중 이동이 거슬리면 몽타주의 `BlendOutTriggerTime`을 0으로 둔다.
- 루트모션이 꺼진 몽타주 구간(`DisableRootMotion`)에서는 이동 컴포넌트가 이동 입력을 그대로 받아, 포즈는 제자리인데 몸은 걸어간다.
- 몽타주는 슬롯 그룹 단위로 서로 끊는다. 그래서 가산 피격은 다른 슬롯 그룹에 두고, 같은 그룹의 넉·패리 반응은 패턴 몽타주를 밀어낸다.
- 메시 등록 해제 중 몽타주 강제 종료가 인터럽트 콜백을 재진입시킨다. 래그돌 진입(`AWxCharacterBase::EnterRagdoll`)이 월드 정리·액터 파괴 중인지 보고 건너뛴다. `IsRegistered()`는 그 시점에 아직 참이라 가드가 되지 않는다.
- 공격 예고는 순정 GameplayCue 노티파이(`AnimNotify_GameplayCueState`)로 낸다. 순정 노티파이는 크기·길이를 0으로 넘기므로 큐(`AWxCueNotify_AttackTelegraph`)는 Niagara 자체 길이로 재생한다.
- 순정 GameplayCue 노티파이는 큐를 복제 없이(`AddGameplayCue_NonReplicated`) 각 머신에서 로컬로 낸다. 복제되는 몽타주가 시점을 나르므로 권위 가드를 두지 않는다.
- 엔진은 발동할 때마다(`PreActivate`) `bIsBlockingOtherAbilities`를 다시 켠다. 후딜 판정을 이 값에 맡길 수 있는 이유이고, 한 활성화 안에서 단계를 잇는 콤보·패턴만 `ResetActionState`로 다시 켠다.
- 서버의 `WaitInputPress`는 창보다 먼저 도착한 클라이언트 입력을 엔진 캐시(`CallReplicatedEventDelegateIfSet`)에서 받아 창이 열릴 때 넘긴다. 콤보가 서버에서도 자기 창 동안만 들을 수 있는 이유다. 네트워크 PIE로는 확인하지 않았다(10-02 기준).
- GAS 프로젝트 설정(`UGameplayAbilitiesDeveloperSettings`)은 `OverrideConfigSection`으로 옛 `[/Script/GameplayAbilities.AbilitySystemGlobals]` 섹션에서 읽힌다. 클래스 이름 섹션에 적으면 통째로 무시되고, 기본값도 유효 클래스라 크래시 없이 조용히 넘어간다(08-11 커스텀 EffectContext가 이렇게 빠졌다).
- AI 폰도 서버에서는 로컬 조종으로 읽힌다. 그래서 가드의 입력 게이트(`UWxAbility_Guard`의 `CanActivateAbility`·`IsInputHeld`)는 `IsLocallyControlledPlayer`일 때만 건다. 막지 않으면 누른 적 없는 키 상태 때문에 AI 가드가 계속 막힌다.

## 결정
- 2026-10-05 GameplayAbility 로직은 C++로만 짜고 BP 이벤트 그래프를 쓰지 않는다. `GA_`는 값만 채운다. AI 입장에서 텍스트로 읽고 검색·수정할 수 있는 쪽이 낫다는 판단이다. (사용자 결정)
- 2026-10-05 쿨다운을 쿨다운마다 `GE_` 에셋으로 두는 엔진 기본 방식으로 바꿨다. 순정에 가깝고 코드가 가장 많이 줄어드는 쪽이다. 공용 쿨다운 GE, `GA_`의 쿨다운 칸 3개(시간·태그·충전 수), 쿨다운 오버라이드 3개(GE 선택·태그·적용)와 대기열 계산, 쿨다운 검증 2개를 지웠다. 대가로 쿨다운 값이 `GA_` 밖(`GE_`)에 있게 되어 09-25 'GA_ 한 곳' 방향과 일부 어긋나는데, 사용자가 받아들였다. 5.8은 스택 GE 적용을 예측하므로(`AbilitySystem.AllowPredictiveStackingGEs`) 충전도 예측된다. 공용 쿨다운 GE와 `GA_`의 쿨다운 칸은 다시 넣지 않는다. (사용자 결정, 커밋 e2eddf46c)
- 2026-10-05 회피·피격 넉백·가드 넉백을 다시 애니메이션 루트모션으로 움직인다. 10-01(`a25fa1d93`)에 일정 속도 이동(`ApplyRootMotionConstantForce`)으로 바꾸고 섹션 전체에 루트모션을 끄는 노티파이를 깔았는데, 애니메이션의 가속·감속과 맞지 않아 미끄러지고 이동이 도중에 끊겼다. 일정 속도 루트모션 소스로 애니메이션 루트모션을 덮지 않는다. 거리·방향 보정이 필요하면 모션 워핑(처형·스냅 선례)을 먼저 본다. 일정 속도 이동에 딸렸던 거리·시간 속성(`DodgeDistance`·`KnockbackDistance` 등)과 회피의 이동 회전 잠금도 함께 지웠다. (사용자 결정 "모든 애니메이션에 루트모션", 커밋 c53c7465e)
- 2026-09-25 어빌리티 테이블 구동(`DT_Ability`)을 거두고 데이터 전용 `GA_` 에셋으로 돌아갔다. 판단 기준은 'AI가 구조를 파악하고 작업하기 편한 쪽'이었다. 같은 날 `DT_Effect`와 행을 읽던 MMC도 지우고 GE 수치를 `GE_` 에셋에 직접 둔다. 행이 에셋과 1:1이면 값은 그 에셋에 둔다는 기준이다. (작업 기록, 커밋 e305161ee·7c52ce0ce)
  - 09-01의 'GE 수치는 `DT_Effect` 행에서 읽고 `DurationMagnitude`도 `WxMMC_EffectDuration`으로 읽는다' 규칙과 어빌리티 아이콘을 `DT_Ability` 행에 두던 방식도 이때 사라졌다.
- 2026-07-22 입력 라우팅 키를 어빌리티 CDO의 `ActivationInputAction` 하나로 정했다. CDO 기본값은 복제 없이 서버·클라이언트에 모두 있어 클라이언트 라우팅이 바로 읽는다. (커밋 fa70379be)
  - `Input.*` 태그 13개, `IsActivationInput`·`IsObservedInput` 가상 함수, 강공격·반격용 명명 IA 필드, `LastPressedInputAction` RPC, `UWxAbilityTask_WaitInputActionPressed`, `OnInputActionTriggered` 브로드캐스트는 다시 넣지 않는다. 강공격·회피 반격은 자기 IA를 가진 별도 어빌리티다.
  - 세트 항목이나 `UWxInputConfig`에 어빌리티 IA를 두는 안은 같은 이유로 기각했다.
- 2026-07-23 어빌리티별 UObject 컴포넌트 앵커(`UWxAbilityComponent`)를 지웠고 다시 넣지 않는다. 아이콘 하나를 나르던 확장점이었다. 표시 데이터는 `GA_`의 `Wx|Display` 칸에 더한다. (사용자 결정)
- 2026-08-10 쿨다운·비용 GE를 커스텀 GE로 바꿔 끼우는 경로는 쓰는 곳이 없어도 유지한다. '체력 50% 미만이면 2배 빨리 회복' 같은 특수 쿨다운에 쓸 예정이다. 죽은 코드로 보고 제거·단일화를 제안하지 않는다. (사용자 결정) 10-05부터 쿨다운은 이 경로가 유일한 경로다.
- 2026-08-19 런타임 계산이 필요한 GE 지속시간은 걸기 전에 계산해 SetByCaller로 싣는다. 활성 GE를 세는 MMC는 엔진이 삽입 뒤 지속시간을 다시 계산할 때 자기 자신까지 세어 쿨다운이 2배로 걸렸다. SetByCaller는 몇 번 되읽어도 같은 값이다(예: `UWxEffect_HitStop`의 `SetByCaller.Duration`). 특수 쿨다운 GE의 지속시간 계산도 활성 GE를 세지 않는다. (사용자 결정)
- 2026-08-21 몽타주는 어빌리티 클래스가 소유한다. 아바타 태그와 트리거 태그로 몽타주 세트를 고르던 `FWxMontageSelector`는 실사용이 0건이라 지웠고 다시 넣지 않는다. 갈래가 필요하면 섹션이나 어빌리티 분리로 한다. (커밋 49e3f5231)
  - 이때 둔 피격·가드 반응의 종류별 몽타주 필드는 09-24에 반응 태그 이름의 섹션으로 합쳤고(30f873038·ed40b5663), 콤보 계열은 09-25부터 공통 부모 `UWxAbility_Combo`의 `ComboMontages` 배열을 쓴다(b6f1e9e8c).
- 2026-08-22 어빌리티는 자기 `Ability.*` 태그를 `ActivationOwnedTags`로 발행하고, 다른 어빌리티의 발동 조건이 그것을 읽는다. 06월의 '발행 금지' 규칙은 소비자가 생겨 폐기됐다. (코드 확인)
- 2026-09-02 수치가 있는 GE는 `GE_` 에셋으로 저작하고, C++ 부모는 배선만 쥔 `UCLASS(Abstract)`로 둔다. 어빌리티는 그 GE를 `GA_`의 `ActivationOwnedEffects`로 지목한다. 표 주소를 ini로 전역화하는 안은 쿠킹 참조가 끊기고 실패가 조용해서 거부했다. (사용자 결정)
- 2026-09-02 UI 슬롯은 어빌리티 자신의 에셋 태그로 어빌리티를 지목한다. 슬롯 전용 태그 축이나 슬롯 표는 같은 사실을 두 곳에 적게 해서 만들지 않는다. (사용자 결정)
- 2026-09-19 엔진에 대응 개념이 있으면 이름도 엔진 어휘를 따른다. 비용·쿨다운 무시 GE는 엔진 치트(`ShouldIgnoreCosts`·`ShouldIgnoreCooldowns`)의 액터 단위판이라 `IgnoreCosts`·`IgnoreCooldowns`다. (사용자 결정)
- 2026-10-05 패시브는 새 어빌리티 클래스 없이 `UWxAbility_Passive`에 GE와 트리거를 조립하고(08-26), 트리거마다 지급한다. 콤보를 한 활성화로 바꾼 뒤 예측 키 판정이 콤보당 1회만 지급하던 결함을 고친 것이다. (사용자 결정, 코드 리뷰 C01, 커밋 1508c1632)
  - 예측 키, 공격 ID 인자, (공격자, 공격 번호) 판정, 마지막 지급 시각 비교, GAS 쿨다운은 다시 넣지 않는다. 다단·범위 타격의 지급량은 GE 수치나 기획으로 다룬다.
  - `TriggeredEffects`를 `ActivationOwnedEffects`와 합치지 않는다. 후자는 종료에서 걷혀 지속형 효과가 같은 프레임에 사라진다.
- 신규 어빌리티·GE C++ 클래스는 정말 고유한 동작에만 만든다. 새 동작이 기존 타입의 책임 안이면 기존 타입을 넓히고, 수치만 다른 효과는 `GE_` 에셋으로 만든다. 클래스가 늘면 추적·유지보수 부담이 커진다는 이유다. (사용자 결정, 날짜 미상)
- 2026-07-18 공격 예고 큐는 순정 GameplayCue 노티파이로 내고, 전용 노티파이(`UWxAnimNotifyState_AttackTelegraph`)는 지웠다. 큐가 Niagara에 길이를 주입하는 방식은 순정 노티파이가 0을 넘겨 쓰지 않는다. (사용자 결정)

## 미결
- 특수 쿨다운(체력 50% 미만이면 2배 빨리 회복 등)은 해당 쿨다운 GE의 지속시간 계산으로 넣을 수 있지만 설계는 시작하지 않았다.
- 대상까지 달려가는 돌진(`UWxAbilityTask_Rush`)은 아직 루트모션 소스로 움직인다. 애니메이션 루트모션으로 바꾸려면 모션 워핑으로 목표 위치를 맞춰야 한다.
- `UWxEffect_Exceed`는 C++ 상수 수치를 가진 채 거는 코드·에셋이 없다. `GE_Exceed`는 09-09에 지워졌다.
