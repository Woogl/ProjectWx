# Wiki 유지 관리

## 한줄 요약

재사용할 프로젝트 지식을 기존 정본에 통합하고 근거·문서 구조·링크를 검증합니다.

[작성 규칙](AGENTS.md)은 필수 원칙, 이 문서는 Wiki 관리 절차를 설명한다. 프로젝트 지식은 [목차](index.md), 개발 작업 절차는 [Workflow](../workflow/index.md), 도구의 저장·복구·실행 구조는 [Wiki·Workflow 도구 구조](knowledge/tooling/wiki-workflow.md)에서 찾는다.

## 지식 반영과 갱신

1. 목차에서 관련 주제와 기존 정본을 찾고 코드·설정·기획 원자료를 확인한다. 파일 변경이나 오래된 확인일만으로 문서 오류를 단정하지 않는다.
2. 다음 작업에서 같은 조사나 판단을 반복하지 않도록 현재 동작·제약·결정 이유를 기존 정본에 통합한다. 요구사항·구현 관찰·확정 결정·추론·미결정을 구분한다.
3. 게임·프로젝트 지식과 기능별 작업 방법은 `knowledge/<주제>/`에, 기획·구현·리뷰·테스트의 공통 진행 절차는 `.agents/workflow/process/`에 둔다. 작은 주제는 한 문서로 유지하고 빈 폴더나 가이드 목록을 만들지 않는다.
4. 주제 개요에는 책임·경계·진입점·읽는 순서를 둔다. 상세 기능은 대표 페이지 한 곳에서 설명하고 관련 주제에서 연결한다. 모듈 이름은 제목·본문·목차에서 검색할 수 있게 유지한다.
5. 본문에 원자료 경로·심볼·확인 범위·기준 버전·미검증 사항을 남긴다. 문서 이동은 재검증이 아니며 기존 상태·검토일·기준을 승계한다. 미검증 문서를 이동만으로 current로 올리지 않는다.
6. 관련 문서와 목차·README·스킬의 참조를 맞춘다. `sources.json`에는 페이지 상태·현재 확인 범위·참고 기준만 유지하고 날짜별 변경 경위를 누적하지 않는다. 파일 해시·감시 루트·원자료 의존 목록은 관리하지 않는다.
7. 구조·링크와 내용의 일관성을 확인하고 뷰어를 다시 생성한다. 결과와 남은 미확인 사항은 대화로 전달한다.

## 작업 방법 작성

완료한 작업에서 재사용할 절차가 생겼을 때 해당 주제의 정본에 통합한다. 대상 독자·준비 사항·수행 순서·결과 확인·주의점을 설명하고 근거와 검증 범위를 연결한다. 새 어빌리티 추가 방법은 `knowledge/combat/`, 코드 리뷰·승인 절차는 `.agents/workflow/process/`에 둔다. 내용이 길어질 때만 별도 페이지로 나누고 주제 개요에서 연결한다. 가이드를 만드는 것 자체는 필수가 아니다.

## 다이어그램 작성과 검증

관계는 flowchart, 호출 순서는 sequenceDiagram, 상태·전이 조건은 stateDiagram-v2로 작성한다. 데이터 관계는 classDiagram 또는 erDiagram을 사용할 수 있다. 전체 타입 목록 대신 문서의 질문에 답하는 최소 관계를 그린다. Markdown의 mermaid 코드 블록을 정본으로 유지하고 별도 이미지에 같은 내용을 수동 관리하지 않는다.

그림 앞에 무엇을 표현하는지와 제외 범위를 설명한다. 기획과 구현을 섞지 않으며 미확정 선택은 비교·분기로 표시한다. 노드와 화살표의 주장은 본문의 코드·기획 근거까지 추적할 수 있어야 한다. 그림 추가만으로 문서의 검증 상태나 기준 버전을 올리지 않는다. 관련 설명을 변경하면 그림의 식별자·방향·전이 조건·미결정 표시도 확인한다.

뷰어 생성 후 실제 렌더링과 원문 표시, 문법 오류 시 복구를 확인한다. 렌더러는 버전이 고정된 로컬 Mermaid를 HTML에 포함하며 외부 CDN을 요청하지 않는다. Mermaid 원문에서 초기화 지시문·frontmatter 설정을 사용하지 않는다. 테마와 보안 설정은 뷰어에서 관리한다. 그림은 표시용 이미지로 격리하고 노드 클릭 실행은 지원하지 않는다.

## 링크 점검

저장소 루트에서 다음 명령으로 Wiki·작업 자료·안내 README의 로컬 Markdown 링크 대상 존재 여부만 확인한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agents/scripts/CheckWikiLinks.ps1
```

종료 코드는 정상 0, 링크 오류 1, 도구 실패 2다. 원자료 해시·Git 기준·문서 상태·목차 도달성은 검사하지 않는다. 섹션 앵커·외부 URL·문장 의미는 검사 범위 밖이다. 내용의 최신성은 AI가 관련 원자료와 대조해 판단한다.

## 내용과 구조 점검

목차에서 각 지식 페이지에 도달할 수 있는지, 같은 규칙을 중복 설명하는지, 문서 사이에 모순이 있는지 확인한다. 근거 없는 단정·원자료까지 추적되지 않는 인용·변경된 근거와 어긋나는 설명은 AI가 원자료와 대조한다. 미결정은 해당 주제의 항목으로 연결하며 사람의 확정 없이 해소하지 않는다. 링크 검사 통과는 내용 검증이 아니다.

문서 변경 후 `pwsh -NoProfile -File .agents/scripts/Export-Wiki.ps1`로 Wiki와 Workflow 뷰어를 다시 생성한다. 생성기는 Markdown과 sources.json을 읽으며 문서를 상시 감시하지 않는다. 경로 변경이 뷰어에 영향을 주면 기존 `TestWikiSpaces.cjs`와 `TestWikiViewer.cjs`로 검색·탐색·라우팅을 확인한다.

## 작업 기록과의 연결

작업 재개·완료·보존·정리는 [Workflow 작업 기록 관리](../workflow/process/records.md)를 따른다. Wiki에는 재사용할 현재 동작·제약·확정 규칙과 필요한 결정 이유만 통합한다. 작업별 판단 원문과 조치 상태는 작업 자료에 두고 연결하며, Wiki 갱신 이력은 Git에서 확인한다.

공용 WxCore·Config·기획 변경은 관련 설명에 미치는 영향을 AI가 확인한다. 에셋 설정을 설명할 때에는 실제 원본과 추출 근거·엔진/추출기 버전·미확인 범위를 본문에 남긴다.

여러 작업자가 갱신하면 본문 파일 단위로 작업을 나누고, `sources.json`·목차는 한 작업자가 합친다. 상시 문서 감시와 원격 검색 서버는 도입하지 않았으며 로컬 AI 연결만 사용한다.
