# Wiki 운영

상태: current · 범위: Wiki 운영 규약 · 2026-09-20

## 읽기

[목차](index.md)에서 모듈 또는 시스템을 고른다. 상태와 확인 범위를 읽고, 실제 코드 변경에 필요한 주장은 링크된 원자료에서 다시 확인한다. `needs-review` 페이지는 탐색 지도이며 최신 구현의 보증이 아니다.

## 로컬 웹 뷰어

[OpenWiki.bat](../../BatchFiles/OpenWiki.bat)을 더블클릭하면 Wiki와 보고서를 검색할 수 있는 브라우저 화면을 생성한다. PowerShell 7을 사용하며 PATH에 없으면 현재 사용자에게 설치된 Codex 번들 런타임을 확인한다. 둘 다 없으면 PowerShell 7 설치가 필요하다.

Markdown과 sources.json이 정본이며 `.agents/scripts/Export-Wiki.ps1`이 `Saved/Wiki/index.html`을 생성한다. 서버·외부 CDN 없이 열리며 문서 변경 후 실행기를 다시 실행해야 갱신된다. 검증 상태는 manifest의 등록 상태이고 실시간 코드 검증 결과가 아니다. 원자료 링크는 저장소 경로로 표시하며 에디터에서 확인한다. 생성 HTML에는 Wiki와 리뷰 본문이 포함되므로 저장소와 같은 범위에서 관리한다.

## 원자료 수집과 갱신

1. 기존 페이지·원자료·관련 미결정을 읽는다. 원자료는 제자리에 두고 새 지식이 필요한 페이지만 수정한다.
2. `sources.json`의 `sources`에 저장소 상대경로를 키로 등록한다. 값에는 SHA-256 `sha256`을 기록한다. 같은 내용을 가진 여러 경로는 그대로 추적하되 독립 근거로 세지 않는다.
3. `pages`의 키는 Wiki 기준 상대경로다. 값에는 `status`, `scope`, `baseline_commit`, `sources` 배열을 둔다. 모듈은 추가·삭제 탐지를 위한 `watch_roots` 배열도 둔다. 감시 루트는 Source·Config와 descriptor만 추적하며 README·빌드 산출물·바이너리를 제외한다.
4. 변경된 근거를 확인한 뒤 해당 페이지의 해시를 업데이트한다. 하나의 원자료를 여러 페이지가 공유하면 모든 소비 페이지를 확인하거나 미확인 페이지를 `needs-review`로 바꾼 후 공용 해시를 갱신한다. 기준 커밋과 작업 트리 관찰 여부도 기록한다.
5. 삭제된 근거는 주장 수정 또는 근거 상실 표시 후 제거한다. 이름 변경은 원자료 키·모든 소비 페이지·본문 링크를 함께 갱신한다. 기준 커밋을 찾지 못하면 재검토한다.
6. 목차와 [로그](log.md)를 갱신하고 점검한다. 미커밋 상태의 해시는 복원 가능한 보관본이 아니므로 커밋 후 근거 버전을 보완한다.

파일럿에는 JSON을 사용한다. PowerShell 기본 기능으로 읽을 수 있고 별도 YAML 라이브러리가 필요 없다. `sources.json`을 지식 본문으로 사용하지 않는다.

## 점검 명령

저장소 루트 PowerShell에서 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File BatchFiles/CheckWiki.ps1
```

구조·링크 오류는 종료 코드 1, 검사 도구 실패는 2다. 원자료 변경이나 재검토 상태는 보고하되 기본 종료 코드는 0이다. 아래 명령은 재검토 필요 상태도 실패로 처리한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File BatchFiles/CheckWiki.ps1 -Strict
```

점검은 읽기 전용이다. 내용 해시로 staged/unstaged를 구분하지 않고 실제 디스크 내용을 비교하며, 감시 루트에 있는 새 파일도 발견한다. 현재성 여부를 자동으로 수정하지 않는다. 링크 검사는 로컬 파일 존재를 확인하며 섹션 앵커·외부 URL·문장 의미의 정확성은 확인하지 않는다.

## 기존 도구와의 관계

`Docs/Programmer/`는 프로그래머가 직접 관리하는 문서만 둔다. AI는 읽기·인용만 하고 자동 생성·수정·삭제하지 않는다. 기존 AI 생성 문서 11개는 2026-09-20 경로 정리 시 `.agents/reports/`로 이관했다. 이후 리뷰·점검·검토 보고서는 `.agents/reports/`에 작성하고 [리뷰 목록](../reports/index.md)에 연결한다. 과거 리뷰 이관은 코드 재검증이 아니며 기존 기준 커밋과 검토일을 유지한다.

reports의 시점별 보고서는 모듈·시스템 정본과 구분한다. 링크 검사는 수행하지만 과거 보고서 자체를 최신 구현으로 표시하지 않는다. 현재 페이지가 보고서를 근거로 인용하면 sources.json에서 파일을 추적한다. 보고서에 포함된 주장은 가능한 한 코드·기획 원자료로 재확인한다.

작업마다 worklog를 새로 작성하지 않는다. 파일·코드 변경 내역은 Git 커밋/PR, 현재 구조는 모듈·시스템 페이지, 재사용할 설계 결정은 decisions, 미결정은 questions에 기록한다. 모든 작업을 Wiki에 기록할 필요는 없다. log.md는 Wiki 수집·갱신·점검 이력만 짧게 남긴다.

기존 worklog는 2026-09-20 사용자 요청으로 모두 삭제했다. worklog 폴더를 다시 만들거나 새 기록을 작성하지 않는다.

과거 판단이 필요하면 Git 이력에 남아 있는 자료를 찾아 현재 코드와 대조한다. Git에 보존되지 않은 기록의 복구를 보장하지 않는다. 삭제 전에 전체 기록을 Wiki로 이관하지는 않았다. 과거의 완료·빌드 성공을 현재 버전의 검증 결과로 옮기지 않는다.

`readme-writer`는 호환 이름을 유지하되 Wiki 모듈 페이지를 갱신한다. `module-review`는 `.agents/reports/module_review_<Module>.md`에 검토 결과를 남긴다. 리뷰의 제안은 Wiki에 결정으로 자동 반영하지 않는다.

공용 WxCore 및 Config 변경은 모든 모듈을 보수적으로 재검토 대상으로 잡는다. C++ 외 기획 의존은 페이지의 sources에 추가한다. 에셋 내부는 현재 감시·검증 범위 밖이며, 에셋 설정을 포함할 때 원본과 추출 결과의 해시·엔진/추출기 버전을 추가해야 한다.

여러 작업자가 갱신하면 본문 파일 단위로 작업을 나누고, `sources.json`·목차·로그는 한 작업자가 합친다. 자동화·검색 서버는 아직 도입하지 않았다.
