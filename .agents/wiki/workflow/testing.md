# 테스트

상태: current · 범위: 확정 기획 기반 시나리오 작성·백그라운드 플레이·결과 판정 절차 · 기준: 2026-09-20 사용자 합의, 작업 트리 반영; 실제 에디터 실행 검증 아님

작업 단계: 테스트

**AI 테스트 → 사람이 필요한 부분 확인 → 수정·재검증 → 승인**

1. AI가 확정 기획과 코드 리뷰된 구현을 기준으로 테스트를 실행하고 결과를 정리합니다.
2. 테스터는 AI가 전달한 **인간 확인 필요** 항목을 직접 확인하고 결과를 알려줍니다.
3. 문제가 있으면 AI가 수정·재검증합니다.
4. 테스터가 결과와 남은 제약을 확인해 승인하면 [완료](completion.md)로 넘어갑니다.

빌드 성공만으로 테스트가 끝난 것은 아닙니다. 실행하지 못한 항목은 미검증으로 남깁니다.

**AI와 사람이 함께 테스트합니다.** AI가 직접 시나리오를 실행하고 결과를 검증합니다. AI가 확인할 수 없거나 모호한 항목은 근거와 함께 사람 테스터에게 전달합니다. 테스터는 해당 부분을 직접 확인해 결과를 돌려주고, 필요한 수정·재검증 후 최종 결과를 수용합니다.

입력은 최종 기획·설계 확정본과 판단 기록, 인간 코드 리뷰가 수용한 구현 버전, 실행 조건·관련 자료입니다. AI가 인계 문서를 읽고 테스트 자료를 준비하며 사람에게 문서 복사·로그 수집을 맡기지 않습니다. 사람이 볼 것은 기대 결과와 실제 결과·증거·미검증 범위입니다. 중요한 판단이 필요하면 항목별 근거·대안을 정리하여 질문하고, 답변 반영·재검증 후 영향받은 항목만 다시 판단받습니다. 기존 수용 판단은 기준 버전과 함께 보존하며 다른 버전의 결과로 옮기지 않습니다.

1. [최종 기획서 확정본](planning.md#최종-기획서-확정본-작성)을 읽고 테스트 시나리오와 체크리스트를 작성합니다. 각 항목에 요구사항 근거, 사전 조건·맵·데이터, 재현 순서, 기대 결과, 확인할 로그 또는 관찰 방법을 적습니다. 정상·예외·경계 조건과 변경 영향에 따른 회귀 항목을 포함합니다.
2. [구현에서 전달한 버전](implementation.md)을 기준으로 백그라운드에서 에디터를 실행하고 플레이합니다. 실행 환경에서 지원하는 자동화·플레이 제어 수단을 확인하여 시나리오를 수행하고 실행 명령·맵·실행 시각·로그 경로를 기록합니다. 에디터 실행과 실제 플레이·시나리오 수행 여부를 각각 확인합니다. 제어 수단이 없거나 실행에 실패하면 미실행 사유를 남깁니다.
3. 해당 실행에서 생성된 로그를 읽고 기대 결과와 실제 결과를 대조합니다. 오류 로그뿐 아니라 시나리오가 실행되었고 기대 상태에 도달했다는 근거를 확인합니다. 오류가 없다는 이유만으로 통과시키지 않습니다.
4. AI가 확인할 수 없거나 판단이 모호한 부분은 ‘인간 확인 필요’로 별도 표시합니다. 화면 연출·애니메이션·조작감 등 해당 항목에는 확인할 장면, 재현 순서, 기대 결과, AI가 확보한 근거와 확인하지 못한 이유를 함께 전달합니다. AI가 직접 확인할 수 있는 항목까지 사람에게 다시 수행하도록 맡기지 않습니다.
5. 테스터가 전달받은 항목을 직접 확인하고 관찰 결과와 판단을 AI에게 돌려줍니다. AI는 이를 같은 항목에 기록하고, 수정이 필요한 경우 관련 구현을 수정한 뒤 다시 실행·검증합니다. 사람이 다시 확인해야 하는 부분만 근거와 함께 재전달합니다.
6. 남은 항목을 함께 확인하고 테스터가 결과를 수용하면 [완료](completion.md)로 넘깁니다. 승인 전에는 테스트 단계에 머뭅니다. 승인자·승인일·승인 범위를 결과에 남깁니다. 미검증 항목을 예외로 수용하는 경우에는 인간의 명시적 판단과 사유를 기록하며 통과 항목과 구분합니다.

## 결과 기록과 후속 처리

후속 테스트와 인간 수용에 필요한 시나리오·체크리스트·결과는 `.agents/in-progress/`의 기존 관련 작업 문서에 함께 관리합니다. 확정본 버전, 구현 기준 커밋과 미커밋 변경 여부, 실행 환경 및 로그 근거를 남깁니다. 실행할 때마다 보고서를 추가하지 않습니다. 일회성 점검 결과는 대화로 전달하고, 승인·후속 인계에 필요한 근거만 파일에 보존합니다. 작업별 worklog는 만들지 않으며 수용 후 [완료 단계의 정리](completion.md#작업-자료-정리)를 수행합니다.

각 체크리스트 항목은 ‘통과’, ‘실패’, ‘미실행’, ‘인간 확인 필요’로 구분합니다. 인간 확인 후에는 확인자·일자·결과를 반영합니다. 미실행이나 인간 확인 필요 항목이 남으면 전체 통과로 표시하지 않고 자동 검증 범위와 남은 항목을 구분하여 전달합니다.

실패하면 원인에 따라 [구현](implementation.md) 또는 [기획](planning.md)으로 돌아가 수정 후 관련 시나리오를 재검증합니다. 빌드 성공을 플레이 검증으로 간주하지 않으며, 과거 테스트 결과를 현재 버전의 결과로 옮기지 않습니다. 문서만 변경한 작업은 Wiki 구조·링크·원자료 점검으로 검증합니다.
