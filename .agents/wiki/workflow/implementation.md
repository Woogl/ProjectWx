# 구현

상태: current · 범위: 반복 설계 판단·AI 구현·인간 코드 리뷰·인계 절차 및 OpenWiki 연결 · 기준: 2026-09-21 사용자 합의, 작업 트리 반영; 실제 구현 작업·플레이 검증 아님

작업 단계: 구현

**설계 질문에 답변 → 설계 확정 → AI 구현 → 코드 리뷰**

1. 기획을 확정하면 AI가 설계 검토를 시작합니다.
2. 검토 직후 나타나는 설계 질문에서 AI 선택지를 누르거나 직접 답변·추가 의견을 적고, 답변 결정 후 AI 재검토를 반복합니다. 현재 질문의 답변을 모두 결정하면 AI 재검토가 자동으로 이어집니다. 추가 판단이 있으면 새 질문에 답하고, 없으면 통합본을 최종 확정합니다. 기존 판단의 범위 제외가 있는 결과만 별도로 확인해 반영합니다.
3. 통합 설계를 확인하고 **설계 확정 · AI 구현 시작**을 누릅니다.
4. AI가 구현·자체 검증한 결과를 확인합니다. **코드 리뷰 승인**을 누르면 AI [테스트](testing.md)가 이어집니다. 수정이 필요하면 결과 화면에서 요청합니다.

설계 확정은 구현 실행도 요청합니다. 설계 중 기획 판단이 바뀌면 답변을 보존하고 AI가 기획 재검토로 연결합니다.

## 구현 목록과 판단 체크리스트

| 구분 | 예시 | 담당 |
| --- | --- | --- |
| 확인할 사실 | 현재 비용 차감 위치, 취소 처리, 기존 인터페이스 | AI가 코드·설정·에셋을 조사 |
| 구현 목록 | 비용 검사, 실패 처리, 회귀 검증 | AI가 수행하고 상태 기록 |
| 설계 판단 체크리스트 | 구조·소유권·인터페이스·예외 처리의 중요한 선택 | AI가 근거·대안·영향을 준비하고 사람이 판단 |

기획의 동작 자체를 바꾸는 질문은 기획 판단으로 돌려보냅니다. 합의된 설계에 따른 세부 작업이나 코드로 확인할 사실까지 사람에게 반복 질문하지 않습니다.

## 설계 반복

1. AI가 최신 기획 인계 자료와 [프로젝트 규칙](../../../AGENTS.md)을 읽고 기존 코드·관련 에셋·호출 경로·제약을 확인합니다. 확인하지 못한 자료는 명시하고 에셋 값을 추측하지 않습니다.
2. AI가 요구사항별 구현 목록과 설계 판단 체크리스트를 분리하여 준비합니다. 구현 목록에는 근거·범위·의존 항목·완료 기준을, 질문에는 식별자·현재 근거·선택지·영향·추천 이유를 둡니다.
3. 사람이 항목별 답변으로 설계를 결정합니다. AI가 답변과 근거를 기록하고 구조·인터페이스·데이터 흐름·수명·예외 처리·검증 방법을 하나의 설계 초안으로 정리합니다.
4. AI가 기획 충족 여부·의존 관계·설계 충돌·미확인 자료를 재검토합니다. 추가 판단이 필요한 항목만 다시 질문합니다. 이전 답을 보존하고 재확인 이유를 설명합니다.
5. 미결정과 자료 부족이 해소되면 사람이 **통합 설계와 구현 범위**를 최종 확정합니다. AI는 확정 설계·판단 기록·기획 근거·관련 코드 및 검증 재료를 구현 작업에 전달합니다.

## 인간 코드 리뷰

설계 확정 후 AI가 합의한 범위를 구현하고 자체 검증합니다. 기존 사용자 변경을 보존합니다. 구현 중 새 제약으로 기획이나 설계 변경이 필요하면 문제·영향·대안을 정리하여 해당 항목만 다시 질문합니다. 영향 없는 합의를 처음부터 반복하지 않습니다.

AI는 변경 설명, 요구사항·설계별 코드 위치와 diff, 검증 결과·실행 근거·남은 제약을 준비합니다. 인간 프로그래머는 그 자료와 실제 코드를 보고 기획·설계 일치와 오류 조건·수명·상태 전이·회귀를 판단합니다. AI가 지적 사항을 수정·재검증하고 사람이 다시 리뷰하는 과정을 반복합니다. AI 자체 검토로 인간 리뷰를 대체하지 않습니다.

인간 리뷰가 수용되면 AI가 확정 기획·설계의 경로와 버전, 판단 기록, 구현 기준 커밋과 미커밋 변경, 리뷰 결과, 실행 조건·검증 근거를 [테스트](testing.md)에 전달합니다. 설계 확정·구현 완료·테스트 승인은 각각 구분합니다.

## OpenWiki에서 진행

기획 동작·범위 변경 질문은 설계 최종 확정을 막는다. 질문의 답변을 모두 결정하면 AI가 별도 기획 변경 작업을 만들고 기획 변경으로 분류된 활성 질문 전체를 자동 전달한다. 기존 기획·설계 확정본은 보존하며 질문·답변·확정 여부·근거를 이어받는다. 새 기획을 검토·확정한 뒤 설계도 다시 검토한다. 미확정 답변은 자동 확정하지 않는다. 연결이 끊기면 같은 요청으로 변경 작업 생성을 복구한다.

설계 확정 후에는 AI가 구현·검증을 시작한다. 설계를 변경해야 하면 AI 작업에서 요청하여 별도 변경 작업을 준비한다. 확정 기획은 그대로 이어받으며 설계 판단·초안·이력을 복사해 영향받는 항목만 재검토한다. 새 설계 확정본이 기존 설계를 대체한다. 기존 확정 내용을 보존하며 제목 변경은 이름·연결만 함께 옮긴다. 구현 AI는 시작·재개·결과 인계 전 `node .agents/scripts/Wiki-AI.cjs --current "작업 제목"`로 최신 기획·설계와 `pending` 보류 범위를 확인한다. 변경 검토 중에는 영향받는 구현을 보류하고 영향 없는 작업은 계속한다. 새 기획이 확정되고 새 설계가 없으면 이전 설계로 새 기획을 구현하지 않는다.

기획을 확정하면 구현 화면에서 해당 기획과 인계 문서를 읽습니다. **AI 설계 검토 · 답변 반영 → 선택지 또는 직접 입력으로 설계 질문에 답변 결정 → AI 재검토**를 반복합니다. 생성기는 기존 판단과 기획 인계 경로를 받아 읽기 전용으로 관련 코드를 조사하고 설계 초안·근거·작업 목록을 준비합니다. 응답에 조사하지 못한 사항이 있으면 자료 부족으로 남깁니다.

**설계 확정 · AI 구현 시작**은 설계와 판단·재료를 `.agents/in-progress/`에 저장합니다. 로컬 서버가 이 문서를 구현 AI에 전달하고 결과·검증 근거를 같은 작업에 기록합니다. 사람은 웹에서 코드 리뷰와 결과 수용을 판단합니다.

실제 구현·리뷰 결과는 대화로 전달하며, 후속 작업에 필요한 판단·미결정·인간 리뷰 수용 근거는 기존 관련 작업 문서에 통합합니다. 항목별 설계 결정·구현 상태·인간 리뷰를 구분합니다. 미결정과 답·근거는 같은 문서의 ‘확인할 사항’에 두며 작업별 worklog나 일회성 구현 보고서는 만들지 않습니다. 작업 재개 시 기존 지적과 판단을 현재 코드에 대조하고, 보류 작업은 보류 이유·재개 조건을 확인합니다. [완료](completion.md) 시 자료 정리를 수행합니다.

기존 [문서 / 코드 리뷰](../documents/code-reviews.md)는 참고 자료이며 현재 작업의 인간 리뷰 완료 증거가 아닙니다.
