# 기획

상태: current · 범위: 인간 판단·AI 자료 준비의 반복 기획 절차 및 OpenWiki 연결 · 기준: 2026-09-21 사용자 합의, 작업 트리 반영; 실제 AI 응답 품질·게임 실행 미검증

작업 단계: 기획

**기획서 입력 → 질문에 답변 → AI 재검토 → 최종 확정**

1. 기획서 원본을 입력하고 **AI 기획 검토 · 답변 반영**을 누릅니다.
2. 검토 직후 나타나는 질문에서 AI 선택지를 누르거나 직접 답변·추가 의견을 적고, 질문마다 **이 답변으로 결정**을 누릅니다. 현재 질문의 답변을 모두 결정하면 AI 재검토가 자동으로 이어집니다. 추가 판단이 있으면 새 질문에 답하고, 없으면 통합본을 최종 확정합니다. 기존 판단의 범위 제외가 있는 결과만 별도로 확인해 반영합니다.
3. AI 검토를 다시 실행합니다. 추가 질문이 있으면 답변을 반복합니다.
4. 통합된 기획서를 확인하고 **기획 최종 확정 · 인계 문서 저장**을 누릅니다.

수정할 내용은 **추가 요청·수정 의견**에 적으세요. 답변 결정과 기획 전체 확정은 별개입니다. AI가 문서를 정리하고 [구현](implementation.md)에 전달합니다.

**사람은 판단하고 AI는 판단에 필요한 자료 준비·정리·기록·인계를 맡습니다.** 최초 입력은 기획서 원본입니다. 원본, 인간 판단, AI가 작성한 통합 초안을 구분합니다.

## 반복 판단

1. AI가 원본을 분석합니다. 명확한 내용은 근거와 함께 추출하고, 미정·충돌·선택이 필요한 부분만 **판단 체크리스트**로 만듭니다. 확인된 값을 사람이 다시 입력하게 하지 않습니다.
2. 각 질문에 식별자, 원본 근거, 판단할 질문, 선택지와 영향, 필요한 경우 추천안과 이유를 제시합니다. 추천은 확정된 판단이 아닙니다.
3. 사람이 항목별로 답변합니다. AI는 답을 임의로 확정하지 않습니다. 보류·제외 답변은 적용 범위를 구분하고 필수 미정이 해결된 것으로 취급하지 않습니다.
4. AI가 결정 원문과 근거를 기록하고 전체 기획 초안을 정리합니다. 원본과 답변을 단순히 이어 붙이지 않고, 유효한 규칙·수치·예외·완료 기준으로 통합합니다. 원본과 이전 판단은 보존합니다.
5. AI가 누락·충돌·변경 영향을 다시 검토합니다. 추가 판단이 필요하면 해당 항목만 사람에게 전달하고 반복합니다. 기존 답변을 지우거나 영향을 받지 않은 결정을 다시 묻지 않습니다. 재확인 시 이전 답과 변경 이유를 함께 제시합니다.
6. 필수 미결정과 자료 부족이 해소되면 사람이 **통합된 최종 기획서와 판단 기록**을 검토하여 최종 확정합니다. 개별 답변 확정과 전체 기획 확정은 별개입니다.
7. AI가 확정본·판단 체크리스트와 답변·원본 및 관련 자료를 [구현](implementation.md)에 전달합니다. 사람은 보고서를 조립하거나 내용을 다시 복사하지 않습니다.

## 최종 기획서 확정본 작성

확정본은 목적·범위·제외 범위, 동작 규칙과 수치, 정상·예외·경계 조건, 기대 결과·완료 기준을 포함합니다. 원본과 구분하고 판단 근거, 확정 시점·버전·적용 범위를 연결합니다. AI가 임의로 미정 수치나 정책을 채우지 않습니다.

최종 확정 후에는 기존 확정본과 판단 기록을 고정한다. 요구사항 변경이 필요하면 AI가 변경 이유·영향·대안을 준비하고 **기획 변경 작업 시작**으로 별도 작업을 만든다. 기존 원본·판단·초안은 자동으로 연결되며 사람은 영향받는 항목만 판단한다. 변경 검토 중 영향받는 구현은 보류하고 영향 없는 작업은 계속한다. 새 기획 확정본이 기존 기획을 대체하며, 이후 설계 재검토·확정을 거친다. 단순 버그 수정과 합의 범위 안의 세부 구현에는 변경 작업이 필요하지 않다.

## OpenWiki에서 진행

독립된 기획은 **새 작업 제목 입력 → 새 작업 만들기**으로 시작하고, **기존 작업** 드롭다운으로 기존 기획을 다시 엽니다. 기존 입력란 수정·파일 불러오기는 현재 작업의 개정입니다. 새 작업에는 이전 작업의 판단·의견·초안을 전달하지 않습니다.

OpenWorkflow.bat으로 새로 열면 빈 시작 화면을 표시합니다. 이전 작업은 기존 작업 드롭다운에서 선택해 불러옵니다. 새로고침할 때도 빈 시작 화면을 표시하며, 저장된 입력은 기존 작업을 선택하면 불러옵니다.

확정 후 변경할 내용과 이유를 입력하고 **기획 변경 작업 시작**을 누른다. 새 제목을 식별자로 사용하는 작업이 만들어지고 기존 원본·답변·판단 이력·초안을 자동으로 이어받는다. 이전 작업과 Markdown·JSON의 확정 내용을 보존한다. 제목 변경 시에는 파일명과 연결만 함께 옮긴다. 작업별 공용 기록에 후속 변경을 연결한다. 구현 AI는 `node .agents/scripts/Wiki-AI.cjs --current "작업 제목"`로 이전 작업에서 출발해도 최신 기준과 보류 범위를 확인한다. 변경 작업 생성·복구가 실패하면 기존 확정본은 그대로 유지한다.

범위 제외로 불필요해진 질문은 AI가 제외 사유와 인간 판단 근거를 제시합니다. **검토 결과 반영 · 기존 판단 보존**은 표시된 제외도 승인합니다. 제외된 질문은 답변을 강요하지 않고 이전 답변·이력을 보존합니다. 단순히 AI 응답에서 질문이 빠진 경우에는 제외로 처리하지 않습니다.

원본을 입력하거나 UTF-8 .md·.txt 또는 .docx·.pdf·.pptx 파일을 불러옵니다. **AI 기획 검토 · 답변 반영 → 선택지 또는 직접 입력으로 항목별 답변 결정 → AI 재검토**를 반복합니다. 재검토 결과에는 추가 질문과 통합 초안을 표시합니다. 사실·조사 근거와 자료 부족은 AI 검토 자료로 보존하며 저장에 필요한 조치는 저장 버튼 옆에 안내합니다. 답변을 결정한 직후에는 확정할 수 없고 AI가 그 답을 반영해 다시 검토해야 합니다. 처음부터 판단할 항목이 없으면 빈 체크리스트로 최종 검토할 수 있습니다.

수정 의견은 ‘추가 요청·수정 의견’에 적습니다. 기존 확정 답변을 AI가 다시 열 때는 식별자와 재확인 이유가 필요하며 이전 답변을 보존합니다. 새 답변은 사람이 결정합니다.

**기획 최종 확정 · 인계 문서 저장**을 누르면 `.agents/in-progress/`에 작업·단계별 Markdown·JSON을 저장하고 목록에 연결한다. 확정한 단계는 다시 저장하지 않는다. 수정은 별도 변경 작업에서 확정하여 새 경로로 남긴다. 구현 화면에는 해당 확정본과 인계 경로를 자동 전달한다. 파일 저장 실패는 요청을 보존해 복구하며, 입력 중 자료와 진행상황도 공용 작업 JSON에 저장한다. 브라우저는 미전송 입력 복구에만 사용한다. [사용 안내](../notices/usage.md)를 참고한다.

관련 AI 검토 문서의 ‘확인할 사항’에 결정과 근거를 관리하며 중복 질문 목록·작업별 worklog를 만들지 않습니다. `Docs/Programmer/`에 AI가 작성하지 않습니다.
