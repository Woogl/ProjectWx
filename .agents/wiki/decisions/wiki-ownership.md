# Wiki에 모듈 설명 통합

상태: current · 범위: 문서 운영 결정 · 결정일 2026-09-20

이 작업의 사용자 대화에서 모듈 README 본문을 Wiki에 통합하고 기존 위치에는 링크만 남기는 제안을 제시했으며, 사용자가 “네, 좋습니다. 진행합시다.”라고 승인했다. 이 문서는 해당 대화의 수기 기록이며 별도 대화 내보내기 파일은 없다.

- 모듈 설명은 `modules/`에서 관리한다.
- 루트 README는 프로젝트 소개와 Wiki 입구로 유지한다.
- 모듈 README는 해당 Wiki 페이지로 연결하는 안내만 담는다.
- 기획·회의록·코드·리뷰 원자료는 보존한다.
- 기존 설명 이관을 코드 재검증 완료로 표시하지 않는다.

이 결정은 게임 규칙이나 코드 구조를 변경하지 않는다. 관련: [운영 절차](../maintenance.md), [목차](../index.md).

## 장기 지식과 진행 중 작업 자료 분리

2026-09-20 사용자는 작업 완료 시 정리·재개 시 유효성 확인·정기 점검으로 누락 보완하는 방식을 승인했다. 폴더명을 진행 중이라는 의미가 분명한 `.agents/in-progress/`로 제안한 뒤 “네 진행하세요”라고 승인했다. 장기 지식은 기존 Wiki 정본에 통합하고, 진행 중 인계·미결정·미해결 사항·아직 필요한 수용 근거만 작업 공간에 유지한다. 보고서를 기본 생성하지 않으며, 삭제 전 인간 판단·승인 근거의 실제 보존 여부를 확인한다. 이 결정은 기존 리뷰 원자료의 무조건 영구 보관 방침을 대체하며 게임 기획 원본·수기 문서 보존 원칙은 유지한다. 상세 운영은 [보존·정리 절차](../maintenance.md#작업-자료의-보존과-정리)를 따른다.

## 작업별 worklog 폐지

2026-09-20 같은 대화에서 신규 worklog 작성과 강제 훅을 폐지하고 기존 기록은 보관하며 필요한 지식만 Wiki로 흡수하자는 제안에 사용자가 “네 정리합시다.”라고 승인했다.

변경 내역은 Git, 현재 설명은 Wiki 모듈·시스템, 설계 결정은 decisions, 미결정은 questions로 관리한다. Wiki log는 작업 일지를 대체하지 않고 Wiki 갱신 이력만 기록한다. 최초 정리에서는 기존 기록을 보존했으며, 아래 후속 결정으로 보관 방침을 대체했다.

## 기존 worklog 전체 삭제

2026-09-20 사용자가 “worklog 전부 지워주세요”라고 명시적으로 요청했다. 삭제 시점 `.agents/worklog/`의 파일 1,113개와 폴더를 제거했다. 전체 내용의 Wiki 이관이나 Git 보존 여부 전수 확인은 수행하지 않았다. 보관소 링크와 신규 기록 위치 안내도 제거했다.

## 미결정을 관련 검토 결과에 통합

2026-09-20 사용자가 질문을 관련 검토 내용과 함께 관리하고 questions 폴더를 삭제하는 방안에 동의하고 진행을 요청했다. 위 worklog 폐지 당시의 미결정 별도 관리 방침은 이 결정으로 대체한다. 질문은 관련 기획·코드 검토 결과의 ‘확인할 사항’에 기록하고 답·근거·결정일을 같은 문서에 남긴다. Q-001~004는 주제별 검토 문서로 옮기며 질문 내용과 미확정 상태를 유지한다.

## Wiki와 Workflow의 역할 분리

2026-09-20 사용자가 “Wiki는 AI 가 작성하고 쌓아나가는 지식 DB 용도로 하고, Workflow는 사람이 작업하고 판단하는 용도로 씁시다.”라고 확정했다. Wiki는 지식 검색·열람, Workflow는 기획서 첨부·AI 검토·사람의 판단·확정·인계를 제공한다. 실행기와 화면을 분리하고 정본 자료와 AI의 지식 통합 책임은 공유한다. 기존 판단의 유실을 막기 위해 Workflow의 파일 URL과 브라우저 저장 키는 유지한다.

## 확정본 보존과 제목 기반 변경 작업

2026-09-21 사용자는 최종 확정본을 유지하고 이후 변경을 별도 작업으로 검토해 새 확정본으로 대체하는 제안에 “네, 그렇게 해주세요.”라고 승인했다. 이전 자료를 자동 연결하고 영향받는 판단·구현·리뷰·테스트만 다시 수행한다. 변경 검토 중 영향받는 구현은 보류한다. 이어 “내부 연결용 ID 없애주세요. 디버깅하기 편하도록요.”라고 요청했다. 작업 제목 자체를 식별자로 사용하고 파일명·변경 연결에도 제목을 쓰며, 제목 변경 시 관련 참조를 함께 갱신한다. 확정 내용과 판단 원문은 보존한다. 이 결정은 기존의 동일 작업 확정 철회·인계 삭제 방식을 대체한다. 상세 절차는 [기획](../workflow/planning.md), [구현](../workflow/implementation.md), [운영 절차](../maintenance.md)에 둔다.

## 작업 상태의 공용 파일 저장

2026-09-21 사용자는 작업 목록을 `.agents/in-progress/`에서 읽고 미확정 입력·답변·초안도 작업별 JSON에 저장하는 제안에 “네. 그렇게 해주세요. 최대한 단순하고 다른 사람도 진행상황이 공유되게 되어야해요”라고 승인했다. 작업 파일을 정본으로 삼고 브라우저 저장은 미전송 입력·실패 요청 복구에만 사용한다. 기존 브라우저 작업은 보존하며 이관하고, 확정 인계 보존 원칙은 유지한다.
