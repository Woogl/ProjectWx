# Workflow 기획서 검토 전환

## 테스트 결과 처리 AI 선택 · 2026-09-25

상태: 구현·자동 회귀 확인·로컬 서버 적용 완료.

- 요청: Codex 외의 AI도 제출한 테스트 결과를 처리하도록 한다.
- 변경: 처리할 AI에 서버가 제공하는 Codex·Claude Code·Gemini CLI를 표시한다. 선택값을 입력 초안·접수·응답 유실 재전송·처리 결과에 저장한다. 실패·중단 뒤 AI를 바꿔 재시도할 수 있고 이전 AI와 결과를 이력에 보존한다. 기존 접수의 AI 필드 누락은 당시 실행기인 Codex로 해석한다.
- 실행: 기존 제공자 실행기를 검토/실행 모드로 나누고 같은 결과 스키마를 검증한다. 기획·설계 검토는 읽기 전용을 유지한다. 테스트 결과는 Codex workspace-write, Claude acceptEdits, Gemini auto_edit로 수행한다. CLI·관리자 권한을 유지하며 무제한 권한 옵션을 추가하지 않는다. Claude의 도구 권한 거부는 blocker로 남긴다.
- 호환: 실제 서버가 반환한 처리 가능 AI 목록을 사용한다. 이전 서버는 기존 Codex 경로만 표시하며, 저장된 선택이 연결되지 않았으면 다른 AI로 자동 대체하지 않는다.
- 검증: TestWorkflowTestFeedback·TestWorkflowFeedbackUI·TestWikiProviders·TestWorkflowExecution·TestWikiAI 통과. 제공자별 실행 옵션·JSON 결과·권한 거부·설정 보존·임시 파일 정리, 선택 저장·재전송·변경 재시도·과거 접수 호환·미연결 선택 거부·HTTP 전달을 확인했다. 설치된 Claude/Gemini 도움말과 공식 비대화형 실행 문서를 대조했다.
- 적용 확인: 대기 상태의 로컬 서버를 갱신하고 실제 list/read API가 Codex·Claude Code·Gemini CLI 세 선택을 반환함을 확인했다. 기존 접수는 Codex와 기존 확인 필요 상태로 보존했다. 생성 화면의 TestWikiViewer·TestWikiSpaces도 통과했으며 Wiki Lint 전 항목 0건, 링크 검사 61개 문서 오류 0건이다.
- 제한: 제공자별 실제 AI 요청과 브라우저 육안 검증은 이번 변경에서 수행하지 않았다. 진행 중이던 체크포인트 처리를 중단하거나 결과를 재전송하지 않았다. 해당 작업은 완료 후 코드 변경 감지 등을 확인 필요로 보고했으며 원문을 유지한다.

## 작업 기록의 테스트 결과 접수 · 2026-09-25

상태: 구현·자동 회귀 확인 완료 · 실제 사용자 결과 제출과 화면 확인 대기.

- 요청: 대시보드에서 이상 없음/이상 있음을 선택하고, 문제가 있으면 상황을 적어 AI가 접수·수정·마무리하도록 한다.
- 화면: 각 기록의 테스트 결과 버튼으로 확인자·확인한 항목·상호 배타적인 결과 선택을 연다. 이상 있음에만 문제 상황·재현 방법을 표시한다. 접수 뒤 AI 상태·검증 근거·남은 확인을 표시하고 자동 갱신한다. 입력을 브라우저에 보존하고 응답 유실은 같은 접수로 재전송한다.
- 실행: 새 `/test-feedback` 경로가 원래 Markdown Task의 최신 결정에 따라 Codex CLI를 실행한다. 이상 없음은 범위 대조·정리, 이상 있음은 합의 범위 내 수정·검증이다. 일부 결과를 전체 수용으로 확대하지 않으며 코드 변경·미실행·남은 확인은 재확인, 실패·미결정은 확인 필요로 남긴다. 기존 웹 작업의 기획·설계·리뷰 승인은 자동 생성하지 않는다.
- 기록: `test_feedback_*.json`에 원문·확인자·시각·작업/코드 식별값·접수 식별자·결과·재시도 이력을 보존한다. 결과를 원래 Task에 추가하고 완료/재확인에 맞춰 목차를 갱신한다. 이전 기록을 삭제하지 않는다. 완료 기록에 새 문제가 확인되면 확인할 일로 돌아온다.
- 검증: TestWorkflowTestFeedback·TestWorkflowFeedbackUI·TestWikiViewer·TestWikiSpaces·TestWikiTasks·TestWikiRecovery·TestWikiAI·TestWorkflowExecution 통과. 실제 AI 대신 모의 실행기로 저장·중복 방지·버전 충돌·작업 변경·완료/재확인/보류·CLI 실패·서버 재시작·실행 잠금·API 권한·화면 입력/복구/갱신을 검증했다.
- 제한: 실제 AI 호출·브라우저 육안·UE 실행은 미실시. 브라우저 육안 검증은 앞선 로컬 파일 URL 보안 정책 제한이 유지된다. 문서 상세 본문은 생성 HTML이므로 OpenWorkflow.bat 재실행 시 추가 기록이 반영된다. 코드 식별은 이 경로에서 Markdown·Wiki 정리를 제외하지만 HEAD 변경 자체는 여전히 재확인 대상이다.
- 적용: 대기 상태의 로컬 서버를 새 버전으로 갱신하고 실제 저장소의 목록·Workflow 개선 작업·문서/코드 식별값 조회를 확인했다. 테스트 결과를 임의 제출하거나 실제 AI를 실행하지 않았다. 순정 Wiki Lint는 전 항목 0건, 저장소 링크 검사는 61개 문서 오류 0건이다.
- 후속: 아래 2026-09-25 분석의 현황 연결·인간 테스트 결과 전달을 적용했다. 세션 간 편집/빌드 조율과 나머지 제안의 적용 판단은 별도다. 운영 지식은 기존 Wiki 도구 구조에 통합한다.

## 작업 현황 표시 개선 · 2026-09-25

상태: 구현·자동 회귀 확인 완료 · 사용자 화면 확인 대기.

- 요청: 작업 목차를 파악하기 쉽게 개선. 표시 위치는 사용자가 기존 Workflow 웹 화면으로 선택했다.
- 변경: 대화 작업 21개를 플레이 확인 9개·에디터 확인 2개·개선 판단 5개·완료 기록 5개로 정리했다. 상세 Task의 후속 기록을 대조했고, 어빌리티 작업은 현재 GA_ 복귀 방향으로 표시한다. 과거 인게임 통과와 후속 미검증을 구분했다.
- 화면: 대시보드에서 분류별 건수·확인 범위·다음 행동을 보고 상세 기록을 연다. 서버 연결 전에도 생성된 기록을 볼 수 있다. 웹 작업이 없으면 빈 단계 카드 7개를 표시하지 않는다. 웹 작업의 생성·재개·확정·승인 경로는 그대로 유지한다.
- 정본: `.agents/workflow/tasks/index.md`의 네 표를 읽으므로 별도 현황 JSON을 만들지 않는다. 공통 기록 절차에 목차의 분류·확인 범위·다음 행동 갱신을 연결했다. 과거 승인이나 원문을 변경하지 않는다.
- 검증: TestWikiViewer·TestWikiSpaces·TestWikiTasks·TestWorkflowExecution 통과. 21개 기록의 누락·중복, 분류 전환, 서버 연결 전 표시, 기존 승인 상태 불변, 잘못된 기록 링크 제외, 웹 작업 생성·재개 시 기록 숨김, 기존 실행·저장 회귀를 확인했다. 저장소 링크 검사 통과.
- 제한: Browser Use의 로컬 파일 URL 보안 정책으로 실제 브라우저 육안 확인은 수행하지 못했다. 우회하지 않았으며 레이아웃은 사용자 화면 확인 대상이다. 게임 코드·에셋은 수정하지 않았다.
- 지식 반영: [Wiki 도구 구조](../../../.wiki/wiki/references/wiki-workflow.md)에 표시 원본·분류·갱신 절차·승인 경계를 통합했다. 순정 Wiki Lint는 critical/warning/suggestion/info 모두 0건이다.

## 현재 점검 · 2026-09-25

상태: 분석 완료 · 아래 개선안은 사용자 판단 전이며 구현하지 않았다.

- 범위: AGENTS.md, 공통 절차, 공용 스킬·실행/저장 코드, 현재 작업 기록. 기준 HEAD `38d4dde08`과 점검 당시 미커밋 변경을 읽었다. 기존 사용자 변경은 보존했다.
- 유지할 원칙: 사람의 판단과 AI 실행 분리, Wiki와 실행 승인 분리, 빌드와 플레이 검증 구분. 2026-09-22의 승인 버전·승인자·정리 완료 개선은 현재 코드와 회귀 테스트에서 확인했다.
- 우선 1 — 작업 현황 경로 통합: `tasks/`에 색인을 제외한 Markdown 작업 기록 21개가 있지만 `Wiki-Tasks.cjs`의 `listTasks`는 `workflow_*_(task|current).json`만 읽어 현재 목록이 0개다. 대화 작업의 검증 대기가 웹 대시보드에 나타나지 않는다. Markdown의 최소 상태·다음 행동을 공통 조회에 연결하되, 과거 기록을 웹 승인으로 승격하지 않는 방안을 권한다. 전체 기획 절차가 필요한 기능 작업과 합의 범위 내 소규모 수정의 진입 기준도 명시할 필요가 있다.
- 우선 2 — 대화 세션 간 편집·빌드 조율: 실행 서비스의 `active`·`workerPid`는 그 서비스를 거친 실행만 관리한다. [Notify 작업](animnotify-labels.md)에 다른 세션의 헤더 변경과 UHT 불일치로 빌드가 실패했다가 재실행한 기록이 있다. 공유 체크아웃의 수정 대상·빌드 소유자를 작업 시작 시 조율하고 빌드 중 해당 소스 변경을 막는 절차를 권한다. 독립 C++ 작업은 작업별 체크아웃을 선택할 수 있고, 공용 에디터·바이너리 에셋 편집은 한 작업이 맡아야 한다.
- 우선 3 — 인게임 검증 대기 관리: [체크포인트](checkpoint-savegame.md), [보스 표시](boss-display-simplification.md), [아이템 VM](item-viewmodel-unification.md)에 인간 리뷰·인게임 미확인이 남아 있다. 기록상 대기이며 실제 결함이나 장기 방치를 뜻하지 않는다. 현재 대기 목록에 확인 담당·대상 버전·맵·재현 순서·기대 결과·재개 조건을 모으고, 저장/부활·전투·UI 등 영향받는 핵심 시나리오를 반복 실행할 수 있게 정리할 필요가 있다.
- 우선 4 — 현재 기준과 이력 구분: [어빌리티 작업](ability-table-driven.md)은 982행·139,977바이트이고 테이블 전환과 GA_ 복귀 판단을 함께 보존한다. 상단에 이력임을 밝혔지만 현재 확정 기준을 재구성하는 비용이 크다. 같은 Task 상단에 현재 결정·미결·남은 검증·다음 행동만 짧게 유지하고 원문 이력은 아래에서 참조하도록 정리할 것을 권한다.
- 우선 5 — 승인 버전 판정 범위: `Workflow-Execution.cjs`의 `codeVersion`은 HEAD와 작업 기록을 제외한 전체 저장소 diff를 해시한다. 임시 저장소에서 Wiki만 수정한 경우와 작업 파일 내용은 그대로 커밋만 한 경우 모두 버전이 바뀜을 확인했다. 기획·규칙 변경의 승인 무효화는 유지하면서 실행 관련 코드·설정·에셋 내용과 문서/커밋 메타데이터의 변경을 구분하는 방안을 검토해야 한다.
- 검증: `TestWorkflowExecution.cjs`, `TestWikiTasks.cjs` 통과. `CheckWikiLinks.ps1`은 60개 문서 오류 0건. 승인 버전 재현은 별도 임시 저장소에서 수행하고 정리했다. 실제 AI 제공자 호출·웹 브라우저 육안·UE 빌드·게임 실행은 이번 점검에서 수행하지 않았다.
- 기록 범위: 분석 결과만 이 Task에 유지한다. 미확정 개선안을 Wiki의 운영 규칙으로 편찬하지 않는다.
