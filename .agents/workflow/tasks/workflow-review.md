## 규칙 사본 정리 · 2026-09-26

- 요청: 사용자가 코드·Wiki·지침을 최신화한 뒤 "아직 충돌이 남아있나요?"라고 물었다. AI는 내용 충돌은 없고 사본 두 곳(처리 프롬프트의 규칙 문장, Wiki 절차 요약)과 정본 본문에 빠진 예외 한 구절이 있다고 답했다. 사용자가 "네 진행하세요"라고 승인했다.
- 처리 프롬프트(`taskPrompt`): 첫 줄은 AGENTS.md와 작업 절차를 따르게 한다. 남긴 것은 단계, 결과 칸 형식, 전체 권한 실행의 제한, 웹 전용 약속, evidence 작성법뿐이다. 체크리스트 규칙은 "기존 항목을 포함한 전체, 작성 규칙은 작업 절차의 테스트 체크리스트 절"로 줄였다. 뺀 규칙 문장은 모두 정본에 있다. 그중 사람 항목 보존·미실행 넘김·사람 항목 최소 하나는 서버 코드가 강제한다. 터미널에서 이어하기 요청문에서 읽을 절 나열도 뺐다. 테스트 `TestWorkflowTestFeedback.cjs`의 프롬프트 검사를 새 문구로 바꿨다.
- 정본: 단계 절의 "명확한 지시는 구현 승인"을 AI 대화로 한정하고, 웹 새 작업은 정하기부터 시작해 구현 승인을 받는다고 적었다. 「작업 절차 도식 교체」의 미결 첫째가 이것으로 정해졌다. 이어 사용자가 "구현 내용을 명확히 지시한 요청은 그 지시를 구현 승인으로 봅니다. 라는 규칙을 아예 빼는게 나을까요?"라고 물었다. AI가 남기기를 추천했다. 빼면 명확한 지시마다 승인 왕복이 생기고, 확인하기의 코드 리뷰·사람 항목 관문은 그대로 남으며, 웹 새 작업의 동작은 달라지지 않기 때문이다. 사용자가 "남깁시다"로 결정했다.
- Wiki: `raw/notes/2026-09-26-workflow-ssot-copies.md`를 수집해 `references/wiki-workflow`의 단계 표·승인 규칙·기록 형식·체크리스트 작성 규칙을 정본 링크로 바꿨다. 「절차 정본과 처리 프롬프트」 절을 새로 두고, 요약과 참조 색인 줄도 맞췄다. 순정 lint는 PASS였다.
- 로컬 서버는 처리 중인 작업이 없어(busy=false) Start-WikiAI.ps1로 새 코드를 띄웠다. 실제 AI 처리로 새 프롬프트의 준수를 확인하지는 않았다. 커밋은 하지 않았다.

## 작업 절차 도식 교체 · 2026-09-26

## 상태는 질문·계획·체크리스트에서만 · 2026-09-26

- 요청: 첫 실제 처리의 두 결함(무관한 경고가 완료를 막음, AI의 완료 문장이 계획 절로 들어감) 뒤 사용자가 "완료로 확정" 우회 버튼을 거절하고 "이 과정에서 문제가 없도록 워크플로우를 직관적으로 다듬어야"라고 했다. "AI가 무관한지 판단하는게 많은 실수를 일으킬까요?"에 답한 뒤 "네."로 제안을 승인했다.
- 원인: AI 결과의 여러 칸(남은 확인·검사 실패·계획·질문)이 모두 상태를 바꾸는 신호였고, 완료가 사람의 판단 뒤 AI 정리의 성공에 걸려 있었다. 여러 세션이 한 체크아웃을 고쳐 AI가 이 작업의 변경만 가려낼 방법이 없으므로, 관련 여부 판단이 상태를 바꾸지 않게 하는 것이 근본 해결이다.
- 서버: 단계마다 AI 결과 칸을 제한한다(정하기 = 질문·계획, 구현·수정 = 변경·질문·체크리스트, 추가 요청 = 여기에 계획, 정리 = 변경만, 모두 요약·근거 포함). 스키마와 검사가 허용한 칸만 돌려주므로 다른 칸은 AI가 채워도 버려진다. 상태는 기록의 질문·계획·체크리스트에서만 정한다. 테스트 결과는 실패가 있으면 AI 수정, 실패 없이 일부 통과면 AI 없이 기록, 모두 통과면 즉시 완료하고 뒤이어 AI 정리(상태를 바꾸지 않고, 실패·중단해도 완료 유지). AI의 미실행·대기 항목은 사람 항목으로 넘기고, 사람 항목이 없으면 결과 확인 항목을 둔다. 처리 중 기록이 바뀌면 기록 충돌로 두고 결과를 반영하지 않는다. 사람의 테스트 결과는 전달 즉시 이력에 남기고, AI 결과는 단계별 제목(AI 조사 결과·AI 구현 결과·AI 추가 요청 처리·AI 수정 결과·AI 완료 정리)으로 남긴다.
- 지시문: 남은 확인(blockers)·검사 목록(checks)을 없애고 근거(evidence)로 바꿨다. 사람의 판단은 선택지가 있는 질문으로만 묻고, 무관한 문제는 요약에 한 줄로, 다른 작업의 변경 때문인 실패는 고치지 않는다.
- 화면: 모두 통과한 작업은 완료 단계로 보이고(정리 중에도 입력 대기 없이), 전달 뒤 결과 기록·즉시 완료 안내를 보여준다. 자동 새로고침은 안내를 덮지 않는다. 옛 처리 결과의 남은 확인도 그대로 보여준다.
- 문서: 워크플로우 규칙의 정본인 작업 절차만 고쳤다(AGENTS.md와 tasks 안내는 같은 날 링크만 두도록 바뀌어 손대지 않았다).
- 제한: 바뀐 흐름을 실제 AI 요청으로는 다시 돌리지 않았다.

## 웹 새 작업·이어하기 · 2026-09-25

## 편의 점검과 후속 개선 · 2026-09-25

- 요청: 단순화한 워크플로우가 AI와 사람 모두에게 작업하기 편한지 점검. 점검 결과를 본 사용자가 네 개선(식별값 검사 제거, 코드 리뷰를 체크리스트로, 옛 기록 정리, 작업 현황 자동 생성)을 모두 승인했다.
- 점검 근거:
  - 다른 세션 두 곳이 새 체크리스트 형식을 그대로 썼고 서버가 정상으로 읽었다. 한 세션은 코드 리뷰를 체크리스트 사람 항목으로 넣었다.

- 변경:
  - 식별값 검사 제거: 제출·재시도의 코드 식별값 비교와 "처리 중 코드 변경이면 재확인" 규칙을 없앴다. 코드를 바꾼 AI가 영향받는 사람 항목과 코드 리뷰를 대기로 되돌린다(처리 프롬프트). 작업 기록 변경 대조는 유지한다.

- 후속: 사용자가 새 작업 시작·기존 작업 이어하기 방법을 물어, 작업 절차에 「시작과 이어하기」 절을 넣었다. AI는 조사·질문을 시작할 때 기록을 만들고, 질문에 답하고 끝나는 일은 기록을 만들지 않는다.
- 제한: 목록 제목이 작업 현황의 짧은 이름 대신 기록 제목(# 줄)으로 바뀌었다. 다른 작업의 코드 변경은 자동으로 감지하지 않는다. 이전 지시로 일하던 세션이 작업 현황 표를 다시 만들 수 있어, 안내 문서에 표를 만들지 말라고 적었다. 실제 AI 처리 요청과 사람의 화면 확인은 하지 않았다.
