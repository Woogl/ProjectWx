## 점검 · 2026-09-30

- 실행 중인 서버로 확인 대기 기록을 읽었다. viewmodel-mvvm-redesign.md는 질문 6번째 행 형식 오류(Q6 행의 `||`로 칸 6개), workflow-codex-terminal-no-daemon.md는 질문 표 머리글 오류(표 없이 "추가 질문 없음.")였다. 같은 날 오전 workflow-remove-redundant-buttons.md도 같은 원인이었다.
- 세 기록 모두 대화·터미널에서 AI가 쓴 기록이다. 웹 처리는 서버가 표를 쓰므로 깨지지 않는다.
- 승인 전에 두 기록의 표 형식만 바로잡아 버튼을 되살렸다(Q6 행의 `||` → `|`, 빈 질문 표 추가). 질문·답변·결과 내용은 바꾸지 않았다.
- 워크플로우 테스트 4개는 수정 전에도 통과했다. 코드는 설계대로 동작했고, 문제는 손으로 쓴 기록과 상태 칸 표시 쪽이다.

## 구현 · 2026-09-30

- 표 읽기: 질문·체크리스트 절에 `|`로 시작하는 줄이 하나도 없으면 표가 없는 것으로 읽는다. 표 줄이 있으면 전처럼 절 제목 바로 아래 머리글부터 검사하므로, 글 아래에 둔 표는 여전히 오류다. 서버가 새 질문을 쓸 때는 그 절 내용을 질문 표로 바꾼다.
- 목록 요약: 두 표 중 먼저 찾은 오류를 `표 오류 · …`로 보여, 대시보드와 `--tasks`에서 작업 탭을 열기 전에 드러난다.
- 상태 칸: 웹 처리 상태 제목은 처리 중·실패·중단·충돌일 때만 보인다. 끝난 처리는 "최근 전달 · …" 줄로만 남고, 웹 전달이 없던 작업은 칸을 숨긴다. 대시보드 목록 옆 표시도 같은 기준이다.
- 표 오류 화면: 서버가 거절하는 추가 요청을 숨기고, 이유와 터미널에서 이어하기로 고치는 법을 보인다.
- 서버 안내 3곳을 브라우저 새로고침 기준으로 바꿨다. 중복 버튼 제거 작업(workflow-remove-redundant-buttons.md)에서 빠진 문구다.
- 작업 절차: 표 없는 "추가 질문 없음" 허용, 대화·터미널에서 기록을 고친 AI의 `--tasks` 확인, 표 오류가 보이는 곳을 적었다.
- 쉬던 워크플로우 서버를 재시작하고 페이지를 다시 만들었다. 이미 열린 화면은 새로고침해야 새 연결 정보와 코드를 쓴다.
