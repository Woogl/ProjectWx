## AI 코드 리뷰 결과 · 2026-09-27

새 문맥의 검토 AI가 `70d34744d..5792614e9`의 워크플로우 도구 변경을 읽기 전용으로 검토했다. 심각도 높음은 없었고, 보안(토큰·Host·Origin, Markdown의 XSS)·처리 순서와 잠금·복구 시점·시간 제한·작업 트리·이름 변경 참조·문서 일치는 문제없었다. 지적 7건을 모두 코드로 다시 확인하고 고쳤다.

1. 중간 · 옛 이름(`Wiki-AI.cjs`)으로 떠 있는 서버를 새 시작 스크립트가 알아보지 못해 다시 띄우지 못했고, 새 페이지의 기록 열기가 옛 서버 응답(내용 없음)에 "불러오는 중"으로 멈췄다. → 시작 스크립트는 이 저장소의 서버임을 확인한 뒤 포트를 잡은 프로세스로 알아본다(명령줄 검사를 없앰). 기록 열기는 그리다 실패해도 페이지의 내용이나 이유로 돌아간다.
2. 낮음 · 새 작업을 전달하는 도중 대시보드로 나가면, 다음 새 작업 폼에 옛 입력이 남아 같은 요청이 두 번 만들어질 수 있었다. → 그때는 다음 새 작업을 빈 입력으로 다시 그린다. 다른 작업으로 옮긴 뒤의 전달 실패 문구가 보이지 않는 점은 입력이 남아 있어 그대로 두었다.
3. 낮음 · 처리 중 다른 곳에서 모두 통과로 바뀐 기록이 충돌·실패로 확인 대기가 되고, 완료로 거부되면서도 다시 시도만 받는 막다른 상태가 될 수 있었다. → 그런 기록은 완료로 두고, 완료된 작업은 다시 시도도 거부한다(작업 절차에 반영).
4. 낮음 · writePlan 주석이 "코드 블록은 그대로"라고 했지만 코드 블록 안의 절 경계 줄도 들여 쓴다(절 읽기가 코드 블록을 가리지 않아 필요한 동작). → 주석을 동작에 맞게 고쳤다.
5. 낮음 · vendor README가 marked 설정을 취소선 한 줄로만 적었다. → HTML 규칙까지 적었다.
6. 낮음 · Codex MCP 목록에 `enabled` 칸이 없으면 서버를 켠 채로 두었다. → 칸이 없으면 끈다.
7. 낮음(이전부터) · 시작 스크립트가 .NET 5 API를 쓰는데 PowerShell 7.0을 요구했다. → 7.1로 올렸다.
