# 대시보드와 작업 탭 분리

상태: 확인 대기 · 구현 승인 대기
다음 행동: 구현 계획을 확인하고 승인한다.

- 날짜: 2026-09-26
- 계기: 사용자가 워크플로우 최종 마무리 코드 리뷰를 요청했다가 멈추고, 먼저 대시보드와 작업을 나누자고 했다. 코드 리뷰는 이 작업 뒤에 한다.

## 요청

- 요청 · 이우성 2026-09-26

> "대시보드"와 "작업"을 분리합시다. 대시보드에서는 작업 현황을 보는 곳이고, 여기서 "새 작업"을 누르거나 "이어서 작업"을 누르면 "작업" 탭으로 전환됩니다.
> "이어서 작업" 버튼은 "작업 진행" 버튼을 리네이밍한 것입니다. 이해 되나요?

- 추가 요청 · 이우성 2026-09-26

> 작업 할 때 “이름” 입력은 “작성자”로 바꿔주세요.

## 구현 계획

추가 질문 없음. 아래 기본값은 AI가 정했으며, 다르게 하려면 승인 전에 알려주면 된다.

1. 화면 구성
   - 왼쪽 메뉴는 대시보드 · 작업 · 작업 절차다. 대시보드에는 작업 현황(목록·필터)과 Wiki 갱신만 두고, 작업 패널은 작업 탭으로 옮긴다.
   - 대시보드의 **새 작업**과 목록의 **이어서 작업**(옛 작업 진행)은 작업 탭으로 바꾸며 새 작업 입력이나 그 작업을 연다. 탭마다 주소(#)가 달라 새로 고침과 뒤로 가기에도 탭과 연 작업이 유지된다.
   - 메뉴에서 작업 탭을 바로 누르면 마지막으로 연 작업을 보이고, 연 적이 없으면 대시보드에서 고르라는 안내를 보인다.
   - 작업 탭의 **닫기**는 **대시보드로**로 바꾼다.
2. 작성자: 작업 탭과 새 작업 입력의 **이름** 칸을 **작성자**로 바꾼다(칸 이름, 읽기 도구 이름, 빈 칸 안내, 서버 오류 문구, 작업 절차의 "이름을 적고 전달합니다"). 기록에 남는 "요청자"·"전달한 사람" 표기는 그대로 둔다.
3. 이름: "작업 진행"을 화면·작업 절차·Wiki 안내·서버 안내 문구에서 "이어서 작업"·"작업 탭"으로 바꾼다(작업 절차의 「작업 진행 화면」 절은 「작업 탭」). 지난 기록의 이력 문구는 그대로 둔다.
4. 검증: 워크플로우 Node 테스트를 고쳐 돌리고 새 동작마다 결함을 넣어 본다. 헤드리스 Edge에서 1440px과 375px로 탭 전환·새 작업·이어서 작업·대시보드로·새로 고침·뒤로 가기·작성자 칸을 실제 클릭으로 확인한다.
   - 테스트 체크리스트 초안: AI 항목은 위 검사들, 사람 항목은 코드 리뷰와 탭 전환 사용감.
