다음 행동: 사람은 코드 리뷰와 탭 전환 사용감을 확인한다.

- 날짜: 2026-09-26
- 계기: 사용자가 워크플로우 최종 마무리 코드 리뷰를 요청했다가 멈추고, 먼저 대시보드와 작업을 나누자고 했다. 코드 리뷰는 이 작업 뒤에 한다.

## 구현 계획

추가 질문 없음. 아래 기본값은 AI가 정했으며, 다르게 하려면 승인 전에 알려주면 된다.

1. 화면 구성
   - 왼쪽 메뉴는 대시보드 · 작업 · 작업 절차다. 대시보드에는 작업 현황(목록·필터)과 Wiki 갱신만 두고, 작업 패널은 작업 탭으로 옮긴다.
   - 대시보드의 **새 작업**과 목록의 **이어서 작업**(옛 작업 진행)은 작업 탭으로 바꾸며 새 작업 입력이나 그 작업을 연다. 탭마다 주소(#)가 달라 새로 고침과 뒤로 가기에도 탭과 연 작업이 유지된다.
   - 메뉴에서 작업 탭을 바로 누르면 마지막으로 연 작업을 보이고, 연 적이 없으면 대시보드에서 고르라는 안내를 보인다.
   - 작업 탭의 **닫기**는 **대시보드로**로 바꾼다.
2. 작성자: 작업 탭과 새 작업 입력의 **이름** 칸을 **작성자**로 바꾼다(칸 이름, 읽기 도구 이름, 빈 칸 안내, 서버 오류 문구, 작업 절차의 "이름을 적고 전달합니다"). 기록에 남는 "요청자"·"전달한 사람" 표기는 그대로 둔다.
3. 용어: "작업 진행"을 화면·작업 절차·Wiki 안내·서버 안내 문구에서 "이어서 작업"·"작업 탭"으로 바꾼다(작업 절차의 「작업 진행 화면」 절은 「작업 탭」). 지난 기록의 이력 문구는 그대로 둔다.
4. Markdown 렌더러 하나로: 문서와 작업 탭의 구현 계획(승인 단계의 계획과 접힌 승인된 계획)을 모두 브라우저에서 순정 라이브러리 marked 18.0.14(MIT)로 그린다. Export-Wiki는 ConvertFrom-Markdown 변환을 빼고 원문만 페이지에 싣는다. marked는 mermaid처럼 vendor에 넣어 페이지에 싣고(실행 중 외부 다운로드 없음), 결과는 지금처럼 안전 필터와 링크 처리를 거친다. 계획 속 mermaid 코드 블록도 문서 화면과 같은 mermaid.run으로 그린다.
   - 받을 파일: `marked@18.0.14/lib/marked.umd.js`(46,891바이트)와 `LICENSE`(2,942바이트). 출처는 https://cdn.jsdelivr.net/npm/marked@18.0.14/ (npm 공식 배포본)다. 승인하면 받아 SHA-256과 함께 vendor README에 적고, README에 남은 없어진 테스트 이름도 고친다.
   - 렌더러가 바뀌므로 문서 33개가 지금과 같게 보이는지(표·접는 절·도식·링크) 바꾸기 전후 HTML 구조를 비교한다. 제목 앵커(#…)에 기대는 문서 링크는 없다(0개).
5. 검증: 워크플로우 Node 테스트를 고쳐 돌리고 새 동작마다 결함을 넣어 본다. 헤드리스 Edge에서 1440px과 375px로 탭 전환·새 작업·이어서 작업·대시보드로·새로 고침·뒤로 가기·작성자 칸, 그리고 표·목록·도식이 든 구현 계획과 문서의 표시를 실제 클릭으로 확인한다.
   - 테스트 체크리스트 초안: AI 항목은 위 검사들, 사람 항목은 코드 리뷰와 탭 전환 사용감.
