# 설계·구현·코드 리뷰

## 한줄 요약

확정 기획을 설계와 코드로 구현하고, 인간 코드 리뷰를 수용한 버전을 테스트로 넘깁니다.

작업 단계: 구현

입력은 [최종 기획 확정본](planning.md#최종-기획서-확정본-작성), 기획 판단 기록, 원본과 관련 자료입니다. [전체 흐름](index.md)의 시작·재개 및 공통 판단 규칙을 적용합니다.

## 설계

1. 기획 확정 후 AI가 관련 코드·설정·에셋·호출 경로·제약을 읽기 전용으로 조사합니다. 확인하지 못한 자료는 자료 부족으로 남기고 실제 에셋 값을 추측하지 않습니다.
2. AI가 요구사항별 구현 목록과 설계 판단을 구분해 준비합니다.

| 구분 | 포함할 내용 | 담당 |
| --- | --- | --- |
| 확인할 사실 | 비용 차감 위치·취소 처리·기존 인터페이스 등 현재 근거 | AI 조사 |
| 구현 목록 | 수행 범위·의존 항목·완료 기준·검증 방법 | AI 수행 |
| 설계 판단 | 구조·소유권·인터페이스·예외 처리의 중요한 선택과 영향 | AI 자료 준비, 사람 판단 |

3. **AI 설계 검토 · 답변 반영**과 [공통 판단 절차](index.md#기획설계의-공통-판단-절차)를 통해 구조·인터페이스·데이터 흐름·수명·예외 처리·검증 방법을 통합 설계로 정리합니다. 코드로 확인할 사실이나 합의된 세부 구현은 사람에게 반복 질문하지 않습니다.
4. 기획 동작·범위를 바꾸는 질문이 생기면 설계 최종 확정을 보류합니다. 웹에서는 현재 질문의 답변 결정 후 기획 변경으로 분류된 활성 질문 전체를 별도 기획 변경 작업에 전달합니다. 질문·답변·확정 여부·근거를 보존하며 새 기획을 확정한 뒤 설계도 재검토합니다.
5. 미결정과 자료 부족이 해소되면 사람이 통합 설계·구현 범위를 확인하고 **설계 확정 · AI 구현 시작**을 누릅니다. 이 동작은 설계와 판단 자료를 저장하고 구현 실행까지 요청합니다.

## 구현과 인간 코드 리뷰

1. AI는 확정 설계에 따라 구현·자체 검증합니다. 새로운 제약으로 합의 변경이 필요하면 [변경 절차](index.md#확정-이후-변경)를 적용합니다.
2. AI는 변경 설명, 요구사항·설계별 코드 위치와 diff, 검증 결과·실행 근거·남은 제약을 제시합니다. 웹 diff에는 현재 HEAD 대비 기존 미커밋 변경도 포함되므로 이번 작업의 변경 범위를 구분해 설명합니다.
3. 인간 프로그래머는 실제 코드와 근거를 보고 기획·설계 일치, 오류 조건·수명·상태 전이·회귀를 검토합니다. **수정 요청**이 있으면 AI가 수정·재검증하고 다시 리뷰받습니다. AI 자체 검토는 인간 리뷰 수용을 대신하지 않습니다.
4. **코드 리뷰 승인**을 누르면 AI [테스트](testing.md)가 이어집니다. AI는 확정 기획·설계의 경로와 버전, 구현 기준 커밋·미커밋 변경, 판단·리뷰 결과, 실행 조건·검증 근거를 전달합니다.

## 모듈 리뷰 자료

후속 조치가 필요한 모듈 리뷰는 대상별 기존 문서 하나에 현재 미해결 사항·미확인 범위·필요한 수용 근거만 유지합니다. 모듈 리뷰의 제안은 확정 결정이 아니며 현재 작업의 인간 코드 리뷰 수용 여부를 대신하지 않습니다. 보존과 정리는 [공통 기록 규칙](index.md#기록-위치)을 따릅니다.
