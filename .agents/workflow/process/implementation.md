# 설계·구현·코드 리뷰

AI가 확정 기획을 설계와 코드로 구현하고, 사람이 설계와 실제 코드 리뷰 결과를 판단합니다. [공통 판단·변경 규칙](index.md)을 따릅니다.

## 설계

1. **AI 조사:** [확정 기획](design_review.md#최종-기획서-확정본-작성)과 판단 기록을 바탕으로 코드·설정·에셋·호출 경로·제약을 확인합니다. 미확인 자료와 에셋 값은 추측하지 않습니다.
2. **AI 설계:** 구조·인터페이스·데이터 흐름·수명·예외 처리, 구현 범위·의존성·검증 방법을 통합합니다. 사실과 합의된 세부 구현은 직접 처리하고 중요한 선택만 사람에게 묻습니다.
3. **사람 확정:** 필수 미결정이 해소되면 **설계 확정**을 선택합니다. 설계 저장과 구현 실행이 함께 요청됩니다.

기획 동작·범위를 바꿔야 하면 설계 확정을 보류하고 질문·답변·확정 여부·근거를 기획 변경 작업으로 전달합니다. 새 기획 확정 후 설계를 재검토합니다.

## 구현과 인간 코드 리뷰

1. **AI 구현:** 확정 설계에 따라 구현·자체 검증합니다. 합의 변경이 필요하면 [변경 절차](index.md#확정-이후-변경)를 따릅니다.
2. **AI 제출:** 변경 동작, 요구사항별 코드 위치·diff, 검증 근거·남은 제약을 제시합니다. 웹 diff에 포함된 기존 미커밋 변경과 이번 작업을 구분합니다.
3. **사람 리뷰:** 실제 코드의 기획·설계 일치, 오류 조건·수명·상태 전이·회귀를 확인합니다. 수정 요청은 AI가 처리하고 재검증합니다. AI 자체 검토는 인간 리뷰를 대신하지 않습니다.
4. **테스트 인계:** 승인자 이름을 입력하고 **코드 리뷰 승인** 후 AI 테스트로 넘어갑니다. AI는 확정본·구현 버전(커밋과 미커밋 변경), 판단·리뷰 결과, 실행 조건·검증 근거를 연결합니다.

모듈 리뷰의 제안은 확정 결정이나 현재 작업의 코드 리뷰 수용을 대신하지 않습니다. 후속 조치가 필요한 결과만 [기록 규칙](index.md#기록-위치)에 따라 유지합니다.
