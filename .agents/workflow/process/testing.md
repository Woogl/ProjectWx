# 테스트

AI가 확정 기획과 실제 실행 결과를 대조하고, 사람이 인간 확인 필요 항목과 최종 결과를 판단합니다.

## 진행 절차

1. **AI 준비:** 확정 기획·설계와 코드 리뷰가 수용한 구현 버전을 확인합니다. 정상·예외·경계·회귀 시나리오에 요구사항 근거, 사전 조건, 재현 순서, 기대 결과와 관찰 방법을 적습니다.
2. **AI 실행:** 지원되는 자동화·플레이 제어 수단으로 실행하고 버전·환경·명령·맵·로그 등 근거를 연결합니다. 문서 변경은 구조·링크·원자료를 확인하며 Wiki는 순정 Lint, Workflow·README는 저장소 링크 검사를 적용합니다.
3. **AI 대조:** 실제 결과를 기대 결과와 비교합니다. 빌드 성공·에디터 실행·오류 로그 부재만으로 플레이 검증을 통과시키지 않습니다.
4. **사람 확인:** AI가 확인하지 못한 장면·애니메이션·조작감은 재현 방법·기대 결과·확보한 근거·미확인 이유를 전달합니다. 확인자·일자·결과를 같은 항목에 기록합니다.
5. **수정과 수용:** AI가 실패 원인에 따라 구현 또는 기획을 수정하고 영향받는 항목을 재검증합니다. 코드 변경은 다시 인간 코드 리뷰를 받습니다. 테스터가 결과와 제약을 확인해 승인자 이름을 입력하고 **테스트 완료** 버튼을 선택하면 [정리 대기](completion.md)로 넘깁니다.

## 결과 구분

### 대시보드의 기존 작업 기록

대화로 진행한 작업은 현황의 **테스트 결과**에서 처리할 AI(Codex·Claude Code·Gemini CLI 중 연결된 서비스)와 확인자·확인 범위를 입력하고 **이상 없음 / 이상 있음**을 선택해 전달할 수 있습니다. 문제가 있으면 재현 상황을 기록합니다. 기획서를 다시 등록하지 않고 해당 Task의 최신 결정과 미해결 사항을 기준으로 이어갑니다. AI 선택은 접수·재전송에 유지되며 처리 실패·중단 뒤 다른 AI로 재시도하면 이전 AI와 결과도 보존합니다.

AI는 이상 없음의 수용 범위를 대조하고 남은 정리를 수행하며, 이상 있음은 기존 합의 안에서 수정·검증합니다. 코드 변경·미실행·남은 사람 확인이 있으면 재확인으로 표시합니다. 미해결 승인·실패 검증은 확인 필요로 남기고, 일부 테스트 수용을 전체 완료나 코드 리뷰 승인으로 확대하지 않습니다.

서버는 접수 원문·확인자·시각·대상 버전과 AI 결과를 보존하고 원래 Task·목차를 갱신합니다. 입력 중 Task·코드가 변경되면 최신 상태를 다시 확인해야 합니다. 기존 웹 작업의 **테스트 완료** 경로는 아래 수용 기준을 유지합니다.

### 개별 시나리오 판정

| 결과 | 기준 |
| --- | --- |
| 통과 | 해당 버전의 시나리오 수행과 기대 결과를 증거로 확인 |
| 실패 | 기대 결과와 실제 결과가 다름 |
| 미실행 | 환경·제어 수단 부족 등으로 수행하지 못함 |
| 인간 확인 필요 | AI가 직접 확인할 수 없거나 판단이 모호함 |

미실행·인간 확인 필요를 전체 통과로 표시하지 않습니다. 예외 수용은 사람의 판단과 사유로 남기며 통과로 바꾸지 않습니다. 승인자·일자·범위와 검증 근거는 [기존 작업 기록](index.md#기록-위치)에 연결하고, 수용 전에는 테스트 단계에 머뭅니다.
