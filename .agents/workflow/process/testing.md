# 테스트

## 한줄 요약

확정 기획의 기대 결과를 실제 실행 증거와 대조하고, 미검증 범위를 구분해 사람이 최종 수용합니다.

작업 단계: 테스트

입력은 최종 기획·설계 확정본과 판단 기록, [인간 코드 리뷰가 수용한 구현](implementation.md)의 버전, 실행 조건·관련 자료입니다. AI가 준비·실행·증거 수집을 맡고 테스터는 인간 확인 필요 항목과 최종 결과를 판단합니다.

## 진행 절차

1. AI가 [확정 기획](planning.md#최종-기획서-확정본-작성)에서 시나리오를 만듭니다. 항목마다 요구사항 근거, 사전 조건·맵·데이터, 재현 순서, 기대 결과, 로그 또는 관찰 방법을 적습니다. 정상·예외·경계 조건과 변경 영향에 따른 회귀를 포함합니다.
2. 실행 환경의 자동화·플레이 제어 수단을 확인하고, 지원되는 범위에서 백그라운드 에디터·플레이 시나리오를 실행합니다. 실행 명령·맵·시각·로그 경로를 기록하고 에디터 실행과 실제 시나리오 수행을 구분합니다. 제어 수단이 없거나 실행에 실패하면 사유를 남깁니다. 문서만 변경한 작업은 Wiki 구조·링크·원자료 점검으로 검증합니다.
3. 해당 실행의 증거로 기대 결과와 실제 결과를 대조합니다. 오류 로그가 없거나 빌드가 성공했다는 사실만으로 플레이 검증을 통과시키지 않습니다.
4. AI가 확인할 수 없거나 판단이 모호한 장면·애니메이션·조작감 등은 **인간 확인 필요**로 전달합니다. 확인할 장면·재현 순서·기대 결과·확보한 근거·직접 확인하지 못한 이유를 함께 제시하고, 테스터가 확인하면 확인자·일자·결과를 같은 항목에 반영합니다.
5. 실패 원인에 따라 [구현](implementation.md) 또는 [기획](planning.md)으로 돌아가 수정하고 관련 시나리오를 재검증합니다. 검증 중 코드가 바뀌면 코드 리뷰로 돌아가 변경 버전에 대한 수용을 받습니다. 사람이 다시 확인할 항목만 재전달합니다.
6. 테스터가 결과와 남은 제약을 확인하고 **결과 수용 · 완료**를 선택하면 [완료](completion.md)로 넘깁니다. 승인자·승인일·승인 범위를 기록하며, 승인 전에는 테스트 단계에 머뭅니다.

## 결과 구분과 기록

| 결과 | 기준 |
| --- | --- |
| 통과 | 해당 버전에서 시나리오 수행과 기대 결과를 증거로 확인 |
| 실패 | 기대 결과와 실제 결과가 다름 |
| 미실행 | 환경·제어 수단 부족 등으로 수행하지 못함 |
| 인간 확인 필요 | AI가 직접 확인하지 못하거나 판단이 모호하여 테스터 확인이 필요함 |

미실행·인간 확인 필요 항목이 남으면 전체 통과로 표시하지 않습니다. 예외 수용은 인간의 명시적 판단과 사유를 남기며 테스트 통과로 바꾸지 않습니다.

후속 테스트·수용에 필요한 시나리오와 결과에는 확정본 버전, 구현 기준 커밋·미커밋 변경, 실행 환경·로그 근거를 연결합니다. [공통 기록 규칙](index.md#기록-위치)에 따라 기존 작업 기록을 갱신하고 실행마다 보고서를 추가하지 않습니다.
