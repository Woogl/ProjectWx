# 작업 절차

## 한줄 요약

사람이 기획·설계·리뷰·테스트를 판단하고, AI가 조사부터 구현·검증·완료 정리까지 수행합니다.

사람은 기획·설계·코드 리뷰·테스트 결과를 판단하고, AI는 조사·구현·검증·기록·인계를 맡습니다. 공통 규칙은 이 문서에, 단계별 수행 방법은 아래 문서에 둡니다.

### AI의 시작과 재개

1. 사용자 요청과 [프로젝트 규칙](../../../AGENTS.md), [Wiki 목차](../../wiki/index.md)에서 관련 지식·원자료·기존 작업 자료를 확인합니다. 기존 사용자 변경을 보존합니다.
2. Workflow 작업을 이어받았다면 시작·재개·결과 인계 전에 저장소 루트에서 `node .agents/scripts/Wiki-AI.cjs --current "작업 제목"`을 실행합니다. 변경 연결 전체의 최신 기획·설계와 `pending` 보류 범위를 확인하며, 개별 인계 파일의 날짜나 제목만으로 구현 기준을 고르지 않습니다. 일반 대화 작업에 이 조회를 위한 작업을 새로 만들지는 않습니다.
3. 이전 판단·미해결 사항·검증 결과를 현재 원자료와 대조합니다. 과거 코드 버전의 승인이나 테스트 결과를 현재 버전의 근거로 옮기지 않습니다.
4. 현재 단계의 입력과 진행 조건을 확인하고 합의한 범위에서 수행합니다. 사실 조사·자료 수집·문서 조립·인계는 AI가 맡으며 사람에게 반복 입력이나 복사를 요구하지 않습니다.

### 기획·설계의 공통 판단 절차

1. AI는 확인할 사실, 수행할 작업, 사람이 선택할 판단을 구분합니다. 원자료에 명확한 사실은 직접 추출하고, 미정·충돌·중요한 선택만 질문합니다. 각 질문에는 식별자·원자료 근거·선택지와 영향·필요한 추천 이유를 붙입니다. 추천은 결정이 아닙니다.
2. 사람은 선택지 또는 직접 답변으로 항목별 **이 답변으로 결정**을 누릅니다. 미확정 답변을 AI가 대신 확정하지 않으며, 보류·제외는 적용 범위를 기록하고 필수 미결정의 해소로 간주하지 않습니다.
3. 현재 질문의 답변이 모두 결정되면 AI가 원본·답변을 유효한 규칙·예외·완료 기준으로 통합하고 재검토합니다. 처음부터 질문이 없으면 빈 체크리스트로 최종 검토할 수 있습니다. 답변 확정 직후에는 전체를 확정하지 않고 재검토 결과를 기다립니다.
4. 추가 판단은 영향받는 항목만 묻습니다. 기존 답변을 다시 열 때는 식별자·이전 답변·변경 이유를 제시하고 원문을 보존합니다. 범위 제외에는 사유와 인간 판단 근거가 필요하며, 웹의 **검토 결과 반영 · 기존 판단 보존**으로 승인합니다. AI 응답에서 질문이 빠진 것만으로 제외하지 않습니다.
5. 필수 미결정·자료 부족·충돌이 해소되면 사람이 통합본과 판단 기록을 최종 확정합니다. **개별 답변 결정, 단계 전체 확정, 코드 리뷰 수용, 테스트 수용은 서로 다른 판단입니다.**

### 확정 이후 변경

확정본과 판단 원문은 덮어쓰지 않습니다. 요구사항·설계 변경이 필요하면 AI가 이유·영향·대안을 준비하고 별도 변경 작업으로 기존 원본·판단·초안을 연결합니다. 사람은 영향받는 항목만 재판단합니다. 단순 버그 수정과 합의 범위 안의 세부 구현에는 변경 작업이 필요하지 않습니다.

기획 변경을 확정하면 설계도 재검토·확정해야 하며, 새 기획에 이전 설계를 적용하지 않습니다. 설계만 바꾸면 확정 기획을 이어받습니다. 새 설계 확정 뒤 영향받는 구현·리뷰·테스트를 다시 수행하고 이전 승인은 당시 버전의 기록으로 보존합니다.

변경 검토 중 영향받는 구현은 보류합니다. 영향 없는 조사·작업은 계속할 수 있으나 웹 실행기의 잠금은 별도 제약입니다. 실행 중인 같은 저장소에서는 추가 구현과 확정 기준 변경을 막으며, 보류 중인 작업의 실행을 우회하지 않습니다. 변경 생성·복구가 실패하면 기존 확정본을 유지하고 공용 기록에 연결되지 않은 자료는 구현 기준으로 사용하지 않습니다.
