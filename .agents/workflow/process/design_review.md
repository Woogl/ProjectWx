# 기획서 검토

개발자가 기획 담당자에게 전달받은 기획서를 검토하고 설계로 넘깁니다. 기획서는 툴 밖에서 작성하며, 기획 담당자의 직접 사용을 전제로 하지 않습니다. AI는 누락·모순·기존 규칙과의 충돌·구현 영향을 조사합니다.

## 진행 절차

1. **입력:** 새 작업을 만들거나 기존 작업을 열고 전달받은 기획서 원본을 붙여넣거나 첨부합니다.
2. **검토:** AI가 목적·규칙·완료 기준을 정리하고 관련 Wiki·원자료와 변경 영향을 조사합니다.
3. **판단:** 개발자는 미정·충돌을 확인하고, 기획 판단이 필요한 항목은 기획 담당자와 협의한 답변을 기록합니다. AI는 답변을 반영해 재검토합니다.
4. **확정:** 필수 미결정이 해소되면 사람이 **검토본 확정 · 설계 검토**를 눌러 설계로 넘깁니다.

[실행·저장 안내](../usage.md) · [공통 판단·변경 규칙](index.md)

## 검토 원칙

- 속도보다 충분한 조사를 우선하고, 확인한 근거와 미확인 사항을 구분합니다.
- 기존 구조는 참고 근거입니다. 신규 기획의 목적을 먼저 보고 변경·확장·대체 방안도 검토합니다.
- 기획 확정에 필수인 문제만 해결합니다. 단순 미구현·상세 설계 부재로 기획을 막지 않습니다.
- 이미 정한 방향은 반복 승인받지 않고, 변경 영향이 있는 판단만 다시 확인합니다.

## 최종 기획서 확정본 작성

AI는 원본의 목적·범위, 동작·수치·예외·완료 기준을 보존하고, 확인된 답변과 변경 영향·판단 근거를 설계에 넘길 검토본으로 통합합니다. 원본에 없는 기획을 새로 작성하거나 미정 사항을 임의로 채우지 않습니다. 기획 변경은 담당자와 확인한 판단을 반영하고, 사람이 검토본을 최종 확정합니다.
