# 위키 적재

자료 하나를 적재하면 요약 문서 하나를 쓰고, 그 내용이 닿는 엔티티·개념 문서와 색인(`Wiki/index.md`)을 함께 고친 뒤 `Wiki/log.md`에 남긴다.
문서 형식과 원칙의 정본은 `Wiki/AGENTS.md`다. 시작할 때 그 파일과 `Wiki/index.md`를 먼저 읽고, 이 스킬과 어긋나면 `Wiki/AGENTS.md`를 따른다.

## 1. 자료 정하기

| 인자 | 자료 |
|---|---|
| 파일·폴더 경로 | 그 경로 아래 파일 |
| 없음 | 아직 적재하지 않은 `Docs/` 문서(6절 점검 스크립트의 '미적재 자료' 항목) |
| 대화로 정한 결정 | 사용자가 말한 내용. 요약 문서 없이 관련 문서의 결정 절에 "사용자 결정"과 날짜로 적는다 |

아직 적재하지 않은 문서는 위키 어디에도 경로가 없는 문서다. 요약 문서의 자료 줄과 `Wiki/log.md`의 제외 목록이 경로를 담는다.

- 강의·학습 자료처럼 프로젝트 결정이 아닌 자료, 중복 사본, 읽을 수 없는 이진 파일은 적재하지 않는다. 다음 실행에서 다시 후보가 되지 않게 로그의 제외 목록에 전체 경로와 이유를 남긴다.
- 적재할 자료와, 각 자료가 닿을 엔티티·개념 문서를 사용자에게 짧게 보여 주고 확인받는다. 사용자가 바로 진행하라고 했으면 건너뛴다.

## 2. 읽기

- 자료는 끝까지 읽는다. PDF는 Read 도구의 `pages`로 20쪽씩 나눠 읽고, HTML은 태그를 빼고 본문만 본다.
- 자료마다 커밋을 구한다: `git log -1 --format=%h -- "<경로>"`.
- 자료가 6개를 넘으면 주제별 묶음으로 나눠 서브에이전트(`general-purpose`)에 맡긴다. 한 번에 6개까지 병렬로 띄우고, 읽기 전용이라는 점과 아래 노트 형식을 전한다.
- 서브에이전트의 트랜스크립트 파일은 읽지 않는다. 결과는 완료 메시지로 받는다.

자료마다 남길 노트:

```
### <경로>
- 커밋 / 자료 안 날짜
- 종류 / 상태: 초안 | 확정 | 대체됨(무엇에 의해)
- 핵심 내용: 규칙·수치·조건·순서를 정확히
- 결정(날짜) / 미정
- 다른 자료와의 대체·중복·모순
- 등장하는 엔티티 / 다루는 개념
```

## 3. 요약 문서 쓰기

- `Wiki/요약/<자료 파일 이름>.md`에 `Wiki/AGENTS.md`의 요약 형식으로 쓴다. 파일 이름은 확장자를 빼고 공백만 `-`로 바꾼다.
- 요지에는 규칙·수치·조건을 정확히 옮긴다. 다른 자료에 대체됐거나 어긋나면 상태 줄과 요지에 적는다.
- 같은 자료를 다시 적재할 때는 기존 요약 문서를 고치고 커밋을 새로 적는다.

## 4. 엔티티·개념 문서 갱신

- 노트의 엔티티와 개념마다 `Wiki/index.md`에서 기존 문서를 찾는다.
- 있으면 고친다. 기획·결정·미결 절에 새 내용을 넣고, 출처 절에 요약 문서 링크를 더한다.
- 없으면 만든다. 엔티티는 이름 있는 대상(캐릭터·적·보스·장소·장치·세력·아이템), 개념은 시스템·규칙·방침이다.
- 한 자료에만 잠깐 나오는 대상은 문서를 만들지 않고 가까운 개념 문서 안에 둔다. 개념 문서 안에서 한 대상의 내용이 커지면 엔티티 문서로 떼어 낸다.
- 새 내용이 기존 기획·결정과 어긋나면 지우지 말고 날짜를 붙여 함께 적고, 보고에 올린다.
- 구현 절에는 코드에서 확인한 사실만 쓴다. 다른 세션의 미커밋 변경이 섞여 있을 수 있으니 `git grep <패턴> HEAD -- Source`와 `git ls-tree -r --name-only HEAD`로 확인하고, 코드 출처에 커밋을 적는다. 확인하지 못한 것은 쓰지 않거나 "(추정)"을 붙인다.
- 마지막으로 요약 문서의 '반영한 문서' 절에 고친 엔티티·개념 문서를 모두 링크한다.

## 5. 색인과 로그

- `Wiki/index.md`에 새 요약 문서를 요약 절의 자료 폴더 분류에, 새 엔티티·개념 문서를 해당 분류에 넣는다. 고친 문서의 한 줄 요약이 낡았으면 고친다.
- `Wiki/log.md` 맨 아래에 `## [YYYY-MM-DD] ingest | <자료 경로>`와 만든·고친 문서를 덧붙인다. 자료가 여럿이면 한 항목으로 묶고, 적재하지 않은 자료와 이유, 구현 절을 확인한 HEAD를 적는다.

## 6. 점검

쓴 뒤 `/wiki-lint`의 기계 점검 스크립트를 돌린다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agents/skills/wiki-lint/scripts/Invoke-WikiLint.ps1
```

- 이번에 쓴 문서에 대해 깨진 링크, 고아 문서, 출처·반영 짝, 색인 누락이 비어야 한다.
- 이번 자료가 미적재 자료에 남아 있으면 안 된다. `Docs/` 밖 자료는 요약 문서의 자료 줄에 경로가 있는지 직접 본다.
- 연결 후보는 문맥을 보고 맞는 것만 링크한다.

## 7. 보고

짧게 보고한다.

- 쓴 요약 문서 수, 만든·고친 엔티티·개념 문서
- 적재하지 않은 자료와 이유
- 기존 내용과 어긋나 함께 적어 둔 것 중 중요한 것 몇 개

커밋은 하지 않는다(`/push`가 맡는다). 단 8절 무인 실행은 직접 커밋·푸시한다.

## 8. 무인 실행 (주간 Routine)

클라우드 Routine 「Wiki 주간 적재·점검 + 푸시」가 매주 월요일 07:00(KST) 새 클론에서 사람 없이 이 절대로 실행한다. 1~7절과 다른 점만 적는다.

**점검 스크립트** — Linux라 `powershell` 대신 `pwsh -NoProfile -File .agents/skills/wiki-lint/scripts/Invoke-WikiLint.ps1`로 돌린다.
- `pwsh`가 없으면 PowerShell 공식 linux-x64 tar.gz(예: v7.4.6)를 `/tmp`에 받아 풀어 쓴다.
- 그래도 돌릴 수 없으면 `/wiki-lint` 1절 표의 항목을 git·grep으로 직접 점검하고, 그렇게 했다고 로그에 적는다.

**대상** — 점검 스크립트의 '미적재 자료'와 '낡은 자료'다. 낡은 자료는 기존 요약 문서를 고쳐 다시 적재한다. 둘 다 없으면 적재를 건너뛰고 점검으로 넘어간다.

**바뀌는 규칙**
- 1절의 사용자 확인을 건너뛴다.
- 판단이 필요한 모순은 한쪽을 고르지 않고 양쪽을 날짜와 함께 적은 뒤 미결 절에 남긴다.
- 언리얼 엔진이 없으니 에디터·MCP는 쓰지 않는다. 구현 확인은 git으로만 한다.

**점검** — 적재 뒤 `.agents/skills/wiki-lint/SKILL.md` 6절(무인 실행)대로 점검하고 결과를 로그에 남긴다.

**커밋·푸시**
1. `Wiki/` 아래 바뀐 파일만 경로를 지정해 `git add` 한다(`-A`·`.` 금지). `git status`로 의도한 파일만 올라갔는지 본다.
2. 커밋 메시지는 `YYYY-MM-DD 위키 주간 적재·점검`(KST 날짜)이고, 본문에 적재한 자료 수와 점검 결과를 한 줄씩 적는다.
3. `git push origin HEAD:main` 한다. 거절되면 `git pull --rebase origin main` 뒤 한 번 다시 시도한다.
4. 바뀐 파일이 없으면 커밋하지 않는다.

**보고** — 7절에 적재한 자료 수, 점검 항목별 건수, 커밋 해시와 푸시 결과를 더한다. 실패하거나 건너뛴 단계는 숨기지 않는다.
