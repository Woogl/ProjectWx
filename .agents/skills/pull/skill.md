# 원격 저장소 최신버전 가져오기

원격 저장소의 최신 내용을 현재 브랜치에 가져오라.
병합은 다음 순서로 처리한다: (1) git이 자동 병합할 수 있는 변경은 그대로 둔다. (2) 충돌이 남으면 각 파일을 열어 양쪽 변경을 모두 살리는 방향으로 직접 병합한다(한쪽을 통째로 버리지 않는다). (3) 같은 코드 라인을 양립 불가하게 고쳐 어느 한쪽만 택할 수밖에 없는 hunk만 사용자에게 선택을 맡긴다.

## 절차

### 1단계: 현재 상태 확인

`git status`로 로컬 변경 사항을 확인하라.

### 2단계: Pull 실행

`git -c merge.autoStash=false pull --no-rebase --no-edit`로 원격 저장소의 최신 내용을 가져오라. 자동 백업 없이 현재 작업 트리에서 병합하며, 사용자 Git 설정의 자동 stash도 이 명령에서 비활성화한다.
- 추적 대상(upstream)이 없어 실패하면 `git -c merge.autoStash=false pull --no-rebase --no-edit origin <브랜치명>`으로 원격·브랜치를 명시해 가져오라.
- 로컬 변경을 덮어쓸 수 있어 Git이 병합을 거부하면 해당 파일과 원인을 보고하고 종료한다. 백업을 만들거나 로컬 변경을 버려 진행하지 않는다.
- git이 자동 병합에 성공하면 그대로 진행한다.
- 충돌 파일이 남으면, 먼저 각 충돌 파일을 열어(Read) 직접 병합하라(Edit): 충돌 마커(`<<<<<<<`/`=======`/`>>>>>>>`)를 제거하되, 서로 다른 관심사를 건드린 변경은 **양쪽 다 남긴다**(한쪽을 통째로 버리지 않는다). 이때 삭제·리네임된 심볼을 참조하는 옛 코드가 있으면 최신(원격) 쪽을 따른다.
- 같은 코드 라인을 양립 불가하게 고쳐 어느 한쪽만 택할 수밖에 없는 hunk만, 사용자에게 원격(theirs)·로컬(ours) 중 선택을 받아 반영하라. (파일 전체를 한쪽으로 대체해야 하면 `git checkout --theirs`/`--ours`)
- 해결 후 `git diff --check`로 남은 충돌 마커가 없는지 확인하고 `git add`, `git commit --no-edit`으로 병합을 완료하라.

### 3단계: 결과 보고

다음을 요약하여 보고하라:
- 가져온 커밋 수
- 변경된 파일 목록
- 충돌 해결 결과 (해당되는 경우)
