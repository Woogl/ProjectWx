# 원격 저장소 최신버전 가져오기

원격 저장소의 최신 내용을 현재 브랜치에 가져오라.
병합은 다음 순서로 처리한다: (1) git이 자동 병합할 수 있는 변경은 그대로 둔다. (2) 충돌이 남으면 각 파일을 열어 양쪽 변경을 모두 살리는 방향으로 직접 병합한다(한쪽을 통째로 버리지 않는다). (3) 같은 코드 라인을 양립 불가하게 고쳐 어느 한쪽만 택할 수밖에 없는 hunk만 사용자에게 선택을 맡긴다.

## 절차

### 1단계: 현재 상태 확인

`git status`로 로컬 변경 사항을 확인하라.

### 2단계: 로컬 변경 사항 임시 저장

커밋되지 않은 변경 사항이 있으면 `git stash -u`로 자동 임시 저장하라. 사용자에게 묻지 말고 바로 진행하라.
`git stash -u`가 "No local changes to save"를 출력하면 실제로 저장된 것이 없으므로 4단계 복원은 건너뛴다. (저장 여부는 stash 출력이나 `git stash list`로 확인한다.)

### 3단계: Pull 실행

`git pull --no-rebase --no-edit`로 원격 저장소의 최신 내용을 가져오라. (머지를 강제해 아래 ours/theirs 기준을 고정하고, 머지 커밋 메시지 에디터가 떠서 멈추는 것을 막는다.)
- 추적 대상(upstream)이 없어 실패하면 `git pull --no-rebase --no-edit origin <브랜치명>`으로 원격·브랜치를 명시해 가져오라.
- git이 자동 병합에 성공하면 그대로 진행한다.
- 충돌 파일이 남으면, 먼저 각 충돌 파일을 열어(Read) 직접 병합하라(Edit): 충돌 마커(`<<<<<<<`/`=======`/`>>>>>>>`)를 제거하되, 서로 다른 관심사를 건드린 변경은 **양쪽 다 남긴다**(한쪽을 통째로 버리지 않는다). 이때 삭제·리네임된 심볼을 참조하는 옛 코드가 있으면 최신(원격) 쪽을 따른다.
- 같은 코드 라인을 양립 불가하게 고쳐 어느 한쪽만 택할 수밖에 없는 hunk만, 사용자에게 원격(theirs)·로컬(ours) 중 선택을 받아 반영하라. (파일 전체를 한쪽으로 대체해야 하면 `git checkout --theirs`/`--ours`)
- 해결 후 `git diff --check`로 남은 충돌 마커가 없는지 확인하고 `git add`, `git commit --no-edit`으로 병합을 완료하라.

### 4단계: Stash 복원

2단계에서 stash를 사용했다면 `git stash pop`으로 복원하라.
- 충돌 파일이 남으면 3단계와 동일하게 처리하라: 먼저 각 파일을 열어(Read) 양쪽 변경을 모두 살리는 방향으로 직접 병합하고(Edit)(충돌 마커 제거, 서로 다른 관심사는 둘 다 유지, 삭제·리네임된 심볼 참조는 최신 쪽을 따름), 같은 라인을 양립 불가하게 고친 hunk만 사용자에게 현재(ours)·stash(theirs) 중 선택을 받아라. (파일 전체 대체는 `git checkout --ours`/`--theirs`)
- 해결 후 `git diff --check`로 남은 충돌 마커가 없는지 확인하고 `git add`로 충돌을 해결한 뒤 `git stash drop`으로 stash를 제거하라.

- 변경된 파일 목록

- stash 복원 결과 (해당되는 경우)
