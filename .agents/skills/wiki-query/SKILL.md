# 위키 질문

위키에서 관련 문서를 찾아 읽고, 출처를 달아 답한다.
규칙의 정본은 `Wiki/AGENTS.md`다. 시작할 때 그 파일과 `Wiki/index.md`를 먼저 읽는다.
질문이 비어 있으면 무엇을 물을지 되묻는다.

## 1. 문서 찾기

- 색인에서 질문이 가리키는 개념·엔티티 문서를 고른다.
- 색인의 한 줄 요약만으로 고르기 어려우면 `Grep`으로 `Wiki/` 전체에서 핵심어를 찾는다. 같은 대상을 부르는 다른 이름(예: 앞잡·그로기 피니시·처형)도 함께 찾는다.
- 개념·엔티티 문서를 먼저 읽는다. 세부 근거가 필요하면 그 문서의 출처 절에 있는 요약 문서를 읽고, 요약으로도 부족하면 요약에 적힌 자료를 직접 읽는다.

## 2. 최신인지 확인

- 답에 쓰는 요약 문서마다 자료가 그 뒤 바뀌었는지 본다: `git log --oneline <요약의 커밋>..HEAD -- "<자료 경로>"`.
- 바뀌었으면 바뀐 자료를 직접 읽고 답한다. 위키가 낡았다는 사실을 답 끝에 알린다.
- 구현을 묻는 질문이면 위키의 구현 절을 코드로 확인한다(`git grep <패턴> HEAD -- Source`). 위키와 코드가 다르면 코드가 맞다고 답하고 차이를 알린다.

## 3. 답하기

- 결론부터 짧게 답한다.
- 근거가 되는 문장이나 항목마다 출처를 단다. 위키 문서는 저장소 기준 경로로 링크하고, 자료를 직접 읽었으면 자료 경로를 적는다.
- 기획(자료가 정한 것), 구현(코드가 하는 일), 결정, 미결을 섞지 않는다. 문서끼리 어긋나거나 정해지지 않은 것은 그렇다고 밝힌다.
- 위키와 자료에 없는 내용은 지어내지 않고 "위키에 없다"고 답한다. 위키 밖에서 확인한 내용은 그렇다고 밝힌다.
- 비교는 표로, 나머지는 짧은 문장과 목록으로 쓴다.

```
<결론 한두 문장>

- <근거> ([<문서 제목>](Wiki/개념/<파일>.md))
- <근거> ([<자료 이름>](Wiki/요약/<파일>.md))

미결: <정해지지 않은 점> ([<문서 제목>](Wiki/개념/<파일>.md))
```

## 4. 저장 (사용자가 원할 때만)

- 답이 여러 문서를 엮은 새 정리이거나 다시 물을 만한 내용이면, 개념 문서로 저장할지 답 끝에 한 줄로 묻는다.
- 사용자가 원하면 `Wiki/AGENTS.md` 형식으로 개념 문서를 만들거나 기존 문서에 절을 더한다. 출처 절에는 답에 쓴 요약 문서를 링크한다.
- 새 문서는 `Wiki/index.md`의 알맞은 분류에 넣고, `Wiki/log.md` 맨 아래에 `## [YYYY-MM-DD] query | <질문>`과 만든·고친 문서를 덧붙인다.

저장 요청이 없으면 아무 파일도 고치지 않는다. 낡은 문서를 발견해도 고치지 않고 알리기만 한다. 다시 적재하는 일은 `/wiki-ingest`가 맡는다.
