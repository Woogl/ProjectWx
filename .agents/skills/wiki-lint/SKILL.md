# 위키 점검

위키를 점검해 문제를 목록으로 보고하고, 사용자가 고른 것만 고친다.
규칙의 정본은 `Wiki/AGENTS.md`다. 시작할 때 그 파일과 `Wiki/index.md`를 먼저 읽는다.
인자로 문서를 주면 그 문서와 링크로 이어진 문서만 읽어서 점검하고, 없으면 위키 전체를 본다. 기계 점검은 항상 전체를 돈다.
사용자가 직접 부를 때는 1~5절을 따르고, 주간 Routine이 부를 때는 6절을 따른다.

## 1. 기계 점검

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agents/skills/wiki-lint/scripts/Invoke-WikiLint.ps1
```

| 항목 | 뜻 | 보통의 처리 |
|---|---|---|
| 낡은 자료 | 요약 문서의 커밋 뒤에 자료가 바뀌었다 | `/wiki-ingest`로 다시 적재 |
| 사라진 자료 | 요약 문서의 자료가 HEAD에 없다 | 요약 상태를 고치고 관련 문서 확인 |
| 낡은 코드 출처 | 엔티티·주제 문서의 코드 출처가 커밋 뒤에 바뀌었다 | 구현 절을 코드로 다시 확인 |
| 없는 코드 이름 | 구현 절이 인용한 클래스·경로가 HEAD에 없다 | 구현 절 정정 |
| 깨진 링크 | 링크 대상 문서가 없다 | 링크 정정 |
| 고아 문서 | 다른 문서에서 들어오는 링크가 없다(색인·로그 제외) | 관련 문서에서 링크하거나 합침 |
| 출처·반영 짝 | 요약의 '반영한 문서'와 엔티티·주제의 출처가 서로 맞지 않는다 | 양쪽을 맞춤 |
| 연결 후보 | 다른 엔티티·주제 문서의 제목을 쓰면서 링크하지 않았다 | 맞는 것만 링크 |
| 색인 누락 | `index.md`에 없다 | 색인에 넣음 |
| 미적재 자료 | 위키 어디에도 없는 `Docs/` 문서 | `/wiki-ingest`로 적재하거나 로그 제외 목록에 남김 |

자료·코드의 존재, 변경 이력, 미적재 후보는 실행 시작 시점의 HEAD를 기준으로 검사한다. 스테이징된 추가·삭제는 이 판정을 바꾸지 않는다. 위키 문서와 링크는 방금 편집한 내용을 점검할 수 있도록 현재 작업 파일을 읽는다.

연결 후보는 단순 문자열 일치라 오탐이 있다. 문맥을 보고 실제로 그 대상을 가리키는 것만 보고한다.

## 2. 의미 점검

기계로 못 찾는 것을 읽어서 찾는다. 엔티티·주제 문서마다 그 문서와 출처 절의 요약 문서를 함께 읽는다.
문서가 많으면 색인의 분류(### 단위)별로 서브에이전트(`general-purpose`)에 나눠 맡기고, `AGENTS.md`의 병렬 상한을 지킨다. 서브에이전트에는 읽기 전용이라는 점과 아래 항목을 전한다.

- 모순: 같은 대상에 대해 문서끼리 수치·조건·규칙이 다른 곳. 어느 쪽이 더 새 자료에 근거하는지 요약 문서의 날짜·커밋으로 판단해 함께 적는다. 이미 미결 절에 적힌 모순은 '기록됨'으로 따로 표시한다.
- 낡은 주장: 더 새 자료가 뒤집었는데 본문이 옛 내용을 현재처럼 쓰는 곳, 미결 절에 남아 있지만 이미 풀린 항목.
- 빠진 문서: 두 개 이상의 문서에 나오지만 자기 문서가 없는 대상·주제. `Wiki/AGENTS.md` 기준으로 엔티티·주제 문서를 만들 만한지 판단해 제안한다.
- 빠진 연결: 내용상 이어져야 하는데 관련 절에 링크가 없는 문서 쌍.
- 다음 질문: 미결 항목 중 기획자에게 물어볼 만한 것, 적재하면 공백이 메워질 자료.

## 3. 보고

- 항목별로 묶어 `문서 — 문제 — 제안하는 처리`를 한 줄씩 적는다. 문서는 저장소 기준 경로로 링크한다.
- 모순, 낡은 주장, 깨진 링크를 먼저 둔다.
- 고칠 것을 사용자에게 고르게 한다. 고르기 전에는 아무 파일도 고치지 않는다.

## 4. 고치기 (사용자가 고른 것만)

- 낡은 자료는 `/wiki-ingest` 절차로 다시 적재한다.
- 링크·색인·출처 짝은 바로 고친다.
- 모순과 낡은 주장은 지우지 말고 날짜를 붙여 정리하고, 어느 쪽이 최신인지 본문에 밝힌다. 판단이 필요한 모순은 미결 절로 옮긴다.
- 새 엔티티·주제 문서를 만들면 `Wiki/AGENTS.md` 형식을 따르고 색인에 넣는다.
- 고친 뒤 1절 기계 점검을 다시 돌려 고친 항목이 사라졌는지 본다.

## 5. 기록

`Wiki/log.md` 맨 아래에 `## [YYYY-MM-DD] lint | <찾은 것과 고친 것 요약>`을 덧붙인다. 고친 것이 없어도 점검한 사실과 주요 발견을 남긴다.

커밋은 하지 않는다(`/push`가 맡는다).

## 6. 무인 실행 (주간 Routine)

사용자가 승인한 주간 Routine에서 호출했을 때만 [references/unattended.md](references/unattended.md)를 읽고 실행한다. 일반 실행의 확인·변경 범위·커밋 규칙을 무인 실행에 임의로 적용하거나 그 반대로 확대하지 않는다.
