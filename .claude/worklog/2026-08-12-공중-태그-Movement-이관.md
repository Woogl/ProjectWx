# 공중 상태 태그를 Movement 계층으로 이관

## 계획

### 목표
`State.InAir`를 `Movement.InAir`로 바꾼다. 이 태그는 캐릭터의 처지가 아니라 이동 모드를 그대로 옮긴 값이라 State 계층과 성격이 다르고, 앞으로 늘어날 이동 관련 태그의 자리를 미리 연다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../Public/WxGameplayTags.h` | State 구획에서 `State_InAir` 선언을 빼고 새 Movement 구획에 `Movement_InAir`로 옮김 | 수정 |
| `Plugins/WxCore/.../Private/WxGameplayTags.cpp` | 정의를 `"Movement.InAir"`로 옮김 | 수정 |
| `Source/WxGame/Character/WxCharacterMovementComponent.cpp` | 발행 지점의 태그 참조 교체 | 수정 |
| `Content/AbilitySystem/Ability/GA_Attack_Light.uasset` | 공중 콤보 세트의 진입 요구 태그를 새 태그로 교체 | 수정 |

### 접근 방식
- **리다이렉트 없이 사용처를 직접 고친다**: 태그 리다이렉트는 `DefaultGameplayTags.ini`를 되살리는데, 이 프로젝트는 태그를 C++ 한 쌍으로만 정의하기로 못 박았다. 사용처가 코드 한 곳·에셋 한 곳뿐이라 직접 고치는 편이 부품이 적다.
- **코드 → 재실행 → 에셋 순서**: 새 태그는 네이티브 등록이라 모듈이 다시 로드돼야 존재한다. 그 전에는 에셋에 새 태그를 넣을 수 없으므로, 코드를 고쳐 빌드하고 에디터를 다시 띄운 뒤 에셋을 고친다.
- **중간에 태그가 빈다**: 재실행 직후 그 에셋의 요구 태그는 사라진 태그라 비워진 채 열린다. 요구가 빈 세트는 조건 없이 매칭돼 지상 콤보를 가로채므로, 이 상태로 저장하지 않고 곧바로 새 태그를 넣어 저장한다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|

| `Plugins/WxCore/.../Private/WxGameplayTags.cpp` | `"Movement.InAir"`로 정의, State 묶음과 한 줄 띄워 분리 | 수정 |
| `Source/WxGame/Character/WxCharacterMovementComponent.cpp` | 이동 모드 전이 시 발행하는 태그 참조 교체 | 수정 |
| `Content/AbilitySystem/Ability/GA_Attack_Light.uasset` | 공중 콤보 세트의 진입 요구 태그를 새 태그로 교체 | 수정 |

### 구현·결정과 그 이유
- **Movement를 독립 구획으로 뒀다**: State 아래 두면 그 계층의 다른 태그들과 성격이 섞인다. 이 값은 캐릭터가 처한 상태가 아니라 이동 모드를 그대로 옮겨 적은 것이고, 발행 주체도 이동 컴포넌트 하나뿐이라 계층을 갈랐다.
- **리다이렉트를 쓰지 않았다**: 태그 리다이렉트는 폐지한 태그 ini를 되살린다. 사용처가 코드 한 곳·에셋 한 곳이라 직접 고치는 쪽이 남는 것도 없고 부품도 적다.
- **사라진 태그는 지워지지 않고 남는다**: 재실행한 에디터가 옛 태그를 등록하지 않는데도 에셋의 요구 태그는 이름 그대로 살아 있었다. 요구가 비어 지상 콤보를 가로챌까 경계했지만, 실제로는 매칭만 실패하는 무해한 상태였다. 대신 이름이 조용히 남는 만큼 사용처를 놓치면 발동만 안 되고 경고는 안 뜬다.

### 계획 대비 달라진 점
- 계획대로.

### 검증
- WxEditor(Development) 빌드 성공. 재실행한 에디터에서 태그 목록을 조회해 `Movement.InAir`만 있고 State 계층엔 없는 것을 확인했다.
- 어빌리티를 컴파일·저장한 뒤 CDO를 다시 읽어 새 태그가 남아 있는 것, 그리고 저장된 에셋 파일에 옛 태그 문자열이 남지 않은 것까지 확인했다.
- PIE 실동작은 미검증이다.
