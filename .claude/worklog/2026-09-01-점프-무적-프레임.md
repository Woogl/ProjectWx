# 점프 무적 프레임 — 도약 순간 0.1초

## 계획

### 목표
플레이어의 무적(`Effect.Invincible`)은 지금 회피·처형·스킬 컷신처럼 몽타주나 어빌리티가 도는 동안에만 열린다. 점프는 GAS를 거치지 않는 순정 `ACharacter` 이동이라 무적 구간이 전혀 없어 적 공격을 점프로 넘기는 길이 없다. 도약이 성립하는 순간 0.1초짜리 창을 열어 1단·2단 점프 모두 회피 선택지가 되게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxPlayerCharacter.h` | `OnJumped_Implementation` 오버라이드 선언, 타이머 콜백·지속시간·타이머 핸들 추가 | 수정 |
| `Source/WxGame/Character/WxPlayerCharacter.cpp` | 도약 시 무적 GE 부여, 0.1초 뒤 제거 | 수정 |

### 접근 방식
- **훅은 `OnJumped_Implementation`**: 엔진 `CheckJumpInput`이 `CanJump`·`DoJump`가 모두 통과해 실제로 도약이 성립한 프레임에만 부르고, 2단 점프도 키를 뗄 때 `bWasJumping`이 풀린 뒤 같은 경로를 다시 탄다. 점프 횟수를 보는 분기 없이 1단·2단이 한 지점에서 잡힌다. `Jump()`는 입력 플래그만 세우는 자리라 점프가 막혀도 불려서 부적합하다. 베이스가 이미 여기서 후딜 어빌리티를 끊고 있으므로 `Super`를 먼저 부르고, 에너미는 점프하지 않으니 플레이어에만 둔다.
- **무적은 기존 GE 재사용**: `UWxEffect_Invincible`은 정의에 지속시간이 없고 수명은 거는 쪽이 쥔다. 노티파이 구간이 Begin에서 걸고 End에서 걷듯, 점프는 도약에서 걸고 타이머 만료에서 걷는다. 신규 GE 클래스는 만들지 않는다. 제거 수량은 노티파이와 같은 이유로 1 — 겹쳐 걸린 회피·처형 무적까지 벗기면 안 된다.
- **2단 점프의 겹침은 타이머 재설정으로**: 창이 열린 채 또 걸면 스택이 둘이 되고 만료 콜백은 하나만 걷어 나머지가 영구히 남는다. 타이머가 이미 돌고 있으면 GE는 새로 걸지 않고 타이머만 다시 세워 스택을 1개로 유지한다. 창은 마지막 도약 기준 0.1초가 된다. "이미 열린 창"은 별도 플래그 없이 타이머 활성 여부에서 파생한다.
- **권한 밖에서는 아무것도 하지 않는다**: 클라이언트에서 거는 쪽은 예측 키가 없어 어차피 no-op인데 제거만 로컬에서 돌면 복제본과 어긋난다.

### 개정 — GE 에셋으로 전환 (타이머 구현 뒤)

위 구현을 마친 직후 사용자가 `GE_JunpInvincible` 에셋과 `DT_Effect` 행(`GE_JumpInvincible`, Duration 0.1)을 만들어 쓸 수 있는지 물었다. 08-31에 깔아 둔 "GE 수치를 디자이너 테이블에서 읽기" 경로의 첫 사용처이고, 지속시간을 GE 자신이 쥐면 타이머·겹침 처리가 통째로 사라지므로 그쪽으로 옮긴다.

- **`DurationMagnitude` 를 표에서 읽게 한다**: 에셋은 `HasDuration` 이고 `Wx Effect Data` 컴포넌트가 행을 가리키지만, `DurationMagnitude` 가 ScalableFloat 0으로 박혀 있어 그대로 걸면 즉시 만료된다. 계산 방식을 `CustomCalculationClass` / `UWxMMC_EffectDuration` 으로 바꿔 행의 `Duration` 을 읽게 한다. 지속시간의 유일한 출처가 표가 된다.
- **에셋 이름 오타 정정**: `GE_JunpInvincible` → `GE_JumpInvincible`. 참조가 없는 새 에셋이라 지금이 가장 싸고, 행 이름은 이미 바르게 적혀 있다.
- **어느 GE를 걸지는 BP가 지정**: `TSubclassOf<UGameplayEffect> JumpInvincibleEffect` 를 `BP_Player` 에서 지정한다. C++에 콘텐츠 경로를 박지 않는 기존 방식이다.
- **C++은 걸기만 한다**: 타이머·핸들·콜백·지속시간 필드가 사라지고, 만료는 GAS가 한다. 2단 점프는 `StackingType = None` 이라 독립 GE가 하나 더 생기고 부여 태그가 참조 카운트로 관리돼, 손수 맞추던 창 연장이 저절로 나온다.

### 구현·결정과 그 이유
- **훅은 도약이 성립한 지점**: 엔진이 `CanJump`·`DoJump`를 모두 통과한 프레임에만 `OnJumped`를 부르므로 점프가 막힌 입력에는 창이 열리지 않고, 2단 점프도 같은 경로를 다시 타 점프 횟수를 보는 분기가 필요 없다. 에너미는 점프하지 않으니 베이스가 아니라 플레이어에 뒀다.
- **지속시간을 GE가 쥐게 하니 코드가 거의 사라졌다**: 처음엔 `UWxEffect_Invincible`(무한 지속)에 0.1초 타이머를 붙였는데, 사용자가 만든 `HasDuration` GE로 옮기자 타이머·핸들·만료 콜백·지속시간 필드가 전부 필요 없어졌다. 만료는 GAS가 한다.
- **`DurationMagnitude` 를 표에서 읽는다**: 에셋은 `Wx Effect Data` 컴포넌트로 `DT_Effect / GE_JumpInvincible` 행을 가리키고 있었지만 Duration 계산 방식이 `ScalableFloat 0` 이라 그대로 걸면 즉시 만료됐다. `CustomCalculationClass` / `UWxMMC_EffectDuration` 로 바꿔 행의 `Duration`(0.1)을 읽게 했다. 이제 지속시간의 출처는 표 하나다.
- **겹침 처리가 공짜가 됐다**: `StackingType` 이 `None` 이라 2단 점프는 독립된 활성 GE를 하나 더 만들고 부여 태그는 ASC가 참조 카운트로 관리한다. 타이머 시절 손으로 맞추던 "마지막 도약 기준 0.1초"가 저절로 나온다.
- **클래스가 갈라져 서로 안 벗긴다**: 회피·처형 구간이 걷는 대상은 `UWxEffect_Invincible` 이라 점프 창과 교차하지 않는다. 타이머 방식엔 노티파이 End 가 점프 스택을 먼저 걷어 두 창의 수명이 뒤바뀌는 경로가 남아 있었다.
- **권한 가드를 뺐다**: 그 가드가 막던 것은 "클라에서 제거만 로컬로 돌아 복제본과 어긋나는 것"인데 제거 자체가 없어졌다. 클라의 부여는 예측 키가 없어 `HasNetworkAuthorityToApplyGameplayEffect` 에서 무산된다.

### 계획 대비 달라진 점
- 타이머 방식으로 먼저 구현·빌드까지 마친 뒤, 사용자가 만든 GE 에셋을 쓰는 쪽으로 갈아엎었다(위 「개정」).
- **BP_Player 의 `JumpInvincibleEffect` 지정을 못 했다.** 켜져 있는 에디터가 DebugGame 구성이라 방금 빌드한 Development 코드의 새 프로퍼티가 리플렉션에 없다. DebugGame 재빌드는 Live Coding 이 잡고 있어 실패했고(`Unable to build while Live Coding is active`), 사용자 작업물이 든 에디터를 강제 종료하지 않았다.

### 검증
- `WxEditor(Development)` 빌드 `Result: Succeeded`, 종료 코드 0.
- MCP 재조회: `DurationMagnitude.magnitudeCalculationType == CustomCalculationClass`, `calculationClassMagnitude == /Script/WxCombat.WxMMC_EffectDuration`, GE 컴포넌트 2개(`Wx Effect Data`·TargetTags) 보존, 저장 성공. 리다이렉터 잔존 없음.

### 후속 과제
- **BP_Player 에 `JumpInvincibleEffect = GE_JumpInvincible` 지정**(남은 유일한 연결). 지정 전까지 `ApplyEffect` 가 널로 조기 반환해 기능이 꺼져 있다. 에디터를 새 빌드로 재시작하면 `Wx|Combat` 카테고리에 뜬다.
- PIE 미검증: `showdebug abilitysystem` 으로 점프 시 `Effect.Invincible` 이 0.1초 붙었다 사라지는지, 1단→2단 연속 점프에서 마지막 도약 기준까지 이어지는지 확인.
- 0.1초가 적 공격을 넘길 만한 폭인지는 플레이 감각 문제다. 좁으면 `DT_Effect` 의 `GE_JumpInvincible` 행 `Duration` 만 고치면 된다.
