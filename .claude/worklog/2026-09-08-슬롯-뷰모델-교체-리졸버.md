# 슬롯의 어빌리티 뷰모델을 Resolver 가 갈아 끼운다

## 계획

### 목표
E 슬롯이 분신 보유 여부로 소환↔명령으로 갈리게 하되, `UWxViewModel_Ability` 는 어빌리티 하나만 담당하는 재사용 부품으로 남긴다. 어느 뷰모델을 볼지는 Resolver 가 런타임에 갈아 끼운다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/MVVM/WxAbilitySlotSwitcher.{h,cpp}` | 슬롯 하나를 감시해 적절한 어빌리티 뷰모델로 갈아 끼우는 `UUserWidgetExtension` | 신규 |
| `Source/WxGame/MVVM/WxViewModelResolver_Ability.{h,cpp}` | `AbilityTags` 를 슬롯 태그로 해석해 후보를 고르고, 위젯에 스위처를 붙인다 | 수정 |

`UWxViewModel_Ability`·`UWxViewModel_AbilitySystem` 과 위젯 바인딩은 건드리지 않는다.

### 접근 방식
- **후보 선택 규칙(리졸버·스위처 공용 static)**: 슬롯 태그를 단 부여 어빌리티 중 ① `DoesAbilitySatisfyTagRequirements` 를 만족하는 첫 후보 → ② 아무도 만족하지 않으면 직전에 보던 후보 유지 → ③ 그것도 없으면 첫 후보. 판정에 쿨다운·비용·배타 그룹은 안 들어가 아이콘이 쿨다운으로 흔들리지 않는다. ②가 필요한 이유는 `WxAbility_Death` 가 `BlockAbilitiesWithTag` 에 `Ability` 를 걸어 사망 중에는 모든 후보가 불만족이 되기 때문이다.
- **표시 조건을 UI 에 적지 않는다**: 조건의 출처는 어빌리티 에셋의 발동 태그 요건 하나뿐이다. 예전에 뺐던 `DisplayCandidates` 는 되살리지 않는다.
- **교체 주체는 위젯 확장**: `CreateInstance` 는 const 이고 1회만 불려 재평가 훅이 없다. `UUserWidgetExtension` 은 위젯 상태에 맞춰 수명이 관리되고 Outer 로 위젯을 되찾을 수 있어 감시자의 자리로 맞다.
- **구독 둘, 판정은 프레임당 한 번**: ASC 의 제네릭 태그 이벤트(상태)와 `AbilitySpecDirtiedCallbacks`(부여). 기존 뷰모델들과 같은 티커 플러시 패턴.
- **소스 이름은 첫 교체 때 확정**: 리졸버가 뷰모델을 돌려준 직후에는 아직 소스에 꽂히기 전이라 그 시점엔 찾을 수 없다. `View->GetSources()` 에서 자기 뷰모델을 들고 있는 소스를 찾아 이름을 캐시한다.
- **후보가 없으면 기존 동작 유지**: 슬롯 태그에 맞는 어빌리티가 하나도 부여돼 있지 않으면 예전처럼 슬롯 태그로 빈 뷰모델을 만들고 스위처는 붙이지 않는다.

### 엔진 API 확인
- `UMVVMView::SetViewModel` 은 바인딩을 재실행하지만 `CanBeSet()` 을 검사하고, 이 플래그는 컴파일러가 `bCreateSetterFunction` 에서만 켠다 → 위젯 소스에 "Create Setter Function" 체크가 선행돼야 한다.
- `FMVVMViewClass_Source::GetName()`, `UMVVMViewClass::GetSource/GetSources`, `UUserWidget::AddExtension/GetExtension` 전부 public 이다.

## 완료

| 파일 | 수정한 내용 | 구분 |

### 구현·결정과 그 이유
- **후보 선택 규칙을 static 으로 두고 리졸버와 나눠 쓴다**: 생성 시점(리졸버)과 상태 변화 시점(스위처)이 같은 답을 내야 하므로 규칙의 출처를 하나로 두고 둘이 부른다.
- **진입점 이름은 `WatchSlot`**: 처음엔 `Initialize` 로 지었는데 `UUserWidgetExtension::Initialize()` 를 가려 C4263/C4264 경고가 났다. 베이스의 수명 훅과 이름이 겹치지 않게 바꿨다.
- **정리를 `Destruct` 와 `BeginDestroy` 양쪽에서**: Construct 없이 사라지는 위젯에는 Destruct 가 오지 않아 티커에 죽은 델리게이트가 남을 수 있다.
- **뷰모델 키는 후보의 전체 에셋 태그**: 슬롯 태그로만 조회하면 두 후보가 같은 뷰모델을 나눠 써 "뷰모델 하나가 어빌리티 하나" 가 깨진다. 그래서 후보를 가르는 태그까지 담아 조회한다.
- **후보가 없으면 예전 동작 그대로**: 슬롯 태그에 맞는 어빌리티가 하나도 부여돼 있지 않으면 슬롯 태그로 빈 뷰모델을 만들고 스위처를 붙이지 않는다. 그 슬롯이 없는 캐릭터의 표시가 지금과 같다.
- **뷰모델은 손대지 않았다**: `UWxViewModel_Ability` 는 여전히 어빌리티 하나만 알고, 위젯 바인딩도 그대로다.

### 계획 대비 달라진 점
- 스위처 진입점 이름을 `Initialize` → `WatchSlot` 으로 바꿨다(위 사유).
