# 보스 전용 뷰모델 제거 — 보스가 공용 뷰모델로 발행

## 계획

### 목표
"지금 이 월드의 보스" 를 스스로 찾아 무는 `UWxViewModel_BossCharacter` 를 없앤다. 보스 바 위젯이 HUD 안에 상시로 들어 있어 보스보다 먼저 생기는 탓에, 이 뷰모델 하나가 정적 델리게이트 구독·액터 순회·소멸 통지·교전 태그 구독을 전부 떠안았고 그 뒷바라지로 적 캐릭터에까지 보스 전용 델리게이트가 두 개 생겼다. 방향을 뒤집어 보스가 공용 `UWxViewModel_Character` 에 자기 데이터를 실어 발행하고, 위젯은 리졸버로 그 뷰모델을 받기만 하게 한다.

### 접근 방식
- **발행자와 소비자를 뷰모델 하나로 잇는다**: 데이터는 오직 뷰모델을 통해 건너간다. 발행자(보스)와 소비자(리졸버)는 GameState 를 Outer 로 하는 같은 인스턴스를 `GetOrCreate` 로 집는다 — `UWxViewModel_AbilitySystem::GetOrCreate` 가 ASC 로 하는 것과 같은 규약이고, 이 Outer 규약이 둘 사이의 유일한 연결 고리다.
- **발행 시점을 화면에 뜨고 지는 시점과 일치시킨다**: 교전 시작에 발행, 교전 종료·EndPlay 에 회수한다. 그래서 위젯 가시성이 "슬롯이 차 있는가" 한 가지로 정해지고, 위젯이 교전 태그를 따로 관찰할 필요가 없다.
- **해제도 통지한다**: 지금 `Deinitialize` 는 통지를 아예 하지 않아 소스가 빠져도 위젯이 마지막 값을 붙든다. 파괴 중(`RF_BeginDestroyed`)이 아닐 때만 통지하도록 갈라, 슬롯이 비는 것을 위젯이 알게 한다.
- **뷰모델을 발행자가 붙든다**: Outer 는 인스턴스를 살려 두지 않으므로, 위젯이 아직 물지 않은 사이 수거되면 발행이 유실된다. 보스가 `UPROPERTY` 로 쥐고 있다가 회수할 때 놓는다.
- **범위 밖**: 새 컴포넌트, HUD 재구성, 네임플레이트 컴포넌트의 입력 계약 변경, 플레이어 리졸버 정리.

### 구현·결정과 그 이유
- **발행을 리졸버가 맡았다**: 계획은 적 캐릭터가 뷰모델을 만들어 넘기게 했는데, 그러면 모델이 뷰모델을 알게 된다. 모델은 "보스가 교전에 들어갔다/빠졌다" 는 게임 사실만 알리고, 그것을 표시 데이터로 옮겨 담는 일은 뷰모델 층인 리졸버가 한다. 계층이 한 방향으로 정리되고, 모델에서 UI 헤더가 전부 빠진다.
- **리졸버가 상태를 들지 않는다**: 리졸버 인스턴스는 위젯 클래스가 공유하고 호출도 전부 const 라 관찰 상태를 둘 자리가 없다. 그래서 "지금 보스" 를 월드의 GameState 를 Outer 로 하는 뷰모델 한 자리가 쥐고, 리졸버는 통지가 올 때마다 그 자리를 다시 찾아 갱신만 한다. 통지에 실려 온 보스가 자기 월드를 말해 주므로 PIE 의 서버·클라 월드가 저절로 갈린다.
- **신호를 교전 상태 하나로 합쳤다**: 준비·소멸 두 델리게이트는 결국 "지금 이 보스를 띄울까 말까" 를 나눠 말하고 있었다. 교전 여부를 이미 한곳에서 계산하므로 그 결과를 그대로 실어 보내면 소멸도 비교전으로 표현된다. 구독자는 델리게이트 하나만 보고, 보스별 태그 구독도 필요 없어졌다.
- **표시 여부를 자리의 유무로 바꿨다**: 예전에는 뷰모델이 교전 태그를 따로 관찰해 bool 필드로 중계했다. 발행 시점을 화면에 뜨고 지는 시점과 같게 잡으면 "자리가 차 있는가" 가 곧 표시 조건이라, 중계 필드와 그 관찰이 통째로 없어진다.
- **사망을 교전 해제로 포함시켰다**: 죽어도 겨누던 대상은 남아 있어 교전 상태가 유지됐고, 시체 수명이 걸려 있지 않으면 바가 계속 떠 있었다(이번 변경 이전부터 있던 구멍이다). 교전 계산에 생존을 넣고 사망 통지에서 갱신한다 — 통지는 전 머신에 오므로 권위 검사 앞에서 부른다. 네임플레이트는 이미 사망 태그를 무시 조건으로 걸러 두었고 피니셔 자격은 생존을 먼저 보므로, 달라지는 표시는 보스 바뿐이다.
- **해제도 통지하게 했다**: `Deinitialize` 가 통지를 아예 하지 않아 자리를 비워도 위젯이 마지막 값을 붙들고 있었다. 파괴 경로(`RF_BeginDestroyed`)만 조용히 두고 그 밖에는 통지한다 — 이 플래그는 `BeginDestroy` 호출 전에 켜지므로 두 경우가 확실히 갈린다.

### 계획 대비 달라진 점
- **발행 주체가 적 캐릭터에서 리졸버로 옮겨졌다**: 모델이 뷰모델을 알면 안 된다는 지적을 받아 방향을 바꿨다. 모델에는 교전 통지 델리게이트만 남았고, `UWxViewModel_Character` 를 캐릭터가 만들어 쥐던 부분(멤버·발행/회수 함수)은 전부 사라졌다.

### 후속 과제
- 에디터 작업이 남았다(전까지 보스 바가 뜨지 않는다): `WBP_Nameplate_Boss` 의 뷰모델 항목을 `UWxViewModel_Character` 로 지정하고, 사라진 `bBossBattleActive` 가시성 바인딩을 `AbilitySystem` + `To Visibility (Object)` 로 다시 건다. 리졸버 지정은 클래스 이름이 같아 그대로 유지된다.
- 위 저장이 끝나면 `Config/DefaultEngine.ini` 의 `[CoreRedirects]` 항목을 제거한다.
- PIE 검증 미수행(빌드까지 확인). 배치 보스(시드 경로)와 교전 시작·종료·언로드 경로를 함께 볼 것.
