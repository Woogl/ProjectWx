# 백스탭(뒤잡) 스텔스 처형

## 계획

### 목표
플레이어를 인지하지 못한 적의 후방에서 상호작용으로 뒤잡(처형)을 발동한다. 모션워핑으로 공격자를 적 뒤에 정렬하고, 공격/피격 짝 몽타주를 동시 재생한 뒤 적을 즉사시킨다.

방금 완성된 그로기 피니시(앞잡)와 동일 메커니즘이므로, 새 메모리(신규 GAS 클래스 억제)에 따라 **새 어빌리티 클래스를 만들지 않고 기존 피니셔를 일반화**한다(사용자 승인).

### 접근 방식
- **피니셔 일반화 + EventTag 분기**(HitReact 패턴): 한 피니셔 어빌리티가 두 트리거(`Event.GroggyFinish` 앞잡 / `Event.Backstab` 뒤잡)를 받아 공격 몽타주·짝 피격 태그·대미지를 분기. 워프 정렬(`RegisterWarpTarget`)은 "대상 방향 접근+바라봄"으로 앞·뒤 공유(뒤잡은 어포던스가 후방 보장).
- **상호작용 재사용**: 적에 `BackstabInteractionComponent`를 달아 기존 스캔/프롬프트로 노출. 타이머 게이트가 생존+미인지(`!State.InCombat`)+로컬 플레이어 후방일 때만 enable. OnInteracted(권위)→플레이어에 `Event.Backstab`.
- **짝 몽타주 + 처형 순서**: 발동 즉시 피해자에 `Event.HitReact.Backstab` 송출(짝 피격 동시 시작) → 공격 몽타주 후반 노티파이가 `Event.Backstab.Damage` → `ApplyRawDamage` 치명타 → `State.Dead`. (피격은 이미 재생 중이라 State.Dead 차단 무관.)

### 구현·결정과 그 이유
- **신규 클래스 대신 기존 피니셔 일반화**: 뒤잡은 방금 완성된 앞잡과 동일 메커니즘이라, 메모리 `minimize-new-gas-classes`에 따라 `UWxAbility_Finisher`(앞잡+뒤잡) 한 클래스로 통합. HitReact 슬롯+트리거 확장 패턴을 그대로 따른다.
- **명칭 통일(Finisher)**: 이전 작업의 `Finish`/`GroggyFinish` 잔재를 `Finisher`로 일관화(앞잡=Finisher, 뒤잡=Backstab). 참조 에셋이 없어 순수 C++ 리네임으로 안전.
- **적 인터랙션 컴포넌트 1개로 통합**: 앞잡(그로기=전투 중)과 뒤잡(미인지=비전투)은 상호 배타라 동시 성립 불가. 단일 볼륨에 조건 게이트와 송출 이벤트만 분기해 중복 컴포넌트를 제거.
- **처형 순서**: 발동 즉시 짝 피격 이벤트를 보내 몽타주를 동시 시작하고, 치명 대미지는 공격 몽타주 후반 노티파이(WaitGameplayEvent)에서 적용. State.Dead가 이미 재생 중인 피격을 막지 않는다.

### 계획 대비 달라진 점
- 그로기 어포던스 게이트가 태그 이벤트 → 주기 평가(0.15s)로 바뀜(단일 컴포넌트 통합에 따른 부수 변경, ≤0.15s 노출 지연).
- 클래스 리다이렉트를 `DefaultEngine.ini`에 추가했으나 참조 에셋이 없어 사용자가 제거(불필요).

### 후속 과제
- **에디터 에셋**: `AM_Backstab_Attack`(MotionWarping warp target **"Finisher"** + 후반 `WxAnimNotify_SendGameplayEvent` EventTag **"Event.Backstab.Damage"**), `AM_Backstab_Victim`(HitReact BP의 `BackstabMontage`), 피니셔 어빌리티 BP에 `BackstabMontage`/`BackstabDamage` 지정, 처형 프롬프트 텍스트.
- 앞잡 에셋(다른 세션 진행분)도 동일하게 warp target **"Finisher"**, `Event.Finisher.Damage` 명칭으로 맞출 것.
- MP(데디 원격 클라)의 후방 판정/프롬프트는 standalone·listen-host 기준(후속).
