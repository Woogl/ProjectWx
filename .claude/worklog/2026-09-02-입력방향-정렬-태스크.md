# 입력 방향 타겟팅 필터를 정렬 태스크로 전환

## 계획

### 목표
입력 방향 콘 밖 후보를 잘라내던 타겟팅 필터를, 컷오프 없이 입력 방향과 사이각이 작은 대상을 앞으로 보내는 정렬 태스크로 바꾼다. 스냅 대상은 결과 배열의 첫 원소라 정렬 순서가 곧 대상 선택이다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/Public/Targeting/WxTargetingSorterTask_InputDirection.h` | 필터 헤더를 개명해 이동, 베이스를 `UTargetingSortTask_Base`로 교체하고 콘 관련 프로퍼티 제거 | 수정(개명) |
| `WxCombat/Private/Targeting/WxTargetingSorterTask_InputDirection.cpp` | `ShouldFilterTarget` 대신 `GetScoreForTarget`으로 사이각 점수 반환 | 수정(개명) |
| `Config/DefaultEngine.ini` | 클래스 개명용 `[CoreRedirects]` 임시 추가 후 재저장 뒤 제거 | 수정 |
| `Content/AbilitySystem/Targeting/TP_Attack_{250,1000,10000}` | 리다이렉트로 살아난 태스크를 새 클래스명으로 재저장 | 수정 |

### 접근 방식
- **점수 = 사이각(도)**: 입력 방향(CMC Acceleration을 수평 평탄화)과 타겟 방향의 사이각을 0~180도로 돌려준다. 베이스가 최고 점수로 정규화한 뒤 오름차순 정렬하므로 사이각이 작을수록 앞에 온다.
- **중립·퇴화 입력은 0**: 입력이 없거나 수평 방향을 못 구하면 0을 돌려 순서에 관여하지 않는다. 컷오프가 없으니 "콘 안 후보가 없으면 전부 유지" 같은 예외 처리도 사라진다.
- **개명은 CoreRedirect로**: 세 프리셋이 인스턴스를 물고 있어 리다이렉트 없이는 태스크가 날아간다. 임시 리다이렉트 → 재저장 → 리다이렉트 제거 순서로 이름을 에셋에 굽는다.

## 완료

| 파일 | 수정한 내용 | 구분 |

| `Config/DefaultEngine.ini` | 클래스 개명용 `[CoreRedirects]` 임시 추가 후 제거 | 수정 없음(원복) |
| `Content/AbilitySystem/Targeting/TP_Attack_{250,1000,10000}` | 리다이렉트로 살아난 태스크를 새 클래스명으로 재저장 | 수정 |

### 구현·결정과 그 이유
- **점수를 사이각(도) 그대로**: 베이스가 최고 점수로 나눠 정규화하므로 스케일은 자유지만, 각도는 값 자체가 곧 의미라 디버그 문자열에서도 읽힌다. 음수가 나오면 정규화가 깨지는데 각도는 0~180이라 안전하다.
- **중립·퇴화를 같은 0으로**: 컷오프가 없어져 "판정 불가"를 따로 다룰 이유가 없다. 전부 0이면 최고 점수도 0이라 정규화가 0을 내고 순서에 손대지 않는다.
- **개명은 리다이렉트로**: 세 프리셋이 인스턴스를 물고 있어 리다이렉트 없이는 태스크가 조용히 사라진다.

### 계획 대비 달라진 점
- 계획대로. 다만 에디터가 떠 있는 동안은 재저장이 `MoveFile Error 32`로 막혀(에디터가 `.uasset` 핸들 보유) 한 차례 미뤘다가, 에디터 종료 후 마무리했다.

### 후속 과제
- 프리셋의 서브오브젝트 이름이 `WxTargetingFilterTask_InputDirection_0`으로 남아 있다. 클래스 개명이 인스턴스 이름까지 바꾸지는 않아서인데, 디테일 패널에는 클래스 표시명이 뜨므로 실사용에 지장은 없다(같은 프리셋의 `WxTargetingFilterTask_TeamAttitude_0` = `WxTargetingFilterTask_Team`도 같은 상태다).
- 프리셋에 `SortByDistance`가 남아 있어 거리·각도 점수가 반반으로 합산된다(정규화가 태스크 단위라 가중 조절이 불가능하다). 각도 우선이 필요해지면 거리 정렬을 빼고 두 축을 한 점수 식으로 합쳐야 하는데, 실사용에서 문제가 보일 때 다루기로 하고 보류했다.
