# Wait Spawners Killed 소프트 포인터 입력 지원

## 계획

### 목표
퀘스트 처치 대상 스포너를 액터 태그 외에 소프트 포인터로도 직접 지정할 수 있게 한다. 트리거 쪽은 기존 소프트 배열 태스크(Trigger Spawners)가 있으므로, 이로써 태그 없이 소프트 쌍만으로도 조립이 가능해진다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/.../Spawnable/WxSpawnerStateTreeNodes.h/.cpp` | WaitSpawnersKilled InstanceData에 `Spawners`(소프트 배열) 추가, 판정 로직·설명 갱신 | 수정 |
| `/Game/Quest/ST_Quest` | Step2를 소프트 방식 쌍(기존 Trigger Spawners + 개선된 Wait)으로 교체, 레벨 스포너 2기 지정 | 수정(MCP) |

### 접근 방식
- **병행 입력(합집합)**: 소프트 지정분은 전원 로드+처치여야 통과(미로드=대기, 강제 로드 없음), 태그분은 기존 로직 유지. 둘 다 미지정이면 잘못된 조립로 보고 경고 후 대기.
- **샘플 이원화**: ST_Quest는 소프트 방식, ST_Quest2는 태그 방식을 유지해 두 지정 방식을 각각 시연한다.
- **PIE 리매핑 전제 실검증**: 에셋에 저장된 레벨 액터 소프트 경로가 PIE에서 풀리는지, 캠프 도달 시 스폰(Trigger의 소프트 해석)으로 확인한다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/.../Spawnable/WxSpawnerStateTreeNodes.h/.cpp` | WaitSpawnersKilled InstanceData에 `Spawners`(소프트 배열, **바인딩 전용**) 추가, 판정 로직(직접 지정분 전원 로드+처치 필요, 태그와 합집합)·미지정 경고·GetDescription 갱신 | 수정 |
| `/Game/Quest/ST_Quest` | Step2 소프트 리터럴 시도 후 태그 방식으로 원복(컴파일 성공 확인) | 원복 |

### 구현·결정과 그 이유
- **소프트 필드는 바인딩 전용으로 확정**: 소프트 리터럴을 에셋에 적어 컴파일하자 ST 컴파일러가 거부했다 — `ValidateNoLevelActorReferences`(StateTreeCompiler.cpp)가 노드·인스턴스 데이터에서 레벨 액터 참조를 스캔해 에러를 낸다(소프트 참조도 에디터에 로드돼 있으면 잡힘). 기믹 ST의 소프트 배열이 통과했던 이유는 값이 바인딩(런타임 주입)이라 에셋에 저장되지 않아서다. 엔진 검증 우회는 하지 않는다.
- **판정 규약**: 직접 지정분은 전원이 로드+처치여야 통과(미로드=대기, 강제 로드 없음), 태그분은 기존 로직, 병행 시 합집합. 둘 다 비면 진입 시 경고 후 대기(침묵 실패 방지).
- 결과적으로 소프트 입력의 실사용처는 **소유 액터 프로퍼티 바인딩이 가능한 기믹 ST**다(형제 TriggerSpawners와 동일한 자리). 레벨 밖 호스트(퀘스트)는 태그가 엔진 제약상 유일한 지정 수단이다.

### 계획 대비 달라진 점
- 계획의 "ST_Quest를 소프트 방식으로 교체"는 컴파일러 금지로 철회하고 태그 방식으로 원복했다(컴파일·저장·PIE 스폰 재확인). PIE 리매핑 전제는 검증 기회 자체가 없었다 — 컴파일 단계에서 차단.

### 후속 과제
- 퀘스트에서 "특정 스포너 집어서 지정"이 꼭 필요해지면: 퀘스트 전용 태그 세분화(현행 권장) 또는 레벨 배치 앵커 액터+바인딩 구조 재검토.
