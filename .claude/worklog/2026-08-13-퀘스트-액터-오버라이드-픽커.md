# 퀘스트 액터 지정: 에셋 오버라이드 복귀 + 전용 액터 픽커

## 계획

### 목표
퀘스트 대상 액터를 ST_Quest_Main1 의 링크 상태 오버라이드에서 직접 지정하는 저작 방식으로 복귀하되, 표준 픽커 수준의 편의를 제공한다. 저장은 UOL(컴파일러 검증 면제·PIE/WP 해석 내장), 편집은 게임 전용 한 줄 액터 픽커 커스터마이제이션으로 분리한다. 오늘 새벽 완료한 소프트 참조+수주 지점 주입 설계는 액터의 에셋 저장이 원천 불가라 사용자가 기각했다.

### 접근 방식
- **저장/픽커 분리**: 소프트 참조는 ST 컴파일러가 값 스캔으로 거부(런처 엔진이라 수정 불가)하므로 에셋 저장은 UOL 이 유일 실증 경로. 편의 문제는 픽커 층에서 푼다 — 엔진 부품(MakeActorPickerWithMenu·MakeInteractiveActorPicker)으로 현재 라벨 콤보→씬 아웃라이너 검색 메뉴+스포이드 한 줄 위젯.
- **래퍼 없이 조건부 등록**: 커스터마이제이션을 FUniversalObjectLocator 타입에 IPropertyTypeIdentifier(AllowedLocators="Actor" 메타 매칭, 원소 행은 부모 배열 메타 확인)로 등록 — HEAD 필드 전부가 이미 이 메타를 가져 코드 복원이 순수 git restore 가 된다. 엔진 전역 UOL 편집기는 메타 없는 곳에서 유지.
- **오버라이드 행 적용 근거**: 파라미터 백은 desc 메타를 생성 FProperty 에 전파(PropertyBag.cpp, 엔진 소스 확인) — 스텝 파라미터를 메타와 함께 만들면 링크 상태 오버라이드 행에도 픽커가 뜬다.
- **수용한 트레이드오프**: 퀘스트 에셋의 레벨 결속(레벨 간 재사용 포기). 수주 컴포넌트·BP 정리 등 새벽 작업의 나머지는 유지(수주 지점은 에셋 픽커+1회성 오버랩으로 역할 축소).

### 구현·결정과 그 이유
- **픽커는 엔진 부품 조립**: 값 위젯 = 현재 액터 라벨 콤보(메뉴는 MakeActorPickerWithMenu — 씬 아웃라이너 검색·Use Selected·Copy/Paste·Clear) + 스포이드(MakeInteractiveActorPicker). 기입은 FUniversalObjectLocator(Actor) 생성 → 트랜잭션+NotifyPre/PostChange 로 언두·더티 처리.
- **식별자 메타 매칭**: 배열 원소 프로퍼티에는 메타가 없어 소유 배열 프로퍼티까지 올라가 확인한다. 파라미터 백 desc 메타는 백 생성 시 FProperty 로 전파되므로(엔진 소스 확인) 링크 상태 오버라이드 행에도 같은 식별이 걸린다.
- **툴셋 메타 기입은 서술자 직접 구성으로**: AddProperty 계열엔 메타 인자가 없어 FPropertyBagPropertyDesc 를 만들어 SetMetaData 후 AddProperties 로 통일.
- **파라미터 이름 유지 재정의**: ST 바인딩은 백 GUID+프로퍼티 이름으로 해석하므로, 같은 이름으로 지우고 다시 만들면 스텝 내부 바인딩이 그대로 살아남았다(재결선 불요).
- **태스크 타입 교체는 배열 비우기→재기입 2단계**: set_properties 는 기존 원소의 _structType 을 바꾸지 못한다(신규 원소만). iD 를 유지해 파라미터→태스크 바인딩을 보존했다.
