# 대화 행 링크 NextDialogue → NextRow 리네임

## 계획

### 목표

`FWxDialogueTableRow::NextDialogue` 를 `NextRow` 로 바꿔 자막 행(`FWxSubtitleTableRow::NextRow`)과 어휘를 통일한다. 두 테이블이 같은 연결 구조를 쓰는데 필드 이름만 다르면 디자이너가 매번 다른 이름을 외워야 한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/.../WxDialogueTableRow.h` | 필드 개명 및 그것을 설명하는 주석 | 수정 |
| `Plugins/WxDialogue/.../WxDialogueSessionComponent.h/.cpp` | 다음 행을 읽는 자리와 주석 | 수정 |
| `Config/DefaultEngine.ini` | `[CoreRedirects]` PropertyRedirects 1건(임시) | 수정 |
| `Content/DesignerTables/DT_Dialogue.uasset` | 새 필드 이름으로 재저장 | 수정 |
| `Plugins/WxDialogue/README.md`, `Docs/Programmer/module_review_WxDialogue.md` | 필드를 지칭하는 서술 | 수정 |

### 접근 방식

- **리다이렉트 필수**: `DT_Dialogue` 의 7개 행이 이 이름으로 링크를 직렬화해 두었다. 리다이렉트 없이 개명하면 값이 조용히 None 이 되어 대화가 첫 줄에서 끊긴다.
- **리다이렉트는 일회용 다리**: GiveRewards 리네임과 같은 절차다 — 리다이렉트를 켠 채 테이블을 헤드리스로 재저장해 새 이름을 구워 넣고, 항목은 다시 걷어낸다.
- **덤프로 검증**: 컴파일은 에셋 데이터가 살았는지 답하지 않는다. 재저장 후 재덤프해 링크 값이 그대로인지 확인한다.

### 구현·결정과 그 이유
- **재저장으로 이름을 구워 넣음**: 리다이렉트를 켠 채 테이블을 헤드리스로 열어 다시 저장하고 항목을 걷어냈다. 에셋에 새 이름이 직렬화된 이상 리다이렉트는 죽은 설정이고, 남겨 두면 옛 이름이 계속 유효한 것처럼 보인다.
- **리다이렉트 없이 재덤프해 검증**: 링크 값 보존은 컴파일이 답해 주지 않는다. 항목을 지운 뒤 다시 덤프해 7개 행이 `NextRow` 로 읽히고 연결(BP_Npc_0→…→5→None)이 그대로임을 확인했다.
- **리뷰 문서는 손대지 않음**: `Docs/Programmer/module_review_WxDialogue.md` 는 커밋·리뷰일이 박힌 시점 스냅샷이라 사후에 식별자만 고치면 그 시점의 기록이 아니게 된다. `/module-review` 재실행이 갱신할 몫이다.
