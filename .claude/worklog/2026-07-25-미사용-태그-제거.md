# 미사용 태그 제거

## 계획

### 목표
`WxGameplayTags` 97개를 코드와 에셋 양쪽에서 전수 대조한 결과 실질적으로 죽어 있는 두 태그를 지운다. `Ability.Pattern.10`은 어디에도 참조가 없고(보스 패턴 BP는 1~9까지만 존재), `ANS.WeaponCollision`은 무기가 공격 구간에 붙였다 떼기만 할 뿐 읽는 곳이 코드에도 에셋에도 없다. 읽는 쪽이 없으니 동작은 변하지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCore/.../Public/WxGameplayTags.h` | `ANS_WeaponCollision`·`Ability_Pattern_10` 선언 삭제 | 수정 |
| `WxCore/.../Private/WxGameplayTags.cpp` | 같은 두 태그의 정의 삭제 | 수정 |
| `WxCombat/.../Private/Weapon/WxWeaponBase.cpp` | 태그를 붙이고 떼는 세 블록(BeginAttack·EndAttack·DetachFromCharacter)과 이 파일의 유일한 태그 사용처였던 `WxGameplayTags.h` include 삭제 | 수정 |
| `WxCombat/.../Public/AnimNotify/WxAnimNotifyState_WeaponAttack.h` | 실제 동작과 어긋난 클래스 주석(태그 부여로 콜리전을 켠다는 설명)을 실제 흐름대로 정정 | 수정 |
| `Plugins/WxCore/README.md`, `Docs/Programmer/Module_Boundary_Audit.md` | 태그 목록에서 `WeaponCollision` 제거, 패턴 범위를 1~9로 정정 | 수정 |

### 접근 방식
- **선언과 발행을 함께 지운다**: 태그를 읽는 쪽이 없으므로 선언만 남기면 "쓰이는 것처럼 보이는 죽은 배선"이 그대로 남는다. 무기의 세 블록은 ASC를 얻는 것 외에 하는 일이 없어 스코프째 사라진다.
- **리다이렉트 불필요**: 두 태그 모두 에셋 참조가 0건이라 저장된 데이터가 잃을 것이 없다.
- **다시 필요해지면 그때 붙인다**: 무기 콜리전 활성 여부를 태그로 알아야 할 일이 생기면 그 시점에 추가한다. 호출자 없는 발행을 미리 남겨두지 않는다.
- **어긋난 주석까지 정정**: 히트 콜리전 on/off는 무기가 직접 하는데도 주석은 태그가 켠다고 설명하고 있어, 태그를 지우면 설명만 남아 오해를 키운다.
