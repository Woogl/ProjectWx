# 이펙트 뷰모델의 죽은 코드 정리

## 계획

### 목표
이펙트 뷰모델 주변에 일할 수 없는 함수와 소비자 없는 프로퍼티가 남았다. 리졸버 공용화로 해제 경로가 정리되면서 생긴 잔재다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_AbilitySystem.h`·`.cpp` | 이펙트 목록 정리 함수 제거, 목록 구축 함수 이름을 실제 역할에 맞춤 | 수정 |
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_Effect.h`·`.cpp` | 이펙트 태그 프로퍼티와 그것을 채우던 CDO 조회 제거 | 수정 |

### 접근 방식
- **정리 함수는 구조상 일할 수 없다**: 초기화가 맨 앞에서 해제를 부르고 거기서 목록을 이미 비우므로, 정리 함수는 어떤 경로로도 빈 배열만 만난다. 게다가 일하게 되는 순간 위젯이 붙들고 있는 이펙트 뷰모델을 끊는 동작이 되는데, 이는 공유화에서 걷어낸 바로 그 문제다.
- **이펙트 태그는 값 정의가 임의다**: 에셋 태그의 첫 번째를 담는데 GE 가 태그를 둘 이상 가지면 무엇이 잡힐지 보장이 없다. 소비자가 없다는 점보다 이쪽이 크다 — 남겨 두면 잘못 설계된 필드를 보존하게 된다.
- **표시 프로퍼티는 남긴다**: 이름·남은 시간·전체 지속은 바인딩하는 위젯이 없지만 값 정의가 명확하고, 특히 이름은 UI 데이터 컴포넌트의 표시 이름을 받는 유일한 소비자다. 지우면 디자이너가 GE 에 채운 텍스트가 갈 곳을 잃는다.

| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_Effect.h`·`.cpp` | 이펙트 태그 프로퍼티와 그것을 채우던 CDO 조회 제거, 쓰이지 않게 된 태그 include 정리 | 수정 |

### 구현·결정과 그 이유
- **정리 함수는 구조상 일할 수 없었다**: 초기화가 맨 앞에서 해제를 부르고 거기서 목록을 이미 비우므로, 정리 함수는 어떤 경로로도 빈 배열만 만났다. 현재 호출 경로가 하나뿐이라 죽은 것이 아니라 구조적으로 죽어 있었다. 일하게 되는 순간 위젯이 붙들고 있는 이펙트 뷰모델을 끊는 동작이 되므로, 공유화에서 걷어낸 문제를 되살리는 셈이기도 했다.
- **개명**: 한 번 짓고 끝나는 함수라 Refresh~ 라는 이름이 실제와 어긋났다. 증분 갱신은 추가/제거 핸들러가 맡는다.
- **이펙트 태그는 값 정의가 임의였다**: 에셋 태그의 첫 번째를 담는데 GE 가 태그를 둘 이상 가지면 무엇이 잡힐지 보장이 없다. 소비자가 없다는 점보다 이쪽이 커서, 남겨 두면 잘못 설계된 필드를 보존하게 된다. 필요해지면 그때 제대로 만든다.
- **표시 프로퍼티는 남겼다**: 이름·남은 시간·전체 지속은 바인딩하는 위젯이 없지만 값 정의가 명확하다. 특히 이름은 UI 데이터 컴포넌트의 표시 이름을 받는 유일한 소비자라, 지우면 디자이너가 GE 에 채운 텍스트가 갈 곳을 잃고 그 컴포넌트도 절반이 죽는다.

### 후속 과제
- 빌드까지만 확인했다. PIE 에서 네임플레이트의 이펙트 아이콘·남은 시간 링·스택 수가 그대로인지는 미검증.
- 이펙트 뷰모델은 여전히 UIData 가 붙은 활성 GE 전부에 대해 만들어진다. 소비자인 네임플레이트가 뷰모델이 생기는 자리마다 있어 낭비가 아니라고 판단해 지연 생성으로 바꾸지 않았다.
