# 대화 카메라를 세션 컴포넌트로 이관

## 계획

### 목표
직전 작업([2026-07-29-대화-카메라-런타임-계산](2026-07-29-대화-카메라-런타임-계산.md))에서 `AWxPlayerController` 로 들어간 대화 카메라 계산·스폰·회수 코드를 통째로 `UWxDialogueSessionComponent` 안으로 옮긴다. 대화 카메라는 대화 시스템의 연출이지 컨트롤러의 책임이 아니며, PC 는 대화 카메라를 아예 모르는 상태로 되돌린다. 받을 그릇은 이미 있다 — 세션 컴포넌트는 PC 의 기본 서브오브젝트로 붙어 있고 대상·시작·종료를 모두 자기 안에서 알며, 이미 소유 클라에서 폰 ASC 에 `State.Dialogue` 를 발행하는 등 "대화가 열릴 때 월드에 하는 일"을 담당한다.

### 수정 범위

| `Plugins/WxDialogue/.../Private/WxDialogueSessionComponent.cpp` | 카메라 로직 구현 + 시작·종료 지점에 연결 | 수정 |

`.Build.cs`·`.uplugin`·에셋 변경 없음 — `ACameraActor`·`APlayerController` 모두 `Engine` 이고 `WxDialogue` 가 이미 의존한다.

### 접근 방식

- **연결은 세션이 이미 아는 두 곳에**: `ClientStartDialogue_Implementation`(대상 기억·ASC 태그 발행 직후)에서 `ActivateDialogueCamera(Target)`, `EndDialogue`(태그 회수 직후)에서 `RestoreGameplayCamera()`. 자기 델리게이트를 자기가 구독하지 않고 직접 호출한다 — 델리게이트는 외부 구독자(PC 위젯·뷰모델)를 위한 것이고, 세션 자신의 일은 순서가 보이는 자리에서 직접 하는 편이 읽힌다.

- **로컬 게이팅**: `ClientStartDialogue` 는 Client RPC 라 소유 클라(리슨호스트 포함)에서만 돌고 `EndDialogue` 는 로컬 UI 가 부르는 경로에서만 온다. 그래도 오너를 `APlayerController` 로 캐스팅하며 `IsLocalController()` 를 함께 확인해 데디 서버 경로에서 새지 않게 한다.

- **로직은 그대로 이관**: 알고리즘·기본값·주석 변경 없음. `ComputeDialogueCameraView()`(눈높이 보정 → `PivotAlpha` 지점 → `Side = Up × Axis` → 180 도 법칙 부호 → `ECC_Camera` 스윕 가림 보정 → 대상 눈높이 응시), 임시 `ACameraActor` 스폰(FOV·`SetConstraintAspectRatio(false)`), `SetLifeSpan(BlendTime + 1)` 회수. 플레이어 위치는 오너 컨트롤러의 폰에서, 현재 카메라 위치는 `PlayerCameraManager` 에서 얻는다.

- **파라미터 위치**: 5 개(`BlendTime` 0.75 / `EyeHeight` 70 / `PivotAlpha` 0.5 / `LateralOffset` 120 / `Fov` 60)를 `EditDefaultsOnly` 로 세션이 소유한다. 세션이 PC 의 기본 서브오브젝트라 `BP_PlayerController` 의 컴포넌트 디테일 패널에서 그대로 조정된다.

```
ClientStartDialogue_Implementation   ← 소유 클라에서만 도는 지점
  CurrentTarget = Target
  폰 ASC 에 State.Dialogue 발행
  ActivateDialogueCamera(Target)     ← 추가
  OnDialogueStarted.Broadcast()      ← PC 는 여기서 대화 창만 띄운다

EndDialogue
  CurrentTarget.Reset() / 태그 회수
  RestoreGameplayCamera()            ← 추가
  OnDialogueEnded.Broadcast()
```

### 구현·결정과 그 이유
- **새 컴포넌트를 만들지 않음(사용자 지시)**: 처음엔 `UControllerComponent` 를 상속한 전용 카메라 컴포넌트를 Experience 주입으로 붙이는 안(스캐너 선례)을 제시했으나, 사용자가 컴포넌트 추가 없는 단순한 해법을 요구했다. 세션 컴포넌트가 이미 PC 에 붙어 있고 대상·시작·종료를 다 아는 이상 그릇을 하나 더 만들 이유가 없었다 — 결과적으로 `ModularGameplay` 의존도, `EXP_Combat` 에셋 등록도, 등록 누락으로 조용히 죽는 실패 경로도 함께 사라졌다.
- **세션이 뷰 타겟을 드는 근거**: 세션은 이미 소유 클라에서 폰 ASC 에 `State.Dialogue` 를 발행하는 등 "대화가 열릴 때 월드에 하는 일"을 담당한다. 뷰 타겟 전환은 성격이 같고, `ACameraActor`·`APlayerController` 가 모두 `Engine` 이라 플러그인 경계도 넘지 않는다. 반면 UI 는 여전히 밖이다 — `WxDialogue` 는 `WxUI` 를 참조할 수 없으므로 창 개폐는 델리게이트 구독자인 PC 몫으로 남겼다.
- **자기 델리게이트를 자기가 구독하지 않음**: `OnDialogueStarted`/`OnDialogueEnded` 는 외부 구독자용이다. 세션 자신의 일은 `ClientStartDialogue`·`EndDialogue` 본문에서 직접 호출해, ASC 태그 발행·회수와 나란히 순서가 보이게 뒀다.
- **로컬 게이팅을 한 곳으로**: `GetLocalPlayerController()` 가 오너 캐스팅과 `IsLocalController()` 를 함께 처리하고, 아니면 null 을 답해 카메라 경로를 통째로 건너뛰게 했다. `ClientStartDialogue` 가 Client RPC 라 이미 소유 클라 전용이지만, 진입점이 둘(시작·종료)이라 게이트를 한 함수에 모으는 편이 안전하다.
- **PC 는 카메라 작업 이전으로 원복**: 두 핸들러가 대화 창 push/deactivate 만 남아, PC 헤더에서 카메라 관련 식별자가 완전히 사라졌다.

### 계획 대비 달라진 점
- 계획대로. 로컬 게이팅을 각 함수에 인라인하는 대신 `GetLocalPlayerController()` 헬퍼 하나로 모았다(진입점이 둘이라 중복을 피했다).

### 후속 과제
- PIE 육안 검증 미실시(빌드까지만 확인). 이관 작업이라 동작 변화가 없어야 정상이다 — 정면/옆/뒤 세 방향 구도, 시작 시 좌우 뒤집힘 없음, 벽 관통 없음, 종료 후 팔로우 카메라 복귀, `CameraActor` 미누적.
- 구도 파라미터가 PC 에서 세션 컴포넌트로 옮겨졌다. `BP_PlayerController` 에서 `DialogueSession` 컴포넌트를 골라 `Wx|Camera` 카테고리에서 조정한다(이전 위치의 오버라이드 값이 있었다면 승계되지 않는다 — 기본값을 쓰고 있었으므로 실제 영향은 없다).
- 앞선 작업이 남긴 한계는 그대로다 — 대화 중 이동·시선 입력 미잠금, `EndDialogue()` 가 `Advance`/`Choose` 경로에서만 호출돼 비정상 이탈 시 뷰가 카메라에 남음, `StartDialogue` 재진입 가드 부재, 선택지 노드 소프트락.
