# 체크포인트를 WxWorld 로 이관

## 계획

### 목표
`AWxCheckPoint`만 다른 기믹들과 떨어져 게임 모듈에 있어, 기믹 계층을 `WxWorld` 한 곳으로 모은다. 이관을 막는 유일한 요소인 충전형 아이템 리필(인벤토리 도메인 참조)은 보상 지급과 같은 방식으로 인벤토리 쪽 StateTree 태스크로 떼어낸다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxGame/WorldObject/WxCheckPoint.h`·`.cpp` | 삭제(WxWorld 로 이동) | 삭제 |
| `WxWorld/.../Public/Gimmick/WxCheckPoint.h`, `Private/Gimmick/WxCheckPoint.cpp` | 이관본. 모듈 API 부여, 인벤토리 리필 블록 제거 | 신규 |
| `WxInventory/.../Public|Private/Inventory/WxInventoryStateTreeNodes.h`·`.cpp` | 충전 리필 ST 태스크 신설 | 신규 |
| `Config/DefaultEngine.ini` | 클래스 경로 이동 리다이렉트 추가 | 수정 |
| `Source/WxGame/README.md`, `Plugins/WxWorld/README.md` | 체크포인트 소속 정정 | 수정 |

### 접근 방식
- **부수효과는 그 도메인이 태스크로 제공한다**: 보물상자가 이미 같은 문제를 같은 방법으로 푼다 — 보상 지급을 액터가 아니라 인벤토리 모듈이 제공하는 ST 태스크로 두고 ST 에셋에서 조립한다. 리필도 같은 자리에 놓으면 기믹 액터는 플러그인 경계를 넘지 않고, 리필 정책은 인벤토리 도메인에 남는다.
- **액터에 남는 일은 경계 안쪽뿐**: 상태 확정·회복 이펙트·적 리스폰은 모두 월드/엔진 범위라 그대로 둔다. 동작과 순서도 바뀌지 않는다.
- **복원 때는 다시 돌지 않는다**: 리필은 불을 켜는 순간의 사건이므로, 보상 지급 태스크와 똑같이 초기 진입·복원 마커를 걸러내고 권위 측에서만 수행한다.
- **저장된 에셋을 위해 리다이렉트를 남긴다**: 자식 BP 가 옛 클래스 경로를 물고 있어, 뷰모델을 옮겼을 때와 같은 형식의 리다이렉트 한 줄로 잇는다.

### 구현·결정과 그 이유
- **리필만 떼고 나머지는 그대로 옮겼다**: 상태 확정·회복 이펙트·적 리스폰은 이미 월드/엔진 범위라 손댈 이유가 없었다. 실제로 경계를 넘던 건 인벤토리 리필 한 조각뿐이라 그것만 옮겼고, 액터의 동작 순서도 그대로다.
- **보상 지급과 같은 자리에 놓았다**: 보물상자가 이미 같은 문제를 ST 태스크로 풀고 있어, 리필도 같은 형태·같은 가드(초기 진입/복원 스킵, 권위 전용, 0번 로컬 플레이어)로 맞췄다. 새 인터페이스도 새 어빌리티도 필요 없고, 두 태스크를 나란히 읽으면 규약이 그대로 보인다.
- **파라미터 없는 태스크로 두었다**: 리필 대상이 "가진 충전형 전부"로 고정이라 고를 것이 없다. 빈 인스턴스 데이터를 두고 에디터 설명도 고정 문구로 했다.
- **리다이렉트를 남겼다**: 자식 BP 가 옛 경로를 물고 있어, 뷰모델을 옮겼을 때와 같은 형식 한 줄로 이었다. BP 를 한 번 저장하면 새 경로가 베이크된다.

### 계획 대비 달라진 점
- 계획을 세울 때 본 소스는 콜리전 채널 응답으로 상호작용 영역을 표식하는 판이었는데, 실제 작업 시점의 워킹 트리는 `ActiveInteractionMeshes` 집합 방식으로 바뀌어 있었다. 이관본은 현재 방식(집합에 등록)을 그대로 따랐다.

### 후속 과제
- **에디터 수작업**: `ST_CheckPoint` 의 Lit 상태에 `Wx Refill Item Charges` 태스크 추가(`Wx Save Game` 앞), `BP_CheckPoint` 열어 부모 확인 후 저장.
- **빌드 검증 미완**: 이관한 두 파일은 오류 없이 컴파일됐지만, 워킹 트리에 진행 중인 다른 작업(`IWxInteractable` 에 순수 가상 `GetActiveInteractionMeshes` 추가 + `ECC_WxInteractable` 제거)을 아직 따라가지 못한 파일들 때문에 전체 빌드는 실패한다(`AWxNpc`·`WxItemPickup`·`WxAbility_Interact`·`AWxEnemyCharacter`). 그 작업이 끝난 뒤 전체 빌드로 다시 확인해야 한다.
