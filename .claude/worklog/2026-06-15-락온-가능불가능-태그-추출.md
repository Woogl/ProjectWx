# 락온 가능/불가능 태그를 LockOnPointComponent로 추출

## 계획

### 목표
락온 사망 감지가 native 태그 `State_Dead`를 로직에 고정해 쓰고 있어(태스크 태그 이벤트 + 어빌리티 후보 필터) 디자이너가 못 바꾼다. "락온 가능/불가능"을 정하는 태그를 대상 쪽 `UWxLockOnPointComponent`의 설정 변수로 빼고, 엔진 표준 `FGameplayTagRequirements`로 표현한다.

### 수정 범위
| 모듈 | 파일 | 수정할 내용 |
|---|---|---|
| `WxCombat` | `Public/Targeting/WxLockOnPointComponent.h` + `Private/.../.cpp` | `FGameplayTagRequirements LockOnRequirements` + `CanBeLockedOn()` 추가. Resolve/Gather를 lockable 필터로 변경 |
| `WxCombat` | `Private/AbilitySystem/Ability/WxAbility_LockOn.cpp` | `HandleTargetLost`의 하드코딩 dead 체크 제거(Resolve가 lockable만 반환하므로 redundant) |
| `WxCombat` | `Task/WxAbilityTask_LockOnTarget.h` + `.cpp` | 태그 이벤트(HandleTargetDeathTagChanged + Register/Unregister) 제거, TickTask에서 `CanBeLockedOn()` 폴링 |

### 접근 방식
- 판정을 `CanBeLockedOn()` 한 곳에 모음: 소유 ASC 보유 태그를 `GetOwnedGameplayTags`로 받아 `LockOnRequirements.RequirementsMet()` 반환. ASC 없으면 빈 컨테이너로 평가.
- 후보 해소(`ResolveLockOnTarget`=첫 lockable, `GatherLockOnPoints`=lockable 전부)가 lockable 지점만 내보내 어빌리티 3개 선택 경로가 자동으로 규칙을 공유.
- 현재 대상 사망 감지는 태그 이벤트(push) → 태스크 틱 폴링(pull)으로 전환. 컨테이너라 태그별 등록이 번거롭고, 태스크는 이미 거리/널을 틱에서 판정하므로 일관적.
- `FGameplayTagRequirements`: `/btw` 제안 채택. RequireTags=HasAll/IgnoreTags=HasAny/TagQuery, 평가기 내장. 기본 IgnoreTags에 State.Dead 저작. NameplateComponent는 범위 밖(그대로).

### 구현·결정과 그 이유
- **`FGameplayTagRequirements` 채택(`/btw` 제안)**: 2개 컨테이너+커스텀 평가 대신 프로퍼티 1개로 묶고 엔진 평가기 `RequirementsMet()`를 그대로 써 `CanBeLockedOn`이 짧아졌다. 에디터 표기(Must Have/Must Not Have/Query)가 자기설명적이고 TagQuery 탈출구도 덤. "불가능"이 IgnoreTags(HasAny)와 의미가 정확히 맞는다.
- **판정 단일화 + 해소 함수에서 필터링**: `CanBeLockedOn()`이 유일한 진실. `ResolveLockOnTarget`/`GatherLockOnPoints`가 lockable 지점만 내보내므로 어빌리티 3개 선택 경로(초기/재탐색/상실)가 자동으로 규칙을 공유한다. 그 결과 HandleTargetLost의 하드코딩 dead 체크가 redundant가 되어 제거.
- **사망 감지 push→pull**: 태그 이벤트 대신 태스크 TickTask에서 `CanBeLockedOn()` 폴링. 컨테이너라 태그별 등록이 번거롭고, 태스크가 이미 거리/널을 틱에서 판정하므로 일관적. 1프레임 지연은 무시 가능. OnDestroyed(파괴) 바인딩은 즉시성 위해 유지.

### 계획 대비 달라진 점
- 계획대로. (NameplateComponent 통일은 사용자 선택으로 범위 밖.)

### 후속 과제
- **콘텐츠(사용자)**: 필요 시 적 BP에서 `LockOnRequirements`를 오버라이드(예: "Untargetable" 태그를 Must Not Have에 추가, 특정 상태를 Must Have로 요구). 기본값은 State.Dead 차단.
