# 투사체 대미지 Spec 생성을 서버 권위로 제한

## 계획

### 목표
`AWxProjectileBase::BeginPlay`가 무조건 `InitializeDamageSpec()`을 불러 EffectContext·GE Spec 배열을 만들지만, 소비처인 `HandleHitCollisionOverlap`은 `HasAuthority()` 뒤에서만 쓴다. 클라이언트에서는 투사체 1발마다 DataTable 조회 + Spec 힙 할당이 버려지므로 생성을 권위 안으로 옮긴다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/Weapon/WxProjectileBase.cpp` | `InitializeDamageSpec()` 호출을 `HasAuthority()` 안으로 이동 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/Weapon/WxProjectileBase.h` | 클래스 주석의 Spec 생성 시점 서술을 서버 한정으로 정정 | 수정 |

### 접근 방식
- **생성을 소비처의 권위와 맞춤**: 투사체는 서버가 스폰해 복제하는 액터(`WxAbilityBase::SpawnProjectile`가 클라 예측 인스턴스에서 무동작)라 예측 키가 없다. 클라에서 만든 Spec은 쓸 방법 자체가 없으므로 생성을 막는 것이 맞다.
- **소비처는 손대지 않음**: `HandleHitCollisionOverlap`의 `CachedEffectContext.IsValid()` 검사가 이미 있어 클라에서 Context가 비어도 안전하다. `PlayImpactFX()`가 권위 검사 앞에 있는 것(충돌을 감지한 머신이 각자 즉시 재생)은 의도된 설계라 유지한다.

### 검토했으나 택하지 않은 안
`HandleHitCollisionOverlap`의 `HasAuthority()` 제거(= 클라도 대미지를 적용하게 두기). GAS가 `ApplyGameplayEffectSpecToSelf` 초입(`AbilitySystemComponent.cpp:1015-1019`)에서 `HasNetworkAuthorityToApplyGameplayEffect`로 막아 빈 핸들만 돌려주므로 대미지는 어차피 안 들어가고, Spec 생성 낭비도 그대로 남는다. 오히려 히트 지점 계산이 클라에서 추가로 낭비되고, 같은 게이트가 감싸는 `Destroy()`의 서버 권위(헤더 명시 규약)까지 깨진다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/Weapon/WxProjectileBase.cpp` | `BeginPlay`의 `InitializeDamageSpec()` 호출을 `HasAuthority()` 안으로 이동 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/Weapon/WxProjectileBase.h` | 권위 서술에 대미지 Spec 생성도 서버 한정임을 명시 | 수정 |

### 구현·결정과 그 이유
- **생성 시점을 권위 안으로**: 클라 복제본이 만든 Spec은 쓸 경로가 없다. 소비처가 이미 권위 게이트 뒤라 동작 변화는 없고, 탄막형 패턴에서 발당 DataTable 조회 + Spec 힙 할당이 사라진다.
- **소비처 무수정**: `HandleHitCollisionOverlap`의 `CachedEffectContext.IsValid()` 검사가 이미 있어 클라에서 Context 가 비어도 그대로 안전하다. `PlayImpactFX()`의 권위 검사 앞 배치도 의도된 설계라 건드리지 않았다.
- **락온 조준 블록은 그대로**: `BeginPlay` 의 락온 회전 보정은 이번 이슈 범위 밖이라 권위 게이트에 넣지 않았다.
