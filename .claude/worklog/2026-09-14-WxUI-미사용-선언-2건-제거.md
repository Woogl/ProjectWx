# WxUI 미사용 선언 2건 제거

## 계획

### 목표
대상도 호출자도 없는 선언 두 개를 지운다(`/module-review` WxUI 4번 🟢). 하나는 `UWxNameplateComponent` 의 `friend class FWxNameplatePresentationTest;` 로, 가리키는 클래스가 없다. 다른 하나는 `UWxUILibrary::DeactivateWidgetsInLayer` 로, C++·BP 어디에서도 호출하지 않는 `BlueprintCallable` 이다. 동작은 바뀌지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/Component/WxNameplateComponent.h` | `friend class FWxNameplatePresentationTest;` 와 뒤따르는 빈 줄 제거 | 삭제 |
| `Plugins/WxUI/Source/WxUI/Public/WxUILibrary.h` | `DeactivateWidgetsInLayer` 선언 제거, 고아가 되는 `GameplayTagContainer.h` include 제거 | 삭제 |
| `Plugins/WxUI/Source/WxUI/Private/WxUILibrary.cpp` | `DeactivateWidgetsInLayer` 정의 제거, 고아가 되는 `Widgets/CommonActivatableWidgetContainer.h` include 제거 | 삭제 |

### 접근 방식
- **friend 단순 삭제**: 이 줄은 09041a20(네임플레이트 리졸버 단순화)에서 들어왔다. 같은 이름의 클래스는 이력 어디에도 없고, 그때 계획했던 표시 테스트도 커밋되지 않았다. 현재 테스트 `FWxNameplateViewModelTest` 는 공개 API만 써서 friend 가 필요 없다.
- **`DeactivateWidgetsInLayer` 단순 삭제**: 리플렉션 노출 함수라 에셋 참조를 따로 확인했다.
  - `Content`·`Plugins` 의 `.uasset`/`.umap` 을 바이너리 문자열로 검색해도 0건이다.
  - 대조군인 `DeactivateOwningActivatable`(`WBP_Close`)·`ShowConfirmationPopup`(`WBP_FrontEnd`)은 같은 검색에 잡혀, 이 방식이 BP 참조를 검출함을 확인했다.
  - 3915a329 에서 `WBP_DeathScreen` 호출용으로 추가됐고, 5598cec5 에서 그 호출이 빠진 뒤로 호출자가 없다.
- **고아 include 2개 함께 제거**: 둘 다 3915a329 에서 이 함수 전용으로 같이 들어왔다. 헤더의 `GameplayTagContainer.h` 를 빼도 안전하다. `WxUILibrary.h` 를 포함하는 세 파일이 모두 `WxUIManagerSubsystem.h` 를 통해 이 헤더를 직접 받는다. adaptive unity 빌드가 누락 include 를 가릴 수 있어 빌드와 별개로 코드로 확인했다.
- **유지하는 것**:
  - `WxPrimaryGameLayout.h` include 는 이 함수보다 먼저 있었고 `GetPrimaryGameLayout` 의 반환 타입이다.
  - 리뷰 문서는 다음 `/module-review` 실행 때 재생성되도록 둔다.

### 구현·결정과 그 이유
- **대체 경로 없이 삭제**:
  - friend 는 이름만 있고 권한을 받을 클래스가 없었다.
  - 함수는 C++·BP 에셋 참조가 0건이라 에셋이 깨질 여지가 없다.
  - 레이어 단위로 비우는 기능이 다시 필요하면 그때 되살린다(원형은 3915a329).
- **고아 include 함께 제거**:
  - 두 include 는 이 함수 전용으로 같이 들어온 것이다. 남기면 공개 헤더를 포함하는 쪽에 쓰지 않는 의존만 퍼진다.
  - 실제 빌드에서도 adaptive 빌드가 수정 파일만 unity 에서 뺐고, `WxIndicator.cpp`·`WxPlayerLayoutComponent.cpp` 는 unity 안에 남았다. 그래서 누락 include 는 빌드 성공만으로 보증되지 않는다.
  - 대신 두 파일 모두 `WxUIManagerSubsystem.h` 를 통해 `GameplayTagContainer.h` 를 직접 받는 것을 코드로 확인했다.
- **검증**:
  - UE 5.8 `WxEditor Win64 Development` 빌드가 `Result: Succeeded` 로 끝났고, 로그에 경고·에러가 없다.
  - UHT 가 `WxUILibrary.gen.cpp`·`.generated.h` 를 재생성해 이 함수 흔적이 사라졌다.
  - 이 코드를 담은 `Module.WxUI.cpp` 와, 헤더를 포함하는 `Module.WxGame.cpp` 도 재컴파일·링크됐다.
  - Grep 결과 두 이름은 소스에 남지 않았다(리뷰 문서·워크로그에만 있음).
  - 동작 변화가 없어 PIE·자동화 테스트는 돌리지 않았다.
