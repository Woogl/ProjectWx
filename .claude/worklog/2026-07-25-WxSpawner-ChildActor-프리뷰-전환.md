# WxSpawner 프리뷰를 ChildActorComponent 방식으로 전환

## 계획

### 목표

스포너 프리뷰가 CDO에서 메시 하나만 복사하는 탓에 보스가 든 카타나가 보이지 않는다. 실제 액터를 세워 부착물까지 그대로 보여주되, 지난 작업의 에디터 월드 격리 구조를 재사용해 게임 월드와 액터 패키지를 오염시키지 않는다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/Source/WxWorld/Public/Spawnable/WxSpawner.h` | 프리뷰 메시 컴포넌트 2종을 ChildActorComponent 하나로 교체 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Private/Spawnable/WxSpawner.cpp` | 에디터 월드 한정 컴포넌트 생성, 메시·머티리얼 복사 로직을 클래스 지정으로 대체, 자식 액터 후처리 추가 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Public/Spawnable/WxSpawnableInterface.h` | 프리뷰 메시 훅 제거 | 수정 |

### 접근 방식

- **RF_Transient 컴포넌트를 에디터 월드에서 직접 생성**: 엔진은 컴포넌트가 transient면 자식 액터도 transient로 만들고, 그때 오너의 외부 패키지를 참조하지 않는다. 이것이 OFPA 오염이 없는 근거다. transient 조건 중 컴포넌트 자신의 오브젝트 플래그를 쓰는데, CDO 서브오브젝트로 만들면 플래그 전파가 불확실하므로 CDO에 두지 않고 생성 시점에 플래그를 명시한다. 생성 지점은 지난 작업의 등록 훅이라 게임 월드에는 컴포넌트 객체 자체가 생기지 않고, CDO에 없으니 쿠킹 빌드에도 흔적이 없다.

- **배치·머티리얼을 엔진에 위임**: 클래스만 지정하면 부착물·소켓·머티리얼이 전부 따라온다. 어태치 체인을 순회해 트랜스폼을 누적하고 머티리얼 슬롯을 복사하던 로직과, 스폰 대상이 프리뷰용 메시 컴포넌트를 알려주던 인터페이스 훅이 사라진다.

- **자식 액터 후처리**: 캡슐이 에디터 네비메시 빌드를 깎지 않도록 콜리전을 끄고, 발 정렬과 스프라이트 높이를 실제 바운드 기준으로 계산한다. 자식은 클래스가 바뀔 때마다 재생성되므로 후처리도 갱신 함수 안에서 함께 수행한다.

- **아웃라이너·쿠킹 위생**: 비주얼라이제이션 컴포넌트로 표시하면 엔진이 자식 액터를 에디터 전용으로 세우고, 트리 표시 모드를 숨김으로 두면 자식 액터가 아웃라이너에 뜨지 않는다.

### 알려진 리스크

- 프리뷰가 실제 액터이므로 BP 컨스트럭션 스크립트가 에디터 월드에서 실행된다. 보스 BP의 스크립트 내용은 확인하지 않았다.
- 적 캐릭터에 컴포넌트를 추가할 때 그 컴포넌트의 등록 시 동작이 에디터 월드에서 안전한지 따져야 하는 부담이 생긴다. 현재 붙어 있는 것들은 확인 결과 안전하다.

### 구현·결정과 그 이유
- **컴포넌트를 CDO가 아닌 생성 시점 플래그로**: 자식 액터가 스포너 패키지에 얹히지 않으려면 컴포넌트가 transient여야 하는데, 에디터 전용 서브오브젝트 헬퍼의 transient 인자는 컴포넌트 자체를 transient로 만들지 않는다고 엔진 주석이 명시한다. CDO 경유의 플래그 전파를 검증하는 대신 생성 시점에 명시하는 쪽을 택했다. 게임 월드에는 컴포넌트 객체조차 생기지 않고 쿠킹 빌드에도 흔적이 없다는 이점이 따라온다.

- **갱신 함수가 자식 액터 후처리까지 맡음**: 자식은 클래스가 바뀔 때마다 파괴 후 재생성되므로, 후처리를 생성 지점이 아니라 갱신 지점에 두어야 매번 다시 적용된다.

- **발 정렬과 스프라이트 높이 모두 루트 바운드 기준**: 캐릭터는 캡슐 중심이 액터 원점이라 정렬 없이는 허리까지 묻힌다. 전체 바운드를 쓰면 손에 든 무기가 발보다 아래로 뻗을 때 캐릭터가 떠오르고 아이콘 높이도 흔들리므로, 이전 방식과 같이 루트 바운드만 본다. 한 번 구한 바운드의 아래위를 각각 발 정렬과 아이콘 높이에 쓴다. 바운드를 로컬로 읽어 컴포넌트의 현재 위치에 좌우되지 않게 했고, 덕분에 갱신이 반복돼도 오프셋이 누적되지 않는다.

- **로드 시점 갱신 제거**: 프리뷰 컴포넌트가 아직 없는 시점이라 의미가 없고, 등록 훅이 생성과 갱신을 함께 담당한다.

### 후속 과제
- 에디터 뷰포트에서 카타나가 함께 보이는지, 클래스 교체 시 갱신되는지 육안 확인이 남았다.
- 레벨 저장 후 스포너 액터 패키지에 예상치 못한 변경이 없는지 확인해야 한다. 이 설계의 전제인 OFPA 비오염을 직접 검증하는 항목이다.
- PIE에서 프리뷰 비노출·유령 스폰 없음, 아웃라이너 비노출, 네비메시 비오염도 미확인이다.
- 프리뷰가 실제 액터이므로 보스 BP의 컨스트럭션 스크립트가 에디터 월드에서 실행된다. 내용은 확인하지 않았다.
