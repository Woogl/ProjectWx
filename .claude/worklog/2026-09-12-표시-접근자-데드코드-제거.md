# WxCharacterBase 표시 접근자 데드 코드 제거

## 계획

### 목표
`AWxCharacterBase`에서 `CharacterName`·`Portrait`로 가는 접근 경로를 `IWxUIData` 하나로 줄인다. 네임플레이트 표시 데이터를 뷰모델로 옮기면서 옛 통로가 호출자 없이 남았다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.h` | `GetCharacterName()`·`GetPortrait()` 선언 제거 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.cpp` | 같은 두 함수 정의 제거 | 수정 |

### 접근 방식
- **선언·정의 동시 제거**: 두 함수는 선언과 정의가 전부이고 `UFUNCTION`이 아니라 BP·에셋에서도 부를 수 없다. 같은 필드를 읽는 정식 통로인 `GetTitle()`·`GetIcon()`만 남긴다. 필드 자체와 `IWxUIData` 구현부는 건드리지 않는다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.h` | 표시 데이터 접근자 두 개 선언 제거 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.cpp` | 같은 두 함수 정의 제거 | 수정 |

### 구현·결정과 그 이유
- **삭제 근거 확인 후 제거**: 두 함수는 저장소 어디에서도 호출되지 않았고 `UFUNCTION`이 아니라 BP·에셋도 부를 수 없어, 지워도 끊길 참조가 없었다. 같은 필드를 읽는 통로가 둘이면 어느 쪽이 계약인지 판단할 근거가 사라지므로 `IWxUIData` 쪽만 남겼다.
- **필드와 인터페이스 구현은 그대로**: 표시 데이터 자체는 여전히 캐릭터가 저작·소유하고, 소비자는 인터페이스로만 읽는다. 접근 경로만 하나로 줄인 것이라 동작 변화는 없다.
