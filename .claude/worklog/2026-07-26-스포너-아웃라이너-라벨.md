# 스포너 아웃라이너 라벨 규칙 개선

## 계획

### 목표
아웃라이너에서 스포너끼리 구분이 안 되는 문제를 해소한다. `LV_DevCombat` 의 스포너 5기 중 3기가 라벨 `BP_Enemy` 로 완전히 동일해, 오늘 UOL 지정으로 바뀐 퀘스트 ST 의 노드 타이틀·픽커(액터 라벨을 그대로 표시)에서도 어느 스포너인지 고를 수 없다.

원인은 세 가지다. 라벨 갱신이 중복을 허용하는 raw `SetActorLabel` 을 직접 불러 번호가 안 붙고, 라벨이 스폰 대상 클래스명 그 자체라 스포너임이 드러나지 않으며, 클래스를 바꾸면 디자이너가 지은 이름을 무조건 덮는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/.../Public/Spawnable/WxSpawner.h` | `WITH_EDITOR` 블록에 `GetDefaultActorLabel` 오버라이드 선언 | 수정 |
| `Plugins/WxWorld/.../Private/Spawnable/WxSpawner.cpp` | `GetDefaultActorLabel` 구현, `PostEditChangeProperty` 의 라벨 갱신을 유니크 경로 + 커스텀 보존 판정으로 교체 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/WxWorld.Build.cs` | `if (Target.bBuildEditor)` 블록에 `UnrealEd` 사설 의존 추가 | 수정 |
| `LV_DevCombat` 스포너 5기 | 에디터에서 라벨 수동 정리 (신규 규칙 + 역할 이름) | 수정 |

### 접근 방식
- **엔진 순정 경로에 얹기**: 자체 번호 매기기를 만들지 않는다. 엔진의 배치·복제·팩토리 경로는 모두 `GetDefaultActorLabel` 로 기본 이름을 얻어 `SetActorLabelUnique` 로 번호를 붙인다. 그 가상 함수를 오버라이드해 `Spawner_<대상클래스>` 를 돌려주면 신규 배치·복제의 번호 부여가 따라온다.
- **접두사 선택**: `Spawner_` 를 앞에 두면 아웃라이너 이름순 정렬에서 스포너가 한 덩어리로 모이고 검색 한 번으로 필터된다. 클래스별 그룹핑은 접두사 뒤 문자열이 해준다. 대상 클래스는 `_C` 접미만 떼어 에셋 이름 그대로 붙인다(`Spawner_BP_Enemy`).
- **클래스 변경 시 재라벨**: 수동 `SetActorLabel` 을 `FActorLabelUtilities::SetActorLabelUnique` 로 교체해 같은 클래스 여러 기가 `Spawner_Enemy`, `Spawner_Enemy2` 로 갈리게 한다. 이 함수가 `UnrealEd` 소속이라 에디터 전용 의존을 추가한다.
- **커스텀 라벨 보존**: 재라벨 직전 현재 라벨이 자동 생성물(`Spawner` 로 시작)인지 보고, 아니면 디자이너 이름으로 간주해 건너뛴다.
- **보류**: 아웃라이너 아이콘 커스터마이즈는 스타일셋 등록용 에디터 모듈 신설이 필요해 하지 않는다. 폴더 자동 분류도 디자이너의 폴더 구성을 침범할 소지가 있어 제외한다.

### 구현·결정과 그 이유
- **엔진 경로 재사용**: 번호 매기기를 자체 구현하지 않고 엔진이 액터를 배치할 때 쓰는 유니크 라벨 함수를 그대로 불렀다. 규칙이 엔진과 어긋나지 않고, 오버라이드 하나로 배치·복제 경로의 넘버링까지 따라온다.
- **자동 라벨 판정은 접두사로**: 클래스 변경 시점엔 이전 클래스를 알 수 없어 "직전 자동 라벨과 일치하는가"를 엄밀히 볼 수 없다. 접두사 한 가지로 가르면 규칙이 한 줄로 설명되고 예측 가능하다. 대신 접두사를 유지한 채 역할을 덧붙인 이름(`Spawner_Enemy_QuestCamp`)은 자동 라벨로 취급되어 클래스 교체 시 덮인다 — 지켜야 할 이름은 접두사 없이 짓는다.
- **갱신 시점은 그대로**: 맵/셀 로드마다 도는 경로에 두면 근거 없이 패키지가 dirty 가 되므로, 디자이너가 클래스를 실제로 바꾼 순간에만 돈다는 기존 판단을 유지했다.

### 계획 대비 달라진 점
- 대상 클래스의 `BP_` 접두는 떼지 않기로 했다(사용자 요청). 에셋 이름 그대로가 검색·대조에 낫다는 판단.
- 계획서는 `Spawner_Enemy_CampLeft` 같은 이름이 보존된다고 봤으나, 접두사 판정이라 실제로는 자동 갱신에 덮인다. 규칙을 그대로 두고 한계를 문서화하는 쪽을 택했다.
- 기존 5기 라벨 정리를 수동이 아니라 MCP 로 처리했다. 외부 액터 패키지라 `save_actor` 가 애셋 레지스트리 조회에서 실패해 저장은 에디터에서 해야 한다.

### 후속 과제
- 라벨 변경분(스포너 5기) 저장이 남았다. 에디터에서 모두 저장 필요.
- 퀘스트 캠프용 Manual 스포너에 `Spawner_Enemy_QuestCamp` 를 붙였는데, 이 이름을 지키려면 접두사 없는 이름으로 바꾸는 편이 안전하다.
