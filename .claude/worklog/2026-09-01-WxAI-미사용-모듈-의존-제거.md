# WxAI 미사용 모듈 의존 제거

## 계획

### 목표
WxAI 모듈이 선언만 해두고 실제로는 쓰지 않는 빌드 의존 두 건을 지운다. 코드 리뷰(module_review_WxAI 발견 8)가 짚은 항목으로, 빌드 결과는 그대로면서 "이 모듈이 내비게이션·게임플레이태스크를 직접 다룬다"는 잘못된 신호만 준다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/WxAI.Build.cs` | `PublicDependencyModuleNames`에서 `GameplayTasks`·`NavigationSystem` 두 줄 삭제 | 수정 |

### 접근 방식
- **직접 쓰는 것만 선언한다**: 모듈 소스 전체에 두 모듈의 include도 심볼도 없다. 정찰·복귀 이동은 엔진 `UBTTask_MoveTo`가 대신 처리하므로 내비게이션 API를 이 모듈이 부를 일이 애초에 없다.
- **전이 의존으로 이미 들어와 있다**: 엔진 AIModule이 두 모듈을 public 의존으로 재수출한다. WxAI는 AIModule을 public으로 물고 있어, 지워도 헤더 해석 경로는 그대로다. 그래서 이 두 줄은 중복이자 무의미다.
- **private으로 옮기지 않는다**: 쓰는 코드가 없으니 private 선언도 똑같이 무의미하다. 나중에 실제로 직접 호출하게 되면 그때 private 의존으로 되살린다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/WxAI.Build.cs` | public 의존 목록에서 `GameplayTasks`·`NavigationSystem` 삭제 | 수정 |

### 구현·결정과 그 이유
- **계획대로 두 줄만 지웠다**: 나머지 의존은 쓰는 코드가 실재해 그대로 뒀다. 태그 정의는 WxCore 태그를 참조하는 데 필요하고, 어빌리티 발동 태스크는 GAS를 직접 부른다.
- **문서는 손대지 않았다**: 리뷰 문서는 특정 커밋 시점 스냅샷이라 소스가 바뀌면 다음 리뷰 실행 때 알아서 다시 쓰인다. 발견 항목을 지우고 번호를 당기는 건 불필요한 손질이다.

### 계획 대비 달라진 점
계획대로.

### 후속 과제
- 없음. 빌드가 성공했고, 무엇보다 빌드 스크립트가 바뀌었는데도 **재컴파일이 한 건도 일어나지 않았다** — 컴파일 환경이 그대로라는 뜻이고, 두 줄이 실제로 아무것도 공급하지 않았다는 사실이 이렇게 확인됐다.
