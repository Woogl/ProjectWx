# AWxTriggerDevice 를 AWxDevice 로 흡수

## 계획

### 목표
발동 장치(버튼·레버)를 "상태를 안 드는 특수 액터"가 아니라 **장치의 한 종류**로 만들어 `AWxTriggerDevice` 클래스를 없앤다. 두 클래스가 실제로 공유하는 코드는 권위 가드 정도인데, 갈라진 대가로 발동 장치만 다른 규약(BP `OnTriggered` 연출·`RetriggerCooldown`·Unreliable 멀티캐스트)을 쓰고 있다. 끝나면 `AWxDevice` 하나 + ST 에셋으로 모든 장치가 설명된다.

액터는 여전히 둘이다 — 상호작용이 액터 단위라 문의 버튼은 별도 액터여야 한다. 합치는 것은 클래스와 저작 모델이다.

### 옮겨가는 자리

| 지금 (`AWxTriggerDevice`) | 옮겨갈 자리 |
|---|---|
| `Prompt` · 상시 활성 | ST_Button 의 Idle 상태 — '상호작용 켜기'(bEnable=true, Prompt) |
| `OnTriggered`(BIE) + `Multicast_Trigger` | Pressed 상태의 연출 태스크. 피어 전파는 StateTag 복제 추종이 대신한다 |
| `RetriggerCooldown` · `IsOnCooldown` | Pressed 상태의 엔진 스톡 `Delay Task`(1초). 그동안 상호작용이 꺼져 있어 상태 자체가 게이트다 |
| `LinkedDevices` + 눌림 전달 | `AWxDevice` 의 프로퍼티로 이동 + 신규 ST 태스크 '연결 장치 발동' |
| `BeginPlay` ChildActor 자동 배선 | `AWxDevice::BeginPlay` 로 이동(부모 장치를 스스로 지목하는 계약 그대로) |
| `BodyMesh` 루트 · 콜리전 토글 잠금 | BP 가 세우는 몸통 + `AWxDevice` 의 활성 플래그(장치 공통 방식) |
| `StateTagRequirements` | 삭제 — 배치 사용처 0건, 대안('상호작용 켜기' Target 갈래)이 이미 있다 |

### 접근 방식
- **ST_Button 구조**: Idle(Tag `Device.Button.Idle`, '상호작용 켜기') --발행자--> Pressed(Tag `Device.Button.Pressed`, '상호작용 끄기' + '연결 장치 발동' + `Delay Task` 1초) --완료--> Idle.
- **Pressed 의 `Delay Task`**: 쿨다운이면서 동시에 완료 판정 태스크를 확보한다 — 즉발 태스크만 있는 상태는 형제의 완료 비트를 물려받아 즉시 완료·되감김하는 엔진 버그(5.8.1 잔존)에 걸린다.
- **신규 태스크는 `RespawnSpawners` 를 본뜬다**: 빈 인스턴스 데이터, `bShouldCallTick=false`, `bConsideredForCompletion=false`, 초기 진입 스킵, 권위 전용.
- **대상은 오너의 `LinkedDevices` 를 직접 읽는다**: ST 에셋 하나를 여러 배치 인스턴스가 공유하므로 배선은 액터에만 실릴 수 있고, 바인딩을 두면 저작자가 빠뜨렸을 때 조용한 무동작이 된다.
- **CoreRedirect 불필요**: 리페어런트를 클래스 삭제보다 먼저 끝내므로 `AWxTriggerDevice` 를 참조하는 에셋이 남지 않는다.

### 수용하는 변화
- 버튼도 ST 컴포넌트를 들어 지금의 `DORM_Initial` 이점을 잃는다(틱은 대부분 잠들어 있다).
- 프롬프트 문구가 ST 에셋에 실려 `ST_Button` 공유 버튼이 같은 문구를 쓴다.
- 아주 짧은 Pressed 는 프로퍼티 복제 합침으로 리모트 클라가 놓칠 수 있다(1초 쿨다운에선 무관, 지금의 Unreliable 멀티캐스트는 유실 자체가 가능했다).

### 구현·결정과 그 이유
- **쿨다운을 `Delay Task` 로 둔 것은 완료 판정 확보를 겸한다**: 즉발 태스크만 있는 상태는 형제의 완료 비트를 물려받아 즉시 완료·되감김하는 엔진 버그에 걸린다. 눌린 상태에 지연 태스크가 하나 있어야 그 상태가 스스로 끝나고 대기 상태로 돌아온다. 나중에 누름 연출을 넣으면 그 태스크가 같은 자리를 대신한다.
- **대상 지목은 태스크 파라미터가 아니라 오너 장치의 배열이다**: ST 에셋 하나를 여러 배치 인스턴스가 공유하므로 배선은 액터에만 실릴 수 있다. 바인딩으로 받게 하면 저작자가 빠뜨렸을 때 조용한 무동작이 되어, 태스크가 오너를 직접 읽게 했다.
- **차일드 액터 템플릿을 재생성해야 했다**: 내장 버튼은 부모 BP 안의 액터 템플릿에서 스폰되는데, 이 템플릿이 옛 클래스 시절 값을 그대로 들고 있어 새로 지정한 ST 에셋이 클래스 기본값에서 내려오지 않았다. PIE 에서 버튼 셋 다 트리가 열리지 않는 것으로 드러났고, 지목 클래스를 비웠다 되돌려 템플릿을 새로 뜨게 해 풀었다. 컴포넌트가 든 상대 트랜스폼은 템플릿 밖이라 그대로 살아남는다.
- **발행자→전이 링크는 프로퍼티가 아니라 바인딩이다**: 태스크의 발행 자리와 전이를 잇는 것은 상태 프로퍼티에 적히지 않고 에셋의 프로퍼티 바인딩으로 저장된다. 저작 도구가 보여주는 표시 이름이 아니라 실제 프로퍼티 이름으로 걸어야 컴파일러가 찾는다.
- **`StateTagRequirements` 는 되살리지 않고 버렸다**: 배치 인스턴스 사용처가 0건이고, 같은 목적을 대상 트리의 '상호작용 켜기' Target 갈래가 이미 처리한다. 살리려면 이 코드베이스에 아직 하나도 없는 ST 조건 노드를 새로 만들어야 해서, 실제로 필요해지는 시점으로 미뤘다.
- **CoreRedirect 없이 끝냈다**: 리페어런트를 클래스 삭제보다 먼저 해 두면 사라질 클래스를 참조하는 에셋이 남지 않는다.

### 계획 대비 달라진 점
- 차일드 액터 템플릿 재생성이 추가됐다(위 참조). 계획은 BP 클래스 기본값만 고치면 되는 줄로 보았다.

### 검증
- WxEditor(Development) 빌드 2회 성공(추가 단계, 삭제 단계).
- PIE: 내장 버튼 3개(문 1·엘리베이터 2) 모두 트리가 열려 대기 상태 태그를 발행하고, 자동 배선이 각자 문·엘리베이터를 지목했다. 문·엘리베이터도 기존대로 시작 상태를 발행한다.
- 남은 PIE 에러 2건은 이번 작업과 무관하다 — 앞선 이관의 후속 과제인 `BP_TreasureChest`·`BP_CheckPoint` 의 ST 에셋 미지정이다.

### 후속 과제
- **실제 누름 미검증**: 에디터 자동화로 게임 입력을 넣을 수 없어 상태 확인까지만 했다. 수동 PIE 로 버튼 누름 → 문 열림, 1초 안에 재조작 차단, 엘리베이터 두 버튼, 리슨 서버+클라 1 의 연출 일치를 확인해야 한다.
- 버튼 누름 연출이 아직 없다(옛 BP 훅도 비어 있었다). 넣는다면 눌린 상태에 '컴포넌트 이동'을 추가한다.
- `BP_TreasureChest`·`BP_CheckPoint` 의 ST 에셋 재지정(선행 작업 잔여).
- `Content/DesignerTables/DT_CharacterAttribute.uasset` 이 에디터 세션 중 내용 변화 없이 재저장됐다(크기 동일). 에디터를 닫고 되돌리면 된다.
