# 이펙트 UI 데이터 인터페이스 (IWxUIData)

## 계획

### 목표
`FWxEffectTableRow`에 추가한 Title/Description/Icon을 버프 위젯이 읽게 한다. `WxUI`는 `WxCombat`을 참조할 수 없으므로 WxCore에 표시 데이터 계약을 두고 WxCombat 쪽이 구현한다. 갈라져 있던 표시 데이터 출처(`UWxEffectComponent_UIData`)를 테이블로 일원화한다.

### 조사로 확인한 사실
- `UGameplayEffect::GEComponents`는 protected이고 배열 접근자가 없다. 조회는 클래스 기반 `FindComponent<T>()` 뿐이라 WxUI가 GE 컴포넌트를 인터페이스로 훑을 수 없다 — 조회 앵커가 될 *클래스*가 WxUI에서 보여야 한다.
- 엔진 `UGameplayEffectUIData`는 `UGameplayEffectComponent` 파생의 Abstract·프로퍼티 없음 클래스로 정확히 이 용도다. WxCore에 GameplayAbilities 의존을 넣지 않고도 앵커가 된다.
- `UWxEffectComponent_UIData` 참조 `.uasset` 0개, `WBP_Effect`는 `EffectName`을 바인딩하지 않는다.

### 접근 방식
- **WxCore `IWxUIData`**: `GetTitle`/`GetDescription`/`GetIcon` 순수 가상 3개. GAS 타입을 쓰지 않아 WxCore 의존성은 그대로다. 함수명을 짧게 둔 덕에 기존 `UWxAbilityBase::GetIcon()`이 시그니처까지 같아 나중에 그대로 오버라이드가 된다.
- **앵커**: `UWxEffectComponent_Table`의 부모를 `UGameplayEffectUIData`로 바꿔 WxUI가 찾을 수 있게 한다. 앵커 클래스에 프로퍼티가 없어 기존 GE 에셋 직렬화 영향 없음.
- **표시 대상 필터 변경**: 예전엔 UIData 컴포넌트 부착 여부가 곧 필터였으나, 이제 수치만 쓰는 GE도 같은 앵커에 걸린다. 아이콘·제목이 모두 비면 목록에 넣지 않는다.

### 구현·결정과 그 이유
- **앵커를 엔진 `UGameplayEffectUIData`로**: `UGameplayEffect::GEComponents`가 protected이고 조회가 클래스 기반 `FindComponent<T>()` 뿐이라, WxUI가 인터페이스로 컴포넌트를 훑을 방법이 없다. 양쪽이 아는 클래스는 엔진 것뿐이고, 이 클래스는 Abstract·프로퍼티 없음이라 기존 GE 에셋 직렬화에도 영향이 없다. WxCore에 GameplayAbilities 의존을 새로 넣지 않아도 되는 것이 이 선택의 이점이다.
- **인터페이스 함수명을 짧게**: 이름이 `IWxUIData`라 맥락을 이미 지고 있다. 덕분에 기존 `UWxAbilityBase::GetIcon()`이 시그니처까지 같아, 어빌리티가 이 계약을 받을 때 추가 함수 없이 그대로 오버라이드가 된다.
- **표시 대상 필터를 아이콘 유효성으로**: 예전엔 UIData 컴포넌트 부착 여부가 곧 "버프 목록에 뜨는가"였는데, 이제 수치만 쓰는 GE(대미지 등)도 같은 앵커에 걸린다. 버프 목록은 아이콘으로 그려지므로 아이콘을 채우는 행위가 곧 노출 의사표시가 된다 — 제목은 판정에 넣지 않는다.
- **`EffectName`→`Title` 개명**: 테이블 칼럼과 이름을 맞췄다. `WBP_Effect`가 이 필드를 바인딩하지 않는 것을 확인하고 진행했다.

### 후속 과제
- `UWxAbilityBase`가 `IWxUIData`를 구현하고 `FWxAbilityTableRow`에 Title/Description을 추가하면, `UWxViewModel_Ability`가 `GetBoundAbility()`를 `Cast<IWxUIData>` 해서 직접 읽을 수 있다. 그때 `WxViewModelResolver_Ability`의 아이콘 주입은 지울 수 있다(최대 충전 수 주입은 별개로 남는다).
- 인게임 확인 미실시 — `DT_Effect`에 표시 데이터를 채운 행이 아직 없다.
