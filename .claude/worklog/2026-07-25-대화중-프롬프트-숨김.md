# 대화 중 상호작용 프롬프트 숨김

## 계획

### 목표
NPC 대화 창이 떠 있는 동안 상호작용 프롬프트 리스트와 외곽선 하이라이트를 숨긴다. 대화 중에는 상호작용이 불가능하므로 표시도 함께 닫는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../WxGameplayTags.h/.cpp` | State.Dialogue 태그 추가 | 수정 |
| `Source/WxGame/AbilitySystem/Ability/WxAbility_Interact.cpp` | 차단 태그에 State.Dialogue 추가 | 수정 |
| `Plugins/WxDialogue/.../WxDialogueSessionComponent.h/.cpp` | 세션 시작/종료에 맞춰 폰 ASC에 loose 태그 발행/제거 | 수정 |
| `Plugins/WxDialogue/` (Build.cs·uplugin) | GameplayAbilities 의존 추가 | 수정 |

### 접근 방식
- **기존 단일 게이트 재사용**: 스캐너의 표시 게이트는 상호작용 어빌리티의 활성 가능 여부에 위임돼 있고, 게이트가 닫히면 후보를 비워 프롬프트·하이라이트까지 정리한다. 처형 연출(State.Finisher)이 같은 용도의 선례라, 대화 상태 태그를 어빌리티 차단 태그에 더하는 것으로 충분하다.
- **태그 발행은 세션 컴포넌트가 직접**: "대화 중" 상태의 원천은 세션이므로 세션이 열리고 닫힐 때 스스로 폰 ASC에 loose 태그를 넣고 뺀다(상태는 원천이 발행, 사용자 요청으로 PC 글루안에서 변경 — PC 무수정). 종료 시 되돌릴 ASC를 발행 시점에 기억해 도중 폰 교체에도 짝이 맞는다. loose 태그는 로컬 전용이라 클라 표시 게이트에 정확히 부합하고, 스탠드얼론에선 대화 중 상호작용 재입력의 서버 활성까지 막혀 이중 푸시 엣지도 함께 해소된다.

### 구현·결정과 그 이유
- **발행 주체를 PC에서 세션으로 이동(사용자 요청)**: "대화 중" 상태의 원천은 세션이므로 세션이 직접 발행한다. PC는 무수정으로 남고, 대화를 붙인 다른 액터도 자동으로 같은 동작을 얻는다.
- **GAS 의존 유지 결정**: GAS 없이 액터에 태그를 주입하는 엔진 API는 없고(GameplayTags 모듈은 타입·읽기 계약뿐, 쓰기는 ASC 소속), 도메인 플러그인의 GameplayAbilities 의존은 WxWorld·WxCombat과 같은 급의 표준. 무의존 대안(WBP 그래프 발행)은 게임플레이 신호가 BP 저작물에 숨는 단점으로 보류 — 장단점 비교 후 사용자 확정.
- **되돌릴 ASC를 발행 시점에 기억**: 종료 시 같은 ASC에서 제거해 도중 폰 교체에도 짝이 맞는다.

### 계획 대비 달라진 점
- 태그 발행 글루가 PC(WxGame)에서 세션 컴포넌트(WxDialogue) 내부로 이동, PC 수정분은 전량 되돌림. 그 외 계획대로.

### 후속 과제
- 없음. (검증: 빌드 성공, PIE 자동 재현으로 대화창 열림과 동시에 프롬프트 리스트·외곽선 소멸 확인 — 스크린샷 대조)
