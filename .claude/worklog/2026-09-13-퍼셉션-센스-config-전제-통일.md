# 퍼셉션 센스 config 전제를 하나로 통일

## 계획

### 목표
`UWxAIPerceptionComponent` 가 한 클래스 안에서 센스 config 의 널 가능성을 두 가지로 다루는 것을 하나로 줄인다. `PostInitProperties` 는 세 config 를 널 검사한 뒤 등록하는데 `ApplySenseSettings` 는 검사 없이 역참조해, 코드만으로는 어느 쪽이 참인 불변식인지 알 수 없다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | `PostInitProperties` 의 널 검사 세 개를 걷어내고 `ConfigureSense` 를 바로 호출. 등록 주석에 "셋은 생성자가 보장한다" 를 합쳐 불변식을 한 번만 선언 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | 클래스 주석에 감지 수치의 SSoT 가 `UWxAIBehaviorComponent` 라는 한 줄 명시 | 수정 |

### 접근 방식
- **생성자 보장 쪽으로 통일**: 감지 수치의 SSoT 는 `UWxAIBehaviorComponent` 이고, 퍼셉션의 세 config 는 그 수치를 받아 적는 그릇일 뿐이라 생성자의 `CreateDefaultSubobject` 가 항상 만든다. 파생 클래스도, 서브오브젝트 생성을 건너뛰는 경로도 없으므로 참인 전제는 "셋은 항상 있다" 다. 반대로 `ApplySenseSettings` 앞에 `check` 를 다는 선택지는 널이 될 경로가 없는데 진단만 늘리는 것이라 택하지 않는다.
- **수치 경로는 건드리지 않는다**: `GetDefault<UWxAIBehaviorComponent>()` 폴백은 "폰에 컴포넌트가 없어도 수치는 SSoT 의 기본값에서 온다" 는 뜻이라 그대로 둔다.
- **동작 변화 없음**: 지우는 분기는 현재 실행되지 않는 경로다. 센스 등록 순서·시점·수치 모두 그대로다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | `PostInitProperties` 의 널 검사 세 개 제거, 등록 주석에 생성자 보장을 명시 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | 클래스 주석에 config 존재 보장과 감지 수치의 출처를 한 줄로 명시 | 수정 |

### 구현·결정과 그 이유
- **참인 전제만 남겼다**: 감지 수치의 출처는 폰의 행동 컴포넌트 하나이고 센스 config 는 그 수치를 받아 적는 그릇이라, 세 config 가 없는 상태는 설계상 성립하지 않는다. 생성자가 셋을 항상 만들고 파생 클래스도 없으므로, 등록 시점의 널 검사는 실행될 일이 없는 방어적 선언이었다. 검사를 지워 클래스 안의 두 전제를 "셋은 항상 있다" 하나로 모았다.
- **진단을 늘리는 쪽은 택하지 않았다**: 반대 방향(수치 적용부에 `check` 추가)도 전제를 통일하지만, 널이 될 경로가 없는데 확인만 늘어난다. 불변식은 주석 한 줄로 선언하는 편이 읽는 비용이 낮다.
- **수치 경로는 손대지 않았다**: 폰에 행동 컴포넌트가 없을 때의 CDO 폴백은 "수치는 어떤 경우에도 행동 컴포넌트에서 온다" 는 뜻이라 그대로 뒀다. 등록 순서·시점·적용 수치가 모두 같아 동작 변화는 없다.

## 추가 정리 — 등록 지점을 생성자로, 수치 갱신을 ConfigureSense 로

검토 중 "그러면 override 자체가 필요 없지 않나" 는 물음이 나와 엔진 소스(UE 5.8)로 사용법을 확인하고 두 가지를 더 고쳤다.

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | 센스 등록을 생성자로 옮기고 `PostInitProperties` 정의 제거, 수치 적용 뒤 갱신을 `ConfigureSense` 재호출로 교체 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | `PostInitProperties` 선언 제거, 클래스 주석을 "생성자가 만들어 등록까지 마친다" 로 조정 | 수정 |

### 구현·결정과 그 이유
- **등록을 만드는 자리로 붙였다**: 센스는 등록 전까지 config 배열에 들어 있기만 하면 되고 채널을 여는 곳은 `OnRegister` 하나다. 생성자에서 config 를 만든 직후 넘기면 생성·설정·등록이 한 블록에서 끝나 override 가 필요 없다. 생성자에서 만든 서브오브젝트를 Instanced 배열에 담는 모양은 엔진이 자체 테스트로 보증하는 패턴이라, 인스턴스마다 자기 config 를 가리키는 것도 보장된다.
- **재구성은 전용 통로로**: 수치를 고친 뒤에는 바뀐 config 를 다시 넘기는 것이 엔진이 의도한 재구성 경로다. 시야는 이때 판정용 캐시만 새로 만들고 피아 필터가 바뀐 경우에만 쿼리를 다시 세우는 반면, 리스너 전체 갱신은 쿼리를 통째로 파기하고 재생성한다.
- **팀 캐시 갱신은 그대로 컨트롤러 몫**: 리스너가 캐시하는 팀 식별자는 재구성 통로로는 갱신되지 않는데, 빙의 직후 컨트롤러가 이미 리스너 갱신을 따로 부르고 있어 빈틈이 없다. 퍼셉션 쪽에서 중복으로 부르지 않는다.
