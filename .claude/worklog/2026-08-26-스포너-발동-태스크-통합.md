# 스포너 발동 태스크 2벌을 UOL 지정형 한 벌로 통합

## 계획

### 목표
같은 표시명(「스포너 발동」)으로 노드 픽커에 나란히 뜨던 스포너 발동 태스크 2벌을 하나로 합친다. 이름은 `TriggerSpawners`, 구현은 UOL 지정형(구 `ByLocator`)이 살아남고, 실사용이 0인 바인딩형 구현은 버린다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxWorld/Public/Spawnable/WxStateTreeTask_TriggerSpawners.h` | `ByLocator` 헤더를 이 이름으로 이동·개명, 형제 지목 문구 정리 | 신규(이동) |
| `WxWorld/Private/Spawnable/WxStateTreeTask_TriggerSpawners.cpp` | 〃 (경고 문구를 `Trigger Spawners:` 로) | 신규(이동) |
| `WxWorld/{Public,Private}/Spawnable/WxStateTreeTask_TriggerSpawnersByLocator.{h,cpp}` | 위로 이동 | 삭제 |
| `WxWorld/{Public,Private}/Device/WxStateTreeTask_TriggerSpawners.{h,cpp}` | 바인딩형 구현 폐기 | 삭제 |
| `Config/DefaultEngine.ini` | `[CoreRedirects]` 에 `StructRedirects` 2줄 | 수정 |

### 접근 방식
- **살아남는 쪽은 UOL 지정형**: 바인딩형은 쓰는 에셋도 없고(에셋 전수 조사) 바인딩할 원본 프로퍼티도 프로젝트에 없다. 반대 방향(소프트 참조 통일)은 2026-08-13 오전에 해봤다가 ST 컴파일러의 레벨 액터 거부로 그날 오후 되돌린 길이다.
- **파일은 `Spawnable/` 로**: 형제 `WaitSpawnersKilled` 와 검증 헬퍼가 있는 자리다. 헤더를 include 하는 곳이 없어 이동 비용이 0이다.
- **개명이라 CoreRedirects 필수**: 없으면 `ST_QuestStep_KillEnemies` 의 노드가 조용히 죽고 저장 시 영구 소실된다. 필드 이름·타입이 그대로라 값은 그 자리에 얹힌다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `WxWorld/{Public,Private}/Spawnable/WxStateTreeTask_TriggerSpawners.{h,cpp}` | `ByLocator` 쌍을 이 이름으로 이동, 구조체·인스턴스 데이터 개명, 경고 문구를 `Trigger Spawners:` 로, 형제 지목 한 줄 삭제 | 수정(이동·개명) |

### 구현·결정과 그 이유
- **UOL 쪽이 살아남았다.** 바인딩형은 쓰는 에셋이 하나도 없고, 프로젝트 어디에도 스포너 배열을 노출한 액터 프로퍼티가 없어 바인딩을 걸 원본조차 없었다. 반대로 UOL 형은 퀘스트 스텝이 실제로 쓴다. 2026-08-13 오전에 반대 방향(소프트 참조 통일)으로 한 번 합쳤다가 ST 컴파일러의 레벨 액터 값 거부로 그날 오후 되돌린 이력도 같은 결론을 가리킨다.
- **파일은 `Spawnable/` 로 갔다.** 살아남은 구현이 형제 `WaitSpawnersKilled` 및 검증 헬퍼와 같은 도메인이고, 실제 소비자도 장치가 아니라 퀘스트 스텝이다. 이 헤더를 include 하는 코드가 없어(ST 태스크는 리플렉션으로만 잡힌다) 이동 자체는 무비용이었다.
- **리다이렉트는 상주시킨다.** 에셋을 되저장해 이름을 굳히는 대신 ini 항목을 남겼다 — 기존 `WxComponentName` 항목과 같은 취급이고, 에셋을 건드리지 않아 되돌리기도 쉽다.
- **바인딩 경로는 버렸다.** 공유 장치 ST 에서 배치 인스턴스별 스포너를 지목하려면 언젠가 필요할 수 있지만, 지금은 소비자도 바인딩 소스도 없다. 필요해질 때 소스 프로퍼티와 함께 되살리는 편이 낫다.

### 검증
- WxEditor(Development) 빌드 성공(`Result: Succeeded`). 낡은 `ByLocator` UHT 산출물도 함께 정리됐다.
- **리다이렉트 실측**: `ResavePackages` 커맨드릿으로 `ST_QuestStep_KillEnemies` 를 헤드리스 로드. 로드 단계 경고·에러 0으로, 구조체 해석 실패 시 나오는 `Unable to find serialized UScriptStruct ... reset to empty FInstancedStruct` 가 유니크 경고 요약에도 없었다. 에셋에는 `ByLocator` 이름이 그대로 박혀 있고 그 구조체는 새 바이너리에 존재하지 않으니, 해석은 리다이렉트를 탄 것이다.
- 저장 단계는 에디터가 파일을 물고 있어 실패했다(Error Code 32) — 의도한 대로 에셋은 그대로다.

### 계획 대비 달라진 점
- 에디터 안 확인(노드 픽커·에셋 열기)은 못 했다. 떠 있는 에디터가 DebugGame 구성이라 이번에 빌드한 Development 바이너리를 물지 않는다. 대신 헤드리스 로드로 같은 질문(리다이렉트가 먹는가)에 답했다.

### 후속 과제
- 에디터를 새 바이너리로 재시작하면 노드 픽커에 「스포너 발동」이 하나만 뜨는지, 스텝의 스포너 값이 패널에 그대로 보이는지 눈으로 확인.
- `Docs/Programmer/module_review_WxWorld.md` 5번(같은 DisplayName 2벌) 지적은 해소됐다 — 다음 module-review 주기에 갱신된다.
