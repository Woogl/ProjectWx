# 어빌리티 뷰모델의 코스트 자식 뷰모델 노출

## 계획

### 목표
WBP_Ability 가 코스트를 표시하려면 코스트 자원의 현재·최대·비율이 필요하다. 지금 어빌리티 VM 은 그 값을 평면 프로퍼티로 직접 들고 있어, 같은 역할을 하는 공용 어트리뷰트 표시 위젯을 그대로 꽂을 수 없다. 코스트 자원으로 만든 어트리뷰트 자식 VM 을 노출해 바인딩 한 줄로 붙게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_Ability.h` | `CostViewModel` 프로퍼티 추가, 코스트 평면 프로퍼티 3종·게터/세터·갱신 함수 제거 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/MVVM/WxViewModel_Ability.cpp` | 코스트 확정 직후 자식 VM 생성, 해제 시 자식 정리, 제거한 프로퍼티 정의 삭제 | 수정 |

### 접근 방식
- **자식 VM 을 FieldNotify 프로퍼티로**: 캐릭터 VM 이 어빌리티시스템 자식 VM 을 노출하는 방식과 같다. 컨버전 함수는 키로 찾아야 할 때 쓰는 장치이고, 코스트는 어빌리티당 고정 1개라 프로퍼티가 맞다.
- **생성 시점은 코스트 확정 직후**: 코스트 GE 를 1회 평가해 자원과 최대치 어트리뷰트를 정하는 자리에서 그 둘로 자식 VM 을 만든다. 코스트가 없는 어빌리티는 자식이 null 로 남아 위젯 쪽에서 자연히 표시되지 않는다.
- **수명은 부모가 끊는다**: 해제 시 자식의 해제를 호출하고 참조를 비운다.
- **중복 제거**: 자식 VM 이 같은 값을 자기 구독으로 갱신하므로 코스트 현재·최대·비율 평면 프로퍼티는 지운다. 콘텐츠에서 이 셋을 바인딩한 에셋은 없다. 소모량은 어트리뷰트 VM 에 없는 값이라 어빌리티 VM 에 남긴다.

### 구현·결정과 그 이유
- **바인딩이 부를 때 만든다**: 코스트를 표시하지 않는 위젯까지 VM 을 만들 이유가 없다. 프로퍼티 직결은 네이티브 Getter 가 const 라 지연 생성에 `mutable`/`const_cast` 가 필요해, 이미 어트리뷰트·어빌리티 VM 에서 쓰던 컨버전 함수 → GetOrCreate 경로로 통일했다.
- **컨버전 함수 인자는 어빌리티시스템 VM + 태그**: 뷰모델 자체는 바인딩 핀에 넣을 수 없어서, 어빌리티 VM 을 직접 받는 형태는 WBP 에서 배선이 불가능했다. 어빌리티 VM 을 태그로 얻는 형제 함수와 같은 모양으로 맞췄다.
- **ASC 에 있는 같은 자원 VM 재사용**: 어빌리티시스템 VM 이 만들어 둔 어트리뷰트 VM 은 ASC 를 Outer 로 살아 있으므로, 자원과 최대치가 같으면 그대로 쓴다. 같은 자원에 구독이 겹치지 않는다.
- **소유는 Outer 로 가른다**: 내가 만든 VM 만 Outer 가 자신이라, 해제 때 남의 VM 을 끊지 않는다. 소유 플래그 멤버를 두지 않아도 된다.
- **자원 값 갱신 책임을 자식에게 넘김**: 자식이 같은 어트리뷰트를 스스로 구독하므로 부모의 값 갱신은 중복이 된다. 부모에 남은 코스트 구독은 발동 가능 여부 재평가 용도만 남겼다.
- **소모량은 남김**: 어트리뷰트 VM 에 없는 값이라 어빌리티 쪽에 있어야 한다.

### 계획 대비 달라진 점
- 계획은 초기화 때 자식 VM 을 만들어 FieldNotify 프로퍼티로 노출하는 것이었으나, 지연 생성 요구에 따라 컨버전 함수 경로로 바꿨다. 재사용 요구가 더해져 ASC 하위 탐색이 추가됐다.

### 후속 과제
- WBP_Ability 에 코스트 표시 위젯 배치 및 컨버전 함수 바인딩(에셋 작업). 어빌리티시스템 VM 을 얻으려면 플레이어 캐릭터 리졸버 컨텍스트가 그 위젯에 있어야 한다. 그 전까지 PIE 실동작 확인은 미검증.
- 컨버전 함수가 태그로 어빌리티 VM 을 얻는 경로라, 슬롯 리졸버가 만든 어빌리티 VM 과 별개의 인스턴스가 하나 더 생긴다. 코스트 자원 VM 은 ASC 탐색으로 공유되지만 어빌리티 VM 자체는 중복이며, 아래 공유화에서 정리된다.
- 재사용한 VM 의 소유자(다른 위젯의 어빌리티시스템 VM)가 먼저 해제되면 값 갱신이 멎을 수 있다. 아래 공유화에서 수명이 한 곳으로 모이면 사라지는 위험이다.
- **뷰모델 공유화(별건)**: 캐릭터 VM 이 위젯마다 새로 생성돼 하위 VM 캐시가 위젯별로 쪼개져 있다. 캐릭터당 1개로 공유하면 어트리뷰트 VM 이 HUD 와 스킬 슬롯 사이에서 재활용되고, 위젯마다 따로 짓는 이펙트 VM 목록·GE 구독 중복도 사라진다. 그때 코스트 VM 은 ASC 하위 탐색 대신 어빌리티시스템 VM 의 어트리뷰트 VM 팩토리 호출로 바꾼다.
