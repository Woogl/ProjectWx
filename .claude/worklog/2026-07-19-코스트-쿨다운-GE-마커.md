# 코스트/쿨다운 GE 클래스를 "프로젝트 방식 vs 커스텀" 마커로 자기문서화

## 계획

### 목표
`UWxAbilityBase`의 `Cost/CooldownGameplayEffectClass` 기본값을 공용 GE(`UWxEffect_Cost`/`UWxEffect_Cooldown`)로 지정해 **마커**로 삼는다. 필드에 마커가 있으면 프로젝트 방식(테이블 기반), 다른 GE면 커스텀 — 디테일 패널에서 코스트/쿨다운 모드가 바로 읽히는 자기문서화 구조로 만든다. 거의 빈 클래스였던 `UWxEffect_Cost`에 "마커"라는 실질적 역할이 생긴다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/.../Ability/WxAbilityBase.cpp` | 생성자에 마커 기본값 2줄, 판정 헬퍼 2개 정의, 분기 조건 7곳 교체(쿨다운 5·코스트 2), `PostEditChangeProperty`가 Row 지정 시 마커로 리셋 | 수정 |
| `WxCombat/.../Ability/WxAbilityBase.h` | 판정 헬퍼 2개 선언, 클래스 독 코멘트 마커 규칙으로 갱신(+오타 `GetDataRow`→`GetTableRow` 정정) | 수정 |
| `WxCombat/.../Effect/WxEffect_Cost.h`, `WxEffect_Cooldown.h` | 마커 역할 한 줄 명시 | 수정 |
| `Docs/Programmer/Ability_Activation_Flow.md` | 스톡 GE 분기 설명을 마커 규칙으로 갱신 | 수정 |

### 접근 방식
- **마커 판정**: 기본값이 마커라 두 필드는 항상 non-null. 분기 기준을 "마커가 아닌 다른 클래스인가"로 바꿔야 오판(빈 CDO로 커밋)하지 않는다. 판정은 클래스 정체성 비교로 파생(멤버 플래그 신설 없음): `HasCustomCostGE()`/`HasCustomCooldownGE()`. `null`과 마커는 모두 "커스텀 아님"=프로젝트 경로.
- **메커니즘 불변**: 런타임 인스턴스(`NewObject` + Modifiers, `ApplyCost` 인스턴스 Def 스펙)는 그대로. 마커는 분기 조건만 바꾼다.
- **불변식**: 데이터 Row=프로젝트 방식=마커 표시. 그래서 `PostEditChangeProperty`가 Row 지정 시 두 필드를 `null` 대신 마커로 리셋한다(기능은 동일, 표시만 마커).

### 구현·결정과 그 이유
- **마커 판정 인라인**: 기본값이 마커라 두 필드는 항상 non-null이므로 분기 기준을 `Class && Class != 마커::StaticClass()`로 바꿔야 오판(빈 CDO 커밋)을 막는다. 처음엔 헬퍼 2개로 뺐으나 사용자 요청으로 제거하고 각 분기에 직접 풀어썼다.
- **메커니즘 불변**: 런타임 인스턴스(`NewObject`+Modifiers, `ApplyCost` 인스턴스 Def 스펙)는 그대로. 마커는 표시·분기 신호일 뿐 적용 방식은 안 건드린다.
- **Row=마커 불변식**: `PostEditChangeProperty`가 Row 지정 시 커스텀 GE를 `null`이 아닌 마커로 리셋 — 기능은 `null`과 동일하나 "Row=프로젝트 방식=마커 표시"를 유지해 패널에서 일관되게 읽힌다.

### 계획 대비 달라진 점
- `HasCustomCostGE()`/`HasCustomCooldownGE()` 헬퍼는 사용자 요청으로 도입하지 않고 비교를 인라인으로 풀어썼다(그 외 계획대로).

### 후속 과제
- 에디터 동작 확인(권장): 어빌리티 BP에서 기본값이 마커로 표시되는지, Row 기반 어빌리티의 MP/UP 코스트·쿨다운 정상 적용 및 자원 부족 시 CheckCost 차단. 컴파일은 WxEditor(Development) 빌드로 검증 완료(Result: Succeeded).
