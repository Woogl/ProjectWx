# 네임플레이트 표시 판정 이벤트 구동화

## 계획

### 목표
`UWxNameplateComponent`가 매 틱 `RefreshVisibility`에서 `GetOwnedGameplayTags`로 태그 컨테이너를 새로 할당하던 것을(화면 적 수만큼 프레임당 N회 힙 할당) ASC 태그 변경 이벤트 구독으로 옮겨 매 틱 할당을 없앤다. `module_review_WxUI.md` 발견 #4 수정. 동작(무엇이 표시되는지)은 불변.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/Component/WxNameplateComponent.h` | `HandleOwnedTagsChanged` 콜백·`EndPlay` override 선언 추가, `RefreshVisibility` 주석 정합 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/Component/WxNameplateComponent.cpp` | 틱에서 `RefreshVisibility` 제거, `InitializeViewModels`에서 태그 이벤트 구독+초기 1회 평가, 콜백·`EndPlay` 정의 | 수정 |

### 접근 방식
- **이벤트 구동화**: `UWxViewModel_AbilitySystem`(`WxViewModel_AbilitySystem.cpp:23,35,219`)의 기존 패턴을 그대로 따른다. `InitializeViewModels`에서 `InASC->RegisterGenericGameplayTagEvent().AddUObject(this, &UWxNameplateComponent::HandleOwnedTagsChanged)`로 구독하고, 구독 직후 `RefreshVisibility()`를 1회 호출해 초기 표시 상태를 확정한다(이벤트는 변화 시에만 발화).
- **콜백**: `HandleOwnedTagsChanged(const FGameplayTag, int32)`는 인자를 무시하고 `RefreshVisibility()` 재평가만 한다. 데이터 구동 요건이라 구체 태그를 알 필요 없음. 규칙 6에 따라 `Handle` prefix.
- **해제**: `EndPlay` override에서 `CachedASC` 유효 시 `RegisterGenericGameplayTagEvent().RemoveAll(this)` 후 `Super::EndPlay` 호출. `AddUObject`는 weak 바인딩이라 댕글링 위험은 없으나 결정적 정리를 위해 명시 해제.
- **틱**: `RefreshVisibility()` 호출만 제거. 스케일 계산·PC 조회는 현행 유지(PC 캐시는 사용자 지시로 이번 범위 제외).

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |

| `Plugins/WxUI/Source/WxUI/Public/Component/WxNameplateComponent.h` | `EndPlay` override·`HandleOwnedTagsChanged` 콜백 선언 추가, `RefreshVisibility` 주석 정합 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/Component/WxNameplateComponent.cpp` | 틱에서 `RefreshVisibility` 제거, `InitializeViewModels`에서 `RegisterGenericGameplayTagEvent` 구독+초기 1회 평가, `HandleOwnedTagsChanged`·`EndPlay` 정의 추가 | 수정 |

### 구현·결정과 그 이유
- **이벤트 구동화로 매 틱 할당 제거**: 표시 여부는 태그가 바뀔 때만 갱신하면 되므로, 매 틱 `GetOwnedGameplayTags`(힙 할당)을 돌리던 것을 `RegisterGenericGameplayTagEvent` 구독으로 옮겼다. 화면 적 수만큼 프레임당 반복되던 할당이 사라진다.
- **초기 1회 평가**: 이벤트는 변화 시에만 발화하므로, 구독 직후 `RefreshVisibility()`를 한 번 호출해 최초 표시 상태를 확정한다(sibling VM `RefreshOwnedTags` 위치와 동일).
- **`EndPlay`에서 명시 해제**: `AddUObject`는 weak 바인딩이라 댕글링 위험은 없으나, 모듈의 "티커·구독 즉시 정리" 관례에 맞춰 결정적 해제한다.
- **null 가드 미추가**: 유일 호출자 `AWxEnemyCharacter::BeginPlay`가 넘기는 ASC는 `WxCharacterBase` 생성자의 default subobject라 항상 유효. 호출자 없는 방어 가드는 프로젝트 방침상 지양.

### 계획 대비 달라진 점
- PC 조회 캐시는 사용자 지시로 범위에서 제외(틱의 `GetFirstPlayerController`·뷰포인트 조회는 현행 유지). 나머지는 계획대로.

### 후속 과제
- 런타임 확인 미수행(컴파일만 검증): 적 인식/락온 시 표시, 사망 시 숨김이 태그 이벤트로 즉시 갱신되는지, 스케일이 매끄러운지는 인게임 확인 권장.
- 리뷰 문서 `module_review_WxUI.md` 발견 #4는 코드가 수정됐으므로 다음 `/module-review` 재실행 시 해소 반영됨.
