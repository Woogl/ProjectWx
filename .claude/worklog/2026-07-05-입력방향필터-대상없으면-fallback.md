# 입력 방향 필터: 대상 없으면 fallback

## 계획

### 목표
락온 입력 방향 필터(`UWxTargetingFilterTask_InputDirection`)에서, 미는 방향 콘 안에 후보가 하나도 없으면 전부 제외되어 락온이 아무도 못 잡는 문제를 해결한다. 콘 안 후보가 없을 땐 아무도 제외하지 않고 전체를 유지(fallback)하며, 이 fallback은 `EditAnywhere` bool로 켜고 끌 수 있게 하고 기본값은 `true`.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/Private/Targeting/WxTargetingFilterTask_InputDirection.cpp` | `ShouldFilterTarget`에 콘 밖 + fallback 켜짐 시 "집합 내 통과 후보 존재" 스캔 추가, `PassesInputCone` 헬퍼 정의 | 수정 |
| `WxCombat/Public/Targeting/WxTargetingFilterTask_InputDirection.h` | `bKeepAllWhenNoMatch`(EditAnywhere, 기본 true) UPROPERTY, `PassesInputCone` private 헬퍼 선언, 주석 보강 | 수정 |

### 접근 방식
- **집합 수준 판정을 per-target 판정으로 끌어옴**: 엔진 `BasicFilterTemplate::Execute`는 per-target `ShouldFilterTarget` 결과로 하나씩 제거하므로 개별 타겟은 "나를 빼면 집합이 비는지" 모른다. 콘 밖 타겟일 때 결과 집합(`FTargetingDefaultResultsSet::Find`)을 스캔해 콘 안 후보 존재 여부로 제외/유지를 결정한다.
- **판정 순서**: 소스 확보 실패·입력 0 → 미제외(기존). 이 타겟이 콘 안 → 유지. 콘 밖이면 fallback off → 항상 제외(기존 동작), fallback on → 집합에 콘 안 후보 있으면 제외·없으면 전부 유지.
- **콘 판정 헬퍼 분리**: 기존 `Dot ≥ cos(MaxInputAngle)` 식을 `PassesInputCone`로 빼 "이 타겟"과 "집합 스캔"이 동일 로직을 재사용.
- **정합성**: 콘 통과(유지) 타겟은 이 필터가 절대 제거하지 않으므로 `RemoveAtSwap` 순회 중 어느 시점에 스캔해도 "통과 후보 존재" 판정은 불변. 후보 수는 소수라 O(n²) 무시 가능. Execute 미변경으로 `Super::` 규칙 위배 없음.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |

| `WxCombat/Private/Targeting/WxTargetingFilterTask_InputDirection.cpp` | 콘 판정을 `PassesInputCone`로 분리, `ShouldFilterTarget`에서 콘 밖 + fallback 켜짐 시 결과 집합 스캔으로 통과 후보 존재 여부 판정 | 수정 |

### 구현·결정과 그 이유
- **콘 판정 헬퍼 분리**: 기존 인라인 `Dot < cos` 제외식을 `PassesInputCone`(통과=콘 안) 긍정형으로 뒤집어 분리. "이 타겟 통과?"와 "집합에 통과 후보 있나?" 두 곳이 같은 로직을 재사용하고, 제외 판정은 `ShouldFilterTarget` 상위에서 조합.
- **fallback 스캔 위치**: 콘 밖 타겟이고 fallback이 켜졌을 때만 `FTargetingDefaultResultsSet`를 훑는다. 콘 안 타겟은 스캔 전에 유지로 조기 반환하므로 대부분 경로에서 스캔 미발생.
- **ToTarget 0 처리**: 방향을 못 구하는 퇴화 케이스(수직으로 겹침)는 콘 통과로 취급 → 원본의 "그 타겟은 제외 안 함"과 동일 결과 유지.
- **fallback 기본 true**: 사용자 요청. 락온이 미는 방향에 후보가 없다고 끊기지 않는 쪽을 기본값으로.
