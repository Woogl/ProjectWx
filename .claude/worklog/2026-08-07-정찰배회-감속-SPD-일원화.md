# 정찰·배회 감속을 SPD 어트리뷰트 경로로 일원화

## 계획

### 목표
`MaxWalkSpeed` 에 주인이 둘이다 — SPD 어트리뷰트 콜백이 변경마다 절대값을 재계산하는데, 정찰·배회 태스크도 같은 필드를 캐시·복원한다. 그래서 정찰 중 SPD 가 바뀌면 감속이 사라지고, 정찰 중 걸린 버프는 종료 시 낡은 절대값에 덮인다. AI 의 감속도 SPD 를 낮추는 GE 로 표현해 주인을 하나로 되돌린다. `Docs/Programmer/module_review_WxAI.md` 발견 5(🟡) 대응.

### 접근 방식
- **GE 로 표현**: `UWxEffect_MoveSpeedScale` 은 Infinite + SPD 모디파이어 하나이며 크기는 SetByCaller 로 받는다. 구현 형태는 `WxEffect_RecoverResource` 를 따르고, 이동 속도를 GE 로 켜고 끄는 선례는 `WxEffect_Sprint`/`WxAbility_Sprint` 다. 부여·제거만으로 합성과 복원을 GAS 애그리게이터가 계산하고 기존 SPD 콜백이 그대로 반영한다.
- **MultiplyCompound 선택**: `MultiplyAdditive`(구 `Multiplicitive`)는 여러 모디파이어를 더해서 합치므로(엔진 주석: 0.5 두 개 = 0.0) 감속이 겹치면 폰이 멈춘다. 곱해서 합치는 `MultiplyCompound` 가 "배율" 의미와 맞는다.
- **GE 클래스는 에셋에서 지정**: WxAI 는 WxCombat 을 참조할 수 없으므로 태스크는 `TSubclassOf<UGameplayEffect>` 만 노출하고 디자이너가 BT 에디터에서 고른다. `UWxBTDecorator_AttributeRatio` 가 `FGameplayAttribute` 를 같은 방식으로 받는 기존 규약을 따른다.
- **부여·제거 지점**: 진입에서 `MakeOutgoingSpec` → `SetSetByCallerMagnitude` → `ApplyGameplayEffectSpecToSelf` 로 얻은 핸들을 노드 인스턴스에 보관하고, `OnTaskFinished` 에서 핸들이 들고 있는 ASC 로 제거한다. 두 태스크 모두 이미 `bCreateNodeInstance`·`bNotifyTaskFinished` 라 폰별 보관과 전 종료 경로 호출이 보장된다.
- **범위 밖**: `MoveSpeedMultiplier` 의 `ClampMin = 0.0` 은 사용자 지시로 그대로 둔다. 중복 제거도 하지 않는다 — 두 태스크의 부여·제거 블록은 지금도 중복이고, 공통 부모·헬퍼를 새로 만드는 것보다 각자에 두는 편이 읽기 쉽다.

### 구현·결정과 그 이유
- **주인을 SPD 하나로**: 감속을 GE 로 표현하니 합성과 복원이 GAS 애그리게이터 몫이 된다. 정찰 중 버프가 걸려도 배율이 살아 있고, 태스크가 끝나면 GE 만 빠져 버프는 그대로 남는다. 캐시한 절대값을 되돌리던 두 갈래 파손이 원인째 사라진다.
- **MultiplyCompound**: 배율을 더해서 합치는 MultiplyAdditive 는 감속이 겹칠 때 폰을 멈추게 한다. 곱셈 합성이 "배율" 의 의미와 같고 겹침에도 안전하다.
- **GE 클래스는 BT 에셋에서 지정**: WxAI 가 WxCombat 을 참조할 수 없으므로 태스크는 베이스 클래스만 노출한다. 어트리뷰트를 같은 방식으로 받는 `UWxBTDecorator_AttributeRatio` 의 기존 규약과 동일하고, 미지정이 눈에 띄도록 노드 설명에 표시했다.
- **핸들이 ASC 를 안다**: 제거할 때 폰에서 ASC 를 다시 찾지 않고 `FActiveGameplayEffectHandle` 이 들고 있는 약참조를 쓴다. 폰이 죽거나 파괴된 뒤의 종료 경로에서도 안전하다.

## 검증

- **컴파일**: WxEditor(Development) 빌드 성공.
- **에셋**: 9개 노드 모두 `MoveSpeedEffect` 지정 후 되읽어 확인, 3개 에셋 저장.
- **PIE 실동작**: 적을 플레이어 앞으로 옮겨 전투에 넣고 배회(strafe) 중 상태를 샘플링했다. 감속 구간에서 SPD 0.3 · `WxEffect_MoveSpeedScale` 활성 · MaxWalkSpeed 120(=400×0.3), 태스크 종료 구간에서 효과 없음 · SPD 1 · MaxWalkSpeed 400 으로 되돌아왔다. 부여 → SPD → 콜백 → 속도, 그리고 제거 → 원복까지 한 줄로 확인됐다.
- 정찰 중 SPD 버프가 겹치는 조합은 실측하지 않았다(치트로 적 SPD 를 바꿀 경로가 없다). 합성은 GAS 애그리게이터가 계산하므로 메커니즘상 성립한다.

## 후속 — 스프린트를 같은 GE 로 통합

### 계획
- **목표**: 이동 속도를 바꾸는 GE 가 둘(가산 `WxEffect_Sprint`, 배율 `WxEffect_MoveSpeedScale`)로 갈리지 않게 통합한다.
- **수정 범위**: `WxAbility_Sprint.h`·`.cpp` 수정, `WxEffect_Sprint.h`·`.cpp` 삭제.
- **접근**: 어빌리티가 배율(`SprintSpeedScale`)을 SetByCaller 로 실어 공용 GE 를 부여한다. GE 클래스 프로퍼티는 없앤다 — WxCombat 안에서 클래스를 직접 볼 수 있어 간접이 필요 없고, 없애면 `GA_Sprint` 에 직렬화돼 있던 옛 클래스 참조도 함께 사라진다.

### 완료
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Ability/WxAbility_Sprint.h`·`Private/.../WxAbility_Sprint.cpp` | `SprintEffectClass` → `SprintSpeedScale`(1.5), 공용 GE 를 SetByCaller 로 부여 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Effect/WxEffect_Sprint.h`·`Private/.../WxEffect_Sprint.cpp` | 공용 GE 로 대체되어 삭제 | 삭제 |

- **값은 안 바뀐다**: SPD 를 건드리는 다른 소스가 없어 기본 SPD 1.0 에서 가산 +0.5 와 배율 ×1.5 의 결과가 같다. 다른 SPD 변경이 함께 걸릴 때만 갈리고, 그때는 배율 쪽이 의도에 맞다(SPD 2.0 에서 스프린트가 +25% 가 아니라 +50%).
- **덤으로 죽은 노브 하나 제거**: 옛 `SprintSpeedBonus` 는 생성자에서 모디파이어를 만들 때만 읽혀, BP 에서 값을 바꿔도 효과가 없었다. SetByCaller 로 옮겨 실제로 편집 가능한 값이 됐다.
- **에셋 후속 없음**: 프로퍼티 자체가 사라져 `GA_Sprint` 의 옛 값은 로드 시 무시된다. 에디터에서 확인한 결과 새 `SprintSpeedScale` 이 1.5 로 읽히고 삭제된 클래스에 대한 참조도 남아 있지 않다.
- **검증**: 빌드 성공. 스프린트 PIE 실주행은 미실시(입력 주도 어빌리티라 자동화 비용이 커서 생략).
