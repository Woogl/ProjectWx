# 인디케이터 대상 언로드 시 기록 좌표로 폴백

## 계획

### 목표

`Mark Indicator` 는 UOL 로 지정한 액터를 해석해 그 루트 컴포넌트에 인디케이터를 건다. 대상이 월드 파티션에서 언로드돼 있으면 해석이 실패해 지금은 인디케이터를 아예 걸지 않는데, 오픈월드 퀘스트 마커는 정확히 그 상황(멀어서 아직 스트리밍되지 않은 목표)에서 가장 필요하다. 언로드 동안 쓸 월드 좌표를 태스크가 들고 있게 하고, 그 좌표는 에디터에서 UOL 을 지정하는 순간 자동으로 기록한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxUI/.../Indicator/WxIndicatorDescriptor.h·.cpp` | 좌표 원점 멤버·게터와 좌표를 받는 `Initialize` 오버로드 | 수정 |
| `WxUI/.../Indicator/WxIndicatorManagerComponent.h·.cpp` | 좌표를 받는 `AddIndicator` 오버로드, `ProjectIndicator` 의 원점 선택 | 수정 |
| `WxUI/.../Indicator/WxStateTreeTask_MarkIndicator.h` | 인스턴스 데이터에 `TargetLocation` 추가, 에디터 훅 선언 | 수정 |
| `WxUI/.../Indicator/WxStateTreeTask_MarkIndicator.cpp` | UOL 지정 시 좌표 기록, `RefreshIndicator` 를 폴백 포함으로 재구성 | 수정 |

### 접근 방식

- **좌표 등록 경로를 인디케이터 계층에 연다**: 등록증이 지금은 컴포넌트 전용이라 좌표만으로 걸 수 없다. 투영 원점을 고르는 곳은 `ProjectIndicator` 한 곳이므로 거기서 컴포넌트가 없으면 기록 좌표를 쓰게 한다. 좌표 모드 여부는 `TargetComponent == nullptr` 로 파생 판별하고 별도 플래그를 두지 않는다.
- **좌표 기록은 엔진 훅으로**: `FStateTreeNodeBase::PostEditInstanceDataChangeChainProperty` 가 인스턴스 데이터 프로퍼티 변경 때 불린다. 우리 UOL 픽커가 `NotifyPostChange` 를 부르므로 이 훅까지 도달한다. `Target` 이 바뀌면 에디터 월드에서 해석해 액터 위치를 적고, 빈 로케이터·미해석이면 0 으로 되돌려 낡은 좌표를 남기지 않는다.
- **등록 갱신은 "원하는 대상"을 먼저 정한다**: 해석되면 루트 컴포넌트가, 안 되면 기록 좌표가 원하는 대상이다. 현재 등록증이 그것과 다를 때만 갈아 끼운다 — 폴백으로 걸린 뒤 매 틱 재등록하지 않고, 스트리밍 인 되는 순간 컴포넌트 등록으로 승격된다.
- **파괴된 대상도 같은 경로**: 해석 실패라는 점이 같아 구분하지 않는다. 마커가 사라지는 것보다 낫다.

### 구현·결정과 그 이유

- **등록증의 모드를 파생으로 읽는다**: 좌표 대역인지 컴포넌트 추적인지를 `TargetComponent == nullptr` 로 가른다. 별도 플래그를 두면 등록 시점과 투영 시점 두 곳에서 같은 사실을 따로 관리하게 된다.
- **"원하는 곳"을 먼저 정하고 비교한다**: 종전엔 "등록증이 살아 있나"만 봤는데, 폴백이 생기면 살아 있어도 걸 곳이 바뀔 수 있다(언로드 → 로드). 원하는 대상을 먼저 구해 현재 등록증과 비교하는 형태라야 매 틱 재등록 없이 승격·강등이 모두 성립한다.
- **좌표 기록은 엔진 훅에 얹었다**: `PostEditInstanceDataChangeChainProperty` 는 인스턴스 데이터 변경마다 불리고, 우리 UOL 픽커가 `NotifyPostChange` 를 부르므로 그대로 도달한다. 별도의 에디터 버튼이나 커스터마이제이션을 만들 이유가 없었다.
- **지정을 지우면 좌표도 지운다**: 앞 대상의 좌표가 남으면 엉뚱한 곳을 가리키는데, 그 실수는 실행 전에는 보이지 않는다.
- **빈 로케이터는 대역도 없다**: 좌표가 기록될 일 자체가 없으므로 등록을 시도하지 않는다. 이 가드가 없으면 미지정 노드가 월드 원점에 마커를 띄운다.
- **파괴된 대상도 같은 대역으로**: 해석 실패라는 점이 언로드와 같아 구분하지 않았다. 마커가 조용히 사라지는 쪽이 더 나쁘다.

### 후속 과제

- **PIE 실동작 미검증**: 목표가 스트리밍 아웃된 거리에서 마커가 가장자리에 뜨는지, 가까이 가 로드될 때 마커가 튀지 않고 이어지는지 확인이 남았다.
- **기존 에셋의 좌표가 비어 있다**: `ST_QuestStep_MoveToTarget`·`ST_QuestStep_InteractTarget` 의 Mark Indicator 는 `TargetLocation` 이 0 인 채로 로드된다. UOL 을 다시 지정하거나 좌표를 직접 넣기 전까지는 언로드 시 월드 원점을 가리킨다.
- **좌표 신선도**: 대상 액터를 레벨에서 옮기면 기록된 좌표는 그대로 남는다. 재지정이 유일한 갱신 경로다 — 어긋남이 잦으면 컴파일 시 재기록이나 경고를 검토한다.
