# UOL 픽커 클래스 제한 — 스포너 지정 필드에서 WxSpawner 만 집히게

## 계획

### 목표
스포너 지정 UOL 필드(TriggerSpawnersByLocator·WaitSpawnersKilled 의 Spawners, MarkIndicator 의 Target)의 픽커가 모든 액터를 나열해 오지정 여지가 있다. 엔진 표준 확장 경로(커스텀 로케이터 에디터 등록 + `AllowedClasses` 메타 관례)로 픽커 자체를 제한한다. 이후로는 어떤 UOL 필드든 메타 한 줄로 클래스 제한을 걸 수 있게 된다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxEditor/WxActorLocatorEditor.h/.cpp` | 스톡 액터 로케이터 에디터 동작 재현 + `AllowedClasses` 메타 기반 픽커 필터 | 신규 |
| `Source/WxEditor/WxEditor.cpp`, `WxEditor.Build.cs` | "Actor" 이름으로 교체 등록(스톡 등록 선행 보장), UOL 모듈 의존성 추가 | 수정 |
| `WxSpawnerStateTreeNodes.h`(WxWorld), `WxQuestStateTreeNodes.h`(WxQuest) | 세 필드에 `AllowedClasses = "/Script/WxWorld.WxSpawner"` 메타 추가 | 수정 |
| `/Game/Quest/ST_Quest` | Step1 MarkIndicator 대상을 캠프 TargetPoint→캠프 스포너로 재지정(MCP) | 수정(MCP) |

### 접근 방식
- **"Actor" 이름 교체 등록이 필수인 이유**: 현재 값의 표시 에디터를 프래그먼트 타입의 `PrimaryEditorType`("Actor")으로 조회하므로, `AllowedLocators` 로 별명 에디터만 노출하면 기존 저장값 표시가 깨진다. 같은 이름으로 덮어쓰고 메타가 있을 때만 필터를 걸면 메타 없는 모든 용처는 순정 동작 그대로다.
- **재현 구현**: 스톡 `FActorLocatorEditor` 가 엔진 Private 라 서브클래스 불가 → `ILocatorFragmentEditor`(공개)를 구현해 동작을 재현하고, `MakeEditUI` 에서 `Customization->GetProperty()` 의 `AllowedClasses` 메타(콤마 구분 클래스 경로, `GetOwnerProperty()` 경유로 배열 원소 대응)를 IsA 필터로 만든다. 클래스 해석은 경로 문자열이라 WxEditor·WxQuest 가 WxWorld 를 링크하지 않는다.
- **한계**: 아웃라이너 드래그드롭 경로는 API 에 프로퍼티 정보가 없어 필터 불가 — 노드 타이틀 라벨·런타임 경고로 드러난다. 컴파일 검증 백스톱은 보류(원하면 후속).

### 구현·결정과 그 이유
- 계획의 코드 구현은 완료. 그러나 검증 중 **엔진 제한을 발견**: ST 노드 인스턴스 데이터의 **맨(단일) `FUniversalObjectLocator` 필드는 디테일 패널에 값 위젯이 아예 생성되지 않는다**(라벨+바인딩 콤보만 렌더). 같은 인스턴스 데이터라도 `TArray<FUniversalObjectLocator>` 원소는 정상 표시·편집된다(동일 세션 실측). 원흉 추정 경로: FInstancedStructDataDetails 의 비커스터마이즈드 구조체 자식 추가 경로에서 자식의 타입 커스터마이제이션이 적용되지 않음(InstancedStructDetails.cpp — 커스터마이즈드 구조체는 "supports IPropertyTypeCustomization" 인 AddChildStructure 로 라우팅한다는 주석이 방증).
- **차등 실험으로 자사 코드 무죄 입증**: 교체 등록을 끈 빌드에서도 증상 동일 → 스톡만으로도 재현. DebugGame/Development 구성 무관.
- 픽커가 아예 없으니 단일 필드에선 AllowedClasses 필터도 무의미 — 배열 필드(Trigger·Wait 의 Spawners)에서만 실효.

### 계획 대비 달라진 점
- "픽커에서 스포너만 나열" 실측은 배열 필드로만 가능(단일 필드는 엔진 제한으로 픽커 자체 부재). MarkIndicator 재지정은 픽커 대신 MCP 텍스트 기입으로 수행.

### 후속 과제
- 단일 Target 필드의 픽커 복구 방향 결정 대기: ① 필드를 배열화(검증된 경로, 단일 의미 흐려짐) ② 인스턴스 데이터 구조체에 패스스루 타입 커스터마이제이션 등록(엔진 주석이 가리키는 탈출구, 미검증) ③ 현행 유지(값은 MCP 기입, 표시는 노드 타이틀 라벨).
- 배열 필드에서 AllowedClasses 필터 대화형 실측(픽커 목록에 스포너만 나오는지) 미완.
