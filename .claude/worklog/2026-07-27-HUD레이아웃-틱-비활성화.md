# HUD 레이아웃과 기본 게임 레이아웃의 틱 비활성화

## 계획

### 목표
`UWxHUDLayout`·`UWxPrimaryGameLayout` 을 상속한 WBP 들이 매 프레임 네이티브 틱을 도는데, 두 클래스 모두 `NativeTick` 을 오버라이드하지 않아 하는 일이 없다. 강제 틱 플래그를 꺼서 낭비를 없앤다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../Public/Widget/WxHUDLayout.h` | `UCLASS` 에 `meta = (DisableNativeTick)` 추가 | 수정 |
| `Plugins/WxUI/.../Public/System/WxPrimaryGameLayout.h` | 위와 동일 | 수정 |
| `/WxUI/WBP_PrimaryGameLayout` | 재컴파일·저장 | 수정(MCP) |
| `/Game/UI/Widget/WBP_GameHUDBase`, `WBP_GameHUD` | 재컴파일·저장 | 수정(MCP) |

### 접근 방식
- **원인**: UMG 는 틱 빈도가 기본값(Auto)일 때 생성 클래스의 "네이티브 부모가 틱을 필요로 한다"는 플래그만으로 틱을 켠다. 그 플래그는 WBP 컴파일 시 네이티브 부모에 `DisableNativeTick` 메타데이터가 없으면 참이 된다. 이 조회는 계층을 거슬러 올라가지 않고 UHT 도 클래스 메타데이터를 자식에게 물려주지 않으므로, CommonUI 베이스에 붙어 있어도 우리 파생 클래스에는 없는 것으로 취급된다.
- **수단**: 그래서 파생 클래스마다 메타데이터를 직접 붙인다. 엔진이 이 목적으로 문서화한 표준 수단이고, 이 프로젝트의 탭 버튼·탭 리스트가 이미 같은 방식을 쓴다.
- **틱 빈도를 Never 로 두지 않는 이유**: 해당 멤버는 `UUserWidget` 의 private 이라 C++ 서브클래스가 못 건드리고, 에셋 기본값으로 지정하면 에셋별이라 새 레이아웃에서 빠뜨리기 쉽다. 무엇보다 Never 는 애니메이션과 Latent 액션까지 함께 죽여 과하다. Auto 를 유지하면 실제로 틱이 필요한 사유가 생겼을 때 자동으로 되살아난다.
- **에셋 재저장이 필요한 이유**: 그 플래그는 생성 클래스에 직렬화되어 WBP 에 저장된다. C++ 메타데이터만 바꾸면 이미 저장된 값이 그대로이므로 WBP 를 한 번 컴파일해야 반영된다. 자식 WBP 도 자기 생성 클래스를 가지므로 함께 대상이다.

### 구현·결정과 그 이유
- **모든 커스텀 위젯 베이스에 붙였다**: 메타데이터가 상속되지 않는 것이 원인이므로, 두 클래스만 고치면 나머지 베이스를 상속한 WBP 는 그대로 틱을 돈다. 위젯 베이스 전부를 훑어 `NativeTick` 을 오버라이드하는 클래스가 하나도 없음을 확인하고 일괄 적용했다. 탭 버튼·탭 리스트는 이미 붙어 있었다.
- **위젯이 아닌 클래스는 대상이 아니다**: 이 메타데이터는 WBP 의 네이티브 부모를 판정할 때만 쓰이므로 `UUserWidget` 계열에만 의미가 있다. `UWidget` 파생(이미지 등)과 외부 샘플 플러그인의 위젯은 건드리지 않았다.

### 계획 대비 달라진 점
- **적용 범위 확대(사용자 요청)**: 계획은 HUD 레이아웃과 기본 게임 레이아웃 둘이었으나, 작업 중 커스텀 UI 전체로 넓혀 달라는 요청을 받아 위젯 베이스 7 개에 적용했다.
- **WBP 재컴파일·저장은 불필요했다**: 계획은 그 플래그가 에셋에 직렬화되므로 대상 WBP 14 개를 다시 컴파일해야 한다고 봤다. 틀렸다. 에디터는 블루프린트를 로드할 때마다 컴파일 관리자에 등록해 다시 컴파일하고, 그 과정에서 플래그를 현재 C++ 메타데이터로 재계산한다. 저장된 값은 로드 시 덮어써지므로 에셋을 건드릴 이유가 없다. 에셋 수정 항목을 전부 취소했다.

### 후속 과제
- **PIE 눈 확인 미실시**: 다른 작업 세션이 DebugGame 구성 에디터를 점유 중이라 화면 확인을 하지 못했다. 빌드 통과와 생성 코드에 메타데이터가 실린 것(위젯 클래스 9 개 전부)까지 확인했다. 다음 에디터 실행 때 HUD·메뉴·팝업·인디케이터 표시가 그대로인지 한 번 볼 것.
