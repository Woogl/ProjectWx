# 아이콘 표시를 일반 Image 바인딩으로 통일하고 WxLazyImage 제거

## 계획

### 목표
아이콘 비동기 로드가 "위젯이 로드"(`VM_Item` → `UWxLazyImage`)와 "VM 이 로드"(`VM_Ability`·`VM_Effect` → 일반 `Image`) 두 갈래로 갈라져 있다. 후자로 통일해 WBP 가 특수 위젯 클래스를 알 필요 없게 만들고, 존재 이유가 사라지는 `UWxLazyImage` 를 제거한다. 다만 후자는 각 VM 이 수기 구현한 상태라, 공통부를 `UWxViewModel` 베이스로 올리고 기존 2개도 이관한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../MVVM/WxViewModel.h` / `.cpp` | `FWxTextureRequest` + `RequestTextureAsync`/`ApplyLoadedTexture`/`HandleTextureLoaded`/`TextureRequests` 추가, `Deinitialize` 에서 전체 취소 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Ability.h` / `.cpp` | `PendingIcon`·`IconStreamHandle`·`HandleIconLoaded` 제거, `SetIconSoft` 축약, `ApplyLoadedTexture` 오버라이드 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Effect.h` / `.cpp` | 동일. `Initialize` 의 인라인 3분기를 `RequestTextureAsync` 한 줄로 | 수정 |
| `Source/WxGame/MVVM/WxViewModel_Item.h` / `.cpp` | `Icon` 을 `TObjectPtr<UTexture2D>` 로, 요청/수신 경로 전환 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Selection.h` / `.cpp` | `Icon` 을 하드로. `SetSelection` 은 소프트 인자 유지(호출부 무변경) | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Character.h` / `.cpp` | `Portrait` 를 하드로 | 수정 |

`UWxLazyImage` 클래스 삭제는 이번 범위에서 제외한다 — 에셋 4개가 아직 위젯 노드로 들고 있어, 먼저 지우면 노드와 레이아웃이 날아간다.

### 접근 방식
- **필드 키로 요청 슬롯 구분**: `RequestTextureAsync(FName FieldName, Soft)` / `ApplyLoadedTexture(FName, UTexture2D*)` 로 두고 내부는 `TMap<FName, FWxTextureRequest>`. 취소가 같은 키의 이전 요청만 대상이라, 한 VM 이 텍스처를 2개 이상 쓰게 돼도 서로 취소하지 않는다. 완료 콜백은 `CreateUObject` 페이로드 인자로 슬롯을 식별해 람다가 필요 없다.
- **베이스가 수명 책임**: `Deinitialize()` 가 모든 슬롯을 취소하고 맵을 비운다. 파생은 `Super::Deinitialize()` 만 부르면 되고 각자의 취소 블록을 지운다.
- **데이터 소스는 소프트 유지**: `UWxItemDefinition::Icon`·`FWxCharacterUIData::Portrait` 등은 그대로 둔다. 에셋이 텍스처를 강참조하지 않는 이점은 거기서 나오고, 바뀌는 것은 VM 이 UMG 에 무엇을 노출하느냐뿐이다.
- **다중 로드 안전성**: 서로 다른 VM 인스턴스는 각자 맵을 가져 독립이다. 같은 텍스처를 여러 핸들이 요청하면 로드는 1회로 합쳐지고, 취소된 요청이 뒤늦게 발화하지도 않는다(`CancelHandle` 이 지연 콜백 큐까지 취소).

### 구현·결정과 그 이유
- **필드 키로 요청 슬롯 구분**: 단일 슬롯이면 한 VM 이 텍스처를 2개 쓰게 되는 순간 둘째 요청이 첫째를 조용히 취소하고, `ApplyLoadedTexture(UTexture2D*)` 만으로는 어느 결과인지 구분할 방법도 없다. 지금은 모든 VM 이 텍스처 1개지만 함정을 남기지 않으려고 `TMap<FName, FWxTextureRequest>` 로 갔다. 비용은 FName 인자 하나와 작은 맵 하나뿐이다.
- **완료 콜백에 페이로드 인자**: `CreateUObject(this, &UWxViewModel::HandleTextureLoaded, FieldName)` 로 슬롯을 식별한다. 람다 없이 키를 나른다.
- **베이스가 수명 책임**: `Deinitialize()` 가 모든 슬롯을 취소하므로 파생 VM 3곳에서 취소 블록이 사라졌다. 파생은 `Super::Deinitialize()` 만 부르면 된다.
- **`Selection::SetSelection` 시그니처 유지**: 인자는 Soft 로 두고 내부에서만 요청으로 바꿨다. 호출부(`WxPlayerController::PushSelectionToViewModel`)와 도메인 브리지 계약이 그대로 유지된다.
- **데이터 소스는 소프트 유지**: `UWxItemDefinition::Icon`·`FWxCharacterUIData::Portrait` 등은 손대지 않았다. 에셋이 텍스처를 강참조하지 않는 이점이 거기서 나오고, 이번에 바뀐 것은 VM 이 UMG 에 무엇을 노출하느냐뿐이다.
