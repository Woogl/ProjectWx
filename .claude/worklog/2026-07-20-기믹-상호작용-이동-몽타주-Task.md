# 기믹 StateTree: 상호작용 플레이어를 대상 앞으로 이동 + (옵션)몽타주 Task

## 계획

### 목표
상호작용한 플레이어 캐릭터를 상호작용 대상(기믹) 앞의 상대 위치로 이동시키고, 도착 후 옵션 몽타주를 재생하며, 이동·몽타주가 끝나면 완료되는 재사용 기믹 StateTree Task를 만든다. 직전 커밋에서 상호작용 어빌리티의 몽타주 연출을 제거하며 "모션·연출은 대상 StateTree Task로 이관"한다고 한 후속 작업이다.

### 접근 방식
- **배관**: base `AWxGimmick`가 상호작용한 플레이어(=아바타 캐릭터)를 복제 프로퍼티로 보관. instigator는 권위 측 `OnInteracted`에서만 오므로, 자식이 `HandleInteracted`에서 `CommitGimmickState` 직전에 `SetInteractingCharacter`를 호출(권위 쓰기→복제→클라 추종). ST 에셋은 Task의 `InteractingCharacter` 입력을 이 프로퍼티로 바인딩(기존 컴포넌트 바인딩과 동일 패턴). 이번 범위는 배관+Task까지, 특정 기믹 배선은 후속.
- **MP 이동**: 목표 = 앵커(또는 오너) 트랜스폼 ∘ 상대오프셋 이라 모든 머신에서 동일 → 각 피어 로컬 보간으로 수렴(복제 미러 불필요, `Wx Component Move` 철학). 진입 시 `StopMovementImmediately()`로 CMC 잔여 속도 제거(입력 차단은 `Wx Enable Player Input`이 별도 담당).
- **회전**: 상대 회전으로 목표 yaw 지정, 이동과 함께 등속 보간(`bAlignRotation`으로 on/off).
- **몽타주**: 각 피어가 로컬로 `AnimInstance->Montage_Play` 호출 후 `Montage_IsPlaying` 폴링(복제형 `PlayAnimMontage` 아님) — 중복 재생 없이 `Wx Play Animation`과 동형.
- **초기/복원 진입**: 기존 노드처럼 `IsInitialOrRestoreEntry`면 즉시 `Succeeded`(발동 순간에만 동작; 복원 시 `InteractingCharacter`는 비영속이라 비어 있음).

### 구현·결정과 그 이유
- **배관은 base 1점**: 상호작용 instigator(아바타 캐릭터)는 권위 측 `OnInteracted`에서만 오므로 base `AWxGimmick`에 권위 전용 `SetInteractingCharacter`로 받아 복제(`DOREPLIFETIME`, SaveGame 아님). ST 에셋이 Task 입력 `InteractingCharacter`를 이 프로퍼티로 바인딩(기존 컴포넌트 바인딩과 동일). 비캐릭터 상호작용은 캐스트 실패로 null → Task no-op.
- **이동은 전 피어 로컬 보간**: 목표=앵커(또는 오너)∘상대오프셋이라 모든 머신에서 동일 → 각자 자기 사본을 `VInterpConstantTo`로 보간해도 수렴(복제 미러 불필요). 진입 시 `StopMovementImmediately()`로 CMC 잔여 속도 제거(입력 차단은 `Wx Enable Player Input` 담당). 회전은 `bAlignRotation` 시 `FixedTurn`으로 yaw 등속 정렬 후 도달 시 스냅.
- **몽타주는 로컬 재생·폴링**: 복제형 `PlayAnimMontage`가 아니라 각 머신이 `AnimInstance->Montage_Play` 후 `Montage_IsPlaying` 폴링(`Wx Play Animation` 동형) — 모든 피어가 `InteractingCharacter`를 복제로 알아 중복 재생이 없다.
- **초기/복원 진입 스킵**: 두 Task 모두 `IsInitialOrRestoreEntry`면 즉시 `Succeeded`(발동 순간에만 동작; 복원 시 `InteractingCharacter`는 비영속이라 null).
- **이동 중 입력 차단(이동+어빌리티+점프, 카메라 유지)**: Move Task가 라이브 진입(초기/복원·null 검사 통과 후, 스냅·이동 두 경로 모두)에서 로컬 컨트롤 인스턴스에 대해 차단을 걸고 `ExitState`에서 해제한다.
  - **이동**: `AController::SetIgnoreMoveInput(true)`. `AddMovementInput`(이동)과 `AddControllerYaw/PitchInput`(카메라 look)이 `IsMoveInputIgnored()`/`IsLookInputIgnored()` 로 분리돼 있어 카메라는 유지.
  - **어빌리티+점프**: `IAbilitySystemInterface`로 얻은 ASC에 `BlockAbilitiesWithTags(Ability)`. 액션 어빌리티가 연출 중 서로를 막는 것과 동일한 **GAS 순정 관례**(루트 `Ability` 태그 차단)이며, `AWxCharacterBase::CanJumpInternal_Implementation`이 이미 `AreAbilityTagsBlocked(Ability)`로 점프를 게이트하므로 **점프도 자동 차단**된다(캐릭터/어빌리티/태그 신규 변경 0).
  - **모듈**: WxWorld는 이미 `GameplayAbilities`·`WxCore` 의존이라 `UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent`·`WxGameplayTags::Ability` 사용에 WxGame 의존이 불필요.
  - **로컬 전용**: 예측이 발동을 게이트하므로 `IsLocallyControlled()` 머신에서만 차단(소유 클라가 막으면 서버로 활성화가 전송되지 않음). 신규 플래그 변수 없이 컨트롤러/ASC 내부 카운터 사용. 스냅·이동 진입 모두에서 걸어 `ExitState` 해제와 짝을 맞춘다(초기/복원 진입은 차단 전 완료하며 그땐 `InteractingCharacter`가 대개 null이라 `ExitState` 가드로 스킵).

### 계획 대비 달라진 점
- **단일 Task → 두 Task로 분리(사용자 요청)**: 원 계획은 이동+몽타주를 한 Task(`Move Interactor To Target`, 옵션 몽타주 포함)로 했으나, 사용자가 이동과 몽타주 재생을 별도 Task로 나누자고 하여 `Wx Move Interactor To Target`(이동·응시 전용)과 `Wx Play Interactor Montage`(몽타주 전용)로 분리했다. 기존 단일 책임 태스크 철학과 더 일관되고, "이동 후 몽타주"는 ST에서 상태를 나눠(이동 상태 → 몽타주 상태, OnCompleted 전이) 조립한다. base 배관·MP 처리 방식은 계획대로.

### 후속 과제
- **실제 사용 기믹 배선(범위 밖)**: 대상 기믹 `HandleInteracted`에서 `SetInteractingCharacter(InstigatorActor)` 호출 + ST 에셋에 두 Task를 상태로 배치·바인딩. 이후 멀티플레이(리슨호스트+클라)에서 이동·응시·몽타주·수렴 런타임 점검.
- **회전 CMC 설정 의존**: 캐릭터가 `bUseControllerRotationYaw=true`면 `SetActorRotation`이 매 틱 컨트롤러 yaw로 덮일 수 있다(현 플레이어는 `bOrientRotationToMovement` 기반이라 무입력·정지 시 무해). 문제 시 `Wx TurnAround`처럼 이동 중 회전 소스 게이팅을 추가 검토.
