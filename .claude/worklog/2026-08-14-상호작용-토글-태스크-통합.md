# 기믹·NPC 상호작용 토글 태스크 통합

## 계획

### 목표
같은 일을 하는 두 태스크(`Enable Interaction`·`Enable Npc Interaction`)를 하나로 합쳐, 기믹이든 NPC든 "이 상태에서 이 대상이 상호작용 가능한가"를 한 노드로 선언하게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../WxInteractable.h/.cpp` | 토글 진입점 `SetInteractionEnabled`(기본 무동작)과 액터로 구현체를 찾는 `Find` 오버로드 추가 | 수정 |
| `Plugins/WxWorld/.../Interaction/WxStateTreeTask_EnableInteraction.h/.cpp` | 통합 태스크 — UOL 액터 지정·상주 재적용 갈래 추가, `Gimmick/` 에서 이동 | 이동·수정 |
| `Plugins/WxDialogue/.../WxDialogueComponent.h/.cpp` | 자체 토글 함수를 계약 오버라이드로 전환 | 수정 |
| `Plugins/WxDialogue/.../WxStateTreeTask_EnableNpcInteraction.h/.cpp` | 삭제 | 삭제 |
| `Plugins/WxWorld/README.md`, `Plugins/WxDialogue/README.md` | 태스크 목록 갱신 | 수정 |
| `/Game/Quest/Steps/ST_QuestStep_InteractTarget` | 구 노드 → 통합 노드로 교체, 기존 `Npc` 루트 파라미터에 바인딩 | 수정(에셋) |

### 접근 방식
- **타입은 WxWorld 쪽을 살린다**: 기믹 에셋 4개(Door·Elevator·TreasureChest·CheckPoint)가 이미 이 타입을 쓰고 전이가 노드의 발행자를 지목하므로, 타입을 유지하면 그쪽은 손댈 것이 없다. 재저작은 퀘스트 스텝의 노드 하나로 끝난다. 기존 필드명도 그대로 두어 값이 보존된다.
- **대상 지정은 둘 중 하나**: `TargetMesh`(바인딩)는 한 액터에 영역이 여럿인 기믹이 자기 트리에서 지목하고, `Target`(UOL 액터)은 외부 트리(퀘스트)가 배치 대상을 지목해 그 대상의 단일 영역을 토글한다. 기믹 에셋은 공유 자산이라 UOL 로 자기를 가리킬 수 없고, 퀘스트 트리는 대상 액터의 컴포넌트를 바인딩할 길이 없어 두 방식이 모두 필요하다.
- **동작도 지정 방식이 가른다**: 메시 지정은 진입 시 1회 적용 후 `Succeeded`(현행 기믹 그대로), UOL 지정은 `Running` 으로 상주하며 대상이 새로 로드됐을 때만 재적용한다(스트리밍으로 콜리전이 레벨 값으로 되돌아가는 것을 복구). 완료 판정 기본값만 제외로 내려 새 노드가 형제 대기 태스크를 막지 않게 하고, 기존 기믹 노드는 에셋에 저장된 값이 이겨 영향이 없다.
- **모듈 경계는 계약으로 넘는다**: WxWorld 는 WxDialogue 를 볼 수 없으므로 `IWxInteractable` 에 토글 진입점을 하나 추가한다 — 활성을 답하는 `IsInteractionMeshActive` 의 짝이며, 켜고 끄는 수단은 구현체가 정한다(대화 상대는 영역 메시 콜리전). 토글이 없는 대상(픽업·적)은 구현하지 않는다.
- **기믹만 구체 타입으로 부른다**: 기믹 영역은 프롬프트와 ST 발행자까지 함께 담아야 하는데, 그것을 계약에 실으면 WxCore 가 StateTree 를 떠안는다. 같은 모듈이므로 기믹 컴포넌트만 직접 호출한다.
- **에셋 편집은 두 번에**: 구 노드 제거는 타입이 살아 있는 지금(재기동 전), 통합 노드 추가는 새 필드가 등록된 뒤(빌드·재기동 후)에 한다. 루트 파라미터는 건드리지 않아 `ST_Quest_Main1` 의 링크 오버라이드가 유지된다.

### 구현·결정과 그 이유
- **타입을 WxWorld 쪽으로 살렸다**: 기믹 에셋 4종이 쓰는 타입을 유지하면 그쪽 노드·전이·프롬프트가 그대로 살아난다. 재저작은 퀘스트 스텝 하나로 끝났고, 실제로 문 에셋의 노드가 프롬프트까지 보존한 채 새 필드만 기본값으로 붙었다.
- **걸고 나면 끝낸다**: 두 갈래 모두 토글을 걸면 Succeeded 로 완료한다. 액터 갈래도 상주하지 않으며, 대상이 아직 스트리밍 인 되지 않은 동안만 Running 으로 남아 다음 틱에 다시 시도한다(엔진은 완료한 태스크를 더 틱하지 않으므로 그 뒤로는 비용이 0). 완료를 제대로 내는 태스크가 됐으므로 완료 판정 제외는 코드에서 걷어내고 엔진 기본값을 따른다 — 대기 태스크와 섞이는 상태는 노드가 아니라 상태의 TasksCompletion=All 이 지킨다(퀘스트 스텝은 이미 All). 기존 기믹 노드는 에셋에 저장된 값이 이겨 완료 거동이 그대로다.
- **계약은 대상 단위로만 넓혔다**: 활성을 답하는 판정의 짝이므로 계약에 두되, 영역을 가르는 인자는 두지 않았다 — 그 인자를 채울 호출자가 없다. 영역 단위(프롬프트·발행자 동반)는 계약에 StateTree 를 들이지 않으려고 같은 모듈의 기믹 컴포넌트로 직접 부른다.
- **기믹의 영역 토글을 개명**: 이름이 같으면 파생 클래스가 계약의 새 가상 함수를 가려 컴파일 경고(C4263/C4264)가 난다. 영역 단위임이 이름에 드러나 부르는 쪽도 헷갈리지 않는다.
- **진단은 잘못된 조립만**: 상호작용 대상이 아닌 액터를 지목한 경우만 진입 시 1회 경고한다. 빈 지정(옵션 미사용)과 미해석(스트리밍 아웃)은 정상 상황이라 조용히 대기한다.

### 계획 대비 달라진 점
- 완료 판정은 태스크 전부가 엔진 순정 값을 쓰도록 통일했다(사용자 지시) — 코드에서 이 플래그를 건드리는 태스크가 하나도 남지 않았다. 완료를 낼 수 없는 태스크는 `Mark Indicator`(표시를 유지하며 매 틱 재해석)와 `Spawn Actor`(주기 스폰) 둘뿐이었는데, 후자는 쓰지 않기로 해 제거했고 전자는 판정에서 뺄지를 에셋이 정한다.
- 액터 갈래를 상주(영원한 Running)에서 "걸면 완료"로 바꿨다(사용자 지시). 스트리밍 재로드로 토글이 되돌아가는 것까지 지키려던 재적용 유지를 접었고, 그 판단에 쓰던 적용 기록 필드도 함께 사라졌다. 대신 대상이 아직 로드되지 않은 동안만 기다리므로 진입 시점 언로드는 여전히 놓치지 않는다.
- 기믹 컴포넌트의 영역 토글 개명이 추가됐다(계약과 이름이 겹쳐 생긴 경고 제거).
- 에셋 편집에서 MCP 배열 조작의 함정을 두 번 밟았다. 배열을 줄이면 남는 원소의 인스턴스 구조체 내용이 통째로 비워질 수 있고(옆에 있던 `Wait For Interaction` 노드가 그렇게 비어 재작성했다), 원소의 타입 교체는 제자리에서 되지 않아 지웠다 다시 붙여야 했다. 편집 후 재조회로 확인하지 않으면 그대로 저장된다.

### 후속 과제
- PIE 수동 검증(사용자 진행): 문·엘리베이터·상자·체크포인트의 상호작용과 프롬프트가 그대로인지, 퀘스트 스텝 진입 시 NPC 가 열리고 상호작용으로 스텝이 완료되는지, 대상이 멀리 있어 스트리밍 아웃된 상태로 스텝에 들어갔다 다가가도 열려 있는지.
- 열어 둔 대상이 언로드→재로드되면 콜리전이 레벨 저장값으로 돌아가 다시 잠긴다(그 상태를 다시 밟기 전까지). 실제로 걸리는 조립이 나오면 그때 대상 쪽 복원 수단을 따로 마련한다.
