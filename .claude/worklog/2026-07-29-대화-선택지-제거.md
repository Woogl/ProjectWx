# WxDialogue 선택지 제거

## 계획

### 목표
`WxDialogue` 의 선택지(Choice) 데이터와 코드를 제거한다. `Choose()` 는 호출처가 없는 죽은 코드인 반면, `Advance()` 는 `Choices` 가 있으면 그대로 return 해 세션이 영구히 굳는 소프트락 함정이었다. 선택지가 실제로 필요해지면 UI·권위·분기 저장까지 포함해 그때 새로 설계한다.

### 접근 방식
- **단순 삭제, 대체 없음**: 선택지를 흉내내는 폴백(경고 후 종료 등)을 남기지 않는다. 없는 기능은 없는 채로 두는 편이 다음 설계를 자유롭게 한다.
- **`Advance()` 가 유일한 진행 경로**: 조건 분기가 빠지면서 `CurrentRow` 검사 → `NextDialogue` 추적 → 실패 시 `EndDialogue()` 의 선형 흐름만 남는다. 소프트락 경로가 구조적으로 사라진다.
- **데이터 정의를 한 줄 = 한 노드로 확정**: `FWxDialogueTableRow` 는 `Speaker`/`Line`/`NextDialogue` 3필드만 남는다.

### 영향
- `Content/DesignerTables/DT_Dialogue.uasset` — 행에 `Choices` 값이 있었다면 필드 제거로 버려진다. 선택지 노드는 진입 즉시 소프트락이라 정상 사용 중일 리 없다.
- BP 영향 없음 — `Choose` 는 `BlueprintCallable` 이 아니었고, 선택지를 꺼낼 공개 접근자가 없어 위젯이 참조할 수단 자체가 없었다.

### 구현·결정과 그 이유
- **폴백 없이 통째로 삭제**: 리뷰 문서가 제안했던 즉시 조치(선택지 노드에서 경고 후 종료)를 넣지 않았다. 기능 자체를 걷어내면 그 폴백이 지킬 상태가 없다. 반쪽 흔적을 남기는 편이 다음 설계를 더 제약한다.
- **소프트락이 구조적으로 소멸**: `Advance()` 에서 조건 분기가 빠지면서 `CurrentRow` 검사 → `NextDialogue` 추적 → 실패 시 `EndDialogue()` 의 단일 경로만 남았다. 데이터를 어떻게 채워도 세션이 굳지 않는다.
- **README 에 부재를 명기**: 확장 포인트에서 "분기(선택지)는 없다 — 필요해지면 그때 설계한다"를 적었다. 지웠다는 사실을 남기지 않으면 다음 사람이 사라진 기능을 찾다가 다시 반쪽으로 되살릴 위험이 있다.
