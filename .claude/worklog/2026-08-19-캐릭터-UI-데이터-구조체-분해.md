# 캐릭터 UI 데이터 구조체 분해

## 계획

### 목표
이름·초상화 두 필드만 담던 `FWxCharacterUIData`를 없애고, 두 값을 `AWxCharacterBase`의 프로퍼티로 직접 둔다. 캐릭터의 표시 데이터가 남의 모듈 구조체 안에 들어가 있던 모양을 걷어내는 것이 목적이다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../MVVM/WxCharacterUIData.h` | 구조체 타입 제거 | 삭제 |
| `Source/WxGame/Character/WxCharacterBase.{h,cpp}` | `UIData` 대신 `CharacterName`·`Portrait` 프로퍼티와 게터 두 개 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Character.{h,cpp}` | `Initialize`가 값 두 개를 인자로 받음 | 수정 |
| `Plugins/WxUI/.../Component/WxNameplateComponent.{h,cpp}` | `InitializeViewModels` 인자 전달 형태 일치 | 수정 |
| `Source/WxGame/Character/WxEnemyCharacter.cpp` | 멤버를 직접 전달 | 수정 |
| `Source/WxGame/MVVM/WxViewModel_BossCharacter.cpp` | 게터로 전달 | 수정 |
| `Source/WxGame/MVVM/WxViewModelResolver_PlayerCharacter.cpp` | 게터로 전달 | 수정 |
| `Content/Character/Boss/BP_Boss.uasset` | 떨어져 나간 이름 값 재입력 | 수정 |

### 접근 방식
- **구조체 분해**: 지정자·카테고리·`AllowedClasses` 메타는 기존 필드 것을 그대로 옮겨 저작 경험을 유지한다. 초상화 비동기 로드 경로(`RequestImageAsync`)는 손대지 않는다.
- **리졸버 파일 통합은 제외**: 플레이어 리졸버는 여전히 캐릭터에서 값을 읽으므로 WxGame에 남는다. WxUI 쪽 VM 파일로 합칠 수 없다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../MVVM/WxCharacterUIData.h` | 구조체 타입 제거 | 삭제 |
| `Source/WxGame/Character/WxCharacterBase.{h,cpp}` | `CharacterName`·`Portrait` 프로퍼티와 게터 두 개로 대체 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_Character.{h,cpp}` | `Initialize`가 이름·초상화를 각각 받음 | 수정 |
| `Plugins/WxUI/.../Component/WxNameplateComponent.{h,cpp}` | 같은 형태로 전달 | 수정 |
| `Source/WxGame/Character/WxEnemyCharacter.cpp` | 베이스 멤버를 직접 전달 | 수정 |
| `Source/WxGame/MVVM/WxViewModel_BossCharacter.cpp` | 게터로 전달 | 수정 |
| `Source/WxGame/MVVM/WxViewModelResolver_PlayerCharacter.cpp` | 게터로 전달 | 수정 |
| `Content/Character/Boss/BP_Boss.uasset` | 베이스 프로퍼티에 이름 값 재입력 | 수정 |

### 구현·결정과 그 이유
- **캐릭터 프로퍼티로 분해**: 두 필드짜리 타입을 WxUI가 소유하고 게임 모듈이 값을 실어 나르던 구조가 배보다 배꼽이 컸다. 캐릭터가 자기 표시 데이터를 자기 프로퍼티로 들고, VM은 값만 받는다.
- **카테고리 분리**: 기존 `Wx` 대신 `Wx|UI`에 둬 팀·이동속도 같은 게임플레이 값과 표시용 값을 디테일 패널에서 갈랐다.
- **리졸버 파일 통합 제외**: 플레이어 리졸버는 여전히 캐릭터에서 값을 읽어야 해 WxGame에 남는다. 컴포넌트로 뽑았다면 WxUI로 옮겨 VM 파일과 합칠 수 있었지만, 클래스를 하나 늘리지 않는 쪽을 택했다.
