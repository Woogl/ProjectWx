# 그로기 타이머의 World 취득을 어빌리티 자신으로

## 계획

### 목표

`UWxAbility_Groggy` 가 타이머용 `UWorld` 를 `ActorInfo->AvatarActor` 약참조로 얻는 삼항식을 어빌리티 자신의 `GetWorld()` 로 바꾼다. 모듈 리뷰(`Docs/Programmer/module_review_WxCombat.md` 7번)가 이를 "아바타가 먼저 파괴되면 반복 타이머가 살아남는다"는 버그로 올렸으나 이 코드베이스에서는 성립하지 않는 시나리오다. 실익은 중복 제거뿐이므로, 코드를 줄이는 동시에 리뷰 문서의 사실관계도 바로잡는다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../Ability/WxAbility_Groggy.cpp` | `ActivateAbility`·`EndAbility` 두 곳의 아바타 경유 삼항식을 `GetWorld()` 로 교체 | 수정 |
| `Docs/Programmer/module_review_WxCombat.md` | 7번 항목을 「버그/정확성」에서 「중복/복잡도」로 내리고 문제 서술을 실제 파괴 순서에 맞게 정정 | 수정 |

### 접근 방식

- **리뷰의 전제가 깨지는 지점**: ASC 는 PlayerState 가 아니라 캐릭터의 DefaultSubobject 이고, 엔진이 컴포넌트 초기화 때 소유자와 아바타를 같은 액터로 물린다. 프로젝트에는 아바타를 따로 갈아 끼우는 호출이 없어 "아바타만 파괴되고 ASC 가 남는" 구성 자체가 없다.
- **파괴 순서도 안전한 쪽**: 액터 파괴는 컴포넌트 해제를 먼저 하고 그 뒤에 액터를 가비지로 표시한다. ASC 는 해제 시점에 활성 어빌리티를 취소하므로 `EndAbility` 가 도는 동안 아바타 약참조는 아직 유효하다. 여기에 더해 그로기는 사망 태그를 구독해 파괴보다 한참 앞서 스스로 끝난다.
- **그럼에도 바꾸는 이유**: 어빌리티의 `GetWorld()` 는 Outer(=ASC 소유 액터)를 거치는데, 액터 쪽 구현은 가비지 표시 여부를 보지 않고 레벨의 월드를 돌려준다. 약참조 검사보다 엄밀히 넓게 성립하면서 표현은 짧다. 같은 모듈이 이미 어빌리티 레벨 `GetWorld()` 를 쓰고 있고, `InstancedPerActor` 라 CDO 널 반환 조건에도 걸리지 않는다.

### 구현·결정과 그 이유

- **버그가 아니라 중복으로 판정**: 리뷰는 아바타가 먼저 파괴되면 World 가 널이 돼 0.1초 반복 폴러가 살아남는다고 봤으나, 이 프로젝트에서는 그 전제가 두 겹으로 깨진다. ASC 가 캐릭터의 서브오브젝트라 소유자와 아바타가 같은 액터이고, 액터 파괴는 컴포넌트 해제를 먼저 하고 그다음에 액터를 가비지로 표시한다 — ASC 가 해제 시점에 어빌리티를 취소하므로 종료 코드가 도는 동안 아바타 약참조는 아직 살아 있다. 그로기는 여기에 더해 사망 태그를 구독해 파괴보다 훨씬 앞서 스스로 끝난다.

- **그래도 `GetWorld()` 로 바꾼 이유**: 어빌리티의 World 는 Outer(= ASC 소유 액터)를 거치고, 액터 쪽 구현은 가비지 표시 여부를 보지 않는다. 약참조 검사보다 넓게 성립하면서 같은 삼항식 두 벌이 사라진다. 나중에 ASC 를 다른 액터로 옮기더라도 소유자와 아바타는 같은 월드에 있어 타이머 매니저가 같으므로 판정이 갈리지 않는다.

- **CDO 널 반환은 걸리지 않는다**: 어빌리티의 World 게터는 인스턴스가 아닐 때 널을 내는데, 엔진은 비인스턴스 정책일 때만 CDO 로 취소를 부른다. 베이스가 `InstancedPerActor` 라 활성화·종료가 언제나 인스턴스에서 돈다.

- **문서는 항목을 지우고 철회 사유를 남김**: 리뷰 문서는 "고쳐야 할 것"의 목록이라 이미 정리된 지적을 남기면 잡음이 된다. 다만 근거 없이 지우면 다음 리뷰가 같은 지적을 다시 올릴 수 있어, 전제가 왜 깨지는지를 「미검토 / 한계」에 한 줄로 박아 뒀다.

### 계획 대비 달라진 점
문서 처리가 계획의 "범주를 내리고 서술을 정정" 에서 "항목 삭제 + 철회 사유 기록" 으로 바뀌었다. 코드를 같은 작업에서 정리해 버려 지적 자체가 남아 있을 이유가 없어졌기 때문이다.

### 후속 과제
- 타이머 해제가 여전히 `ActorInfo` 널 검사 블록 안에 있다. 이제 그 안의 코드가 `ActorInfo` 를 안 보므로 불필요한 종속이지만, 그 인자가 널로 들어오는 경로가 실제로 없어 그대로 뒀다.
