# 퀘스트 스텝 행 파라미터에 행 타입 메타 기입

## 계획

### 목표
데이터 테이블 행 파라미터의 테이블 픽커에 모든 테이블이 뜬다. 필터는 행 타입 메타가 붙은 필드에만 걸리는데, StateTree 파라미터는 태스크 인스턴스 데이터와 별개의 프로퍼티라 태스크 헤더에 선언한 메타가 오지 않고, 이 파라미터들은 만들 때 액터 지정 쪽에만 메타를 넣었다. 기존 파라미터에 메타를 얹을 수 있게 하고 대화 스텝에 적용한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxToolset/.../WxStateTreeToolset.h/.cpp` | 기존 루트 파라미터의 메타를 갈아 끼우는 도구 신설, 메타 기입 로직을 헬퍼로 공유 | 수정 |
| `/Game/Quest/Steps/ST_QuestStep_TalkNPC` | 행 파라미터에 대화 행 타입 메타 기입 | 에셋 |

### 접근 방식
- **지웠다 다시 만들지 않는다**: 파라미터를 재생성하면 ID가 바뀌어 그것을 소스로 쓰던 바인딩과 링크 상태 오버라이드 값이 끊긴다. 대신 현재 서술자를 복사해 메타만 갈아 끼우고 덮어쓰기로 되돌려 준다. 엔진의 덮어쓰기 경로가 기존 ID를 명시적으로 보존하고, 백 교체 시 값 이동이 이름이 아니라 ID 매칭으로 일어나므로 값과 바인딩이 그대로 남는다.

- **공유 백 오염 없음**: 프로퍼티 백은 레이아웃이 같으면 공유되는 캐시 구조체지만, 캐시 키가 되는 해시에 메타와 ID가 함께 들어간다. 메타가 달라지면 새 백이 따로 만들어지고 기존 것은 건드리지 않는다. 파라미터 ID가 해시에 들어가는 이상 애초에 이 백은 이 에셋 전용이다.

- **런타임 무관**: 서술자의 메타는 에디터 전용 데이터라 쿠킹된 빌드에 실리지 않는다. 순수하게 픽커 후보를 거르는 표시용이다.

- **교체 의미**: 도구는 넘긴 메타로 기존 메타를 갈아 끼운다(빈 입력이면 메타 제거). 키를 하나씩 더하는 것보다 결과를 예측하기 쉽고, 잘못 넣었을 때 되돌리기도 같은 도구로 된다.

- **적용 순서**: 대화 스텝 하나에만 먼저 넣고, 그 스텝을 링크한 퀘스트의 오버라이드 행까지 필터가 전파되는지 확인한 뒤 나머지 스텝으로 넓힌다. 링크 상태는 루트 레이아웃을 복사해 갖고 있어 전파가 자동이 아닐 수 있는데, 재링크는 오버라이드 값을 리셋하므로 쓰지 않는다.

## 완료

### 수정한 파일

| `/Game/Quest/Steps/ST_QuestStep_TalkNPC` | 행 파라미터에 대화 행 타입 메타 기입 | 에셋 |

### 구현·결정과 그 이유
- **덮어쓰기 경로 재사용**: 서술자 사본에 메타를 얹어 덮어쓰기로 되돌려 주면 엔진이 알아서 ID를 보존하고 값을 ID 매칭으로 옮긴다. 별도 마이그레이션을 직접 짤 필요가 없었다. 기입 후 파라미터 ID와 바인딩 4개가 그대로임을 확인했다.

- **메타는 교체, BP 변수와 다른 선택**: 파라미터 서술자의 메타는 우리가 넣은 것뿐이라 통째로 갈아 끼우는 편이 결과를 예측하기 쉽다. 빈 입력이 곧 메타 제거가 되어 되돌리기도 같은 도구로 된다.

### 계획 대비 달라진 점
- 계획대로.

### 후속 과제
- 픽커에 대화 테이블만 뜨는지 눈으로 확인하는 일이 남았다. 파라미터 백 구조체가 교체되므로 에셋 창을 닫았다 열어야 한다.
- 링크 상태 오버라이드 행까지 필터가 전파되는지 미확인. 안 되면 링크 상태 백에도 같은 방식이 필요하다.
- 나머지 두 스텝(MoveToTarget·KillEnemies)의 행 파라미터는 아직 적용하지 않았다 — 대화 스텝 확인 후로 미뤘다.
