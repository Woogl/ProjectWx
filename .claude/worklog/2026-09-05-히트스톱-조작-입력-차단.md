# 히트스톱 조작 입력 차단

## 계획

### 목표
히트스톱이 멈추는 것은 애니메이션뿐이라, 얼어 있는 동안에도 이동·점프·앉기 입력이 그대로 들어가 캐릭터가 굳은 포즈로 미끄러지거나 뛰어오른다. 히트스톱 동안에는 플레이어의 조작이 캐릭터를 움직이지 못하게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../AbilitySystem/WxHitStopComponent.h/.cpp` | `RefreshAnimRateScale` 안의 동결 판정식을 공개 const 함수 `IsFrozen()`으로 분리 | 수정 |
| `Source/WxGame/Character/WxPlayerCharacter.cpp` | `Move`·`Jump`·`ToggleCrouch`에서 동결 중이면 조기 반환 | 수정 |

### 접근 방식
- **판정 원천은 히트스톱 컴포넌트**: 캐릭터가 `Effect.HitStop` 태그를 직접 보면 안 된다. 소유 클라에서는 예측 인스턴스와 서버 복제본이 겹쳐 태그가 RTT만큼 늦게 걷혀, 애니메이션은 이미 풀렸는데 입력만 더 오래 막힌다. 애니메이션을 세우는 그 판정을 그대로 물으면 정지 구간과 차단 구간이 정확히 겹친다. 판정식은 이미 `RefreshAnimRateScale` 안에 있어 const 함수로 꺼내기만 하면 되고 상태를 새로 들지 않는다.
- **막는 것은 이동 계열 입력**: GAS 바깥에서 캐릭터를 직접 움직이는 셋만 막는다. 뗌(`StopJumping`)은 엔진에 바로 묶여 있고 막으면 눌린 상태가 남으므로 건드리지 않는다.
- **카메라(`Look`)는 막지 않는다**: 잠깐이라도 시점이 굳으면 캐릭터가 멈춘 게 아니라 게임이 끊긴 것처럼 느껴진다.
- **어빌리티 입력도 막지 않는다**: 히트스톱은 공격 본동작(공격자)이나 히트리액트(피격자) 한가운데에 걸려, 새 액션은 지금도 배타 게이트에 막히고 선입력으로 쌓였다가 콤보 창·후딜에서 나간다. 여기서 끊으면 그 선입력만 사라진다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../AbilitySystem/WxHitStopComponent.h/.cpp` | 공개 `IsFrozen()` 신설. 동결 판정을 여기로 옮기고 `RefreshAnimRateScale`은 그 결과로 배속을 대입만 한다 | 수정 |
| `Source/WxGame/Character/WxPlayerCharacter.cpp` | `Move`·`Jump`·`ToggleCrouch` 진입부에서 `HitStopComponent->IsFrozen()`이면 조기 반환 | 수정 |

### 구현·결정과 그 이유
- **판정을 옮기고 복제하지 않았다**: 배속을 세우는 조건과 입력을 막는 조건이 서로 다른 자리에서 각자 자라면 언젠가 어긋난다. 판정은 계산 원천인 히트스톱 컴포넌트 한 곳에 두고, 배속 대입도 입력 차단도 그 결과를 묻는다.
- **널 검사는 `IsFrozen` 안**: 기존 경로는 ASC가 있을 때만 등록되는 델리게이트라 검사가 없었지만, 입력 핸들러는 그런 보장이 없다.
- **세 곳에 같은 가드를 풀어 썼다**: 캐릭터 쪽에 얇은 헬퍼를 만들면 진짜 판정이 어디 있는지가 한 겹 흐려진다.
- **막지 않은 것**: 카메라(`Look`)와 어빌리티 입력. 어빌리티 입력은 지금도 배타 게이트에 걸려 발동하지 못하고 선입력으로 쌓이므로, 여기서 끊으면 차단이 아니라 콤보용 선입력만 사라진다.

### 후속 과제
- PIE 확인: 이동 키를 누른 채 적을 때렸을 때 미끄러지지 않고 풀리는 즉시 다시 움직이는지, 히트스톱 중 점프·앉기가 씹히는지, 선입력 콤보는 그대로인지.
- 관성·중력은 그대로다 — 붙어 있던 속도로 잠깐 미끄러지고 공중에서는 계속 떨어진다. 이동 자체를 얼리는 건 별건.
