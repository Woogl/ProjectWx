# 어빌리티 차단·캔슬을 Exclusive 마커 하나로 통일

## 계획

### 목표

차단(BlockAbilitiesWithTag)이 아직 루트 `Ability`를 쓰는 탓에, 반응 어빌리티는 애셋 태그를 비워 두어야만 남의 차단을 피할 수 있고 적 패턴은 마커를 못 받아 사망·그로기가 루트로 캔슬하는 예외로 남아 있다. 차단도 마커로 옮겨 규칙을 하나로 만든다 — **액션 슬롯을 점유하면 `Ability.Exclusive`를 갖고, 차단·캔슬은 오직 이 태그만 지목한다.**

### 접근 방식

- **축을 하나로**: 루트 `Ability`는 식별 태그의 부모로만 남고 차단·캔슬에서 완전히 빠진다. 마커 유무가 유일한 기준이므로, 반응 어빌리티는 마커만 안 붙이면 되고 식별 태그는 정상적으로 가질 수 있다.
- **패턴도 액션**: 패턴에 마커를 주면 사망·그로기의 루트 캔슬과 피격 중 패턴 차단이 전부 공통 규칙으로 흡수된다. 대신 피격이 패턴을 끊게 되는데, 지금도 같은 슬롯 몽타주 인터럽트로 사실상 끊기므로 종료가 명시적이 될 뿐이다.
- **캐릭터 차이는 데이터로**: 보스가 피격에도 패턴을 잇는 것은 `GA_HitReact_Custer`의 차단·캔슬 컨테이너를 비워 표현한다. 차단은 이미 그렇게 돼 있으므로 캔슬만 맞춘다.
- **판정 인자 동반 수정**: `AreAbilityTagsBlocked`는 차단 태그를 정확 매칭하므로, 점프 게이트와 기믹 차단의 인자를 같이 바꾸지 않으면 조용히 항상 false가 된다.

### 구현·결정과 그 이유
- **루트 태그를 차단·캔슬에서 완전히 퇴출**: 축이 하나면 규칙도 하나다. 루트를 남겨두면 "언제 루트를 쓰나"라는 애매함이 계속 남고, 반응 어빌리티가 태그를 못 갖는 함정도 그대로다.
- **적 패턴도 액션으로 취급**: 패턴에 마커를 주자 그로기·사망의 루트 캔슬과 피격 중 패턴 차단이 전부 공통 규칙에 흡수됐다. 유일한 걸림돌이던 "피격이 패턴을 끊는다"는 근거 규칙이 실제로는 코드에 구현된 적이 없었고(`Ability.Pattern`을 읽는 C++ 코드 0곳), 평타 경직 무시는 대미지 행이 HitReact 태그를 싣지 않는 방식으로 이미 동작한다.
- **보스 예외를 데이터로**: `GA_HitReact_Custer`의 캔슬 컨테이너를 비워, 이미 비어 있던 차단과 짝을 맞췄다. 캐릭터 성격 차이가 코드 분기가 아니라 어빌리티 BP 값으로 남는다.
- **판정 인자 동반 수정**: `AreAbilityTagsBlocked`는 차단 태그를 부모 확장 없이 정확 매칭하므로, 점프 게이트와 기믹 차단의 인자를 함께 바꾸지 않으면 조용히 항상 false가 된다.

- PIE 실동작 확인 미실시(빌드·CDO 덤프 검증까지 완료). 특히 적 피격 시 패턴 중단·보스 패턴 지속은 눈으로 볼 필요가 있다.
