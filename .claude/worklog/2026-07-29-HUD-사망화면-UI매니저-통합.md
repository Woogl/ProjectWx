# HUD·사망 화면을 UI 매니저 서브시스템으로 통합

## 계획

### 목표
`AWxPlayerController` 가 `OnPossess`/`OnRep_Pawn` 을 오버라이드하는 유일한 이유인 HUD 푸시·사망 화면 푸시를 `UWxUIManagerSubsystem` 으로 옮긴다. 둘 다 화면을 띄우는 일(WxUI 책임)인데 PC 가 폰 생명주기를 감시해 중개하고 있었다. 서브시스템은 이미 로컬 플레이어의 PC 를 추적해 레이아웃을 세우므로, 빙의까지 직접 따라가면 중개가 사라진다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../Public/System/WxUIManagerSubsystem.h` | 빙의·사망 핸들러 3 개, 추적 상태 3 개 선언 | 수정 |
| `Plugins/WxUI/.../Private/System/WxUIManagerSubsystem.cpp` | `HandlePlayerControllerSet` 에 빙의 구독 추가, 핸들러 구현, `Deinitialize` 정리, 낡은 주석 갱신 | 수정 |
| `Source/WxGame/Controller/WxPlayerController.h` | `OnRep_Pawn`·`OnPossess` 오버라이드와 `PushGameHUD`·`BindCharacterDeath`·`HandleCharacterDeath` 선언 제거, 전방선언 2 개 제거, 클래스 주석 갱신 | 수정 |
| `Source/WxGame/Controller/WxPlayerController.cpp` | 같은 함수 5 개와 include 2 개 제거 | 수정 |

신규 클래스 없음. `.Build.cs`·`.uplugin`·에셋 변경 없음 — 서브시스템은 자동 생성이라 `EXP_Combat` 등록 같은 단계가 없다. WxUI 는 이미 `GameplayAbilities` 의존이 있고 쓰는 태그 3 개는 모두 WxCore 다.

### 접근 방식

- **받을 자리는 이미 있었다**: `UWxUIManagerSubsystem` 은 `HandleLocalPlayerAdded` → `OnPlayerControllerChanged` → `HandlePlayerControllerSet` 로 로컬 PC 를 추적하고 그 PC 로 레이아웃을 세운다. 심지어 자기 주석에 "컨텐츠는 PC 의 OnPossess/OnRep_Pawn 에서 다시 push 되므로"라고 적어, 지금 끊으려는 결합에 기대고 있음을 스스로 밝히고 있었다.

- **빙의 추적은 엔진 델리게이트 하나로**: `AController::OnPossessedPawnChanged`(다이내믹) 가 PC 가 잡던 두 지점을 모두 덮는다 — 서버/로컬 빙의는 `Controller.cpp:342` `OnPossess()` 반환 **후** `:350`, 원격 클라 폰 복제는 `:568` `SetPawn` 후 `:572`. 빙의가 끝난 뒤 오므로 기존 제약("HUD 리졸버가 빙의 폰의 ASC 를 읽으므로 빙의 완료 후 푸시")이 그대로 지켜지고, 현재보다 조금 늦어 오히려 안전하다.

- **사망은 WxCore 태그로**: `AWxCharacterBase::OnDeath`(WxGame 타입)에 묶여 WxUI 로 못 가던 것이었는데, 그 델리게이트의 출처는 `State.Dead` 태그다(`WxCharacterBase.cpp:198` → `:217 HandleDeath()` → `:272 Broadcast`). `HandleDeath()` 호출부가 저 태그 콜백 하나뿐이라 같은 태그를 직접 관찰하면 동일한 신호를 WxGame 타입 없이 받는다. ASC 는 캐릭터의 기본 서브오브젝트라(`WxCharacterBase.cpp:26`) 폰이 있으면 바로 잡히므로 늦은 도착 처리가 필요 없다.

```
HandlePlayerControllerSet(PC)     ← 기존 함수
  이전 PC 구독 해제 + 폰 관찰 해제
  레이아웃 재생성                  ← 기존
  PC->OnPossessedPawnChanged 구독
  현재 폰으로 1 회 따라잡기         ← 레이아웃 재생성이 빙의보다 늦어도 HUD 가 선다

HandlePossessedPawnChanged(Old, New)
  WatchPawnDeath(New)             ← 이전 ASC 해제 후 새 ASC 구독 (null 이면 해제만)
  New 있으면 GameHUDClass → UI.Layer.Game

HandleDeathTagChanged(NewCount > 0)
  DeathScreenClass → UI.Layer.Menu
```

- **로컬 게이팅 불필요**: 서브시스템은 `ULocalPlayer` 를 통해서만 PC 를 얻으므로 추적 대상이 언제나 로컬이다. `Deinitialize` 에서 PC·ASC 구독을 모두 끊는다(GameInstance 서브시스템이라 월드를 넘어 산다).

- **곁다리로 닫히는 구멍**: 지금은 PC 교체로 레이아웃이 재생성될 때 이미 빙의가 끝나 있으면 HUD 를 다시 띄울 계기가 없다. 재생성 직후의 "현재 폰으로 따라잡기"가 이를 닫는다.

### 구현·결정과 그 이유
- **신규 컴포넌트 대신 기존 서브시스템에 통합(사용자 지시)**: 처음엔 `UControllerComponent` 상속 신규 컴포넌트를 Experience 주입으로 붙이는 안을 냈으나 반려됐다. 다시 보니 `UWxUIManagerSubsystem` 이 이미 로컬 PC 를 추적해 레이아웃을 세우고 있었고, 심지어 자기 주석에 "컨텐츠는 PC 의 OnPossess/OnRep_Pawn 에서 다시 push 되므로"라고 적어 끊으려는 결합에 기대고 있음을 밝히고 있었다. PC 를 이미 쥔 쪽이 빙의까지 따라가면 되는 일이었다 — 결과적으로 새 클래스도, `EXP_Combat` 등록도, 등록 누락으로 조용히 죽는 실패 경로도 없다.
- **빙의 추적은 `OnPossessedPawnChanged` 하나로**: PC 가 오버라이드하던 `OnPossess`(서버/로컬)와 `OnRep_Pawn`(원격 클라)을 엔진 델리게이트 하나가 모두 덮는다. 두 경로 모두 빙의가 끝난 **뒤** 발행되므로 "HUD 리졸버가 빙의 폰의 ASC 를 읽는다"는 기존 전제가 그대로 유지되고, 현재보다 조금 늦어 오히려 안전하다.
- **사망을 캐릭터 델리게이트가 아니라 태그로**: `AWxCharacterBase::OnDeath` 는 WxGame 타입이라 WxUI 가 구독할 수 없지만, 그 델리게이트의 출처가 WxCore 의 `State.Dead` 태그다(`HandleDeath()` 호출부가 태그 콜백 하나뿐). 같은 태그를 직접 관찰해 신호는 그대로 받으면서 모듈 경계를 지켰다. ASC 가 캐릭터의 기본 서브오브젝트라 폰이 있으면 즉시 잡히므로 늦은 도착 처리도 불필요했다.
- **구독 정리를 `WatchPawnDeath(nullptr)` 하나로**: 폰 교체·PC 교체·`Deinitialize` 세 경로가 같은 해제 코드를 필요로 해서, "이전 것 끊고 새 것 구독"을 한 함수에 넣고 null 을 해제 전용 호출로 썼다. GameInstance 서브시스템이라 월드를 넘어 사는 만큼 해제 누락이 곧 댕글링이다.
- **로컬 게이팅 제거**: PC 에 있던 `IsLocalController()` 체크가 사라졌다. 서브시스템은 `ULocalPlayer` 를 통해서만 PC 를 얻으므로 추적 대상이 언제나 로컬이다.
- **`Widget/WxActivatableWidget.h` include 유지**: 점검 때 죽은 코드로 분류했으나 오판이었다. `WxUIDeveloperSettings.h` 가 `UWxActivatableWidget` 을 전방선언만 하므로 `TSoftClassPtr<UWxActivatableWidget>` → `TSoftClassPtr<UCommonActivatableWidget>` 변환에 완전 타입이 필요하다. 대화 창 push 가 남아 있어 계속 쓰인다.

### 계획 대비 달라진 점
- 계획대로. 죽은 include 는 계획대로 2 건(`Character/WxCharacterBase.h`·`Character/WxPlayerCharacter.h`)만 걷혔고, 이관으로 결합이 사라지면서 함께 정리됐다.

### 후속 과제
- PIE 육안 검증 미실시(빌드까지만 확인). 이관이라 동작 변화가 없어야 정상이다 — ① 시작 시 HUD 표시 ② HUD 어트리뷰트 바인딩 생존(리졸버의 ASC 읽기) ③ 사망 시 사망 화면 ④ 대화 창 기존대로.
- `AWxCharacterBase::OnDeath` 의 C++ 구독자가 0 이 됐다. `BlueprintAssignable` 이라 BP 가 물고 있을 수 있어 남겨 뒀다 — BP 참조를 확인한 뒤 없으면 제거 후보다.
- PC 에 남은 이관 후보는 점검 2 번(`DialogueSession` 기본 서브오브젝트 → Experience 주입)뿐이다. Client RPC 라우팅 때문에 복제 활성화와 에셋 등록이 따라오므로 별도 판단이 필요하다.
