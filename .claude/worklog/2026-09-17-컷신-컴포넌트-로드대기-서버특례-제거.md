# 컷신 컴포넌트의 로드 대기와 서버 특례 제거

## 계획

### 목표
궁극기 시퀀스가 하드 참조가 되어, 시전자를 아는 모든 머신에 시퀀스가 미리 올라와 있다(직전 작업 `2026-09-17-궁극기-보류-축소와-컷신-하드참조.md`). 이제 필요 없어진 비동기 로드 대기와 거기서 파생된 분기를 걷는다. 리슨 서버 특례도 없애 서버에는 "길이 타이머로 세션 수명만 정한다"는 규칙 하나만 남긴다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/Cutscene/WxSkillCutsceneComponent.h` | 세션 시퀀스를 `TObjectPtr`로 바꾼다. `SequenceLoad`·`FStreamableHandle`을 제거하고, `StartTime`+`Duration`을 `EndTime`으로 합친다. 클래스 주석과 사본 주석을 고친다. | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/Cutscene/WxSkillCutsceneComponent.cpp` | 비동기 로드를 제거하고 `PrepareLocalPlayer`를 평탄화한다. 세션 종료를 타이머로 일원화하고 권위 분기를 제거한다. "Player" 태그 검사를 `Start`로 옮긴다. include 2개를 제거한다. | 수정 |

### 접근 방식
- **참조는 네트 레이어에 맡긴다.** 세션의 시퀀스를 하드 참조로 복제한다. `net.AllowAsyncLoading` 기본값이 0이라 수신 즉시 해석되고, 대개는 시전자 클래스와 함께 이미 메모리에 있다. 늦게 풀리는 참조는 엔진이 OnRep을 다시 불러 주므로, 준비 단계는 "시퀀스와 시전자가 모두 풀렸는가"만 보면 된다.
- **서버는 길이로만 끝낸다.**
  - 리슨 서버와 스탠드얼론도 전용 서버처럼 오디오 시각 타이머로 세션을 닫는다. 자기 로컬 재생은 클라처럼 따로 자기 끝까지 간다.
  - 준비 실패와 로컬 완료는 모든 머신에서 같은 경로를 탄다.
  - 호스트의 세션 종료는 로컬 끝과 같은 프레임이거나 최대 1프레임 앞선다. 몽타주는 여전히 로컬 시퀀스가 끝난 뒤 시작한다.
- **타이머 뒤 `return`은 유지한다.** 서버가 틱 도중 바꾼 배율은 다음 프레임 델타부터 들어간다(네트 수신 → 배율 적용 → 틱 그룹 순). 그래서 종료 프레임의 Groom 역배율은 옛 값으로 둬야 정상 속도가 유지된다.
- **저작 오류는 `Start`에서 거른다.** "Player" 태그 검사를 비용 확정 전의 서버 `Start`로 옮긴다. 그러면 모든 넷 모드에서 비용 없이 발동이 실패하고, 로컬 실패 검사는 플레이어·인스턴스 데이터 생성 실패만 남는다.
- **남기는 것**: 다음은 이유가 남아 있어 유지한다.
  - 준비 단계: `ActivateAbility` 안에서 재생하면 GAS로 재진입하고, 참조 대기와 재시작 방지도 이 단계가 맡는다.
  - 세션 사본: 다음 세션이 `State`를 덮어쓴다.
  - 관련성 강제, 매 틱 Groom 역배율, 입양 규칙.

### 구현·결정과 그 이유
- **시퀀스 로드는 네트 레이어에 맡겼다**
  - 직전 작업에서 폴백으로 남겨 둔 비동기 로드는 없앴다. 메모리에 없는 에셋은 이제 복제 수신 시점에 엔진이 즉시 로드한다(`net.AllowAsyncLoading` 기본 0).
  - 대개는 시전자 클래스와 함께 이미 올라와 있어 실제 로드는 일어나지 않는다.
  - 참조가 늦게 풀리면 엔진이 OnRep을 다시 부르므로, 준비 단계의 조건은 "시퀀스와 시전자가 모두 풀렸는가" 하나로 충분하다.
- **서버는 길이로만 세션을 끝낸다**
  - 리슨 서버의 "자기 로컬 완료로 종료" 특례를 없앴다. 이제 모든 넷 모드에서 규칙이 같다.
  - 호스트의 로컬 끝은 타이머와 같은 프레임이거나 부동소수 반올림으로 최대 1프레임 앞이다. 둘 다 오디오 시각을 쓰고 로컬 시작이 `Start`보다 빠를 수 없기 때문이다.
  - 몽타주는 여전히 호스트 로컬 시퀀스가 끝난 뒤 시작한다(`UpdateSession`의 "재생 중이면 자기 끝까지").
- **타이머 뒤 `return`은 남겼다**
  - 서버가 틱 도중에 바꾼 배율은 다음 프레임 델타부터 적용된다(네트 수신 → 배율 적용 → 틱 그룹 순).
  - 종료 프레임에 Groom 역배율을 새 배율로 덮으면 그 프레임에 머리카락이 멈춘다. 옛 값을 두면 정상 속도로 이어지고, 다음 틱에서 갱신된다.
  - 나중에 불필요한 `return`으로 보고 지우지 않도록 이유를 주석에 남겼다.
- **"Player" 태그 검사를 `Start`로 옮겼다**
  - 비용 확정 전에 거르므로, 저작 오류가 모든 넷 모드에서 비용 없이 발동 실패로 끝난다.
  - 타이머로 일원화하면 호스트에서 "저작 오류인데 길이만큼 월드 정지"가 생길 수 있었는데, 이 이동으로 그 문제도 막았다. 이전에는 호스트는 취소(비용 소모), 전용 서버는 정지로 모드마다 달랐다.
  - 클라 콘텐츠는 서버와 같으므로 로컬 태그 검사는 지웠다. 로컬 실패 검사는 플레이어·인스턴스 데이터 생성 실패만 남았다.
- **실패 경로에서 `UpdateSession()`을 뺐다**
  - Preparing은 `bPlaying`일 때만 서고, `bPlaying`이 꺼지는 모든 경로(Finish, OnRep)가 곧바로 준비를 접는다.
  - 따라서 준비 중에는 항상 `bPlaying`이고, 그 호출은 사본만 복사한 뒤 반환하는 무동작이었다.
- **남긴 것**
  - Preparing 단계: `Play()`가 첫 평가를 동기로 하고 Force Custom Mode가 AnimBP 인스턴스를 교체하므로, `ActivateAbility` 안에서 재생을 시작하면 몽타주 콜백이 GAS로 재진입한다. 참조 대기와 재시작 방지도 이 단계가 맡는다.
  - 세션 사본: 다음 세션이 `State`를 덮어쓴다.
  - 관련성 강제, 매 틱 Groom 역배율, 입양 규칙.

### 후속 과제
- **미실행 수동 검증**
  - 2인 리슨 PIE에서 세 가지 경로로 궁극기를 쓴다: 호스트 라이브 입력, 원격 클라 시전을 호스트에서 관전, 입력 버퍼 경유. 각 경로에서 종료 프레임에 몽타주가 시작되는지, 머리카락이 끊기지 않는지 본다.
  - 스탠드얼론에서 컷신 도중 일시정지했다가 재개한다.
  - "Player" 태그를 지운 시퀀스 사본으로 발동이 비용 없이 실패하는지 본다.
- **동작 변화(호스트)**
  - 세션 종료(배율·무적·`IsBusy`)가 원격 RPC·UI·입력 버퍼 경유일 때 최대 1프레임 앞선다.
  - 라이브 입력의 후속 몽타주는 같은 프레임 애님 틱 뒤에 시작한다. 현재 몽타주는 BlendIn 기본값 0.25라 화면 차이가 없다. BlendIn 0 몽타주를 쓰면 AnimBP 포즈가 1프레임 보일 수 있다.
- **별도 발견 (범위 밖, 미실측)**
  - **호스트 직접 시전 시 첫 프레임 Groom 튐**: 입력 처리에서 배율을 바꾼 프레임의 델타는 이미 1배인데, 같은 프레임에 역배율 1000이 걸린다. Niagara가 틱 델타를 0.125초로 잘라 한 프레임 튐 수준으로 보인다. 역배율을 "이번 프레임에 실제 적용된 배율"(`DeltaTimeSeconds / DeltaRealTimeSeconds`)로 구하면 해소된다.
  - **`StartLocalPlayer`의 잠복 null 역참조**: `StopAnimMontage`가 `Phase` 설정보다 먼저 불린다. 그 콜백이 세션 소유 어빌리티를 취소하면 null `SequenceActor`를 역참조한다. 지금은 궁극기가 컷신 전에 몽타주를 재생하지 않아 도달하지 않는다.
