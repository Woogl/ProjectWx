# ST 태스크의 컴포넌트 지목을 Context 액터 드롭다운으로

## 계획

### 목표
ST 에셋에서 이동·연출 태스크의 대상 컴포넌트를 Context 액터의 컴포넌트(DoorLeft 등)로 지정할 수 없다. 바인딩 피커가 소스 프로퍼티를 `CPF_Edit` 로 거르는데(`PropertyBindingExtension.cpp:1189`) BP 컴포넌트 패널로 추가한 컴포넌트의 클래스 변수에는 `CPF_BlueprintVisible | CPF_NonTransactional` 만 붙어(`KismetCompiler.cpp:1429`) 구조적으로 목록에 뜰 수 없기 때문이다. 예전엔 네이티브 `AWxDoor` 가 `VisibleAnywhere` 로 문짝을 들고 있어 됐고, `18756ef1 기믹 하위 클래스 제거` 로 그 클래스가 사라지면서 새 바인딩을 만들 수단이 없어졌다.

컴포넌트를 다시 네이티브로 올리지 않고, 그 자리를 **Context 액터의 컴포넌트 목록 드롭다운**으로 바꾼다.

### 접근 방식
- **값은 이름**: ST 에셋은 레벨 컴포넌트를 가리킬 수 없으므로 이름이 유일한 저장 형태다. `FWxComponentName::Resolve` 가 액터의 컴포넌트를 이름으로 찾는다(BP SCS 컴포넌트의 인스턴스 이름 = 변수 이름 = 컴포넌트 패널 이름).
- **드롭다운**: 프로퍼티 핸들의 outer 에서 `UStateTreeEditorData` 를 찾아 그 `Schema` 의 Context 액터 클래스를 꺼내고, 그 클래스의 오브젝트 프로퍼티 중 허용 컴포넌트 클래스 파생인 것을 목록으로 만든다. 네이티브·BP 컴포넌트가 같은 방식으로 잡힌다. 허용 클래스는 `meta = (AllowedClasses = ...)` 로 좁힌다.
- **액터는 자동 연결**: 인스턴스 데이터에 `Category = "Context"` 의 `TObjectPtr<AActor> Actor` 를 두면 컴파일러가 스키마 Context 데이터에 자동 바인딩한다(`StateTreeCompiler.cpp:3140~3175`) — 에셋에서 배선할 것이 없다.
- **해석 시점**: `EnterState` 앞머리에서 한 번 해석해 런타임 캐시에 담고, `Tick` 은 캐시만 읽는다. 못 찾으면 액터·이름을 담은 에러 로그 후 `Failed`.
- **에디터 모듈 신설 없이**: `WxWorld.Build.cs` 에 이미 `bBuildEditor` 블록이 있고 모듈 Startup 이 비어 있어 그 자리에 얹는다.

### 에디터 작업 (코드 밖)
프로퍼티 타입이 바뀌어 기존 바인딩은 컴파일 때 정리된다. ST_Door(4곳) · ST_Elevator · ST_TreasureChest · ST_CheckPoint 에서 드롭다운으로 다시 고른다. 드롭다운이 비면 그 에셋 스키마의 Context Actor Class 가 BP 로 지정돼 있는지 먼저 확인한다.

### 구현·결정과 그 이유
- **바인딩을 포기한 근거**: 피커가 소스 프로퍼티에 `CPF_Edit` 를 요구하는데 BP 컴포넌트의 클래스 변수엔 그 플래그가 없다. 네이티브 액터로 되돌리지 않는 한 방법이 없고, 기믹은 네이티브 클래스를 두지 않기로 한 방향이라 지목 수단 자체를 바꿨다.
- **후보를 액터 클래스의 컴포넌트 프로퍼티에서 뽑는다**: 네이티브 선언이든 BP 컴포넌트 패널이 만든 것이든 클래스에는 똑같이 오브젝트 프로퍼티로 남는다. 편집 플래그를 보지 않으니 바인딩 피커가 걸러내던 것이 그대로 잡히고, 목록에 뜨는 이름이 곧 런타임 조회 키라 저작과 해석이 같은 것을 가리킨다.
- **`Resolve` 는 오브젝트 이름이 아니라 프로퍼티를 읽는다**: 컴포넌트 인스턴스 이름은 충돌 시 접미사가 붙어 흔들리지만 프로퍼티는 드롭다운이 고른 그 이름 그대로다.
- **액터는 `Context.GetOwner()` 로 충분**: Context 액터를 인스턴스 데이터로 받는 대신 이미 SpawnNiagara 가 쓰던 경로를 따랐다. 노드에 `Actor` 행이 하나 더 생기지 않고, 스키마 Context 액터가 곧 컴포넌트 소유 액터라는 사실도 그대로다.
- **해석은 진입에서 한 번**: 이름 조회는 상수 시간이 아니라 `EnterState` 에서 캐시하고 `Tick` 은 캐시만 읽는다 — 아키타입·속도 캐시와 같은 자리다. 못 찾으면 액터와 이름을 담아 에러 로그를 남긴다(조용히 안 움직이면 원인을 찾을 수 없다).
- **`NoBinding` 은 구조체 타입에**: 엔진이 프로퍼티뿐 아니라 구조체 타입의 메타도 보므로 타입에 한 번만 달았다. 고르는 길이 드롭다운 하나로 남는다.

### 계획 대비 달라진 점
- 커스터마이제이션을 WxWorld 런타임 모듈이 아니라 이미 같은 일을 하는 `Source/WxEditor` 에 넣었다(액터 로케이터·데이터테이블 행 편집기가 사는 곳). WxWorld 에 에디터 의존을 추가할 필요가 없어졌고, 대신 WxEditor 가 WxWorld 를 참조한다.
- Context 액터를 받는 `Actor` 인스턴스 데이터를 두지 않았다 — 위 이유.
- 형제 태스크 2종(PlayAnimation·SpawnNiagara)도 함께 전환했다(계획 5번).

### 후속 과제
- **에디터 재시작 필요**: USTRUCT 신설과 프로퍼티 타입 변경이라 Live Coding 으로는 반영되지 않는다.
- **에셋 재저작**: ST_Door(4곳) · ST_Elevator · ST_TreasureChest · ST_CheckPoint 의 컴포넌트 지정을 드롭다운으로 다시 고른다. 예전 바인딩은 타입이 달라져 무효다.
- 인게임 미검증 — 문 개폐, 엘리베이터 층 이동, 상자 애니메이션, 체크포인트 FX.
- 드롭다운이 비면 그 에셋 스키마의 Context Actor Class 가 BP 로 지정돼 있는지 확인한다(AActor 로 두면 후보가 없다).
