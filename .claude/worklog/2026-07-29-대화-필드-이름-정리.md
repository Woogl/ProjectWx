# 대화 행 필드 이름 정리

## 계획

### 목표
대화 행의 본문 필드가 `Text` 라 타입 이름과 같은 단어인 데다, 범용어를 특정 의미 하나가 선점해 나중에 다른 텍스트가 들어올 자리가 없다. 대본 업계가 "한 사람이 한 번에 하는 말"을 세는 단위어이자 이 코드베이스가 이미 쓰고 있는 말인 `Line` 으로 바꾼다. 겸사겸사 최근 `NextRow` → `NextDialogue` 개명이 남긴 어휘 불일치도 맞춘다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueTableRow.h` | 행 `Text` → `Line`, 선택지 `TargetRow` → `TargetDialogue`, 개명 잔재 주석 정리 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueSessionComponent.h` | `GetCurrentText` → `GetCurrentLine`, 대사 변경 델리게이트 인자 이름 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Private/WxDialogueSessionComponent.cpp` | 개명한 필드·함수에 맞춰 호출부 갱신 | 수정 |
| `Source/WxGame/MVVM/WxViewModel_Dialogue.h/.cpp` | 세션 게터 호출·수신 인자 이름 | 수정 |
| `Config/DefaultEngine.ini` | `[CoreRedirects]` 프로퍼티 리다이렉트 추가 | 수정 |

### 접근 방식
- **`Line` 선정**: `Script` 는 대본 전체를 가리켜 행 하나에 붙이기엔 층이 안 맞고, 언리얼에서 Script 는 `/Script/` 패키지 접두·`UScriptStruct` 처럼 코드를 뜻해 데이터 필드로 오독된다. `Line` 은 코드베이스가 이미 같은 뜻으로 쓰는 말이라(대사 변경 발행·위젯) 이름들이 서로 맞물린다.
- **`ChoiceText` 는 유지**: 애초에 행 본문과 맞추려던 개명이라, 행이 `Line` 이 된 시점에 근거가 사라졌다. 남는 이유는 접두 중복 제거뿐이라 값어치가 작고, 지금은 말(`Line`)과 선택지 문구(`ChoiceText`)가 다른 단어라 구분에 오히려 도움이 된다.
- **데이터 보존**: 프로퍼티 개명은 저장된 행 값을 버리므로 CoreRedirects 로 옛 이름을 새 이름에 잇는다. 값을 다시 넣지 않아도 되고, 개명 전 저장본으로 되돌아가도 읽힌다.

### 구현·결정과 그 이유
- **`Line` 선정**: `Script` 는 대본 전체라 행 하나에 붙이기엔 층이 안 맞고, 언리얼에서 Script 는 패키지 접두·ScriptStruct 처럼 코드를 가리켜 데이터 필드로 오독된다. `Line` 은 대본 업계가 "한 사람이 한 번에 하는 말"을 세는 단위어이자 이 코드베이스가 이미 발행·위젯에서 쓰던 말이라, 필드부터 위젯까지 한 단어로 맞물린다.
- **뷰모델 표시 프로퍼티는 그대로**: 위젯 바인딩이 이름으로 걸려 있어 건드리면 WBP 쪽이 끊긴다. 개명은 C++ 안에서 끝나는 것들로 한정했다.
- **CoreRedirects 로 데이터 보존**: 프로퍼티 개명은 저장된 행 값을 버린다. 리다이렉트를 깔아 재입력 없이 실었고, 개명 전 저장본으로 되돌아가도 읽힌다. 옛 `NextRow` 도 함께 이어 뒀다.

### 계획 대비 달라진 점
- `ChoiceText` → `Text` 는 취소했다. 애초 근거가 "행 본문과 이름을 맞춘다"였는데 행이 `Line` 이 된 순간 사라졌고, 남는 이유가 접두 중복 제거뿐이라 값어치가 작다. 지금은 말(`Line`)과 선택지 문구(`ChoiceText`)가 서로 다른 단어라 구분에 오히려 낫다.

### 후속 과제
- DT_Dialogue 는 디스크에 아직 옛 프로퍼티 이름으로 저장돼 있고 리다이렉트로 읽힌다. 다음에 테이블을 손대 저장하면 새 이름으로 굳는다.
