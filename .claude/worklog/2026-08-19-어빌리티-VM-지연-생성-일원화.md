# 어빌리티 뷰모델 지연 생성 일원화

## 계획

### 목표
어빌리티 뷰모델은 위젯 바인딩이 요청할 때 만들어지는 지연 생성 뷰모델인데, 플레이어 리졸버가 아이콘을 넣으려고 부여된 어빌리티를 미리 훑어 선생성하는 경로를 하나 더 갖고 있다. 생성 경로를 지연 생성 하나로 줄이고, 아이콘 공급을 그 시점으로 옮긴다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_AbilitySystem.h` | 아이콘 게터 델리게이트 타입·필드 추가 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/MVVM/WxViewModel_AbilitySystem.cpp` | 어빌리티 뷰모델 생성 직후 게터로 아이콘 주입 | 수정 |
| `Source/WxGame/MVVM/WxViewModelResolver_PlayerCharacter.h` | 아이콘 게터 정적 함수 선언 | 수정 |
| `Source/WxGame/MVVM/WxViewModelResolver_PlayerCharacter.cpp` | 선생성 루프 제거, 게터 바인딩으로 대체 | 수정 |

### 접근 방식

선생성 루프가 사라지면 아이콘을 꽂을 자리도 함께 사라진다. UI 플러그인은 전투 플러그인을 참조할 수 없어 어빌리티에서 아이콘을 직접 읽지 못하므로, 아이콘을 어디서 얻을지가 이 작업의 실제 설계 지점이다.

- **아이콘 공급자를 뷰모델에 꽂는다**: 어빌리티를 받아 아이콘 소프트 참조를 돌려주는 델리게이트를 어빌리티 시스템 뷰모델이 들고 있고, 지연 생성이 일어날 때 그것으로 아이콘을 채운다. 양쪽을 다 아는 리졸버가 뷰모델을 만들면서 공급자를 묶어 준다.
- **리졸버는 공급자만 꽂는다**: 어빌리티를 훑는 일 자체가 없어지므로 리졸버는 캐릭터 뷰모델을 만들고 게터를 묶는 것으로 끝난다.

컨버전 함수를 게임 모듈로 옮겨 그 안에서 아이콘까지 채우는 대안도 있으나, 스킬바 슬롯의 바인딩을 전부 새 함수로 다시 걸어야 해서 에셋 쪽 리스크가 코드 이득보다 크다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Source/WxGame/MVVM/WxViewModelResolver_PlayerCharacter.cpp` | 어빌리티 뷰모델 선생성·아이콘 주입 루프 제거, 쓰이지 않게 된 include 정리 | 수정 |

### 구현·결정과 그 이유
- **선생성 루프만 걷어냄**: 생성 경로를 지연 생성 하나로 줄이는 것이 목적이므로 리졸버는 캐릭터 뷰모델을 만들고 초기화하는 본래 일만 남긴다.
- **아이콘 공급자를 두지 않음**: 계획에서는 아이콘을 지연 생성 시점에 채우도록 게터를 꽂으려 했으나, 그 간접이 경로를 다시 둘로 만드는 셈이라 받지 않기로 했다. 아이콘 주입 코드는 지금 없다.

### 계획 대비 달라진 점
- 아이콘 게터 델리게이트를 도입하지 않았다. 뷰모델·리졸버 양쪽에 걸치는 간접을 늘리지 않겠다는 판단이며, UI 플러그인 쪽은 손대지 않았다.

### 후속 과제
- 어빌리티 뷰모델의 아이콘을 채우는 코드가 없어 항상 비어 있다. 슬롯 아이콘을 위젯에서 직접 지정할지, 다른 공급 경로를 둘지는 미정.
- PIE 실동작 확인(스킬바 슬롯이 지연 생성으로 뷰모델을 받아 쿨다운·발동 가능 표시가 도는지)은 미수행. 컴파일 검증까지만 마쳤다.
