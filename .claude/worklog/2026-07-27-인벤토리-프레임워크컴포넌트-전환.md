# 인벤토리 매니저를 ModularGameplay 프레임워크 컴포넌트로 전환

## 계획

### 목표
`UWxInventoryManagerComponent` 의 부모를 `UActorComponent` 에서 `UControllerComponent`(= `UGameFrameworkComponent` 계열)로 바꿔 `AWxGameMode` 의 `FrameworkComponents` 주입 경로에 올린다.
PlayerController 가 인벤토리를 직접 알고 하드 부착하던 구조를 걷어내고, 기존 `UWxPlayerSpawnComponent`·`UWxIndicatorManagerComponent`·`UWxQuestComponent` 와 동일하게 "부착은 코드가 아니라 GameMode 에셋 설정으로" 통일한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxInventory/WxInventory.uplugin` | `ModularGameplay` 플러그인 의존 추가 | 수정 |
| `Plugins/WxInventory/Source/WxInventory/WxInventory.Build.cs` | `ModularGameplay` 모듈 의존 추가 | 수정 |

### 접근 방식
- **베이스 클래스 선택**: `AWxGameMode::InitGame` 은 컴포넌트 베이스로 receiver 액터를 추론한다(GameState/Pawn/Controller/PlayerState 컴포넌트 중 하나). `UGameFrameworkComponent` 를 직접 상속하면 추론에 실패해 경고와 함께 건너뛰므로, PlayerController 전용인 인벤토리는 `UControllerComponent` 를 상속한다.
- **하드 부착 제거**: GameMode 주입과 CDO 생성이 공존하면 컨트롤러에 인벤토리가 2개 붙는다. `CreateDefaultSubobject` 와 멤버 필드를 제거하고 조회는 `FindComponentByClass` 로 통일한다(정적 헬퍼 `UWxInventoryManagerComponent::FindInventory` 와 동일 방식).
- **멀티플레이 대응**: `InitGame` 은 서버 전용이라 클라 주입 경로를 별도로 마련한다.
- **기본 지급 아이템**: 이번 범위에서 제외(요청). `DefaultItems`/`GrantDefaultItems` 는 그대로 둔다.

### 구현·결정과 그 이유
- **`UControllerComponent` 상속**: GameMode 의 receiver 추론이 4개 프레임워크 컴포넌트 베이스만 인식한다. `UGameFrameworkComponent` 직접 상속은 추론 실패로 주입 자체가 안 되므로, PlayerController 전용이라는 소유 규칙과도 맞는 `UControllerComponent` 를 골랐다.
- **클라 수동 등록 경로를 만들지 않음**: 엔진이 복제 컴포넌트를 non-authority 액터에 생성하지 않도록 막고 있어(`GameFrameworkComponentManager.cpp:487`) 클라 등록은 no-op 이다. 클라 인스턴스는 액터 채널이 복제 수신 시 자동 생성한다(`DataChannel.cpp:5085`). 즉 엔진 설계상 서버 주입 + 복제가 정답이고, Lyra 의 QuickBar 컴포넌트도 같은 경로다.
- **HUD 푸시를 인벤토리 도착으로 게이팅**: 진짜 위험은 주입이 아니라 타이밍이었다. 인벤토리 리졸버는 위젯 생성 시점에 한 번만 조회하고 없으면 `nullptr` 을 반환한 뒤 재시도하지 않아, 클라에서 컴포넌트가 늦게 도착하면 인벤토리 UI 가 그 세션 내내 죽는다. `PushGameHUD` 가 인벤토리 존재를 확인하고, Pawn 이 먼저 도착한 순서는 `OnSubobjectCreatedFromReplication` 훅이 메운다. 두 순서 어느 쪽이든 푸시는 정확히 한 번이다.
- **게터를 캐시 없이 매번 조회**: 부착 시점이 서버(주입)와 클라(복제)에서 다르므로 멤버로 들고 있으면 어느 한쪽이 항상 틀린다. 조회 비용보다 단일 진입점 유지가 중요하다.

### 계획 대비 달라진 점
- 클라이언트에서 GameState 의 복제된 GameModeClass CDO 를 읽어 `FrameworkComponents` 를 재등록하려던 계획을 취소했다. 엔진이 그 경로를 막고 있어 효과가 없고, 필요한 건 주입이 아니라 늦은 도착 대응이었다.
- 계획에 없던 `WxViewModel_Inventory.h` 리졸버 주석을 함께 고쳤다. "PC 생성자 서브오브젝트라 항상 사용 가능"이 이번 변경으로 거짓이 되어 그대로 두면 다음 작업자를 오도한다.

### 후속 과제
- GameMode 에셋(BP)의 `FrameworkComponents` 에 `WxInventoryManagerComponent` 등록 — 하지 않으면 인벤토리가 조용히 없는 상태가 된다.
- BP 에서 제거된 `InventoryManager` 변수를 참조하던 곳이 있으면 `Get Inventory Manager` 호출로 교체.
- 원격 클라이언트 실제 검증 미완 — 빌드까지만 확인했다. 인벤토리 도착과 Pawn 복제 순서 양쪽에서 HUD 바인딩이 성립하는지 2인 PIE(클라이언트 분리 프로세스)로 확인 필요.
- 기본 지급 아이템: 주입되는 C++ 클래스는 `DefaultItems` 기본값이 비어 실질 지급이 없다. 필요해지면 BP 서브클래스나 별도 지급 경로를 정해야 한다.
