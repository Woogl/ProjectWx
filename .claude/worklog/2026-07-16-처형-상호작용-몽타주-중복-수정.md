# 처형(Finisher) 상호작용 시 일반 상호작용 몽타주 중복 재생 수정

## 계획

### 목표
적 처형을 상호작용으로 발동하면 처형 몽타주(Finisher 어빌리티)와 일반 상호작용 몽타주(Interact 어빌리티)가 함께 재생되는 중복을 없앤다. 처형은 상호작용이 보내는 GameplayEvent로 자체 어빌리티를 깨우는데, Interact 어빌리티가 그 상호작용에도 자기 범용 몽타주를 조건 없이 얹는 것이 원인이다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/Source/WxWorld/Public/Interaction/WxInteractionComponent.h` | `bUseInteractMontage`(EditDefaultsOnly, `bUseHighlight` 옆) + `SetUseInteractMontage`/`GetUseInteractMontage` 선언 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Private/Interaction/WxInteractionComponent.cpp` | 세터·게터 정의 | 수정 |
| `Source/WxGame/Character/WxEnemyCharacter.cpp` | 생성자에서 `FinisherInteractionComponent->SetUseInteractMontage(false)` | 수정 |
| `Source/WxGame/AbilitySystem/Ability/WxAbility_Interact.cpp` | `PlayInteractMontage` 가드에 `!Target->GetUseInteractMontage()` 스킵 추가 | 수정 |

### 접근 방식
- **컴포넌트 opt-out 게이트**: 어떤 몽타주를 재생할지는 상호작용 대상(컴포넌트)이 스스로 발행한다. 처형 컴포넌트만 게이트를 꺼(자체 어빌리티가 모션을 구동) 일반 몽타주를 스킵. 두 어빌리티 분리·플러그인 경계는 그대로 두는 최소 수정.
- **복제 불필요**: 컴포넌트 CDO 디폴트라 서버·클라 동일. 세 진입점(리슨호스트·원격클라·서버수신) 모두 `PlayInteractMontage(Selected)`로 대상을 넘기므로 가드 한 줄이 전부 커버.
- **흡수안 기각**: Finisher를 Interact로 합치면 대미지 노티파이(WxCombat)가 WxGame 어빌리티를 참조해야 해 플러그인 경계(WxCore만 참조)가 깨진다. 예측(Interact)/서버권위(Finisher ServerInitiated) 모델도 다르다.

### 구현·결정과 그 이유
- **게이트는 대상(컴포넌트)이 발행**: 어떤 몽타주를 쓸지는 상호작용 어빌리티가 적 타입을 알아서가 아니라, 대상 컴포넌트가 스스로 선언한다. 어빌리티↔적 결합 없이 디커플. 컴포넌트의 기존 `bUseHighlight` 게이트 컨벤션과 일치.
- **복제 없이 충분**: CDO 디폴트라 서버·클라 동일. 세 진입점 모두 대상 컴포넌트를 넘겨 가드 한 줄로 커버.
- **흡수 대신 게이트(사용자와 합의)**: Finisher를 Interact로 흡수하면 대미지 노티파이(WxCombat)가 WxGame 어빌리티를 캐스팅해야 해 플러그인 경계가 깨지고, 예측(Interact)/서버권위(Finisher) 모델도 뒤섞인다. 분리 유지가 옳고 빠진 건 몽타주 게이트뿐이었다.

### 검증
- WxEditor(Development) 빌드 성공(25/25, WxWorld·WxCombat·WxGame 링크). 경고는 전부 엔진 측 기존 deprecation.
- 인게임 확인(에디터 실행)은 미수행 — 애셋 재생 동작은 다음 실행 시 확인 권장.
