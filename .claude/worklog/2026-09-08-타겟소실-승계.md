# 타겟 소실 후 이미 감지 중인 다른 적대 액터 승계

## 계획

### 목표
타겟이 사라진 자리에서, 폰이 이미 계속 보고 있던 다른 적대 액터로 곧바로 이어붙지 못하는 문제를 고친다. 시야 자극은 계속 등록되지만 엔진이 감지 상태가 바뀔 때만 통지하므로, 자극을 기다리는 지금 구조로는 "이미 보이는 대상" 이 영영 재획득되지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | `FindPerceivedTarget()` private 선언 | 수정 |
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | `FindPerceivedTarget()` 정의, 사망·파괴 경로에서 승계, 빙의 변경 경로에 `ForgetAll()`, 낡은 주석 정정 | 수정 |

### 접근 방식
- **근거**: `UAISense_Sight` 는 `NotifyType = OnPerceptionChange` 라, 자극이 담아 오는 `bWantsToNotifyOnlyOnValueChange` 때문에 `ProcessStimuli` 가 감지 성공/실패가 뒤집힐 때만 방송한다. 계속 보이는 액터는 매 질의마다 성공 자극을 등록해도 통지가 나오지 않는다. Hearing·Damage 는 매 자극마다 통지되므로 지금은 소리·피격으로만 재획득된다.
- **이미 가진 정보에서 승계**: `GetCurrentlyPerceivedActors` 로 현재 감지 중인 목록을 읽어 살아 있는 첫 후보를 다음 타겟으로 삼는다. 새 감지 비용이 없고 자극을 기다리지 않는다. 자기 폰은 선택 단계에서 뺀다 — `SetTargetActor` 의 자기 폰 가드는 조기 return 이라 후보로 뽑히면 죽은 타겟이 블랙보드에 그대로 남는다.
- **한 번만 방송**: 비웠다가 다시 넣지 않고 다음 타겟을 계산해 `SetTargetActor` 를 한 번만 호출한다. `OnTargetChanged` 구독자가 해제→재획득으로 한 프레임 튀지 않는다.
- **파괴 경로는 먼저 잊는다**: `EndPlay` 시점엔 사라지는 액터가 아직 감지 목록에 있어 자기 자신이 다시 뽑힌다. 리시 복귀가 쓰는 `ForgetActor` 와 같은 처리로 기록을 먼저 지운다.
- **빙의 변경은 승계가 아니라 `ForgetAll()`**: 관찰자가 바뀐 자리라 옛 폰의 기록으로 타겟을 물리면 새 폰이 못 보는 대상을 잡는다. 기록을 지우면 시야 질의 결과도 초기화돼 새 폰이 보는 적이 새 상태 변화로 정상 획득된다.
- **선별 기준은 두지 않는다**: 팀 필터는 세 센스가 이미 적대만 등록하므로 불필요하고, 거리 우선은 기존 획득에도 없던 별도 판단이라 섞지 않는다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/.../WxAIPerceptionComponent.h` | `FindPerceivedTarget()` 선언, 사망·파괴 핸들러 doc 를 "다음 감지 대상으로 넘긴다" 로 정정 | 수정 |
| `Plugins/WxAI/.../WxAIPerceptionComponent.cpp` | `FindPerceivedTarget()` 정의, 사망·파괴 경로 승계, 파괴 경로에 `ForgetActor`, 빙의 변경 경로에 `ForgetAll`, 부활 주석 정정 | 수정 |

### 구현·결정과 그 이유
- **엔진 근거 확인**: 시야 센스는 통지 유형이 "상태 변화" 로 고정돼 있어, 계속 보이는 액터의 반복 성공 자극은 퍼셉션 컴포넌트가 전부 삼킨다. 성공 자극의 보조 저장 경로도 갱신 여부를 항상 false 로 돌려주므로 예외가 없다. 반면 청각·촉각은 기본 유형이라 매 자극마다 통지된다 — 지금까지 "때리거나 소리를 내야 다시 붙는" 것으로 보였던 이유다.
- **자극을 기다리지 않고 이미 가진 목록을 읽는다**: 감지 기록은 컴포넌트가 이미 들고 있으므로, 소실 시점에 현재 감지 중인 액터를 훑어 살아 있는 첫 후보로 넘긴다. 추가 감지 비용이 없고 다음 시야 질의를 기다리지 않는다.
- **비웠다 채우지 않고 한 번만 적용**: 타겟 변경 통지 구독자(락온·전투 진입)가 해제→재획득으로 한 프레임 튀지 않도록, 다음 타겟을 먼저 계산해 한 번만 적용한다.
- **자기 폰을 선택 단계에서 제외**: 적용 함수의 자기 폰 가드는 조기 return 이라, 자기 폰이 후보로 뽑히면 잃은 타겟이 블랙보드에 그대로 남는 역효과가 난다. 그래서 가드에 기대지 않고 후보에서 먼저 뺐다.
- **파괴 경로는 먼저 잊고 승계**: EndPlay 시점엔 사라지는 액터가 아직 감지 목록에 있어 자기 자신이 다음 타겟으로 뽑힌다. 리시 복귀가 쓰던 것과 같은 방식으로 그 기록을 먼저 지운다.
- **빙의 변경은 승계가 아니라 전체 망각**: 관찰자가 바뀐 자리라 옛 폰이 모은 기록으로 타겟을 물리면 새 폰이 보지도 못하는 대상을 잡는다. 기록을 통째로 지우면 시야 질의 결과도 초기화돼, 새 폰이 보고 있는 적이 새 상태 변화로 정상 획득된다. 폰 재사용에서도 같은 함정이 사라지고 "새 빙의는 대상 없이 시작한다" 는 기존 의도는 유지된다.
- **선별 기준은 추가하지 않음**: 세 센스가 이미 적대만 등록하므로 피아 재판정은 불필요하고, 가까운 적 우선은 기존 획득에도 없던 별도 판단이라 섞지 않았다.

### 후속 과제
- 인게임 미검증(컴파일만): 둘이 상대하던 적이 한쪽을 죽였을 때 시야 안 생존자로 즉시 타겟이 넘어가는지, 리시 복귀에서는 승계 없이 그대로 귀환하는지 확인 필요.
- 후보 선택은 감지 목록 순서를 그대로 따른다. 시야 안에 적대 대상이 둘 이상일 때 "가장 가까운 쪽" 이 필요해지면 그때 별도로 다룬다.
