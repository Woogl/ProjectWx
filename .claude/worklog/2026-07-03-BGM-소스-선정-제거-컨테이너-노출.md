# BGM 소스 선정 제거 — 활성 소스 태그를 컨테이너로 Chooser에 전부 노출

## 계획

### 목표
`GetTopSource`(단일 소스 선정)를 없애고, 활성 소스들의 `MusicTag`와 각 owner의 owned 태그를 각각 태그 컨테이너로 모아 Chooser에 전부 노출한다. 다중 소스 시 서브시스템 사전 선정이 "Row=우선순위" 결정을 무력화하던 문제를 해소한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxSound/Source/WxSound/Public/WxBGMChooserContext.h` | `BGMTag`(단일)→`BGMTags`(컨테이너), `SourceOwner`(AActor)→`SourceOwnerTags`(컨테이너), 주석 갱신 | 수정 |
| `Plugins/WxSound/Source/WxSound/Public/System/WxMusicSubsystem.h` | `GetTopSource` 선언 제거, `FWxBGMSourceRequest`/`ActiveSources` 순서 관련 주석 정리 (필드 구성 유지) | 수정 |
| `Plugins/WxSound/Source/WxSound/Private/System/WxMusicSubsystem.cpp` | `EvaluateBGM` 컨테이너 구성으로 교체, `GetTopSource` 정의 삭제, `RegisterBGMSource` 주석 정리 | 수정 |

### 접근 방식
- **선정 제거 + 컨테이너 노출**: `EvaluateBGM`이 베이스라인 `BGMTag` + 활성 소스 전체 `MusicTag`를 `BGMTags`에, 각 owner ASC의 owned 태그를 `SourceOwnerTags`에 합쳐 넣는다. Chooser Row 순서가 우선순위(첫 매치 승).
- **owner 태그 합집합** (사용자 확정): 대표 소스 선정 없이 owner 정보를 태그로 담아 Object Class 필터를 대체. `FWxBGMSourceRequest.Owner` 약참조는 평가 시점 owner 태그 조회용으로 유지.
- **컴포넌트 무변경**: 이미 `RegisterBGMSource(this, MusicTag)`만 호출.

### 필수 후속 (데이터)
`DefaultBGMChooser` 애셋을 에디터에서 재작성해야 런타임 완성: `BGMTag`→`BGMTags` 컬럼 재바인딩, `SourceOwner` Object Class 컬럼 제거→`SourceOwnerTags` Gameplay Tag 컬럼 추가, Row 우선순위 정렬. (사용자/기획 몫)

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxSound/Source/WxSound/Public/WxBGMChooserContext.h` | `BGMTag`→`BGMTags`, `SourceOwner`(AActor)→`SourceOwnerTags`(컨테이너), doc 주석 갱신, `class AActor` 전방선언 제거 | 수정 |
| `Plugins/WxSound/Source/WxSound/Public/System/WxMusicSubsystem.h` | `GetTopSource` 선언 제거, `FWxBGMSourceRequest`/`ActiveSources` 순서 관련 주석 정리 | 수정 |
| `Plugins/WxSound/Source/WxSound/Private/System/WxMusicSubsystem.cpp` | `EvaluateBGM` 컨테이너 구성 교체, `GetTopSource` 정의 삭제, `RegisterBGMSource` 주석 정리 | 수정 |

### 구현·결정과 그 이유
- **owner 태그는 평가 시점 조회**: `FWxBGMSourceRequest.Owner`(약참조)를 유지하고, `EvaluateBGM`에서 각 owner ASC의 `GetOwnedGameplayTags`를 임시 컨테이너로 받아 `SourceOwnerTags`에 `AppendTags`. `GetOwnedGameplayTags`가 인자 컨테이너를 Reset 후 채우므로 다중 owner 누적을 위해 owner마다 임시 컨테이너를 쓴다(직접 대입 불가).
- **무효 처리 단순화**: `AddTag`가 무효 태그를 무시하고 중복을 자동 제거하므로 `MusicTag.IsValid()` 개별 방어를 없앴다. 파괴된 소스만 `Source.IsValid()`로 건너뛴다.
- **컨텍스트 전방선언 정리**: `SourceOwner`(AActor*) 제거로 `WxBGMChooserContext.h`의 `class AActor;` 전방선언이 불필요해져 함께 삭제.

### 계획 대비 달라진 점
- 계획대로. (부수적으로 `WxBGMChooserContext.h`의 `class AActor;` 전방선언 제거는 계획에 명시 안 했으나 `SourceOwner` 삭제의 자연스러운 정리)

### 후속 과제
- **(필수·데이터) `DefaultBGMChooser` 애셋 재작성** — C++ 컴파일은 통과하나 구조체 멤버 변경으로 기존 컬럼 바인딩이 끊긴다. `BGMTag`→`BGMTags` 컬럼 재바인딩, `SourceOwner` Object Class 컬럼 제거→`SourceOwnerTags` Gameplay Tag 컬럼 추가, Row 우선순위 정렬. 이 작업 전까지 런타임 선택이 비어 있을 수 있음. (사용자/기획 몫)
- PIE에서 동시 2개 소스(서로 다른 owner) 활성 시 Row 상위 소스 승 검증 — 애셋 재작성 후.
