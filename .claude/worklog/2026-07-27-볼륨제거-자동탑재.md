# QuestStartVolume 제거 — 퀘스트 자동 탑재(에셋 자체 선언) 전환

## 계획

### 목표
퀘스트 수주 볼륨을 제거해 마지막 남은 레벨 배치 의존을 걷어내고, 퀘스트 ST 에셋이 탑재 여부(bAutoStart)와 시작 조건(Start 게이트 태스크)을 온전히 스스로 기술하게 한다. 아울러 7/27 「대화 순수화」의 미완 잔여인 ST_Quest_Main1 의 Start 게이트(Wait Dialogue Completed 배치)를 완성한다 — 현재는 볼륨 미배치 + 게이트 판정자 부재로 퀘스트를 시작할 수단이 전무하다.

### 접근 방식
- **탑재 선언은 에셋에**: 타입 마커 서브클래스가 예고한 메타데이터 자리의 첫 사용. 컴포넌트는 특정 에셋을 모르고(발견은 타입 기준) 데이터가 지정한다는 원칙을 유지하며, 전역 설정·BP 배선 없이 에셋 하나가 자기 완결된다.
- **발견·탑재**: 권위 BeginPlay 에서 애셋 레지스트리 클래스 필터로 나열하고 bAutoStart 태그가 참인 것을 기존 지연 시작 경로(RequestStartQuest, 다음 틱)로 탑재 — 초기화 순서 문제를 재사용으로 회피. 복수 발견 시 경로 정렬 첫 번째 + 경고(활성 1개, 결정성은 명시 정렬로 확보). 엔진 전제(파생 클래스 태그 수집, bool 태그 True/False 문자열, 태그 부재=false)는 엔진 소스로 사전 검증했다.
- **단일 러너 유지**: 동시 게이트 대기 1개는 볼륨 시절(마지막 승리 1개)과 동일. 후속 퀘스트는 StartNextQuest 체인. 병렬 게이트 대기는 러너 다중화가 필요한 별도 확장으로 보류.
- **볼륨 전용 API 소거**: 재진입·강탈 가드(GetCurrentQuest/CurrentQuest)는 탑재 경로가 결정적이 되면서 소비처가 소멸해 함께 제거한다.

### 구현·결정과 그 이유
- **탑재 선언은 에셋에**: 발견은 레지스트리 태그(로드 불요, 태그 부재=false)로 하고, 시작은 기존 지연 경로(다음 틱)를 재사용해 BeginPlay 초기화 순서를 우회했다. 복수 선언은 경로 사전순 첫 에셋 + 경고로 결정성을 유지한다.
- **볼륨은 레벨에 배치돼 있지 않았다**: 7/26 기록과 달리 Content 전수 검색에서 참조 0건 — 클래스 삭제만으로 충분했고, 고아 외부 액터도 없음을 확인했다.
- **잠복 결함 발견·수정 — 상태 완료 모드 유실**: 수주 직후 퀘스트가 한 프레임에 Success 까지 관통해 즉시 성공 처리되는 결함을 실주행에서 발견했다. 원인은 상태의 TasksCompletion 이 기본 Any 라서, 진입 즉시 Succeeded 를 반환하는 저널 태스크 하나가 상태 전체를 완료시킨 것. 이 에셋의 설계는 All 전제(인디케이터 태스크를 완료 판정에서 제외해 둔 것이 그 증거)였는데 7/26 MCP 트리 재작성 때 기본값으로 유실됐고, 진행부가 실주행된 것이 이번이 처음이라 드러나지 않았다.
- **게이트 완성은 이 구조의 전제**: 자동 탑재 = 즉시 게이트 대기이므로, 7/27 「대화 순수화」의 미완 잔여(Start 에 판정 태스크 부재 — 빈 상태는 즉시 통과)를 이번 범위에 흡수해 마무리했다.
