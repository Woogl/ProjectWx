# 팝업 미사용 선언 제거

## 계획

### 목표
WxUI 리뷰 3번을 반영해 호출자 없는 팝업 강제 종료 함수와 버튼 정의 구조체의 비교 연산자를 걷는다. 외부 비활성화만으로 이미 강제 종료 결과가 전달되므로 기능이 겹치고, 비교 연산자는 코드와 리플렉션 어디에서도 쓰이지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../Public/Widget/WxGamePopup.h` | 비교 연산자 선언과 베이스 `KillPopup` 선언 삭제 | 수정 |
| `Plugins/WxUI/.../Private/Widget/WxGamePopup.cpp` | 비교 연산자 정의와 빈 베이스 `KillPopup` 정의 삭제 | 수정 |
| `Plugins/WxUI/.../Public/Widget/WxConfirmationPopup.h` | `KillPopup` override 선언 삭제, 결과 진입점 주석을 실제 진입 경로(버튼·뒤로 가기)에 맞게 정정 | 수정 |
| `Plugins/WxUI/.../Private/Widget/WxConfirmationPopup.cpp` | `KillPopup` override 정의 삭제 | 수정 |

### 접근 방식
- **순수 삭제**: 강제 종료는 비활성화·Destruct 훅이 결과를 한 번만 내는 기존 경로에 맡기고, 그 경로는 건드리지 않는다. 결과 열거형의 강제 종료 값은 그 경로와 표시 실패에서 계속 쓰므로 유지한다.
- **리뷰 문서는 유지**: 리뷰 루틴이 다시 생성하는 문서라 반영 여부를 여기서 고치지 않는다.

### 구현·결정과 그 이유
- **강제 종료 API를 따로 두지 않는다**: 밖에서 팝업을 닫으려면 위젯을 비활성화하면 되고, 비활성화·Destruct 훅이 콜백을 먼저 떼어낸 뒤 강제 종료 결과를 한 번만 보낸다. 같은 결과를 내는 두 번째 입구는 호출자도 없이 중복만 만든다.
- **비교 연산자 삭제는 리플렉션에 영향이 없다**: 동등 비교 트레이트를 켜지 않아서 프로퍼티 비교는 원래도 필드 단위로 했다. BP 배열 검색도 이 연산자를 거치지 않는다.
- **리뷰 1번과 독립적이다**: 가려진 팝업의 강제 종료 판정을 Destruct 쪽으로 옮기더라도 외부 비활성화 경로는 남는다. 이번 제거가 그 수정의 선택지를 막지 않는다.
