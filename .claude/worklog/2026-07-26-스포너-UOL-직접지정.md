# 스포너 지정을 FUniversalObjectLocator 로 단일화 (액터 태그 전면 제거)

## 계획

### 목표
퀘스트 ST(레벨 밖 에셋)에서 월드 배치 스포너를 직접 집어 지정한다. 오전에 소프트 포인터 리터럴이 ST 컴파일러(`ValidateNoLevelActorReferences`)에 막혔으나, 엔진 공식 로케이터인 `FUniversalObjectLocator`(UOL)는 순수 구조체라 스캔 대상이 아니고(우회가 아니라 런타임 컨텍스트 해석), 씬 액터 픽커 커스터마이제이션과 WP 런타임 셀·PIE 픽스업 해석이 내장돼 있다. 액터 태그 지정은 아예 제거하고 공유 스포너 태스크의 지정 수단을 UOL 로 단일화한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/Source/WxWorld/WxWorld.Build.cs` | `UniversalObjectLocator` 모듈 의존성 추가(Public) | 수정 |
| `Plugins/WxWorld/.../Spawnable/WxSpawnerStateTreeNodes.h/.cpp` | 태그 입력·캐시·해석 헬퍼 전면 제거, `TArray<FUniversalObjectLocator>` 단일 입력, 트리거 구조체 개명(`TriggerSpawnersByTag`→`TriggerSpawnersByLocator`), 판정·설명 갱신 | 수정 |
| `/Game/Quest/ST_Quest`, `/Game/Quest/ST_Quest2` | 스폰·처치 스텝을 UOL 지정 쌍으로 재조립(MCP), 배치 스포너 잔여 액터 태그 정리 | 수정(MCP) |

### 접근 방식
- **UOL 단일 지정**: 두 공유 태스크의 InstanceData 를 `TArray<FUniversalObjectLocator> Spawners`(meta: `AllowedLocators = "Actor"`) 하나로 통일. 해석은 `SyncFind(오너 액터)` — 강제 로드 없음.
- **판정 규약 계승**: Wait 는 지정 전원이 해석(로드)되고 처치여야 통과, 미해석=대기. 빈 배열·빈 로케이터는 진입 시 경고 후 보수적 대기(침묵 완료 방지). Trigger 는 미해석 스킵, 전부 미해석·빈 배열이면 경고.
- **캐시 제거**: 매 틱 `SyncFind` 는 경로 조회 기반이라 소수 항목에선 비용이 무시되고 WP 언로드/재로드를 자연 처리한다 — 태그 시절의 전 액터 순회 캐시·재해석 로직이 통째로 사라진다.
- **개명 안전**: `WxSpawnerStateTreeNodes` 는 오늘 신설된 미커밋 파일이고 사용처가 ST_Quest·ST_Quest2 뿐이라(기믹 ST 는 별도 바인딩 태스크) 리다이렉트 없이 개명·재조립한다. 기믹 노드는 일절 손대지 않는다.

### 구현·결정과 그 이유
- **UOL 채택 근거 실증**: ST 컴파일러의 레벨 액터 검증은 오브젝트 프로퍼티(하드+소프트)만 스캔하므로 순수 구조체인 UOL 은 원천적으로 대상이 아니다. UOL 리터럴을 담은 ST_Quest 가 컴파일 성공(오전 소프트 리터럴이 막힌 지점 통과).
- **PIE 실검증 통과**: 캠프 위치에서 PIE 를 시작해 Step2 라이브 진입 → UOL 해석 → Manual 스포너 Respawn → 적 스폰과 HUD 목표 갱신(Eliminate all enemies.)까지 확인. UOL 의 컨텍스트 기반 해석에 PIE 픽스업이 내장되어 있어(엔진 ActorLocatorFragment) 별도 처리 없이 동작한다.
- **캐시 없이 매 틱 해석**: 경로 조회 기반 SyncFind 는 소수 항목에서 비용이 무시되고 WP 언로드/재로드를 자연 처리한다 — 태그 시절의 전 액터 순회 캐시·재해석 로직이 통째로 사라졌다.
- **기믹 노드 불변**: 공유 ST 에셋을 여러 배치 인스턴스가 쓰는 기믹 ST 는 인스턴스별 지정이 리터럴로 불가능하므로 바인딩형 Trigger Spawners 를 유지한다. DisplayName 도 충돌하지 않아 손대지 않았다.
- **MCP UOL 값 기입 형식**: 텍스트 임포트는 괄호 필수 `(uobj://actor?payload0=<액터 소프트 경로>)`. 괄호 없이 넣으면 소프트 경로 폴백을 타고 조용히 빈 로케이터가 된다(1차 시도 실패 원인). ToString 주석의 `id=payload` 표기는 실제 포맷과 다르니 주의.

### 계획 대비 달라진 점
- ST_Quest2 는 존재하지 않는 에셋이라(오전 워크로그의 이원화 계획 미실현) 재조립 대상에서 제외했다.
- 저장 시 MCP `save_actor` 가 외부 액터 패키지의 애셋 레지스트리 조회 실패로 에러를 내서, 에디터 Save Content 대화상자(OS 레벨 클릭)로 저장했다.

### 추가 개선: 에디터 가시성 (같은 날 후속)
- 노드 타이틀이 개수만 보여("Wait Spawners Killed (1)") 무엇이 지정됐는지 안 보이던 문제를 GetDescription 개선으로 해소: 로케이터를 에디터에서 해석해 **액터 라벨**(아웃라이너와 동일)을 표시한다 — "Wait Spawners Killed (BP_Enemy)". 3개 초과는 +N 축약, 미해석은 경로 끝 이름, 빈 로케이터는 unset.
- UOL 원소 위젯이 내부 오브젝트 이름(WxSpawner_UAID_…)을 보여주는 것은 엔진 커스터마이제이션 소관이라 손대지 않음 — 노드 타이틀 라벨로 한눈 파악이 해결되므로.
- 빌드·에디터 재실행·States 트리 표시 확인 완료. 표시 전용 변경이라 에셋 영향 없음.

### 후속 과제
- Wait Spawners Killed 의 완료 판정(적 전원 처치 → Success 전이)은 전투가 필요해 자동 검증 못함 — 플레이 확인 필요.
- Step1 의 캠프 지정(WxQuest 의 MarkIndicator·WaitMoveToTarget `targetActorTag=QuestCamp`)은 여전히 액터 태그다. 퀘스트에서 태그를 완전히 걷어내려면 이 두 태스크도 UOL 입력으로 전환해야 한다(승인 범위 밖이라 미착수).
- ST 에디터 디테일 패널의 UOL 픽커 UX(씬 픽커 표시 여부)는 눈으로 확인 안 함 — 값은 MCP 로 기입했고 컴파일·PIE 는 통과.
