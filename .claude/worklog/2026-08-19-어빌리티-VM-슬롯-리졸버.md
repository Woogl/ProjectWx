# 어빌리티 뷰모델을 슬롯별 Resolver 로 만든다

## 계획

### 목표
어빌리티 뷰모델의 아이콘을 채우는 코드가 없어졌다. 아이콘은 전투 플러그인이 쥐고 있어 UI 플러그인이 직접 읽지 못하므로, 뷰모델 생성을 슬롯별 리졸버로 옮겨 게임 모듈이 뷰모델을 만들면서 아이콘까지 넣게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/MVVM/WxViewModelResolver_Ability.h` | 슬롯 태그를 받는 리졸버 선언 | 신규 |
| `Source/WxGame/MVVM/WxViewModelResolver_Ability.cpp` | 태그로 어빌리티를 찾아 뷰모델 생성·초기화·아이콘 주입 | 신규 |
| `Content/UI/Widget/WBP_PlayerSkills` | 슬롯마다 리졸버 뷰모델 항목으로 교체, 컨버전 바인딩 제거 | 수정 |
| `Plugins/WxUI/.../WxViewModel_AbilitySystem.*`, `WxMVVMConversionLibrary.*` | 쓰이지 않게 된 어빌리티 뷰모델 레지스트리·컨버전 함수 제거 | 수정 |

### 접근 방식

리졸버는 게임 모듈 소속이라 어빌리티와 뷰모델을 모두 본다. 도는 시점도 위젯 뷰가 초기화될 때 — 지금 컨버전 함수가 평가되는 그 시점이라 지연 생성 성격이 그대로 유지된다. 계약을 새로 세우거나 아이콘 데이터를 옮기지 않고 벽을 넘는 유일한 자리다.

- **슬롯마다 리졸버 인스턴스**: 리졸버가 어느 어빌리티를 가리키는지는 편집 가능한 태그 컨테이너로 지정한다. 지금 컨버전 함수에 리터럴로 박혀 있는 슬롯 태그가 그 자리로 옮겨간다. 위젯 트리와 슬롯 위젯 클래스는 그대로다.
- **부여되지 않은 어빌리티**: 매칭이 없으면 뷰모델을 만들지 않는다. 그 슬롯은 빈 상태가 된다.
- **정리는 에셋 교체 뒤에**: UI 플러그인의 어빌리티 뷰모델 레지스트리와 컨버전 함수를 먼저 지우면 그 사이 스킬바가 죽는다.

### 구현·결정과 그 이유
- **Outer 를 ASC 로**: 위젯이 아닌 데이터 소스에 매달아야 뷰가 사라져도 수명 규칙이 기존 뷰모델들과 같아진다.
- **빈 태그 컨테이너 거부**: 포함 판정이 빈 컨테이너에는 항상 참이라, 지정을 깜빡한 슬롯이 아무 어빌리티나 집어오는 것을 막는다.
- **매칭 실패 시 뷰모델 없음**: 부여되지 않은 어빌리티를 가리키는 슬롯은 빈 채로 두는 것이 맞다.

### 계획 대비 달라진 점
계획대로. 다만 에셋 교체와 UI 플러그인 정리는 아직 하지 않았다.

### 후속 과제
- WBP_PlayerSkills 의 슬롯 바인딩을 리졸버 방식으로 교체(에디터 작업). 이때 뷰모델 항목 자체를 바인딩 소스로 고를 수 있는지 확인이 필요하고, 막히면 리졸버를 슬롯 위젯 쪽으로 옮기는 갈래로 돌린다.
- 교체 후 UI 플러그인의 어빌리티 뷰모델 레지스트리(`AbilityViewModels`·`FindAbilityViewModel`·`GetOrCreateAbilityViewModel`)와 컨버전 함수 `GetAbilityViewModel` 제거.
- PIE 실동작 확인(아이콘·쿨다운·발동 가능 표시)은 에셋 교체 뒤에 가능하다. 지금은 컴파일 검증까지 마쳤다.
