# 그로기 종료를 GP 0 감지로 복귀

## 계획

### 목표
그로기는 GP가 0이 되면 끝난다. 드레인의 마지막 틱과 처형이 거는 ResetGP가 같은 경로로 그로기를 풀게 한다(모듈 리뷰 WxCombat #1).

4b5b7e95e(09-15)가 정상 종료를 드레인 GE의 자연 만료로만 바꿨다. 그 뒤로 앞잡 종료 때 대상에 거는 ResetGP가 그로기를 풀지 못한다. 처형을 버틴 적은 남은 그로기 시간 동안 그로기 태그와 BT 정지를 유지하고, 같은 그로기 창에서 앞잡이 반복된다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Ability/WxAbility_Groggy.h` | 만료 콜백과 제거 델리게이트 핸들을 GP 변경 콜백과 GP 델리게이트 핸들로 되돌리고, 드레인 시작 함수 반환형을 void로 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbility_Groggy.cpp` | 서버에서 GP 변경을 구독해 0 이하면 종료한다. 만료 콜백과 그 등록·해제, 등록 실패 시 활성화 종료, 몽타주 길이 검사를 걷는다 | 수정 |

- 두 파일을 4b5b7e95e 직전 내용으로 정확히 되돌린다. 그 뒤로 두 파일과 의존 헤더는 바뀌지 않았다.
- 다음 주석은 GP 0 종료를 전제로 적혀 있어, 복귀하면 그대로 맞으므로 손대지 않는다: ResetGP 헤더, 어트리뷰트 셋의 그로기 진입 주석, 드레인 MMC의 초과 차감 주석, 처형 헤더.
- 09-15의 Codex 작업 기록은 이력으로 남긴다.

### 접근 방식
- **드레인이 GP를 남긴 채 끝나는 경로가 없다**:
  - MMC는 실제 틱 수로 나누고 조금 넘치게 뺀다.
  - 엔진은 프레임이 튀어 밀린 틱을 몰아 실행하고, 만료 순간에 걸린 마지막 틱도 효과를 걷기 전에 실행한다.
  - 그로기 중 GP를 올리는 경로(피격, 퍼펙트 가드 반사)는 모두 그로기에서 막히고, GP를 바꾸는 GE 에셋도 없다.
  - 그래서 만료 종료는 막아 준 경우 없이 ResetGP 해제만 끊었다. 사용자와 합의해 만료 안전장치도 두지 않는다.
- **GP 0 종료 복귀**:
  - 서버가 드레인을 걸 때 GP 변경을 구독하고, 새 값이 0 이하면 정상 종료한다.
  - 드레인 마지막 틱과 앞잡 종료의 ResetGP가 모두 이 알림으로 들어온다.
  - 종료 정리는 드레인을 걷은 뒤 구독을 푼다.
- **재진입은 09-15 이전과 같은 경로라 안전하다**:
  - 만료 순간의 마지막 틱 안에서 종료가 드레인을 먼저 걷으면, 엔진 만료 처리가 제거 대기를 보고 빠진다.
  - 방송 중 델리게이트 해제는 멀티캐스트가 허용한다.
- **함께 빠지는 것**: 만료 설계를 위해 들어온 실패 처리(드레인 적용·알림 등록 실패, 비정상 몽타주 길이 → 활성화 실패)도 빠진다. 몽타주가 비정상이면 첫 테스트에서 그로기가 안 풀리는 모습으로 바로 드러나므로 가드를 두지 않는다.
- 사망 폴링 종료, HitStop, 몽타주 폴링, BT 정지·재개는 그대로다.

### 구현·결정과 그 이유
- **4b5b7e95e 직전 코드로 그대로 복귀**: 그 뒤로 두 파일과 의존 헤더가 바뀌지 않았다. 그래서 09-15 이전에 쓰던 종료·정리 순서를 손대지 않고 되살렸다.
- **만료 안전장치를 두지 않음**: 드레인이 GP를 남긴 채 끝나는 경로가 없어 막을 경우가 없다. 남기면 종료 경로가 둘이 되어, 읽는 사람이 둘의 관계를 매번 따져야 한다.
- **0에 매우 가까운 값도 종료로 봄(사용자 요청)**: 지금은 초과 차감이 마지막 틱을 0 아래로 보내고 클램프가 정확히 0을 만든다. 그래도 부동소수 잔여가 남으면 종료 조건이 성립하도록 했다. 허용오차는 프로젝트 관례대로 기본값을 쓴다.
- **주석은 손대지 않음**: ResetGP 헤더, 어트리뷰트 셋, 드레인 MMC, 처형 헤더의 설명이 모두 GP 0 종료를 전제로 적혀 있어 복귀 후 그대로 맞다.
- **검증**:
  - 두 파일이 직전 버전과 같음을 diff로 확인한 뒤, 조건 한 줄을 더했다.
  - WxEditor Win64 Development 빌드는 복귀 직후와 조건 추가 후 두 차례 모두 성공했다(그로기 cpp 컴파일, Result: Succeeded).

### 계획 대비 달라진 점
- 사용자 요청으로 종료 조건에 0 근사 판정을 더했다. 그래서 cpp는 직전 버전과 이 한 줄이 다르다.

### 후속 과제
- PIE는 실행하지 않았다(unreal-mcp 미연결). 확인할 항목:
  - 앞잡 종료와 함께 그로기가 풀리는지(태그 제거, BT 재개, 그로기 몽타주 재생 없음, 같은 창 재처형 프롬프트 없음)
  - 처형 없는 그로기가 몽타주 길이 뒤에 풀리는지
  - 종료 직전 HitStop 증상이 재발하는지
- 09-15 "종료 직전 HitStop이면 그로기가 안 끝남" 버그는 원인을 모르는 채로 남는다. 재현되면 GP 잔여가 아닌 경로(몽타주 정지·복제)부터 조사한다.
