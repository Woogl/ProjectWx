# 체크포인트 시작지점 명시화: 디자이너 태그 + 에디터 검증

## 계획

### 목표
레벨 최초 접속 시작지점 규칙을 암묵(매직 스트링 `"Default"` + GUID 자동 베이킹)에서 명시로 바꾼다. 식별자는 디자이너가 지정하는 읽기 좋은 PlayerStartTag로 되돌리고, 최초 시작지점은 에디터에 보이는 `bIsDefaultStart` 프로퍼티로 지정하며, 실수는 런타임이 아니라 에디터 타임(복제 초기화 + Map Check)에서 잡는다.

### 접근 방식
- **식별자 = 디자이너 지정 태그**: GUID 자동 베이킹을 제거하고 PlayerStartTag를 사람이 읽는 이름(`CP_Chapel` 등)으로 되돌린다. 세이브 구조·WxSave 플러그인은 무변경(태그 필드 그대로).
- **최초 시작지점 = 명시 프로퍼티**: `EditInstanceOnly bIsDefaultStart`. `ChoosePlayerStart`는 저장 태그가 없을 때 이 플래그가 켜진 첫 체크포인트를 시작지점으로 쓴다.
- **실수 방지는 에디터 타임에**: 복제 시 태그·플래그를 초기화(조용한 중복 차단)하고, `CheckForErrors`(Map Check)로 태그 미지정·태그 중복·플래그 다중을 액터 점프 가능한 에러로 리포트한다.
- **폴백 분기**: 플래그된 체크포인트가 없을 때, 레벨에 체크포인트가 있으면 기획 실수로 보고 에러 로그, 아예 없으면(메뉴/테스트 맵) 정상으로 보고 무로그. 양쪽 다 엔진 기본 선택으로 폴백해 플레이는 계속.

### 구현·결정과 그 이유
- **`bIsDefaultStart` 은 public 게터로 노출**: 다른 클래스인 스폰 컴포넌트가 읽어야 하나, friend 남발 대신 얇은 접근자(`IsDefaultStart()`)를 뒀다. 프로퍼티 자체는 `EditInstanceOnly protected` 유지.
- **실수 방지를 런타임이 아닌 에디터 타임에**: 복제 시 태그·플래그 초기화로 조용한 중복을 원천 차단하고, `CheckForErrors`(Map Check)로 미지정·중복·다중을 액터 점프 가능한 에러로 노출. 기획자 대면 에디터 툴링이라 "저ROI 런타임 진단 가드 지양" 방침과 상충하지 않는다.
- **폴백 로그를 체크포인트 유무로 분기**: 최초 시작지점 미발견 시, 체크포인트가 있으면(기획 실수) 에러 로그, 없으면(메뉴·테스트 맵) 무로그. 같은 순회에서 `bAnyCheckPoint` 를 함께 판정해 추가 순회 없이 처리. 소음으로 진짜 에러가 묻히는 것을 피한다.
- **PIE 시작지점 최우선(ⓘ 신규)**: 저장 태그가 "여기서 플레이"를 덮던 개발 편의 저하를 없애려 `APlayerStartPIE` 를 0순위로 추가(Lyra 패턴).

### 계획 대비 달라진 점
- `APlayerStartPIE` 헤더 경로는 `GameFramework/` 가 아니라 `Engine/PlayerStartPIE.h` 였다(빌드 1차 실패 후 수정).

### 후속 과제
- 에디터 확인(사용자): Map Check 로 검증 에러 노출 확인 → 각 레벨 체크포인트에 읽기 좋은 태그 지정·`bIsDefaultStart` 1개 지정·기존 `"Default"` PlayerStart 정리 → 신규 세이브로 최초 접속·부활 동선 확인.
