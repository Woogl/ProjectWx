# 상호작용 사거리 판정을 어빌리티로 이관

## 계획

### 목표
`IWxInteractable::IsActorInRange` 를 제거한다. 사거리 판정은 대상이 지켜야 할 계약이 아니라 소비자 한 곳(서버 권위 검증)의 판정이므로, 계약에서 빼고 유일 호출부인 상호작용 어빌리티로 옮긴다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxInteractable.h` | `IsActorInRange` 선언·주석 삭제, 클래스 주석의 함수 참조 정리 | 수정 |
| `WxInteractable.cpp` | `IsActorInRange` 정의 삭제, 불필요해진 콜리전·액터 인클루드 정리 | 수정 |
| `WxAbility_Interact.h/.cpp` | private 헬퍼 `IsInRange` 추가, 호출부 교체, 콜리전 인클루드 추가 | 수정 |
| `WxInteractionScannerComponent.cpp` | 삭제된 이름을 참조하던 주석을 "서버 사거리 검증" 으로 정정 | 수정 |

### 접근 방식
- **계약은 순수 가상만**: 액터 전용 전환에서 정적 `Find` 를 뺀 것과 같은 방식이다. 계약에서 정적 유틸을 지우고 판정 본문은 유일 소비자 쪽에 그대로 둔다.
- **판정 자체는 유지**: 감지·선택이 클라 로컬이라 서버 권위 사거리 검증이 변조 클라 차단의 유일한 장치다. 프리미티브 순회 + `OverlapComponent` 구 테스트와 전제 위반 `ensure` 를 동일하게 옮겨 동작 변화가 없다.
- **반경 소유가 자연스러워짐**: 반경(`ScanRadius`)을 이미 어빌리티가 들고 있으므로, 헬퍼가 인자 대신 멤버를 읽는다.

### 구현·결정과 그 이유
- **계약에서 뺐지 판정을 없애지 않았다**: 감지·선택이 클라 로컬이라 서버 사거리 검증이 변조 클라의 원거리 상호작용을 막는 유일한 장치다. 계약에서 빠질 이유(소비자가 하나뿐인 정적 유틸)와 판정이 사라져야 할 이유는 다르다.
- **널 검사 생략**: 호출부 `ExecuteInteract` 가 이미 `Selected` 를 걸러 넘기므로 옮기면서 중복 가드를 지웠다.
- **반경을 인자에서 멤버로**: 소비자가 하나이고 그 소비자가 `ScanRadius` 를 이미 소유하므로 인자로 되받을 이유가 없다.

## 후속: 사거리 판정 점검과 ensure 제거

이관 후 판정의 유효성·필요성을 점검했다.

- **기준은 정합**: 원점(폰 위치)·반경(양쪽 150, 오버라이드 에셋 없음)·대상 자격(응답 매트릭스를 보지 않는 오브젝트 쿼리 vs 바디 직접 테스트)이 클라 스캔과 일치한다. 콘텐츠 쪽 전제도 성립한다(NPC 메시는 QueryOnly + 응답 전부 Ignore 로도 양쪽에 잡힌다).
- **판정은 유지**: 지금은 스탠드얼론이라 안티치트 가치가 없지만, 클라 목록이 최대 0.1초 낡고 리스폰·세이브 로드 직후 선택이 이전 위치를 가리킬 수 있다. 활성·자격 검사는 거리를 보지 않으므로 서버에 남은 유일한 거리 개념이다.
- **`ensureMsgf` 제거**: 전제(쿼리 콜리전 없음)가 깨진 액터는 스캐너의 구 오버랩에도 안 잡혀 선택 목록에 오르지 못한다 — 즉 어빌리티까지 도달할 길이 없어 "저작 실수를 개발 빌드에서 드러낸다"는 목적을 달성할 수 없었다. 콜리전을 내리며 활성을 유지하는 대상도 없다(AWxTriggerDevice 는 콜리전이 곧 활성값이라 앞단 게이트에 막힌다). 전제 설명은 헤더 주석에 남겼다.

보류한 제안(요청 시 적용): 서버 반경 여유(스캔 지연·MP 위치 지연 흡수), 거부 경로 Verbose 로그.
