# PIE 시작 시 항상 새 세이브파일로 시작

## 계획

### 목표
PIE로 시작하면 이전 세션의 저장 상태를 이어받지 않고 매번 깨끗한 새 세이브파일로 시작하도록 한다. 지금은 PIE 감지 시 기본 슬롯 "Test"를 디스크에서 자동 로드해 이전 체크포인트 등이 이어진다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxSave/.../Private/WxPersistenceGameSubsystem.cpp` | `Initialize()`의 `#if WITH_EDITOR` PIE 자동 로드 블록 제거 → 전 경로가 `StartNewSaveFile`로 통일, 주석 정리 | 수정 |
| `Plugins/WxSave/.../Public/WxPersistenceGameSubsystem.h` | 클래스 doc·`DefaultSlotName` 주석에서 "PIE 자동 로드" 문구 갱신 | 수정 |
| `Plugins/WxSave/README.md` | `DefaultSlotName` 설명의 "PIE 자동로드" 문구 제거 | 수정 |
| `Docs/Programmer/WxSave_PersistenceLab_Comparison.md` | PIE 자동 로드 서술 행을 실제 동작에 맞게 갱신 | 수정 |

### 접근 방식
- **자동 로드 제거로 경로 통일**: 자동 로드를 없애면 PIE·스탠드얼론·패키지 모두 `StartNewSaveFile(DefaultSlotName, 0, ...)`로 빈 새 슬롯을 시작하므로 `#if WITH_EDITOR` 분기 자체를 제거한다.
- **명시적 로드 경로는 불변**: UI의 `LoadFromFile`/`ReloadFromFile`, 사망 리스폰의 월드 리로드는 그대로라 로드 기능은 유지된다. 사라지는 건 시작 시 자동 로드뿐.

### 구현·결정과 그 이유
- **PIE 자동 로드 제거로 경로 단일화**: PIE 감지 분기가 유일한 자동 로드 원천이었다. 없애니 전 모드가 동일하게 새 SaveGame 을 시작 → `#if WITH_EDITOR` 분기 자체가 불필요해져 통째로 제거.
- **`DefaultSlotName` 공유 개념 폐기(작업 중 사용자 지시)**: PIE 자동 로드가 사라지고 BP용 `GetDefaultSlotName` 게터도 이미 제거된 상태라, 이 상수를 참조하는 곳은 서브시스템 `.cpp` 내부뿐이었다. 슬롯 이름 자체는 없앨 수 없다(체크포인트 오토세이브 `SaveToFile()` 무인자가 활성 슬롯 파일명을 필요로 함) — 그래서 `Initialize` 가 부팅 슬롯명을 한 번 정하는 리터럴로 강등하고 공용 상수/개념은 폐기했다.
- **빈-슬롯 폴백 제거**: 폴백이 참조하던 기본값이 사라졌고, 유일한 실사용 호출부(`Initialize`)는 유효한 리터럴을 넘긴다. 빈 슬롯은 호출자(BP) 책임으로 두는 편이 개념을 완전히 없애는 데 부합.

### 계획 대비 달라진 점
- 승인받은 계획은 PIE 자동 로드 제거만이었으나, 작업 중 사용자가 "개발 단계 슬롯 이름 개념 자체를 없애자"고 지시해 `DefaultSlotName` 상수·네임스페이스 폐기까지 확장했다.
