# 엔진 표준(태그 기반) 충전형 쿨다운으로 전환

## 계획

### 목표
모든 어빌리티가 태그를 부여하지 않는 공용 쿨다운 GE를 공유하던 구조를, 어빌리티별 쿨다운 GE + 고유 쿨다운 태그 + 엔진 스택으로 바꾼다. 스택 1개 = 충전 1개, GE 지속시간 = 1충전 회복 시간이 되어 순정 쿨다운 API가 그대로 1충전 값을 내고, UI 진행률도 전체 쿨다운이 아닌 현재 충전 기준이 된다.

### 접근 방식
- **어빌리티별 GE + 태그**: 엔진 스택 병합은 `Spec.Def`(GE CDO) 일치로만 판정하므로(`GameplayEffect.cpp:3675`) 공용 GE로는 어빌리티끼리 쿨다운이 섞인다. DynamicAssetTag도 식별 키가 아니라 오히려 스택 시 동일한지 `ensureMsgf`로 검사한다(`:4266`). 애셋을 늘리지 않도록 파생 GE는 C++로 둔다.
- **직렬 회복**: `NeverRefresh` + `RemoveSingleStackAndRefreshDuration`. 지속시간은 `UWxMMC_CooldownDuration`이 소스 어빌리티의 테이블 행에서 읽는다(`UWxMMC_Cost`와 같은 패턴).
- **판정**: 순정 `CheckCooldown`은 태그 유무만 보므로, 남은 충전이 있으면 그 앞에서 통과시키고 아니면 `Super`에 넘겨 실패 태그까지 순정대로 채운다.

### 구현·결정과 그 이유
- **스택 식별을 태그가 아닌 GE 클래스로 나눈 이유**: 엔진 병합 판정에 태그가 끼어들 자리가 없다. 공용 GE를 유지하면서 스택만 켜면 도지 쿨다운 위에 스킬 쿨다운이 얹히고 스펙이 뒤 시전자 것으로 교체된다.
- **`AggregateByTarget`**: 쿨다운은 항상 자기 자신에게 걸린다. `AggregateBySource`는 인스티게이터 ASC가 비면 스택이 갈라져 GE가 둘로 늘어나는데, 대상 기준이면 그 경로가 없다.
- **`StackLimitCount = 0`**: 충전 상한은 테이블의 `MaxRecharges`이고 이를 아는 곳은 어빌리티뿐이라 GE에 두지 않았다. 상한을 담보하는 지점은 `CheckCooldown` 하나다.
- **지속시간을 SetByCaller에서 MMC로**: 순정 `ApplyCooldown`이 스펙을 직접 만들어 적용하므로 SetByCaller를 실을 자리가 없다. MMC로 옮겨 오버라이드를 통째로 지웠다.
- **뷰모델이 순정 조회 API 대신 직접 순회하는 이유**: 순정 API는 스택 수를 주지 않고 호출마다 배열을 새로 할당한다. 매 프레임 도는 경로라 태그로 GE 하나를 찾아 스택·잔여·지속시간을 한 번에 읽는다.
- **표시도 서버 진실만 따른다**: 스택 반납은 서버 권위라 회복 시점이 지나도 제거 복제가 올 때까지는 소모된 상태다. 뷰모델에서 이를 미리 돌려주면 발동 판정(같은 복제 값을 본다)과 어긋나 "게이지는 찼는데 안 나가는" 구간이 생기므로, 선반영하지 않고 원격 클라이언트에서 회복 표시가 RTT 절반만큼 늦는 쪽을 택했다.
- **쿨다운 GE는 각 어빌리티가 지정한다**: 베이스에는 기본값을 두지 않는다(두면 어빌리티끼리 스택이 섞인다). 식별 태그로 GE를 유도하는 방식도 한 번 구현했다가 되돌렸다 — 결선 실수는 검증 두 겹이 이름까지 찍어 잡아 주는 반면, 자동 해석은 이름 규칙이라는 불변식과 문자열 유도·클래스 스캔을 상시 짊어져야 하고 어빌리티를 열어도 무엇이 걸리는지 보이지 않는다. 파생 클래스 18개는 그대로 두고 "고르는 메뉴"로 쓴다.
- **쿨다운을 실제로 쓰는 어빌리티만 짝을 둔다**: 처음엔 플레이어 어빌리티 전체를 미러했다가, 회피·스킬·궁극기 셋만 남겼다. 리액션(GuardReact·HitReact 등)과 Override 계열(Finisher)은 강제로 나가야 해서, 상태 유지형(Sprint·Guard·LockOn)은 쿨다운으로 제어할 대상이 아니라서, 적 패턴은 BT가 간격을 잡아서 제외했다. 트리거 패시브는 쿨다운을 걸려면 `CommitAbility`가 필요한데 지금 구조가 커밋하지 않아 함께 뺐다.
- **누락 검증을 두 겹으로**: 이 구조의 유일한 구멍이 "쿨다운 수치는 있는데 전용 GE를 안 고른 어빌리티"다. 에디터 검증(`IsDataValid`)이 에셋 저장·Validate 시점에, 런타임 로그가 테이블만 고친 경우에 각각 잡는다.

### 코드 리뷰에서 고친 것
- **회복 대기 중 티커가 꺼지던 문제**: 스택을 미리 돌려주면 GE가 살아 있는데도 소모 0으로 보여 티커가 멈춘다. 그 구간에 다시 쓰면 새 GE가 아니라 스택으로 얹혀 적용 통지(`OnActiveGameplayEffectAddedDelegateToSelf`)가 오지 않아 표시가 만충으로 굳었다. 선반영을 없애자 GE가 살아 있는 동안 스택이 항상 1 이상이라 이 구멍이 함께 닫혔다.
- **지속시간 0인 쿨다운 GE가 영구히 남던 문제**: 엔진은 `DurationBaseValue > 0`일 때만 만료 타이머를 건다(`GameplayEffect.cpp:4440`). 어빌리티 컨텍스트 없이 적용돼 MMC가 0을 내면 쿨다운이 풀리지 않으므로, 경고를 남기고 즉시 만료되게 했다.
- **태그를 빠뜨린 쿨다운 GE 미검출**: 검증이 GE 존재만 봐서, 태그 없는 GE는 순정 판정을 그냥 통과했다. 두 검증 모두 `GetCooldownTags()` 비어 있음으로 바꿨고, 태그리스 설계 때문에 꺼 두었던 `AbilitySystem.WarnCooldownEffectWithoutTags=0`도 걷어냈다.

### 계획 대비 달라진 점
- 스태킹 집계를 `AggregateBySource` → `AggregateByTarget`으로 바꿨다(위 이유).
- 애초 계획(공용 GE 유지 + 테이블 값을 표시 분모로 공급)을 한 번 구현했다가, 엔진 표준 방식 요청에 따라 전면 교체했다. 그때 넣었던 `WxViewModelResolver_Ability`의 1충전 시간 공급은 되돌렸다(분모가 GE 지속시간에서 바로 나온다).
- 파생 GE를 어빌리티 BP에서 고르게 하려던 것을, 식별 태그 기반 자동 해석으로 바꿨다. 저작 편의와 결선 실수 방지를 함께 챙기기 위해서다.

### 후속 과제
- 스킬 4종이 `Cooldown.Skill.1` 하나를 공유한다. 슬롯별로 따로 굴려야 하면 슬롯마다 태그·파생 GE를 만들어 각 BP에서 지정한다.
- 쿨다운이 새로 필요한 어빌리티가 생기면 `Cooldown.X` 태그와 파생 GE 클래스를 만들고 어빌리티 생성자(또는 BP)에서 지정한다. 빠뜨리면 에디터 검증·런타임 로그가 지목한다.
- 트리거 패시브에 쿨다운을 붙이려면 `UWxAbility_Passive::ActivateAbility`가 중복 지급 차단 뒤에 `CommitAbility`를 불러야 한다.
- 인게임 검증 미완: 충전 소모·직렬 회복·게이지 0→100% 반복, 어빌리티 간 간섭 없음, `WxEffect_NoCooldown` 동작, 리슨 서버 2인 예측·복제.
