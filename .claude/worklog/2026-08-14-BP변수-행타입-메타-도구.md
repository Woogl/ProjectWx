# 블루프린트 변수 메타 기입 도구

## 계획

### 목표
보물상자의 보상 행은 블루프린트 변수라 테이블 픽커에 모든 테이블이 뜬다. 같은 값이 흘러가는 C++ 태스크 필드에는 행 타입 메타가 이미 붙어 있지만, 편집하는 자리가 BP 변수라 그쪽 제한이 걸리지 않는다. BP 변수에 메타를 기입하는 도구를 만들고 보물상자에 적용한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxToolset/.../WxBlueprintToolset.h/.cpp` | BP 변수 메타 기입 도구 | 신규 |
| `WxToolset/.../WxToolsetModule.cpp` | 새 툴셋 등록·해제 | 수정 |
| `/Game/WorldObject/Gimmick/BP_TreasureChest` | 보상 행 변수에 보상 행 타입 메타 기입 | 에셋 |

빌드 설정은 손대지 않는다 — 필요한 에디터 모듈이 이미 의존에 들어 있다.

### 접근 방식
- **생성자 주입은 불가**: 블루프린트는 컴파일할 때마다 프로퍼티를 새로 만들고 변수 서술자의 메타 배열로 다시 채운다. 생성자에서 프로퍼티에 직접 메타를 넣어도 다음 컴파일에 사라진다. 권위 있는 저장소는 에셋 안의 변수 서술자이므로 그쪽에 기입한다.

- **엔진 진입점 사용**: 서술자 배열을 직접 만지지 않고 `FBlueprintEditorUtils::SetBlueprintVariableMetaData` 를 쓴다. 변경 통지와 컴파일 마킹이 그 안에 들어 있어 순정 편집과 같은 경로가 된다.

- **StateTree 파라미터와 달리 병합**: 파라미터 쪽 도구는 메타를 통째로 교체하지만, BP 변수의 메타 배열에는 카테고리·툴팁처럼 엔진이 쓰는 항목이 함께 살 수 있다. 통째로 지우면 그것들까지 날아가므로 넘긴 키만 덮어쓴다.

- **별도 툴셋 클래스**: 기존 툴셋은 StateTree 저작 전용이라 BP 변수 편집이 섞이면 성격이 흐려진다. 모듈이 툴셋을 수동 등록하므로 신설 클래스도 같은 자리에 등록한다.
