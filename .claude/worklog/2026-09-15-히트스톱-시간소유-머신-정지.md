# 히트스톱은 캐릭터의 시간을 가진 머신만 건다

## 계획

### 목표
네트워크에서 히트스톱이 위치 보정과 외삽 튐을 만든다(WxGame 모듈 리뷰 1번). 원인은 시간을 스스로 굴리지 않는 원격 클라 폰의 서버 사본까지 서버 태그로 이동과 애니를 멈추는 데 있다. 캐릭터의 시간을 가진 머신만 멈추게 해 동기화 문제 자체를 없애고, 클라에서도 애니와 이동이 온전히 서게 한다.

### 접근 방식
- **시간을 가진 머신만 멈춘다**: 원격 클라 폰의 서버 사본은 이동도 포즈 틱도 클라가 보낸 무브 안에서만 진행한다. 소유 클라가 정지 동안 무브를 만들지 않으면 서버 사본은 받을 무브가 없어 같은 구간만큼 저절로 멈추고, 다르게 재생할 무브도 없어 보정이 오지 않는다.
- **로컬 조종 캐릭터는 이동 틱을 건너뛴다**: 소유 클라·스탠드얼론·리슨 호스트 자기 폰·서버 AI가 해당한다. 입력은 비워 쌓이지 않게 한다.
- **서버 사본에는 아무것도 걸지 않는다**: 애니 배속도 걸지 않는다. 걸면 클라가 아직 멈추지 않은 무브에서 루트모션과 노티파이가 멈춘다.
- **시뮬 프록시는 표시만 멈춘다**: 애니는 태그로 세우고, 서버가 멈춰 복제 갱신이 끊긴 동안 보존된 속도로 외삽하지 않게 한다.

### 구현·결정과 그 이유
- **무브 플래그 동기화 대신 시간 소유로 정리**: 처음에는 정지 여부를 세이브드 무브 플래그에 싣는 설계를 검토했다. 세이브드 무브·재생·루트모션 재시뮬까지 손대야 해서 사용자가 더 근본적이고 간단한 해법을 요청했다. 서버 사본은 이동도 포즈 틱도 클라 무브로만 진행하므로, 클라가 무브를 만들지 않으면 알려 줄 것 없이 같이 멈춘다. 동기화할 대상을 없애는 쪽을 택했다.
- **틱 비활성화가 아니라 틱 안에서 반환**: 태그를 매 틱 직접 보면 켜고 끄는 상태가 없다. 입력을 비워 두면 풀릴 때 쌓인 이동 입력이 한꺼번에 나가지 않는다.
- **서버 사본 판별은 엔진 비트로**: `bOnlyAllowAutonomousTickPose`는 엔진이 "이 메시의 포즈 틱은 클라 무브가 몬다"고 정한 값이다. 빙의·해제 때 엔진이 갱신하므로 역할 조합을 따로 따지지 않는다.
- **시뮬 프록시는 외삽만 막는다**: 위치 복제와 스무딩은 그대로 두고, 서버가 멈춰 갱신이 끊긴 동안 보존된 속도로 미끄러지는 것만 없앤다.
- **검증**: UE 5.8.1 WxEditor Win64 Development 빌드 성공. 같은 빌드에 다른 작업의 WxCombat 헤더 변경 3건이 함께 컴파일됐다.

### 후속 과제
- 네트워크 PIE 실측 미실시(에디터 MCP 연결 끊김). 2클라 PIE에서 `Net PktLag=100`, `p.NetShowCorrections 1`로 확인할 것:
  - 방향키를 누른 채 적중
  - 루트모션 공격 적중(공격자·피격자 양쪽)
  - 넉업 적중 시 보정 0건
  - 스탠드얼론 회귀
- 연속 피격으로 클라 무브가 0.25초(`MAXCLIENTUPDATEINTERVAL`) 넘게 끊기면 서버 강제 갱신 뒤 보정이 올 수 있다.
- 제3자 화면에서 원격 플레이어의 정지 구간이 태그 기준이라 실제 무브 중단과 약 RTT 어긋난다.
- WxGame 리뷰 4번(`Move` 가드 주석)은 이번 변경으로 입력이 틱마다 비워지므로 그대로 유효하다. 별건으로 남긴다.

# 후속: 코드 리뷰 반영

## 계획

### 목표
위 변경을 코드 리뷰해 엔진 소스로 확인한 회귀 4건과 정리 거리 2건을 고친다.
- 틱을 통째로 건너뛰어 정지 중 도착한 보정의 무브 재생이 밀리고, 그동안 캐릭터가 되감긴 위치에 서 있다.
- 로컬 조종 조건 때문에 컨트롤러 없이 이동을 굴리는 캐릭터가 정지에서 빠진다.
- 0.25초를 넘는 정지에서는 서버 강제 갱신이 타임스탬프를 올려 재개한 무브가 거부된다.
- 서버 사본에서 배속 대입을 건너뛰어 드문 전환에서 배속 0이 굳을 수 있다.
- 정지한 로컬 캐릭터가 발판을 따라가지 않는다.
- 히트스톱 GE 주석이 낡았다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/Component/WxCharacterMovementComponent.h/.cpp` | `TickComponent` 재정의를 `ControlledCharacterMove` 재정의로 교체(정지 중 발판 추종 포함), `ForcePositionUpdate` 재정의 추가, 태그 판정을 private 헬퍼로 통합 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/WxHitStopComponent.cpp` | 조기 반환 대신 서버 사본 조건을 배속 계산에 합침 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Effect/WxEffect_HitStop.h` | 애니·이동 정지 주체 주석 정정 | 수정 |

### 접근 방식
- **무브 생성만 건너뛴다**: 엔진은 `ControlledCharacterMove`를 입력 비우기와 보정 재생 다음에 부른다. 대상은 로컬 조종 캐릭터와 컨트롤러 없이 이동을 굴리는 권위 캐릭터이고, 원격 클라 폰의 서버 사본은 부르지 않는다. 여기서 반환하면 재생은 제때 돌고, 조종 여부를 따로 묻지 않아도 대상 범위가 맞는다.
- **정지 중에도 발판은 따라간다**: 서버 사본이 무브 사이에 하는 발판 갱신을 같은 자리에서 해 두 머신의 기준 위치를 맞춘다.
- **정지 중 강제 갱신 거부**: 서버가 대신 움직이지 않으면 클라 타임스탬프와 서버 기준 시각이 벌어지지 않는다.
- **배속은 늘 대입**: 서버 사본이면 멈추지 않는 값(1)을 대입해, 다음 태그 이벤트에서 반드시 참값으로 돌아오게 한다.

# 후속: 강제 갱신 설정

## 계획

### 목표
위에서 추가한 `ForcePositionUpdate` 재정의는 서버 태그 구간 [T0, T0+D] 동안만 막는다. 그런데 서버가 보는 클라 무브 공백은 [T0+RTT, T0+RTT+D]다. 공백이 강제 갱신 간격(0.25초)을 넘으면 태그가 풀린 꼬리 구간에서 반드시 강제 갱신이 걸리고, 재개된 무브가 과거 타임스탬프로 거부된다. 즉 재정의는 강제 갱신을 미룰 뿐 막지 못한다. 재정의를 걷고 강제 갱신 간격 자체를 올린다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/Component/WxCharacterMovementComponent.h/.cpp` | `ForcePositionUpdate` 재정의 제거 | 수정 |
| `Config/DefaultGame.ini` | `[/Script/Engine.GameNetworkManager]` `MAXCLIENTUPDATEINTERVAL=1.0` 추가 | 수정 |

### 접근 방식
- **판정 창을 맞추지 않고 문턱을 올린다**: 서버는 클라가 무브를 멈춘 구간을 정확히 알 수 없다. 창을 맞추려면 상태가 늘어난다. 히트스톱은 적중당 0.1초라 1초 문턱이면 연속 정지도 넘지 않는다.
- **0(기능 끄기)은 쓰지 않는다**: 0이면 CMC가 `MaxMoveDeltaTime`(0.125)보다 작다고 캐릭터마다 경고를 남긴다.
- **PvE라 방어 필요성이 낮다**: 강제 갱신은 핑을 인위로 튀기는 치트 방어용이다.

- **코드가 아니라 설정으로 해결**: 서버는 클라가 히트스톱으로 무브를 멈춘 구간을 알 수 없다. 코드로 막으려면 그 구간을 추정하는 상태가 필요하다. 엔진 문턱값 하나를 올리면 같은 문제가 상태 없이 사라진다.
- **값은 1.0**: 적중당 0.1초 히트스톱이 겹쳐도 1초를 넘기기 어렵다. 엔진 기본 `MaxMoveDeltaTime`(0.125)보다 커서 CMC 경고 조건(`MaxMoveDeltaTime > MAXCLIENTUPDATEINTERVAL`)에도 걸리지 않는다.

- **검증**: UE 5.8.1 WxEditor Win64 Development 빌드 성공. ini 값은 `GlobalConfig` 속성이라 에디터·게임을 다시 실행하면 적용된다.
