# 점유 판정을 WxAbilityBase로 이관 — ASC 표면 축소

## 계획

### 목표
점유자 조회가 ASC에 함수 둘(수집 본체와 판별 보조)로 걸쳐 있고 반환형에 인라인 할당자까지 드러나 읽기 어렵다. 조회를 어빌리티 클래스의 static 함수 하나로 이관해 ASC 확장을 줄이고, 열거와 판정을 한 곳에 모은다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxAbilityBase.h/.cpp` | static `FindActivationGroupBlocker(ASC, Candidate)` 신설, `CanActivateAbility`의 점유자 루프를 이 호출 한 줄로 축약 | 수정 |
| `WxAbilitySystemComponent.h/.cpp` | `FindActivationGroupBlockers`·`AsActivationGroupBlocker` 삭제, 입력 버퍼 판정을 새 static 호출로 교체 | 삭제·수정 |
| `WxCharacterBase.cpp` | 점프 게이트를 새 static 호출로 교체 | 수정 |

### 접근 방식
- **배열 제거**: 모든 Wx 어빌리티는 기반 생성자가 InstancedPerActor를 강제하므로 스펙당 인스턴스는 하나뿐이다. 엔진의 단일 인스턴스 접근자로 복제/비복제 이중 루프와 수집 배열, 인라인 할당자가 통째로 사라진다.
- **첫 차단자 반환**: 점유자 전원을 순회하되 후보를 실제로 막는 첫 점유자를 만나면 바로 반환한다. "전원 통과해야 발동"(08-24) 의미는 그대로고, 배열을 만들지 않아 홀드 입력 매 프레임 비용(08-25)도 더 싸진다.
- **후보 없는 호출은 존재 질의**: 입력 버퍼와 점프 게이트는 점유자가 있는지만 물으므로, 후보 없이 부르면 첫 점유자를 반환하는 것으로 겸한다.
- **원칙 강화**: "ASC는 태그를 모르고 판정은 어빌리티가 조립한다"(08-22)에서 이제 열거까지 어빌리티로 넘어간다. ASC와 캐릭터는 결과만 받아 쓴다.

| `WxAbilitySystemComponent.h/.cpp` | 점유자 수집·판별 함수 둘과 전방선언 삭제, 입력 버퍼 판정을 새 static 호출로 교체 | 삭제·수정 |
| `WxCharacterBase.cpp` | 점프 게이트를 새 static 호출로 교체, 어빌리티 헤더 포함 복원 | 수정 |

### 구현·결정과 그 이유
- **수집 대신 첫 차단자 반환**: 호출부 셋 모두 "막히는가"라는 예/아니오만 필요했지 명단이 필요한 곳은 없었다. 후보를 실제로 막는 첫 점유자를 만나는 즉시 반환하니 수집 배열과 인라인 할당자 반환형이 통째로 사라지고, 전원 순회이므로 "점유자 전원 통과"(08-24) 의미는 유지된다.
- **단일 인스턴스 접근자로 이중 루프 제거**: 모든 Wx 어빌리티는 기반 생성자가 InstancedPerActor를 강제하므로 스펙당 인스턴스가 하나뿐이다. 복제/비복제 배열을 따로 훑던 루프를 엔진 접근자 한 줄로 접었고, 전제는 주석으로 남겼다.
- **ASC가 아니라 어빌리티의 static으로**: 점유·차단을 정의하는 상태(그룹·창·캔슬 지목 태그)가 전부 어빌리티에 있으므로 열거까지 어빌리티가 맡는 게 "판정은 어빌리티가 조립한다"(08-22)와 맞다. ASC와 캐릭터는 결과만 받아 쓰고, `CanActivateAbility`의 Wx ASC 캐스트도 필요 없어졌다.
