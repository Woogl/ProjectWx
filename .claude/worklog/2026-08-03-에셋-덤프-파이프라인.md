### 접근 방식
- **실행 수단**: 헤드리스 커맨드릿(`-run=pythonscript`)이 기본. PythonScriptPlugin은 uproject 변경 없이 `-EnablePlugins` 커맨드라인 플래그로 켠다(baseline OFF 유지). 과거 커맨드릿이 게임 모듈 로드 실패(GetLastError=126)로 폐기된 이력이 있어, 빌드 최신화 후 1회 재검증(스파이크)하고 실패 시 `-ExecutePythonScript`(에디터 기동 실행) 경로로 폴백한다. MCP에는 raw Python 실행 툴이 없음이 확인되어 라이브 에디터 경로는 일괄 덤프에 쓸 수 없다.
- **범용 직렬화기**: 과거 어빌리티셋 마이그레이션 덤프의 리플렉션 패턴을 일반화한다. 프로퍼티 열거는 상시 활성인 ToolsetRegistry의 라이브러리로 하고, 값은 타입별로 디스패치(외부 참조는 경로 문자열로 축약, 패키지 내부 서브오브젝트는 재귀 전개, 순환은 seen set + depth cap으로 차단). 출력은 키 정렬·LF 고정으로 결정적이어야 재실행 diff가 0이 된다.
- **타입별 전략**: 인덱스는 AssetRegistry로 로드 없이, DataTable은 엔진 JSON 익스포터, DataAsset류는 직렬화기 전체 덤프, StateTree는 에디터 데이터에서 상태 계층·노드 설명 재귀, BP/WBP는 구조 요약(부모·컴포넌트·변수·그래프 이름·위젯 트리) + CDO 값. 그래프 노드 수준과 MVVM 바인딩은 v2로 미룬다.
- **산출물 관례**: 에셋당 1파일로 diff를 국소화하고, provenance(커밋 SHA·생성일)는 INDEX.md 끝 한 줄만 — readme-writer 관례를 따라 stale 판정에 재사용한다. v1은 증분 없이 전체 재덤프.

### 구현·결정과 그 이유
- **커맨드릿이 기본 경로로 확정**: 폐기 사유였던 게임 모듈 로드 실패(126)는 재검증 결과 스테일 DLL이 원인이었고 빌드 최신화로 해소됐다. PythonScriptPlugin은 커맨드라인 플래그로만 켜서 uproject baseline(OFF)을 유지한다.
- **MCP 플러그인은 커맨드릿에서 끔**: 포트 바인드 실패가 엔진 오류로 집계돼 exit code를 오염시킨다. 성공 판정은 exit code가 아니라 로그의 완료 라인으로 한다.
- **protected 프로퍼티 우회**: 위젯 트리와 BP 부모 클래스는 리플렉션 읽기가 막혀 있어, 각각 로드된 서브오브젝트 순회 + 부모 관계 재구성, AssetRegistry 태그로 취득했다.
- **결정성 확보**: 문자열 폴백의 메모리 포인터 제거, 함수 목록은 구현된 것만 이름 추출, 맵 키는 직렬화 후 단일 필드 구조체를 값으로 축약. 동일 입력 재실행 diff 0을 두 차례 확인했다.
- **가독성 다듬기**: DataTable의 FText 로컬라이즈 래퍼는 소스 문자열만 남겼고(대사 한글 그대로 검색됨), StateTree 상태 링크의 GUID는 제거했다.

### 계획 대비 달라진 점
- **`.claude/CLAUDE.md`에 「에셋 분석」 절을 두지 않았다.** 한 번 넣었다가 되돌렸다 — 상시 로드되는 지침에 특정 산출물 경로를 박아 두면 덤프 위치가 바뀔 때마다 지침을 고쳐야 하고, 정작 그 안내가 필요한 것은 에셋을 읽는 세 스킬뿐이다. 그래서 각 스킬이 `Docs/AssetDump/`(진입점 `INDEX.md`, 갱신 `/dump-assets`)를 직접 가리키게 하고, 안내처를 CLAUDE.md에 두는 계획은 버렸다.
- 계획의 폴백 경로(에디터 기동 실행)는 필요 없어져 SKILL.md의 실패 대응 절차로만 남겼다.
- BP 부모 표기를 인덱스(네이티브 우선)와 본문(즉시 부모 + 네이티브 병기)으로 이원화했다.
- 사후 보완: INDEX.md(카테고리 수치·provenance)는 전체 실행에서만 재작성하게 했다 — 부분 실행(--only)이 수치를 0으로 오염시키고, 본문이 낡은 채 신선도 기록만 갱신돼 stale 판정이 거짓 통과하는 구멍을 막는다.
- 사후 보완 2: INDEX.md를 provenance + 짧은 안내로 슬림화했다 — 카테고리 수치·제외 폴더 목록은 다시 셀 수 있는 파생 정보라 걷어내고(제외 통계는 index.json으로 이동), 셀 수 없는 정보(어느 커밋 기준 덤프인가)만 남긴다. 데이터 JSON에 시간/SHA를 넣는 안은 결정성(재실행 diff 0) 파괴와 시간→커밋 역산의 부정확성 때문에 기각.
- 사후 보완 3: 부분 실행 단위를 카테고리에서 에셋으로 교체했다(`--only=카테고리` 제거, `--asset=에셋명` 추가) — 실행 시간이 엔진 부팅에 지배돼 카테고리 필터의 실익이 없었고, 전체/단일 에셋 두 모드가 더 단순하다. 단일 에셋 모드는 기존 파일명을 보존해 그 JSON만 교체하고 신선도 기록은 건드리지 않는다.
- 사후 보완 4: index.json(전체 에셋 카탈로그)을 제거했다 — 에셋의 존재·경로·증감은 `Content/`의 .uasset과 git이 이미 원본으로 말해 주므로 카탈로그 사본은 SSOT 위반이다(사용자 결정). 클래스·부모 조회는 본문 덤프 봉투(`class`/`parent`)와 파일명 관례로 대신한다.
- 사후 보완 5: INDEX.md를 README.md로 개명했다 — index.json이 사라진 뒤 "INDEX"는 명실불부(색인이 아니라 폴더 표지 + provenance)이고, 모듈 README + 끝줄 provenance라는 기존 관례와 형태가 같다. provenance 자체는 사본이 아니라 유일 기록(덤프 생성 시점)이라 SSOT 위반이 아니므로 유지.
