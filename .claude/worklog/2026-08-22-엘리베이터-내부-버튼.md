# 엘리베이터 내부 버튼 — 누르면 반대 층으로

## 계획

### 목표
BP_Elevator 에 새로 심긴 내부 버튼(`ButtonDevice_Lift`, PlatformRoot 에 붙어 칸과 함께 움직임)을 누르면 현재 층의 반대 층(1F ↔ 2F)으로 이동하게 한다. 같이 이뤄진 버튼 변수 이름 변경(`TriggerDevice_*` → `ButtonDevice_*`)도 ST 에 반영한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/WorldObject/Gimmick/ST_Elevator.uasset` | 1F/2F 에 `On Event(Event.Device.Triggered)` → 반대 층 전이 추가, 잠금 태스크의 ChildDevice 이름을 `ButtonDevice_1F/2F` 로 (MCP) | 수정 |

### 접근 방식
- **규칙 ① 그대로**: 내부 버튼은 목적지가 상태에 따라 달라지는 "눌렸다" 요청이라 기본 `Event.Device.Triggered` 를 보내면 된다(BP 템플릿 기본값, 손대지 않음). 받는 엘리베이터가 자기 상태로 목적지를 정한다 — 1F 는 2F 로, 2F 는 1F 로. 문(ST_Door)의 Close/Open 토글과 같은 모양이다.
- **Inactive 는 듣지 않는다**: 미가동에선 칸이 1F 위치에 문 닫힌 채라 내부 버튼에 닿을 수 없다. 전이를 두지 않으면 이벤트가 그냥 버려져 미가동 상태가 그대로 유지된다.
- **잠금 없음**: 내부 버튼은 어느 층에서든 눌러야 하므로 끄기/켜기 태스크를 더하지 않는다. 태스크 수가 그대로라 완료 비트 배치도 그대로다.
- **이름 변경 반영**: ChildDevice 는 이름으로 컴포넌트를 찾으므로 옛 이름이 남으면 층 진입 때 잠금 태스크가 실패해 상태 진입 자체가 막힌다.
- **배선**: 내부 버튼은 ChildActorComponent 라 BeginPlay 에서 자기를 품은 엘리베이터를 스스로 지목한다(레벨 저작 불필요).

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Content/WorldObject/Gimmick/ST_Elevator.uasset` | 1F 에 `On Event(Event.Device.Triggered) → 2F`, 2F 에 `→ 1F` 전이 추가; 잠금 태스크의 ChildDevice 를 `ButtonDevice_1F/2F` 로 (MCP) | 수정 |

### 구현·결정과 그 이유
- **코드·BP 는 손대지 않았다**: 내부 버튼의 요청은 "현재와 반대 층"이라 보낸 이를 가를 필요가 없고, 규칙 ①의 기본 이벤트가 그대로 맞는다. 목적지는 받는 엘리베이터의 현재 상태가 정하므로 전이 두 줄이 구현의 전부다. ST_Door 의 Close/Open 토글과 같은 모양이라 읽는 사람이 새로 배울 것이 없다.
- **Inactive 는 내부 버튼을 듣지 않는다**: 미가동은 칸이 1F 위치에 문 닫힌 채라 내부 버튼에 닿을 수 없고, 닿더라도 "반대 층"의 기준이 없다. 전이를 두지 않으면 이벤트가 버려져 미가동이 그대로 유지된다.
- **내부 버튼은 잠그지 않는다**: 어느 층에서든 눌러야 하므로 끄기/켜기 태스크를 더하지 않았다. 이동 중에 누르면 층 부모의 전이가 받아 되돌아온다(층 버튼과 같은 동작). 태스크 수가 그대로라 완료 비트 배치도 그대로다.
- **이름 변경은 실제로 깨져 있었다**: 사용자의 앞선 PIE 로그(08:20)에 `내장 장치 'TriggerDevice_1F' 를 찾지 못했다` 에러가 찍혀 있었다. ChildDevice 는 이름으로 찾으므로 층 진입 때 잠금 태스크가 실패해 층 상태에 들어가지 못하던 상태였다.

### 계획 대비 달라진 점
- 계획대로. 저작 과정에서 원소가 있는 전이 배열에 MCP 로 원소를 덧붙이는 것은 거부되어(`ArrayAdd: elements changed alongside the size change`, 기존 원소를 `{}` 로 둬도 같음) 배열을 비웠다가 두 원소를 다시 기입했다. 에디터가 새 전이 iD 를 재부여하지만 바인딩이 없어 무관하다.

### 검증
- ST_Elevator 컴파일 `succeeded`, 저장 실기록(17:28). 재조회: 1F/2F 전이 각 2건(층 태그·`Event.Device.Triggered`), 잠금 태스크 `ButtonDevice_1F/2F`.
- PIE: 엘리베이터 `Device.Elevator.Inactive`, 내부 버튼 액터 `Device.Button.Idle`·칸 내부(엘리베이터 기준 -180,180,5, PlatformRoot 부착), 이번 세션 LogWxWorld 에러 0건. PIE 가 외부에서 종료되어 내부 버튼의 런타임 `LinkedDevices` 는 못 읽었다 — 자동 배선은 층 버튼과 같은 BeginPlay 경로이고, 템플릿 `TriggerEvent` 는 기본값임을 에디터 월드에서 확인했다.

### 후속 과제
- **사람 PIE 확인**(입력은 MCP 로 못 넣음): 1F 가동 후 내부 버튼 → 문 닫힘·상승·2F 문 열림, 2F 에서 → 1F; 이동 중 내부 버튼 → 되돌아오기; 미가동에선 무반응.
- 범위 밖 선행 문제: ChildActorComponent 로 스폰된 버튼 네 개가 `WxSaveId` 무효로 세이브에서 제외된다는 LogWxSave 경고(PreSave 가 CAC 자식 액터엔 돌지 않음). 버튼은 저장할 상태가 없어 당장 해는 없다.
