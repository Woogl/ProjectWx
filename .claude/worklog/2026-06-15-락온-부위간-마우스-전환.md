# 락온: 같은 액터의 부위 간 마우스 전환 지원

## 계획

### 목표
현재 락온은 액터당 지점 1개만 인식해(ResolveLockOnTarget이 첫 지점만 반환, 재탐색이 액터 단위로 현재 액터를 통째 제외) 같은 액터의 부위 간 런타임 전환이 불가능하다. 마우스(IA_Look) 방향으로 같은 적의 다른 부위로도 전환할 수 있게 한다(기존 적→적 전환 유지).

### 수정 범위
| 모듈 | 파일 | 수정할 내용 |
|---|---|---|
| `WxCombat` | `Public/Targeting/WxLockOnPointComponent.h` + `Private/.../WxLockOnPointComponent.cpp` | 정적 헬퍼 `GatherLockOnPoints(Actor, OutPoints)` 추가(액터의 모든 지점 수집). `ResolveLockOnTarget` 유지 |
| `WxCombat` | `Private/AbilitySystem/Ability/WxAbility_LockOn.cpp` | `HandleRetargetRequested` 후보 비교를 액터→지점 단위로 변경 |

### 접근 방식
매니저/태스크는 이미 지점(SceneComponent) 단위로 동작하고 대상 변경 시 레티클을 새 지점에 재부착하므로 수정 불필요. 막힌 곳은 어빌리티의 후보 해소가 액터 단위라는 점뿐.

`HandleRetargetRequested`:
- 후보 액터를 돌며 각 액터의 **모든 지점**을 `GatherLockOnPoints`로 펼쳐 후보 지점 목록 구성. **현재 타겟 액터도 포함**(같은 액터 다른 부위를 후보로).
- 제외 조건을 "현재 타겟 액터"에서 **"현재 타겟 지점"** 으로 변경.
- 화면 투영·정렬도 비교·`SetLockOnTarget` 등 나머지는 그대로.

### 범위 밖
- 초기 락온/타겟 상실 자동 재탐색은 기존 액터 단위 유지.
- 실제 부위 추가는 적 BP SCS에 `UWxLockOnPointComponent`를 소켓에 더하는 콘텐츠 작업(사용자).

## 완료

### 수정한 파일
| 모듈 | 파일 | 수정 내용 |
|---|---|---|
| `WxCombat` | `Public/Targeting/WxLockOnPointComponent.h` | `GatherLockOnPoints` 정적 헬퍼 선언 추가 |
| `WxCombat` | `Private/Targeting/WxLockOnPointComponent.cpp` | `GatherLockOnPoints` 구현(액터의 모든 지점 수집) |
| `WxCombat` | `Private/AbilitySystem/Ability/WxAbility_LockOn.cpp` | `HandleRetargetRequested` 후보 비교를 액터→지점 단위로 변경, 현재 지점만 제외 |

### 구현·결정과 그 이유
- **변경을 어빌리티 한 곳에 집중**: 매니저·태스크가 이미 지점(SceneComponent) 단위로 동작하고 대상 변경 시 레티클을 새 지점에 재부착하므로, 후보 해소만 지점 단위로 넓히면 부위 전환이 성립한다. 매니저/태스크는 손대지 않았다.
- **현재 "지점" 제외(현재 "액터" 제외 X)**: 같은 액터의 다른 부위를 후보로 남기려면 제외 단위가 지점이어야 한다. 이게 부위 전환을 여는 핵심 한 줄.
- **`ResolveLockOnTarget` 유지**: 초기 락온·타겟 상실 재탐색은 액터당 대표 지점 하나로 충분해 기존 함수를 그대로 두고, 다중 후보가 필요한 재탐색 경로에만 `GatherLockOnPoints`를 신설했다.

### 계획 대비 달라진 점
- 계획대로.

### 후속 과제
- **콘텐츠(사용자)**: 적 BP SCS에 `UWxLockOnPointComponent`를 원하는 소켓(head/spine 등)에 추가해야 실제 부위가 여러 개가 된다. C++ pelvis 기본 지점이 초기 시작 부위.
- 범위 밖으로 남긴 항목: 초기 락온의 "가장 가까운 부위" 선택, 타겟 상실 시 같은 액터 잔여 부위로의 전환(현재는 액터 단위). 필요 시 후속.
