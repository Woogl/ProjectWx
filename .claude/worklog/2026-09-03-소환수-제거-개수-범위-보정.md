# 소환수 제거 개수 범위 보정

## 계획

### 목표
`HandleSpawnMinionEvent` 의 제거 횟수 계산이 `MaxMinionCount >= 1` 을 암묵 전제해, BP 에서 0 이나 음수가 들어오면 빈 배열을 인덱싱한다. 데이터 값과 무관하게 안전하도록 계산 자체를 보정한다. (`module_review_WxCombat.md` 발견 2)

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/Minion/WxMinionComponent.cpp` | `:131` 제거 횟수를 보유 수로 상한 클램프 | 수정 |

### 접근 방식
- **`FMath::Max` → `FMath::Clamp(..., 0, ActiveMinions.Num())`**: 하한 0 은 그대로 두고 상한만 "지금 들고 있는 수"로 묶는다. 루프가 도는 횟수가 배열 길이를 넘을 수 없으므로 `ActiveMinions[0]` 접근이 항상 유효하다.
- **`ClampMin` 메타는 붙이지 않는다**: 요구가 "데이터에 관계없이 안전"이므로 에디터 입력 제약에 기대지 않는다. 메타는 이미 저장된 에셋이나 런타임 대입을 막지 못해 안전 보장이 되지 않는다.
- **결과 동작**: `MaxMinionCount` 가 0 이하이면 매 소환마다 보유분을 전부 정리하고 하나를 새로 소환해, 사실상 1 과 같게 수렴한다. 크래시 대신 예측 가능한 축퇴 동작이 된다.

### 수정한 파일

### 구현·결정과 그 이유
- **`FMath::Max` 를 `FMath::Clamp` 로 교체**: 하한 인자를 그대로 두고 상한만 추가하면 되므로 별도 변수나 가드 분기 없이 한 표현식으로 끝난다.
- **주석은 그대로 뒀다**: 기존 주석이 설명하는 의도(한 자리 확보 + 초과분 정리)는 변하지 않았고, 상한을 두는 이유는 `Clamp` 인자에서 그대로 읽힌다.
