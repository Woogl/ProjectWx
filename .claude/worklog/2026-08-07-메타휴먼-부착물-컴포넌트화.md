# 메타휴먼 부착물의 C++ 컴포넌트화 — UWxMetaHumanVisualComponent

## 계획

### 목표
BP_Player에 수작업으로 얹은 메타휴먼 부착물(Face·그룸 4종·Outfit·MetaHumanComponentUE·LODSync + UCS 리더포즈 1줄)을 C++ 컴포넌트 하나로 내린다. NPC·Enemy 메타휴먼화가 실제 계획이므로, 클래스 계보가 달라도(AWxNpc는 AActor 직상속) BP에 컴포넌트 1개만 얹으면 되는 재사용 단위를 만든다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxMetaHumanVisualComponent.h/.cpp` | 부착물 일체를 OnRegister에서 생성·배선하는 UActorComponent | 신규 |
| `Source/WxGame/WxGame.Build.cs` | HairStrandsCore, MetaHumanSDKRuntime 의존 추가 | 수정 |
| `Content/Character/Player/BP_Player.uasset` | SCS 부착물 7개 삭제·UCS 비우기, 신규 컴포넌트 1개 추가+에셋 설정 | 수정 |

### 접근 방식
- **독립 UActorComponent + 등록 시점 조립**: 오너가 ACharacter면 GetMesh(), 아니면 첫 SkeletalMeshComponent를 바디로 잡고, 설정 에셋(페이스, 그룸 슬롯 6종 명명 필드, 복장)으로 자식 컴포넌트를 RF_Transient로 생성한다(에디터 프리뷰 가시). Outer=GetOwner()는 WxQuestComponent, 등록 훅·프리뷰 관례는 WxSpawner 선례를 따른다.
- **이름 문자열 하드코딩 제거가 실익**: LODSync·MetaHumanComponent의 컴포넌트 이름 참조를 실제 생성된 컴포넌트의 FName으로 동적 구성한다.
- **리더포즈 판정을 코드로**: 어셈블 BP의 EnableMasterPose와 동일 조건(PP-ABP·AnimClass 없는 메시만 리더포즈)으로 UCS 그래프를 대체한다.
- 플레이어도 SCS 추가 방식으로 통일해 캐릭터 C++는 메타휴먼을 모르게 유지한다.
- 리스크: UMetaHumanComponentUE 프로퍼티 접근 지정자 — protected면 얇은 파생, private이면 FProperty 기입 폴백.

### 구현·결정과 그 이유
- **이름 프로퍼티는 얇은 파생으로 설정 (리뷰 반영)**: UMetaHumanComponentBase의 BodyComponentName/FaceComponentName은 접근자 없는 protected다. 처음엔 리플렉션 기입으로 구현했으나, 엔진이 프로퍼티를 개명하면 조용히 no-op이 되는 위험 지적을 받아 `UWxMetaHumanComponent`(UMetaHumanComponentUE 파생, 세터 1개)로 교체했다 — 개명 시 컴파일 에러로 드러난다. 생성자·소멸자가 METAHUMANSDKRUNTIME_API로 익스포트돼 있어 크로스 모듈 파생이 링크됨을 확인했다. PostProcessAnimBP(private)는 Torso/Legs/Feet 파트가 빈 현 구성에선 휴면 값이라 설정을 생략했다.
- **생성물 이름은 MakeUniqueObjectName**: 재등록 시 같은 이름의 파괴 대기 객체와 충돌하지 않도록 유니크 네임("Face_0" 등)을 쓰고, 이름을 참조하는 LODSync·MetaHuman 설정에는 실제 생성된 FName을 그대로 넘긴다.
- **LOD 매핑 동적 계산**: NumLODs=구성 메시 최대 LOD 수, 매핑=Index×메시LOD÷NumLODs — 어셈블 BP의 하드코딩 값([0,0,1,1,2,2,3,3])과 동일한 결과가 실측으로 나온다.
- **삭제 순서 함정**: SCS의 Outfit을 지우면 UCS의 리더포즈 노드가 타깃을 잃어 컴파일이 깨지고 이후 조작이 전부 막힌다 — UCS 노드를 먼저 삭제한 뒤 컴포넌트를 지워야 한다(이번엔 사후 노드 삭제로 복구).

### 계획 대비 달라진 점
- 계획대로. (부착물 SCS 개수는 계획서의 7이 아니라 8이었다 — 그룸 4종+Face+Outfit+MetaHuman+LODSync.)

### 검증 결과
- WxEditor 빌드 성공. BP_Player 컴파일·저장 후 재조회로 설정 유지 확인.
- PIE: 부착물 8종+그룸 나이아가라가 런타임 생성, Face 부모=바디, Outfit 리더포즈=바디, LODSync Drive/Passive·매핑, MetaHuman 이름 배선 전부 정확. 외형 리팩터 전과 동일, 관련 경고 0건.
- BP 에디터 프리뷰 뷰포트에서도 부착물 표시 확인(디자인타임 프리뷰 성립).

### 후속 과제
- NPC·Enemy 메타휴먼화 시: 각 BP에 `WxMetaHumanVisualComponent` 추가 + 해당 캐릭터의 어셈블 에셋 설정만 하면 됨(바디 메시 교체·Compatible Skeletons·ik 본 추가는 별도 절차).
- 부착물 개별 튜닝 요구가 생기면 설정 프로퍼티를 점진 추가(SCS 재발명 경계).
