# MarkIndicator → MarkIndicators 배열화

## 계획

### 목표
인디케이터 태스크가 대상을 하나만 받아 여러 대상을 가리키려면 노드를 여러 개 붙여야 한다. 짝이 되는 `WaitSpawnersKilled`(WxWorld)와 같은 모양으로 대상 목록을 받게 하고, 이름도 복수형으로 맞춘다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../Public/Indicator/WxIndicatorStateTreeNodes.h` | 태스크·인스턴스 데이터 복수형 개명, 대상 파라미터를 UOL 배열로, 등록 기록도 배열로, 래퍼 include·주석 정리 | 수정 |
| `Plugins/WxUI/.../Private/Indicator/WxIndicatorStateTreeNodes.cpp` | 해석·등록·해제를 인덱스 루프로 확장, 목록 표시 텍스트 헬퍼 추가 | 수정 |
| `/Game/Quest/ST_Quest_Main1` | Step1 의 Mark Indicator 노드를 새 태스크로 재저작(구조체 개명으로 기존 노드는 로드 시 소멸) | 수정(MCP) |

### 접근 방식
- **파라미터 배열화**: `FWxActorTarget Target` → `TArray<FUniversalObjectLocator> Targets`(`AllowedLocators = "Actor"`). 스포너 노드의 `Spawners` 와 동일한 선언이다. 배열 원소는 UOL 값 위젯이 정상 생성되므로(엔진 제한은 인스턴스 데이터 직속 멤버에만 걸린다) 래퍼가 필요 없어진다. 래퍼 자체는 다른 노드가 계속 쓰므로 남긴다. `WorldZOffset` 은 전 대상 공통값으로 유지.
- **등록 기록 배열화**: 등록 기록을 대상과 같은 인덱스로 짝지어, 대상마다 독립적으로 등록·해제되게 한다(하나가 스트리밍 아웃돼도 나머지 표시는 유지).
- **개명**: 태스크·인스턴스 데이터·DisplayName·로그 문구를 복수형으로.
- **동작 규약 유지**: 매 틱 해석 → 해석되면 등록, 안 되면 해제. 루프로만 넓힌다. 진입 시 빈 배열·빈 로케이터 항목 경고는 `WaitSpawnersKilled` 와 같은 형식으로.
- **표시 텍스트**: 라벨 3개까지 나열하고 초과분은 `+N`. WxUI 는 WxWorld 를 참조할 수 없으므로 헬퍼는 각 모듈에 둔다.
- **Compile 검증 없음**: 인디케이터 대상은 특정 액터 클래스로 좁혀지지 않아 스포너 노드의 클래스 검사에 해당하는 것이 없다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../Public/Indicator/WxIndicatorStateTreeNodes.h` | 태스크·인스턴스 데이터를 복수형으로 개명, 대상을 UOL 배열로, 등록 기록을 짝 배열로, 래퍼 include·주석 갱신 | 수정 |
| `Plugins/WxUI/.../Private/Indicator/WxIndicatorStateTreeNodes.cpp` | 해제 헬퍼를 슬롯 단위로 바꾸고 갱신을 인덱스 루프로 확장, 진입 경고 보강, 목록 표시 텍스트 헬퍼 추가 | 수정 |

### 구현·결정과 그 이유
- **대상 지정은 래퍼 없이 UOL 배열 그대로**: 값 위젯이 만들어지지 않는 엔진 제한은 인스턴스 데이터 직속 멤버에만 걸리고 배열 원소는 무관하다. 스포너 노드가 이미 같은 선언으로 픽커까지 정상 동작하는 것이 확인돼 있어 그 모양을 그대로 따랐다.
- **등록 기록을 지정과 같은 인덱스로 짝지음**: 대상마다 해석 결과가 달라지므로(하나만 스트리밍 아웃) 등록·해제 판단이 대상별로 독립적이어야 한다. 인덱스 짝이면 별도 매핑 없이 그 관계가 유지된다.
- **매니저 조회는 루프 밖 1회**: 대상 수와 무관한 조회다. 매니저가 아직 없을 때도 해제는 수행돼야 하므로, 없으면 등록만 건너뛰고 루프는 계속 돈다.
- **Compile 검증 없음**: 스포너 노드의 클래스 검사는 대상 타입이 하나로 정해져 있어 가능한 것이고, 인디케이터는 어떤 액터든 가리킬 수 있어 검사할 계약이 없다.
- **완료 판정 기본 제외**: 완료를 내지 않는 태스크라 판정에 끼면 그 상태가 영영 완료되지 않는다. 에셋마다 손으로 끄게 두면 빠뜨릴 여지가 있어 생성자에서 기본값으로 꺼 둔다(퀘스트·대화의 부수효과 태스크와 같은 처리). 에디터 전용 데이터라 `WITH_EDITORONLY_DATA` 안에 둔다.
- **표시 텍스트 헬퍼 중복 허용**: 스포너 노드의 같은 형식 헬퍼를 공유하려면 WxUI→WxWorld 참조가 필요해 규칙 위반이다. 짧은 표시용 코드라 각 모듈에 둔다.

### 계획 대비 달라진 점
- 계획대로. 단 에셋 재저작은 미착수 — 실행 중인 에디터가 DebugGame(구 코드)이라 새 태스크를 만들 수 없었고, 사용자가 직접 수행하기로 했다.

### 후속 과제
- `/Game/Quest/ST_Quest_Main1` Step1 의 Mark Indicator 노드 재저작: 구조체 개명으로 다음 로드 때 노드가 사라진다. 새 코드로 에디터를 띄운 뒤 `Mark Indicators` 를 다시 만들고 캠프 스포너를 첫 항목으로 지정, 컴파일·저장해야 한다.
- 대상 2개 이상 지정 시 동시 표시·개별 해제 PIE 실측 미수행.
