# 퀘스트 수주를 볼륨 진입으로 전환 (bAutoStart 제거)

## 계획

### 목표
퀘스트 에셋이 스스로 탑재를 선언하던 `bAutoStart` 와 그 애셋 레지스트리 스캔을 걷어내고, 레벨에 배치한 볼륨에 플레이어가 닿을 때 퀘스트가 탑재되게 한다. 개시 판정(대화 완료)은 지금처럼 에셋 안 Start 게이트가 그대로 맡아, 1차 조건은 볼륨·2차 조건은 대화가 된다.

### 접근 방식
- **탑재 선언을 에셋에서 레벨로**: 자동 탑재는 "켜진 에셋 1개" 라는 전역 유일성을 요구했지만, 볼륨은 배치 인스턴스마다 대상 퀘스트를 들고 있어 여러 시작점이 자연히 공존한다. 컴포넌트는 여전히 특정 에셋을 모른다.
- **새 진입점 없음**: `UWxQuestLibrary::StartQuest` 가 이미 BlueprintCallable 진입점이라 C++ 추가 없이 BP 볼륨만 만든다. 볼륨을 C++ 액터로 되살리는 안은 코드 증식 대비 이득이 없어 기각.
- **1회성은 볼륨이 책임**: `StartQuest` 는 교체 시맨틱이라 재진입하면 진행 중 퀘스트가 처음부터 다시 켜진다. 첫 오버랩 후 콜리전을 꺼 재진입 자체를 없앤다.

### 구현·결정과 그 이유
- **볼륨은 BP, 부모는 ATriggerBox**: 라이브러리가 이미 BP 진입점이라 C++ 액터를 되살릴 이유가 없었다. 엔진 트리거 박스를 상속하면 오버랩 프리셋과 배치 편의(스케일로 크기 조절)를 그대로 얻어 컴포넌트 구성조차 필요 없다.
- **1회성은 볼륨 책임**: 컴포넌트의 시작은 교체 시맨틱이라 재진입하면 진행 중 퀘스트가 처음부터 다시 돈다. 첫 성립 후 액터 콜리전을 꺼 재진입 자체를 없앴다 — 컴포넌트에 가드를 넣으면 체인 교체까지 같이 막힌다.
- **권위·플레이어 판별을 그래프에 명시**: 비-권위 호출은 라이브러리에서 어차피 무시되지만, 볼륨을 읽는 사람이 "서버에서만 성립" 을 그래프에서 바로 보게 뒀다.
- **탑재/개시 2단 구조 유지**: 볼륨이 1차 조건(탑재), 에셋 안 Start 게이트가 2차 조건(개시)이라 `ST_Quest_Main1` 은 손대지 않았다.
- **`StartQuest`→`ActivateQuest` 개명**: 2단 구조가 드러나자 "start" 가 탑재와 개시 두 뜻으로 갈렸다. 플레이어가 느끼는 시작(저널에 뜨는 순간)에 Start 어휘를 남기고, 컴포넌트·라이브러리·체인 태스크는 활성화 어휘로 옮겼다. 체인 태스크까지 함께 바꾼 것은 같은 동작을 다른 동사로 부르지 않기 위함이며, 이 태스크를 쓰는 에셋이 아직 없어 리다이렉트 없이 안전했다.

### 계획 대비 달라진 점
- 계획의 "Box Collision 을 단 AActor" 대신 `ATriggerBox` 상속으로 만들었다. 결과 구성은 같고 SCS 저작이 사라져 더 단순하다.
- 계획에 없던 `StartQuest`→`ActivateQuest` 개명을 이어서 했다(위 참조).

### 후속 과제
- **BP 노드 재연결 대기** — `BP_QuestStartVolume` 의 호출 노드가 아직 옛 `StartQuest` 를 가리킨다. 실행 중인 에디터가 개명 전 DLL 이라 지금은 새 노드를 만들 수 없어, 에디터를 새 빌드로 재시작한 뒤 노드를 `Activate Quest` 로 교체·재컴파일해야 한다.
- 레벨 배치 미완 — `LV_OpenWorld` 의 어느 지점에 둘지는 레벨 디자인 판단이라 남겼다. 배치 후 PIE 로 「볼륨 진입 → 대화 완료 → 저널 표시」 실동작 검증 필요.
