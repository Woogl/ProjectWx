# 그로기 피니시(앞잡) — 상호작용 발동 + 모션워핑 정렬 + 짝 피격 모션

## 계획

### 목표
그로기 상태 적에게 플레이어가 상호작용 키(F)로 피니시("앞잡")를 발동한다. 모션워핑으로 적 앞 정렬 후 공격자 피니시 몽타주를 재생하고, 적은 프레임 싱크된 짝 피격 몽타주를 동시 재생한다. 큰 피해 + DP 전부 제거로 그로기를 해제한다. 1차는 핵심 루프만(무적·DP증감정지·락온우선·3m·예외·전용UI는 후속).

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxGameplayTags.h/.cpp` (WxCore) | `Ability.GroggyFinish`, `Event.GroggyFinish`, `Event.HitReact.Finish` 추가 | 수정 |
| `WxAbility_GroggyFinish.h/.cpp` (WxCombat) | 공격자 피니시 어빌리티 신규. Event.GroggyFinish 트리거, 워프타겟 등록+피니시 몽타주, 적에 Finish 이벤트 송출, 후반 대미지 GE 적용 | 신규 |
| `WxAbility_HitReact.h/.cpp` (WxCombat) | `FinishMontage` 슬롯 + `Event.HitReact.Finish` 트리거/분기 추가(짝 피격) | 수정 |
| `WxEnemyCharacter.h/.cpp` (WxGame) | `UWxInteractionComponent` 부착, State.Groggy 구독 토글, OnInteracted→플레이어에 Event.GroggyFinish 송출 | 수정 |
| BP/몽타주/GE 에셋 | 짝 몽타주(동일 타임라인), 피니시 대미지 GE(피해+DP override 0), BP_GroggyFinish | 신규(에디터) |

### 접근 방식
- **클래스 최소화**: 신규 C++ 어빌리티는 `WxAbility_GroggyFinish` 하나. 적 짝 피격은 HitReact 확장, DP 클리어는 피해 GE에 모디파이어로 통합.
- **발동**: 기존 상호작용 파이프라인 재사용. 적 InteractionComponent를 그로기 동안만 활성화 → OnInteracted → 플레이어 ASC에 `Event.GroggyFinish` → 피니시 어빌리티.
- **동기화**: 피니시 어빌리티가 발동 즉시 적에 `Event.HitReact.Finish` 송출 → 두 몽타주 t=0 동시 시작. 같은 길이로 제작해 프레임 싱크.
- **그로기 해제**: 피니시 대미지 GE가 DP를 0으로 → `WxCombatAttributeSet`이 State.Groggy 제거 → Groggy 종료(다운 없음).

### 구현·결정과 그 이유
- **대미지 타이밍을 WaitGameplayEvent + 범용 노티파이로**: 무기 콜리전은 대상이 비확정적이라, 상호작용으로 확정된 적에 정확히 적용하기 위해 어빌리티가 대상을 쥐고 `UWxCombatLibrary::ApplyDamage`로 적용한다. 타이밍은 연출 후반 노티파이가 `Event.GroggyFinish.Damage`를 송출하면 어빌리티의 `WaitGameplayEvent`가 받는다. DP 제거가 연출 후반에 일어나야 적이 연출 내내 그로기를 유지하므로 즉시 적용 대신 노티파이 타이밍을 택했다. 노티파이는 UseItem 사례처럼 신규 1개가 필요했고, 향후 재사용을 위해 태그 지정형 범용으로 만들었다.
- **모션워프 타겟을 어빌리티가 직접 등록**: 기존 SnapToTarget 노티파이는 락온/타겟팅 프리셋으로 타겟을 스스로 찾아, 피니시 대상이 락온이 아니면 빗나간다. 대상이 확정적이므로 어빌리티가 SnapToTarget과 동일한 수평 접근 규칙으로 워프 타겟을 등록하고, 몽타주는 그 이름의 MotionWarping 노티파이로 정렬한다.
- **적 토글은 캐릭터가 State.Groggy 태그를 구독**: 그로기 신호는 이미 ASC 태그로 발행되므로(WxCombatAttributeSet), 적 캐릭터가 이를 구독해 InteractionComponent를 켜고 끈다. 그로기 어빌리티(WxCombat)가 InteractionComponent(WxWorld)를 직접 만지지 않아 플러그인 의존을 늘리지 않는다.

### 계획 대비 달라진 점
- 대미지 타이밍 전달용 `WxAnimNotify_SendGameplayEvent`(범용 이벤트 송출 노티파이)를 신규 추가. 계획엔 "후반 대미지 노티파이 재사용"으로 적었으나, 적합한 기존 노티파이가 없어 범용 1개를 신설했다(어빌리티/GE 신규 클래스는 계획대로 GroggyFinish 1개 유지).

### 후속 과제
- **콘텐츠(에디터) 작업 필수**: 공격자/적 짝 몽타주(동일 타임라인) 제작, 공격자 몽타주에 MotionWarping(SkewWarp, Warp Target Name="GroggyFinish") + `WxAnimNotify_SendGameplayEvent`(EventTag=Event.GroggyFinish.Damage) 배치, 피니시 대미지 GE 에셋(피해 ExecCalc + DP Override 0), `BP_GroggyFinish`(플레이어 ASC 그랜트)와 HitReact BP의 `FinishMontage` 지정, 적 InteractionComponent의 InteractionText("처형") 설정.
