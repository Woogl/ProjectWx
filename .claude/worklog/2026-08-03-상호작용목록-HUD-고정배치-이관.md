# 상호작용 목록 위젯을 캐릭터 위젯 컴포넌트에서 HUD 고정 배치로 이관

## 계획

### 목표
상호작용 목록이 캐릭터의 월드 위치를 투영한 자리에 떠서 카메라를 따라 흔들리고 화면 가장자리에서 잘린다. 목록은 캐릭터에 붙은 말풍선이 아니라 HUD 요소이므로 `WBP_GameHUD`의 고정 위치로 옮기고, 캐릭터 쪽 호스팅 코드를 걷어낸다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxPlayerCharacter.h` | `UWidgetComponent` 전방선언, `InteractionListWidget` UPROPERTY, `NotifyControllerChanged` override 선언 삭제 | 수정 |
| `Source/WxGame/Character/WxPlayerCharacter.cpp` | 위젯 컴포넌트 include·생성자 블록·`NotifyControllerChanged` 정의 삭제 | 수정 |
| `/Game/UI/Widget/WBP_GameHUD` | `WBP_InteractionList` 배치, 앵커·정렬로 고정 위치 지정 | 수정(에디터) |
| `/Game/UI/Widget/WBP_InteractionList` | 루트 `Padding`(투영 지점 밀어내기용) 제거 | 수정(에디터) |
| `/Game/Characters/BP_Player` | 사라진 네이티브 컴포넌트 잔여 오버라이드 정리 위해 재저장 | 수정(에디터) |

### 접근 방식
- **호스트만 교체, 데이터 경로는 불변**: 리졸버는 위젯의 소유 플레이어로 VM 을 만드는데, Screen-space 위젯 컴포넌트에서도 그 값은 로컬 뷰어 컨트롤러였다. HUD 자식이 되어도 같은 값이라 배선 변경이 없다. 위젯 그래프의 Enhanced Input 도 엔진이 구성~해제 동안 입력 스택에 올리는 스톡 동작이라 그대로다.
- **에셋 배치 vs 코드 배치**: 퀘스트 트래커·자막·스태미나 바 등 여덟 개가 이미 `WBP_GameHUD` 에 배치돼 있다. HUD 루트의 `RebuildWidget` 으로 까는 방식은 화면 전체를 좌표계로 쓰는 인디케이터 캔버스처럼 스캐폴드를 건드려야 할 때의 수단이고, 이번 위젯은 슬롯 하나에 들어가는 평범한 고정 위치 요소라 해당하지 않는다.
- **로컬 게이트 제거**: 컨트롤러 변경 훅의 가시성 대입은 원격 프록시 캐릭터에 목록이 중복 투영되는 것을 막던 장치다. HUD 는 로컬 플레이어별로 뜨므로 게이트 자체가 불필요해져 훅을 통째로 없앤다.

### 구현·결정과 그 이유
- **호스트 교체만으로 끝난 이유**: 리졸버가 위젯의 소유 플레이어로 뷰모델을 만드는 구조라, 위젯이 캐릭터에 매달려 있든 HUD 자식이든 같은 로컬 컨트롤러가 나온다. 입력도 엔진이 위젯 수명에 맞춰 스택에 넣고 빼므로 배선이 그대로 성립한다.
- **훅을 통째로 없앤 이유**: 그 안의 유일한 동작이 원격 프록시 중복 투영을 막는 가시성 게이트였다. HUD 는 로컬 플레이어별로 뜨므로 막을 중복 자체가 없어져 남길 근거가 사라졌다.
- **캐릭터가 UI 를 들지 않게 됨**: 캐릭터 클래스에서 UI 소유가 빠지면서 게임 모듈의 UI 하드참조가 하나 줄고, 목록 위젯의 유일한 참조자가 HUD 에셋으로 모인다.
