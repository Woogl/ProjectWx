# PostInitializeComponents 즉시 태그 확인 제거

## 계획

### 목표
`AWxCharacterBase::PostInitializeComponents`에서 콜백 등록 직후 `State.Ragdoll`·`Ability.Death`를 즉시 확인하는 두 분기를 지운다. 이 시점에는 어느 머신에서도 두 태그가 서 있을 수 없어서 두 분기는 실행되지 않는 코드다. 그런데도 주석이 "late join 안전망"이라고 믿게 만든다(모듈 리뷰 WxGame #6).

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.cpp` | 두 즉시 확인과 그 근거 주석을 지우고, 등록 시점이 초기 복제보다 앞선다는 점을 한 줄 덧붙인다 | 수정 |

### 접근 방식
- **경로별 검증**:
  - 권위 측은 피해 GE가 한 번도 실행되지 않은 상태다(적은 자동 빙의로 `GiveAbilitySets`까지만 끝났다). 사망은 피해 처리에서만 발동하고, 래그돌 태그는 사망 어빌리티만 붙인다.
  - 원격 측 동적 액터는 지연 없이 스폰된 뒤에 속성을 받는다. 레벨 배치 액터는 복제 전에 로드된다.
  - Iris는 엔진 기본값이 꺼져 있고 프로젝트도 켜지 않았다.
- **실제 안전망**: 늦게 들어온 태그는 등록 콜백으로 들어온다. `OnDeath` 구독 전에 방송이 지나가는 경우는 `AWxEnemyCharacter::BeginPlay`의 재확인이 맡는다.
- **동작 변화 없음**: 실행되지 않던 분기만 지운다.

```mermaid
sequenceDiagram
    autonumber
    participant Ch as UActorChannel(원격)
    participant Actor as AWxCharacterBase
    participant ASC as ASC
    Ch->>Actor: SerializeNewActor → SpawnActorAbsolute
    Actor->>ASC: PostInitializeComponents: 태그 콜백 등록(태그 없음)
    Ch->>ASC: 초기 속성 수신 → 태그 추가
    ASC->>Actor: HandleDeathTagChanged / HandleRagdollTagChanged
    Ch->>Actor: PostNetInit → BeginPlay(적: 사망 재확인)
```

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.cpp` | 래그돌·사망 즉시 확인 두 분기와 낡은 근거 주석을 지우고, 등록 시점이 초기 복제보다 앞선다는 주석 한 줄을 추가 | 수정 |

### 구현·결정과 그 이유
- **즉시 확인을 BeginPlay로 옮기지 않고 지움**: 늦게 들어온 태그는 등록 콜백이 받는다. 구독자가 빠지는 문제는 적의 BeginPlay 재확인이 이미 맡고 있다. 옮기면 콜백과 중복돼 `HandleDeath`·`EnterRagdoll`이 두 번 돈다.
- **등록 시점 주석을 덧붙임**: 즉시 확인이 없는 것을 누락으로 보고 되살리는 일을 막으려고, 콜백만으로 충분한 이유를 한 줄 남겼다.
