# "빈 대사 = 종료" 관용구 폐기

## 계획

### 목표
종료 신호가 문서와 코드에서 어긋난다. 행 구조체 주석과 README 는 "대사가 비면 종료된다"를 정상 관용구로 안내하는데, `EnterRow` 는 빈 대사를 실패로 보고 경고를 남기며 그 실패가 `Advance` 에서 두 번째 경고를 부른다. 종료를 `NextRow=None` 하나로 통일하고 문서를 코드에 맞춘다. 같은 결함이 자막에도 그대로 있어 함께 고친다.

### 접근 방식
- **코드를 남기고 문서를 고친다**: 리뷰는 양방향 택일을 제안했으나, `NextRow=None` 이 이미 명시적 종료 신호이고 "빈 대사로 끝낸다"는 종료를 표시하려고 쓸모없는 행을 하나 더 만들어야 하는 열등한 방법이다. 빈 대사는 사실상 전부 디자이너 실수(행은 만들었는데 텍스트 미기입)라, 정상으로 인정하면 그 실수가 "대화가 이유 없이 끊김"으로만 나타나 진단이 불가능해진다.
- **데이터 마이그레이션 없음**: `DT_Dialogue` 7행 전부 본문이 차 있고 `NextRow=None` 으로 끝난다(에셋 덤프 확인). 자막은 아직 테이블 자체가 없다.
- **경고 두 갈래 분리**: 지금 한 줄이 "행을 해석하지 못했거나 대사가 비어 있다"로 두 원인을 뭉뚱그려, 진짜 오타와 빈 본문이 로그에서 구분되지 않는다. 각각이 무엇을 고쳐야 하는지 말하게 한다. 빈 본문 쪽 문구가 곧 새 규약의 안내가 된다.
- **`Advance` 의 두 번째 경고는 유지**: 관용구가 사라지면 진짜 오류에만 뜬다. `EnterRow` 는 도착 행을, `Advance` 는 출발 행과 그 `NextRow` 를 찍어 잘못된 셀을 짚는 데 필요하다.

### 구현·결정과 그 이유
- **관용구를 없애고 문서를 코드에 맞췄다**: 리뷰는 양방향 택일을 제안했지만 두 종료 관용구는 서로 중복이고, `NextRow=None` 쪽이 명백히 낫다 — 빈 대사로 끝내려면 쓸모없는 행을 하나 더 만들어야 한다. 반대로 코드를 고쳐 빈 대사를 정상으로 인정하면, 텍스트 미기입이라는 흔한 실수가 "대화가 이유 없이 끊김"으로만 나타나 진단할 방법이 사라진다.
- **자막까지 함께 고쳤다**: `FWxSubtitleTableRow` 주석과 `ShowRow` 가 대화를 그대로 본떠 같은 어긋남을 안고 있었다. 대화만 고치면 다음 리뷰에서 자막이 같은 항목으로 다시 올라온다.
- **경고를 두 갈래로 나눴다**: 이 어긋남의 실질적 피해가 "빈 대사 경고와 진짜 오타 경고가 같은 문구"라는 점이었다. 관용구를 걷어내면 두 갈래 모두 진짜 오류이므로, 각각 무엇을 고쳐야 하는지 말하게 했다. 빈 대사 쪽 문구(`종료는 NextRow=None 으로 표시한다`)가 곧 새 규약의 안내 역할을 한다.
- **`Advance` 의 두 번째 경고는 남겼다**: `EnterRow` 는 도착 행을, `Advance` 는 출발 행과 그 `NextRow` 를 찍는다. 잘못된 셀을 짚으려면 출발 쪽 정보가 필요해 중복이 아니다.
