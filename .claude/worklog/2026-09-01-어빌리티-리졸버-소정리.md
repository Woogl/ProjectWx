# 어빌리티 리졸버 소정리

## 계획

### 목표
어빌리티 표시 데이터가 `IWxUIData` 로 넘어가면서 어빌리티 리졸버를 만든 원래 목적인 아이콘 주입이 사라졌다. 리졸버 자체는 슬롯 태그로 뷰모델을 고르는 자리라 존치하되, 남은 게임 모듈 의존을 실제로 필요한 하나(최대 충전 수 조회)로 줄인다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/MVVM/WxViewModelResolver_Ability.cpp` | ASC 획득을 플레이어 캐릭터 구체 타입에서 어빌리티시스템 인터페이스 캐스팅으로 교체, include 정리 | 수정 |
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_Ability.h` | 아이콘도 주입받던 시절의 낡은 게터 주석 정정 | 수정 |

### 접근 방식
- **어트리뷰트 리졸버와 같은 3줄로 맞춘다**: WxUI 의 어트리뷰트 리졸버가 이미 소유 컨트롤러의 빙의 폰을 인터페이스로 받아 ASC 를 얻는다. 같은 형태를 쓰면 리졸버 관례가 하나로 모이고, 리졸버가 게임 모듈에 남는 이유가 최대 충전 수 조회 하나로 드러난다.
- **리졸버 제거·컨버전 함수 회귀는 하지 않는다**: `IWxUIData` 는 뷰모델이 도메인 데이터를 읽는 통로고 리졸버는 위젯이 뷰모델 인스턴스를 얻는 통로라 층이 다르다. 컨버전 함수는 슬롯 태그가 리터럴로 박히는 문제 때문에 2026-08-20 에 리졸버로 일원화한 이력이 있고, 되돌려도 최대 충전 수 때문에 게임 모듈에 라이브러리를 새로 둬야 해 모듈 경계 문제가 그대로다.
- **최대 충전 수는 표시값이 아니다**: 충전 수 파생과 쿨다운 재스캔의 입력이라 위젯 바인딩 시점의 컨버전으로 뺄 수 없다. 계약 확장 여부는 이전 보류 결정을 그대로 둔다.

### 구현·결정과 그 이유
- **어트리뷰트 리졸버와 같은 형태로**: 리졸버가 필요한 것은 ASC 하나지 플레이어 캐릭터라는 구체 타입이 아니었다. WxUI 의 어트리뷰트 리졸버가 쓰는 인터페이스 캐스팅을 그대로 가져와 리졸버 관례를 하나로 모았다. 부수적으로 ASC 를 가진 다른 폰에 빙의해도 슬롯이 동작한다.
- **리졸버는 존치**: 표시 데이터가 계약으로 넘어간 것은 뷰모델이 도메인 데이터를 읽는 통로가 바뀐 것이고, 위젯이 슬롯 태그로 뷰모델 인스턴스를 고르는 자리는 여전히 리졸버뿐이다. 컨버전 함수로 되돌리는 갈래는 슬롯 태그가 리터럴로 박히는 문제로 이미 한 번 접은 방향이라 다시 열지 않았다.
- **최대 충전 수 주입은 그대로**: 충전 수 파생과 쿨다운 재스캔의 입력이라 위젯 바인딩 시점에 변환해 쓰는 값이 아니다. 계약에 올릴지는 이전 보류 결정을 유지한다.

### 후속 과제
- 리졸버가 게임 모듈에 남는 이유는 이제 최대 충전 수 조회 하나다. WxUI 이관은 그 공급 통로가 정해질 때까지 보류다. 옮기게 되면 위젯 에셋 두 개가 옛 경로를 물고 있어 CoreRedirects 신설이 필요하다.
- 빌드까지만 확인했다. PIE 에서 스킬바 슬롯 4개의 아이콘·쿨다운·충전 수 표시는 미검증.
