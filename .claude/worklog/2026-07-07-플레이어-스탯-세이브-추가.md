# 플레이어 캐릭터 전체 스탯 세이브/로드 추가

## 계획

### 목표
세이브/로드 파이프라인에 플레이어 캐릭터의 **모든 어트리뷰트 base 값**(HP/MaxHP/…/ATK/DEF/SPD 등) 영속을 추가한다. 인벤토리·버프·태그는 제외. Provider 인터페이스 없이, 캐릭터가 자기 스탯 캡처/적용을 소유하고 체크포인트(저장)·GameMode(로드)가 직접 호출한다. WxCore 불변.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxSave/.../Public/WxPersistenceSaveGame.h` | `UWxPersistenceSaveGame` 최상위에 `TMap<FName,float> PlayerStats` + `bool bHasPlayerStats` 추가 (TravelData 밖 — `FlushMapTravelData` 덮어쓰기 회피) | 수정 |
| `Source/WxGame/Character/WxCharacterBase.h/.cpp` | `public` 메서드 `CaptureSaveStats(TMap<FName,float>&) const` / `ApplySaveStats(const TMap<FName,float>&)`. GAS 리플렉션으로 `CPF_Net` 어트리뷰트 base 캡처/복원 | 수정 |
| `Source/WxGame/WorldObject/WxCheckPoint.cpp` | `HandleInteracted`의 **기존 `SaveToFile()` 바로 앞**(회복·리필·리스폰 이후)에 캐릭터 캐스팅→`CaptureSaveStats`로 `SaveGame->PlayerStats` 채움 + `bHasPlayerStats=true` | 수정 |
| `Source/WxGame/Framework/WxGameMode.cpp` | `FinishRestartPlayer`에서 `bHasPlayerStats`면 새 폰 캐스팅→`ApplySaveStats` | 수정 |

### 접근 방식
- **인터페이스 제거**: WxSave가 스탯을 자동 캡처하려면 GAS 브리지(인터페이스/델리게이트)가 필요하지만, 캡처를 체크포인트 저장 시점에 명시적으로 하면 캐릭터 public 메서드 2개로 충분하다. WxGame 내부(체크포인트/GameMode)가 캐릭터를 직접 캐스팅한다.
- **최상위 필드**: `FlushMapTravelData`가 `TravelData`를 통째 재구성하므로, 스탯은 `TravelData` 밖 SaveGame 최상위에 둬 캡처 순서와 무관하게 보존한다.
- **리플렉션 순회**: 어트리뷰트 16개를 손으로 나열하지 않고 `TFieldIterator<FStructProperty>`로 `FGameplayAttributeData`·`CPF_Net`만 순회한다(메타 `IncomingDamage` 자동 제외, 신규 스탯 자동 포함).
- **복원 2패스**: `PreAttributeChange`가 HP 등을 현재 MaxHP로 클램프하고 `PostAttributeChange`가 Max 변경 시 current를 비율 재조정하므로, **Max\* 어트리뷰트 먼저 → 나머지 나중** 2패스로 세팅해 충돌을 막는다. base 저장/복원(`Get/SetNumericAttributeBase`).
- **캡처 타이밍**: 체크포인트 `HandleInteracted`는 `HealEffect`(Instant GE, 즉시 동기 반영)로 HP를 만피로 만든 뒤 저장하므로, `SaveToFile()` 직전 캡처는 회복된 값을 담는다.
- **게이트**: `bHasPlayerStats`만(스탯은 맵 무관 → 맵 일치 체크 불필요).

### 구현·결정과 그 이유
- **브리지 인터페이스 미도입, WxSave 가 GameplayAbilities 직접 참조**: `GameplayAbilities` 는 엔진 플러그인이라 "Wx 플러그인 간 참조 금지" 규칙 대상이 아니다. WxSave 가 폰→`IAbilitySystemInterface`→ASC 로 접근해 `UAttributeSet` 리플렉션으로 순회하면, 구체 전투 타입(`UWxCombatAttributeSet`)을 참조하지 않고도 제네릭하게 캡처/복원할 수 있어 도메인 독립성이 유지된다.
- **캡처를 저장 파이프라인으로**: `RequestSaveFlush → FlushPlayerStats` 가 첫 플레이어 폰 스탯을 자동 캡처하므로, 체크포인트·메뉴 등 모든 `SaveToFile` 경로가 커버된다. 체크포인트 수동 캡처와 캐릭터 메서드는 제거했다.
- **복원은 GameMode 가 호출**: 새 폰 스폰/possess 타이밍은 GameMode 소관이라, WxSave 의 static 헬퍼를 `FinishRestartPlayer`(ASC 초기화 이후)에서 호출한다.
- **최상위 필드**: `FlushMapTravelData` 가 `TravelData` 를 통째 재구성하므로 스탯은 그 밖 최상위에 둔다.
- **리플렉션 + CPF_Net 필터**: 비복제 메타(IncomingDamage) 자동 제외, 신규 스탯 자동 포함.
- **복원 2패스(Max 먼저)**: `PreAttributeChange` 클램프·`PostAttributeChange` 비율 재조정과의 충돌 방지.
- **게이트 `bHasPlayerStats` 단독**: 스탯은 맵 무관.

### 계획 대비 달라진 점
- **캡처 위치 변경(사용자 요청)**: "체크포인트 수동 캡처 + 캐릭터 public 메서드" → "저장 파이프라인 자동 캡처". 이로써 메뉴 수동 저장까지 스탯이 잡힌다. 브리지 인터페이스 없이 WxSave 의 GameplayAbilities 참조로 해결.

### 후속 과제
- **리플렉션 순회의 미래 조건부 리스크**: (1) ASC 에 AttributeSet 이 복수가 되고 서로 동명 어트리뷰트가 생기면 `TMap<FName,float>` 키 충돌 — 현재 단일 set 이라 무해, 필요 시 "SetName.AttrName" 키로 확장. (2) 복원 2패스가 `"Max"` 접두 네이밍 관례에 의존 — 관례 이탈 시 순서 보장 깨짐. (3) 저장 제외가 필요한 복제 어트리뷰트가 생기면 명시 제외 목록 필요.
- PIE 실동작 검증 미수행(컴파일만 확인).
