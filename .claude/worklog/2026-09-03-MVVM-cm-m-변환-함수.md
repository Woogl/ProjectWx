# MVVM cm → m 변환 함수 추가

> **정정**: 아래 "인자를 float 으로" 근거는 틀렸다. MVVM 은 float/double 실수 핀을 호환으로 판정하므로(`EdGraphSchema_K2.cpp:4502`) double 로 둬도 바인딩이 물린다. 이후 double 로 전환했다 — `2026-09-03-변환-함수-double-전환.md` 참고.

## 계획

### 목표
MVVM 바인딩에서 cm 거리 값을 m 로 보여줄 수단이 없어 `Divide (double)` 에 리터럴 100 을 꽂아 우회해야 했다. 자릿수 반올림까지 한 번에 처리하는 전용 변환 함수를 `UWxMVVMConversionLibrary` 에 둔다.

### 수정 범위

|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxMVVMConversionLibrary.h` | `Conv_CentimetersToMeters` 선언 추가 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/MVVM/WxMVVMConversionLibrary.cpp` | 구현 추가 | 수정 |

### 접근 방식
- **기존 변환 함수와 동일한 형태**: `BlueprintPure` static, DisplayName 은 엔진 관례(`To <Dest> (<Source>)`)를 따라 `To Meters (Centimeters)`.
- **시그니처**: `static float Conv_CentimetersToMeters(float Centimeters, int32 FractionDigits = 1)` (이후 double 로 전환). 소스 인자 뒤의 추가 인자는 바인딩 편집기가 리터럴로 채운다 — 엔진 `Conv_BoolToSlateVisibility` 와 같은 구조.
- **인자를 float 으로**: 프로젝트 VM 필드가 전부 C++ `float` 이기 때문. ~~`double` 로 두면 소스 프로퍼티와 타입이 어긋난다~~ → 틀림. 실수 핀끼리는 호환이다.
- **double 로 계산 후 마지막에만 float 으로**: 나눗셈·스케일링 누적 오차를 줄인다.
- **FractionDigits 를 0~6 으로 클램프**: 음수면 `Scale < 1` 이 되어 m 단위가 뭉개지고, 큰 값이면 `Scale` 이 발산해 NaN 이 된다.

### 한계
부동소수는 12.3 을 정확히 담지 못한다. 값만 반올림할 뿐 실제 표시 자릿수는 뒤따르는 Text 변환이 정한다. 표시 자릿수까지 보장하려면 Text 반환 함수가 필요하나 이번 범위 밖이다.

### 범위에서 제외
`WxIndicator.cpp:189` 의 인라인 cm→m 계산은 MVVM 바인딩용이 아닌 C++ 호출부라 건드리지 않는다.

### 구현·결정과 그 이유
- **엔진·프로젝트에 대체재가 없음을 먼저 확인**: 엔진 `UMVVMConversionLibrary` 는 `Conv_BoolToSlateVisibility` 하나뿐이고, Font/SlateBrush 변환 라이브러리는 머티리얼 파라미터 세팅용이다. `FUnitConversion` 은 C++ 전용이라 바인딩 변환 함수로 쓸 수 없어 새로 만드는 것이 맞았다.
- **인자를 `float` 으로**: ~~`double` 로 두면 소스 프로퍼티와 타입이 어긋나 바인딩이 물리지 않는다~~ → 틀린 근거였다. 실수 핀끼리는 호환이라 어느 쪽이든 물린다.
- **자릿수 지정을 두 번째 인자로**: 소스 인자 뒤의 기본값 인자는 바인딩 편집기가 리터럴로 채운다 — 엔진 `Conv_BoolToSlateVisibility` 와 같은 구조라 별도 장치가 필요 없다.
- **0~6 클램프**: 음수면 `Scale < 1` 이 되어 m 단위가 뭉개지고, 큰 값이면 `Scale` 이 발산해 NaN 이 된다. (상한 6 의 근거였던 float 유효자릿수는 double 전환으로 무의미해졌으나, m 단위 UI 표시에 소수 6자리를 넘길 이유가 없어 상한은 유지했다.)
