# 상호작용 자격 판정에 주체 인자 복원

## 계획

### 목표
`IWxInteractable::CanInteract()`에 주체 인자를 되돌려, 클라 표시 게이트와 서버 권위 자격 검증이 "실제로 상호작용하려는 주체" 기준으로 같은 답을 내게 한다. 주체를 스스로 추측하던 `AWxEnemyCharacter`의 0번 플레이어 조회를 없애, 데디케이티드 멀티에서 2번째 이후 플레이어의 뒤잡이 0번 플레이어 위치로 판정되던 오판을 제거한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/Source/WxCore/Public/WxInteractable.h` | `CanInteract(const AActor* Interactor) const`로 시그니처 변경, 계약 주석 작성 | 수정 |
| `Plugins/WxCore/Source/WxCore/Private/WxInteractable.cpp` | 기본 구현 시그니처 맞춤(여전히 `true`) | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueActor.h`, `Private/WxDialogueActor.cpp` | override 시그니처 맞춤 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Public/Device/WxDevice.h`, `Private/Device/WxDevice.cpp` | override 시그니처 맞춤, `OnInteracted`의 내부 재검증에 받은 주체 전달 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Private/Interaction/WxInteractionScannerComponent.cpp` | `Target->CanInteract(Pawn)` | 수정 |
| `Source/WxGame/AbilitySystem/Ability/WxAbility_Interact.cpp` | `Target->CanInteract(Avatar)` | 수정 |
| `Source/WxGame/Character/WxEnemyCharacter.h`, `.cpp` | `IsLocalPlayerInRearCone()` → `IsInRearCone(const AActor* Interactor)`, 0번 플레이어 조회 제거, 주석 갱신 | 수정 |

### 접근 방식
- **주체 타입은 `const AActor*`**: 자격 판정은 주체를 읽기만 한다. `OnInteracted(AActor*)`가 비-const인 것과 갈리지만 응답 실행과 자격 조회는 요구가 다르다.
- **주체는 호출부가 보장한다**: 발동 경로는 `Avatar` 널 체크를 지난 뒤이고, 표시 경로는 폰이 유효할 때만 스캔한다. 계약 주석에 이를 명시하되 주체를 실제로 읽는 구현체만 널을 `false`로 방어한다.
- **주체를 안 보는 구현체도 인자 이름은 유지**한다. 대화·장치는 `bInteractionEnabled`만 보므로 본문은 그대로다.
- **`AWxEnemyCharacter`가 유일한 실질 변화**: 후방 원뿔을 받은 주체 위치로 재고, 이름도 `IsInRearCone`으로 줄인다. 헤더의 "대상이 직접 찾는다 / 데디에서 0번 기준" 제약 주석은 사라지므로 함께 지운다.
- **`AWxDevice::OnInteracted`의 내부 재검증도 주체를 넘긴다**: 어빌리티가 통과시킨 것과 같은 기준으로 한 번 더 가르는 자리라, 인자 없는 호출을 남기면 두 검증의 기준이 갈린다.
- **범위 밖**: 프롬프트 문자열 하드코딩(WxGame 리뷰 건)은 별건이라 손대지 않는다.

### 구현·결정과 그 이유
- **주체를 계약에 되돌렸다**: 표시와 발동이 같은 함수를 지나므로 자격 판정의 단일 소스라는 성질은 그대로 두되, "누가"가 빠져 있어 상대 자격을 구현체가 추측할 수밖에 없던 구멍만 메웠다. 두 호출부가 이미 주체를 스코프에 들고 있어 전달 외에 추가 조회·저장이 없다.
- **`const AActor*`로 받는다**: 자격 판정은 주체를 읽기만 한다. 응답을 시켜야 하는 `OnInteracted`와 달리 const를 벗길 이유가 없다.
- **널 방어는 주체를 읽는 구현체에만 두었다**: 호출부 둘 다 유효성을 이미 확인한 뒤 부르므로 계약 주석으로 그 보장을 적고, 실제로 위치를 읽는 후방 원뿔 판정만 널을 false로 답한다.
- **장치의 내부 재검증도 주체를 넘긴다**: 어빌리티가 통과시킨 것과 같은 기준으로 한 번 더 가르는 자리라, 인자 없는 호출이 남으면 두 검증의 기준이 갈릴 수 있었다.

### 후속 과제
- PIE 실동작(비전투 적 후방 접근 시 프롬프트 노출, 정면·인지 후 미노출, 뒤잡 몽타주 재생) 미검증. 데디케이티드 멀티 2인 이상 세션에서의 주체별 판정도 코드 경로 확인까지만 했다.
- 데디 멀티에선 스캔 시점의 클라 위치와 서버 검증 시점의 서버 위치가 지연만큼 달라, 경계각에서 표시와 발동이 갈릴 여지는 남는다(사거리 검증이 이미 안고 있는 성질과 동일).
