# 퀘스트 StateTree 순정 전환 — UWxQuestStateTree 제거

## 계획

### 목표
퀘스트 ST 에셋을 구분하려고 뒀던 빈 마커 클래스 `UWxQuestStateTree` 를 걷어내고 엔진 순정 `UStateTree` 로 통일한다. 마커 때문에 순정 생성 경로(팩토리·MCP 툴셋)가 퀘스트 에셋을 만들지 못하는 상태이고, 전용 팩토리는 이미 디스크에서 사라져 신규 저작 경로가 끊겨 있다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Config/DefaultEngine.ini` | `[CoreRedirects]` 신설 + `WxQuestStateTree` → `/Script/StateTreeModule.StateTree` 클래스 리디렉트 | 수정 |
| `Plugins/WxQuest/.../Public/Quest/WxQuestStateTree.h` | 마커 클래스 | 삭제 |
| `Public/Quest/WxQuestComponent.h`, `Private/Quest/WxQuestComponent.cpp` | 전방선언·3개 함수 시그니처 타입 교체, 불용 include 제거, 클래스 주석 정정 | 수정 |
| `Public/Quest/WxQuestLibrary.h`, `Private/Quest/WxQuestLibrary.cpp` | `StartQuest` 인자 타입 교체 | 수정 |
| `Public/Quest/WxStateTreeTask_StartNextQuest.h`, `.cpp` | 인스턴스 데이터 `Quest` 소프트 참조 타입 교체, 불용 include 제거 | 수정 |
| `Plugins/WxQuest/README.md` | 마커 클래스 행 삭제 | 수정 |

### 접근 방식
- **클래스 리디렉트 선행**: 저장된 패키지가 사라질 클래스를 참조하므로(퀘스트 ST 2개는 자기 클래스, `BP_QuestVolume` 은 변수·핀 타입, 배치 외부 액터 2개는 그 값) 리디렉트를 먼저 넣고 클래스를 지운다. 재저장으로 굳히는 것과 리디렉트 제거는 누락 위험이 있어 별건으로 남긴다.
- **마커 상실 감수**: 퀘스트 지정 픽커에 프로젝트의 모든 `UStateTree` 가 뜨게 된다. 필터가 다시 필요하면 마커 부활이 아니라 메타 기반으로 건다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Config/DefaultEngine.ini` | `[CoreRedirects]` 신설, `WxQuestStateTree` → `/Script/StateTreeModule.StateTree` 클래스 리디렉트 1줄 | 수정 |
| `Plugins/WxQuest/.../Public/Quest/WxQuestStateTree.h` | 마커 클래스 | 삭제 |
| `Public/Quest/WxQuestComponent.h` | 전방선언 교체, `ActivateQuest`·`RequestActivateQuest`·`HandleDeferredActivateQuest` 타입 교체, 클래스 주석 정정 | 수정 |
| `Private/Quest/WxQuestComponent.cpp` | 세 함수 정의 타입 교체, 마커 헤더 include 제거 후 `StateTree.h` 로 대체 | 수정 |
| `Public/Quest/WxQuestLibrary.h`, `Private/Quest/WxQuestLibrary.cpp` | `StartQuest` 인자 타입 교체 | 수정 |
| `Public/Quest/WxStateTreeTask_StartNextQuest.h`, `.cpp` | 인스턴스 데이터 `Quest` 소프트 참조 타입 교체, 불용 include 제거 | 수정 |
| `Plugins/WxQuest/README.md` | 핵심 타입 표에서 마커 클래스 행 삭제 | 수정 |

### 구현·결정과 그 이유
- **리디렉트를 남긴다**: 저장된 패키지 다섯(퀘스트 ST 2개는 자기 클래스, `BP_QuestVolume` 은 변수·핀 타입, 배치 외부 액터 2개는 그 값)이 사라진 클래스를 가리키므로 리디렉트 없이는 로드 자체가 깨진다. 재저장으로 굳힐 수 있지만 누락 시 조용히 죽는 쪽이 아니라 대놓고 못 여는 쪽이라, 확인 전까지는 남겨두는 편이 안전하다.
- **마커 대신 순정 타입**: 마커가 주던 것은 픽커 필터뿐이었고, 대가로 순정 생성 경로(팩토리·MCP 툴셋)를 통째로 잃고 있었다. 전용 팩토리는 이미 디스크에 없어 신규 퀘스트 저작이 막힌 상태였다.
- **`StateTree.h` 를 cpp 에 직접 넣음**: 마커 헤더가 대신 끌어오던 완전 타입이 사라졌는데, 다음 틱 콜백의 소프트 참조 로드가 `Cast` 를 거쳐 완전 타입을 요구한다.

### 계획 대비 달라진 점
- 계획에서는 전방선언만으로 충분하다고 봤으나 위 이유로 `WxQuestComponent.cpp` 에 `StateTree.h` include 를 추가했다.

### 후속 과제
- 에디터에서 퀘스트 ST 2개·`BP_QuestVolume`·해당 레벨의 배치 액터가 값 손실 없이 열리는지, PIE 로 수주→저널→체인이 도는지 확인(빌드까지만 검증됨).
- 위 확인 후 다섯 패키지를 재저장하면 클래스가 굳으므로, 그 시점에 리디렉트 제거 가능(별건).
- 퀘스트 지정 픽커에 모든 `UStateTree` 가 뜨는 것은 감수한 사항. 필터가 다시 필요해지면 마커 부활이 아니라 메타로 건다.
