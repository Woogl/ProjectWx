# Event.Backstab 제거 + State.BeingFinished → Ability.BeingFinished 이관

## 계획

### 목표
적이 앞잡/뒤잡을 골라 보내던 이벤트 태그 둘을 `Event.Finisher` 하나로 줄이고, 변형 선택을 어빌리티 에셋의 순정 태그 요건으로 옮긴다. 공격자가 대상에 수동으로 걸던 `State.BeingFinished`는 피해자 어빌리티가 스스로 발행하는 `Ability.BeingFinished`로 바꿔 "어빌리티는 자기 `Ability.*`를 발행한다" 규약에 맞춘다.

### 접근 방식
- **변형 선택을 태그 요건으로**: 엔진은 이벤트 페이로드의 `TargetTags`를 `CanActivateAbility`의 순정 `TargetRequiredTags`/`TargetBlockedTags` 판정에 넘긴다. 적이 자기 소유 태그를 실어 보내면 앞잡 에셋은 `Ability.Groggy` 필수, 뒤잡 에셋은 `Ability.Groggy` 차단으로 하나만 성립한다. 적 코드는 변형을 모른다.
- **피해자 어빌리티가 자기 상태를 발행**: 활성 태그는 엔진 기본 설정에서 존재가 전원에 복제되므로(`CountToOwner`), `Ability.Groggy`와 같은 경로로 클라 프롬프트 게이트에 닿는다. 태그 수명이 공격자 몽타주에서 피해자 몽타주(기상 포함)로 바뀌어 기상 중 재처형 프롬프트가 닫힌다.

### 구현·결정과 그 이유
- **변형 선택을 순정 태그 요건으로**: 적은 이벤트 하나에 자기 소유 태그만 실어 보내고, 앞잡은 그로기 필수·뒤잡은 그로기 차단을 각 클래스 생성자가 선언한다. 엔진이 페이로드 `TargetTags`를 `CanActivateAbility` 요건 판정에 넘기므로 코드 분기가 없다.
- **뒤잡을 독립 C++ 클래스로**: 상속으로 앞잡 요건을 되돌리는 꼴을 피하고(사용자 지시), 뒤잡에 없는 그로기 해제도 자연히 빠진다. 워프·피해자 부여·대미지 위임은 두 클래스가 각자 갖는다.
- **피해자 상태는 피해자 어빌리티가 발행**: 활성 태그는 존재가 전원에 복제되므로(`CountToOwner`) 다른 클라의 프롬프트 게이트에도 닿는다. 태그 수명이 피해자 몽타주(기상 포함)로 바뀌어 기상 중 재처형이 닫힌다.
- **GA_Finisher는 에셋 수정 없음**: 저장돼 있던 트리거가 생성자 값과 같고, 요건은 생성자에서 온다. GA_Backstab만 부모 교체와 죽은 트리거 정리가 필요했다 — 첫 로드에 `Invalid GameplayTag Event.Backstab` 경고가 한 번 났고 재저장으로 사라졌다.

### 계획 대비 달라진 점
- 승인 계획은 요건을 에셋(`TargetRequired/BlockedTags`)에 두는 것이었으나, 구현 중 사용자 지시로 뒤잡을 `UWxAbilityBase` 직계 C++ 클래스로 분리하고 요건·트리거를 생성자로 옮겼다. 그에 따라 `Ability.Backstab` 태그가 늘고 상호작용 차단이 둘을 본다.

### 후속 과제
- PIE 실동작은 사용자가 확인: 그로기 적 → 앞잡만, 미인지 후방 → 뒤잡만; 처형 중·기상 중 프롬프트 닫힘; 로그에 `LogAbilitySystem` Error 없음.
