# 퀘스트 제목·목표 태스크 분리와 다중 목표 지원

## 계획

### 목표
제목과 목표를 겸하던 태스크 하나를 제목 전용·목표 전용 둘로 나눈다. 제목은 퀘스트당 하나지만 목표는 여러 개일 수 있으므로, 저널이 목표 목록을 담고 트래커가 그 목록을 표시하게 한다.

### 접근 방식
- **목표의 수명 = 상태의 수명**: 목표 태스크는 진입 시 저널에 목표를 등록해 핸들을 인스턴스 데이터에 보관하고, 상태를 떠날 때 그 핸들로 제거한다. 정리 전용 태스크가 필요 없고, 부모 상태와 자식 상태가 각각 목표를 걸면 두 목표가 동시에 표시된다 — 병렬 상태가 없는 StateTree 에서 다중 목표는 이렇게 성립한다. 같은 모양의 기존 노드(인디케이터 표시)를 그대로 따른다.
- **저널 태스크는 완료 판정에서 제외**: 엔진은 상태별로 자기 태스크의 완료를 따로 본다. 제목·목표 태스크가 완료 판정에 들어가면 자식을 가진 상태에 얹었을 때 그 상태가 즉시 완료돼 퀘스트가 통째로 관통된다. 둘 다 표시용 부수효과일 뿐이므로 생성자에서 아예 제외한다.
- **목표 목록 표시는 기존 리스트 패턴 재사용**: 상호작용 목록(리스트뷰 + 엔트리 위젯 + 엔트리 뷰모델 배열)과 같은 구조로 트래커를 바꾼다.

### 구현·결정과 그 이유
- **목표의 수명을 상태의 수명에 묶었다**: 목표 태스크가 진입 시 저널에 걸고 이탈 시 걷어간다. 정리 전용 태스크가 없어도 스텝이 바뀌면 이전 목표가 저절로 사라지고, 부모 상태와 자식 상태에 각각 걸면 두 목표가 동시에 표시된다. 병렬 상태가 없는 StateTree 에서 여러 목표를 동시에 세울 방법은 이것뿐이다. 진입에서 등록하고 이탈에서 해제하는 인디케이터 노드가 이미 같은 모양이라 구조를 그대로 따랐다.
- **목표를 문구가 아니라 발급 핸들로 지목한다**: 서로 다른 상태가 같은 문구를 걸 수 있어 문구로는 어느 것을 걷어갈지 가릴 수 없다. 핸들은 재사용하지 않으므로, 저널이 이미 비워진 뒤 뒤늦게 들어온 제거 요청이 엉뚱한 목표를 건드리지 못한다.
- **두 태스크를 상태 완료 판정에서 제외했다**: 엔진은 상태마다 자기 태스크의 완료를 따로 본다. 판정에 끼어 있으면 자식을 둔 상태에 얹는 순간 그 상태가 곧바로 완료되고, 그 완료가 위로 전파돼 퀘스트가 통째로 관통된다. 에셋에서 매번 체크를 풀게 하는 대신 생성자에서 못 박아, 잘못 놓을 여지를 없앴다.
- **목표 목록 표시는 이미 있는 리스트 패턴을 재사용했다**: 상호작용 목록이 쓰던 리스트뷰 + 엔트리 위젯 + 엔트리 뷰모델 배열 구조를 그대로 가져왔다. 엔트리 위젯은 리스트 항목 인터페이스가 필요해 새로 만들 수 없어 상호작용 엔트리를 복제한 뒤 뷰모델과 그래프를 갈아끼웠다.
- **엔트리 텍스트의 자동 줄바꿈을 껐다**: HUD 좌상단 슬롯이 자동 크기라 트래커 폭이 내용물의 desired width 로 정해진다. 자동 줄바꿈 텍스트의 desired width 는 부모가 내어준 폭에 맞춰 접힌 결과라, 그 폭이 다시 자식에게서 결정되는 자동 크기 부모 아래에서는 순환이 좁은 값으로 고착된다. 그래서 트래커 폭이 제목 길이까지 눌리고 목표가 접혔다. 줄바꿈을 끄면 desired width 가 한 줄 전체 폭이 되어 리스트 → 트래커로 그대로 전달된다. 엔트리 정렬도 좌측에서 채움으로 바꿔 리스트 폭을 온전히 쓴다.
- **폭 고정은 쓰지 않았다**: 처음엔 리스트뷰가 폭을 못 내놓는 줄 알고 SizeBox 로 400 을 박았으나, `SListPanel::ComputeDesiredSize` 가 가로로는 자식 중 최대 폭을, 세로로는 항목 높이 × 실제 항목 수를 돌려주므로 리스트뷰도 자동 크기 부모에서 정상 동작한다. 고정 폭은 불필요해 제거했고, 트래커는 예전처럼 내용 길이에 맞춰 늘어난다.

### 계획 대비 달라진 점
- 계획대로. 다만 퀘스트 제목은 스텝마다 달랐던 둘 중 "Scout the Camp" 로 통일했다(다른 하나는 플레이스홀더로 판단).

### 후속 과제
- 인게임 표시 확인: 대화로 퀘스트를 시작해 제목이 한 번만 뜨는지, 스텝 전환 시 목표만 바뀌는지, 부모·자식 상태에 목표를 동시에 걸었을 때 두 줄이 함께 보이는지. 빌드·에셋 컴파일·바인딩 보존까지는 확인했으나 실제 플레이 검증은 남아 있다.
