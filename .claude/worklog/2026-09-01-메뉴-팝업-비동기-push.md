# 메뉴·팝업 push 를 비동기 경로로 통일

## 계획

### 목표
메뉴 토글과 확인 팝업이 위젯 클래스를 동기 로드해 입력 프레임을 멈추는 문제를, 이미 있는 스트리밍 push 액션으로 옮겨 없앤다. 옮기고 나면 쓰이지 않는 동기 push API 도 함께 걷는다.

### 접근 방식
- **push 직전 콜백**: 팝업은 활성화 전에 내용을 채워야 한다. 기존 `BeforePush` 는 블루프린트용 동적 델리게이트라 페이로드를 실은 네이티브 바인딩이 안 되므로, 완료 콜백과 같은 모양의 네이티브 콜백을 하나 더 두어 위젯 생성 직후에 실행한다.
- **확인 팝업**: 서술자와 결과 콜백을 push 직전 콜백의 페이로드로 실어 잇는다. 서술자는 소유자가 없어 스트리밍 대기 중 수거될 수 있으므로 페이로드에서 강한 참조로 잡는다.
- **메뉴 토글**: 소프트 클래스를 그대로 액션에 넘긴다. 로드가 끝나기 전까지 HUD 입력 바인딩이 살아 있어 연타로 메뉴가 겹칠 수 있으므로, 진행 중인 요청을 기억해 그동안의 입력은 무시한다.
- **죽은 동기 push 삭제**: 두 경로가 옮겨가면 클래스를 받아 곧바로 스택에 넣던 API 는 호출자가 없어진다. 레이어 push 는 액션이 만든 인스턴스를 넣는 한 경로만 남긴다.

### 구현·결정과 그 이유
- **push 직전 콜백을 새로 둔 이유**: 팝업은 활성화 전에 서술자를 받아야 하는데, 기존의 push 직전 신호는 블루프린트용 동적 델리게이트라 네이티브에서 페이로드를 실을 수 없다. 완료 콜백으로 미루면 팝업이 뜬 뒤에 내용이 채워지고, 서브시스템에 대기 중 서술자를 멤버로 들면 상태가 늘어난다. 액션 쪽에 완료 콜백과 같은 모양을 하나 더 두는 편이 기존 초기화 순서를 그대로 지킨다.
- **서술자 수명**: 서술자는 소유자 없이 만들어져 델리게이트 말고는 붙잡는 곳이 없다. 동기 로드일 때는 문제가 없었지만 스트리밍을 기다리는 동안은 수거 대상이 되므로 페이로드에서 강한 참조로 잡고, 액션이 끝날 때 함께 놓는다.
- **메뉴 연타 차단**: 로드가 끝나기 전까지 HUD 의 토글 바인딩이 살아 있어 연타로 메뉴가 두 장 쌓일 수 있다. 동기 로드 때는 없던 창이라, 진행 중인 요청을 기억해 그동안의 입력을 흘린다.
- **동기 push API 삭제**: 두 경로가 옮겨가면서 클래스를 받아 곧바로 스택에 넣던 API 는 호출자가 사라졌다. 레이어 push 를 "액션이 만든 인스턴스를 넣는" 한 경로로 좁혀 둔다.
