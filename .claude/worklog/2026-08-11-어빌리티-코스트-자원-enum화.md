# 어빌리티 코스트 자원 enum화

## 계획

### 목표
`FWxAbilityTableRow`의 `MPCost`·`UPCost`·`SPCost` 3필드를 「자원 enum 1개 + 수치 1개」로 통합한다. 실제 규칙은 "어빌리티 하나가 자원 하나를 소모"인데 3필드 구조는 동시 입력을 허용해 잘못된 자유도를 주고, 자원이 늘 때마다 필드가 선형으로 늘어난다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/.../Ability/WxAbilityTableRow.h` | `EWxAbilityCostResource` 신설, 3필드 → `CostResource`+`CostAmount` | 수정 |
| `WxCombat/.../Effect/WxMMC_Cost.{h,cpp}` | `GetCostRow` → `GetCostMagnitude(Spec, Resource)`, 파생 3개는 한 줄 | 수정 |
| `WxCombat/.../Effect/WxEffect_Cost.h` | 주석 갱신 | 수정 |
| `WxCombat/.../Ability/WxAbility_Sprint.h`, `WxAbilityBase.h` | 주석 갱신 | 수정 |

### 접근 방식
- **자원 선택은 enum, 수치는 하나**: `CostResource`가 `None`이면 코스트 미적용. `CostAmount`에 EditCondition은 걸지 않는다.
- **MMC 3분화 유지, 로직만 베이스로**: 베이스가 Row의 `CostResource`와 인자를 대조해 일치할 때만 `-CostAmount`를 반환하고, 파생 3개는 자기 자원을 넘기는 한 줄만 남긴다.

#### MMC 1개 통합 검토 결과 (UE 5.8 소스 확인)
- `FCustomCalculationBasedFloat`는 MMC **클래스의 CDO**에 `CalculateBaseMagnitude(Spec)`를 호출한다. 인자가 Spec뿐이라 평가 중인 모디파이어가 어느 자원인지 알 수 없다 → 자원 구분은 클래스로만 가능.
- 자원 부족 판정(`CanApplyAttributeModifiers`)은 Additive 모디파이어만 본다. ExecutionCalculation 1개로 합치면 순정 코스트 검사가 무력화돼 `CheckCost`를 직접 구현해야 한다 → 엔진 판정의 중복 구현이라 기각.
- 어빌리티별 GE 인스턴스에 모디파이어를 바꿔 끼우는 방식도 불가. `ApplyGameplayEffectToOwner`가 `GameplayEffect->GetClass()`로 스펙을 다시 만들어(`GameplayAbility.cpp:2044`) 인스턴스 변경분이 적용 경로에 반영되지 않는다.
- 남는 대안인 "자원별 GE 3개 + `GetCostGameplayEffect()` 오버라이드"는 분기 위치만 옮기면서 클래스와 코드가 더 늘어나므로 채택하지 않는다.

### 데이터 영향
`DT_Ability.uasset`에 직렬화된 `MPCost`·`UPCost` 값은 프로퍼티 이름이 바뀌어 로드 시 초기화된다. 3필드→2필드라 CoreRedirect로는 자원 선택까지 복원할 수 없으므로 리다이렉트를 두지 않고, 에디터에서 재입력한다.

### 구현·결정과 그 이유
- **MMC 3분화 유지, 로직은 베이스 한 곳**: 엔진이 MMC 클래스 CDO에 Spec만 넘겨 호출하므로 어느 모디파이어를 평가 중인지 알 수 없다. 자원 구분은 클래스로만 가능해 3분화는 남기고, Row 조회와 자원 대조는 베이스 `GetCostMagnitude` 하나로 모아 파생 클래스를 한 줄로 줄였다.
- **모디파이어는 계속 3개**: Row가 고르지 않은 자원은 0을 반환한다. 순정 `CanApplyAttributeModifiers`는 값이 0이면 부족 판정을 내리지 않으므로 코스트 검사에 영향이 없고, 이는 필드 3개 시절과 같은 동작이다.
- **`CostAmount`에 EditCondition 미적용**: 자원이 `None`이어도 칸이 그대로 보이고 편집된다. 값이 남아 있어도 자원이 없으면 소모가 없다.

### 후속 과제
- 에디터 작업 필요 — `DT_Ability`의 `GA_Skill_1~4`·`GA_Ultimate`에 있던 MP/UP 코스트 값은 프로퍼티명이 바뀌어 초기화됐다. 각 Row에 `CostResource`/`CostAmount`를 다시 입력해야 코스트가 걸린다.
- PIE 실주행 검증 미실시 — 컴파일까지만 확인했다.
- 별건: `WxAbilityBase.cpp`의 `CooldownEffect` 인스턴스 생성·`StackLimitCount` 설정은 사실상 무효다. `ApplyGameplayEffectToOwner`가 `GameplayEffect->GetClass()`로 스펙을 다시 만들어 CDO를 쓰기 때문. 충전은 GE 1개당 1충전으로 동작 중이라 증상은 없다.
