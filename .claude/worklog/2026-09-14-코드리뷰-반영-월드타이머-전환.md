### 접근 방식
- **비용 통지는 필터 + 즉시 판정**
  - 가득 찬 대기 상태의 헛 판정은 동등값 필터가 이미 없앤다.
  - 남는 실제 변경은 회복·소모 GE 가 1/30초마다 서로 다른 프레임에 따로 보내므로 모을 것이 없다. 월드 타이머로 모아도 그 통지가 타이머 틱 안에서 와서 다음 프레임에 돌기 때문에 즉시 판정보다 늦다.
- **예약 게이트는 `IsTimerActive`**
  - 핸들 유효성이나 별도 bool 이 아니라 타이머 매니저에 직접 묻는다. 타이머가 발화 없이 사라져도 게이트가 굳지 않는다(쿨다운 티커 주석에 기록된 핸들 게이트 함정이 구조적으로 없다).
  - 실행 중 타이머도 활성으로 잡히므로, 플러시는 첫 줄에서 핸들을 놓아 판정 도중 요청이 삼켜지지 않게 한다.
- **월드 타이머 다음 틱의 실행 시점(UE 5.8)**
  - `GuaranteeEngineTickDelay` 가 0이라 `ExpireTime = InternalTime` 으로 들어가고, `InternalTime > ExpireTime` 에서 실행된다.
  - 월드 타이머 틱 전 이벤트(입력·네트 수신·애님 노티파이)는 같은 프레임, Slate 보다 먼저 반영된다. 타이머 콜백 안 이벤트는 다음 프레임에 반영되고, 같은 틱 재실행은 없다.
- **매 프레임 게이지 티커는 코어 티커로 유지**: 쿨다운·이펙트 남은 시간 게이지다. 월드 타이머에는 매 프레임 호출 수단이 없고, 값은 월드 시간을 직접 읽는다.
- **파사드 재사용**: `UWxUILibrary::GetPrimaryGameLayout` 은 삭제된 함수가 유일한 호출자였다. 같은 조회를 인라인한 `WxPlayerLayoutComponent` 두 곳을 파사드로 돌린다.
- **감수**
  - `ActionPhase`(후딜·콤보 창)에 따른 `CanActivate` 변화는 통지가 없어 반영되지 않는다. 권위 측에서 SP 가 가득 찬 동안 헛 통지가 우연히 메워 주던 것이다. 원격 클라는 원래도 이렇게 동작했고, 바인딩 에셋 0건이라 잠재 결함이다.
  - 메뉴 일시정지 중에는 월드 타이머가 돌지 않아 해제 후 반영된다.

### 구현·결정과 그 이유
- **비용 통지는 즉시 판정**
  - 헛 판정은 동등값 필터가 없앤다. 남는 실제 변경은 회복·소모 GE 가 프레임마다 따로 보내 모을 것이 없다.
  - 모아 봐야 통지마다 예약 등록·해제와 태그 전용 `RefreshBoundAbility` 스캔만 붙는다. 월드 타이머로 예약해도 그 통지가 타이머 틱 안에서 오므로 다음 프레임에 돈다.
  - 결과적으로 5번 수정은 HEAD 대비 필터 한 줄만 남았다.
- **게이트는 `IsTimerActive`, 별도 bool 은 두지 않음**
  - 예약 여부를 타이머 매니저에 직접 묻는다. 그래서 타이머가 발화 없이 사라져도 게이트가 굳지 않는다.
  - 사용자가 더티 플래그(bool) 방식을 물어 비교했다. bool 은 같은 사실을 두 곳에 두어 굳을 수 있고, 얻는 것은 버스트 중 월드 조회 생략뿐이라 택하지 않았다.
- **플러시 첫 줄 `Invalidate`**: 실행 중(`Executing`)인 타이머도 활성으로 잡힌다. 판정 도중 들어온 요청이 삼켜지지 않게 핸들부터 놓는다. 콜백 안에서 건 다음 틱 예약은 `InternalTime > ExpireTime` 조건 때문에 같은 틱에 다시 돌지 않는다.
- **해제는 ASC 가 살아 있을 때 `ClearTimer`**
  - ASC 가 먼저 사라져 못 지운 예약이 VM 파괴 뒤 오면, `FTimerUnifiedDelegate::Execute` 가 바인딩을 확인해 건너뛴다.
  - VM 이 살아 있으면 null ASC 로 판정해 전부 false 가 될 뿐이다.
- **AbilitySystem VM 도 함께 전환**: 같은 1회성 코어 티커 예약이라 Slate 뒤 실행 문제도 같다. 세 예약을 한 방식으로 맞췄다.
- **매 프레임 게이지 티커 두 곳은 코어 티커 유지**: 월드 타이머에는 매 프레임 호출 수단이 없고, 값은 월드 시간을 직접 읽어 실행 순서의 영향을 받지 않는다.
- **파사드 재사용**: 호출자가 0이 된 `GetPrimaryGameLayout` 을 `WxPlayerLayoutComponent` 의 인라인 조회 두 곳에 쓰니, 중복 조회와 `WxUIManagerSubsystem.h` 의존이 함께 빠졌다.
- **검증**
  - UE 5.8 `WxEditor Win64 Development` 빌드가 `Result: Succeeded` 로 끝났고, UBT 로그에 경고·에러가 없다.
  - 수정한 cpp 4개(`WxUILibrary`·`WxPlayerLayoutComponent`·`WxViewModel_Ability`·`WxViewModel_AbilitySystem`)가 adaptive 빌드로 단독 컴파일돼 include 제거가 확인됐다.
  - AbilitySystem VM 헤더를 포함하는 나머지 파일은 `Module.WxUI.cpp`·`Module.WxGame.cpp` 로 재컴파일됐다.
  - Grep 결과:
    - `FTSTicker` 는 쿨다운(`WxViewModel_Ability`)·이펙트(`WxViewModel_Effect`) 게이지 티커에만 남았다.
    - `SetTimerForNextTick`·`IsTimerActive`·`ClearTimer`·플러시 `Invalidate` 는 각 3곳이다.
    - `RefreshActivationState` 는 대상 교체·쿨다운 적용·비용 통지·쿨다운 티커·플러시에서 불린다.
