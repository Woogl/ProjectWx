# 아이콘에 머터리얼/머터리얼 인스턴스 허용

## 계획

### 목표
아이콘 파이프라인이 데이터 소스부터 VM 까지 `UTexture2D` 로 못박혀 있어 머터리얼 아이콘(애니메이션·마스크 등)을 쓸 수 없다. 바인딩 종착지인 `UImage::SetBrushResourceObject` 는 이미 `UObject*` 를 받으므로, 막고 있는 우리 쪽 타입 선언만 넓히고 에디터 피커를 두 클래스로 제한한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxItemDefinition.h` / `WxItemFragment.h` (ChargeIcons) | 소스 필드를 `TSoftObjectPtr<UObject>` + `AllowedClasses` 메타로 | 수정 |
| `WxAbilityTableRow.h` / `WxEffectComponent_UIData.h` / `WxCharacterUIData.h` | 동일 | 수정 |
| `WxItemInstance.h/.cpp`, `WxAbilityBase.h/.cpp` | `GetDisplayIcon`·`GetIcon` 반환 타입 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel.h` / `.cpp` | `FWxTextureRequest`→`FWxImageRequest`, `RequestTextureAsync`→`RequestImageAsync(FName, TSoftObjectPtr<UObject>)`, `ApplyLoadedTexture`→`ApplyLoadedImage(FName, UObject*)` 등 개칭·확장 | 수정 |
| VM 5종 (`Item`·`Ability`·`Effect`·`Selection`·`Character`) | 노출 필드를 `TObjectPtr<UObject>` 로, 오버라이드·시그니처 반영 | 수정 |
| `WxViewModelResolver_PlayerCharacter.cpp` | `IconSoft` 지역 변수 타입 | 수정 |
| `WxItemDefinitionThumbnailRenderer.cpp` / `WxAbilityThumbnailRenderer.cpp` | 로드 결과를 `UObject*` 로 받아 텍스처/머터리얼 분기 | 수정 |

### 접근 방식
- **소스는 `UObject` + `AllowedClasses`**: `meta = (AllowedClasses = "/Script/Engine.Texture2D,/Script/Engine.MaterialInterface")` 로 피커만 두 클래스로 제한한다. 타입은 넓히되 기획자 UX 는 좁게 유지.
- **기존 에셋 데이터 보존**: 오브젝트 계열 프로퍼티는 태그에 내부 클래스를 기록하지 않는다(`SaveTypeName` 오버라이드는 Byte/Array/Map/Set/Struct 뿐). 배열 `ChargeIcons` 도 인너 타입명이 `SoftObjectProperty` 라 동일하게 안전하다.
- **`Texture` → `Image` 개칭**: 이 자리는 이제 텍스처가 아니라 UMG 브러시 리소스다. 로직·구조는 그대로 두고 이름만 실체에 맞춘다.
- **썸네일도 머터리얼 대응**: 타입이 넓어지면 기존 `UTexture2D*` 대입이 컴파일되지 않아 어차피 손대야 한다. `Cast` 분기로 머터리얼은 `FCanvasTileItem(Pos, RenderProxy, Size)` 로 그린다.

### 구현·결정과 그 이유
- **타입은 넓게, 피커는 좁게**: 필드는 `UObject` 지만 `AllowedClasses` 로 에디터 피커를 Texture2D·MaterialInterface 두 클래스로 묶었다. 기획자 UX 는 그대로 좁게 유지된다.
- **`Texture` → `Image` 개칭**: 이 자리는 이제 텍스처가 아니라 UMG 브러시 리소스다. 종착지 `UImage::SetBrushResourceObject` 가 `UObject*` 를 받고 엔진 자신도 `RequestAsyncLoad(TSoftObjectPtr<UObject>)` 로 다루므로 이름을 실체에 맞췄다.
- **에셋 데이터 보존 근거**: 오브젝트 계열 프로퍼티는 태그에 내부 클래스를 기록하지 않는다(`SaveTypeName` 오버라이드는 Byte/Array/Map/Set/Struct 뿐). 배열 `ChargeIcons` 도 인너 타입명이 `SoftObjectProperty` 라 동일하다.
- **썸네일 머터리얼 대응**: 타입이 넓어지면 기존 `UTexture2D*` 대입이 컴파일되지 않아 어차피 손대야 했다. 머터리얼 아이콘이 콘텐츠 브라우저에서 빈 썸네일이 되지 않게 `FCanvasTileItem` 렌더 프록시 생성자로 그린다. 크기는 고유 해상도가 없어 어빌리티는 `Super`, 아이템은 128 정사각으로 폴백한다.
- **텍스처 전용으로 남긴 곳**: `WxWorldDeveloperSettings::SpawnerClassIcons` 는 에디터 빌보드 스프라이트라 `UTexture2D` 가 필수다.

### 계획 대비 달라진 점
- 계획대로. (1차 빌드에서 `VM_Effect::Icon` 필드 타입을 빠뜨려 UHT 가 게터/세터 불일치를 잡아냈고, 필드까지 `UObject` 로 맞춰 해결했다.)

### 후속 과제
- 앞 작업의 후속(에셋 마이그레이션 → `UWxLazyImage` 삭제)은 그대로 남아 있다.
- PIE·에디터 실물 확인 미완 — 빌드까지만 검증했다. 기존 아이콘 참조 보존, 머터리얼 인스턴스를 아이콘으로 지정했을 때의 표시·썸네일, 그리고 `WBP_Ability`·`WBP_Effect` 재컴파일 경고 여부를 봐야 한다.
