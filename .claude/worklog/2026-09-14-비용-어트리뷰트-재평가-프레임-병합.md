# 비용 어트리뷰트 통지도 더티로 모아 다음 틱에 한 번 판정

## 계획

### 목표
`UWxViewModel_Ability` 는 태그 통지만 더티로 모아 다음 틱에 발동 판정을 한다. 비용 어트리뷰트 통지는 올 때마다 곧바로 판정한다. 그런데 초당 30회 주기 GE(`UWxEffect_RegenSP`·`InfiniteMP`)가 자원이 가득 찬 상태에서도 매 주기 통지를 보내, SP·MP 비용 슬롯마다 대기 중에도 판정이 초당 30회 헛돈다(`/module-review` WxUI 5번 🟢). 값이 그대로인 통지는 버리고, 실제 변경은 태그와 같은 더티로 모은다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Public/MVVM/WxViewModel_Ability.h` | `MarkActivationDirty()` 선언, 클래스 주석의 병합 대상을 태그·비용 통지로 정정 | 수정 |
| `Plugins/WxUI/Source/WxUI/Private/MVVM/WxViewModel_Ability.cpp` | 태그 핸들러의 예약 블록을 `MarkActivationDirty` 로 옮기고, 두 통지 핸들러가 그것을 부르게 한다. 비용 통지는 동등값이면 반환한다 | 수정 |

### 접근 방식
- **더티 플래그는 기존 예약 핸들이 겸한다**: `ActivationRefreshHandle` 이 유효하면 곧 더티다. bool 을 따로 두지 않는다(08-27 태그 병합과 같은 결정).
- **몰려서 오는 통지만 더티로 모은다**
  - 태그·비용 통지는 더티로, 한 번뿐인 전이(쿨다운 적용·충전 수 변화·대상 교체)는 지금처럼 즉시 판정한다.
  - 전 경로 통일도 검토했지만 기존보다 낫지 않았다.
    - 줄어드는 판정이 스킬 1회당 약 1회뿐이다.
    - `FTSTicker::Tick` 이 틱 중 추가된 티커를 같은 틱에 실행하므로(`Ticker.cpp:93-139`), 플러시 안 Reset 순서 함정이 새로 생긴다.
    - 초기 바인딩·대상 교체 표시가 한 프레임 늦어진다.
- **동등값 통지는 버린다**
  - 엔진은 값이 그대로여도 통지한다(UE 5.8 `GameplayEffect.cpp:3945-3984`, `GameplayEffectAggregator.cpp:438-445`).
  - `UWxCombatAttributeSet` 이 Pre 훅에서 클램프하므로, 가득 찬 상태의 통지는 Old = New 가 비트 단위로 같다. 복제 경로도 현재값을 싣는다. 그래서 근사가 아닌 정확 비교를 쓴다.
  - 더티는 같은 프레임에 몰린 통지만 합치는데, 회복 통지는 프레임마다 따로 온다. 상시 판정을 없애는 것은 이 필터다.
- **최대치 구독은 유지한다**: `UWxAbility_Sprint` 의 시작 조건이 SP/MaxSP 비율이다.
- **필터가 버리는 통지에 기대던 판정은 없다**: BP `K2_CanActivateAbility` 오버라이드가 0건이고, C++ 오버라이드 입력은 태그·SP 값·입력 키 상태뿐이다.

### 구현·결정과 그 이유
- **더티는 몰려 오는 통지에만**
  - 사용자 방향("더티 → 다음 프레임 갱신")을 처음엔 모든 판정 경로에 넓혀 계획했다. 기존 대비로 비교해 보니 이득이 없어 좁혔다.
  - 한 번뿐인 전이까지 더티로 돌려도 스킬 1회당 판정은 3회에서 2회로만 준다. 활성화 태그로 예약된 플러시가 먼저 돌고, 쿨다운 티커의 충전 수 변화가 다시 예약하기 때문이다.
  - 반면 두 가지 비용이 생긴다. 틱 중 추가된 티커를 같은 틱에 실행하는 엔진 동작 때문에 플러시 안 Reset 순서 함정이 생기고, 초기 바인딩·대상 교체 표시가 한 프레임 늦어진다.
- **동등값 필터가 실제 해결책**: 더티는 같은 프레임에 몰린 통지만 합친다. 회복 GE 는 1/30초마다 서로 다른 프레임에 따로 통지하므로, 더티만으로는 가득 찬 대기 중에도 판정이 초당 30회 그대로다. 이 필터가 그 상시 판정을 없앤다.
- **정확 비교**: 헛 통지는 클램프된 저장값을 다시 읽은 값이라 비트가 같다. 근사 비교는 문턱 근처의 실제 미세 변화를 버릴 수 있다.
- **예약 블록을 함수로 뺌**: 두 핸들러가 같은 핸들을 공유하므로 검사와 등록이 한곳에만 있어야 어긋나지 않는다. 같은 클래스의 `StartCooldownTicker` 와 같은 모양이다.
- **검증**:
  - UE 5.8 `WxEditor Win64 Development` 빌드가 `Result: Succeeded` 로 끝났고, UBT 로그에 경고·에러가 없다.
  - `FlushActivationRefresh` 티커 등록은 `MarkActivationDirty` 한 곳뿐이다. 두 통지 핸들러는 즉시 판정을 부르지 않고, 즉시 판정은 쿨다운 적용·충전 수 변화·대상 교체·플러시에만 남았다.

### 후속 과제
- PIE 실측 미수행(unreal-mcp 미연결). 확인할 항목:
  - SP 가 가득 찬 대기 상태에서 플러시가 돌지 않는지.
  - SP·MP 소모·회복과 무한 MP 구간에서 슬롯 디밍이 한 프레임 이내로 따라오는지.
- 리뷰 문서 `module_review_WxUI.md` 는 다음 `/module-review` 실행 때 갱신된다.
- **정정(같은 날 코드 리뷰)**: 두 판단이 틀렸다. 후속 작업 `2026-09-14-코드리뷰-반영-월드타이머-전환.md` 에서 비용 통지를 필터 뒤 즉시 판정으로 되돌리고, 태그 예약은 월드 타이머로 옮겼다.
  - **"필터가 버리는 통지에 기대던 판정은 없다"**: `UWxAbilityBase::ActionPhase`(후딜·콤보 창)는 통지 없이 바뀌어 배타 그룹 점유를 풀어 준다. 권위 측에서 SP 가 가득 찬 동안에는 그 변화를 헛 통지가 우연히 메워 주고 있었다. `CanActivate` 바인딩 에셋이 0건이라 잠재 결함으로 남긴다.
  - **"비용 통지도 더티로 모은다"**: 회복·소모 스트림에서는 합쳐지는 것이 없다. 통지마다 티커 할당과 `RefreshBoundAbility` 헛 스캔이 붙고, 코어 티커가 Slate 페인트 뒤(`LaunchEngineLoop.cpp:5991` → `:6103`)에 돌아 표시가 한 프레임 늦었다.
