# 락온 서버 RPC를 「클라 선택 신뢰」 정책으로 정리

## 계획

### 목표

락온 서버 RPC가 클라가 고른 대상을 절반만 검증하고, 조건에 안 맞으면 조용히 무시해 클라의 로컬 예측만 남긴다. 락온은 클라 선택을 신뢰하는 정책이므로 거절 경로 자체를 없애고, 코드와 주석이 그 정책을 드러내게 한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/Targeting/WxLockOnComponent.cpp` | `ServerSetLockOnTarget_Implementation`을 무조건 반영으로 축약, 필요 없어진 `WxLockOnPointComponent.h` include 제거 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/Targeting/WxLockOnComponent.h` | RPC 주석을 신뢰 정책 서술로 교체, 클래스 주석에 유효성 유지 주체 한 줄 추가 | 수정 |

### 접근 방식

- **거절 경로를 없앤다**: 서버는 받은 값을 그대로 반영한다. 해제(`nullptr`)도 같은 경로라 조기 반환 분기가 사라진다. Reliable RPC라 순서가 보장되어 클라가 마지막으로 보낸 값이 곧 서버 값이 되고, 로컬 예측이 굳는 경우가 원천적으로 없어 정정 RPC 같은 되돌리기 장치가 필요 없다.
- **타입 검사도 남기지 않는다**: 정상 클라에서 절대 실패하지 않아 실효가 없고, 남겨 두면 "서버가 무언가는 검증한다"는 잘못된 인상을 준다. 계약은 주석으로 남긴다.
- **유효성 유지는 로컬 태스크 몫**: 락온 태스크가 컴포넌트 파괴·사망·거리 이탈을 매 틱 폴링해 재탐색/해제를 다시 서버로 올린다. 서버가 같은 조건을 한 번 더 보는 것은 중복이면서 판정 시점 차이로 오히려 어긋남을 만든다.
- **감수하는 것**: 변조된 소유 클라는 임의의 복제 컴포넌트를 서버 락온 대상으로 만들 수 있고 투사체 호밍·모션 워핑 스냅이 그 값을 읽는다. 정책상 수용하며, 스냅은 이미 쿼리 범위 밖이면 회전만 적용해 소비처에서 한 번 더 좁혀진다.

### 구현·결정과 그 이유

- **무조건 반영**: 서버가 요청을 무시할 수 있는 한, 클라의 로컬 값과 서버 값이 갈라지는 경로가 항상 남는다. 값이 안 바뀌면 RepNotify도 안 오므로 복제가 정정해 주지도 않는다. 거절을 없애는 쪽이 정정 RPC를 새로 만드는 쪽보다 정책과도 맞고 상태 수도 줄인다.
- **타입 검사까지 제거**: 정상 클라에서는 통과가 보장되는 검사라 실효가 없으면서, 남아 있으면 "서버가 대상을 검증한다"고 읽혀 다음 수정자가 여기에 조건을 덧붙이게 된다. 대상이 락온 지점 컴포넌트라는 계약은 헤더 주석에 적었다.
- **해제도 같은 경로**: 널 조기 반환은 결국 같은 함수를 부르는 분기였다. 무조건 반영으로 합치면서 자연히 사라졌다.
- **유효성 유지는 그대로 로컬 태스크에 둔다**: 사망·거리 이탈·컴포넌트 파괴는 락온 태스크가 매 틱 보고 해제·재탐색을 서버로 다시 올린다. 서버가 같은 조건을 한 번 더 보면 판정 시점이 달라 오히려 어긋난다.

### 계획 대비 달라진 점

계획대로.

### 후속 과제

- 변조된 소유 클라가 임의의 복제 컴포넌트를 서버 락온 대상으로 만들 수 있다. 정책상 수용한 트레이드오프이며, 치팅이 문제가 되는 시점에는 서버 재검증이 아니라 소비처(투사체 호밍) 쪽 범위 제한으로 좁히는 편이 예측과 충돌하지 않는다.
- 네트워크 실측(PIE 2클라)은 하지 않았다. 단일 플레이·리슨 호스트는 권위 분기로 RPC를 타지 않아 동작 변화가 없다.
