# 그로기-사망 몽타주 충돌 및 피니셔 재생속도 불일치 수정

## 계획

### 목표
그로기 도중 몬스터가 사망(특히 앞잡 처형 치명타)하면 사망 몽타주 종료 후 Groggy 폴러가 시체 위에 그로기 몽타주를 덮어씌우는 버그를 없애고, 앞잡 처형 시 공격자/피해자 몽타주 재생속도 불일치(ASPD≠1.0)로 프레임 싱크가 깨지는 문제를 바로잡는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Ability/WxAbility_Groggy.h` | `State.Dead` 태그 핸들러/델리게이트 핸들 선언 추가 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbility_Groggy.cpp` | `State.Dead` 태그 이벤트 구독 → 사망 시 `EndAbility` | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbility_Finisher.cpp` | 공격자 몽타주 재생속도 `GetMontagePlayRate()` → `1.f` | 수정 |

### 접근 방식
- **Fix 1 (`WxAbility_Groggy`)**: `ActivationBlockedTags(State.Dead)`는 신규 활성화만 막고 실행 중 인스턴스는 종료하지 못한다(loose 태그라 자동 캔슬 없음). 기존 `State.Groggy` 구독 패턴과 대칭으로 `State.Dead` NewOrRemoved 이벤트를 구독해, 사망 부여와 같은 동기 콜스택에서 `EndAbility`로 즉시 종료한다. 폴링 타이머·DrainDP·구독은 기존 `EndAbility`가 정리하므로 시체 위 재생이 원천 차단된다.
- **Fix 2 (`WxAbility_Finisher`)**: 공격자 몽타주 Rate를 `1.f` 고정으로 바꿔, 고정 `1.f`로 재생되는 피해자 짝 피격(`WxAbility_HitReact`)과 프레임 싱크를 보존한다(처형 연출은 ASPD 비의존).

### 구현·결정과 그 이유
- **`State.Dead` 태그 이벤트 구독으로 종료**: `ActivationBlockedTags(State.Dead)`는 활성화 시점만 검사하고 실행 중 인스턴스는 못 끝낸다(State.Dead가 loose 태그라 자동 캔슬도 없음). 실행 중 종료가 필요하므로 기존 `State.Groggy` 구독과 동일한 패턴으로 처리해 일관성을 유지했다.
- **사망과 같은 동기 콜스택에서 종료**: 사망 부여(`AddLooseGameplayTag(State.Dead)`) 즉시 `EndAbility`가 호출돼 폴링 타이머·DrainDP·구독이 정리되므로, 사망 몽타주 종료 후 폴러가 시체에 그로기 몽타주를 덮는 창(0.1초 폴 지연 포함)이 사라진다. 이 종료 경로는 기존 DP=0 → `HandleGroggyTagChanged → EndAbility` 가 GE 실행 콜스택에서 돌던 것과 동일 패턴이라 추가 위험 없음.
- **피니셔 Rate 고정 1.0**: 피해자 짝 피격(`WxAbility_HitReact`)이 고정 1.0이라 "같은 길이 프레임 싱크" 설계를 지키려면 공격자도 ASPD 비의존이어야 한다. 대미지 노티파이 타이밍도 함께 안정된다.
