# 퍼펙트 가드 GP 반사를 bCanParry 게이트에서 분리

## 계획

### 목표
`ProcessPerfectGuard`가 GP 반사와 패리 리액션을 `Damage.CanParry` 하나로 묶어 게이트해, `bCanParry = false` 공격은 퍼펙트 가드로 막아도 공격자 GP가 오르지 않는다. 근접 공격은 `bCanParry`와 무관하게 막아낸 대가로 GP가 오르게 하고, `bCanParry`는 패리 리액션(역경직) 여부만 가르게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Effect/WxEffectComponent_DamageResponse.cpp` | `ProcessPerfectGuard`에서 `Damage.CanParry` 검사를 블록 조건에서 빼내 `Event.Hit.Parry` 전송에만 남긴다 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/Damage/WxDamageTableRow.h` | `bCanParry` 주석 정정 | 수정 |
| `Source/WxEditor/Tests/WxDamageResponseTest.cpp` | `FWxReflectCase` non-parry 케이스 기대값 갱신 | 수정 |

### 접근 방식
- **게이트 분리**: `IncomingReflect` 산출은 `UWxExecCalc_Damage`에서 `bPerfectGuardApplied`(`Damage.CanGuard` + `Effect.PerfectGuard`)만으로 결정되고 `Damage.CanParry`를 보지 않는다. 즉 `bCanParry = false`여도 반사량은 정상값이라, 소비 쪽 게이트만 풀면 된다.
- **투사체 제외 유지**: 직전 작업의 `bReflectedProjectile` 조건은 그대로 둔다 — 되돌아간 투사체가 보복이므로 GP도 리액션도 없다.
- **가드 불가 공격**: `ProcessPerfectGuard` 자체가 `IncomingReflect` 실행 기록이 있을 때만 도므로 애초에 닿지 않는다.

### 구현·결정과 그 이유
- **반사 GP는 `SourceASC` 유무와 투사체 여부만 본다**: `Damage.CanParry`는 `Event.Hit.Parry` 전송을 감싸는 안쪽 조건으로 내려갔다. `bCanParry = false` 공격도 퍼펙트 가드로 막으면 공격자 GP가 오르고, 역경직만 빠진다.
- **non-parry 테스트 케이스의 반사량을 20에서 5로 낮췄다**: 40에서 20을 더하면 최대치 50에 닿아 그로기 이벤트가 하나 발생해, "패리 이벤트가 없다"는 확인이 이벤트 수 1 안에 묻힌다. 45로 끝나게 하면 GP 상승(반사 성립)과 이벤트 0(패리 없음)이 서로 다른 항목으로 갈린다.

### 계획 대비 달라진 점
- **테스트 수정이 한 케이스로 끝나지 않았다**: `ReflectSpec` 블록은 컨텍스트 시전자가 방어자 자신이라 반사 GP가 같은 ASC로 되돌아온다. 앞 검증에서 GP가 이미 최대치라, 게이트를 푼 뒤에는 0 반사만으로도 그로기가 다시 떠 `Zero reflect still emits one event`가 2로 실패했다. 실제 전투에는 없는 조합(시전자 = 방어자)이므로 블록 앞에서 GP를 비우는 것으로 정리했다.

### 후속 과제
- 인게임 확인 미수행: `bCanParry = false` 근접 공격을 퍼펙트 가드로 막았을 때 공격자 GP만 오르고 역경직은 없는지 확인 필요.
