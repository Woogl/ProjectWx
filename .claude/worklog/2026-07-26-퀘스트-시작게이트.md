# ST_Quest 구조 개선 — Start=시작 조건 게이트, InProgress=실동작

## 계획

### 목표
Start 상태가 저널 등록 후 즉시 InProgress 로 넘어가 퀘스트가 레벨 시작과 동시에 수주되는 현 구조를, Start=시작 조건 게이트 / InProgress=실동작으로 재구성한다. 시작 조건은 사용자 결정으로 **전 퀘스트 이벤트형 통일**: Start 는 엔진 순정 Delay Task(Run Forever)로 대기하다 `On Event(Quest.Start) → InProgress`. 수주 전에는 HUD 저널이 없고, 저널 등록은 Step1 의 SetQuestObjective(제목+목표)가 수주 순간 수행한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../WxGameplayTags.h/.cpp` | `Quest_Start` 네이티브 태그 추가(Quest.Fail 형제) | 수정 |
| `/Game/Quest/ST_Quest` | Start: SetQuestObjective 제거 → Delay Task(bRunForever), 전이 OnStateCompleted→InProgress 를 OnEvent(Quest.Start)→InProgress 로 교체 | 수정(MCP) |

### 접근 방식
- **게이트에 머무는 태스크 필수**: 활성 태스크가 0개면 상태가 즉시 자동 완료된다(StateTreeExecutionContext 확인). 엔진 순정 `FStateTreeDelayTask(bRunForever)` 재사용으로 신규 태스크 클래스 없이 해결.
- **이벤트형 통일 근거**: 이벤트형은 자체 판정형을 포괄(도달 = 트리거 볼륨 발화). 역방향은 원인별 Wait 태스크 증식 = 이벤트 수신의 재발명. 발화는 기존 `UWxQuestLibrary::SendQuestEvent`(Quest.Fail 과 동일 경로). 활성 1개 구조라 태그는 `Quest.Start` 단일로 충분.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../WxGameplayTags.h/.cpp` | `Quest_Start` 네이티브 태그 추가(Quest.Fail 형제, 수신·송출 경로 주석) | 수정 |
| `/Game/Quest/ST_Quest` | Start: SetQuestObjective 제거 → 엔진 Delay Task(bRunForever=true), 전이 OnStateCompleted→InProgress 를 OnEvent(Quest.Start)→InProgress 로 교체(링크 대상 보존), 컴파일·저장 | 수정(MCP) |

### 구현·결정과 그 이유
- **엔진 순정 Delay Task(bRunForever) 재사용**: 활성 태스크 0개면 상태가 즉시 자동 완료되므로(엔진 확인) 게이트에 머무는 태스크가 필수 — 신규 태스크 클래스 없이 순정으로 해결.
- **이벤트형 전 퀘스트 통일(사용자 결정)**: 이벤트형은 자체 판정형을 포괄(도달 = 트리거 볼륨 발화), 역방향은 원인별 Wait 태스크 증식 = 이벤트 수신의 재발명. 발화는 기존 `UWxQuestLibrary::SendQuestEvent`(Quest.Fail 동일 경로). 활성 1개 구조라 `Quest.Start` 단일 태그로 충분.
- **저널 등록의 자연 이동**: Start 의 저널 태스크가 사라져도 Step1 의 SetQuestObjective(제목+목표)가 수주 순간 등록한다 — "둘 다 채움" 규약과 정확히 맞물려 태스크 코드 변경이 없다.
- **전이 부분 갱신**: trigger·requiredEvent 만 부분 갱신해 기존 InProgress 링크·GUID 를 보존했다.

### 계획 대비 달라진 점
- PIE 시각 확인(저널 미표시)은 사용자가 화면을 사용 중이라 보류 — 결정적 요소(ST 컴파일 통과, Start 에 Delay(Run Forever) 단독 + 유일 출구 OnEvent(Quest.Start), InitialQuest=ST_Quest 구동 확인)는 전부 검증했다. 병행 세션(스포너 라벨) 완료 상태를 git·에디터 상태로 확인 후 빌드·재실행했다.

### 후속 과제
- 플레이 확인: 시작 직후 저널 없음 → Quest.Start 발화(첫 발화자: 트리거 볼륨·대화 통합 시) 시 수주·저널 등록. 즉석 검증용으로 레벨 BP 에 `ce` 콘솔 호출용 디버그 커스텀 이벤트를 달 수 있음(선택).
- Start 상태 이름은 의미상 "대기(수주 전)"에 가까워졌다 — 이름 정리는 선택.
