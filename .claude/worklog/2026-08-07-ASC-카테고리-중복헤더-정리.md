# ASC AbilitySet 카테고리 정리 (디테일 패널 중복 헤더 제거)

## 계획

### 목표

BP_Enemy → Class Defaults 디테일 패널에서 `GAS` 하위 카테고리와 그 안의 `Ability Set` 행이 두 번 그려진다. 액터와 컴포넌트가 같은 하위 카테고리 경로를 공유해 생기는 표시 중복이므로, 컴포넌트 쪽 카테고리를 최상위 `Wx`로 옮겨 한 번만 뜨게 한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/WxAbilitySystemComponent.h` | `AbilitySet`의 카테고리를 `"Wx\|GAS"` → `"Wx"`로 변경, 이유 주석 한 줄 추가 | 수정 |

### 접근 방식

- **원인**: Class Defaults 패널은 액터 CDO와 컴포넌트 템플릿의 프로퍼티를 한 레이아웃에 합친다. 최상위 카테고리는 인스턴스별 그룹으로 병합되지만(그래서 `NameplateComponent`·`LockOnPoint` 그룹이 생긴다) 하위 카테고리는 인스턴스 구분 없이 부모에 그대로 붙어, 기여한 객체 수만큼 헤더가 생기고 각 헤더가 이름으로 공유되는 같은 내용을 그린다. `Wx|GAS`에는 캐릭터 베이스(컴포넌트 포인터 둘)와 ASC(AbilitySet)가 함께 기여한다. 우리 에디터 개조(`FWxCategoryDetailCustomization`)는 프로퍼티 맵 순회가 끝난 뒤 정렬만 하므로 원인이 아니다.
- **선택**: 캐릭터 쪽 `Wx|GAS`는 두 멤버를 묶는 이름으로 적절하니 그대로 두고, 편집 프로퍼티가 하나뿐인 ASC를 최상위 `Wx`로 옮긴다. 같은 패널의 다른 Wx 컴포넌트들과 표시 방식이 같아진다.
- 프로젝트 전체에서 액터와 컴포넌트가 하위 카테고리 경로를 공유하는 곳은 여기가 유일하다.
- 카테고리는 에디터 표시 메타데이터라 런타임 동작·에셋 데이터에 영향이 없다.

## 완료

### 수정한 파일

| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/WxAbilitySystemComponent.h` | `AbilitySet` 카테고리를 최상위 `Wx`로 옮기고, 경로를 다시 합치면 안 되는 이유를 주석으로 남김 | 수정 |

### 구현·결정과 그 이유

- **컴포넌트 쪽을 옮긴 이유**: 캐릭터 베이스의 `Wx|GAS`는 어빌리티 시스템 컴포넌트와 어트리뷰트 세트를 묶는 이름으로 그대로 쓸 값어치가 있는 반면, 컴포넌트에는 편집 프로퍼티가 하나뿐이라 전용 하위 카테고리를 유지할 이유가 없다. 옮기고 나면 에디터가 컴포넌트 이름으로 그룹을 만들어 주므로, 같은 패널에 이미 보이던 다른 Wx 컴포넌트들과 표시 방식이 같아진다.
- **주석을 남긴 이유**: 하위 카테고리 이름만 보면 다시 `Wx|GAS`로 되돌리는 편이 자연스러워 보인다. 중복이 재발하는 조건이 "액터와 컴포넌트가 같은 경로를 공유할 때"라는 점은 코드만 봐서는 드러나지 않는다.

### 계획 대비 달라진 점

계획대로.

### 후속 과제

- 에디터 재실행 후 육안 확인 미완. UPROPERTY 메타데이터는 Live Coding으로 반영되지 않아 실행 중이던 에디터에는 아직 그대로다. 재실행 뒤 BP_Enemy → Class Defaults에서 `Ability Set`이 한 번만 뜨는지 보면 된다.
