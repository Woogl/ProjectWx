# 어트리뷰트 상한 클램프를 Base 훅으로 이관

## 계획

### 목표
자원 어트리뷰트의 상한 클램프가 Current 쪽과 GE 실행 직후 두 군데로 갈려 있어 Base 값 전체를 덮지 못한다. 모든 Base 쓰기가 지나는 훅으로 상한을 옮겨 한 자리에서 걸리게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/Public/AbilitySystem/Attribute/WxCombatAttributeSet.h` | private 구역에 클램프 규칙 함수 선언 추가 | 수정 |
| `WxCombat/Private/AbilitySystem/Attribute/WxCombatAttributeSet.cpp` | 클램프 규칙 함수 신설, 두 Pre 훅을 그 호출로 축약, 실행 훅의 클램프 제거 | 수정 |

### 접근 방식
- **클램프 규칙 한 벌을 두 Pre 훅이 공유**: 하한 0과 "짝 최대치가 유효하면 상한" 규칙을 private const 함수 한 곳에 담고, Current 훅과 Base 훅이 각각 그것을 부른다. 지금 Current 훅에만 있는 5중 분기가 그리로 옮겨가며, 같은 분기를 Base 훅에 복제하지 않아도 된다.
- **왜 Base 훅이어야 하나**: Base 쓰기는 집계자 유무와 무관하게 이 훅을 무조건 지난다. 지금처럼 실행 훅에서 클램프하면 GE 경로만 덮여서, 코드가 직접 부르는 Base 쓰기(최대치 변동 시 비례 재조정)가 상한을 안 지난다.
- **실행 훅에서는 클램프만 걷어낸다**: 클램프가 전부이던 분기는 통째로 사라지고, 소진 적용이 딸린 분기는 클램프 줄만 뺀다. 메타 어트리뷰트 소비 분기는 손대지 않는다.
- **부수 효과**: GE 실행마다 나가던 클램프 전용 Base 재기록이 사라진다. 그 재기록은 매번 쓰기 파이프라인을 한 바퀴 더 돌리고 있었다.

### 구현·결정과 그 이유
- **상한을 Base 훅으로**: Base 쓰기는 집계자 유무와 무관하게 이 훅을 무조건 지나므로, 여기 걸어야 GE 경로와 코드가 직접 부르는 쓰기가 같은 규칙 아래 놓인다. 종전에는 실행 훅에만 상한이 있어 최대치 변동 시 비례 재조정이 상한을 안 지나고 있었다.
- **규칙을 함수 하나로**: 같은 다섯 갈래 분기를 두 Pre 훅에 복제하지 않으려고 한 곳에 모았다. Current 훅에 있던 분기를 옮겨 담은 것이라 판정은 그대로고, 두 훅이 각각 한 줄로 줄었다.
- **최대치 0이면 상한을 건너뛴다**: 기존 Current 훅이 쓰던 가드를 그대로 가져왔다. 초기화 도중 짝이 아직 안 채워졌을 때 자원이 0으로 눌리는 것을 막는다. 초기화는 최대치를 짝의 현재값보다 먼저 넣으므로 실제 순서상으로도 안전하다.
- **실행 훅에서는 클램프만 제거**: 클램프가 전부이던 네 분기는 통째로 사라졌고, SP 분기는 소진 적용이 남아 분기 자체는 유지했다. 이로써 GE 실행마다 나가던 클램프 전용 Base 재기록이 없어졌다 — 그 재기록은 매번 쓰기 파이프라인을 한 바퀴 더 돌리고 DP는 그로기 판정을 한 번 더 하고 있었다.

### 후속 과제
- 인게임 회귀 미검증(빌드까지만). PIE에서 ① 최대치를 넘기는 회복이 최대치에서 멈추는지 ② DP 상한과 그로기 진입이 한 번만 일어나는지 ③ SP 0에서 소진이 그대로 걸리는지 ④ 재부여 시 HP·MaxHP가 테이블 값대로 복구되는지 확인이 남았다.
- 대미지 차감의 하한 방어(`FMath::Max(..., 0.f)`)는 이제 Base 훅과 겹치지만 호출부 의도 표시로 남겨 뒀다.
- **하한이 어트리뷰트마다 달라질 여지가 있다**(사용자 지적). 지금은 0 하나로 모든 어트리뷰트에 무조건 걸고 있고, 상한만 짝을 찾아 고른다. 하한이 다양해지면 상한과 같은 모양으로 짝을 찾아 고르게 바꾸고, 무조건 적용을 걷어내야 한다. 규칙이 이미 함수 하나에 모여 있어 그 함수 안에서 끝난다.
