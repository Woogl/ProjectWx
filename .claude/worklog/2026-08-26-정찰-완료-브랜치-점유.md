# 정찰을 마친 브랜치를 점유 상태로 유지

## 계획

### 목표
`UWxBTTask_Patrol` 은 Once 경로를 마치면 이동도 지연도 없이 동기 `Succeeded` 를 반환한다. 즉시 끝난 태스크는 곧바로 실행 갱신을 부르므로 정찰을 마친 폰이 살아 있는 내내 루트 되감김을 되풀이한다. 완료 상태에서 `InProgress` 를 반환해 브랜치를 실제로 점유하게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxBTTask_Patrol.cpp` | 완료 분기의 반환값을 `Succeeded` → `InProgress` 로 바꾸고, 주석을 "Failed 도 Succeeded 도 아닌 이유" 로 고쳐 쓴다 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxBTTask_Patrol.h` | 완료 플래그 주석을 점유 의미에 맞게 정정 | 수정 |

### 접근 방식
- **완료 = 브랜치 점유**: 세 결과 중 이 상태를 가리키는 것은 `InProgress` 뿐이다. `Failed` 는 하위 폴백이 폰을 집·배회로 끌고 가고, `Succeeded` 는 브랜치를 놓아 주어 상위가 다시 탐색하게 만든다. 점유는 "그 자리에 머문다" 를 노드가 스스로 표현하는 유일한 형태다.
- **리뷰가 말한 "매 틱" 은 과장**: 실제 트리에서 이 노드는 `[Patrol, Wait(5초)]` 시퀀스 안에 있어 완료 후 주기는 5초다. 프레임 단위 부하는 없지만, 노드의 유휴 비용을 형제 Wait 이 정해 준다는 점 자체가 문제다. 형제가 빠지거나 대기 시간이 0이 되는 순간 곧바로 틱 단위 재탐색이 된다.
- **빠져나오는 길은 그대로**: 상위 우선순위 데코레이터의 관찰자 abort 는 점유 중에도 산다. 타겟이 잡히면 전투 분기 조건(Both)이, 리시를 벗어나면 복귀 분기 조건(LowerPriority)이 점유를 끊는다.
- **MoveTo 를 건너뛴 채 머물러도 안전(엔진 5.8 대조)**: 중단 시 부모 `AbortTask` 는 이동 요청 ID 가 유효할 때만 실제 중단을 거는데 그 필드는 5.8 에서 무효값만 들어가는 죽은 필드이고, 이동 게임플레이 태스크 포인터도 직전 이동의 종료 콜백에서 이미 비워져 있다. 결국 아무 것도 하지 않고 동기 `Aborted` 를 돌려준다. 블랙보드 관찰자도 등록한 적이 없어 해제가 no-op 이다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxBTTask_Patrol.cpp` | 완료 분기가 `InProgress` 를 반환하도록 바꾸고, 그 자리와 완료 표시 지점의 주석을 점유 의미로 정정 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxBTTask_Patrol.h` | 클래스 주석에 "완료 후에는 뒤따르는 형제 노드가 실행되지 않는다" 는 계약을 추가 | 수정 |

### 구현·결정과 그 이유
- **완료 상태는 브랜치 점유로 표현**: 이 노드가 말하려던 것은 "정찰 분기를 계속 차지한 채 그 자리에 있다" 이고, BT 세 결과 중 그 뜻을 가진 것은 `InProgress` 뿐이다. `Failed` 는 폴백이 폰을 끌고 가서 안 되고, 즉시 `Succeeded` 는 브랜치를 놓아 주어 상위가 되감기게 만든다. 결과 하나를 바꾸는 것으로 끝났고 플래그·타이머 같은 상태는 늘리지 않았다.
- **리뷰의 "매 BT 틱" 은 실제와 달라 정정했다**: 실제 트리에서 Patrol 은 뒤에 5초 Wait 이 붙은 시퀀스 안에 있어, 완료 후 재탐색 주기는 틱이 아니라 5초였다. 그래도 고친 이유는 부하가 아니라 계약이다 — 노드의 유휴 비용을 형제 노드가 정해 주고 있었고, 형제가 빠지거나 대기 시간이 0이 되면 그 순간 틱 단위 재탐색이 된다.
- **MoveTo 를 건너뛴 채 머물러도 안전한지 엔진 5.8 소스로 대조**: 중단 시 부모의 중단 처리는 이동 요청 ID 가 유효할 때만 실제 이동을 끊는데, 그 필드는 5.8 에서 무효값 대입 외에 쓰는 곳이 없는 죽은 필드다. 이동 게임플레이 태스크 포인터도 직전 이동의 종료 콜백에서 이미 비워져 있어, 결국 아무 것도 하지 않고 동기 `Aborted` 를 돌려준다. 블랙보드 관찰자는 애초에 등록하지 않았으므로 해제도 no-op 이다.
- **빠져나오는 길이 살아 있는지 에셋으로 확인**: 정찰을 쓰는 트리는 하나뿐이고, 거기서 전투 분기 조건은 `Both`, 복귀 분기 조건은 `LowerPriority` 다. 둘 다 관찰자로 등록돼 점유 중인 하위 우선순위 정찰을 끊으므로, 타겟이 잡히거나 리시를 벗어나면 그대로 전환된다.
- **형제 Wait 이 죽는 점은 헤더에 명시**: 완료 후 시퀀스가 더 진행되지 않는다는 것은 BT 를 짜는 쪽에서 코드를 열지 않으면 알 수 없어, 클래스 주석에 계약으로 남겼다.

### 계획 대비 달라진 점
- 완료 플래그 멤버 주석은 그대로 뒀다. 문장이 여전히 맞고, 점유 계약은 클래스 주석 한 곳에 두는 편이 낫다고 봤다.

### 후속 과제
- 인게임 확인 미수행 — `MoveMode = Once` 인 정찰 경로를 끝까지 돈 적이 마지막 지점에서 멈춘 뒤, BT 디버거에서 정찰 노드가 활성으로 남는지와 플레이어 발견 시 전투로 정상 전환되는지 확인 필요.
