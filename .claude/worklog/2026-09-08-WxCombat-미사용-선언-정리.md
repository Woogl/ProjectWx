# WxCombat 미사용 선언 정리

## 계획

### 목표

모듈 리뷰가 지목한 "호출자 없는 선언 3건"이 타당한지 직접 확인하고 정리한다. 셋 다 저장소 전체에 호출자가 없고 `UFUNCTION` 이 아니라 BP 에서도 닿지 않으며, `Content/` 바이너리 조회에서도 참조가 0건임을 확인했다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Ability/WxAbilityBase.h` | `GetActiveMontage()` 선언과 `ActiveMontage` 멤버 제거 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbilityBase.cpp` | `GetActiveMontage()` 정의와 `ActiveMontage` 대입 2곳 제거 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/Targeting/WxLockOnPointComponent.h` | `FWxOnLockedOnChanged` 델리게이트 선언, `IsLockedOn()`, `IsActorLockedOn()`, `OnLockedOnChanged` 멤버 제거 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/Targeting/WxLockOnPointComponent.cpp` | `IsLockedOn()`·`IsActorLockedOn()` 정의와 `SetLockedOn` 의 브로드캐스트 제거 | 수정 |

### 접근 방식

- **연쇄까지 걷는다**: `IsActorLockedOn()` 이 `IsLockedOn()` 의 유일한 호출자였으므로 게터도 함께 제거한다.

- **`SetLockedOn`/`bLockedOn` 은 남긴다**: 리뷰가 "소비처가 있는지 확인 후 판단하라"고 열어 둔 항목인데, 확인 결과 `bLockedOn` 은 `UPROPERTY(VisibleInstanceOnly)` 라 실행 중 인스턴스의 디테일 패널에 노출되고 `SetLockedOn` 은 `WxAbilityTask_LockOnCamera` 가 실제로 호출한다. 호출자 없는 선언이 아니므로 정리 대상에서 뺀다.

- **`SetLockedOn` 은 단순 대입으로 줄인다**: 조기 반환 가드는 중복 브로드캐스트를 막으려 있던 것이라 델리게이트가 사라지면 존재 이유가 없다.

- **`ActiveMontage` 는 게터와 함께 완전히 걷는다**: 쓰기만 남은 `UPROPERTY(Transient)` 는 GC 참조만 붙든다. `EndAbility` 의 `MontageTask = nullptr;` 은 몽타주 수명 관리의 본체라 유지한다.

### 구현·결정과 그 이유

- **리뷰 지적 3건은 모두 사실이었다**: 저장소 전체에 호출자가 없고 `UFUNCTION` 이 아니라 BP 에서도 닿지 않으며 `Content/` 바이너리 조회에서도 참조가 0건이다. `WxCharacterMovementComponent` 가 쓰는 `GetCurrentActiveMontage()` 는 엔진 API 라 무관하다.

- **`SetLockedOn`/`bLockedOn` 은 정리 대상이 아니었다**: 리뷰가 열어 둔 "소비처 확인" 질문의 답이 "있다" 였다. `bLockedOn` 은 `VisibleInstanceOnly` 라 실행 중 인스턴스의 디테일 패널에 노출되고, `SetLockedOn` 은 락온 카메라 태스크가 실제로 호출한다. 지점별 락온 표시라는 설계 의도도 그대로 살아 있다.

- **`SetLockedOn` 의 조기 반환 가드는 걷었다**: 중복 브로드캐스트를 막으려 있던 것이라 델리게이트가 사라진 뒤에는 남길 이유가 없다.
