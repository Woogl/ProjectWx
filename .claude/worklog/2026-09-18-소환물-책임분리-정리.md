# 소환물 책임 분리 정리 — 상한 범위·사망 감지·주인 판정

## 계획

### 목표
`UWxMinionComponent`(정책 선언)와 `UWxMinionSubsystem`(로스터 운영)의 경계를 넘은 세 항목을 제자리로 돌린다. 상한이 종류를 가리지 않아 다른 종류를 파괴하던 문제가 이 정리로 함께 닫힌다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/Public/Minion/WxMinionComponent.h`·`.cpp` | `GetMaster` static 이관, 자기 ASC 사망 구독·핸들 보관·해제 | 수정 |
| `WxCombat/Public/Minion/WxMinionSubsystem.h`·`.cpp` | `GetMaster`·사망 핸들러 제거, `CollectMinions`에 태그 필터, 상한 집계를 종류 단위로 | 수정 |
| `Source/WxGame/Controller/WxAIController.cpp` | include·호출을 컴포넌트로 교체 | 수정 |
| `WxCombat/Private/AnimNotify/WxAnimNotifyState_Rush.cpp` | `GetMaster` 호출을 컴포넌트로, include 추가 | 수정 |

### 접근 방식
- **집계 범위를 `MasterStateTag`로 좁힌다**: `CollectMinions(Master, StateTag)`에서 태그가 유효하면 그 태그를 선언한 소환물만 담는다. 상한 정리는 소환하려는 종류의 태그를 넘겨 같은 종류 안에서만 자리를 비우고, 주인 소멸 정리와 `FindActiveMinion`은 빈 태그로 부른다. 종류 간 배타는 이미 `MasterTagRequirements.IgnoreTags`가 담당하므로 **상한 = 같은 종류 안 / 배타 = 태그 조건**으로 두 축이 갈라진다. `RefreshMasterStateTag`의 루프는 `CollectMinions(...).IsEmpty()` 한 줄로 접힌다.
- **사망은 컴포넌트가 듣는다**: 컴포넌트가 `BeginPlay`에서 자기 ASC의 `Ability.Death`를 구독하고 발동 시 `UnregisterMinion(*this)`를 부른다. self 가 주체라 페이로드가 사라지고, `FDelegateHandle` 하나만 지우면 되어 `RemoveAll` 도 사라진다.
- **`GetMaster`는 컴포넌트의 static으로**: 로스터 상태를 읽지 않는 순수 함수라 로스터 서비스에 있을 이유가 없다. 호출부 3곳이 로스터를 쓰지 않으면서 서브시스템 헤더를 include 하던 것도 정리된다.

### 구현·결정과 그 이유
- **상한을 `MasterStateTag` 단위로**: `CollectMinions`에 태그 인자를 더해, 상한 정리만 소환하려는 종류의 태그를 넘긴다. 주인 소멸 정리와 `FindActiveMinion`은 종류를 가려선 안 되므로 빈 태그로 부른다. 선언 주체(소환물)와 적용 범위(같은 종류)가 일치하게 되면서, 종류 간 배타는 `MasterTagRequirements.IgnoreTags`가 맡는 구도로 두 축이 갈라졌다. 태그를 비워 둔 소환물은 종전처럼 주인의 전체 소환물과 한 상한을 나눠 쓰며, 그 폴백을 프로퍼티 주석에 남겼다.
- **집계 필터가 루프 하나를 없앴다**: `RefreshMasterStateTag`가 "같은 태그를 든 소환물이 있는가"를 묻는 것이라, 태그 필터가 생기자 `CollectMinions(Master, StateTag).IsEmpty()` 한 줄이 됐다.
- **사망을 컴포넌트가 듣게 한 근거**: 서브시스템이 구독할 때는 태그 이벤트가 주체를 알려주지 않아 컴포넌트를 페이로드로 실어 보내야 했고, 해제도 그 ASC에 건 서브시스템 구독을 싹 지우는 `RemoveAll(this)`였다. 컴포넌트로 옮기니 self 가 주체라 페이로드가 사라지고 `FDelegateHandle` 하나만 지우면 된다. 사망 후 `EndPlay`가 `UnregisterMinion`을 다시 불러도 `Minions.Remove(...) == 0` 조기 반환이 받아 주므로 이중 해제도 안전하다.
- **`GetMaster`는 로스터와 무관해 컴포넌트로**: `Instigator` 비교만 하는 순수 함수인데 서브시스템에 있어, 로스터를 쓰지 않는 호출부 3곳까지 서브시스템 헤더를 include하게 만들고 있었다. 컴포넌트 보유와 무관하게 답해야 하므로 static 은 유지했다.

### 계획 대비 달라진 점
- 계획대로. 부수로 `WxMinionSubsystem.cpp`의 `WxGameplayTags.h` include 가 사망 구독 이관으로 미사용이 되어 함께 지웠다.

### 후속 과제
- 상한 분리의 실제 효과는 `BP_Doppelganger`의 `MasterStateTag`를 `State.MinionMaster.Doppelganger`로 저작해야 드러난다. 저작 전에는 두 종류가 같은 태그를 들고 있어 종전처럼 한 상한을 나눠 쓴다.
- `FindActiveMinion`은 여전히 종류를 가리지 않는다. Rush 노티파이가 원하는 종류를 지정하려면 노티파이 저작 필드가 필요해 별도 건으로 남긴다.
- 팀 상속·주인 소멸 시 파괴를 컴포넌트가 선언하게 하는 것은 물려받는 항목이 팀 하나뿐이라 미뤘다.
