# 처형 대미지 통일 — 뒤잡도 앞잡 대미지를 쓴다

## 계획

### 목표
`UWxAbility_Finisher`가 앞잡은 노티파이의 계수 대미지로, 뒤잡은 `BackstabEffectClass`(`UWxEffect_Kill`)로 즉사시켜 대미지만 갈라져 있다. 이 분기를 없애고 양쪽 다 앞잡 대미지로 통일한다.

에셋 조사 결과 **에셋 수정이 필요 없다**: `AM_BackstabFinisher`의 `WxFinisherDamage` 노티파이가 이미 앞잡과 같은 `DT_Damage` / `AM_Finisher` 행(CoeffATK 3.0)을 가리키고 있고, 코드 분기 때문에 무시되고 있을 뿐이다. `GA_Finisher`는 `BackstabEffectClass`를 오버라이드하지 않아 C++ 기본값을 쓴다.

> ⚠ `Docs/CombatDesign/뒤잡_시스템.md` §4·§8은 "일반 적 = 즉사"를 규정한다. 이번 통일은 그와 어긋나며, 기획서는 직접 수정하지 않는다(등급 분기는 애초에 코드에 구현된 적 없음 — 현재는 등급 무관 무조건 즉사).

### 접근 방식
- **어빌리티가 대미지 종류를 판단하지 않게 한다**: 분기를 걷어내면 "타이밍도 수치도 노티파이가 정한다"로 책임이 한 곳에 모이고, 헤더에 적힌 "무엇을 적용할지는 어빌리티가 현재 재생 몽타주로 정한다"는 예외 규칙 자체가 사라진다. 딸려 죽는 `BackstabEffectClass`·`ApplyFinisherEffect()`도 함께 정리한다.
- **`UWxEffect_Kill` 클래스는 남긴다**: 치트(`UWxCheatManager::WxKillPlayer`)가 쓴다.
- **DP 리셋 분기는 유지**: 앞잡만 종료 시 그로기를 푸는데, 뒤잡은 애초에 그로기를 전제하지 않아 리셋할 DP가 없다. 대미지와 무관한 축이다.
- **뒤잡 대상이 생존할 수 있게 된다**: 짝 피격 몽타주가 `AM_HitReact_Finisher`(Executed_Death + Getup2_Idle2)라 죽지 않으면 자연스럽게 일어나고, `State.Finisher`는 `EndAbility`에서 해제되므로 어포던스도 정상 복구된다. 별도 배선 없이 주석만 사실에 맞춘다.

### 구현·결정과 그 이유
- **분기를 지우는 것으로 충분했다**: 뒤잡 몽타주 노티파이가 이미 앞잡과 같은 `DT_Damage`/`AM_Finisher` 행을 가리키고 있어, 코드에서 즉사 분기만 걷어내면 에셋 수정 없이 통일된다. 통일 후 뒤잡의 대미지 거동은 `HitReactTag`·`bUnblockable` 등 행의 모든 필드까지 앞잡과 동일해진다.
- **`BackstabEffectClass`를 남기지 않고 제거**: 분기가 사라지면 아무도 읽지 않는 BP 노출 프로퍼티가 된다. 남겨두면 "여기 값을 넣으면 뒤잡이 달라진다"는 잘못된 신호를 준다.
- **DP 리셋 분기는 유지**: 대미지와 별개 축이다. 앞잡은 그로기 해제가 필요하고 뒤잡은 애초에 그로기를 전제하지 않는다.
- **`UWxEffect_Kill` 클래스는 존치**: 치트(`WxKillPlayer`)가 유일 사용처가 되었고, 헤더 주석에 그 사실을 적어 다음 사람이 죽은 코드로 오인하지 않게 했다.

### 계획 대비 달라진 점
- `WxEffect_Kill.h` 주석 갱신이 계획에 없었으나 추가했다. 사용처를 "뒤잡 처형"으로 명시하고 있어 그대로 두면 사실과 어긋난다.

### 후속 과제
- **PIE 실동작 미검증** — 컴파일까지만 확인했다. 뒤잡 시 즉사 대신 ATK×3.0 대미지가 들어가는지(대미지 플로터 표시로 구분됨), 생존 시 짝 피격 후 정상 복귀하는지, 앞잡 회귀는 없는지 확인 필요.
- **기획서 불일치** — `Docs/CombatDesign/뒤잡_시스템.md` §4(일반=즉사/엘리트=배율)·§8(모션 종료 시 사망)이 구현과 어긋난 채 남는다. 기획서는 직접 수정하지 않으므로 별도 판단 필요.
