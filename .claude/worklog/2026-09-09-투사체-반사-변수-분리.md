# 투사체 반사 판정을 투사체 소유로 이관

## 계획

### 목표
투사체가 퍼펙트 가드로 되돌아가는 조건을 대미지 행의 `bCanParry`에서 떼어내 투사체의 새 변수 `bCanReflect`로 옮긴다. 그 결합 때문에 `UWxEffectComponent_DamageResponse`가 EffectCauser를 `AWxProjectileBase`로 캐스트하고 있는데, 반사 여부를 아는 쪽이 투사체 하나가 되면 이 참조도 사라진다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../Public/Weapon/WxProjectileBase.h` | `bCanReflect` (EditAnywhere, 기본 `true`) 추가, 클래스 주석의 "패리" 표현 정정 | 수정 |
| `Plugins/WxCombat/.../Private/Weapon/WxProjectileBase.cpp` | 반사 조건의 `DamageRow->bCanParry`를 `bCanReflect`로 교체 | 수정 |
| `Plugins/WxCombat/.../Private/AbilitySystem/Effect/WxEffectComponent_DamageResponse.cpp` | `bReflectedProjectile`·EffectCauser 조회·`WxProjectileBase.h` include 제거 | 수정 |
| `Plugins/WxCombat/.../Public/Damage/WxDamageTableRow.h` | `bCanParry` 주석에서 투사체 예외 문구 삭제 | 수정 |

### 접근 방식
- **반사 판정은 투사체가 접촉 시점에 단독으로 낸다**: `HandleHitCollisionOverlap`의 조건을 `!bEvaded && bCanReflect && DamageRow->bCanGuard && Effect.PerfectGuard`로 바꾼다. `bCanGuard`가 남는 이유는 가드를 뚫는 공격에는 퍼펙트 가드 자체가 서지 않기 때문이다.
- **`DamageResponse`에서 투사체 분기를 통째로 걷어낸다**: 공격자 처벌은 저작값 `bCanParry`만 보고 나간다. 새 태그도, `ApplyDamage`에 전달 인자를 뚫는 일도 없다. 되돌아가는 투사체에 처벌을 겹치고 싶지 않으면 그 행의 `bCanParry`를 끄면 되고, 반사는 `bCanReflect`가 쥐고 있어 살아 있다.
- **역할 정리**: `bCanReflect`(투사체) = 되돌아갈지. `bCanParry`(대미지 행) = 퍼펙트 가드로 막혔을 때 공격자가 역경직에 걸릴지. GP 반사는 모든 퍼펙트 가드에 들어간다.

### 동작 변화
되돌아가는 투사체에도 공격자 GP 반사가 들어간다. 예외를 유지하려면 "이 히트는 되돌아간다"를 대미지 GE 쪽으로 전달할 장치가 다시 필요해, 태그를 늘리지 않는 대신 단순한 새 동작을 택한다. 역경직은 `DT_Damage`의 투사체 행에서 `bCanParry`를 끄면 뺄 수 있고, GP는 필요해지면 그때 통로를 만든다.

### 구현·결정과 그 이유
- **전달 통로를 만들지 않았다**: 반사 여부를 스펙 태그로 실어 보내는 안도 있었지만, 태그와 `ApplyDamage` 인자를 늘려야 한다. 분리하고 나면 `DamageResponse`가 반사 여부를 알아야 할 이유 자체가 없어져 통로가 필요 없다.
- **`bCanGuard`는 조건에 남겼다**: 가드를 뚫는 공격에는 `Effect.PerfectGuard`가 있어도 퍼펙트 가드가 서지 않는다(`UWxEffect_Damage`의 `bPerfectGuardApplied`). 태그만 보고 되돌리면 대미지는 그대로 들어가면서 투사체만 돌아선다.
- **기본값을 `true`로 뒀다**: 유일한 투사체 에셋 `BP_Projectile`이 별도 저작 없이 기존 반사 동작을 유지한다.
- **`bCanParry` 지역 변수를 인라인했다**: 투사체 분기가 사라져 사용처가 리액션 게이트 한 곳만 남았다.

### 후속 과제
- PIE 확인 3건: ① `bCanReflect = true` 투사체를 퍼펙트 가드 → 되돌아간다(대미지 행의 `bCanParry`와 무관) ② `bCanReflect = false` 투사체 → 되돌아가지 않고 소멸 ③ 근접 퍼펙트 가드의 GP·역경직은 기존과 동일.
- 되돌아가는 투사체가 이제 공격자 GP도 올린다. 3중 보복이 과하면 `DT_Damage`의 투사체 행에서 `bCanParry`를 꺼 역경직만 뺀다. GP까지 빼야 하면 그때 전달 통로를 만든다.
