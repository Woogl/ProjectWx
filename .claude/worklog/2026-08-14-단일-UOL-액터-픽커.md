# 단일 UOL 필드에도 액터 픽커 적용

## 계획

### 목표
`AllowedLocators="Actor"` UOL 필드에 붙는 한 줄 액터 픽커를 단일 `FUniversalObjectLocator` 멤버에서도 쓸 수 있게 한다. 현재 프로젝트의 UOL 필드는 전부 배열이고, 태스크 헤더 5곳과 `WxQuest/README.md` 가 "직속 단일 UOL 멤버는 ST 에디터가 값 위젯을 못 만드는 엔진(5.8) 제한" 때문이라고 못 박아 두었다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxQuest/.../WxStateTreeTask_WaitMoveToTarget.h` | 단일 UOL 필드 임시 추가 → 실측 후 원복 | 수정(임시) |
| `Source/WxEditor/WxActorLocatorCustomization.h/.cpp` | (조건부) 픽커를 자립형 위젯으로 분리해 멤버 상태 제거 | 수정 |
| 태스크 헤더 5곳(`WxQuest` 이동, `WxWorld` 스포너 2종, `WxUI` 인디케이터, `WxDialogue` NPC) | "하나만 쓸 자리라도 배열로 받는다 — 엔진(5.8) 제한" 문장을 실제 이유로 교체 | 수정 |

### 접근 방식
- **선행 실측**: 프로젝트에 단일 UOL 필드가 하나도 없어 직속 멤버 경로가 미검증이다. 임시 필드를 하나 넣고 빌드해 ST 노드 디테일에서 픽커 렌더·선택·메뉴 닫힘을 먼저 확인한다.
- **파라미터 백은 이미 동작**: 스크래치 ST 에 메타 포함 단일 UOL 루트 파라미터를 넣어 픽커가 뜨는 것을 실측했다. 링크 상태 오버라이드·`FStateTreeReference` 쪽은 손댈 것이 없다.
- **엔진 제한의 진짜 원인**: ST 의 `ModifyRow` 가 직속 자식 행에 `GetDefaultWidgets` 를 부르고, 이게 버려지는 행에 `CustomizeHeader` 를 한 번 더 실행한다. 엔진 UOL 커스터마이제이션은 그 호출에서 `bRebuildRequested` 를 세우고 화면 밖 위젯에 액티브 타이머를 걸어 플래그가 영영 안 풀리고, 진짜 행의 재빌드가 통째로 무시돼 값 영역이 빈다. 우리 커스터마이제이션엔 그 래치가 없어 마지막 호출이 이긴다.
- **보강은 필요할 때만**: 실측에서 어긋나는 게 있으면 픽커를 자립형 Slate 위젯으로 분리해 호출 순서 비의존으로 만든다. 문제가 없으면 코드는 건드리지 않고 문서만 고친다.
- **배열 단일화는 안 한다**: UOL 을 쓰는 태스크 5종은 전부 다중 대상이 의도다. 단일 선언은 앞으로 만들 노드를 위한 선택지로 열어두는 것이다.

### 구현·결정과 그 이유
- **픽커 코드는 손대지 않았다**: 임시 단일 필드로 실측해 보니 ST 인스턴스 데이터 직속 멤버에서도 렌더·메뉴·선택·라벨 갱신·메뉴 닫힘이 전부 정상이었다. 계획의 "필요할 때만 보강" 조건이 성립하지 않아 자립형 위젯 분리는 하지 않았다.
- **7월에 기록한 "엔진(5.8) 제한"의 실체**: ST 의 ModifyRow 가 직속 자식 행에 `GetDefaultWidgets` 를 부르고 그게 버려질 행에 `CustomizeHeader` 를 한 번 더 돌린다. 엔진 UOL 편집기는 그 첫 호출에서 재빌드 요청 플래그를 켜고 화면 밖 위젯에 액티브 타이머를 걸어, 플래그가 안 풀린 채 진짜 행의 재빌드가 통째로 무시된다 — 그래서 값 영역이 비었던 것이다. 우리 커스터마이제이션은 호출마다 위젯을 새로 만들어 무관하다. 다만 이 이중 호출 때문에 호출 간 지연 상태를 두면 안 되므로 주석으로 남겼다.
- **인디케이터·NPC 태스크까지 단일화한 이유**: 스텝의 대상 파라미터 하나가 도메인 태스크와 MarkIndicator 를 함께 먹이는데 ST 바인딩은 단일↔배열을 잇지 못한다. 이동 태스크만 단일로 바꾸면 같은 액터를 두 번 지정해야 해서, 사용자 선택(A안)대로 스텝의 대상 지정을 단일로 통일했다. Kill 스텝의 스포너는 여럿이 실제 의미가 있고 인디케이터가 걸려 있지 않아 배열 그대로 뒀다.
- **개명 손실은 StructRedirect 로 회수**: `MarkIndicators`→`MarkIndicator` 개명으로 기존 스텝 에셋의 노드가 로드 시 사라지면서 `WorldZOffset`(둘 다 40)까지 잃을 뻔했다. 임시 리다이렉트를 넣고 재시작해 값을 살린 뒤, 두 에셋을 새 이름으로 저장하고 리다이렉트를 지웠다(콘텐츠 전수 스캔으로 잔여 참조 0 확인).

### 계획 대비 달라진 점
- 임시 필드는 실측 후 제거하고 끝낼 계획이었으나, 사용자가 "MoveToTarget 에서 단일 UOL 을 쓰고 싶다" 고 밝혀 태스크 3종 단일화 + 스텝 에셋 2종 + 퀘스트 오버라이드 재작업까지 범위가 늘었다.
- 커스터마이제이션 보강(계획 2단계)은 불필요로 판명돼 생략했다.

### 검증
- WxEditor(Development) 빌드 성공(3회, 에러 0).
- 단일 UOL 픽커 실측: 태스크 인스턴스 데이터 직속 멤버 행에 픽커 렌더 → 콤보 메뉴(Use Selected/Copy/Paste/Clear + 아웃라이너 검색) → Use Selected 로 값 기입(`(uobj://actor?...)`) → 메뉴 자동 닫힘 → 라벨 `BP_Npc` 갱신. 파라미터 백(루트 파라미터) 단일 UOL 도 같은 픽커 확인.
- ST 에셋 4종 전부 컴파일 succeeded(에디터 기동 시 자동 컴파일 로그로 재확인) — 바인딩 경로가 모두 해석된다는 뜻.
- 저장 후 재조회로 Step1·Step2 오버라이드 값·마킹 잔존 확인, MoveTo 스텝 디테일 패널에서 `Target` 픽커 행 렌더 확인.
- PIE 기동 로그에 StateTree·인디케이터·바인딩 관련 에러/경고 없음.

### 후속 과제
- 퀘스트 풀 플로우 수동 PIE 검증(Step1 대화 → Step2 이동 → Step3 처치) — 수주가 볼륨 오버랩이라 자동화로 걷지 못했다.
- `ST_Quest_Main1` 의 `Quest.Fail` 태그가 미등록 상태라 로드 시 경고가 뜬다(이번 작업과 무관한 기존 문제).
