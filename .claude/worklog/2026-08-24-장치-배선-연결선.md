# 장치 배선 — 선택 장치 전용 연결선

## 계획

### 목표
`LinkedDevices` 배선이 디테일 패널의 오브젝트 참조 목록으로만 보여, 레벨을 훑는 것만으로는 어떤 장치가 어떤 장치를 미는지 알 수 없다. 에디터 뷰포트에서 선택 중인 장치의 배선을 시안 화살표로 그린다. 게임 플레이 화면에는 절대 나오지 않아야 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxEditor/WxDeviceLinkVisualizer.h` | `FComponentVisualizer` 파생 선언. `DrawVisualization` 하나만 오버라이드, 색·두께·화살촉 크기 멤버 | 신규 |
| `Source/WxEditor/WxDeviceLinkVisualizer.cpp` | 오너를 `AWxDevice` 로 캐스팅 → `LinkedDevices` 순회 → 유효한 끝점마다 화살표 | 신규 |
| `Source/WxEditor/WxEditor.h` | 비주얼라이저는 엔진이 들고 있으므로 모듈 멤버 없음 | 수정 |
| `Source/WxEditor/WxEditor.cpp` | 시작 시 `GUnrealEd->RegisterComponentVisualizer`, 종료 시 `Unregister` | 수정 |

### 접근 방식
- **에디터 모듈에만 둔다**: 런타임 모듈을 한 줄도 고치지 않아 쿠킹된 빌드엔 코드 자체가 없고, 에디터 빌드와 쿠킹 빌드의 런타임 동작이 완전히 같다. 런타임 클래스에 `#if WITH_EDITOR` 틱을 다는 갈래는 기각했다 — `WITH_EDITOR` 는 PIE 에서도 참이라 어차피 월드 타입 게이트가 진짜 방어선인데, 그 갈래는 두 빌드의 틱 등록을 서로 다르게 만들고 배치 상태를 장치 수만큼 흩뿌린다.
- **선택 게이팅·수명을 엔진에 맡긴다**: 엔진은 선택이 바뀔 때 선택된 액터의 컴포넌트를 훑어 비주얼라이저 목록을 만들고, 뷰포트 드로우마다 그 목록만 그린다. 그래서 우리 쪽엔 선택 추적도, 편집 이벤트 구독도, 직전 목록 캐시도 필요 없다. 여러 장치를 함께 선택하면 각자의 배선이 함께 나오므로 전체 그래프도 전체 선택으로 볼 수 있다.
- **등록 키는 `UStateTreeComponent`**: 비주얼라이저는 컴포넌트 클래스로만 등록되는데 배선은 액터가 들고 있다. 장치의 컴포넌트는 `UWxDeviceStateTreeComponent` 하나뿐이지만 WxWorld Private 헤더인 데다 API 노출도 없어 에디터에서 잡을 수 없다. 엔진이 비워 둔 `UStateTreeComponent` 자리에 등록하면 클래스 사슬을 거스르는 탐색이 파생 컴포넌트까지 덮는다(박스 모서리 핸들이 `UBoxComponent` 에 한 것과 같은 패턴). 장치가 아닌 오너는 그리기 직전 캐스팅으로 거른다.
- **매 드로우 갱신**: PDI 로 매 프레임 그리므로 드래그 도중에도 화살표 끝이 따라온다.

### 기각한 갈래
- **영속 라인 배쳐에 월드 전체 배선을 상시 그리기**: 편집 이벤트(이동·추가·삭제·프로퍼티·언두·맵 열림)를 전부 구독해 배선 목록을 다시 만들고, 직전 목록과 달라졌을 때만 자기 BatchID 를 갈아 끼우는 판. 배선을 한눈에 다 볼 수 있지만 장치가 늘면 화면이 선으로 덮이고, 드래그 도중에는 엔진이 쏘는 것이 액터 가상 함수(`PostEditMove`)뿐이라 밖에서 들을 수 없어 선이 따라오지 않는다.
- **`WxDeviceStateTreeComponent.h` 를 Public 으로 이관**: 정확한 등록 키를 얻지만 에디터 전용 도구 하나 때문에 런타임 모듈의 공개 표면을 넓힌다.

### 구현·결정과 그 이유
- **선만 긋는다**: 뷰포트는 「이 둘이 이어져 있다」만 보이고, 어느 쪽이 미는지는 디테일 패널이 답한다. 방향 표시를 얹었다가 걷어낸 경위는 아래 참조.
- **두께 0**: 화면에서 항상 1픽셀이라 거리와 무관하게 같은 굵기로 보인다. 멀리 있는 배선이 가늘어져 사라지지 않는다.

### 계획 대비 달라진 점
- 방향 화살표를 뺐다. 엔진 기본 방향 화살표는 촉이 정사각형 네 귀퉁이로 뻗는 선 네 가닥이고 끝을 잇는 테두리가 없어, 정면에서는 X자 옆에서는 V자로 갈라진 뭉툭한 모양이 된다(크기를 줄여도 갈라지는 성질은 그대로다). 스포크 끝을 테두리로 잇는 쪽으로 한 번 바꿔 보았다가, 선만 남기는 것으로 정리했다.

### 후속 과제
- 방향은 보이지 않는다. 되돌림 배선처럼 두 장치가 서로를 가리키면 선 한 가닥으로 겹쳐 보인다.
- 들어오는 배선(누가 나를 가리키는가)은 그리지 않는다. 그러려면 월드 전체를 훑어야 해서 이번 범위 밖으로 두었다.
- 레벨 에디터의 Show Selection Subcomponents 를 끄면 그려지지 않는다. 장치의 컴포넌트가 루트가 아니라 엔진이 이 설정을 보기 때문이며, 켜져 있는 것이 기본값이다.
