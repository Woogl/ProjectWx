# 대미지 판정을 스펙 태그로 통일하고 커스텀 이펙트 컨텍스트를 걷어낸다

## 계획

### 목표
`UWxCombatAttributeSet::ProcessDamageTaken`이 커스텀 컨텍스트(`FWxCombatEffectContext`)를 캐스팅해 크리를 읽고 큐 파라미터 태그로 옮겨 담는다. 같은 파일이 `UWxEffect_Damage` 클래스도 `IsA`로 직접 안다. 대미지 판정을 전부 스펙 동적 애셋 태그 한 축으로 통일해 두 의존을 없애고, 크리 하나 때문에 존재하던 커스텀 컨텍스트를 삭제한다.

|---|---|---|
| `Plugins/WxCombat/.../Effect/WxEffect_Damage.cpp` | ExecCalc가 크리를 스펙 동적 태그로 실음, 컨텍스트 캐스팅·ensure 제거 | 수정 |
| `Plugins/WxCombat/.../Damage/WxDamageTableRow.cpp` | 공격 대미지 표식 `Damage.Attack`을 항상 실음 | 수정 |

### 접근 방식
- **크리를 스펙 동적 애셋 태그로**: ExecCalc가 `SetCritical` 대신 `AddDynamicAssetTag(Damage.Critical)`을 쓴다. 가드 브레이크가 이미 쓰는 경로다. 컨텍스트를 떠나는 이유는 수명이다 — `MakeSpecs`가 하나의 컨텍스트 핸들을 대미지 스펙과 `AdditionalEffects` 스펙들에 함께 넘기므로, 거기 적은 판정은 같은 히트의 상태이상 GE에도 딸려 간다. 히트 단위 판정은 스펙 단위 수명을 갖는 태그가 맞는 그릇이다.
- **공격 여부도 태그로**: `IsA<UWxEffect_Damage>()`가 하던 판별은 `MakeSpecs`가 `Damage.Attack`을 항상 실어 대신한다. 표식을 공격 쪽에 두는 이유는 관리 지점이 하나이기 때문이다 — 치트·환경 피해가 "반응 없음"을 선언하는 반대 방향은 새 피해원마다 잊을 자리가 생긴다.
- **큐 파라미터가 한 줄 줄어든다**: 크리를 조건 분기로 담던 자리가 스펙 동적 태그를 통째로 넘기는 한 줄이 된다. 큐 노티파이는 지금처럼 `AggregatedSourceTags`에서 크리를 읽으므로 큐 쪽은 손대지 않는다.
- **커스텀 컨텍스트 삭제**: `UWxAbilitySystemGlobals`는 남는다 — 큐 파라미터에 `ImpactPoint`를 채우는 다른 역할이 있어 ini 등록도 그대로다. 컨텍스트는 런타임 전용이라 에셋에 직렬화된 참조가 없다.
- **큐 실행은 남긴다**: 대미지 값이 이 자리에 있고, GE에 붙인 큐로 옮기면 예측 클라(ExecCalc가 돌지 않아 값이 0이고 크리 태그도 없다)에서 0짜리 플로터가 뜨는 문제를 새로 떠안는다.

### 구현·결정과 그 이유
- **판정의 그릇은 수명으로 골랐다**: `MakeSpecs`가 컨텍스트 핸들 하나를 대미지 스펙과 `AdditionalEffects` 스펙들에 함께 넘긴다. 컨텍스트에 적은 판정은 같은 히트의 상태이상 GE에도 딸려 가므로, 히트 하나와 수명이 같은 스펙 동적 태그가 맞는 그릇이다. 크리를 옮기자 커스텀 컨텍스트의 존재 이유가 사라져 구조체를 통째로 지웠다.
- **표식은 공격 쪽에 뒀다**: "이 피해가 공격에서 왔는가"를 공격이 스스로 선언하게 하면 관리 지점이 `MakeSpecs` 하나다. 반대로 치트·환경 피해가 "반응 없음"을 선언하는 방향은 새 피해원마다 잊을 자리가 생긴다.
- **큐에 태그를 통째로 넘겼다**: 크리만 골라 담던 조건 분기가 한 줄이 됐고, 어떤 갈래를 쓸지는 큐가 고른다. `AggregatedSourceTags`에 판정 태그를 싣는 것은 기존 관행 그대로다 — 큐 파라미터에 판정용 전용 필드가 없다.
- **`UWxAbilitySystemGlobals`는 남겼다**: 큐 파라미터에 `ImpactPoint`를 채우는 역할이 있어 ini 등록도 그대로 필요하다. 클래스 주석을 그 역할로 고쳤다.
- **어트리뷰트 셋의 도메인 의존이 사라졌다**: include가 엔진 헤더와 `WxGameplayTags`만 남았다.
