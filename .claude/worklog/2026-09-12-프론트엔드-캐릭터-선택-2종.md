# 프론트엔드 위젯 — 캐릭터 2종 선택에 맞춘 구조 정리

## 계획

### 목표
캐릭터 페이지에 두 번째 캐릭터 버튼이 추가됐지만 배선은 캐릭터가 하나뿐이던 시절 그대로라, 어느 버튼을 눌러도 첫 번째 캐릭터가 선택된다. 두 캐릭터가 실제로 선택되게 만들고, 캐릭터가 더 늘어날 때 이벤트가 함께 늘어나지 않는 모양으로 정리한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_FrontEnd.uasset` | 선택 핸들러를 축별 하나로 합치고 인덱스를 파라미터로 받게 변경, 선택지별 핸들러와 죽은 이벤트 삭제, 두 번째 캐릭터 목록 항목 추가, 새 버튼을 활성 갱신 대상에 포함, 캐릭터 버튼 변수 이름을 규칙에 맞게 변경 | 수정 |

C++ 변경은 없다.

### 접근 방식
- **선택 핸들러를 축별로 하나만 둔다**: 지금은 선택지 하나당 이벤트 하나이고 그 안에 똑같은 가드(현재 페이지·이동 중·팝업 열림 확인)가 복사돼 있다. 캐릭터가 늘 때마다 가드 사본도 는다. 캐릭터축·목적지축에 각각 이벤트 하나만 남기고, 버튼이 고르는 값은 인덱스 파라미터로 클릭 이벤트가 넘긴다. 버튼과 인덱스의 대응이 클릭 이벤트에서 바로 보이므로 목록 순서와 어긋났는지도 드러나고, 캐릭터를 더 붙일 때 필요한 것은 버튼·클릭 이벤트 한 줄·목록 항목 하나뿐이다.
- **파라미터 있는 이벤트를 만드는 수단**: 커스텀 이벤트에 타입 있는 파라미터 핀을 직접 붙일 방법이 없어, 함수 그래프로 만들어 정수 파라미터를 단 뒤 엔진의 함수→이벤트 전환으로 바꾼다.
- **상태 갱신은 노드를 직접 잇는다**: 이 이벤트는 이동 상태 조회의 두 출력을 모두 쓰고 있어 그래프 DSL 왕복이 출력 핀 선택을 잃는다. 새 버튼의 활성 설정만 노드로 만들어 기존 체인 끝에 붙인다.
- **표시명 구분**: 확인 팝업이 캐릭터 표시명을 그대로 보여주므로, 기존 항목의 `Player` 를 `Template Player` 로 고쳐 둘이 구분되게 한다. 버튼 라벨은 레벨 버튼과 같은 규칙(에셋 이름)이라 그대로 둔다.
- **죽은 이벤트 제거**: 아무도 부르지 않던 새 게임 가드 이벤트를 지운다. 새 게임 버튼은 지금도 캐릭터 페이지를 직접 열고, 그 가드는 버튼이 이미 비활성이라 걸릴 일이 없다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_FrontEnd.uasset` | 선택 핸들러를 축별 하나로 합쳐 인덱스를 파라미터로 받게 하고, 선택지별 핸들러 셋과 죽은 이벤트를 삭제. 클릭 이벤트 넷이 각자 인덱스를 넘기도록 재배선. 캐릭터 목록에 두 번째 항목 추가, 첫 항목 표시명 정정. 상태 갱신에 새 버튼 활성 설정 추가. 캐릭터 버튼 변수 이름 두 개 변경 | 수정 |

### 구현·결정과 그 이유
- **선택 이벤트가 넷에서 둘로 줄었다**: 선택지마다 가드를 복사하던 구조를 캐릭터축·목적지축 이벤트 하나씩으로 합쳤다. 인덱스는 클릭 이벤트가 넘긴다. 가드 사본이 넷에서 둘로 줄었고, 버튼과 인덱스의 대응이 클릭 이벤트 한 줄에 드러나 목록 순서와 어긋났는지 바로 보인다. 캐릭터를 더 붙일 때 손댈 곳은 버튼·클릭 이벤트·목록 항목 셋뿐이다.
- **파라미터 있는 이벤트는 함수를 거쳐 만들었다**: 커스텀 이벤트에 타입 있는 파라미터 핀을 붙이는 수단이 없어, 함수 그래프로 정수 파라미터를 달고 본문을 채운 뒤 엔진의 함수→이벤트 전환을 썼다. 지운 커스텀 이벤트의 이름은 한 번 컴파일하기 전까지 스켈레톤에 남아 새 함수 이름에 접미사가 붙으므로, 삭제 후 컴파일을 한 번 끼워 넣었다.
- **상태 갱신은 손으로 다시 썼다**: 이 이벤트는 이동 상태 조회의 두 출력을 쓰는데 그래프 DSL 역변환이 그 구분을 잃는다. 두 출력을 함께 묶는 형태로 직접 적어 새 버튼 한 줄을 끼웠고, 결과적으로 조회 노드가 하나로 유지된다.
- **표시명을 구분했다**: 캐릭터가 둘이 되어 확인 팝업의 `Player` 가 모호해졌다. 첫 항목을 `Template Player`, 새 항목을 `Test Player` 로 두었다. 버튼 라벨은 레벨 버튼과 같은 규칙(에셋 이름)이라 건드리지 않았다.
- **배열은 두 번에 나눠 썼다**: 프로퍼티 설정이 배열 크기 변경과 원소 값 변경을 한 번에 거부한다. 기존 항목을 그대로 둔 채 새 항목만 붙이고, 표시명 수정은 두 번째 호출로 처리했다.
- **검증**: 경고를 오류로 취급한 컴파일 통과, 저장 시 에셋 검증 통과. 그래프를 다시 읽어 클릭 이벤트 넷이 각자 다른 인덱스를 넘기는지, 가드 내용이 기존과 같은지, 팝업 델리게이트가 여전히 결과 핸들러에 묶여 있는지 확인했다.

### 계획 대비 달라진 점
- 계획대로다. 다만 함수 그래프 제거가 위젯 에디터를 닫아, 다시 열었을 때 Designer 모드로 시작해 그래프 모드로 전환하는 단계가 중간에 끼었다.

### 후속 과제
- 플레이 확인 미실행. 두 캐릭터를 각각 골라 레벨에 들어가 서로 다른 폰으로 스폰되는지 봐야 한다.
- 레벨 전환 실패 시 메뉴가 스스로 복구되지 않는 상태는 그대로다. 상태 폴링 제거 때의 후속 과제를 함께 본다.
