# GP 드레인 종료 시점을 그로기 몽타주 길이에 맞춘다

## 계획

### 목표

`UWxEffect_DrainGP`가 적용 즉시 한 번 더 실행되는 탓에 GP가 의도한 길이보다 한 주기(33ms) 먼저 0에 닿고, 그 값을 보는 그로기 어빌리티가 몽타주가 끝나기 전에 종료된다. 즉시 실행을 없애고 틱당 차감량 계산을 고쳐 GP가 몽타주 길이 끝에서 0에 닿게 한다. 길이는 `SetByCaller.Duration` 태그 대신 호출부가 스펙에 직접 넣는다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |

| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Effect/WxEffect_DrainGP.h` | 두 클래스 주석을 바뀐 계약(명시 길이·마지막 틱에서 0)에 맞게 정정 | 수정 |

### 접근 방식

- **길이는 스펙에 직접 지정**: 호출부가 `SetDuration(GroggyDuration, /*bLockDuration=*/true)`로 몽타주 길이를 넣는다. 적용 시점에 엔진이 Def에서 Duration을 재계산해 덮어쓰는 경로가 있는데, 잠금 플래그가 그 재진입을 막아 명시값이 유지된다. GE 쪽 SetByCaller 선언은 지운다. 다른 GE의 SetByCaller 사용은 건드리지 않는다.
- **즉시 실행 제거**: 엔진 기본값이 `true`라 생성자에서 명시적으로 끈다. 실행 지점은 주기 배수뿐이 된다.
- **틱당 차감량 = `-MaxGP / 실제 틱 수`**: 즉시 실행만 끄고 시간 비례 계산을 두면, 길이가 주기의 배수가 아닐 때 마지막 부분 주기가 실행되지 않아 GP가 0에 못 닿는다. 그로기 종료는 GP == 0에만 걸려 있고 몽타주는 폴링으로 계속 재생되므로 그 경우 그로기가 풀리지 않는다. 그래서 나눗셈 기준을 시간이 아니라 실행 횟수(`Floor(Duration / Period)`, 최소 1)로 바꾼다. 길이가 주기의 배수면 마지막 틱이 만료 시점에 정확히 놓이고(엔진이 만료 프레임에서 남은 주기 틱을 한 번 더 실행한다), 아니면 최대 한 주기 이르게 0이 된다 — 고정 주기에서의 한계다.
- **프레임률 영향 없음**: 타이머 매니저가 한 프레임에 여러 주기를 넘겼을 때 그만큼 반복 호출하므로 실행 횟수는 프레임률과 무관하게 결정적이다.

### 구현·결정과 그 이유

- **길이를 스펙에 직접 넣었다**: 태그로 실어 보내던 값을 스펙의 지속시간 지정으로 바꿨다. 적용 시점에 엔진이 Def에서 지속시간을 다시 계산해 덮어쓰는 경로가 있어 잠금 인자를 켜서 넣는다 — 잠기면 그 재계산이 스펙을 건드리지 못한다. 이 GE에는 더 이상 태그로 넘길 값이 없어 태그 헤더 의존도 사라졌다. 쿨다운·치트 GE의 같은 태그 사용은 그대로 뒀다.
- **즉시 실행을 껐다**: 즉시 실행은 주기 눈금 밖에 놓여 실행 횟수만 하나 늘렸고, 그만큼 GP가 일찍 0에 닿아 몽타주가 끝나기 전에 그로기가 풀렸다. 엔진 기본값이 켜짐이라 생성자에서 명시적으로 끈다.
- **나눗셈 기준을 시간에서 실행 횟수로 바꿨다**: 즉시 실행만 끄고 시간 비례 차감을 두면, 지속시간이 주기의 배수가 아닐 때 마지막 자투리 주기가 실행되지 않아 GP가 0에 못 닿는다. 그로기 종료 조건은 GP가 0인 것뿐이고 몽타주는 폴링이 계속 다시 재생하므로, 그 경우 그로기가 영영 풀리지 않는다. 그래서 실제 실행 횟수로 MaxGP를 나눈다. 몽타주가 30fps 눈금으로 저작돼 지속시간이 주기의 배수면 마지막 틱이 만료 시점에 정확히 놓이고(엔진이 만료 프레임에서 남은 주기 틱을 한 번 더 실행한다), 아니면 최대 한 주기 이르게 0이 된다 — 주기가 고정인 이상 이보다 정밀할 수 없다.
- **틱 수 산정과 차감량 양쪽에 부동소수 여유를 뒀다**: 지속시간을 주기로 나눈 몫이 오차로 한 눈금 아래로 떨어져 틱 하나를 잃는 일을 막으려고 내림 전에 작은 값을 더한다. 차감량 쪽에는 틱당 0.01% 여유를 곱한다 — 마지막 틱이 정확히 0에 떨어지길 기대하면 float 누적 오차로 GP가 1e-5 남짓 남고, 종료 조건이 GP 0 하나뿐이라 그로기가 죽을 때까지 안 풀린다. MaxGP·몽타주 길이 4천 조합을 float32로 돌려 보니 여유가 없을 때 절반가량이 0에 못 닿았고, 0.01%를 곱하면 전부 마지막 틱에서(더 이르지 않게) 0에 닿았다.
- **프레임률은 영향이 없다**: 타이머 매니저가 한 프레임에 여러 주기를 넘겼을 때 넘긴 횟수만큼 반복 호출하므로, 실행 횟수는 프레임률과 무관하게 결정적이다. 히치가 나도 틱이 유실되지 않는다.

### 계획 대비 달라진 점

- **차감량 여유는 계획에 없던 것이다**: 구현을 마치고 재검토하다 발견했다. 예전 코드는 즉시 실행 한 번이 한 틱치(1/N) 여유로 작동해 누적 오차를 덮고 있었는데, 그 여유를 걷어내면서 마지막 틱이 경계에 정확히 놓이게 됐다. 여유를 0.01%로 줄여 되살렸다 — 한 틱치의 1/100 수준이라 종료 시점은 그대로다.
