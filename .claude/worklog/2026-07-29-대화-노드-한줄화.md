# 대화 노드 = 대사 한 줄로 단순화

## 계획

### 목표
`FWxDialogueTableRow` 가 `TArray<FWxDialogueLine> Lines` 로 한 행에 여러 대사를 담는 탓에, 세션이 행 순회(NextRow·Choices)와 행 내부 라인 순회(LineIndex) 두 층을 동시에 굴린다. 노드를 대사 한 줄로 못 박아 진행 축을 행 하나로 통일한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueTableRow.h` | `FWxDialogueLine` 구조체 삭제, `FWxDialogueTableRow` 가 `Speaker`·`Text` 를 직접 보유 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueSessionComponent.h` | `LineIndex` 멤버 삭제, 관련 주석 갱신 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Private/WxDialogueSessionComponent.cpp` | `Advance` 의 라인 순회 분기 제거, 게터·`EnterRow` 를 행 직접 참조로 | 수정 |
| `Plugins/WxDialogue/README.md` | 데이터 모델·핵심 타입 표에서 `FWxDialogueLine`/Lines 표현 갱신 | 수정 |
| `Content/DesignerTables/DT_Dialogue.uasset` | 2줄짜리 행 3개를 행 2개씩으로 분할해 재작성 | 수정(에셋) |

### 접근 방식
- **행 = 대사 한 줄**: `Speaker`·`Text` 가 행 필드가 되고 `Choices`·`NextRow` 는 그대로다. 세션의 진행 축이 행 하나로 줄어 `Advance` 는 "선택지 있으면 대기, 없으면 `NextRow`, 그것도 없으면 종료" 세 갈래가 된다.
- **빈 노드 = 종료 유지**: 지금은 `Lines` 가 비면 `EnterRow` 가 실패해 대화가 끝난다. 같은 뜻으로 `Text` 가 비면 실패로 둔다 — 오타난 행 이름이 빈 대사창으로 굳는 걸 막는 기존 안전망을 그대로 옮긴다.
- **데이터 이관**: 구조체에서 `Lines` 가 사라지면 기존 대사는 로드 시 버려지므로, 변경 전에 덤프한 4행 7줄을 행 분할로 복원한다. 머리 행 이름을 유지해 `StartRow` 지정과 퀘스트 ST 참조는 그대로 산다.

| 기존 행 (줄 수) | 이관 후 |
|---|---|
| Intro (2) | `Intro` → `Intro2` → `Warning` |
| Warning (2) | `Warning` → `Warning2` → `Request` |
| Request (2) | `Request` → `Request2` → 종료 |
| Success (1) | 그대로 |

이어붙인 행 이름은 기계적인 숫자 접미사로 둔다. 노드가 곧 대사라 개수가 늘어날 텐데, 의미 이름을 붙이면 대사가 바뀔 때마다 이름이 낡는다.

### 구현·결정과 그 이유
- **진행 축을 행 하나로**: 라인 인덱스가 사라지면서 `Advance` 는 선택지 대기·`NextRow`·종료 세 갈래만 남았다. 대사를 늘리는 방법이 행 추가 하나로 통일돼, 같은 일을 두 방식으로 하던 겹침이 없어졌다.
- **빈 대사를 실패로 유지**: 대사가 비면 `EnterRow` 가 실패해 대화가 끝난다. 오타난 행 이름이 빈 대사창으로 굳는 걸 막던 기존 안전망을 뜻 그대로 옮긴 것이라, 새 판정이 아니라 기존 판정의 이름만 바뀐 셈이다.
- **머리 행 이름 보존**: 이어붙인 행만 새 이름을 받고 기존 4행 이름은 그대로 뒀다. 시작 노드를 가리키는 NPC 지정과 퀘스트 ST 참조가 대화 데이터 개편과 무관하게 살아남는다.
- **대사 원문 보존**: 이관은 로컬라이즈 텍스트 형태를 유지한 채로 했다. 표시 문자열은 물론 줄바꿈까지 변경 전 덤프와 동일하게 왕복되는 걸 확인했다.

### 계획 대비 달라진 점
계획대로. 다만 PIE 실동작 확인은 사용자가 직접 진행하기로 했다.

### 후속 과제
- PIE 실동작 확인 — 대사 7줄이 순서대로 넘어가고 종료되는지 (사용자 진행). 확인용 PIE 세션을 켜 둔 상태다.
