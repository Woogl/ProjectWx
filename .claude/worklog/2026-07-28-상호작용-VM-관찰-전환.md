# 상호작용 VM 관찰 전환

## 계획

### 목표

상호작용 스캐너는 멀티플레이 클라이언트에 복제로 늦게 도착하는데, 리스트 뷰모델 리졸버가 위젯 생성 시점 1회 조회 실패로 굳어 세션 내내 프롬프트가 죽는다. 인벤토리에 검증된 관찰형 VM 패턴을 1:1 이식해 늦은 도착을 흡수한다. (퀘스트 저널 복제·인디케이터 마커 보드는 퀘스트 멀티플레이 정책 미정으로 보류)

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/.../Interaction/WxInteractionScannerComponent.h/.cpp` | static Ready 델리게이트 3점 세트 + BeginPlay 무조건 발행 | 수정 |
| `Source/WxGame/MVVM/WxViewModel_InteractionList.h/.cpp` | 관찰 멤버·StartObserving·BeginDestroy 추가, Initialize 선행 Deinitialize, 리졸버를 항상-생성형으로 전환 | 수정 |

### 접근 방식

- **관찰형 VM(인벤토리 패턴)**: 리졸버는 스캐너 유무와 무관하게 VM 을 만들어 돌려주고(뷰가 인스턴스를 교체할 수 없으므로), VM 이 즉시 조회 → 실패 시 클래스 차원 Ready 신호를 구독해 도착 시 내부 상태만 갈아끼운다. Ready 신호는 컴포넌트 BeginPlay 에서 무조건 발행해 주입(서버)·복제 도착(클라) 어느 경로든 수렴시키고, 구독자는 소유 컨트롤러로 자기 것인지 가린다(이 필터가 PIE 다중 인스턴스 교차 발화도 막는다).
- 발행 위치는 스캐너 BeginPlay 의 로컬 컨트롤러 조기 리턴보다 위 — 데디 서버 PC 발행은 구독자가 없어 무해.
- 재초기화 안전: 늦은 도착으로 Initialize 가 두 번째 호출될 수 있고 다이나믹 델리게이트는 중복 구독을 막지 않으므로, Initialize 맨 앞에서 Deinitialize 로 이전 구독을 걷는다. 구독 해제는 소멸 시점(BeginDestroy)에만 둔다.

## 완료

| `Source/WxGame/MVVM/WxViewModel_InteractionList.h/.cpp` | StartObserving/HandleScannerReady/StopObserving/BeginDestroy 추가, Initialize 선행 Deinitialize, 리졸버 항상-생성형(Outer=PC) 전환, 주석 갱신 | 수정 |

### 구현·결정과 그 이유
- **인벤토리 패턴 그대로, 1회성 관찰**: 스캐너는 PC 수명과 함께 가므로 연결 성공 시 구독을 끊는 인벤토리형을 택했다(보스형 상시 구독은 불필요). 구독 해제는 소멸 시점에만 두어 재초기화 경로와 충돌하지 않게 했다.
- **Ready 발행은 로컬 게이트 위**: 데디 서버 PC 사본의 발행은 구독자가 없어 무해하고, 게이트 아래 두면 클라 도착 경로가 막힌다.
- **검증 결과**: 스탠드얼론에서 체크포인트 접근 시 VM 항목·선택 갱신 확인(기존 동일). Play As Client 에서 클라 PC 아래 VM 이 생성돼 있고(수정 전엔 스캐너 미도착 시 VM 자체가 없던 지점), 폰을 체크포인트 옆으로 옮기자 클라 VM 에 프롬프트 1건·선택 0 이 채워짐 — 복제 도착 → 관찰 연결 → 로컬 스캔 → 표시 흐름 전체 확인.
