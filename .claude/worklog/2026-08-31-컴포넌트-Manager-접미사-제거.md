# 컴포넌트 Manager 접미사 제거

## 계획

### 목표
컴포넌트 클래스 5종의 이름에서 `Manager`를 제거해 평범한 이름으로 정리한다. (FinisherDamage·ItemUse·Projectile·LockOn·Inventory)

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| 각 컴포넌트 .h/.cpp 10개 | 파일명·클래스명 개명 | 수정 |
| 참조 소스 전체 | 클래스명·멤버명·서브오브젝트명·주석 치환 | 수정 |
| `Config/DefaultEngine.ini` | LockOn·Inventory용 CoreRedirects 추가 | 수정 |
| `BP_Player`·`WAS_CoreGameplay` | 옛 이름 참조 리세이브 | 수정 |

### 접근 방식
- **순수 소스 리네임 + 리다이렉트**: 앞 3종은 에셋 참조가 전혀 없어 치환만으로 끝. LockOn·Inventory는 에셋 2개가 클래스 경로·멤버명을 저장하고 있어 ClassRedirects 2건·PropertyRedirects 1건을 걸고 ResavePackages로 구웠다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| 컴포넌트 .h/.cpp 10개 | `Wx{FinisherDamage,ItemUse,Projectile,LockOn,Inventory}Component`로 개명 | 수정 |
| 참조 소스·README 2건 | 이름 일괄 치환 | 수정 |
| `Config/DefaultEngine.ini` | CoreRedirects 3줄 추가(유지) | 수정 |
| `BP_Player`·`WAS_CoreGameplay` | 커맨들릿 리세이브로 새 클래스 경로 반영 | 수정 |

### 구현·결정과 그 이유
- **리다이렉트 유지**: WAS_CoreGameplay는 완전히 구워졌으나 BP_Player의 UserConstructionScript 변수 노드가 옛 멤버 이름 FName 하나를 여전히 직렬화에 보존한다. 헤드리스 컴파일·저장으로는 노드 재구성이 일어나지 않아 굽지 못했고, PropertyRedirects가 로드 시 해결하므로 ini에 남겨 두는 표준 방식을 택했다.

### 계획 대비 달라진 점
- 리다이렉트를 임시로 걸었다 제거하는 태그 리네임 절차와 달리, BP_Player 잔존 참조 때문에 리다이렉트를 유지한다.

### 후속 과제
- 에디터에서 BP_Player를 열어 노드 새로고침 후 저장하면 잔존 참조가 구워지며, 그때 CoreRedirects 3줄을 지워도 된다.
