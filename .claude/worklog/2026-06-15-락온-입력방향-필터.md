# 락온 타겟팅: 입력 방향 필터

## 계획

### 목표
이동 입력 방향으로 락온 후보를 좁히는 타겟팅 필터를 추가한다. 입력이 없으면(스틱 중립) 필터링하지 않음(전부 통과). 락온 프리셋에서 사용.

### 수정 범위
| 모듈 | 파일 | 내용 |
|---|---|---|
| `WxCombat` | `Targeting/WxTargetingFilterTask_InputDirection.h/.cpp` (신규) | 이동 입력 방향 기준 `MaxInputAngle` 초과 대상 제외. 입력 없으면 미제외 |

### 접근 방식
`_CameraDirection`과 형제. `ShouldFilterTarget`에서 소스 폰의 `GetLastMovementInputVector()`(수평 평탄화) → 0이면 false(필터 없음) → ToTarget(수평)과 Dot이 `cos(MaxInputAngle)` 미만이면 제외. 원점은 소스 폰. WxCombat.Build.cs·WxCore 무변경. 프리셋 추가는 사용자.

## 완료

### 수정한 파일
| 모듈 | 파일 | 수정 내용 |
|---|---|---|
| `WxCombat` | `Targeting/WxTargetingFilterTask_InputDirection.h/.cpp` (신규) | 이동 입력 방향 기준 `MaxInputAngle` 초과 대상 제외, 입력 없으면 미제외 |

### 구현·결정과 그 이유
- **입력 없음 → 미제외**: `GetLastMovementInputVector()`를 수평 평탄화 후 `IsNearlyZero`면 `false` 반환(요구사항). 스틱 중립 시 전체 후보 유지.
- **수평 평탄화 비교**: 이동 입력은 평면적이라 XY로 펴서 yaw 기준 방향 필터(카메라 필터의 3D 비교와 구분). 원점은 소스 폰(입력은 플레이어 기준 이동 방향).
- `_CameraDirection`과 동일 패턴(BasicFilterTemplate, true=제외) — 일관성.

### 계획 대비 달라진 점
- 계획대로.

### 후속 과제
- **사용자(에디터)**: 락온 `TargetingPreset`(.uasset) Tasks 에 `WxTargetingFilterTask_InputDirection` 추가 + `MaxInputAngle` 조정. (카메라/입력 필터를 함께 쓰면 카메라 후방 제외 + 미는 방향 우선이 결합됨.)
