# 상호작용 계약 액터 전용 방침

## 계획

### 목표
WxCore 리뷰 3번("IWxSavable 에 Find 대응물이 없어 WxSave 가 같은 해석 로직을 복제한다")은 `IWxSavable::Find` 추가를 제안했으나, 결정된 방향은 반대다 — `IWxInteractable` 은 앞으로 액터에만 구현한다. 그러면 `IWxInteractable::Find` 는 이관과 함께 사라지고 `FindSavable` 만 남으므로, 중복은 통합이 아니라 이관으로 해소된다. 이관은 별도 작업으로 미루고, 이번에는 방침을 코드에 못박아 신규 컴포넌트 구현을 막고 이 지적이 다시 올라오지 않게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/Source/WxCore/Public/WxInteractable.h` | 클래스 주석을 액터 구현으로 좁히고 신규 컴포넌트 구현 금지 명시, `Find` 는 이관 후 제거 예정임을 명시 | 수정 |
| `Plugins/WxSave/Source/WxSave/Public/WxSaveWorldSubsystem.h` | `FindSavable` 을 `IWxInteractable::Find` 와 통합하지 않는 근거 명시 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueComponent.h` | 컴포넌트가 상호작용 계약을 드는 것이 이관 대기 상태임을 명시 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Public/Gimmick/WxGimmickStateTreeComponent.h` | 상호작용 계약 갈래만 한시적임을 명시(IWxSavable 갈래는 유지) | 수정 |
| `Plugins/WxCore/README.md` | 존재하지 않는 `Find(UActorComponent*)` 오버로드 언급 정정 + 두 인터페이스의 갈래 차이 반영 | 수정 |

### 접근 방식
- **두 인터페이스의 규약이 갈린다**: `IWxInteractable` 은 액터 전용으로 수렴(컴포넌트 갈래 X), `IWxSavable` 은 기믹 상태 영속을 컴포넌트가 들기 때문에 두 갈래가 영구히 필요하다. 같아 보이는 해석 로직을 공용 헬퍼로 묶으면 곧 없어질 쪽에 맞춰 WxCore 에 층을 얹는 셈이라 묶지 않는다.
- **이번엔 주석만**: 코드 라인은 건드리지 않는다. 동작 변경 없음.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/Source/WxCore/Public/WxInteractable.h` | 클래스 주석을 "액터가 구현한다"로 좁히고 신규 컴포넌트 구현 금지·이관 대기 둘을 명시, `Find` 주석에 이관 후 제거 예정과 그때의 형태(`Cast` 한 줄)를 기록 | 수정 |
| `Plugins/WxSave/Source/WxSave/Public/WxSaveWorldSubsystem.h` | `FindSavable` 주석에 `IWxInteractable::Find` 와 묶지 않는 근거 추가 | 수정 |
| `Plugins/WxDialogue/Source/WxDialogue/Public/WxDialogueComponent.h` | 컴포넌트가 계약을 드는 갈래가 이관 대기임을 명시, 구현체 둘일 때의 모호함도 이관으로 해소된다고 정정 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Public/Gimmick/WxGimmickStateTreeComponent.h` | 세 책임 중 상호작용 계약만 이관 대상임을 명시(상태 영속·ST 구동은 유지) | 수정 |
| `Plugins/WxCore/README.md` | 존재하지 않는 `Find(UActorComponent*)` 오버로드를 실제 이름(`UWxSaveWorldSubsystem::FindSavable`)으로 정정하고 두 계약의 방향 분기를 추가 | 수정 |

### 구현·결정과 그 이유
- **통합이 아니라 이관으로 해소한다**: 리뷰는 `IWxSavable::Find` 추가를 제안했지만, 그러면 곧 사라질 `IWxInteractable::Find` 에 맞춰 공용 층을 얹는 셈이 된다. 액터 전용 이관이 끝나면 해석 로직 구현이 하나만 남아 중복이 자연히 사라지므로, 그 사실을 코드에 남기는 것이 이번 작업이다.
- **두 계약의 방향이 갈린다는 것이 핵심 근거**: `IWxInteractable` 은 액터 전용으로 수렴하고, `IWxSavable` 은 기믹 상태 영속을 컴포넌트가 들어 두 갈래가 영구히 필요하다. 같은 모양이라고 묶으면 이 차이가 지워진다.
- **주석만 바꾼다**: 지금 컴포넌트 조회를 빼면 대화(`AWxNpc` + `UWxDialogueComponent`)와 기믹(순수 BP 호스트 4종)의 상호작용이 즉시 끊긴다. 이관 전에는 `Find` 의 두 갈래를 그대로 둬야 한다.

### 후속 과제
- **이관 작업**: `AWxNpc` 가 `IWxInteractable` 을 구현해 `UWxDialogueComponent` 로 위임하고, WxWorld 에 C++ 기믹 액터를 신설해 `UWxGimmickStateTreeComponent` 로 위임한다. `BP_CheckPoint`·`BP_Door`·`BP_Elevator`·`BP_TreasureChest` 를 그 액터로 리페어런트해야 하며, "순수 BP 액터도 기믹" 설계가 바뀐다.
- 이관 완료 시 `IWxInteractable::Find` 제거, 호출부 4곳(`WxInteractionScannerComponent.cpp` ×2, `WxStateTreeTask_EnableInteraction.cpp`, `WxAbility_Interact.cpp`)을 `Cast<IWxInteractable>` 한 줄로 정리.
