# 퀘스트 스텝 폴백 좌표를 루트 파라미터로 노출

## 계획

### 목표

[[2026-08-24-인디케이터-폴백-좌표-자가복구]] 로 등록증이 대상 소멸 시 폴백 좌표로 내려앉게 만들었지만, 실제 퀘스트 에셋에는 그 좌표를 넣을 자리가 없었다. Mark Indicator 의 `Target` 은 스텝 에셋의 **루트 파라미터**로 노출돼 퀘스트가 링크 상태에서 오버라이드하는데, `TargetLocation` 은 파라미터가 아니라 태스크의 리터럴이라 퀘스트별로 지정할 통로 자체가 없었다. 좌표도 `Target` 과 같은 자리에 나란히 노출해 퀘스트가 지정하게 한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/Quest/Steps/ST_QuestStep_MoveToTarget` | 루트 파라미터 `TargetLocation`(Vector) 추가, Mark Indicator 의 같은 이름 프로퍼티에 바인딩 | 수정 |
| `Content/Quest/Steps/ST_QuestStep_InteractTarget` | 위와 동일 | 수정 |
| `Content/Quest/ST_Quest_Main1` | Step1·Step2 링크 상태에 대상 액터의 실제 좌표를 오버라이드로 기입 | 수정 |

### 접근 방식

- **`Target` 과 같은 층에 둔다**: 좌표는 대상과 한 몸이므로 노출 방식도 같아야 한다. 루트 파라미터로 올리면 퀘스트의 링크 상태 오버라이드 UI 에서 대상 바로 아래 줄에 뜬다.
- **좌표는 대상 액터의 실제 위치를 읽어 넣는다**: 에디터에 로드된 `LV_DevCombat` 에서 각 대상의 트랜스폼을 조회해 그 값을 그대로 쓴다.

### 구현·결정과 그 이유

- **문제가 "값이 비었다"가 아니라 "통로가 없다"였다**: 앞선 작업의 후속 과제는 에셋의 좌표가 0 이라는 데이터 공백으로 적혀 있었지만, 실제로는 퀘스트가 좌표를 지정할 수단이 아예 없었다. 태스크의 리터럴 좌표는 스텝 에셋 하나에 하나뿐이라 퀘스트마다 다른 대상을 가리킬 수 없다.
- **에디터 자동 기록 훅은 이 경로에 닿지 않는다**: 08-21 이 붙인 "UOL 을 지정하면 좌표를 자동 기록" 훅은 태스크 인스턴스 데이터를 직접 편집할 때만 불린다. 실제 저작은 루트 파라미터 오버라이드에서 이뤄지므로 이 훅은 퀘스트 에셋에서는 돌지 않는다 — 좌표는 지금도 사람이 넣는 값이다.
- **바인딩 경로는 표시명이 아니라 프로퍼티 원본 이름이다**: 조회 결과가 `Target Location` 처럼 띄어쓰기된 표시형으로 나와 그대로 기입했더니, 컴파일이 해석되지 않는 바인딩으로 보고 조용히 걷어냈다(추가 직후 조회에는 멀쩡히 보였다). 원본 이름으로 다시 걸어 컴파일·저장을 통과시켰다.

### 후속 과제
- **PIE 실동작 미검증**: 컴파일·저장·재조회까지만 확인했다. 대상이 스트리밍 아웃된 거리에서 마커가 이 좌표를 가리키는지는 남아 있다.
- **좌표 동기화는 여전히 수동**: 대상 액터를 레벨에서 옮기면 이 값은 낡는다. 대상과 좌표가 나란히 보이긴 하지만 함께 갱신해 주는 장치는 없다.
- **`ST_QuestStep_KillEnemies` 는 대상 무관**: Mark Indicator 를 쓰지 않아 손대지 않았다.
