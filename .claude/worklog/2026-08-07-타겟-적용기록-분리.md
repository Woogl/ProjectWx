# 타겟 적용 기록을 블랙보드에서 분리

## 계획

### 목표

`UWxAIPerceptionComponent::SetTargetActor` 의 조기 반환이 블랙보드 값을 기준으로 판단해, 타겟이 파괴돼 그 값이 스스로 비워지면 이후 해제 요청이 "이미 비어 있다" 로 걸러진다. 그 결과 포커스와 회전 모드가 strafe 에 고착돼 자력 복구되지 않는다. 비교 기준을 컴포넌트 자신의 적용 기록으로 옮겨 해소한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | 타겟 보관 필드를 오브젝트 키로 교체·개명, 두 역할을 주석에 명시, 해당 헤더 명시 include | 수정 |
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | 조기 반환 기준을 블랙보드 값에서 적용 기록으로 교체, 구독 해제의 액터 조회 방식 변경 | 수정 |

### 접근 방식

- **원인은 기준 혼동**: "블랙보드에 뭐가 들어 있나" 와 "내가 무엇을 적용해 뒀나" 를 같은 것으로 취급했다. 앞의 것은 약참조라 외부 사정으로 조용히 바뀌고, 뒤의 것은 이 컴포넌트만 안다. 적용 기록을 직접 들고 그것과 비교한다.
- **타입은 오브젝트 키**: 리뷰가 제안한 약참조로는 고쳐지지 않는다. 약참조 비교는 양쪽이 모두 null 을 돌려줄 상황이면 같은 것으로 치도록 엔진이 정의해 놓아서, 대상이 파괴되면 블랙보드와 똑같이 무너진다. 오브젝트 키는 유효성 개념 없이 식별자만 비교하므로 대상이 사라져도 "예전에 그걸 적용해 뒀다" 는 사실이 남는다. 베이스 퍼셉션 컴포넌트도 같은 이유로 감지 데이터를 이 키로 다룬다.
- **필드는 새로 만들지 않고 승격**: 직전 작업에서 넣은 소실 구독 대상 필드가 이미 현재 타겟을 가리키므로, 타입만 바꾸고 이름을 적용 기록에 맞춰 가드 비교와 구독 해제를 한 필드로 처리한다. 기록 갱신 지점은 지금처럼 구독 교체 안에 두고, 가드는 그보다 앞서 읽는다.

### 구현·결정과 그 이유
- **기준을 컴포넌트 안으로**: 블랙보드는 외부 사정으로 값이 조용히 바뀌는 저장소라 "내가 무엇을 적용해 뒀나" 의 근거가 될 수 없다. 적용 기록을 직접 들어야 해제 요청이 항상 파생 상태 원복까지 도달한다.
- **약참조가 아니라 오브젝트 키**: 리뷰 제안대로 약참조 필드를 뒀다면 버그가 그대로 남는다. 엔진이 약참조 비교를 "양쪽이 모두 null 을 돌려줄 상황이면 같다" 로 정의해 놔서, 대상이 파괴되면 블랙보드와 똑같이 무너진다. 오브젝트 키는 유효성 개념이 없어 식별자만 비교한다. 베이스 퍼셉션 컴포넌트도 같은 이유로 감지 데이터를 이 키로 다룬다.
- **필드 신설 대신 승격**: 소실 구독 대상과 적용 기록은 언제나 같은 액터다. 둘로 나누면 어긋날 여지만 생기므로 한 필드가 겸하게 했다.
