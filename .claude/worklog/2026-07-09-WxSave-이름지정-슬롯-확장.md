# WxSave 이름 지정 세이브 슬롯 확장

## 계획

### 목표
플레이어가 임의의 슬롯 이름으로 저장/로드/삭제할 수 있도록 WxSave C++ API를 확장한다. 현재 `SaveToFile()`은 무인자라 활성 슬롯(개발 기본 `"Test"`)에만 기록되는데, 저장 시 슬롯 이름을 지정하는 경로를 열고 존재확인·삭제 API를 추가한다. 슬롯 열거·메타데이터는 범위 밖. UI(WBP) 배선은 API 제공 후 사용자가 처리한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxSave/.../Public/WxPersistenceGameSubsystem.h` (+`.cpp`) | `SaveToFile`에 `(SlotName="", UserIndex=0)` 인자 추가(비면 활성 슬롯 유지, 지정 시 활성 슬롯 재지정 후 저장). `DoesSaveFileExist`/`DeleteSaveFile` 신설 | 수정 |
| `Plugins/WxSave/.../Public/WxSaveFilePersistenceUtils.h` (+`.cpp`) | BFL 래퍼: `SaveToFile`에 SlotName/UserIndex 인자 추가, `DoesSaveFileExist`/`DeleteSaveFile` 신설(`BlueprintCallable`) | 수정 |
| `Plugins/WxSave/README.md` | 담당 문구·BFL 목록·모델 설명을 "이름 지정 저장/로드/삭제"로 갱신 | 수정 |

### 접근 방식
- **활성 슬롯 모델 유지**: 슬롯 정체성은 계속 `UWxPersistenceSaveGame`이 소유. "이름 지정 저장"은 활성 슬롯을 그 이름으로 재지정 후 저장하는 의미론 — 이후 체크포인트 오토세이브도 그 슬롯을 이어감(콘솔 게임 표준).
- **하위 호환**: 신규 인자 전부 기본값(빈 슬롯/0). 기존 무인자 호출(`WxCheckPoint` 오토세이브, `WBP_DeathScreen` 로드)은 동작 불변. 재지정은 `SlotName`이 비어있지 않을 때만.
- **재지정 안전성**: 저장 플러시 경로(`FlushMapTravelData` 등)는 슬롯 정체성을 건드리지 않으므로, 널가드 직후 `SaveGame->SlotName`을 갈아끼워도 안전하다.
- **최소 신설**: 열거/메타데이터/새 클래스 없음. 엔진 표준 `UGameplayStatics::DoesSaveGameExist`/`DeleteGameInSlot`을 얇게 래핑. `DeleteSaveFile`은 디스크 파일만 삭제(인메모리 활성 SaveGame 불변).

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxSave/.../Public/WxPersistenceGameSubsystem.h` (+`.cpp`) | `SaveToFile(SlotName="", UserIndex=0)` 로 확장(지정 시 활성 슬롯 재지정). `DoesSaveFileExist`/`DeleteSaveFile` 신설 | 수정 |
| `Plugins/WxSave/.../Public/WxSaveFilePersistenceUtils.h` (+`.cpp`) | BFL `SaveToFile` 에 SlotName/UserIndex 인자 추가, `DoesSaveFileExist`/`DeleteSaveFile` 래퍼 신설 | 수정 |
| `Plugins/WxSave/README.md` | 담당 문구·BFL 래퍼 목록·확장 포인트에 "이름 지정 저장/로드/삭제·존재확인" 반영, DefaultSlotName 을 폴백으로 재서술 | 수정 |

### 구현·결정과 그 이유
- **활성 슬롯 재지정 의미론**: 슬롯 정체성은 계속 `UWxPersistenceSaveGame` 이 소유한다. `SaveToFile` 에 슬롯 이름을 넘기면 저장 직전 활성 SaveGame 의 SlotName/UserIndex 를 갈아끼워, 이후 체크포인트 오토세이브도 그 슬롯을 이어가게 했다(콘솔 게임에서 "현재 세이브 = 내가 저장한 슬롯" 이 자연스럽다). 파일 복사가 아니라 활성 슬롯 전환이라 인메모리 상태가 분기하지 않는다.
- **널가드 직후 재지정**: 저장 플러시(FlushMapTravelData 등)와 디스크 기록(`SaveGame->SlotName` 사용) 사이 어디서 재지정해도 안전하나, 널가드 직후로 앞당겨 이후 경로 전체가 새 슬롯을 보게 했다.
- **하위 호환은 빈 문자열 게이트**: 신규 인자 기본값이 빈 슬롯이라, 무인자 `SaveToFile()`(WxCheckPoint 오토세이브)·BP 미배선 노드는 동작 불변. 재지정은 `!SlotName.IsEmpty()` 일 때만.
- **삭제는 순수 디스크 연산**: `DeleteSaveFile` 은 `DeleteGameInSlot` 만 호출하고 인메모리 활성 SaveGame 은 안 건드린다. 메뉴(비플레이) 맥락 전용이라 단순함을 택했고, 활성 슬롯을 지웠다면 다음 저장이 재생성한다는 점을 주석·README 에 명시.
- **열거/메타데이터 제외**: 현재 UI 가 타이핑 입력창이라 슬롯 목록이 불필요. 엔진에 슬롯 열거 API 가 없어 디렉터리 스캔이 필요한데 ROI 가 낮아 범위에서 뺐다.

### 계획 대비 달라진 점
- **`GetDefaultSlotName` 무관**: 작업 도중 사용자가 BFL `GetDefaultSlotName` 을 헤더·cpp 양쪽에서 제거하고 "쓰지 말라"고 지시. 본 변경은 이 함수를 호출/참조하지 않아 영향 없음. README 의 DefaultSlotName 설명에서 "UI 공유" 문구만 폴백 표현으로 정리.

### 후속 과제
- **UI(WBP) 배선(사용자 몫)**: `WBP_MainMenu` 의 `EditableText_302` → Save/Load/Delete 노드 `SlotName` 핀 연결, `[Load Game]`→`LoadFromFile`, `[Delete Saved Data]`→`DeleteSaveFile`. 필요 시 Save 전 `DoesSaveFileExist` 로 덮어쓰기 확인. `WBP_DeathScreen` 은 무명 로드 유지.
- **런타임 검증 미수행**: 컴파일만 확인. 배선 후 이름 A 저장→`Saved/SaveGames/A.sav` 생성·로드·삭제, `Wx.Save.Dump` 로 활성 슬롯 확인 필요.
