# BaseWalkSpeed 캐시 멤버 제거 — 기준 속도를 클래스 기본값에서 파생

## 계획

### 목표
`AWxCharacterBase::BaseWalkSpeed`가 초기화자 없이 선언돼 있다는 모듈 리뷰 지적(WxGame 5번)을 해결한다. 표면적 문제는 초기화자지만 실제 위험은 "구독보다 대입이 먼저"라는 암묵 계약에만 안전성이 걸려 있다는 점이므로, 캐시 멤버 자체를 없애고 기준 속도를 클래스 기본값에서 파생한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.h` | `BaseWalkSpeed` 멤버 선언과 주석 삭제 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.cpp` | `InitAbilitySystem`·`HandleSPDAttributeChanged`가 CDO에서 기준 속도를 읽도록 변경 | 수정 |

### 접근 방식
- **기준 속도를 CDO에서 파생**: `GetDefault<AWxCharacterBase>(GetClass())->GetCharacterMovement()->MaxWalkSpeed`를 읽는다. CDO 값은 직렬화가 끝난 뒤라 파생 클래스 생성자와 BP 디테일 패널 값이 모두 반영돼 있고, 런타임에 SPD가 곱해지지 않아 언제 읽어도 같다.
- **리뷰 제안 두 가지를 모두 채택하지 않는 이유**: `= 0.f`는 "0이 되는 실패"를 정상값으로 굳힌다. 생성자 초기화는 직렬화 전에 돌아 파생 클래스가 지정한 500·400 대신 엔진 기본값 600을 잡는다.
- **1회 적용을 가드 밖으로**: 기준값이 인스턴스 상태가 아니게 되면서 재빙의로 다시 들어와도 배율이 누적되지 않는다. 구독 가드는 델리게이트 중복 바인딩 방지라는 본래 역할만 남는다.

### 구현·결정과 그 이유
- **캐시 멤버를 지우는 쪽을 골랐다**: 초기화자를 붙이는 것은 증상만 가리고, 리뷰가 걱정한 "조용히 0이 되는" 상태를 오히려 정상값으로 만든다. 기준 속도는 이미 클래스 기본값에 있는 값이므로 사본을 들고 있을 이유가 없고, 사본을 없애면 "언제 채우느냐"라는 순서 문제 자체가 성립하지 않는다.
- **생성자 초기화는 틀린 답이다**: 생성자는 직렬화 전에 돌아 파생 클래스가 지정한 500·400이 아직 반영되지 않은 시점이다. 항상 엔진 기본값 600을 잡게 된다.
- **1회 적용을 가드 밖으로 내보냈다**: 기준값이 인스턴스 상태가 아니게 되면서 재빙의로 다시 들어와도 배율이 누적되지 않는다. 가드는 델리게이트 중복 바인딩 방지라는 본래 역할만 남았고, "재진입 시 배율 누적" 주석도 함께 사라졌다.
- **작은 헬퍼를 만들지 않았다**: CDO 조회 표현식이 두 곳에 반복되지만 프로젝트 관례대로 풀어쓰고 각각 로컬 상수로 받았다.

### 후속 과제
- WxEditor(Development) 빌드로 컴파일까지 확인했다. 에셋에 `MaxWalkSpeed` 오버라이드가 하나도 없음을 확인했으므로 값이 달라지는 경로는 없지만, PIE에서 SPD 버프·디버프와 재빙의 후 속도를 눈으로 본 것은 아니다.
- 앞으로 레벨 인스턴스별로 걸음 속도를 다르게 주고 싶다면 `MaxWalkSpeed` 직접 오버라이드가 아니라 SPD 어트리뷰트를 써야 한다 — 기준값을 클래스 단위로 못 박았기 때문이다.
