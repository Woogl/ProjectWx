# 순간 토글 태스크(EnableInteraction/EnablePlayerInput) 완료 비구동 디폴트

## 계획

### 목표
순간 side-effect 토글 태스크(`Wx Enable Interaction`, `Wx Enable Player Input`)가 상태 완료를 구동하지 않도록 `bConsideredForCompletion` 디폴트를 false로 바꾼다. "순간 토글 태스크는 완료를 구동하지 않는다"를 프로젝트 컨벤션으로 못박아, 토글만 든 정지 leaf가 진입 즉시 완료→재선택 루프(엘리베이터 문 무한 개폐)를 디폴트에서 차단한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxGimmickStateTreeNodes.cpp` | `FWxStateTreeTask_EnableInteraction()`·`FWxStateTreeTask_EnablePlayerInput()` 생성자에 `#if WITH_EDITORONLY_DATA bConsideredForCompletion = false; #endif` + 의도 주석 | 수정 |
| `WxGimmickStateTreeNodes.h` | 두 태스크 struct doc에 "기본 완료 비구동(side-effect), 인스턴스별 override 가능" 1줄 | 수정(주석) |

### 접근 방식
- **디폴트만 끄고 override는 유지**: `bCanEditConsideredForCompletion`(기본 true)은 그대로 둬 인스턴스별로 다시 켤 수 있게 한다. mover/시퀀스가 완료를 구동하는 상태는 off여도 무영향, 토글만 든 정지 상태만 올바르게 머문다.
- **소급 효과 인지**: StateTree task instance는 디폴트 델타 직렬화라, 디폴트 변경이 기존 디폴트값 인스턴스에도 전파될 가능성이 크다(빌드 후 에디터 확인). 단독 완료 구동자였던 토글 상태(엘리베이터 standalone `Disable Interaction`)는 인접 mover 상태로 접어넣어야 — ST 에셋 작업(사용자).

### 구현·결정과 그 이유
- **순간 토글 태스크를 완료 비구동으로 디폴트화**: EnableInteraction/EnablePlayerInput은 플래그 한 번 토글하고 끝나는 side-effect라, 상태 완료를 구동할 의미가 없다. 디폴트 off면 토글만 든 정지 leaf가 즉시 완료→재선택 루프(엘리베이터 문 무한 개폐)에 디폴트에서부터 안 빠진다. 컨벤션: "순간 토글 태스크는 완료를 구동하지 않는다."
- **override 여지 유지**: `bCanEditConsideredForCompletion`(기본 true)은 건드리지 않아, 단독 완료 구동이 필요한 드문 상태는 인스턴스별로 다시 켤 수 있다. `WITH_EDITORONLY_DATA` 가드로 비에디터 빌드에서도 컴파일.
- **검증**: WxEditor(Development) 빌드 `Result: Succeeded`. 경고는 변경 무관한 엔진 C4996뿐.

### 후속 과제
- **ST 에셋 작업(사용자, 에디터)**: 빌드 후 두 태스크를 쓰는 ST(Door/Elevator/TreasureChest/SpawnConsole/AlarmConsole + 컷신·입력차단 ST)를 열어, 토글이 **단독 완료 구동자**인 상태가 있으면 인접 mover/시퀀스 상태로 접어넣거나 그 인스턴스만 완료 아이콘을 다시 켠다. 기존 인스턴스 완료 아이콘이 디폴트 전파로 off 됐는지 함께 확인.
- **엘리베이터(ST_Elevator)**: 각 leaf의 standalone `Disable Interaction` 상태를 삭제하고 `Wx Enable Interaction(false)`×3을 `Closing`에 합치기. 각 `Idle`의 전이를 `On State Completed → Root` → `On Tick + Enum Compare(Actor.State != 이 leaf 값) → Root`로 교체. PIE에서 문 1회 개폐(무한 루프 없음) 확인.
