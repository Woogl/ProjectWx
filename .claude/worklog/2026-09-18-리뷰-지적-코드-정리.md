# 코드 리뷰 지적 반영 — C++ 결함 정리

## 계획

### 목표
코드 리뷰가 낸 14건 중 **C++로 닫을 수 있는 것**만 고친다. 에셋 저작이 필요한 4건은 `unreal-mcp`가 막혀 있어 범위 밖이고, 팀 인터페이스 지적 1건은 성립하지 않는 것을 확인해 손대지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/.../Minion/WxMinionSubsystem.cpp` | CDO 상한 조회 실패 시 스폰 차단, `GetDefaultObject()` 널 가드, 파괴 2곳을 `GetMinionPawn()`으로, `RefreshMasterStateTag`·`FindActiveMinion`이 `CollectMinions` 재사용 | 수정 |
| `WxCombat/.../Minion/WxMinionComponent.cpp` | `BeginPlay`의 `GetWorld()` 가드를 `EndPlay`와 대칭으로 | 수정 |
| `WxAI/.../WxBTService_UpdateTargetActor.cpp` | `CanBeAggroTarget`에서 `IsValid`를 ASC 조회보다 앞으로 | 수정 |
| `WxCombat/.../AnimNotify/WxAnimNotify_SpawnMinion.h` | `MustImplement` 메타 제거 | 수정 |

### 접근 방식
- **상한 계약이 없으면 소환하지 않는다**: CDO에서 `UWxMinionComponent`를 못 찾으면 `MaxCountPerMaster`가 0이 되고 같은 식이 0을 "무제한"으로 읽어 상한이 사라지며, `CanBeSummonedBy` 조건 검사도 통째로 건너뛴다. `IWxMinion` 시절의 결정(상한 계약이 없으면 로스터 관리가 서지 않는다)을 복원해 조기 반환한다. 그러면 뒤에서 `MinionDefaults`가 항상 유효해 삼항 폴백이 사라진다.
- **파괴는 `GetMinionPawn()`으로**: 약참조가 컴포넌트로 바뀌면서 `.Get()` 성공이 살아 있는 소유자를 뜻하지 않게 됐다. `CollectMinions`가 쓰는 접근자를 파괴 지점 두 곳에서도 쓴다.
- **소유 판정은 `CollectMinions` 한 곳에**: `RefreshMasterStateTag`가 그 루프 본문을 복제하고 태그 비교만 더했다. `CollectMinions(Master)`를 돌며 태그를 보는 형태로 바꾸고, `FindActiveMinion`의 널 검사 사슬도 접는다.
- **`MustImplement` 제거**: `SpawnMinion`이 `IWxSpawnable::OnSpawnedBy`를 부르지 않아 요구할 근거가 없다. 계약을 지키려 호출을 새로 넣지 않는다 — 소환물은 `Instigator`로 이미 주인을 알고 `AWxEnemyCharacter::OnSpawnedBy`는 `Cast<AWxSpawner>` 실패로 아무 일도 하지 않는다. 실제 요구인 "CDO에 MinionComponent"는 런타임 게이트가 강제하고, 픽커에서 사라진 안내는 프로퍼티 주석으로 남긴다.

| `WxCombat/.../Minion/WxMinionComponent.cpp` | `BeginPlay`의 월드 조회를 `EndPlay`와 같은 가드 형태로 | 수정 |

| `WxCombat/.../AnimNotify/WxAnimNotify_SpawnMinion.h` | `MustImplement` 메타 제거, 실제 요구 조건을 주석으로 | 수정 |

### 구현·결정과 그 이유
- **계약 부재를 경고가 아니라 차단으로**: CDO에 `MinionComponent`가 없으면 `MaxCountPerMaster`가 0이 되는데 같은 식이 0을 "무제한"으로 읽어 상한이 통째로 사라지고, `CanBeSummonedBy` 조건 검사도 건너뛰어진다. 로그는 "추적하지 않는다"고 하지만 인스턴스는 `BeginPlay`에서 정상 등록되므로 사실과도 달랐다. 조기 반환으로 되돌리니 뒤쪽의 삼항 폴백 두 개가 함께 사라져 계산이 단순해졌다. SCS로 붙인 컴포넌트는 CDO에 없으므로 이 게이트는 "네이티브 부착이어야 한다"는 요구를 그대로 강제한다.
- **파괴는 `GetMinionPawn()`으로**: 로스터가 폰이 아니라 컴포넌트를 담게 되면서 `.Get()` 성공이 살아 있는 소유자를 뜻하지 않게 됐다. `CollectMinions`가 후보를 고를 때 쓰는 접근자를 파괴 지점에서도 써서 판정 통로를 하나로 맞췄다.
- **주인 판정을 한 벌로**: `RefreshMasterStateTag`가 `CollectMinions`의 루프 본문을 복제하고 태그 비교만 더하고 있었다. 주인 판정 방식이 바뀌면 한쪽만 고쳐져 로스터와 주인 태그가 어긋난다.
- **`MustImplement`는 호출을 추가하지 않고 제거**: `SpawnMinion`은 `IWxSpawnable::OnSpawnedBy`를 부르지 않아 이 계약을 요구할 근거가 없었다. 계약을 지키려 호출을 넣는 쪽은 택하지 않았다 — 소환물은 `Instigator`로 이미 주인을 알고, `AWxEnemyCharacter::OnSpawnedBy`는 `Cast<AWxSpawner>`가 실패해 아무 일도 하지 않는다. 인터페이스 요구를 정당화하려고 빈 통로를 하나 더 만드는 셈이 된다.
- **리뷰 지적 1건은 반영하지 않았다**: "팀 `Cast`가 BP 구현 인터페이스를 놓친다"는 지적은 `UGenericTeamAgentInterface`가 `UINTERFACE(MinimalAPI)`에 `UFUNCTION`이 하나도 없어 BP가 구현할 수 없는 인터페이스라 성립하지 않는다.

### 후속 과제
- 에셋 저작이 필요한 리뷰 지적 4건은 그대로 남아 있다 — `BP_Minion`·`BP_Doppelganger`의 `IWxMinion` 잔존 참조 제거와 값 이전, `WxEffect_AggroIgnored`의 AbilitySet 등록, `State.Minion.Active`를 든 어빌리티 4개의 태그 재선택, `MasterTagRequirements` 저작. `unreal-mcp`가 ConnectionRefused라 이번에도 손대지 못했다.
- 특히 `BP_Minion`·`BP_Doppelganger`가 깨진 상태에서는 이번에 넣은 스폰 차단 게이트가 "소환이 아예 안 되는" 증상으로 드러날 수 있다. BP 정리가 선행되어야 한다.
