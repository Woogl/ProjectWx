# DP base 클램프 누락 수정

## 계획

### 목표
DP만 base 값 상한 클램프가 없어 MaxDP를 넘어 쌓이고, 그 초과분 때문에 그로기 드레인이 DP를 0까지 내리지 못해 그로기가 매번 안전 타이머 폴백으로 끝난다. 두 유입 경로를 각각 막아 그로기가 설계대로 DP 소진으로 끝나게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Attribute/WxCombatAttributeSet.cpp` | `PostGameplayEffectExecute`에 HP·MP·SP·UP와 같은 형태의 DP 분기 추가 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Effect/WxEffect_Damage.cpp` | `ReflectPerfectGuard`가 가산 결과를 MaxDP로 잘라 기록, 사실과 어긋난 주석 정정 | 수정 |
| `Docs/Programmer/module_review_WxCombat.md` | 2번 항목을 조치 완료로 갱신 | 수정 |

### 접근 방식
- **훅이 잡는 경로**: GE 모디파이어의 base 쓰기는 `ApplyModToAttribute` → `SetAttributeBaseValue`를 지나 `PostGameplayEffectExecute`까지 오므로, 다른 vital과 같은 되밀기 한 줄이면 대미지 ExecCalc의 DP 가산이 범위 안에 남는다.
- **훅 밖 경로**: 퍼펙트 가드 반사는 ExecCalc에서 `SetNumericAttributeBase`를 직접 부르므로 그 되밀기를 지나지 않는다. 기록 전에 잘라야 한다.
- **클램프를 base 훅으로 모으는 안은 채택하지 않는다**: 두 훅이 공유할 함수를 만들게 되므로, 파일이 이미 쓰는 형태를 그대로 따른다.

## 완료

### 수정한 파일

| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Effect/WxEffect_Damage.cpp` | `ReflectPerfectGuard`가 가산 결과를 MaxDP로 자른 뒤 기록, 그로기 중인 공격자에겐 반사 생략, 상한을 훅이 맡는다던 주석 정정 | 수정 |
| `Docs/Programmer/module_review_WxCombat.md` | 2번 항목을 조치 완료로 갱신 | 수정 |

### 구현·결정과 그 이유
- **경로마다 막는다**: DP가 base 범위를 벗어나는 통로가 두 개다. GE 모디파이어는 `PostGameplayEffectExecute`까지 오므로 다른 vital과 같은 되밀기 한 줄로 충분하지만, 퍼펙트 가드 반사는 ExecCalc에서 어트리뷰트를 직접 써 그 훅을 지나지 않는다. 한쪽만 막으면 반사로 들어간 그로기만 여전히 안전 타이머로 끝난다.
- **상한 클램프를 base 훅으로 모으지 않음**: 두 훅(`PreAttributeChange`·`PreAttributeBaseChange`)이 공유할 함수를 새로 만들게 되어 채택하지 않았다. 파일이 이미 쓰는 형태를 그대로 따르는 편이 읽는 비용이 낮다.
- **주석을 원인으로 취급**: `ReflectPerfectGuard`에 "상한 클램프는 어트리뷰트 셋의 변경 훅이 맡는다"고 적혀 있었는데, 훅이 자르는 건 CurrentValue뿐이라 사실이 아니었다. 이 서술이 있는 한 같은 실수가 반복되므로, 왜 여기서 직접 잘라야 하는지로 바꿨다.
- **MaxDP 0은 상한 없음**: DP를 쓰지 않는 아바타라는 뜻이라, `PreAttributeChange`·`PostAttributeChange`가 이미 쓰는 `Max > 0` 게이트를 반사 경로에도 그대로 적용했다.
- **그로기 중인 공격자에겐 반사하지 않음**: 대상의 DP 가산에는 `!bIsGroggy` 게이트가 있는데 반사 경로엔 공격자 쪽 게이트가 없었다. 클램프를 걸기 전엔 base가 어차피 넘쳐 있어 드러나지 않았지만, 클램프 이후로는 "반사 = DP를 MaxDP로 되돌림"이 정확히 성립해 그 케이스만 다시 안전 타이머로 끝난다. 그로기 중인 공격자가 쏜 투사체가 뒤늦게 퍼펙트 가드에 걸리는 경로가 실재해 대상 쪽 게이트와 대칭을 맞췄다. 반사만 생략하고 퍼펙트 가드 연출·패링 이벤트는 그대로 나간다.
- **안전 타이머 유지**: 이제 DP 소진으로 끝나는 정상 경로가 돌아왔으므로, 헤더가 원래 적어 둔 대로 실패복구 폴백으로 남겼다.

### 계획 대비 달라진 점
- 그로기 중인 공격자에게 반사가 들어가는 경로를 추가로 막았다. 클램프를 넣고 나서야 같은 증상(그로기가 안전 타이머로 끝남)의 남은 경로로 드러난 건이라 같은 작업으로 묶었다.

### 후속 과제
- WxEditor(Development) 빌드 통과까지 확인했다. 그로기가 몽타주 종료와 함께 끝나는지, DP 게이지가 그로기 내내 만렙에 붙어 있지 않은지, 퍼펙트 가드 반사로 들어간 그로기도 같은지는 다음 PIE 세션에서 눈으로 확인한다.
