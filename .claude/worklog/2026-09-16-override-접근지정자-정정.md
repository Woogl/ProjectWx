# override 접근 지정자 정정

## 계획

### 목표
override는 직접 베이스의 접근 지정자를 따른다는 규칙에 어긋난 두 곳을 되돌린다(WxGame 모듈 리뷰 2번). 엔진만 부르는 함수라 동작은 바뀌지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.h` | `CanJumpInternal_Implementation` 선언을 protected 절 첫머리로 이동 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.cpp` | 같은 함수 정의를 헤더 순서에 맞춰 공개 함수 뒤로 이동 | 수정 |
| `Source/WxGame/Character/Component/WxMetaHumanComponent.h` | `OnRegister`·`OnUnregister` 선언을 public 절로 이동, Begin/End 주석의 베이스명 정정 | 수정 |

### 접근 방식
- **기준은 직접 베이스**: `ACharacter`는 `CanJumpInternal_Implementation`을 protected로 둔다(`Character.h:873`). `UMetaHumanComponentUE`는 `OnRegister`·`OnUnregister`를 public으로 다시 선언한다(`MetaHumanComponentUE.h:17-20`) — `UActorComponent` 기준으로 적힌 주석이 기준 베이스를 한 단계 잘못 가리키고 있었다.
- **정의 순서 동기화**: 선언이 옮겨간 절에 맞춰 cpp 정의도 옮긴다. 메타휴먼 컴포넌트는 이미 그 순서라 손대지 않는다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.h` | `CanJumpInternal_Implementation` 선언을 protected 절 첫머리로 이동 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.cpp` | 같은 함수 정의를 `IsAlive` 뒤, `InitAbilitySystem` 앞으로 이동(본문 변경 없음) | 수정 |
| `Source/WxGame/Character/Component/WxMetaHumanComponent.h` | `OnRegister`·`OnUnregister` 선언을 public 절 `SetLeaderMesh` 뒤로 이동, Begin/End 주석을 `UMetaHumanComponentUE`로 정정 | 수정 |

### 구현·결정과 그 이유
- **`OnJumped_Implementation`은 그대로 뒀다**: 같은 줄에 붙어 있었지만 `ACharacter`에서 public이라 규칙에 맞다. 접근 지정자가 어긋난 것만 옮긴다.
- **메타휴먼 주석의 베이스명까지 고쳤다**: 선언을 옮기는 것만으로는 다음 사람이 다시 `UActorComponent` 기준으로 판단해 되돌릴 수 있다. 기준 베이스가 한 단계 위였다는 것이 규칙 위반의 원인이었다.
- **검증**: UE 5.8.1 WxEditor Win64 Development 빌드 성공. 접근을 좁힌 쪽에서 컴파일 에러가 나지 않아, 못 찾은 외부 호출부가 없음도 함께 확인됐다.
