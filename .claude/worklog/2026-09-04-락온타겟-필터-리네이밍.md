# SelectedTarget 필터 리네이밍 + bSkipIfEmpty 옵션

## 계획

### 목표

`UWxTargetingFilterTask_SelectedTarget` 은 AI Blackboard 분기가 빠지면서 이제 락온 대상만 본다. 이름을 `UWxTargetingFilterTask_LockOnTarget` 으로 바꾸고, "겨누는 대상이 없을 때" 의 동작을 `bSkipIfEmpty`(기본 true)로 저작 가능하게 만든다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../Public/Targeting/WxTargetingFilterTask_LockOnTarget.h` | `WxTargetingFilterTask_SelectedTarget.h` 에서 이름 변경, `bSkipIfEmpty` 추가 | 수정(리네이밍) |
| `Plugins/WxCombat/.../Private/Targeting/WxTargetingFilterTask_LockOnTarget.cpp` | 위와 같은 리네이밍, 대상 없음 경로를 `bSkipIfEmpty` 로 가름 | 수정(리네이밍) |
| `Config/DefaultEngine.ini` | 기존 `[CoreRedirects]` 에 클래스 리다이렉트 추가 | 수정 |

### 접근 방식

- **리네이밍**: `git mv` 로 파일을 옮기고 클래스명·include·`.generated.h`·주석을 맞춘다. 필터 태스크는 `UTargetingPreset` 안의 인스턴스드 서브오브젝트라, `ClassRedirects` 가 없으면 `TP_Attack_250/1000/10000`·`TP_Guard` 가 조용히 필터를 잃는다. 기존 `WxBossCharacter` 항목과 같은 형식으로 넣고, 프리셋을 재저장하면 지워도 된다는 주석을 단다.
- **bSkipIfEmpty**: 엔진 `UTargetingFilterTask_BasicFilterTemplate::Execute` 가 `ShouldFilterTarget` 의 true 를 "이 결과를 뺀다" 로 읽으므로, 대상이 없을 때 `!bSkipIfEmpty` 를 돌려주면 true = 아무것도 안 거름(현재 동작), false = 전부 거름이 된다. 기본값이 현재 동작이라 기존 프리셋 4종은 그대로다.
- `ResolveSelectedTarget` 이 널 소스에 안전하므로 `!SourceActor` 조기 반환을 없애고 "대상 없음" 한 경로로 합친다.

## 완료

### 수정한 파일

| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/.../Public/Targeting/WxTargetingFilterTask_LockOnTarget.h` | `git mv` 로 리네이밍, 클래스명·주석 정리, `bSkipIfEmpty` 추가 | 수정(리네이밍) |
| `Plugins/WxCombat/.../Private/Targeting/WxTargetingFilterTask_LockOnTarget.cpp` | 같은 리네이밍, 대상 없음 경로를 `bSkipIfEmpty` 로 가름 | 수정(리네이밍) |
| `Config/DefaultEngine.ini` | `[CoreRedirects]` 에 클래스 리다이렉트 1건 추가 | 수정 |
| `Plugins/WxCombat/.../Targeting/WxLockOnComponent.h/.cpp` | `ResolveSelectedTarget` → `ResolveLockOnTargetActor`, `GetLockOnTarget` 에 파괴 대상 가드, 중복 전방 선언 제거 | 수정 |

### 구현·결정과 그 이유

- **리다이렉트를 반드시 함께 넣는다**: 필터 태스크는 `UTargetingPreset` 안의 인스턴스드 서브오브젝트라, 클래스명이 바뀌면 참조가 조용히 끊겨 프리셋이 필터를 잃는다. 로드 에러도 나지 않아 눈치채기 어렵다.
- **`bSkipIfEmpty` 기본 true**: 기존 동작이 "대상이 없으면 아무것도 거르지 않는다" 였으므로 기본값이 곧 현행 유지다. 프리셋 4종은 재저장 없이 그대로 돈다.
- **널 소스와 대상 없음을 한 경로로**: `ResolveSelectedTarget` 이 널 소스에 안전해 `!SourceActor` 조기 반환을 따로 둘 이유가 없었다. 컨텍스트가 없는 요청도 `bSkipIfEmpty` 가 정한 답을 받는다.

### 코드 리뷰 반영

- **파괴된 대상이 GC 전까지 살아 돌아오는 창**: `LockOnTarget` 은 하드 참조라 대상이 파괴돼도 다음 도달성 검사까지 널이 되지 않는다. 서버는 퍼셉션의 EndPlay 경로가 즉시 비우지만 그 경로가 없는 클라는 복제된 널이 올 때까지 죽은 컴포넌트를 읽는다. 리뷰는 새 헬퍼에 가드를 제안했으나 읽기 경로가 여럿(투사체·카메라 태스크·락온 어빌리티)이라 `GetLockOnTarget()` 한 곳에서 끊었다. 이후 약참조 전환으로 이 가드를 없애 보려 했으나 되돌렸다 — [2026-09-04-락온대상-약참조-전환.md](2026-09-04-락온대상-약참조-전환.md) 참조.
- **주석 정확화**: "전 머신이 같은 결과" 는 복제가 닿기 전 창을 빼고 한 말이라 그 예외를 적었고, `bSkipIfEmpty` 를 끄면 스냅 워프의 회전 폴백까지 사라진다는 결합을 프로퍼티 주석에 남겼다.
- **중복 전방 선언 제거**: `Components/ActorComponent.h` 가 이미 `AActor` 를 선언한다. 이웃 `WxLockOnPointComponent.h` 도 같은 이유로 두지 않는다.

리뷰의 나머지 지적은 받지 않았다. 헬퍼 미이관 3곳은 둘이 컴포넌트를 필요로 하고 하나는 이미 컴포넌트를 쥐고 있어 오히려 재스캔이 되며, 널 가드는 베이스 클래스가 명시한 "서브오브젝트는 수명 내내 널이 아니다" 불변식과 어긋난다. 후보마다 도는 `FindComponentByClass` 는 `Execute` 를 오버라이드해 엔진 디버그 훅까지 재구현할 값이 아니다.

### 계획 대비 달라진 점

계획에서는 `ResolveSelectedTarget` 을 그대로 두려 했으나, 요청을 받아 `ResolveLockOnTargetActor` 로 함께 맞췄다. `UWxLockOnPointComponent::ResolveLockOnTarget` 이 이미 같은 계열 이름이라 그대로 쓰면 두 클래스에 같은 이름이 다른 의미로 남으므로, 반환 타입을 이름에 드러내 "지점" 과 "액터" 를 가르는 짝으로 만들었다.

### 후속 과제

- **`bSkipIfEmpty` 이름**: 리뷰가 "Skip If 무엇을 / Empty 무엇이" 가 모호하고 안전한 값이 true 라 체크를 푸는 순간 파괴적인 모드가 된다며 `bRequireLockOnTarget`(기본 false)을 제안했다. 지정받은 이름이라 그대로 뒀다.
- **에디터에서 리다이렉트 확인 미완**: 컴파일까지 확인했다. `TP_Attack_250/1000/10000`·`TP_Guard` 를 열어 필터가 새 이름으로 살아 있는지 보고, 재저장하면 `DefaultEngine.ini` 의 리다이렉트 항목을 지울 수 있다.
