# WxUI 탭 UI 프레임워크 제거

## 계획

### 목표
7월에 Lyra에서 이식한 CommonUI 탭 UI 프레임워크가 실사용에 한 번도 연결되지 않은 채 고립돼 있다. 메뉴는 탭 없는 `WBP_MainMenu` 계열로 굳었으므로 코드와 고아 에셋을 함께 걷어낸다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_NewMenu.uasset` · `WBP_TabList.uasset` · `WBP_TabButton.uasset` | 참조처 없는 고아 사슬 제거 | 삭제 |
| `Plugins/WxUI/Source/WxUI/Public/Widget/WxTabListWidgetBase.h` · `Private/Widget/WxTabListWidgetBase.cpp` | `UWxTabListWidgetBase`·`FWxTabDescriptor`·`IWxTabButtonInterface` 제거 | 삭제 |
| `Plugins/WxUI/Source/WxUI/Public/Widget/WxTabButtonBase.h` · `Private/Widget/WxTabButtonBase.cpp` | `UWxTabButtonBase` 제거 | 삭제 |
| `Plugins/WxUI/Source/WxUI/Public/Widget/WxButtonBase.h` · `Private/Widget/WxButtonBase.cpp` | 호출자가 없어지는 `SetButtonText` 제거 | 수정 |
| `Plugins/WxUI/README.md` | 위젯 베이스 나열에서 탭 제외 | 수정 |
| `Docs/Programmer/module_review_WxUI.md` | 사라진 코드에 대한 지적 정리 | 수정 |

### 접근 방식
- **고립 확인**: `WBP_NewMenu` → `WBP_TabList` → `WBP_TabButton` 사슬만 탭 클래스를 상속하고, 사슬 머리를 참조하는 에셋·ini·코드가 없다. 실사용 경로는 `WBP_GameHUD` → `WBP_MainMenu`로 탭을 거치지 않는다.
- **삭제 순서**: 에셋을 먼저 지운다. 네이티브 부모만 사라지고 BP가 남는 상태를 만들지 않기 위해서다. 참조처가 없으므로 리다이렉터는 필요 없다.

### 구현·결정과 그 이유
- **에셋을 먼저 지웠다**: 네이티브 부모만 사라진 BP는 다음 에디터 기동에서 로드 실패로 남는다. 참조하는 쪽이 없어 리다이렉터도 필요 없으니 파일째 지우는 편이 깔끔하다.
- **`SetButtonText`도 함께 걷었다**: 유일한 호출자가 탭 버튼이었다. 남겨 두면 호출자 없는 선언이 되고, 버튼 텍스트 자체는 에디터에서 지정하는 `ButtonText`와 갱신 경로로 그대로 돌아간다.
- **`WxUI.Build.cs`는 손대지 않았다**: CommonUI·Slate 의존은 남은 위젯들이 계속 쓴다.
- **리뷰 문서의 지적을 지웠다**: 두 항목 모두 사라진 코드만 겨냥한 것이라 남기면 존재하지 않는 파일을 가리킨다.

### 계획 대비 달라진 점
- 계획대로. 리뷰 문서에서 발견 본문 외에 "확인만 하고 문제를 못 찾은 지점"과 "미검토/한계"에도 탭 언급이 남아 있어 함께 정리했다.

### 후속 과제
- 지운 세 에셋이 고아라는 근거는 저장소 전체 `.uasset` 이진 검색(참조 0건)이다. 다음에 에디터를 띄울 때 관련 로드 경고가 없는지만 한 번 보면 확정이다.
