# UOL 표시명·Compile 검증 중복 제거

## 계획

### 목표
UOL(Universal Object Locator)에서 저작자용 표시명을 뽑는 함수가 4개 모듈에 걸쳐 6벌, 스포너 UOL 의 `Compile()` 클래스 검증이 2벌 복제돼 있다. 한 벌만 고치면 조용히 갈라지므로 각각 한 곳으로 모은다. BP 에서 부를 일이 없는 저작 도구용 코드라 BP Library 가 아니라 순수 static 헬퍼로 만든다.

### 접근 방식
- **표시명은 WxCore 로**: 쓰는 쪽이 WxWorld·WxQuest·WxUI·WxEditor 4개 모듈이라 도메인 플러그인엔 둘 수 없다. 4개 모두 이미 `WxCore` 와 `UniversalObjectLocator` 를 참조 중이라 WxCore 의 Build.cs 만 손대면 된다.
- **UCLASS 아님**: BP 호출 대상이 아니므로 리플렉션 없는 순수 struct 로 둔다.
- **검증은 WxWorld Private 로**: `ICompileNodeContext` 가 StateTreeModule 타입이라 WxCore 로 올릴 수 없다. 호출부 둘 다 `AWxSpawner` 한 종류만 검증하므로 클래스 인자를 받는 일반형으로 만들지 않는다.
- **빈 로케이터 문구는 `unset` 로 통일**: 기존에 `none`/`unset` 두 갈래였다. 액터 픽커의 `None` 라벨만 표준 픽커와 맞추기 위해 호출부에서 유지한다.

### 구현·결정과 그 이유
- **에디터 전용 모듈로 분리하지 않았다**: 표시명을 부르는 `GetDescription()`·`Compile()` 이 전부 런타임 모듈(WxWorld·WxQuest·WxUI) USTRUCT 의 `WITH_EDITOR` 멤버라, 에디터 모듈에 두면 런타임 플러그인 셋이 에디터 모듈을 참조해야 한다. `Source/WxEditor` 는 플러그인→게임 모듈 역방향이고 `WxToolset` 은 플러그인 참조 금지 규칙에 걸려, 유일한 선택지가 WxCore 에 에디터 서브모듈을 새로 만드는 것이었다. 옮기는 코드가 이미 전부 `#if WITH_EDITOR` 라 쿠킹 빌드에 한 줄도 안 들어가므로 모듈을 늘려서 얻을 실익이 없다고 보고 WxCore 런타임 모듈에 뒀다.
- **`UCLASS` 가 아닌 순수 struct**: BP 호출 대상이 아니다. 기존에 BP Library 에 얹혀 있던 것이 자리를 잘못 잡은 것이었다.
- **검증 헬퍼만 WxWorld Private 에**: `ICompileNodeContext` 가 StateTreeModule 타입이라 WxCore 로 올리면 foundation 이 StateTree 를 떠안는다. 호출부 둘 다 `AWxSpawner` 하나만 보므로 클래스 인자를 받는 일반형으로 만들지 않았다.
- **액터 픽커의 `None` 은 호출부에서 유지**: 표준 액터 픽커와 라벨을 맞춰야 하므로, 빈 값 판정을 `WxActorLocatorCustomization` 쪽에 남겼다.

### 계획 대비 달라진 점
- 계획대로. 다만 `AWxDevice::PreSave` 주석은 `AWxSpawner::PreSave` 를 지목해 상세를 넘기는 2줄로 줄였다 — 같은 설명을 통째로 복제하면 이번에 없앤 것과 같은 종류의 중복이 된다.

### 후속 과제
- 에디터 실측은 하지 않았다. 노드 설명 문구와 스포너 아닌 액터 지정 시 컴파일 에러는 코드상 동일하나 눈으로 확인하지 않았다.
- `module_review_WxWorld.md` 의 남은 이슈(1·2·3·5·6)는 손대지 않았다. 특히 3번(두 대기 태스크의 레지스트리 중복)은 이번 정리와 같은 성격의 중복이다.
