# 팝업/메뉴 동시 표시 시 게임 일시정지 조기 해제 버그 수정

## 계획

### 목표
메인메뉴 위에 팝업을 띄웠다 팝업만 닫으면 메뉴가 아직 열려 있는데도 게임 정지가 풀리는 버그를 고친다. 위젯이 개별적으로 정지를 켜고/끄던 방식을, 서브시스템이 모든 레이어의 활성 위젯을 순회해 매번 재평가하는 방식으로 바꿔 조기 해제를 없앤다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxActivatableWidget.h/.cpp` | `ApplyGamePause` 제거, `ShouldPauseGame()` getter 추가, 활성/비활성/파괴 훅에서 서브시스템 재평가 요청 | 수정 |
| `WxPrimaryGameLayout.h` | 레이어 순회용 `GetLayerMap()` 접근자 추가 | 수정 |
| `WxUIManagerSubsystem.h/.cpp` | `RefreshGamePause()` 추가 — 레이어 순회로 정지 여부 재평가 | 수정 |

### 접근 방식
- **원인**: `ApplyGamePause`가 참조 카운트 없이 `SetGamePaused`를 절대값으로 호출. 메뉴(`WBP_MenuBase` 디폴트)와 팝업(`UWxGamePopup` 생성자)이 서로 다른 레이어에 동시 활성인데, 팝업이 닫힐 때 무조건 정지를 해제해 메뉴의 정지 요청을 덮어씀. (memory: `ui-pause-simple-bool`)
- **해결**: 위젯은 정지를 직접 적용하지 않고, 활성/비활성 시 `UWxUIManagerSubsystem::RefreshGamePause()`만 요청. 서브시스템이 전 레이어의 `GetActiveWidget()` 중 `IsActivated() && ShouldPauseGame()`이 하나라도 있으면 정지, 아니면 해제. 누적 상태가 없어 조기 해제·영구 정지가 원천 차단됨.
- **타이밍 근거**: `InternalProcessDeactivation`이 `bIsActive=false` → `NativeOnDeactivated()` 순서라, 비활성화 훅 시점에 그 위젯의 `IsActivated()`는 이미 false. 스택에 위젯이 하나뿐이면 비활성화 시 전환이 없어 `GetActiveWidget()`이 비활성 위젯을 반환할 수 있으므로 `IsActivated()` 가드로 무시.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `WxActivatableWidget.h/.cpp` | 정지 적용 로직(`ApplyGamePause`)과 활성/비활성/파괴 오버라이드 전부 제거, `ShouldPauseGame()` getter만 남긴 순수 데이터 홀더로 | 수정 |
| `WxPrimaryGameLayout.h` | 전 레이어 순회용 `GetLayerMap()` 접근자 추가 | 수정 |
| `WxUIManagerSubsystem.h/.cpp` | push된 위젯의 `OnActivated/OnDeactivated` 구독(`ObserveWidgetForGamePause`)·콜백·`RefreshGamePause`(레이어 순회) 추가, 3개 push 경로에서 구독 | 수정 |

### 구현·결정과 그 이유
- **위젯은 서브시스템을 모른다**: 사용자 요구. 위젯이 서브시스템을 직접 부르는 대신, 모든 push가 서브시스템을 경유하는 점을 이용해 서브시스템이 push 시 위젯의 기존 공개 델리게이트 `OnActivated()`/`OnDeactivated()`(엔진 제공)를 구독한다. 위젯 헤더에 서브시스템 의존이 전혀 없다.
- **왜 스택 이벤트(`OnDisplayedWidgetChanged`)로는 부족한가**: 레이어 스택에 RootContent가 없어 위젯 1개짜리 스택은 index 0이고, 이 위젯이 비활성화되면 엔진의 `HandleActiveWidgetDeactivated`가 `index>0` 가드에 막혀 전환/컨테이너 이벤트를 발생시키지 않는다. 그래서 팝업/메뉴 닫힘을 놓친다. 위젯 자신의 `OnDeactivated`는 항상 발생하므로 이를 직접 구독해야 확실히 잡힌다.
- **재평가 방식**: 누적 카운트 없이, 매번 전 레이어의 `GetActiveWidget()`을 훑어 `IsActivated() && ShouldPauseGame()`이 하나라도 있으면 정지. 상태를 누적하지 않아 조기 해제·영구 정지가 원천 차단된다. index 0 잔존(비활성) 위젯은 `IsActivated()` 가드로 무시.
- **풀 재사용 대비**: CommonUI 위젯 풀 재사용 시 중복 바인딩을 막으려 구독 전 `RemoveAll(this)`.

### 계획 대비 달라진 점
- 계획은 "위젯이 활성/비활성 훅에서 서브시스템의 `RefreshGamePause`를 호출"이었으나, 진행 중 사용자가 (1) 헬퍼 함수 추가 금지, (2) 위젯이 서브시스템을 모를 것을 요구 → **트리거를 위젯→서브시스템 호출에서 서브시스템→위젯 델리게이트 구독으로 역전**. 위젯의 `NativeOn*` 오버라이드는 불필요해져 삭제.

### 후속 과제
- 런타임(스탠드얼론) 실제 검증: ESC 메뉴(정지) → 팝업(정지 유지) → 팝업 닫기(정지 **유지**) → 메뉴 닫기(정지 해제). 컴파일은 통과.
