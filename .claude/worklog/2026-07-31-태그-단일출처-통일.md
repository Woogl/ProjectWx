# 태그 단일 출처 통일 (DefaultGameplayTags.ini 제거)

## 계획

### 목표
프로젝트 태그가 네이티브 선언(`WxGameplayTags`)과 `Config/DefaultGameplayTags.ini` 두 곳에 나뉘어 있다. ini 에 남은 엘리베이터 영역 태그 3종을 네이티브로 옮기고 ini 를 없애, 태그 어휘집을 `WxGameplayTags::` 한 곳으로 통일한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/Source/WxCore/Public/WxGameplayTags.h` | 엘리베이터 영역 태그 3종 선언 추가, ini 를 가리키던 주석 정정 | 수정 |
| `Plugins/WxCore/Source/WxCore/Private/WxGameplayTags.cpp` | 위 3종 정의 추가 | 수정 |
| `Config/DefaultGameplayTags.ini` | 파일 삭제 | 삭제 |
| `Docs/Programmer/Gimmick_State_Authority.md` | ini 안내 2곳을 네이티브 선언 안내로 교체 | 수정 |
| `Plugins/WxWorld/README.md` | ini 언급 2곳 교체 | 수정 |

### 접근 방식
- **태그 3종을 네이티브로 이관**: `StateTree.Interact` 선언 아래 붙인다. 태그 문자열을 그대로 두므로 `ST_Elevator` 가 이름으로 참조하는 태그는 재저작 없이 해석된다 — 네이티브 태그는 모듈 로드 시점에 등록되어 에셋 로드보다 먼저 존재한다.
- **ini 는 파일째 삭제**: 태그 목록 외의 `GameplayTagsSettings` 설정이 없고, 태그를 담은 ini 는 프로젝트에 이 하나뿐이다.
- **주석·문서 정정**: 지금 헤더와 두 문서는 "신규 기믹 상태 태그는 C++ 없이 태그 매니저에 추가한다"고 안내한다. 이 규칙이 뒤집히므로 C++ 두 파일에 쌍으로 선언하는 것으로 바꾼다.

### 구현·결정과 그 이유
- **태그 문자열 보존**: 이름을 그대로 옮겨 에셋 재저작을 없앴다. 네이티브 태그는 모듈 로드 때 태그 매니저에 들어가므로 에셋이 이름으로 참조하던 것을 그대로 찾는다.
- **ini 파일째 삭제**: 안에 태그 목록 말고는 아무 설정도 없었고, 태그를 담은 ini 는 프로젝트에 이 하나뿐이었다. 앞으로 에디터 태그 매니저로 태그를 추가하면 엔진이 이 파일을 되살리므로, 태그 추가처를 C++ 두 파일로 못박는 문구를 헤더와 문서에 남겼다.
- **표제 정정**: 기믹 추가에 C++ 이 전혀 필요 없다던 안내는 이제 사실이 아니다. 기믹 클래스는 여전히 필요 없지만 상태 태그 선언은 C++ 이라, 표제를 그 범위로 좁혔다.

### 계획 대비 달라진 점
- **`StateTree.Interact.Elevator.Platform` 은 옮기지 않고 버렸다**: 콘텐츠 전수 검색 결과 이 태그를 참조하는 에셋이 없다. 플랫폼 영역은 기본 태그(`StateTree.Interact`)로 발동하고 전이가 페이로드로 가른다. 소비처 주석이 곧 색인인 헤더에 죽은 태그를 넣으면 없는 소비처를 문서화하는 셈이라 뺐다. 필요해지면 그때 소비처와 함께 선언한다.

### 후속 과제
- 에디터에서의 실동작 확인(엘리베이터 호출 콘솔 A/B) 미수행 — 빌드 성공과 에셋 내 태그 문자열 일치까지만 확인했다.
