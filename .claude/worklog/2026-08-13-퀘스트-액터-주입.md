# 퀘스트 레벨 액터 주입 — UOL 전면 제거 + FStateTreeReference 수주 컴포넌트

## 계획

### 목표
퀘스트 파이프라인에서 UOL 을 완전히 걷어낸다. 액터 지정은 전부 `TSoftObjectPtr<AActor>` 로 통일하고, 값은 에셋이 아니라 레벨에 배치된 수주 컴포넌트의 `FStateTreeReference` 가 런타임에 주입한다. 퀘스트 에셋의 레벨 참조가 0이 되어 레벨 간 재사용이 가능해지고, 디자이너는 수주 지점 패널에서 표준 소프트 액터 픽커로 대상을 지정한다.

### 접근 방식
- **소프트 참조가 성립하는 이유**: ST 컴파일러의 레벨 액터 거부는 "에셋 안 저장"에만 걸린다. 이 설계는 에셋에 빈 파라미터 선언만 두고 값을 레벨 데이터(배치 컴포넌트)에 저장하므로 검증 밖이다. 매 틱 `Get()`(로드 없는 경로 해석)이 UOL SyncFind 와 동등한 WP 스트리밍 내성을 주고, 레벨 패키지의 소프트 경로는 PIE 복제 시 엔진이 자동 리매핑한다(기존 실증 문제는 네트워크 복제 한정).
- **주입 배관은 엔진 그대로**: 수주 컴포넌트의 `FStateTreeReference`(에셋 픽커+루트 파라미터 자동 미러링 패널 내장)를 러너의 `SetStateTreeReference()` 에 통째로 넘기면 `StartLogic()` 이 루트 파라미터로 주입한다. 새 배관 코드가 사실상 없다.
- **수용한 트레이드오프**: 픽커 타입 게이트 약화(런타임 마커 검증으로 대체), 루트 파라미터 개명 시 배치 오버라이드 증발(**루트 파라미터는 공개 계약, 개명 금지 규약**), 편집 분산(레벨 불가지의 뒷면).
- **체인 한계**: ActivateNextQuest 는 액터 파라미터 없는 퀘스트만(현 콘텐츠 미사용).

### 구현·결정과 그 이유
- **소프트 참조가 컴파일을 통과하는 근거**: ST 컴파일러의 레벨 액터 거부는 에셋에 저장된 값에만 걸린다. 에셋에는 빈 파라미터 선언만 두고 값은 배치 컴포넌트(레벨 데이터)에 저장하므로 검증 밖이며, 퀘스트 에셋의 레벨 참조가 0이 되어 레벨 간 재사용이 성립한다.
- **주입 배관은 엔진 그대로**: 수주 컴포넌트의 레퍼런스(에셋 픽커+파라미터 자동 미러링 패널 내장)를 러너에 통째로 넘기면 시작 시 루트 파라미터로 주입된다. 새 배관 코드 없음.
- **링크 상태 바인딩은 오버라이드 마킹과 무관**: 엔진 소스 확인 결과 컴파일러는 상태 파라미터 백 전체를 바인딩 타깃으로 컴파일하고, 오버라이드 목록은 편집 시 레이아웃 동기화에서 값 보존용으로만 쓰인다. 리터럴(문구·대사 행·반경)은 오버라이드, 액터는 루트 바인딩으로 이원화.
- **이동 목표 파라미터 분리**: 구 에셋은 이동 판정 대상을 스포너 값과 공유했으나, 수주 지점이 임의 액터를 지정할 수 있도록 MoveTargets 를 독립 파라미터로 두고 현 콘텐츠는 기존 동작 보존을 위해 같은 스포너를 기입했다.
