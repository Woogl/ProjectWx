# 스킬 2·3·4 쿨다운 GE 추가

## 계획

### 목표
슬롯 2·3·4 스킬이 각자 독립된 쿨다운을 굴릴 수 있도록, 슬롯 1과 같은 모양의 쿨다운 GE 파생 클래스와 짝이 되는 식별 태그를 마련한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/Source/WxCore/Public/WxGameplayTags.h` | `Cooldown_Skill_2`·`_3`·`_4` 선언을 `Cooldown_Skill_1` 다음에 추가 | 수정 |
| `Plugins/WxCore/Source/WxCore/Private/WxGameplayTags.cpp` | 같은 태그를 `"Cooldown.Skill.2"`~`"Cooldown.Skill.4"`로 정의 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Public/AbilitySystem/Effect/WxEffect_Cooldown.h` | `UWxEffect_Cooldown_Skill_2`·`_3`·`_4` 선언을 `Skill_1` 다음, `Ultimate` 앞에 추가 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Effect/WxEffect_Cooldown.cpp` | 세 생성자에서 각자의 태그로 `GrantCooldownTag` 호출 | 수정 |

### 접근 방식
- **기존 패턴 그대로 복제**: 엔진이 쿨다운 스택을 GE 클래스 단위로 병합하므로, 따로 도는 쿨다운마다 파생 클래스가 하나씩 필요하다. 지속시간·스택 정책은 베이스가 쥐고 있어 파생 클래스는 순정 쿨다운 API가 쓸 식별 태그만 정한다.
- **태그는 네이티브 선언만**: ini는 손대지 않고, 이름은 짝이 되는 `Ability.Skill.N`을 따라 맞춘다.
- **선언 순서 유지**: cpp 정의 순서를 헤더 선언 순서에 맞춰 Dodge → Skill 1~4 → Ultimate로 둔다.
- **어빌리티 코드는 건드리지 않음**: 슬롯 2·3·4 BP가 각자 `CooldownGameplayEffectClass`를 새 클래스로 지정하면 된다. BP 지정은 이번 범위 밖.

### 구현·결정과 그 이유
- **파생 클래스를 슬롯마다 하나씩**: 엔진이 쿨다운 스택을 GE 클래스 단위로 묶기 때문에, 클래스를 공유하면 서로 다른 스킬의 충전이 한 덩어리로 병합된다. 슬롯마다 독립된 쿨다운을 굴리려면 클래스를 나누는 것 말고 다른 수가 없다.
- **파생 클래스는 태그만**: 지속시간 계산과 스택 정책은 베이스가 모두 쥐고 있으므로 파생은 순정 쿨다운 API가 식별자로 쓸 태그 한 줄만 정한다. 슬롯 1과 완전히 같은 모양이라 나중에 슬롯을 더 늘려도 비용이 일정하다.
- **어빌리티 코드는 그대로**: 슬롯 구분은 원래부터 BP 소관이라, 어느 쿨다운 GE를 쓸지도 각 슬롯 BP가 고르게 두었다. C++에 슬롯 분기를 새로 들이지 않는다.

### 계획 대비 달라진 점
계획대로.

### 후속 과제
- 슬롯 2·3·4 스킬 BP에서 `CooldownGameplayEffectClass`를 각자의 새 클래스로 지정해야 실제로 쿨다운이 갈라진다. 지정 전까지는 넷 모두 슬롯 1 GE를 물려받아 쿨다운을 공유한다.
