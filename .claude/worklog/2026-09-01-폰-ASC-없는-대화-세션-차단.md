# 폰 ASC 없이 열린 대화 세션이 굳는 문제

## 계획

### 목표
폰 ASC가 없으면 `State.Dialogue`가 안 올라가 대화 창이 뜨지 않는데도 세션은 열려, 넘길 주체도 끝낼 신호도 없는 채로 굳는다. 그 상태에서 `Play Dialogue` 태스크가 무한히 Running에 머물러 퀘스트가 멈춘다. 띄울 수 없으면 아예 열지 않도록 바꾼다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/.../Private/WxDialogueSessionComponent.cpp` | ASC 조회를 세션 상태 대입 전으로 올리고, 없으면 Warning 후 반환 | 수정 |
| `Plugins/WxDialogue/.../Private/WxStateTreeTask_PlayDialogue.cpp` | 실패 로그의 사유 열거가 불완전해져 직전 경고를 가리키는 문구로 정정 | 수정 |
| `Plugins/WxDialogue/.../Public/WxDialogueSessionComponent.h` | 클래스 주석에 "폰 ASC가 세션의 전제" 한 줄 추가 | 수정 |

### 접근 방식
- **띄울 수 없으면 열지 않는다**: 창을 여는 신호가 태그뿐이라, 태그를 못 올리는 세션은 진행도 종료도 불가능하다. 열어 두고 경고만 찍는 것으로는 교착이 그대로 남는다.
- **기존 실패 경로 재사용**: 세션을 열지 않으면 `HasActiveDialogue()`가 거짓이라 `FWxStateTreeTask_PlayDialogue`의 기존 검사가 그대로 걸려 Failed로 끝난다. 새 실패 통로를 만들 필요가 없다.
- **조기 반환 위치**: 앞 세션을 접는 `EndDialogue()` 뒤에 둔다. 새 요청이 실패해도 앞 세션이 매달려 남지 않고 그쪽 태스크도 정상 종료된다.
- **태그 발행 위치는 유지**: 창을 여는 관찰자가 그 시점에 현재 대사를 pull 해 시드하므로 발행은 세션이 다 채워진 뒤 그대로 두고, 위로 올리는 것은 조회뿐이다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/.../Private/WxDialogueSessionComponent.cpp` | Controller→Pawn→ASC 조회를 `EndDialogue()` 직후로 이동, ASC 없으면 Warning 후 반환 | 수정 |
| `Plugins/WxDialogue/.../Private/WxStateTreeTask_PlayDialogue.cpp` | 실패 로그 문구 정정 | 수정 |
| `Plugins/WxDialogue/.../Public/WxDialogueSessionComponent.h` | 클래스 주석 한 줄 추가 | 수정 |

### 구현·결정과 그 이유
- **조회만 올리고 발행은 그대로**: 발행 시점을 앞당기면 창을 여는 관찰자가 아직 안 채워진 세션에서 대사를 pull 해 빈 대화 창이 뜬다. 판정에 필요한 것은 조회 결과뿐이라 조회만 끌어올렸다.
- **경고 문구에 결과를 적었다**: "ASC가 없다"만으로는 다음 사람이 왜 대화가 안 열리는지 잇지 못한다. 창을 띄울 신호가 없다는 것까지 한 줄에 담았다.
- **검증**: UE 5.8 `WxEditor Win64 Development` 빌드가 `Result: Succeeded`로 끝났다. 폰 없는 상태에서 Play Dialogue를 태우는 런타임 실측은 하지 않았다.

### 계획 대비 달라진 점
- 계획대로.

### 후속 과제
- 대화 도중 폰이 교체되면 같은 교착이 난다 — UI 매니저가 관찰을 옮기며 창을 닫는데 새 폰 ASC엔 태그가 없고, 옛 ASC에 남은 태그는 `TaggedAbilitySystem`이 붙잡고 있다. 세션이 폰 전이를 직접 듣고 태그를 옮기거나 세션을 접는 처리가 필요하다.
- 세션 교체로 인한 `EndDialogue()`도 `OnDialogueEnded`를 발화해 앞 태스크가 완주로 오인된다(모듈 리뷰 2번). 이번 범위 밖.
