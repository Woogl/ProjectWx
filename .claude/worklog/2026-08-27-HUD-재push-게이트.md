# HUD 재-push 게이트를 레이어 소속으로

## 계획

### 목표
HUD 중복 push 를 막는 게이트가 약참조 생존 여부라, 레이어에서 걷힌 뒤에도 풀에 보관된 인스턴스를 "떠 있음"으로 오독한다. 그 상태에서 폰이 바뀌면 HUD 가 다시 올라오지 않고 HUD 없는 화면으로 굳는다. 게이트가 묻는 질문을 "레이어에 아직 걸려 있는가"로 바꾼다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Private/Component/WxHUDComponent.cpp` | 게이트를 Game 레이어 스택 목록 조회로 교체, 매니저·레이아웃 획득을 앞으로 이동, 레이아웃 헤더 include 추가 | 수정 |

### 접근 방식
- **레이어 목록에 묻는다**: 엔진 컨테이너의 위젯 목록이 곧 그 스택에 걸린 것들이고, 걷을 때 컨테이너 스스로 그 목록에서 지운다. 판정 근거가 엔진 자신의 장부이며, 경로가 이미 공개돼 있어 새로 만들 것이 없다.
- **활성 여부로 가르지 않는다**: Game 레이어는 스택이고 대화 창도 같은 레이어에 올라온다. 스택은 새 위젯을 올릴 때 아래 위젯을 비활성화만 하고 목록에는 남기므로, 활성 여부로 가르면 대화 중 폰이 바뀔 때 HUD 가 멀쩡한데도 두 번째 HUD 를 쌓는다.
- **게이트 자체는 없앨 수 없다**: 엔진 컨테이너가 같은 인스턴스의 재등록을 ensure 로 막으므로 "매번 push" 는 중복 대신 ensure 를 부른다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/Source/WxUI/Private/Component/WxHUDComponent.cpp` | 게이트를 Game 레이어 스택 목록 조회로 교체, 매니저·레이아웃 획득을 게이트 앞으로 이동, 레이아웃 헤더 include | 수정 |

### 구현·결정과 그 이유
- **판정 근거를 엔진 장부로 옮겼다**: 약참조 생존은 "화면에 있는가"를 답하지 못한다 — 풀이 인스턴스를 붙잡고 있기 때문이다. 스택이 위젯을 걷을 때 자기 목록에서 지우므로, 그 목록에 남아 있는지가 곧 답이고 우리가 따로 상태를 들 필요가 없다.
- **활성 여부로 가르지 않았다**: Game 레이어는 스택이고 대화 창이 같은 레이어에 올라온다. 스택은 아래 위젯을 비활성화만 하고 목록에는 남기므로, 활성 여부를 게이트로 쓰면 대화 중 폰 교체에서 HUD 가 멀쩡한데도 하나 더 쌓인다.
- **신규 함수를 두지 않았다**: 레이아웃 조회와 스택 조회가 이미 공개돼 있어 컴포넌트가 그대로 물어볼 수 있다. 서브시스템에 조회 함수를 하나 더 두는 안도 있었으나, 호출자가 하나뿐이라 표면만 넓힌다.
- **레이아웃 부재는 그 자리에서 반환**: 조회에 레이아웃이 필요하고, 없으면 push 도 실패하므로 결과가 같다.
- **검증**: WxEditor(Development) 빌드 성공.
