# 반응 어빌리티의 이벤트 판정을 응답 훅으로 단일화

## 계획

### 목표
직전 작업(`2026-09-15-무반응-게이트-일반피격-한정.md`) 뒤로 HitReact·GuardReact의 이벤트 판정이 응답 훅과 활성화 검사 두 곳에 흩어져 읽기 어렵다. 두 함수의 역할을 나누는 원칙은 이렇다. 응답 훅은 "이 이벤트가 내 몫인가"를 페이로드로 판정하고, 활성화 검사는 "지금 상태로 발동할 수 있는가"를 소유자 상태로 판정한다. 이 원칙에 맞춰 이벤트 판정을 응답 훅 한 곳으로 모은다. 동작은 바꾸지 않는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `WxCombat/Public/.../WxAbility_HitReact.h` | 활성화 검사 오버라이드 선언 삭제 | 수정 |
| `WxCombat/.../Ability/WxAbility_HitReact.cpp` | 활성화 검사 정의 삭제, 응답 훅을 조건별 조기 반환으로 재작성 | 수정 |
| `WxCombat/Public/.../WxAbility_GuardReact.h` | 활성화 검사 오버라이드 선언 삭제 | 수정 |
| `WxCombat/.../Ability/WxAbility_GuardReact.cpp` | 활성화 검사 정의 삭제, 응답 훅을 같은 모양으로 재작성 | 수정 |

### 접근 방식
- **활성화 검사 오버라이드를 지운다**: 지금은 페이로드가 있는지만 보는 이벤트 판정인데, 이벤트 경로에서는 늘 통과라 하는 일이 없다. 이것이 막던 직접 발동 경로는 코드에도 에셋에도 없다. 입력·선입력 버퍼, 부여 즉시 발동, UI 조회, 상호작용 스캐너, BT, BP를 모두 확인했다.
- **응답 훅은 조건 하나에 반환 하나**: 자기 몫이 아닌 이벤트를 배제하고, 반응 태그 없는 일반 피격을 거부한 뒤, 부모에 넘긴다. 엔진은 페이로드가 있을 때만 이 훅을 부르므로 null 검사는 뺀다.

### 구현·결정과 그 이유
- **나누는 기준은 판정 재료다**: 응답 훅만 이벤트 태그를 볼 수 있고, 이벤트 경로에서 재트리거 종료나 공격 취소보다 먼저 돈다. 활성화 검사는 입력·UI 조회 같은 모든 경로에서 불리므로 소유자 상태(SP, 입력 등)만 봐야 한다. 가드와 질주가 이미 그렇게 쓰고 있다.
- **직접 발동 차단을 포기한 이유**: 차단이 막던 경로는 쓰는 곳이 없다. 차단을 유지하려면 활성화 검사에 이벤트 판정을 두는 수밖에 없어, 판정이 다시 두 곳으로 흩어진다. 누군가 나중에 이벤트 없이 HitReact를 발동하면 공격·스킬이 취소된 뒤 곧바로 종료되는데, 그런 발동을 저작할 이유가 없다.
- **동작 대조**: 태그 있는 일반 피격은 두 어빌리티 모두 받고, 태그 없는 일반 피격은 둘 다 거부한다. 패리는 HitReact만, 가드 브레이크와 퍼펙트 가드는 GuardReact만 받는다. 직전 작업 결과와 같다.
