# Wait Dialogue Completed 인자를 대화 행으로 전환

## 계획

### 목표

`Wait Dialogue Completed` 는 지금 대상 액터(UOL 로케이터)를 인자로 받아 그 액터와의 대화가 열렸다 닫히면 완주로 본다. 그래서 같은 NPC 가 단계마다 다른 대사를 내도 게이트가 구분하지 못하고, 대상 없는 대사(나레이션·`Play Dialogue` 가 연 대화)는 판정 자체가 불가능하다.
인자를 `Play Dialogue` 와 같은 대화 행 핸들로 바꿔, "이 대화를 완주했는가"를 대화의 신원으로 판정한다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/.../Public/WxDialogueSessionComponent.h` | 세션이 시작 행을 보관·노출하도록 멤버와 게터 교체 | 수정 |
| `Plugins/WxDialogue/.../Private/WxDialogueSessionComponent.cpp` | 테이블 멤버를 시작 행 핸들로 대체, 게터 구현 | 수정 |
| `Plugins/WxDialogue/.../Public/WxDialogueStateTreeNodes.h` | 대기 태스크 인스턴스 데이터를 대상 액터 → 행 핸들로 교체, 주석 갱신 | 수정 |
| `Plugins/WxDialogue/.../Private/WxDialogueStateTreeNodes.cpp` | 판정을 행 비교로 교체, 로케이터 헬퍼 제거 | 수정 |

### 접근 방식

- **판정 기준은 세션이 시작한 행**: 진행 중 지나가는 중간 노드가 아니라 세션을 연 행으로 본다. 세션이 열려 있는 동안 값이 변하지 않아 틱 샘플링으로 놓칠 일이 없고, `Play Dialogue` 와 대화 정의 컴포넌트가 지정하는 값과 정확히 같은 것이라 에셋에서 두 곳에 같은 행을 적으면 그대로 맞물린다. 선택지 분기 노드까지 대기 대상으로 삼는 확장은 지금 요구가 아니라 미룬다.

- **세션의 테이블 멤버를 시작 행 핸들로 대체**: 세션은 이미 진행 중인 테이블을 강참조로 붙잡고 있다. 이를 행 핸들로 바꾸면 테이블과 시작 행 이름을 한 값으로 들게 되어 멤버가 늘지 않고, 관찰자에게 그대로 노출할 수 있다.

- **관찰 방식(엣지 감지)은 그대로**: 지정 행에서 시작한 대화가 진행 중이면 목격을 기록하고, 목격 후 그 대화가 아니게 되면 완주다. 진입 이전 대화를 세지 않는 성질도 유지된다. 행 미지정은 활성 대화와 절대 같을 수 없어 오통과가 없고, 기존과 같이 경고만 남기고 대기한다(게이트가 실패 전이로 단계를 건너뛰는 편이 더 나쁘다).

- **대상 액터 노출은 유지**: `GetCurrentDialogueTarget` 은 PC 의 대화 카메라 전환이 쓰므로 그대로 둔다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxDialogue/.../Public/WxDialogueSessionComponent.h` | 테이블 멤버를 시작 행 핸들로 교체, 시작 행 게터 추가 | 수정 |
| `Plugins/WxDialogue/.../Private/WxDialogueSessionComponent.cpp` | 세션 개시·종료에서 시작 행을 채우고 비움, 행 탐색이 그 핸들의 테이블을 씀 | 수정 |
| `Plugins/WxDialogue/.../Public/WxDialogueStateTreeNodes.h` | 대기 태스크 인자를 대상 액터 → 대화 시작 행으로 교체, 판정 설명 갱신 | 수정 |
| `Plugins/WxDialogue/.../Private/WxDialogueStateTreeNodes.cpp` | 판정을 시작 행 비교로 교체, 로케이터 헬퍼 제거, 행 표시 헬퍼를 두 태스크가 공유 | 수정 |

### 구현·결정과 그 이유
- **대화의 신원을 시작 행으로 봄**: 대상 액터로는 같은 NPC 의 단계별 대사를 구분할 수 없고 나레이션은 아예 판정할 수 없었다. 시작 행은 세션이 열려 있는 동안 변하지 않아 틱 샘플링으로 놓칠 일이 없고, 출력(Play Dialogue)·대화 정의 컴포넌트가 지정하는 값과 같은 것이라 에셋에서 그대로 맞물린다.
- **세션의 테이블 멤버를 행 핸들로 교체**: 세션은 이미 진행 중인 테이블을 강참조로 붙잡고 있었다. 이를 행 핸들로 바꾸니 테이블과 시작 행을 한 값으로 들면서 관찰자에게 노출할 신원까지 겸하게 되어 멤버가 늘지 않았다.
- **이름은 `StartRow` 로 통일**: 대화는 행 하나가 아니라 행들의 그래프이고 인자가 가리키는 것은 그 진입점이다. 대화 정의 컴포넌트·세션 진입점이 이미 같은 어휘를 쓰고 있어, 같은 값이 경로마다 다른 이름으로 불리지 않게 했다.
- **미지정은 여전히 경고 후 대기**: 게이트가 실패 전이로 단계를 건너뛰는 편이 더 나쁘다. 미지정 행은 진행 중인 대화와 절대 같을 수 없어 오통과도 없다.
- **관찰 대상을 활성 대화로 한정**: 대화가 없을 때의 빈 핸들과 미지정 인자가 서로 같아 보이는 것을 막기 위해, 대화가 열려 있을 때만 신원을 비교한다.

### 계획 대비 달라진 점
- **행 표시 헬퍼를 두 태스크가 공유**: 대기 태스크 설명을 행 이름으로 바꾸면서 출력 태스크와 같은 모양이 되어, 각자 쓰던 표시 코드를 익명 네임스페이스의 헬퍼 하나로 합쳤다.

### 후속 과제
- 에셋 재지정(사용자 담당): `ST_Quest_Main1` 의 `Wait Dialogue Completed` 노드는 기존 대상 값이 유실되므로 대화 시작 행을 다시 지정해야 한다(해당 NPC 의 대화 정의와 같은 행).
- PIE 실기 확인: 수주·납품 게이트가 지정 대화 완주에서만 통과하는지, 다른 대화로는 통과하지 않는지.
