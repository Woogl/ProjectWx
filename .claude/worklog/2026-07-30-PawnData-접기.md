# PawnData 접기 — 폰 클래스를 Experience 필드로 직접 이동

## 계획

### 목표
필드 하나(`PawnClass`)뿐인 `UWxPawnData`를 없애고 폰 클래스를 Experience 정의가 직접 들고, 폰 클래스의 출처를 Experience 하나로 확정한다. 프라이머리 에셋 타입·스캔 설정·에셋 파일이라는 대가에 비해 간접이 얻는 게 없고, GameMode의 `DefaultPawnClass`와 값이 이중으로 존재하는 상태이기 때문이다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Framework/WxExperienceDefinition.h` | `DefaultPawnData` 제거 → `TSubclassOf<APawn> DefaultPawnClass` 추가, 전방 선언 정리 | 수정 |
| `Framework/WxGameMode.cpp` | 폰 클래스 조회를 Experience 필드 직독으로 축소, Super 폴백 제거(미설정 시 Error) | 수정 |
| `Framework/WxGameMode.h` | 폰 클래스 출처가 Experience 단일임을 클래스 주석에 명시 | 수정 |
| `Framework/WxPawnData.h` | 폰 데이터 클래스 | 삭제 |

### 접근 방식
- **간접을 접는 기준**: Lyra의 PawnData는 어빌리티 셋·입력·카메라를 담는 조립 레시피라 값을 하지만, Wx 폰 BP는 그것들을 자기가 소유해 담을 페이로드가 없다. 레퍼런스에서 핵심만 취하고 확장용 간접은 생략한다는 원칙을 적용한다. 두 번째 필드가 실제로 생길 때 다시 승격한다.
- **출처 단일화**: `GetDefaultPawnClassForController`가 Super를 부르지 않게 해 GameMode의 `DefaultPawnClass`를 아예 읽지 않는다. 엔진에서 그 프로퍼티를 직접 읽는 곳은 `AGameModeBase`의 같은 함수뿐이라, Super만 끊으면 죽은 데이터가 된다. 미설정 시 nullptr을 반환하면 엔진이 스폰을 건너뛰고 `FailedToRestartPlayer`로 빠지므로 크래시 없이 우리 Error 로그가 원인을 지목한다. 폴백을 남기면 GM 값을 비웠을 때 CDO 기본값(`ADefaultPawn`)으로 조용히 되돌아가는 쪽이 더 위험하다.
- **마이그레이션**: 타입이 바뀌어 CoreRedirect로 보존할 수 없고 C++ 프로퍼티 삭제 시 저장값이 드롭되므로, 현재 값(`/Game/Character/Player/BP_Player.BP_Player_C`)을 계획 단계에서 선확보해 두고 새 필드에 재기입한다.
- **범위 제한**: 액션셋에는 필드를 추가하지 않는다(폰 클래스는 판당 하나라 합산이 성립하지 않음). `IsDataValid`에 검증 항목도 더하지 않는다(첫 PIE에서 즉시 드러나고 Error 로그가 있음).

### 구현·결정과 그 이유
- **간접을 접었다**: 감싸고 있던 값이 폰 클래스 하나뿐인데 프라이머리 에셋 타입·스캔 설정·에셋 파일을 유지하고 있었다. 원본에서 이 데이터가 값을 하는 이유는 폰을 데이터로 조립하기 때문인데, Wx 폰은 필요한 것을 자기가 소유해 담을 내용이 없다. 두 번째 필드가 실제로 생길 때 다시 승격하기로 했다.
- **폴백을 없애 출처를 하나로 만들었다**: 폰 클래스가 Experience와 GameMode 양쪽에 실제로 들어 있어 한쪽만 고치면 아무 일도 안 일어나는 상태였다. 상속받은 프로퍼티를 직접 읽는 곳이 엔진에도 오버라이드한 그 함수뿐이라, Super만 끊으면 완전히 죽은 데이터가 된다. 폴백을 남기고 GameMode 쪽 값을 비우는 안은 기각했다 — 비우면 엔진 기본값으로 되돌아가 조용히 엉뚱한 폰이 스폰될 수 있어서다.
- **실패를 시끄럽게 뒀다**: 미설정 시 널을 돌려주면 엔진이 스폰을 건너뛰고 리스타트 실패 경로로 빠진다. 크래시 없이 폰만 안 뜨고 에러 로그가 원인을 지목하므로, 별도 검증 가드는 두지 않았다.
- **폰 클래스 조회를 로드 상태에서 분리했다**: 처음엔 로드 완료를 전제로 조회했는데, PIE 로그에서 로그인 도중 에러가 찍혀 드러났다. 엔진은 로그인 단계에서 시작 지점을 고르며 폰 CDO 크기로 점유 여부를 재는데, 이 시점이 비동기 로드보다 이르다. 폰 클래스는 정의 에셋 자체의 데이터라 주입·플러그인 활성을 기다릴 이유가 없으므로, 확정만 됐으면 돌려주는 게터를 두고 그것을 쓰게 했다. 로드 상태를 기다렸다면 거짓 에러가 매 세션 남고, 그 사이 시작 지점 점유 판정이 무력화된다(직전 구현에선 상속 폴백이 우연히 이를 가려 주고 있었다).

### 계획 대비 달라진 점
- 에셋 작업(폰 클래스 기입·폰 데이터 에셋 삭제)은 이번 세션에 에디터 연동이 없어 사용자가 직접 수행했다.
- 매니저에 게터 하나를 추가했다 — 위의 조회 시점 문제를 잡기 위해.

### 후속 과제
- 조회 시점 수정분은 빌드까지 확인했다. 에디터를 새 빌드로 재시작해 PIE 로그에 폰 클래스 관련 에러가 남지 않는지 한 번 더 봐야 한다.
