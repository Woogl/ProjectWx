# 모듈 리뷰 확신도 높음 3건 수정

## 계획

### 목표

`/module-review` 산출물에서 확신도 높음이면서 수정이 한 줄로 끝나는 3건을 처리한다. 세 건은 서로 무관한 독립 결함이며, 공통점은 "실패 경로가 성공으로 새거나 전제가 코드에 없음"이다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbility_Guard.cpp` | `PlayMontage` 앞단에 `if (!Montage) { return false; }` 추가 | 수정 |
| `Plugins/WxInventory/Source/WxInventory/Private/Items/WxItemPickup.cpp` | 생성자에 `SetReplicateMovement(true)` 추가 | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Task/WxAbilityTask_WaitInputActionTriggered.cpp` | `Activate()` 첫 줄에 `Super::Activate()` 추가 | 수정 |

### 접근 방식

- **가드 몽타주 널 가드 (WxCombat #2)**: 페이즈 몽타주 4종이 모두 선택적 `UPROPERTY`인데 널을 거르지 않아, 태스크가 `OnCancelled`를 즉시 쏴 어빌리티가 끝나는데도 `true`를 반환한다. 그 결과 `ActivateAbility`·`HandleGuardHitReact`의 실패 분기가 타지 않고 종료된 어빌리티 위에 리스너 3종이 등록된다. 형제 클래스 `UWxAbility_Dodge::PlayMontage`가 이미 같은 자리에서 널을 검사하므로 그 패턴을 그대로 맞춘다.

- **픽업 이동 복제 (WxInventory #1)**: `LaunchInDirection`이 서버에서만 물리를 걸지만 `bReplicateMovement`는 엔진 기본값이 false라 클라에선 픽업이 스폰 지점에 멈춘다. 상호작용 사거리 검증은 서버 위치 기준이라 보이는 자리에서 상호작용이 안 되는 불일치가 된다. BP 개별 설정이 아니라 생성자에서 켜 물리 발사의 전제를 코드가 소유한다 — BP에 맡기면 픽업 BP가 늘 때마다 재발한다.

- **`Super::Activate()` 누락 (WxCombat #12)**: 프로젝트 규칙 위반. 같은 폴더의 다른 AbilityTask 3종은 모두 호출한다. 현재 엔진 기본 구현이 비어 있어 동작 영향은 없으나 업데이트에 취약하다. 조기 `EndTask()` 경로보다 앞에 둔다.

## 완료

### 수정한 파일

| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Ability/WxAbility_Guard.cpp` | `PlayMontage` 앞단 널 몽타주 조기 반환 | 수정 |
| `Plugins/WxInventory/Source/WxInventory/Private/Items/WxItemPickup.cpp` | 생성자에서 `SetReplicateMovement(true)` | 수정 |
| `Plugins/WxCombat/Source/WxCombat/Private/AbilitySystem/Task/WxAbilityTask_WaitInputActionTriggered.cpp` | `Activate()` 첫 줄 `Super::Activate()` | 수정 |

### 구현·결정과 그 이유

- **널 가드를 태스크 생성 실패 검사보다 앞에**: 기존 `if (!MontageTask)` 가드는 프록시 생성 실패만 잡고 널 몽타주는 통과시킨다. 앞단에 두어야 `CurrentMontageTask` 정리·`ActiveMontage` 대입 전에 빠져나가 상태가 오염되지 않는다.
- **이동 복제를 BP가 아니라 생성자에서**: 물리 발사를 서버 권위로 거는 주체가 이 클래스이므로 그 전제도 같은 클래스가 소유해야 한다. BP 디폴트에 맡기면 파생 픽업 BP가 늘 때마다 같은 누락이 재발한다.
- **`Super::Activate()` 를 조기 `EndTask()` 앞에**: 조기 반환 경로에서도 베이스 초기화가 건너뛰이지 않게 한다.
