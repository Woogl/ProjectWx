# 장치 태스크 대상 지목 — 모드 enum 명시화

## 계획

### 목표
`상호작용 켜기`는 `Target`(UOL)을 비우면 오너 장치를 대상으로 삼는 유추가 있고, 채우면 `Prompt`·`OnInteracted`가 조용히 무시된다. `이벤트 보내기`는 유추는 없지만 지목 수단이 둘이라 쓰지 않는 칸이 화면에 남고 둘 다 채우면 양쪽으로 나간다. 두 태스크가 **대상의 종류를 enum 한 칸으로 선언**하게 하고, 모드에 안 맞는 칸은 감춘다.

### 접근 방식
- **기본값은 그 태스크의 본래 자리로 정한다**: `상호작용 켜기`는 `Self`(장치가 자기 상호작용을 여닫는 것이 원래 일, `Actor`는 08-14에 합쳐 들어온 파생), `이벤트 보내기`는 `Linked`(레벨 장치끼리 미는 배선이 발동 장치의 기본 경로, `Child`는 오너 BP 내장 장치를 지목하는 좁은 갈래). 열거자 순서도 그 순서로 두고 기본값은 명시 초기화로 박는다.
- **저장된 노드는 새 필드가 기본값을 받으므로 해당 노드를 전부 다시 기입한다**: `ST_Door`·`ST_Elevator`의 10노드가 `Child`로, 퀘스트 스텝 1노드가 `Actor`로 바뀌어야 한다. 빠뜨린 노드는 경고를 남기며 무동작이 되므로 코드와 에셋 편집을 같은 작업에서 끝낸다.
- **모드에 안 맞는 칸은 감춘다**: `EditCondition` + `EditConditionHides`. 이 구조체엔 이미 `Prompt`의 `EditCondition = "bEnable"` 선례가 있다. 바인딩 배열과 커스터마이즈된 드롭다운에서도 숨김이 먹는지 에디터에서 확인하고, 안 되면 `EditConditionHides`만 떼어 회색 처리로 둔다.
- **경고는 "선언했는데 비었다"에만 붙인다**: `Self`인데 오너가 장치가 아님, `Child`인데 이름 미지목, `Linked`인데 배열이 빔. `Actor`인데 `Target`이 빈 것은 퀘스트 스텝의 「빈 지정 = 기능 미사용」 계약이라 조용히 통과한다. 이름을 지목했는데 못 찾는 경우는 지금처럼 Error + `Failed`.
- **배치 대상 칸을 `LinkedDevices`로 개명한다**: 태스크가 고른 대상이 아니라 오너의 배선을 그대로 받는 거울이므로 이름을 원본에 맞춘다. 바인딩은 프로퍼티 경로를 이름으로 저장하므로 개명하면 기존 바인딩 3개가 끊긴다 — 컴파일에서 드러나며 같은 편집에서 다시 건다.
- **설명 텍스트는 고른 모드만 보여 준다**: 두 대상을 `·`로 잇던 조합 표기가 사라진다.
- **`상호작용 켜기`의 두 갈래 자체는 그대로 둔다**: 바뀌는 것은 갈래를 무엇이 정하느냐 하나다.

### 구현·결정과 그 이유
- **갈래를 선언으로 옮겼다**: 종전엔 「대상 칸이 비었는가」가 모드였고, 채우면 프롬프트·발행 칸이 조용히 무시됐다. 이제 `TargetKind` 하나가 갈래를 정하고 안 쓰는 칸은 디테일 패널에서 감춰진다.
- **태스크를 쪼개지 않았다**: 08-14 통합("한 노드로 선언")을 되돌리지 않으면서 유추만 걷어내는 쪽을 골랐다. 덤으로 에셋 편집이 노드 교체가 아니라 필드 값 하나라 08-23 같은 컴파일 파손 위험을 피한다.
- **기본값은 본래 자리로**: 상호작용은 `Self`, 이벤트는 `Linked`.
- **경고는 「선언했는데 비었다」에만**: Self인데 오너가 장치가 아님 / Child인데 이름 미지목 / Linked인데 배선이 빔. Actor인데 지목이 빈 것은 퀘스트 스텝의 옵션 미사용 계약이라 조용히 통과한다.
- **배치 대상 칸을 `LinkedDevices` 로 개명**: 태스크가 고르는 값이 아니라 오너 배선의 거울이라 이름을 원본에 맞췄다. 개명으로 끊긴 바인딩은 Context Actor 소스로 다시 걸었다 — 그 소스 ID 는 엔진 상수(`StateTreeComponentSchema.cpp` 의 `ContextDataDescs`, `1D971B00-2888-4FDE-B543-680236984FD5`)라 에셋마다 찾을 필요가 없다.

### 계획 대비 달라진 점
- enum 열거자에 붙였던 한글 `UMETA(DisplayName=...)` 은 걷어냈다(사용자 편집 반영). README 표기도 열거자 이름으로 맞췄다.
- **에셋 작업 도중 남의 개명이 만든 데이터 소실 위험을 만나 순서를 바꿨다.** 작업 트리에 들어와 있던 별건의 구조체 개명(`FWxComponentName` → `FWxStateTreeComponentName`)에 CoreRedirect 가 없어, 에디터에 로드된 ST 에셋의 컴포넌트 지목이 전부 None 으로 죽어 있었다(디스크엔 멀쩡). 그 상태로 저장하면 영구 소실이라 `ST_Door`·`ST_Elevator`·`ST_Piston` 저장을 멈추고, 같은 에디터를 쓰는 두 세션과 조율해 `StructRedirects` 반영 → 종료·빌드·재시작 후에 마저 처리했다. 재시작 직후 `Trigger`·`ButtonDevice_1F/2F/Lift`·`DoorLeft`/`PlatformRoot`/`Cylinder` 가 되살아난 것을 확인하고 이어 갔다.
- 저장 순서를 둘로 나눴다(안전한 `ST_Button`·퀘스트 스텝 먼저, 나머지는 리다이렉트 후). 남의 세션과 에디터를 공유하는 동안엔 저장이 곧 남의 인메모리 상태까지 디스크에 싣는 행위라는 것도 함께 확인했다.

### 검증
- `WxEditor(Development)` 빌드 `Result: Succeeded`(에디터 재시작 포함, 마지막 빌드에 enum 편집분과 다른 세션의 에디터 코드가 함께 들어갔다).
- 에셋 6개 컴파일 `succeeded` 를 툴 반환값이 아니라 `LogStateTreeEditor` 신규 엔트리로 확인, 저장 후 재조회로 값·바인딩 온전함 확인(문 2·엘리베이터 8 노드가 `Child`+각자 버튼 이름, 피스톤 2 노드가 `Linked`+Context Actor 바인딩, 퀘스트 스텝이 `Actor`).
- 디스크 기록 확인: `ST_Elevator` 에 `ButtonDevice_1F/2F/Lift` 보존, `ST_Button`·`ST_Piston` 의 옛 `TargetDevices` 경로가 `LinkedDevices` 로 교체됨.
- 에디터 기동 후 `LogWxWorld` 경고·에러 0건, StateTree 컴파일 실패 0건.

### 후속 과제
- 사람 확인: 디테일 패널에서 `TargetKind` 를 바꿨을 때 안 쓰는 칸이 실제로 감춰지는지(바인딩 배열·컴포넌트 드롭다운 포함). 코드로는 확인할 수 없는 부분이다.
- PIE(`LV_DevCombat`): 문 버튼 여닫기 / 배치 버튼 → 피스톤 3대 이동 후 버튼 해제 / 엘리베이터 첫 가동·층·내부 버튼 / 퀘스트 스텝 진입 시 NPC 상호작용이 열리고 상호작용으로 스텝 완료.
