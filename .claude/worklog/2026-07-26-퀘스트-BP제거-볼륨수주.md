# 퀘스트 C++ 전용 구조 — BP 제거 + QuestStartVolume + UWxQuestStateTree

## 계획

### 목표
BP_QuestComponent(역할: GM_Combat 주입 클래스 + InitialQuest 기본값)를 제거해 퀘스트 시스템을 C++ 전용 구조로 전환한다. 퀘스트 ST 다수화에 대비해 수주(탑재)를 레벨 배치 볼륨으로 옮기고, 퀘스트 ST 를 `UWxQuestStateTree` 서브클래스로 타입 구분한다. 신원 태그는 소비처가 없어 넣지 않는다(필요 시 서브클래스에 비파괴 추가).

### 접근 방식
- **볼륨 = 탑재(arm), 시작은 게이트**: 볼륨 진입은 러너에 ST 를 올리는 것까지만 하고, 진행 개시는 각 퀘스트의 Start 게이트(OnEvent Quest.Start ← 생존자 대화)가 판정한다. 볼륨이 시작 이벤트까지 쏘면 대화 없는 개시가 되어 기존 첫 수주 흐름과 충돌한다.
- **진입 정책**: 같은 퀘스트 재진입 무시(진행 리셋 방지), 다른 퀘스트 진행 중(저널 활성) 무시(강탈 금지), 그 외 교체(마지막 볼륨 승리). 가드는 소프트 경로 비교로 로드 없이 판정.
- **타입 마커 서브클래스**: 지정 필드·API 가 퀘스트 ST 만 받아 기믹 ST 오지정을 차단하고, 추후 메타데이터의 자리가 된다. 퀘스트 1개인 지금이 전환 비용 최저점.
- 알려진 한계(보류): 완료 퀘스트 볼륨 재진입 시 재탑재 — 완료 이력은 세이브 도입 시 함께.

### 구현·결정과 그 이유
- **팩토리는 엔진 상속으로 충분**: 생성 헤더가 MinimalAPI 클래스라도 생성자를 모듈 API 로 내보내는 것을 실측 — 자체 UFactory 재구현 없이 SupportedClass 교체 + 생성자에서 스키마 고정(컴포넌트 러너 전제)으로 끝. 스키마 픽커도 생략된다.
- **탑재 기록은 컴포넌트가 자체 유지**: 러너가 현재 에셋을 공개하지 않아, 유일 탑재 경로인 StartQuest 가 직접 기록하고 Running 이탈 시 저널과 함께 비운다. 볼륨 가드는 소프트 경로 비교라 로드 없이 판정.
- **StartNextQuest 완성**: 태스크 본체 없이 인스턴스 데이터만 남은 미완 상태를 발견, 체인 경로(설계 ②)가 성립하도록 이번에 구현.
- **재작성 시 상태 ID 복사**: 전이는 상태 ID 로 링크되므로 구 에셋 ID 를 그대로 옮겨 전이 정의를 원본과 동일하게 보존.
- PIE 실측: 시작 시 러너 비어 있음 → 볼륨 진입 시 탑재(StateTreeRef=ST_Quest_Main1) → 이탈·재진입 시 러너 무반응(Verbose 로그로 정지·재시작 부재 확인, 같은 시점 기믹 ST 로그는 출력됨).

### 계획 대비 달라진 점
- 재작성 대상에 MarkIndicator 포함 — 그 사이 병행 세션이 Step1 에 재배치해 둔 것을 그대로 이식.
- MCP 상태 신설 문법 확립: Children 배열 원소에 클래스 refPath 를 주면 인스턴스 생성. 기존 원소가 있는 배열은 증가+값 기입이 모호 판정이라 먼저 빈 배열로 비운 뒤 재기입.
- 팩토리 메뉴 항목이 스톡과 같은 "StateTree" 표시명으로 AI 카테고리에 나란히 등장(표시명은 부모 에셋 정의를 따름) — 구분은 클릭 시 스키마 픽커 유무. 표시명 분리는 후속 과제.

### 후속 과제
- Add 메뉴에서 두 "StateTree" 항목 구분이 안 됨 — UAssetDefinition(또는 GetDisplayName 오버라이드)으로 "Wx Quest" 표시명 부여 검토.
- 완료 퀘스트 볼륨 재진입 시 재탑재(재플레이) — 완료 이력은 세이브 시스템 도입 시 함께.
- 대화(Quest.Start) → 저널 등장까지의 E2E 는 기존 검증 유지(이번 변경으로 흐름 불변).
