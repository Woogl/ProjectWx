# 캐릭터 베이스 도달 불가 널 검사 정리

## 계획

### 목표
`AWxCharacterBase` 가 헤더에서 "생성자 서브오브젝트라 널이 아니다"는 불변식을 선언해 두고도 `EquipmentComponent`·`WeaponActor` 만 네 곳에서 널 검사를 한다. 도달 불가 분기라 읽는 쪽에 잘못된 신호를 주므로 걷어내고, 불변식 주석이 서브오브젝트 전체를 덮게 한다. (`module_review_WxGame.md` 발견 6)

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.cpp` | 널 검사 4곳 제거 (`:89`, `:94`, `:169`, `:304`) | 수정 |
| `Source/WxGame/Character/WxCharacterBase.h` | 불변식 주석을 `AbilitySystemComponent` 전용에서 서브오브젝트 블록 전체로 이동 | 수정 |

### 접근 방식
- **검사 제거 쪽을 택한 이유**: 리뷰는 검사 제거와 주석 수정 두 갈래를 제시했지만, 불변식이 실제로 성립하므로 주석 수정은 사실이 아닌 내용을 적고 무가드 역참조 11곳에 가드를 덧대는 방향이 된다.
- **불변식 성립 근거**: 네 서브오브젝트 모두 조건 없는 `CreateDefaultSubobject` 이고, 저장소 전체에 `DoNotCreateDefaultSubobject` 호출이 없으며, 파생 3종은 `ObjectInitializer` 를 그대로 `Super` 로 넘기기만 한다. `EquipmentComponent`·`WeaponActor` 는 `WxCharacterBase.cpp` 밖에서 참조되지 않아 영향이 파일 안에 갇힌다.
- **자식 액터 널 검사는 유지**: `WeaponActor->GetChildActor()` 의 널 가능성(초기 복제 타이밍)은 별개의 실재 조건이다. `:169` 는 `Cast` 가 널 입력에 널을 반환하므로 컴포넌트 검사만 걷어도 동작이 같다.
- **주석 위치 교정**: 주석이 한 필드에만 붙어 있어 나머지 서브오브젝트엔 규약이 없는 것처럼 읽혔고 그 틈이 이번 불일치를 낳았다. `protected:` 직후 블록 주석으로 올린다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxCharacterBase.cpp` | `EquipmentComponent`·`WeaponActor` 널 검사 4곳 제거 | 수정 |
| `Source/WxGame/Character/WxCharacterBase.h` | 불변식 문장을 필드 doc 에서 클래스 doc 으로 이동 | 수정 |

### 구현·결정과 그 이유
- **불변식 문장을 클래스 doc 으로 올렸다**: 처음엔 `protected:` 직후 블록 주석으로 두려 했으나, UHT 가 UPROPERTY 앞 주석을 툴팁으로 집어가므로 빈 줄을 끼워도 `AbilitySystemComponent` 한 필드의 설명처럼 읽힐 여지가 남는다. 클래스 doc 은 그런 결합이 없어 "이 클래스 전체의 규약"이라는 의도가 그대로 전달된다.
- **문구를 "서브오브젝트 멤버"로 넓혔다**: `CombatAttributeSet` 은 컴포넌트가 아니지만 같은 생성자 서브오브젝트라 같은 규약을 따른다.
- **자식 액터 널 검사는 남겼다**: `GetEquippedWeapon` 에서 걷어낸 건 컴포넌트 자신에 대한 삼항뿐이고, `Cast` 가 널 입력에 널을 반환하므로 자식 액터 미스폰 케이스는 종전대로 처리된다.

### 계획 대비 달라진 점
- 주석 위치를 `protected:` 블록 주석 대신 클래스 doc 으로 바꿨다 (위 UHT 툴팁 사유).
