# LV_OpenWorld 맵 이름 대소문자 정정

## 계획

### 목표
오픈월드 맵을 열 때마다 레벨 이름이 `LV_Openworld`(소문자 w)로 되돌아가는 문제를 없앤다. 디스크의 파일·폴더 이름만 소문자라서 생기는 현상이므로, 디스크 이름을 패키지 내용과 같은 `LV_OpenWorld`로 맞춘다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/Maps/LV_Openworld.umap` | `LV_OpenWorld.umap`으로 리네임 | 수정 |
| `Content/__ExternalActors__/Maps/LV_Openworld/` | `LV_OpenWorld/`로 리네임 (153개 패키지) | 수정 |
| `Content/__ExternalObjects__/Maps/LV_Openworld/` | `LV_OpenWorld/`로 리네임 (5개 패키지) | 수정 |

### 접근 방식
- **원인**: 에디터가 보여주는 레벨 이름은 패키지 이름이고, 패키지 이름은 디스크 파일명에서 나온다. 월드 오브젝트 자체는 계속 대문자 표기였고 소문자로 보이던 것은 파일명이었다. 에디터 개인 설정에 기록된 경로가 패키지만 소문자이고 오브젝트는 대문자인 형태라 이를 뒷받침한다.
- **`PostLoad` 강제 리네임은 무관**: `UWorld::PostLoad`에 월드 이름을 패키지 이름에 맞추는 분기가 있지만, 비교에 쓰는 `FString`의 `!=`가 대소문자를 무시해서 케이스만 다른 지금 상황에서는 발동하지 않는다. 즉 오브젝트 이름이 훼손되고 있던 것은 아니다.
- **디스크 리네임만으로 충분**: 맵과 External Actor/Object 패키지의 *내용*은 이미 전부 대문자 W 표기를 쓰고 있고, 프로젝트 내 다른 에셋 중 이 맵을 참조하는 것은 없다. 따라서 바이너리를 건드릴 필요 없이 파일·폴더 이름만 바꾸면 정합성이 맞는다.
- **에디터 리네임을 쓰지 않는 이유**: 콘텐츠 브라우저 리네임은 대상 경로 존재 여부를 대소문자 무시로 검사해서 케이스만 다른 리네임을 거부한다. 게다가 월드 파티션 맵이라 리다이렉터와 External Actor 이동까지 얽힌다.
- **git 처리**: `core.ignorecase=true`라 케이스만 바뀐 변경을 감지하지 못한다. 임시 이름을 거쳐 두 단계로 `git mv`해서 인덱스에 확실히 반영한다.

## 완료

| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Content/Maps/LV_OpenWorld.umap` | 소문자 w 파일명에서 리네임 | 수정 |
| `Content/__ExternalActors__/Maps/LV_OpenWorld/` | 폴더 리네임 (하위 패키지 153개) | 수정 |
| `Content/__ExternalObjects__/Maps/LV_OpenWorld/` | 폴더 리네임 (하위 패키지 5개) | 수정 |
| `Content/Maps/LV_OpenWorld_HLOD0_Instancing.uasset` | 파일 리네임 + 내부 이름 표기 5곳 바이트 패치 | 수정 |
| `Content/Maps/LV_OpenWorld.umap` | HLOD 레이어 참조 표기 2곳 바이트 패치 | 수정 |

### 구현·결정과 그 이유
- **맵과 External 패키지는 파일명만 고침**: 이쪽은 내부 표기가 이미 전부 대문자 W였고 참조하는 다른 에셋도 없어서, 디스크 이름을 맞추는 것만으로 어긋남이 사라진다.
- **HLOD 레이어는 바이트 패치 병행**: 이 에셋만은 파일명과 내부 표기가 모두 소문자였다. 파일만 바꾸면 맵의 참조가 끊기고, 콘텐츠 브라우저 리네임은 케이스만 다른 경로를 거부한다. 그래서 이름 문자열의 `w` 한 바이트만 대문자로 바꿨다. 길이가 그대로라 패키지 서머리의 오프셋이 전부 유효하고, 이름 뒤에 붙는 해시 2개는 엔진이 버리는 값으로 읽어 검증에 쓰지 않는 것을 코드로 확인한 뒤 진행했다.
- **두 단계 `git mv`**: 저장소가 대소문자를 무시하도록 설정돼 있어 한 번에 바꾸면 인덱스가 변경을 못 알아챈다. 임시 이름을 경유해 리네임 159건을 스테이징에 확실히 올렸다.
- **검증**: NTFS 실제 표기가 대문자 W임을 확인했고, `Content` 전체를 재스캔해 소문자 표기가 아래 HLOD 에셋 하나만 남았음을 확인했다. 짝으로 리네임해야 할 `_BuiltData` 패키지는 존재하지 않는다.
- **로드 검증**: `-run=PkgInfo`로 두 패키지의 헤더를 실제로 파싱시켰다. 오류 없이 읽혔고, 맵이 참조하는 패키지 목록에 대문자 표기의 HLOD 레이어와 External Actor 경로가 파일명 그대로 나온다.
- **부수 효과 점검**: 이 맵을 참조하는 에셋·설정·코드가 없어 리다이렉터가 필요 없다. 에디터 빌드는 FName이 인스턴스별로 케이스를 보존하므로, 옛 경로가 남은 에셋 레지스트리 캐시가 표시 이름을 소문자로 되돌리지는 않는다. 오히려 전에는 External Actor 폴더명(소문자)과 패키지 내부 표기(대문자)가 어긋나 있어 대소문자를 구분하는 파일시스템에서 깨질 수 있었고, 이번 리네임으로 그 잠재 문제도 사라졌다.

### 계획 대비 달라진 점
- HLOD 레이어 에셋까지 범위를 넓혔다. 처음에는 자동 생성물이라 놔두려 했는데, 참조 표기와 파일명이 함께 소문자여서 정리하려면 바이트 패치가 필요했다.
- 작업 도중 에디터가 실행 중이라 HLOD 에셋 파일이 잠겨 한 번 막혔다. 프로세스 이름을 `UnrealEditor`로만 조회해서 DebugGame 구성을 놓친 탓이다. 다음부터는 접미사까지 포함해 확인한다.
