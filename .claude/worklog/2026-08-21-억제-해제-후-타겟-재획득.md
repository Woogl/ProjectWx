# 억제 해제 후 타겟 재획득

## 계획

### 목표
리시 복귀가 끝나며 타겟팅 억제(disengage)를 풀어도, 억제 내내 시야에 있던 대상은 재획득되지 않아 AI 가 눈앞의 플레이어를 무시하고 굳는다. Sight 퍼셉션이 엣지 트리거라 억제 중 흘려보낸 자극 이후 새 자극이 오지 않는 것이 원인이다. 억제 해제 시점에 현재 감지 상태를 직접 읽어 타겟을 다시 잡는다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | `SetTargetingSuppressed` 의 해제 분기에서 `PerceptualData` 를 순회해 현재 감지 중인 첫 유효 대상을 타겟으로 세운다 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | `SetTargetingSuppressed` 의 `false:` 주석을 실제 동작으로 정정 | 수정 |

### 접근 방식
- **레벨 읽기로 엣지 공백을 메움**: `UAISense_Sight` 는 `NotifyType = OnPerceptionChange` 라 감지 여부가 바뀔 때만 `OnTargetPerceptionUpdated` 를 방송한다. 억제 해제 후 다시 올 엣지가 없으므로, 엔진이 이미 유지 중인 `PerceptualData` 를 그 시점에 한 번 직접 조회한다.
- **기존 API·가드 재사용**: `GetPerceptualDataConstIterator()` / `HasAnyCurrentStimulus()` 는 `UAIPerceptionComponent` 의 public API 이고, 사망 가드는 획득 경로와 같은 `IsActorDead` 를 쓴다. 새 메서드·필드를 늘리지 않는다.
- **`UpdateRecognition()` 을 분기 밖으로**: 억제 중이면 자연히 off, 해제 후엔 재획득 결과를 따르므로 두 경로가 한 호출로 합쳐진다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxAI/Source/WxAI/Private/WxAIPerceptionComponent.cpp` | `SetTargetingSuppressed` 해제 분기에서 `PerceptualData` 를 순회해 현재 감지 중인 첫 유효 대상을 타겟으로 세우고, `UpdateRecognition()` 호출을 분기 밖으로 이동 | 수정 |
| `Plugins/WxAI/Source/WxAI/Public/WxAIPerceptionComponent.h` | `SetTargetingSuppressed` 의 `false:` 주석을 실제 동작(현재 감지 상태 직접 조회)과 그 이유로 정정 | 수정 |

### 구현·결정과 그 이유
- **엣지 대신 레벨을 읽는다**: `UAISense_Sight` 는 `NotifyType = OnPerceptionChange` 이고, `ProcessStimuli` 는 `WasSuccessfullySensed()` 값이 바뀔 때만 방송한다. 가시 상태가 유지되면 성공 자극이 매 쿼리 재등록되어도 방송이 없으므로, 억제 중 흘려보낸 엣지 이후에 다시 올 엣지가 없다. 해제 시점에 엔진이 이미 유지 중인 `PerceptualData` 를 한 번 조회하는 것이 이 공백을 메우는 최소 수단이다.
- **`HasAnyCurrentStimulus()` 를 판정으로**: 만료되지 않은 성공 자극이 남은 대상만 본다. `HasAnyKnownStimulus()` 로 기억까지 집으면 억제 중 시야를 벗어난 대상도 되살아난다. 센스를 가리지 않으므로 Hearing/Damage 의 같은 함정도 함께 덮인다.
- **새 메서드·필드 없음**: `GetPerceptualDataConstIterator()` / `HasAnyCurrentStimulus()` 는 `UAIPerceptionComponent` 의 public API 이고 사망 가드는 획득 경로의 `IsActorDead` 를 그대로 쓴다. 임시 배열을 채우는 `GetCurrentlyPerceivedActors` 대신 인라인 순회 + 첫 성공에서 break 로 끊었다.
- **적대 필터를 두지 않음**: Sight/Hearing 은 `DetectionByAffiliation` 로 이미 걸러 등록되고, 기존 엣지 획득 경로에도 필터가 없다. 여기만 조건을 더하면 두 경로의 획득 기준이 갈린다.
- **경계 왕복 없음**: `UWxBTDecorator_BeyondLeash` 의 `FlowAbortMode` 가 `LowerPriority` 라 복귀 브랜치는 자기중단되지 않는다. 억제 해제는 폰이 홈(리시 안)에 도착한 뒤 일어나므로 재획득해도 이탈 판정이 곧바로 서지 않는다.

### 후속 과제
- 다수 대상이 동시에 감지되면 `TMap` 순회 첫 대상을 잡는다. "가장 가까운 적" 같은 선택 정책이 필요해지면 이 경로만이 아니라 엣지 획득 경로(`HandleTargetPerceptionUpdated`)와 함께 넣어야 한다.
- 인게임 확인 미수행 — 시야를 유지한 채 복귀 완료 시 즉시 재-어그로되는지 확인 필요.
