# 상태별 상호작용 프롬프트

## 계획

### 목표
엘리베이터·보물상자 등이 상태별로 다른 상호작용 프롬프트(`Call Elevator`/`Move`/`Open` 등)를 표시하도록, 디자이너가 **C++ 수정 없이 ST 에셋에서** 프롬프트를 author할 수 있게 한다. 별도 태스크를 새로 만들지 않고 이미 상태마다 있는 `Wx Enable Interaction` 태스크에 `Prompt` 필드를 얹어, 상호작용을 켜는 그 자리에서 프롬프트를 함께 지정한다.

### 배경
프롬프트는 스캐너가 매 스캔 `IWxInteractable::GetInteractionPrompt()`로 pull한다(`WxInteractionScannerComponent.cpp:79`). 지금 기믹은 베이스의 고정 `InteractionPrompt` 하나만 반환한다(`WxGimmick.cpp:72-75`). `GetInteractionPrompt()`가 현재 상태에 맞는 값만 돌려주면 UI는 자동 갱신된다.

### 접근 방식
- **저장은 기믹 로컬 멤버, 복제 없음**: ST는 모든 피어에서 실행되고 EnableInteraction의 EnterState는 각 피어 로컬에서 돈다(이미 메시 콜리전을 각 피어에서 토글). 스캐너도 로컬 클라 pull이라 같은 피어 액터 사본에서 저장·조회 → 복제 불필요. State가 복제되어 각 피어 ST가 같은 상태로 수렴하므로 표시 일치.
- **bEnable=true일 때만 프롬프트 적용**(사용자 결정): 비활성 메시는 스캔에 안 잡혀 프롬프트 불필요. `meta=(EditCondition="bEnable")`로 필드 그레이아웃, stale 방지.
- **복원 게이팅 없음**: EnableInteraction은 선언형 상태라 IsInitialOrRestoreEntry로 막지 않고 모든 진입에서 적용된다 — 프롬프트도 그 흐름을 타 복원·late-join에서 맞게 세팅됨.
- **폴백 보존**: 프롬프트 미지정이면 멤버가 비어 기존 InteractionPrompt 기본값 반환. 동작 변화 없음.
- **bConsideredForCompletion은 손대지 않음**: EnableInteraction의 이 플래그 미설정(베이스 기본 true, doc는 false 주장 — review 🟡 발견 4)은 8개 에셋에 파급되는 별도 사안. 프롬프트 추가와 무관하게 완료 동작 불변 유지.
- **프롬프트는 액터 단위**(기존 설계): 다중 상호작용 메시가 동시 활성이면 마지막 EnableInteraction이 이김 — 대상 기믹(단일 메시)에선 비이슈. 한계로 문서화.

### 구현·결정과 그 이유
- **새 태스크 대신 EnableInteraction 확장**(사용자 결정): 상태마다 이미 EnableInteraction이 있으므로 필드만 채우면 되고, "상호작용 가능 + 프롬프트"가 한 자리에 모인다. 별도 태스크·별도 배치가 불필요해 더 간편하다.
- **프롬프트는 복제 없는 로컬 멤버**: ST가 각 피어에서 실행되어 EnterState가 로컬로 세팅하고 스캐너도 로컬 pull이라 같은 피어에서 저장·조회가 닫힌다. State 복제가 각 피어를 같은 상태로 수렴시켜 표시가 일치한다. anim/collision 토글과 동형.
- **bEnable=true일 때만 세팅**(사용자 결정): 비활성 메시는 스캔에 안 잡혀 프롬프트가 무의미. `meta=(EditCondition="bEnable")`로 필드 그레이아웃, 비활성 상태에서 stale 값을 남기지 않음.
- **캐스트 실패 시 콜리전 토글은 유지**: 비기믹 오너 ST에서도 EnableInteraction이 계속 동작하도록 프롬프트만 스킵. 기존 "메시 토글" 책임을 보존.
- **폴백**: 프롬프트 미지정이면 `CurrentInteractionPrompt`가 비어 `InteractionPrompt` 기본값 반환 → 프롬프트를 안 쓰는 기존 기믹 동작 불변.
- **bConsideredForCompletion 미변경**: EnableInteraction의 이 플래그 미설정(베이스 기본 true, doc는 false 주장 — review 🟡 발견 4)은 8개 에셋에 파급되는 별도 사안. 이번엔 프롬프트 필드만 얹어 완료 동작을 바꾸지 않음.
