# BP_Door 내장 발동 장치 (ChildActorComponent)

## 계획

### 목표
`BP_Door`가 ChildActorComponent로 발동 장치(레버) 하나를 기본 내장하게 한다. 지금은 문 배치 → 레버 별도 배치 → 레버 `LinkedDevices` 배선까지 세 단계를 손으로 해야 하는데, 문 하나만 배치하면 레버와 배선이 따라오게 하는 기획 데이터 작업 편의가 목적이다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/.../Private/Device/WxTriggerDevice.cpp` | BeginPlay 차일드 액터 자동 배선 — 자기를 스폰한 ChildActorComponent 의 오너가 `AWxDevice` 면 `LinkedDevices` 에 자동 추가 | 수정 |
| `Content/WorldObject/Gimmick/BP_Door.uasset` | ChildActorComponent `Trigger` 추가(루트 부착), ChildActorClass=`BP_LeverDevice` (MCP) | 에셋 |
| `Content/Maps/LV_DevCombat.umap` | 기존 배치 레버 삭제 — 내장 레버와 중복 방지 (MCP) | 에셋 |
| `Plugins/WxWorld/README.md` | 발동 장치 연결 항목에 child actor 자동 배선 추가, 낡은 `Gimmicks` 명칭을 `LinkedDevices` 로 정정 | 문서 |

### 접근 방식
- **링크는 런타임 자동 해석**: `LinkedDevices` 는 `EditInstanceOnly` 레벨 액터 참조라 CAC 템플릿(에셋 아키타입)이 자기를 소유할 문 인스턴스를 지목할 수 없다. 대신 레버 `BeginPlay` 가 `GetParentComponent()` 로 부착 관계를 읽어 오너 장치를 `AddUnique` 한다 — 발동 장치 공통부라 향후 버튼 내장 엘리베이터 등에도 그대로 성립한다.
- **멀티플레이 반증 검증**: UE 5.8 `ChildActorComponent.cpp:748` — 비권위 피어는 복제 child class 를 스폰하지 않고 서버 복제분을 받으며 `AActor::ParentComponent` 는 비복제라, 리모트 클라의 자동 배선은 빈다. 영향은 `GimmickStateRequirements` 프롬프트 게이트뿐(기본 빈 값, 실제 차단은 서버 검증)이라 '상호작용 켜기' 태스크와 같은 싱글/리슨 호스트 전제로 수용.
- **기본 상대 트랜스폼**: LV_DevCombat 의 기존 배치 레버↔문 오프셋을 읽어 CAC 기본값으로 재사용.

### 구현·결정과 그 이유
- **로컬 변수명 `SpawningComponent`**: `ParentComponent` 는 `AActor` 멤버와 이름이 겹쳐 C4458(섀도잉)이 에러로 잡힌다.
- **BP_Door 의 기존 빈 `ChildActor` 컴포넌트 제거**: BP 에 클래스 미지정 ChildActorComponent 스텁이 이미 있었다(앞선 수동 시도로 추정). 아무 동작 없는 죽은 노드라 `Trigger` 하나로 정리했다.
- **CAC 기본 트랜스폼은 기존 배치 재사용**: LV_DevCombat 의 레버↔문 오프셋 (150,-240,0)·Yaw 90 을 그대로 CAC 기본값으로 옮겨, 내장 레버가 기존 자리 그대로 스폰됨을 PIE 로 확인했다.
- **저작 중 인스턴스 꼬임은 레벨 재로드로 해소**: MCP 로 템플릿을 단계 수정하는 동안 배치 문 인스턴스가 재구성 캐시(빈 ChildActorClass·트랜스폼)를 보존해 템플릿 값을 물려받지 못했다. 디스크 인스턴스는 깨끗함을 확인하고 BP 저장 → 레벨 재로드로 메모리를 버려 해결 — 인스턴스에 오버라이드가 남지 않아 이후 배치 문들도 템플릿을 그대로 상속한다.

### 계획 대비 달라진 점
- BP_Door 에 이미 있던 빈 `ChildActor` 스텁 제거가 추가됐다(위 참조). 나머지는 계획대로.

### 검증
- WxEditor(Development) 빌드 성공.
- PIE 2회: 발동 장치가 정확히 1개(문 내장 차일드 레버)이고 위치 (-1940,-3860,0)·Yaw 90 으로 기존 배치 자리와 일치. 금일 세션 Wx·StateTree 에러/경고 0건.

### 후속 과제
- 실행 중 에디터는 구(DebugGame) 바이너리라 자동 배선 C++ 미탑재 — 레버→문 열림 전체 흐름은 에디터 재실행(재빌드 포함) 후 PIE 로 확인해야 한다.
- 리모트 클라이언트에서 복제 child 는 `ParentComponent` 미복제로 자동 배선이 비지만, 눌림 전달은 권위 전용이라 무관(코드 주석에 명시). 데디케이트 전환 시 재검토.
