# DP 반사 전용 GE 제거

## 계획

### 목표
퍼펙트 가드 DP 반사가 전용 GE(`UWxEffect_Reflect`) 하나와 SetByCaller 태그 하나를 쓰고 있다. 반사량을 어트리뷰트에 직접 써서 두 기계장치를 모두 없앤다. 전제는 DP 변경 시의 그로기 판정을 GE 실행 전용 훅에서 어트리뷰트 변경 훅으로 옮기는 것이다.

조사에서 확인한 두 가지가 이 전환을 가능하게 한다.

* DP 클램프는 이미 `PreAttributeChange`에 있고, 이 훅은 GE 실행이든 직접 쓰기든 모든 현재값 변경 경로에서 호출된다. `PostGameplayEffectExecute`의 DP 클램프는 이미 중복이다.
* `PostAttributeChange` 역시 모든 현재값 변경 경로에서 호출된다. 그로기 토글을 여기로 옮기면 GE를 거치지 않는 쓰기에서도 판정이 걸린다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|

### 접근 방식
- **그로기 토글을 값 변경 지점으로**: 그로기는 DP가 상한에 닿았다는 신호이므로 DP가 바뀌는 곳에서 발행하는 것이 맞다. 훅을 옮기면 반사가 GE를 거칠 이유가 사라지고, 덤으로 `DrainDP`·`ResetDP` 등 다른 DP 경로도 같은 판정을 공유한다.
- **권위 측 가드 필수**: `PostAttributeChange`는 클라이언트의 복제 수신(OnRep) 경로에서도 호출된다. 현재 그로기 태그는 서버가 붙여 복제되므로, 가드 없이 옮기면 클라이언트가 같은 태그를 중복으로 얹어 카운트가 어긋난다.
- **클램프는 건드리지 않는다**: DP 클램프는 이미 `PreAttributeChange`에 있으므로 중복 코드만 지운다. HP/MP/SP/UP 클램프는 현재 위치 그대로 둔다. 이들은 실행 후 현재값을 다시 죄는 성격이라 옮기면 의미가 달라진다.
- **반사는 베이스 값 가산**: `GetNumericAttributeBase`로 읽어 더한 값을 `SetNumericAttributeBase`로 쓴다. 둘 다 순정 API이고 프로젝트가 이미 어트리뷰트 초기화에 쓰는 경로다.

### 구현·결정과 그 이유
- **그로기 토글을 `PostAttributeChange`로**: 계획은 베이스 변경 훅을 지목했지만 실제로는 현재값 변경 훅이 맞았다. 이 클래스가 이미 오버라이드하고 있고, 베이스 훅과 달리 const가 아니어서 상태 변경에 자연스럽다. 엔진이 현재값을 쓰는 모든 경로에서 호출하므로 커버리지도 동일하다.
- **권위 측 가드**: 이 훅은 클라이언트의 복제 수신 경로에서도 돈다. 가드 없이 두면 서버가 붙여 복제한 그로기 태그 위에 클라이언트가 같은 태그를 또 얹어 카운트가 어긋나고 해제가 실패한다. `IsOwnerActorAuthoritative`가 GAS 관용 표현이라 `AActor`를 완전 타입으로 요구하지 않는 이점도 있다.
- **클램프 코드는 삭제만**: DP 클램프는 이미 `PreAttributeChange`에 있어서 `PostGameplayEffectExecute` 쪽은 순수 중복이었다. 옮길 것이 없어 지웠다.
- **베이스 값으로 가산**: DP에는 지속형 모디파이어가 없어 베이스와 현재값이 같지만, 쓰는 쪽이 `SetNumericAttributeBase`이므로 읽기도 베이스로 맞춰 짝을 지었다. `ApplyModToAttributeUnsafe`는 이름이 말하는 대로 순정 GE 경로를 벗어나므로 쓰지 않았다.
- **헬퍼 추출 안 함**: 그로기 토글을 별도 함수로 뽑았다가 되돌렸다. 호출 지점이 한 곳이라 기존 분기 구조를 그대로 옮기는 편이 읽기 쉽다.

### 계획 대비 달라진 점
- 그로기 토글 위치를 `PostAttributeBaseChange`에서 `PostAttributeChange`로 바꿨다(위 이유).
- DP 클램프를 `PreAttributeBaseChange`로 옮길 계획이었으나, 이미 `PreAttributeChange`에 있어 이동 없이 중복 제거로 끝났다.

### 후속 과제
- 인게임 검증 미완: 퍼펙트 가드 반사로 그로기 진입, `WxAbility_Groggy`의 DrainDP로 DP가 0까지 빠졌을 때 그로기 해제, `WxEffect_ResetDP`(앞잡 후 DP 0)에서의 해제를 확인해야 한다. 세 경로 모두 훅 이동의 영향을 받는다.
