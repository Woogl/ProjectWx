# 적 후방 접근 시 백스탭(Finisher) 상호작용 복원

## 계획

### 목표
`IWxInteractable` 계약 단순화(5f13671d)로 주체 인자가 사라지며 함께 떨어져 나간 후방 판정을 되살려, 비전투 상태의 적 뒤로 접근하면 처형 프롬프트가 뜨고 백스탭이 나가게 한다. 단순화한 인자 없는 `CanInteract()`는 그대로 두고, 잔재가 된 `GetEligibleFinisherEventTag()`를 없앤다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxEnemyCharacter.h` | `GetEligibleFinisherEventTag` 선언 제거, 후방 판정 헬퍼 선언 추가, 주석 갱신 | 수정 |
| `Source/WxGame/Character/WxEnemyCharacter.cpp` | `CanInteract()`에 자격 판정 이관, `GetEligibleFinisherEventTag` 제거, `OnInteracted`는 변형 선택만 | 수정 |
| `Source/WxGame/AbilitySystem/Ability/WxAbility_Interact.cpp` | 인터페이스 병합 잔재인 중복 `CanInteract()` 호출 제거 | 수정 |

### 접근 방식
- **자격 판정의 단일 소스를 `CanInteract()`로**: 사망·연출 중이면 불가, 그로기면 방향 무관 허용(앞잡), 그 외엔 미인지(`State.InCombat` 없음) + 플레이어가 후방 원뿔 안일 때만 허용(뒤잡). 각도는 기존 `BackstabRearHalfAngle`(기본 90 = 후방 반구)을 그대로 쓴다.
- **주체는 대상이 직접 찾는다**: 계약이 주체를 넘기지 않으므로 로컬 플레이어 폰을 조회한다. 같은 파일의 보상 지급이 쓰는 관례와 같다. 클라 표시 경로에선 로컬 플레이어라 정확하고, 서버 검증 경로에선 싱글·리슨호스트 호스트 기준으로 정확하다. 데디 멀티에서 2번째 이후 플레이어의 뒤잡이 0번 기준으로 판정되는 것은 단순화를 유지하는 대가로 남긴다.
- **변형 선택은 발동 시점에**: 서버가 `CanInteract()`로 자격을 검증한 뒤 `OnInteracted`가 들어오므로, 여기선 그로기 여부만 보고 앞잡·뒤잡 이벤트 태그를 고른다. 전투 측 `UWxAbility_Finisher`는 이미 트리거 태그로 두 변형을 분기하므로 손대지 않는다.

### 구현·결정과 그 이유
- **자격을 `CanInteract` 한 곳에 모았다**: 표시(클라 스캐너)와 발동(서버 어빌리티)이 같은 함수를 지나므로 프롬프트가 뜨는 조건과 실제로 발동되는 조건이 어긋날 수 없다. 판정 입력이 전부 복제되는 값이라 머신이 달라도 답이 같다.
- **주체를 대상이 직접 찾는다**: 단순화한 계약이 주체를 넘기지 않는데 후방 판정엔 주체가 필요하다. 계약에 인자를 되돌리는 대신 로컬 플레이어 폰을 조회했다 — 보상 지급이 이미 쓰는 관례이고, 클라 표시에선 로컬 플레이어라 정확하다.
- **변형 선택을 발동 시점으로 옮겼다**: 자격이 이미 서버에서 검증된 뒤 들어오므로 앞잡·뒤잡을 가르는 정보는 그로기 여부뿐이다. 두 갈래를 태그로 돌려주던 중간 함수가 사라지고 조건식 하나로 줄었다.
- **중복 검증을 지웠다**: 활성 판정과 자격 판정이 한 함수로 합쳐졌는데 호출부는 둘 다 남아 있었다. 뜻이 같은 호출이 연달아 두 번 도는 상태였다.

### 계획 대비 달라진 점
- 계획대로. 헤더에서 쓰이지 않게 된 인클루드 한 줄을 함께 지운 것만 추가다.

### 후속 과제
- 데디케이티드 멀티에서 2번째 이후 플레이어의 뒤잡은 서버가 0번 플레이어 위치로 판정한다. 주체별 자격을 되살리려면 계약에 주체 인자를 되돌려야 하므로 단순화를 유지하는 대가로 남겼다.
- PIE 실동작(정면 접근 시 프롬프트 미노출, 인지 후 후방 접근 시 미노출, 뒤잡 몽타주 재생) 미검증.
