# 기믹 상태 소유를 AWxDevice 로 올리기

## 계획

### 목표
`UWxGimmickStateTreeComponent` 가 들고 있던 상태 소유(복제 `StateTag`·`InteractingCharacter`, 세이브 키, `IWxSavable`, 권위 발행/클라 추종)를 호스트 액터 `AWxDevice` 로 올린다. 컴포넌트는 엔진 protected 멤버가 있어야만 가능한 일(트리를 특정 상태에서 열기, 활성 태그 읽기, 라이브 전이 요청)만 남은 얇은 ST 어댑터가 된다.

부수 효과로 `IWxSavable` 을 구현한 컴포넌트가 없어져 `UWxSaveWorldSubsystem::FindSavable` 도 `IWxInteractable::Find` 와 같이 `Cast` 한 줄로 붕괴한다 — 두 계약 모두 액터 전용으로 수렴한다.

### 접근 방식
- **트리 열기는 액터가 민다**: 자동 시작을 끄고 `AWxDevice::BeginPlay` 가 `StartAtState(StateTag)` 를 부른다. 세이브 복원·스트리밍 인도 같은 함수를 다시 부르는 것이 전부다.
- **틱 결합은 컴포넌트 → 액터 한 방향**: 발행·추종은 트리 틱 직후여야 한다. 액터가 틱 선행조건으로 스스로 돌면 트리가 잠들어도 매 프레임 돌아 잠자기 최적화를 깨뜨리므로, 컴포넌트가 자기 틱 말미에 액터를 부른다.
- **`InteractingCharacter` 는 `StateTag` 와 같은 액터로**: 같은 복제 번치에 실려야 추종 전이 시점에 상태와 당사자의 짝이 맞는다.
- **서브클래스는 유지**: `InstanceData`·`StateTreeRef`·`bIsRunning`·`SetContextRequirements`·`ScheduleTickFrame`·`ConditionalEnableTick` 이 전부 `UStateTreeComponent` 의 protected 라 순정으로 대체할 수 없다.

### 호환성
- 기존 세이브의 기믹 상태는 초기화된다 — `StateTag` 가 `Record.ComponentData[컴포넌트명]` 에서 `Record.ByteData`(액터 직렬화)로 자리를 옮긴다. 레코드 키(`SaveId`=`ActorGuid`)는 그대로라 레코드는 계속 맞물린다.

### 구현·결정과 그 이유
- **상태는 액터, 트리 조작은 컴포넌트**: 무엇이 지금 상태인가·복제·저장은 전부 `AWxDevice` 로 모았다. 컴포넌트에 남은 넷(`StartAtState`·`GetActiveStateTag`·`RequestState`·`HasState`)은 `UStateTreeComponent` 의 protected 멤버(`InstanceData`·`StateTreeRef`·`bIsRunning`·`SetContextRequirements`·`ScheduleTickFrame`·`ConditionalEnableTick`)를 요구해서 밖으로 뺄 수 없는 것들뿐이다. 상호작용 배선(프롬프트·발행자·약참조 컨텍스트)은 세팅하는 쪽이 ST 태스크라 트리 곁에 남겼다.
- **틱 결합을 컴포넌트 → 액터 한 방향으로**: 발행·추종은 트리 틱 직후여야 대기 중인 발행을 소화한 결과를 본다. 액터가 틱 선행조건으로 스스로 도는 방식은 트리가 잠들어 컴포넌트 틱이 꺼져도 매 프레임 돌아 잠자기 최적화를 깨뜨리므로, 컴포넌트가 자기 틱 말미에 호스트를 부른다. 호스트가 아닌 액터에 붙으면 무동작이다.
- **자동 시작을 껐다**: 트리를 여는 시점·상태를 정하는 것이 상태를 든 액터이므로 `AWxDevice::BeginPlay` 가 `StartAtState(StateTag)` 를 부른다. 컴포넌트 BeginPlay 가 먼저 돌아 `Super::BeginPlay()` 뒤면 순서가 맞는다. `StartLogic`/`RestartLogic` 은 오버라이드하지 않았고, 직접 부르면 루트에서 시작한다는 사실을 헤더에 못박았다.
- **`InteractingCharacter` 를 `StateTag` 와 같이 옮겼다**: 둘이 같은 복제 번치에 실려야 추종 전이 시점에 상태와 당사자의 짝이 맞는다. 한쪽만 옮기면 그 성질이 깨진다.
- **`FindSavable` 이 함께 사라졌다**: `IWxSavable` 을 구현한 컴포넌트가 이것 하나뿐이었다(나머지는 액터인 `AWxSpawner`). 계약이 액터로 올라가자 컴포넌트 갈래에 사용자가 없어져 `IWxInteractable::Find` 와 같은 자리에서 붕괴했다. 다만 `Record.ComponentData` 캡처 루프는 그대로 뒀다 — 계약과 무관한 범용 직렬화 경로다.
- **`SaveId` 심기가 짧아졌다**: 액터가 자기 `ActorGuid` 를 쓰므로 오너 조회도, BP 컴포넌트 템플릿을 걸러내던 가드도 필요 없다.
- **컴포넌트 복제를 껐다**: 복제할 자기 값이 없어졌다. 액터의 `bReplicates` 는 그대로 생성자에서 켜고, 파생 BP 가 되돌린 경우의 Error 로그는 액터 BeginPlay 로 옮겼다.

### 후속 과제
- **기존 세이브의 기믹 상태는 초기화된다** — `StateTag` 가 `Record.ComponentData[컴포넌트명]` 에서 `Record.ByteData`(액터 직렬화)로 자리를 옮겼다. 레코드 키(`SaveId`=`ActorGuid`)는 그대로라 레코드 자체는 계속 맞물리고, 문·상자·체크포인트가 각자 기본 상태로 돌아간다.
- **에디터 작업이 남아 있다**(직전 작업 것과 동일): BP 4종을 `WxDevice` 로 리페어런트 → 같은 작업에서 SCS `WxGimmickStateTreeComponent` 삭제 후 상속된 `GimmickComponent` 에 ST 에셋 지정 → `LV_DevCombat`·`LV_OpenWorld`·`LevelInstance/SiegeCannonEmplacement01` 저장(이제 액터의 `SaveId` 가 심긴다) → `BP_Npc` 의 `bInteractionEnabled` 확인.
- 인게임 동작 미검증 — 빌드 확인까지만 마쳤다. 특히 확인할 것: 문·상자 여닫기, 엘리베이터 층별 잠금(레버의 `GetStateTag()` 경로), 체크포인트 세이브 → 재로드 복원, 상호작용 후 이동·몽타주 태스크가 당사자를 찾는지.
- **순정 `UStateTreeComponent` 교체는 검토 후 보류**(2026-08-21). 컴포넌트 자체 API 로는 활성 상태 조회·전이 요청이 전부 protected 라 불가능하지만, `FStateTreeWeakExecutionContext` 에 public `RequestTransition`·`SendEvent`·`GetStateTree`·`MakeStrongReadOnlyExecutionContext` 가 있어 **우회 경로는 존재한다**. 다만 그 컨텍스트는 `MakeWeakExecutionContext()` 로 트리 안에서만 발급되므로, 장치 ST 에셋마다 컨텍스트를 넘겨줄 글로벌 태스크를 심어야 한다. 기각 사유 셋: (1) 에셋에 태스크를 빠뜨리면 그 기믹의 저장·클라 수렴이 조용히 죽는다(지금은 컴포넌트만 있으면 자동), (2) 활성 태그를 읽으려면 `GetStorage()` 의 const 를 벗겨야 한다, (3) 강제 전이 복원은 초기 진입이 아니게 되어 로드 때마다 `TriggerSpawners`·`RespawnSpawners`·`PlayLevelSequence` 가 발동한다.
- 상태 태그를 컴포넌트로 되돌리는 안도 검토 후 기각 — 되돌리면 `IWxSavable` 이 함께 내려가 `FindSavable` 이 되살아나고, 순정화 선택지도 영구히 닫힌다(순정 컴포넌트엔 복제·SaveGame 프로퍼티를 얹을 자리가 없다).
- 컴포넌트의 `BlueprintSpawnableComponent` 는 여전히 남아 있다. 이제 붙여도 호스트가 아니면 아무 일이 없으므로, 위 에디터 작업이 끝난 뒤 떼는 것이 안전하다.
