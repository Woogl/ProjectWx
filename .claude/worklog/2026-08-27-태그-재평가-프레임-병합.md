# 태그 통지에 따른 재평가를 한 프레임 한 번으로 병합

## 계획

### 목표
어빌리티 VM 과 어빌리티시스템 VM 이 ASC 제네릭 태그 통지마다 즉시 재평가한다(발동 가능 판정, 소유 태그 통째 복사). 엔진은 바뀐 태그와 그 부모 태그 전부에 발화하므로 태그 몇 개를 부여하는 GE 하나에 통지가 십수 회 몰리고, 구독자 수만큼 곱해져 같은 프레임에 중복된다. 결과는 마지막 한 번과 같으므로 한 프레임 분을 모아 한 번만 돌게 한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxUI/.../MVVM/WxViewModel_Ability.h·.cpp` | 태그 통지가 발동 가능 재평가를 1회성 티커로 예약, 예약 실행 함수 추가, 해제에서 예약 취소 | 수정 |
| `Plugins/WxUI/.../MVVM/WxViewModel_AbilitySystem.h·.cpp` | 같은 방식으로 소유 태그 갱신을 병합 | 수정 |

### 접근 방식
- **예약 여부는 티커 핸들이 말한다**: 더티 bool 을 따로 두지 않고, 예약이 있으면 통지에서 그냥 나간다. 예약분은 다음 코어 티커에서 한 번 돌고 `false` 를 반환해 스스로 빠진다.
- **상시 티커를 만들지 않는다**: 예약이 있는 한 프레임에만 존재한다. 두 VM 모두 이미 같은 코어 티커를 쿨다운·남은 시간에 쓰고 있다.
- **구독은 각 VM 이 원천에서 직접**: 어빌리티시스템 VM 이 통지를 대신 받아 자식에 밀어 넣는 구조는 relay 라 택하지 않는다.
- **소유 태그는 증분 반영하지 않는다**: 통지가 부모 태그에도 오므로 증분으로 넣으면 명시 태그 컨테이너에 부모가 섞인다.

| `Plugins/WxUI/.../MVVM/WxViewModel_AbilitySystem.h·.cpp` | 같은 방식으로 소유 태그 갱신 병합 | 수정 |

### 구현·결정과 그 이유
- **더티 bool 을 두지 않았다**: 예약 여부는 티커 핸들의 유효성이 그대로 말한다. 같은 사실을 두 곳에서 관리하지 않는다.
- **상시 티커가 아니다**: 예약이 있는 한 프레임에만 존재하고 실행 후 스스로 빠진다. 두 VM 모두 이미 같은 코어 티커를 쓰고 있어 새 수단도 아니다.
- **구독 구조는 그대로**: 어빌리티시스템 VM 이 통지를 대신 받아 자식에 밀어 넣으면 구독 수는 줄지만 relay 가 된다. 각 VM 이 원천에서 직접 받되 자기 일만 모은다.
- **통지 빈도를 먼저 확인했다**: 엔진이 바뀐 태그의 부모까지 발화하므로(`GatherTagChangeDelegates`) 리뷰가 추정한 것보다 통지가 잦다 — 깊이 3 태그 하나에 3회, 태그 다섯 개짜리 GE 면 십수 회가 한 프레임에 몰린다.
- **소유 태그는 여전히 통째로 다시 읽는다**: 바뀐 태그만 넣고 빼는 증분 반영이 더 싸 보이지만, 통지가 부모 태그에도 오므로 명시 태그 컨테이너에 부모가 섞인다.
- **태그 외 경로는 손대지 않았다**: 쿨다운 GE 적용·비용 어트리뷰트 변경은 건당 한 번이고, 충전 수 변화는 이미 티커 안이라 모을 것이 없다.
