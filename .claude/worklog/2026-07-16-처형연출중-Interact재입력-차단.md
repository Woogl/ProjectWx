# 처형 연출 중 Interact 재입력 차단 (Case 2)

## 계획

### 목표
처형 몽타주가 재생되는 동안 상호작용 키를 다시 눌러 근처 다른 대상(예: 상자)을 상호작용하면 그 일반 몽타주가 처형 위에 얹히는 문제(Case 2)를 막는다. 처형이 활성인 동안 Interact 발동 자체를 차단한다. (발동 순간의 중복 = Case 1은 `bUseInteractMontage` 게이트로 이미 처리됨.)

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxCore/.../WxGameplayTags.h` / `.cpp` | `State_Finisher`("State.Finisher") 선언·정의 | 신규 태그 |
| `Plugins/WxCombat/.../WxAbility_Finisher.cpp` (생성자) | `ActivationOwnedTags.AddTag(State_Finisher)` | 수정 |
| `Source/WxGame/.../WxAbility_Interact.cpp` (생성자) | `ActivationBlockedTags.AddTag(State_Finisher)` | 수정 |

### 접근 방식
- **처형 전용 State 태그**: 처형만 활성 동안 `State.Finisher`를 발행하고 Interact이 그 태그에 막힌다. 공격/스킬은 `Ability` 부모를 차단하므로 `Ability.Interact` 태그를 쓰면 공격/스킬 중에도 막혀 스코프에 반함 → 전용 State 태그로 처형만 한정.
- **발동 순간 안 막힘 / 재입력만 막힘**: 최초 Interact 활성화 시엔 아직 태그 부재(그 안에서 처형이 활성화되며 발행) → dispatch 정상. 이후 재입력은 태그가 있어 차단.
- **코옵 정합**: 처형(ServerInitiated)이 소유 클라에도 활성화 복제되어 클라가 로컬로 태그 발행 → 클라 Interact 예측 발동도 로컬에서 차단(태그 복제 불필요).

### 구현·결정과 그 이유
- **전용 State 태그(처형만 발행)**: `Ability.Interact`를 붙이면 공격/스킬의 `Ability` 부모 차단(`WxAbility_Attack.cpp:21`)에도 걸려 스코프가 넓어짐. 처형만 발행하는 `State.Finisher`로 한정해 "처형 중에만" 차단.
- **발동 순간은 통과, 재입력만 차단**: 최초 Interact 활성화 시점엔 태그 부재(그 안에서 처형이 활성화되며 발행)라 dispatch 정상 → Case 1은 `bUseInteractMontage`가 몽타주만 스킵. 이후 재입력은 태그가 있어 `ActivationBlockedTags`에 막힘.
- **코옵 정합(태그 복제 불필요)**: 처형(ServerInitiated)이 소유 클라에도 활성화 복제되어 클라가 로컬로 태그를 발행 → 클라 Interact 예측 발동도 로컬에서 차단.
