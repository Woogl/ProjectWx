# 미사용 장비 경로 제거

## 계획

### 목표

장비(Equip) 경로는 배선만 있고 트리거 호출부가 0건인데, `AWxCharacterBase` 가 모든 캐릭터에 `UWxEquipmentComponent` 를 기본 서브오브젝트로 만들고 그 컴포넌트가 `SetIsReplicatedByDefault(true)` 라서 액터마다 쓰이지 않는 복제 등록을 소모한다. 죽은 코드가 런타임 비용을 걷고 있으므로 걷어낸다.

### 접근 방식

- **이름만 겹치는 별개 시스템 보존**: `EWxItemCategory::Equipment` 는 인벤토리 UI 탭 분류라 `UWxViewModel_Inventory` 가 기본 탭으로 쓰고, `GetEquippedWeapon()`/`WeaponActor` 는 `UChildActorComponent` 기반 무기 장착이라 이번에 걷어내는 GE 배선과 무관하다. 둘 다 남긴다. `Wx|Equipment` 카테고리도 `WeaponActor` 가 계속 쓴다.

- **범위 한정**: 리뷰 발견 4가 함께 묶은 `RemoveItemInstance` 는 장비 기능이 아니라 호출부 0건인 범용 인벤토리 API라 이번 범위에서 제외한다.

- **잔여 의존 유지**: `WxItemFragment.h` 의 `UGameplayEffect` 전방 선언은 `UWxItemFragment_Usable::Effect` 가, `WxInventory.Build.cs` 의 `GameplayAbilities` 의존은 `UseItemByDef` 의 GE 적용 경로가 계속 쓴다.

- **에셋 파급은 빌드로 안 잡힌다**: `Content/Item/DA_Katana.uasset` 이 `UWxItemFragment_Equippable` 인스턴스를 물고 있어 다음 로드에서 누락 클래스 경고와 함께 드랍된다(`EquipEffects` 가 빈 배열이라 기능 손실은 없다). 캐릭터 BP 6종은 상속받던 컴포넌트 항목을 잃는데, BP 그래프가 이를 참조하는지는 바이너리 조회로 판별할 수 없어 에디터 확인이 필요하다.

### 구현·결정과 그 이유

- **이름만 겹치는 두 시스템은 남겼다**: `EWxItemCategory::Equipment` 는 GE 배선이 아니라 인벤토리 UI 탭 분류이고 뷰모델의 기본 탭이라 건드리면 UI 가 깨진다. `GetEquippedWeapon()`/`WeaponActor` 도 ChildActor 기반 무기 장착이라 실사용 경로다. `Wx|Equipment` 카테고리는 `WeaponActor` 가 계속 쓰므로 유지했다.

- **`RemoveItemInstance` 는 제외했다**: 리뷰가 같은 발견에 묶었지만 장비 기능이 아니라 호출부 0건인 범용 인벤토리 API다. 요청 범위가 "장비 기능"이라 별건으로 남겼다.

- **잔여 의존은 손대지 않았다**: `WxItemFragment.h` 의 `UGameplayEffect` 전방 선언은 `UWxItemFragment_Usable::Effect` 가, `WxInventory.Build.cs` 의 `GameplayAbilities` 는 `UseItemByDef` 의 GE 적용이 계속 쓴다.

### 계획 대비 달라진 점
계획대로.

### 후속 과제
- **에디터에서 확인이 필요하다 (빌드로는 잡히지 않음)**:
  - `Content/Item/DA_Katana.uasset` 의 `Equippable` 프래그먼트가 다음 로드에서 누락 클래스 경고와 함께 드랍된다. `EquipEffects` 가 빈 배열이라 기능 손실은 없고, 열어서 재저장하면 경고가 사라진다.
  - 캐릭터 BP 6종(`BP_Player`·`BP_Boss`·`BP_Enemy`·`BP_Minion`·`BP_Sandbag`·`BP_Soldier`)이 상속받던 `EquipmentComponent` 항목을 잃는다. BP 그래프가 이를 참조하는지는 바이너리 조회로 판별할 수 없었으므로, 참조 노드가 있다면 해당 BP 가 컴파일 에러를 낸다. 에디터를 열어 확인하고 발견되면 그 노드도 제거해야 한다.
