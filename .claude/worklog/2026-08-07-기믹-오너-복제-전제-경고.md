# 기믹 오너의 bReplicates 전제를 드러내기

## 계획

### 목표
`UWxGimmickStateTreeComponent` 는 생성자에서 자기 몫의 복제만 켠다. 오너 액터가 `bReplicates=false` 면 `StateTag` 도 `Multicast_Interact` 도 나가지 않아 헤더가 서술한 클라 수렴이 통째로 죽는데, 지금은 그 전제를 보장하거나 알리는 장치가 없다(커밋 `18756ef1` 로 C++ 기믹 액터 베이스가 사라지며 안전망도 함께 사라졌다). 이 전제를 런타임 로그와 문서로 드러낸다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxWorld/Source/WxWorld/Private/Gimmick/WxGimmickStateTreeComponent.cpp` | `BeginPlay` 에 오너 `bReplicates` 확인 Error 로그 + `WxWorldModule.h` 인클루드 | 수정 |
| `Plugins/WxWorld/Source/WxWorld/Public/Gimmick/WxGimmickStateTreeComponent.h` | 클래스 주석 「상태 구동 패턴」에 오너 복제 전제 명시 | 수정 |
| `Plugins/WxWorld/README.md` | 「확장 포인트 / 규약」의 **새 기믹** 항목에 전제 추가 | 수정 |

### 접근 방식
- **BeginPlay 진단 로그**: 오너의 `GetIsReplicated()` 가 false 면 `LogWxWorld` Error 를 한 줄 남긴다. 인스턴스당 1회, 오너 이름을 담아 어느 배치인지 바로 짚게 한다. 게임 월드에서만 도는 훅이라 에디터·CDO 에서는 발화하지 않는다.
- **동작은 바꾸지 않는다**: 컴포넌트가 오너의 `bReplicates` 를 대신 켜면 의도적 로컬 전용 배치를 조용히 덮어쓰므로 진단만 한다.
- **Error 수준**: 멀티플레이에서 기믹이 확실히 깨지는 오조립인데 로컬 플레이에서는 증상이 안 보인다. 모듈의 기존 Warning 들(그 노드만 건너뛰는 급)과 등급이 갈린다.
- **Map Check 를 택하지 않은 이유**: `FMessageLog("MapCheck")` 배선과 `WITH_EDITOR` 분기가 추가로 들고, 이 컴포넌트의 `OnRegister` 는 이미 `SaveId` 심기 전용으로 목적이 뚜렷해 성격이 다른 검사를 섞지 않는다.

### 구현·결정과 그 이유
- **자동 활성화가 아니라 진단**: 컴포넌트가 오너의 `bReplicates` 를 대신 켜면 의도적 로컬 전용 배치를 조용히 덮어쓰고, 생성자·`OnRegister` 어디서 켜도 배치 BP 의 저장값과 어긋날 여지가 남는다. 소유권은 배치 측에 두고 어긋남만 알린다.
- **`BeginPlay` 말미**: `RefreshStateTag()` 뒤에 두어 기존 시작 흐름의 순서를 건드리지 않았다. 이 훅은 게임 월드에서만 도므로 에디터 배치 중이나 CDO 에서는 발화하지 않는다.
- **Error 수준**: 멀티플레이에서 기믹이 확실히 깨지는 오조립인데 로컬 플레이에선 증상이 안 보인다. 같은 모듈의 기존 Warning 들은 그 노드만 건너뛰는 급이라 등급을 나눴다.
- **문서 두 곳**: 헤더는 패턴을 읽는 프로그래머용, README 「새 기믹」은 실제로 액터를 배치하는 쪽이 보는 자리다. 로그만으로는 배치 전에 알 방법이 없어 둘 다 남겼다.

### 검증
WxEditor(Development) 빌드 성공(26 액션, 에러·경고 없음). 배치된 기믹 4종(`BP_Door`·`BP_Elevator`·`BP_CheckPoint`·`BP_TreasureChest`)은 모두 `bReplicates: true` 라 현재 맵에서는 이 로그가 뜨지 않는 것이 정상이다.
