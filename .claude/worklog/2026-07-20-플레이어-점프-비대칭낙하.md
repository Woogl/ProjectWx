# 플레이어 점프 — 스텔라 블레이드식 비대칭 낙하 튜닝

## 계획

### 목표
플레이어 점프에 비대칭 중력을 도입해 스텔라 블레이드처럼 "정점에서 덜 머물고 빨리 떨어지는" 감각을 낸다. 스펙: 상승 높이 = 캐릭터 키 180cm, 총 체공 1.0초(상승 0.55s / 하강 0.45s). 고정 점프(`JumpMaxHoldTime`=0)는 이미 충족.

역산값(World Gravity −980): `JumpZVelocity`=655, 상승 `RiseGravityScale`=1.21, 하강 `FallGravityScale`=1.81.

### 접근 방식
- **CMC 서브클래스 + GetGravityZ 오버라이드**: 속도 부호 기반 중력 전환의 정확·표준 훅. 틱 GravityScale 스왑(틱 순서 의존·상태 변이)은 지양.
- **플레이어 한정**: CMC 클래스 교체는 `FObjectInitializer::SetDefaultSubobjectClass`로만 가능 → 생성자에 OI 전달. 베이스에 위임 기본 생성자를 남겨 에너미/보스는 손대지 않는다.
- **범위 밖**: 더블 점프, AirControl 조정은 이번 스펙에 없어 후속으로 분리.

### 구현·결정과 그 이유
- **GetGravityZ 오버라이드**: 속도 부호 기반 중력 전환의 정확·표준 훅. `Super::GetGravityZ()`(=월드중력·GravityScale 1.0)에 방향 스케일만 곱해 부작용 없이 falling 물리 전반에 일관 적용. 틱 GravityScale 스왑은 컴포넌트 틱 순서 의존·상태 변이가 있어 배제.
- **베이스 위임 기본 생성자 유지**: CMC 클래스 교체엔 OI가 필수라 베이스를 OI 생성자로 이관하되, 기본 생성자를 `FObjectInitializer::Get()` 위임으로 남겨 에너미/보스 생성자를 건드리지 않고 호환 유지. UHT가 OI 생성자를 우선 인식해 빌드 정상.
- **수치 배치**: `JumpZVelocity`/Rise·Fall 스케일을 플레이어 전용 WxCMC 한곳에 모아 점프 느낌을 응집. Rise/Fall은 EditDefaultsOnly라 BP_Player에서 디자이너 미세 튜닝 가능.

- 인게임 체감 검증(정점 ~0.55s / 총 체공 ~1.0s / 최고점 ≈ 캐릭터 키 / 상승<하강 속도)은 플레이테스트로 확인 필요.
- 범위 밖으로 둔 항목: 더블 점프, SB식 약한 공중 조향(`AirControl` 하향) — 원하면 별도 작업.
