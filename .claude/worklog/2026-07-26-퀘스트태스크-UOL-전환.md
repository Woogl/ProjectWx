# 퀘스트 태스크(WaitMoveToTarget·MarkIndicator) UOL 전환

## 계획

### 목표
WxQuest 의 WaitMoveToTarget·MarkIndicator 가 아직 `TargetActorTag`(QuestCamp)로 캠프 액터를 지정한다. 스포너 태스크와 동일하게 `FUniversalObjectLocator` 직접 지정으로 전환한다. 두 태스크는 같은 대상을 같은 태그로 지정하는 짝이라 함께 전환해야 QuestCamp 태그를 레벨에서 완전히 걷어낼 수 있고, 이로써 퀘스트 ST 의 레벨 액터 지정이 전부 UOL 로 단일화된다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxQuest/Source/WxQuest/WxQuest.Build.cs` | `UniversalObjectLocator` 모듈 의존성 추가(Public) | 수정 |
| `Plugins/WxQuest/.../Quest/WxQuestStateTreeNodes.h/.cpp` | 두 태스크의 `TargetActorTag`·`CachedTarget` 삭제 → `Target`(UOL), `FindActorByTag` 삭제, 해석·표시명 헬퍼 추가, 주석 갱신 | 수정 |
| `/Game/Quest/ST_Quest`, `LV_DevCombat` | Step1 두 노드에 캠프 TargetPoint UOL 지정, TargetPoint 의 QuestCamp 액터 태그 제거·저장 | 수정(MCP) |

### 접근 방식
- **판정 규약**: 스포너 태스크와 동일 — 캐시 없이 매 틱 `SyncFind(오너)` 해석(경로 조회라 비용 무시, WP 언로드/재로드 자연 처리), 미해석=대기, 진입 시 빈 로케이터 경고. MarkIndicator 는 미해석이면 Tick 재시도라는 기존 구조 유지.
- **표시명 헬퍼 중복**: 라벨 해석 헬퍼는 스포너 노드와 같은 패턴을 이 파일에 중복 구현 — 도메인 플러그인 간 참조 금지라 공유 불가, 소규모 중복은 인플레이스 선호.
- **에셋 마이그레이션**: 인스턴스 데이터 구조체 이름 유지라 노드는 필드 소멸+신규 필드(빈 값)로 로드, 값은 MCP 텍스트 임포트(`(uobj://actor?payload0=…)`)로 채움.

### 구현·결정과 그 이유
- **스포너 태스크와 동일 규약**: 캐시 없이 매 틱 `SyncFind(오너)` 해석, 미해석=대기, 진입 시 빈 로케이터 경고. 태그 시절의 전 액터 순회 캐시(`CachedTarget`)·`FindActorByTag` 가 통째로 사라졌다.
- **표시명 헬퍼 파일 내 중복**: 도메인 플러그인 간 참조 금지라 스포너 쪽 헬퍼를 공유할 수 없어 같은 패턴을 소규모 중복(인플레이스 선호).
- **에셋 편집 중 배운 것**: ① 전체 배열 재기술은 그 사이 사용자가 편집한 값(Step1·Step2 재배열, 제목 "Quest Test")을 전제 못 해 어긋났다 — 기존 원소의 `_structType` 교체가 무시되는 규칙 덕에 값은 보존됐고, **부분 갱신(빈 dict=무변경)으로 재작업**해 해결. 편집 전 반드시 현 상태를 다시 읽을 것. ② `AssetTools.save_assets(빈 목록)` 이 더티 외부 액터 패키지도 조용히 저장한다 — `save_actor` 의 레지스트리 조회 실패·Save 대화상자(모달, MCP 블록)가 모두 불필요.

### 계획 대비 달라진 점
- PIE 실검증은 보류 — 사용자가 같은 머신에서 병행 작업 중이라 PIE 의 입력 캡처가 방해가 된다. 해석 경로(SyncFind+오너 컨텍스트)는 스포너 태스크에서 이미 두 차례 PIE 실증된 동일 코드라 리스크가 낮고, ST 컴파일(레벨 액터 검증 통과)은 확인했다.

### 후속 과제
- PIE 확인 1회: 기본 시작 → 마커가 캠프에 스폰되는지, 캠프 도달 시 Step1 완료되는지(사용자 플레이 또는 다음 세션).
