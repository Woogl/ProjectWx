# 프론트엔드 위젯 — 커스텀 함수를 커스텀 이벤트로, 상태 폴링 타이머 제거

## 계획

### 목표
`WBP_FrontEnd` 는 화면 전환·선택·확인 팝업 흐름을 BP 함수 10개로 쪼개 두어, 리뷰하려면 함수를 하나씩 타고 들어가야 한다. 흐름 전체가 이벤트 그래프 한 화면에서 읽히도록 함수를 전부 커스텀 이벤트로 옮긴다. 같은 이유로 읽기를 방해하는 문자열 이름 기반 상태 폴링 타이머도 함께 없앤다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_FrontEnd.uasset` | 함수 그래프 10개를 같은 이름의 커스텀 이벤트로 전환, 상태 갱신 타이머 설정·해제 노드와 빈 Destruct 이벤트 삭제 | 수정 |

부모 함수의 오버라이드이고 반환값이 있는 포커스 대상 게터는 이벤트가 될 수 없어 그대로 둔다.

### 접근 방식
- **엔진 기본 전환 기능을 쓴다**: 함수 엔트리 노드 컨텍스트 메뉴의 "Convert Function to Event" 는 같은 이름의 커스텀 이벤트를 만들고 엔트리의 파라미터 핀을 타입까지 그대로 옮긴 뒤, 함수 그래프의 노드를 통째로 이벤트 그래프로 이동시키고 함수 그래프를 지운다. 호출부는 같은 이름의 UFunction 이 그대로 생기므로 유효하게 남는다. 그래프를 DSL 로 재작성하면 확인 팝업 쪽의 서식 텍스트 명명 인자, 로컬라이즈 키, 델리게이트 바인딩, 열거형 기본값을 전부 다시 맞춰야 하고, 무엇보다 팝업 결과 파라미터는 열거형이라 DSL 로는 타입 있는 핀 자체를 만들 수 없다. 에디터 UI 자동화로 전환 명령을 호출한다.
- **타이머는 두 지점을 지운다**: 갱신 이벤트 끝의 "이동 중이면 0.1초 뒤 자신을 다시 호출" 분기와, Destruct 의 해제 호출. 해제만 하던 Destruct 는 할 일이 없어져 이벤트째 지운다. 이동 중 여부 자체는 버튼 활성 계산에 계속 쓰이므로 남는다.
- **잃는 것**: 레벨 전환이 실패해도 메뉴가 스스로 다시 열리지 않는다. 전환 실패 통지는 엔진 델리게이트로 비동기에 오고, 위젯이 그 변화를 알아채는 통로가 이 폴링뿐이었다. 복구가 다시 필요해지면 폴링을 되살리는 대신 상태를 계산하는 원천이 변경을 발행하고 위젯이 구독하는 형태가 맞다.
