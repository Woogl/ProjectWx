# 프론트엔드 위젯 — 커스텀 함수를 커스텀 이벤트로, 상태 폴링 타이머 제거

## 계획

### 목표
`WBP_FrontEnd` 는 화면 전환·선택·확인 팝업 흐름을 BP 함수 10개로 쪼개 두어, 리뷰하려면 함수를 하나씩 타고 들어가야 한다. 흐름 전체가 이벤트 그래프 한 화면에서 읽히도록 함수를 전부 커스텀 이벤트로 옮긴다. 같은 이유로 읽기를 방해하는 문자열 이름 기반 상태 폴링 타이머도 함께 없앤다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_FrontEnd.uasset` | 함수 그래프 10개를 같은 이름의 커스텀 이벤트로 전환, 상태 갱신 타이머 설정·해제 노드와 빈 Destruct 이벤트 삭제 | 수정 |

부모 함수의 오버라이드이고 반환값이 있는 포커스 대상 게터는 이벤트가 될 수 없어 그대로 둔다.

### 접근 방식
- **엔진 기본 전환 기능을 쓴다**: 함수 엔트리 노드 컨텍스트 메뉴의 "Convert Function to Event" 는 같은 이름의 커스텀 이벤트를 만들고 엔트리의 파라미터 핀을 타입까지 그대로 옮긴 뒤, 함수 그래프의 노드를 통째로 이벤트 그래프로 이동시키고 함수 그래프를 지운다. 호출부는 같은 이름의 UFunction 이 그대로 생기므로 유효하게 남는다. 그래프를 DSL 로 재작성하면 확인 팝업 쪽의 서식 텍스트 명명 인자, 로컬라이즈 키, 델리게이트 바인딩, 열거형 기본값을 전부 다시 맞춰야 하고, 무엇보다 팝업 결과 파라미터는 열거형이라 DSL 로는 타입 있는 핀 자체를 만들 수 없다. 에디터 UI 자동화로 전환 명령을 호출한다.
- **타이머는 두 지점을 지운다**: 갱신 이벤트 끝의 "이동 중이면 0.1초 뒤 자신을 다시 호출" 분기와, Destruct 의 해제 호출. 해제만 하던 Destruct 는 할 일이 없어져 이벤트째 지운다. 이동 중 여부 자체는 버튼 활성 계산에 계속 쓰이므로 남는다.
- **잃는 것**: 레벨 전환이 실패해도 메뉴가 스스로 다시 열리지 않는다. 전환 실패 통지는 엔진 델리게이트로 비동기에 오고, 위젯이 그 변화를 알아채는 통로가 이 폴링뿐이었다. 복구가 다시 필요해지면 폴링을 되살리는 대신 상태를 계산하는 원천이 변경을 발행하고 위젯이 구독하는 형태가 맞다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Content/UI/Widget/WBP_FrontEnd.uasset` | 함수 그래프 10개를 같은 이름의 커스텀 이벤트로 전환, 상태 갱신 타이머 설정 분기와 해제 호출 삭제, 할 일이 없어진 Destruct 이벤트 삭제 | 수정 |

남은 그래프는 이벤트 그래프와 포커스 대상 게터 오버라이드 둘뿐이다.

### 구현·결정과 그 이유
- **엔진 기본 전환 기능을 그대로 썼다**: 함수 엔트리 노드 컨텍스트 메뉴의 전환 명령을 에디터 UI 자동화로 호출했다. 노드 배치와 핀 값이 그대로 옮겨지고, 팝업 결과 파라미터도 열거형 타입을 유지한 채 이벤트 핀이 됐다. 호출부는 같은 이름의 함수가 그대로 생겨 한 건도 끊기지 않았고, 확인 팝업의 델리게이트 바인딩도 전환된 이벤트를 그대로 가리킨다.
- **그래프 DSL 재작성을 쓰지 않은 이유**: DSL 역변환은 출력 핀이 여러 개인 노드에서 어느 핀을 썼는지를 잃는다. 이동 상태 조회는 바쁨 여부와 문구 두 출력을 쓰는데, 되쓰면 문구 자리에 바쁨 여부가 물려 조용히 틀린 그래프가 된다. 확인 팝업의 서식 텍스트 명명 인자와 로컬라이즈 키도 같은 위험이 있었다.
- **타이머는 분기째 지웠다**: 갱신 이벤트 끝의 "이동 중이면 다시 호출" 분기와 그 아래 설정 노드를 함께 지웠다. 이동 중 여부는 버튼 활성 계산에 계속 쓰이므로 조회 노드는 남는다. 해제만 하던 Destruct 는 할 일이 없어져 이벤트째 지웠다.
- **검증**: 경고를 오류로 취급한 컴파일 통과, 저장 시 에셋 검증 통과, 그래프를 다시 읽어 이벤트 10개의 몸통이 원본 함수와 같은지 대조했다.

### 계획 대비 달라진 점
- 계획대로다. 다만 전환 중 사용자가 같은 에디터에서 다른 에셋을 열어 UI 조작이 몇 차례 엇나갔고, 그때마다 위젯 에디터를 다시 앞으로 가져와 이어갔다.

### 후속 과제
- **레벨 전환 실패 복구가 사라졌다**: 전환 실패 통지는 비동기로 오는데 위젯이 그 변화를 알아채는 통로가 이 폴링뿐이었다. 되살린다면 폴링이 아니라 상태를 계산하는 원천이 변경을 발행하고 위젯이 구독하는 형태여야 한다.
- **죽은 이벤트 하나**: 새 게임 가드 이벤트는 아무도 호출하지 않는다. 새 게임 버튼은 가드를 건너뛰고 캐릭터 화면을 직접 열고, 나머지 세 버튼은 모두 가드를 거친다. 배선 실수로 보이지만 동작 변경이라 이번 범위에서 뺐다. 연결할지 지울지 결정 필요.
- **쓰이지 않는 변수는 없다**(전환 후 확인): 위젯 변수 7개와 블루프린트 변수 6개 모두 참조가 있다. 다만 캐릭터 선택 인덱스는 읽히는 시점마다 값이 항상 0이다. 캐릭터 목록에 항목이 하나뿐이고 선택 이벤트가 0을 박아 넣기 때문이다. 목록이 늘어날 자리로 남겨 둔 것인지, 지금 구조에 맞춰 접을 것인지는 결정 필요.
- 플레이 확인(프론트엔드에서 캐릭터→레벨→확인→시작) 미실행.
