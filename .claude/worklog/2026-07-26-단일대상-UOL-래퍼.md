# WaitMoveToTarget 단일 대상 지정 복구 — UOL 래퍼 구조체

## 계획

### 목표
WaitMoveToTarget 의 대상을 단일 액터로 유지하면서(배열화 기각) 픽커를 복구한다. 엔진(5.8) 제한 — ST 노드 인스턴스 데이터의 직속 `FUniversalObjectLocator` 필드는 값 위젯이 생성되지 않음 — 을 한 겹 래퍼 구조체로 우회한다.

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxQuest/.../Quest/WxQuestStateTreeNodes.h/.cpp` | 래퍼 `FWxActorTarget { FUniversalObjectLocator Locator; }` 신설, Target 타입 교체, 접근 경로 `.Locator` | 수정 |
| `/Game/Quest/ST_Quest` | WaitMoveToTarget 의 target 재기입(타입 교체로 소실), 컴파일·저장 | 수정(MCP) |

### 접근 방식
- **메커니즘(엔진 소스 확정)**: ST 의 ModifyRow 는 인스턴스 데이터 **직속 자식 행에만** 적용되고, Category 가 무엇이든 usage 는 Parameter 로 귀결되어 `GetDefaultWidgets` 가 호출된다. `FDetailPropertyRow::GetDefaultWidgets` 는 타입 커스터마이제이션의 CustomizeHeader 를 버려지는 행에 실행해(DetailPropertyRow.cpp) 상태를 가진 UOL 커스터마이제이션을 훼손한다. 손자 행(배열 원소·중첩 구조체 멤버)은 이 경로를 타지 않아 정상(배열 원소 실측 완료).
- **래퍼로 손자화**: UOL 을 래퍼로 한 겹 감싸 손자 행으로 내리면 단일 의미 유지 + 픽커 복구. 엔진 수정 없음. 래퍼는 유일 사용처인 WxQuest 에 둔다(WxCore 승격은 타 모듈 확산 시).
- 실패 시(가설 오류) 원복하고 대안(인스턴스 데이터 구조체 커스터마이제이션 — ST 바인딩 데코 상실 리스크)을 재보고한다.

## 완료

### 수정한 파일
| 파일 | 수정한 내용 | 구분 |
|---|---|---|
| `Plugins/WxQuest/.../Quest/WxQuestStateTreeNodes.h/.cpp` | `FWxActorTarget { FUniversalObjectLocator Locator; }` 래퍼 신설(메커니즘 주석), WaitMoveToTarget 의 Target 타입 교체, 접근 `.Locator` | 수정 |
| `/Game/Quest/ST_Quest` | WaitMoveToTarget target 재기입(중첩 JSON `{"locator": "(uobj://…)"}`), 저장 | 수정(MCP) |

### 구현·결정과 그 이유
- **가설 검증 성공**: 래퍼로 UOL 을 손자 행으로 내리자 Target 펼침 → Locator 행에 완전한 UOL 위젯(타입 콤보+값 콤보)이 렌더되고, 클릭 시 액터 픽커 팝업(CURRENT ACTOR / BROWSE 검색)이 정상으로 열림을 실측했다. 단일 의미 유지 + 픽커 복구 달성.
- **에디터 소실 소동은 크래시가 아니었다**: 검증 중 에디터가 두 번 "죽었"는데, 로그·크래시 덤프 분석 결과 병행 세션의 run-editor 사이클(종료→빌드→재실행)과 충돌한 것 — 두 세션이 서로의 에디터를 죽이고 있었다. 이후 병행 세션이 띄운 에디터를 죽이지 않고 그 위에서 검증을 마쳤다.
- MCP 기입 시 래퍼는 중첩 JSON 으로 기입하며, 타입 교체로 구 값은 로드 시 소실되므로(struct type mismatch 경고) 재기입이 필요했다.

### 계획 대비 달라진 점
- 계획대로(래퍼 가설 적중). 에디터 재시작 횟수만 병행 세션 충돌로 늘었다.

### 후속 과제
- MarkIndicator(WxUI)의 Target 도 동일 래퍼 적용 가능 — 파일 소유가 병행 세션 작업분이라 별도 확인 후 진행.
- 병행 세션과 에디터 재시작 조율 규약 필요(서로 죽이는 문제).
