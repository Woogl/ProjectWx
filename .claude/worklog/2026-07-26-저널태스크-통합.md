# SetQuestObjective 에 RegisterJournal 흡수

## 계획

### 목표
퀘스트 저널 태스크 2종(RegisterJournal=제목 등록, SetQuestObjective=목표 갱신)은 "진입 시 컴포넌트에 문구 반영 후 즉시 완료"라는 같은 골격이므로 `FWxStateTreeTask_SetQuestObjective` 하나로 통합하고 RegisterJournal 을 삭제한다(클래스 증식 억제).

### 수정 범위
| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Plugins/WxQuest/.../Quest/WxQuestStateTreeNodes.h/.cpp` | RegisterJournal 구조체·구현 삭제, SetQuestObjective 에 `QuestTitle`(선택) 추가·판정·설명 확장, 주석 갱신 | 수정 |
| `Plugins/WxQuest/.../Quest/WxQuestComponent.h/.cpp` | SetJournal/SetObjective 주석의 태스크 명칭 갱신(로직 불변) | 수정 |
| `/Game/Quest/ST_Quest` | Start 상태의 RegisterJournal 노드를 SetQuestObjective(`QuestTitle="Scout the Camp"`)로 재조립(MCP) | 수정(MCP) |

### 접근 방식
- **동작 보존 통합**: `QuestTitle` 이 비어있지 않으면 `SetJournal`(저널 신규 등록, 목표 비움) 후 `ObjectiveText` 가 있으면 이어서 `SetObjective`. `QuestTitle` 이 비면 기존대로 무조건 `SetObjective`(빈 문구=목표 비우기 의미 유지). 기존 두 태스크의 사용처 동작이 정확히 보존되고, 제목+첫 목표를 한 노드에서 지정할 수도 있게 된다.
- **컴포넌트 API 불변**: 제목 등록과 목표 갱신은 의미가 달라 `SetJournal`/`SetObjective` 를 병합하지 않고 주석만 갱신한다.
- **에셋 마이그레이션 최소화**: 구조체 삭제로 빈 노드가 되는 Start 의 옛 노드만 `_structType` 교체로 재기술(기존 iD 유지), Step1·Step2 노드는 필드 추가(기본 빈 값)라 무변경.

| `/Game/Quest/ST_Quest` | Start 상태의 옛 RegisterJournal 노드를 SetQuestObjective(`QuestTitle="Scout the Camp"`)로 재조립·컴파일·저장(MCP) | 수정(MCP) |

### 구현·결정과 그 이유
- **동작 보존 규약**: 제목이 있으면 `SetJournal`(신규 등록, 목표 비움) 후 목표가 있으면 이어서 `SetObjective`, 제목이 비면 기존대로 무조건 `SetObjective` — 기존 두 태스크의 사용처 동작이 정확히 보존된다(빈 목표=목표 비우기 의미 포함).
- **컴포넌트 API 불변**: 제목 등록(목표 비움 부수효과)과 목표 갱신은 의미가 달라 `SetJournal`/`SetObjective` 를 병합하지 않았다.
- **에셋 마이그레이션 최소**: 구조체 삭제로 빈 노드가 된 Start 노드만 `_structType` 교체로 재기술(기존 iD 유지). Step1·Step2 의 기존 SetQuestObjective 노드는 새 필드가 기본 빈 값으로 로드되어 무변경임을 확인.
- **GetDescription**: 제목 지정 시 `Set Quest Objective (제목: 목표)`, 미지정 시 기존 `(목표)` 형식.
