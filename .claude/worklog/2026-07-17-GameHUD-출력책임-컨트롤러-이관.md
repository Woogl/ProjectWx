# WBP_GameHUD 출력 책임을 WxPlayerController로 이관

## 계획

### 목표

HUD를 띄우는 코드는 이미 컨트롤러에 있으나 "어떤 HUD를 띄울지"라는 데이터만 캐릭터에 남아, 컨트롤러가 폰에게 게터로 되물어보는 구조다. HUD는 화면·플레이어의 소유물이므로 데이터도 컨트롤러로 옮겨 게터와 폰 의존을 없애고, 지정 지점을 하나로 합친다.

### 수정 범위

| 파일 | 수정할 내용 | 구분 |
|---|---|---|
| `Source/WxGame/Character/WxPlayerCharacter.h` | `GameHUDClass` 프로퍼티, `GetGameHUDClass()` 선언, `UWxActivatableWidget` 전방 선언 제거 | 수정 |
| `Source/WxGame/Character/WxPlayerCharacter.cpp` | `GetGameHUDClass()` 정의 제거 | 수정 |
| `Source/WxGame/Controller/WxPlayerController.h` | `GameHUDWidgetClass` 프로퍼티 추가(`DeathScreenWidgetClass` 옆), `PushGameHUD()` 인자 제거 | 수정 |
| `Source/WxGame/Controller/WxPlayerController.cpp` | `PushGameHUD()`가 자기 프로퍼티를 읽도록 변경, 호출부 2곳 정리 | 수정 |
| `Content/Framework/BP_PlayerController.uasset` | `GameHUDWidgetClass = WBP_GameHUD` 지정 | 에디터 수작업 |

### 접근 방식

- **데이터 이관**: `GameHUDClass`(`TSubclassOf`, `EditDefaultsOnly`)를 컨트롤러로 옮기고 이름은 이웃 프로퍼티와 맞춰 `GameHUDWidgetClass`로 둔다. `DeathScreenWidgetClass`가 소프트 참조인 것과 달리 하드 참조를 유지한다. 사망 화면과 달리 HUD는 빙의 즉시 항상 필요해 지연 로드 이득이 없고, 기존 동작과 같다.

- **푸시 타이밍은 그대로**: `OnPossess`(리슨/스탠드얼론)와 `OnRep_Pawn`(원격 클라이언트) 두 진입점, 그리고 플레이어 캐릭터 캐스팅 가드를 모두 유지한다. HUD 위젯의 리졸버가 생성 시점에 빙의 폰의 ASC를 읽으므로, 빙의 완료 후·플레이어 캐릭터일 때라는 조건은 여전히 유효하다. 캐스팅 결과는 더 이상 쓰이지 않으므로 인자로 넘기지 않고 가드로만 쓴다.

- **BP 정리**: C++ 프로퍼티가 사라지면 `BP_Player`·`BP_HR_Player`의 값은 자동 소멸한다. 두 캐릭터 모두 같은 HUD를 지정하고 있었으므로 컨트롤러에 한 번만 지정하면 동일하게 적용된다.

### 구현·결정과 그 이유
- **캐스팅을 가드로만 남김**: 푸시 함수가 더 이상 폰을 받지 않으므로 캐스팅 결과는 쓰이지 않지만, 조건 자체는 유지했다. HUD 위젯의 리졸버가 생성 시점에 빙의 폰을 플레이어 캐릭터로 캐스팅해 ASC를 읽으므로, 그 조건이 성립할 때만 띄우는 의미는 그대로다. 널 허용이 필요한 원격 클라이언트 경로 때문에 `IsA` 대신 캐스팅을 그대로 썼다.
- **하드 참조 유지**: 이웃한 사망 화면과 달리 HUD는 빙의 즉시 항상 필요해 지연 로드 이득이 없다. 기존 캐릭터 쪽 지정도 하드 참조였으므로 로드 동작이 바뀌지 않는다.
