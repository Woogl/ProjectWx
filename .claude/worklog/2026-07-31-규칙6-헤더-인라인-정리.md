# 규칙 6 위반 정리 — 헤더 인라인 함수 정의 8건 + 규칙 예외 명문화

## 계획

### 목표
모듈 리뷰 6개(WxAI·WxCombat·WxDialogue·WxGame·WxInventory·WxQuest)가 확신도 "높음"으로 지적한 코딩 규칙 6 위반을 해소한다. 전수 스캔 결과 지적에 성격이 다른 두 부류가 섞여 있어, 진짜 위반 8개는 cpp 로 내리고 StateTree 노드의 `GetInstanceDataType()` 26곳은 규칙 예외로 명문화한다.

### 접근 방식
- **두 부류를 가른 근거**: `GetInstanceDataType()` 은 엔진 소스로 확인했을 때 규칙의 대상이 아니다 — 베이스 `FStateTreeNodeBase::GetInstanceDataType()` 자체가 헤더 안 정의이고(`StateTreeNodeBase.h:94`), 같은 헤더가 `using FInstanceDataType` 별칭과 "The type should match GetInstanceDataType()" 을 한 쌍으로 못박는다(`:78-82`). 즉 옮길 로직이 없는 **타입 선언의 짝**이다. 엔진 StateTree 모듈 안에 아웃오브라인 정의가 0건이고, `virtual` 이라 인라인 확장되지도 않아 규칙 6이 겨냥하는 `FORCEINLINE` 류와 성격이 다르다.
- **예외를 규칙에 적는 이유**: 코드만 고치면 다음 리뷰가 같은 26곳을 다시 위반으로 집어 논의가 반복된다. 근거를 규칙 옆에 한 줄로 남겨 재조사 비용을 없앤다.
- **신규 cpp 2개**: UBT 가 `Private/` 를 글로빙하므로 `Build.cs` 수정은 불필요하다. 다만 파일 추가라 makefile 이 무효화되므로 빌드에서 해당 모듈 재링크를 함께 확인한다.

### 구현·결정과 그 이유
- **두 부류를 가른 근거**: `GetInstanceDataType()` 은 엔진 소스로 확인했을 때 규칙의 대상이 아니다. 베이스 `FStateTreeNodeBase::GetInstanceDataType()` 자체가 헤더 안 정의이고(`StateTreeNodeBase.h:94`), 같은 헤더가 `using FInstanceDataType` 별칭과 "The type should match GetInstanceDataType()" 을 한 쌍으로 못박는다(`:78-82`) — 옮길 로직이 없는 타입 선언의 짝이다. 엔진 StateTree 모듈에 아웃오브라인 정의가 0건이고, `virtual` 이라 인라인 확장되지도 않아 규칙 6이 겨냥하는 `FORCEINLINE` 류와 성격이 다르다.
- **근거를 CLAUDE.md 가 아니라 코드에 적었다**: 처음엔 규칙 6 아래 예외 조항으로 적었으나, 사용자 지시로 되돌리고 해당 헤더 파일마다 1줄로 옮겼다. 규칙 문서를 읽지 않고 그 파일만 여는 사람에게 근거가 닿는다는 점에서 이쪽이 낫다.
- **예외 주석을 지적 대상 밖 모듈에도 달았다**: 같은 패턴이 WxWorld·WxUI·WxSave·WxInventory 에도 있어, 지적된 모듈만 표기하면 "여긴 왜 예외가 아닌가" 라는 반대 방향의 혼선이 생긴다.
- **신규 cpp 2개에 Build.cs 수정 불필요**: UBT 가 `Private/` 를 글로빙하므로 파일 추가만으로 잡힌다. 빌드 로그의 `Invalidating makefile for WxEditor (source file added)` 로 실제 인식을 확인했다.

### 계획 대비 달라진 점
- CLAUDE.md 규칙 6 예외 명문화를 취소하고, 대신 예외 근거를 해당 코드(ST 노드 헤더 8개 + `WxItemDefinition.h`)에 주석으로 남겼다. 작업 도중 사용자 지시.
- 주석 분량도 사용자 지시로 3줄 → 1줄로 줄였다.

### 후속 과제
- **여전히 남아 있는 헤더 인라인 정의**(리뷰가 지적하지 않았고 이번 결정 범위도 아님) — 인터페이스·가상 함수 기본 구현 4건(`IWxSavable::OnSaveRestored`, `IWxInteractable::CanBeInteractedBy`, `IWxSpawnable::OnSpawnedBy`, `UWxViewModel::ApplyLoadedImage`), 다른 모듈의 1줄 게터 10건(WxUI 7, WxSave 2, WxWorld 1). 정리할지 예외로 둘지는 별도 결정이 필요하다.
- **확신도 높음 잔여 26건**: 다음은 WxSave 3건(디스크 기록 실패 통지·`ResumeTransform` 원시 포인터·`bSaveInProgress` 전역 플래그)부터.
