# 장치 이벤트 태스크 둘을 '이벤트 보내기' 하나로

## 계획

### 목표
`연결 장치 발동`과 `내장 장치에 이벤트 보내기`는 하는 일이 같다 — 다른 장치의 트리에 이벤트를 보내는 것. 다른 것은 대상과 태그를 어디서 얻느냐뿐이라, 그 두 축을 파라미터로 노출해 하나로 접는다. 이름은 장치에 매이지 않게 `이벤트 보내기`로 하고 페이로드도 실을 수 있게 한다.

| | 대상 | 태그 |
|---|---|---|
| `연결 장치 발동` | 오너의 `LinkedDevices`(레벨 배선) | 오너의 `TriggerEvent`(액터 프로퍼티) |
| `내장 장치에 이벤트 보내기` | 오너 BP 의 내장 컴포넌트(에셋 저작) | 태스크 파라미터(에셋 저작) |

둘 다 비운 것이 지금의 `연결 장치 발동`, 둘 다 채운 것이 지금의 새 태스크다. 기본값이 곧 기존 동작이라 문 버튼 저작은 손댈 것이 없다. 값을 어디 두는지는 한 문장으로 정리된다 — **인스턴스마다 다르면 액터에, 에셋이 정하면 태스크에**.

### 접근 방식
- **파라미터 셋, 갈래는 그 조합**: `ChildDevice`(비우면 오너의 `LinkedDevices` 전부), `Event`(비우면 오너의 `TriggerEvent`), `Payload`(비우면 태그만). 서로 독립이라 조합이 전부 뜻이 통한다.
- **이름은 장치에 매지 않는다**: 지금 대상은 장치뿐이지만 구조체 경로가 에셋에 박히므로 나중에 넓혀도 바꾸지 않도록 `SendEvent` 로 짓는다. GAS 의 `SendGameplayEventToActor` 와 헷갈리지 않게 `Gameplay` 는 붙이지 않는다 — 트리 안에서 「이벤트」는 StateTree 이벤트다.
- **나머지 계약은 `연결 장치 발동` 그대로**: 권위 전용, 초기 진입 스킵, 틱 없음, 완료 판정 불참, 당사자는 오너의 것을 그대로 넘긴다. 통로도 기존 장치 이벤트 진입점을 쓴다.
- **실패 처리는 갈래마다 다르다**: `LinkedDevices` 가 비어 있는 것은 정상이라 무동작 통과. 반면 `ChildDevice` 를 지목했는데 못 찾으면 저작 실수이므로 에러 로그와 함께 상태 진입을 실패시킨다.
- **추가 → 에셋 교체 → 삭제 3단계**: 클래스를 먼저 지우면 에디터가 그 노드를 미지 타입으로 버려 배열이 줄고 완료 비트 배치까지 흔들린다.
- **에셋 교체는 개수를 유지한다**: 타입 교체는 배열을 비웠다 같은 개수로 재기입해야 반영된다. 개수가 그대로라 방금 잡은 완료 비트 배치(`Delay(bRunForever)` 판정 태스크)는 손대지 않는다.

### 구현·결정과 그 이유
- **두 축을 파라미터로 노출하니 한 태스크가 됐다**: 대상(내장 장치 지목 / 오너의 연결 장치)과 태그(에셋 값 / 오너의 값)가 서로 독립이라 네 조합이 전부 뜻이 통한다. 모드 플래그가 생기지 않고 둘 다 비운 것이 옛 `연결 장치 발동` 과 같아 문 버튼 저작은 손대지 않았다.
- **비운 칸이 오너의 값을 쓰는 것이 곧 규칙이다**: 인스턴스마다 달라지는 값은 액터(`LinkedDevices`·`TriggerEvent`), 에셋이 정하는 값은 태스크. 버튼은 같은 에셋을 여럿이 공유하며 보낼 이벤트가 저마다 달라 앞쪽이고, 엘리베이터는 여러 대가 공유해도 보낼 이벤트가 늘 같아 뒤쪽이다.
- **이름에 `Gameplay` 를 붙이지 않았다**: GAS 의 `SendGameplayEventToActor` 와 한 화면에서 만나는 코드베이스라(`Event.Interact` 가 스캐너→어빌리티 경로에 쓰인다) 어빌리티 이벤트로 오해된다. 트리 안에서 「이벤트」는 StateTree 이벤트이므로 `SendEvent` 로 짧게 두었다. 구조체 경로가 에셋에 박히므로 장치에 매이지 않는 이름으로 미리 잡았다.
- **페이로드는 통로만 열었다**: 태스크의 `FInstancedStruct` 를 장치 진입점을 거쳐 그대로 넘긴다. 지금 저작에서 쓰는 곳은 없고, 받는 쪽은 전이의 Payload Struct 로 타입을 좁혀 바인딩으로 읽는다.
- **추가 → 에셋 교체 → 삭제 순서를 지켰다**: 클래스를 먼저 지웠다면 에디터가 로드에서 그 노드를 미지 타입으로 버려 배열이 줄고, 방금 잡아 둔 완료 비트 배치까지 흔들렸을 것이다.
- **교체는 개수를 유지했다**: 노드를 원본 그대로 덤프해 `_structType` 과 인스턴스만 갈아 끼우고 `iD` 를 보존했다. 상태별 태스크 개수·판정 태스크 수가 교체 전과 같아 비트 배치가 그대로다.

### 계획 대비 달라진 점
- 이름을 `SendDeviceEvent` 로 계획했다가 사용자 지시로 범용 이름으로 바꿨다. `SendGameplayEvent` 안은 GAS 어휘와 겹쳐 `SendEvent` 로 좁혔고, 같은 지시에서 `Payload` 파라미터가 더해졌다.

### 검증
- `WxEditor(Development)` 빌드 2회(추가·삭제) `Result: Succeeded`, 각 단계 뒤 에디터 재시작.
- `ST_Button` · `ST_Elevator` 컴파일 `succeeded`, 저장 실기록. 재조회로 노드 일곱 개가 새 타입이고 파라미터(대상·태그, 그리고 비운 갈래의 "연결 장치 / Trigger Event" 표시)가 온전함을 확인. 다른 태스크의 컴포넌트 지목도 유실 없음.
- 옛 클래스 삭제·재시작 뒤에도 두 에셋이 온전하고, PIE 에서 되감기 로그 0건 · `LogWxWorld` 에러 0건.

### 후속 과제
- **사람 PIE 확인**: 문 버튼 여닫기(파라미터를 비운 갈래가 옛 동작과 같은지), 층 버튼 잠금·해제, 이동 중 칸 안 버튼 잠금.
- 다른 장치 트리(`ST_Door` · `ST_CheckPoint` · `ST_TreasureChest` · `ST_Piston`)에 판정 태스크 0개인 머무는 상태가 남아 있다(앞 작업의 잔여 과제).
