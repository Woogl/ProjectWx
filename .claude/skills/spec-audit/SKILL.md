# 기획서-코드 감사

지정한 **기획서 하나**를 실제 코드와 대조해, 기획 규칙·수치가 코드에 제대로 구현됐는지 검증하고 불일치를 찾아낸다. 반대로 코드에만 있고 문서엔 없는 동작(문서화 공백)도 함께 표기한다. 결과는 대화창에 인라인으로만 보고한다(파일로 남기지 않는다).

핵심 원칙 세 가지.

1. **컨텍스트 격리** — 오케스트레이터(이 스킬을 실행하는 너)는 **기획서(마크다운)만** 읽어 검증 체크리스트로 분해한다. 코드 통독은 **검증 서브에이전트**에 맡겨, 본문이 아니라 판정표만 돌려받는다.
2. **무수정** — 이 스킬은 기획서·코드 **어느 것도 편집하지 않는다**(그래서 오케스트레이터에 `Write` 권한도 없고, 서브에이전트에도 파일을 쓰지 말라고 지시한다). 산출물은 보고뿐이다. 실제 수정은 사람이 판단한 뒤 별도로 한다.
3. **중립 판정** — 불일치가 곧 버그는 아니다. **기획서 최신화 누락**일 수도, **구현 누락·오류**일 수도 있다. 어느 쪽이 옳다고 단정하지 말고 양쪽 가능성을 함께 제시해 사람이 결정하게 한다.

---

## 1. 대상 결정 (인자 처리)

인자 = 감사할 **기획서 하나**. 경로거나 주제다. 한 번에 기획서 1개만 다룬다(여러 개면 각각 실행하라고 안내).

- **인자 없음**: 무엇을 감사할지 추측하지 말고 한국어로 되묻는다.
- **경로**(예: `Docs/CombatDesign/그로기_시스템.md`): 그 파일을 대상으로 삼는다. 파일이 없으면 되묻는다.
- **주제**(예: `그로기`, `퍼펙트 가드`): `Glob`으로 `Docs/**/*.md` 후보를 찾는다(기획 문서 `Docs/CombatDesign/`, `Docs/SystemDesign/`, `Docs/Leveldesign/`에 있다.). 파일명·제목으로 매칭한다.
  - 정확히 1개면 그 문서로 진행.
  - 여러 개면 후보 목록을 제시하고 어느 것인지 되묻는다.
  - 0개면 서브에이전트를 띄우지 말고 범위를 좁혀 달라고 되묻는다.

대상이 정해지면 오케스트레이터가 그 **기획서를 `Read`** 한다(스펙이 비교의 기준이므로 직접 읽어 체크리스트를 만든다). **여기서 코드 본문은 읽지 않는다** — 오케스트레이터 컨텍스트는 비워 둔다.

## 2. 기획서 → 체크리스트 분해 (오케스트레이터)

읽은 기획서를 **검증 가능한 원자적 주장(claim)** 목록으로 분해한다. 각 주장은 규칙·수치·동작 하나이고, 코드로 확인 가능해야 한다.

분해 지침:

- **표·불릿·수치를 우선** 뽑는다. 예: 「받는 피해 30% 증가」, 「스태거 게이지 최대 도달 시 그로기 진입」, 「그로기 중 이동 불가」는 각각 별개 주장이다.
- 산문 속 규칙도 뽑되, **모호한 서술**(「적절히」, 「자연스럽게」, 「추후 결정」, TBD)은 검증 대상에서 빼고 `정성적 — 검증 보류`로 따로 표시한다(억지로 판정하지 않는다).
- **수치는 정확히** 옮긴다(30%, 1.3배, N초, 게이지 값 등). 나중에 코드 상수·DataTable 값과 그대로 대조한다.
- 각 주장에 **기획서 내 위치**(섹션 번호/표 행)를 붙여, 보고 때 독자가 원문을 찾아갈 수 있게 한다.

그다음, 각 주장이 **코드 어디쯤**에 있을지 `Grep`/`Glob`으로 **가볍게 시드 포인터만** 모은다 — 진입점 파일 경로 수준이며 **본문은 읽지 않는다**(예: 그로기 → `WxAbility_Groggy.*`, `WxExecCalc_Damage.*`, `WxCombatAttributeSet.*`). 이 경로 목록을 서브에이전트에 넘겨 탐색을 앞당긴다. 못 찾아도 무방하다(서브에이전트가 직접 탐색한다).

### 2.1 GitHub 단락 링크 준비

「기획 항목」을 클릭하면 GitHub 웹에서 **원문 해당 단락으로 점프**하도록, 주장마다 링크를 만든다. 링크에는 **기획서 이름과 단락(섹션)만** 담는다 — 라인 번호로 못 박지 않고 해당 섹션 헤딩 앵커로 넘긴다.

- 베이스: `git config --get remote.origin.url`에서 `OWNER/REPO`를 뽑아(`.git` 제거, SSH `git@github.com:OWNER/REPO.git`·HTTPS `https://github.com/OWNER/REPO.git` 모두) `https://github.com/OWNER/REPO/blob/<브랜치>/<기획서 상대경로>`. 브랜치는 `git rev-parse --abbrev-ref HEAD`, 상대경로는 POSIX 슬래시(`git rev-parse --show-toplevel` 기준)·공백만 `%20`(한글은 그대로).
- 앵커: 주장이 속한 **섹션 헤딩**의 GitHub 슬러그. 헤딩 텍스트를 ①소문자화 ②마침표·괄호 등 부호 제거(글자·숫자·공백·하이픈만 남김, 한글 유지) ③공백을 `-`로. 예: `### 3.2 그로기 상태 효과` → `#32-그로기-상태-효과`, `## 4.1 우선순위` → `#41-우선순위`. 표 행·불릿은 앵커가 없으니 **그것을 감싸는 가장 가까운 섹션 헤딩**을 쓴다.
- 링크 = `<베이스>#<앵커>`. 이걸로 `[<항목 텍스트> (<위치>)](<링크>)` 마크다운 문자열을 주장마다 만들어 서브에이전트에 넘긴다(URL 조립은 오케스트레이터만 하고, 서브에이전트는 받은 문자열을 그대로 쓴다).

`origin`이 없거나 호스트가 `github.com`이 아니면 링크는 생략하고 항목 텍스트만 쓴다(감사는 그대로 진행).

## 3. 검증 서브에이전트 (기본 1개)

`Agent`(subagent_type: `general-purpose`)를 띄운다. 기본은 **1개**. 체크리스트가 크고 **서로 다른 서브시스템**에 걸치면 서브시스템별로 나눠 한 메시지에서 병렬로 띄워도 된다(각자 자기 주장 묶음만 검증). 각 서브에이전트에 전달한다.

- 감사 **주제**와 2절에서 만든 **체크리스트**(주장 목록 + 각 주장의 기획서 내 위치 + 기대값 + 2.1에서 만든 **단락 링크 마크다운 문자열**)
- 2절에서 모은 **시드 포인터**(진입점 파일 경로 목록)
- 아래 **검증 규약**과 **반환 형식**

서브에이전트가 할 일:

1. **파일을 쓰지 않는다.** 읽기·검색만 한다(이 감사는 무수정이 원칙이다).
2. 각 주장을 코드에서 검증한다. **헤더 위주로** 읽되 핵심 로직은 cpp까지 본다. **흐름을 끝까지 추적**한다 — 트리거에서 최종 효과까지, 모듈 경계를 넘어(누가 부르고 무엇과 통신하는지). 모든 파일을 통독하지 않는다.
3. 각 주장을 아래 넷 중 하나로 **판정**하고 **근거(`파일:라인`)** 를 반드시 붙인다. `✅`도 어디서 구현됐는지 근거를 단다.
   - `✅ 일치` — 기획대로 구현됨(값·동작 일치).
   - `❌ 불일치` — 구현은 됐으나 기획과 다름(수치가 다르다·동작이 다르다·조건이 다르다). **「기대 vs 실제」를 한 줄**로.
   - `⚠️ 미구현` — 코드에 해당 규칙의 흔적이 없음.
   - `❔ 확인불가` — 코드만으로 판단 못 함(DataTable Row·BP 디폴트값·에셋 설정에 의존). **무엇을 봐야 하는지** 명시한다. 추측으로 ✅/❌를 찍지 않는다.
4. **역방향(코드 → 기획서)**: 검증 중 마주친, **기획서에 없지만 코드에 존재하는 주목할 동작**을 수집한다(문서에 없는 규칙·수치·분기·예외 처리). 사소한 구현 디테일은 빼고 **기획적으로 의미 있는 것만**.
5. **반환**: 아래 형식의 판정표 + 역방향 발견 목록만 돌려준다. 코드 본문·통독 내용은 반환하지 않는다(오케스트레이터 컨텍스트 절약).

**검증 규약** (서브에이전트에 함께 전달):

- **검증된 사실만.** 파일 경로·타입명·라인은 실제와 정확히 일치해야 한다. 애매하면 `❔ 확인불가`로 둔다.
- **런타임 값 주의.** 수치가 C++ 상수가 아니라 DataTable/DataAsset/BP에 있으면 그 출처를 밝힌다. BP/WBP·에셋 디폴트값이 필요하면 프로젝트 `CLAUDE.md`의 `Blueprint 분석` 절이 안내하는 `Plugins/WxBlueprintSnapshot/Snapshots/` 스냅샷을 참조한다. 스냅샷으로도 불명확하면 `❔ 확인불가`로 두고 어디를 열어봐야 하는지 적는다.
- 식별자(타입·함수·경로·Gameplay Tag)는 **영문 원문 유지**, 설명은 **한국어**.
- 모든 경로는 저장소 루트(`C:\Wx`) 기준 상대경로로 적어 클릭 가능하게 한다.
- 「기획 항목」칸은 오케스트레이터가 준 **단락 링크 마크다운 문자열을 그대로** 넣는다(링크를 새로 만들거나 변형하지 않는다). 링크를 못 받은 주장은 항목 텍스트만 쓴다.

**반환 형식** (서브에이전트가 이대로 돌려줌):

```
## 판정
| # | 기획 항목 (위치) | 판정 | 근거(파일:라인) | 기대 vs 실제 |
|---|---|---|---|---|
| 1 | [받는 피해 30% 증가 (3.2 표)](https://github.com/OWNER/REPO/blob/main/Docs/CombatDesign/그로기_시스템.md#32-그로기-상태-효과) | ❌ 불일치 | WxExecCalc_Damage.cpp:213 | 기대: 그로기 시 ×1.3 / 실제: 배율 없음 |
...

## 코드에만 있는 동작 (기획서 미기재)
- <동작> — <근거 파일:라인> (없으면 "없음")

## 검증 보류 (정성적/모호)
- <주장> — <보류 사유> (없으면 생략)
```

## 4. 보고 (인라인)

서브에이전트 판정을 받아 오케스트레이터가 한국어로 **표 중심으로 깔끔하게** 보고한다. 불일치를 산문으로 다시 풀어 쓰지 않는다 — 판정·근거·기대 vs 실제는 전부 **표 안에서** 끝낸다.

- **요약 한 줄**: `N개 주장 중 ✅X · ❌Y · ⚠️Z · ❔W` 형태로 먼저 결론.
- **판정표**: 서브에이전트 표를 그대로. 「기획 항목」의 GitHub 단락 링크와 `파일:라인`을 모두 클릭 가능하게 유지한다. 링크가 빠진 항목이 있으면 2.1 방식으로 오케스트레이터가 채워 넣는다. 감사 문서가 여럿이면 문서별로 「요약 한 줄 + 표」를 나눠 낸다.
- **기획서에 없는 코드 동작**(역방향)·**검증 보류**: 서브에이전트가 준 목록을 있을 때만 **그대로 짧게** 붙인다(없으면 생략). 따로 부연하지 않는다.
- **맺음(한 줄)**: 아무것도 수정하지 않았고 **검증 보고뿐**임(수정·갱신 제안 없음), 그리고 판정이 코드 근거 기반이라 런타임 데이터(DataTable/BP)·미저장 수정은 못 볼 수 있어 `❔ 확인불가`는 에디터에서 직접 확인을 권한다는 점을 **한 줄로** 덧붙인다.
