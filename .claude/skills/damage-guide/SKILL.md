# 데미지 가이드 생성

게임 코드를 분석하여 기획자용 데미지 가이드 HTML 문서를 `Docs/Guides/damage-guide.html`에 생성하라.

## 대상 독자

대상 독자는 **게임 기획자**. 이 문서는 기획자가 새 공격을 설계할 때 열어보는 데미지 시스템 설명서다.

기획자의 실무 질문은 다음 다섯 가지로 수렴한다:

1. 내가 공격 노티파이에서 뭘 만질 수 있나?
2. HitReact 태그를 바꾸면 플레이어가 뭘 느끼나?
3. 내 공격이 가드/무적/그로기 상태의 적에게 어떻게 되나?
4. 공격력 계수를 얼마로 잡으면 체감이 어떨까?
5. 새 공격을 만들 때 뭘 확인해야 하나?

### 규칙
- C++ 용어(Spec, ExecCalc, SetByCaller, ASC, GameplayEffect 등) 금지
- 의사코드 금지
- HTML `lang="ko"`

## 분석 대상 파일

반드시 Glob으로 찾아서 읽어라. 아래 네 파일만으로 충분하다:

- `**/WxDamageInfo.h` — 기획자가 편집하는 파라미터 (공격력 계수, MP/UP 회복, HitReact 태그, 가드 불가, 추가 이펙트)
- `**/WxExecCalc_Damage.cpp` — 방어 공식, 치명 공식, 가드 감소율, 퍼펙트 가드 처리, 무적 처리, 그로기 처리
- `**/WxAbility_Guard.h` — 퍼펙트 가드 성공 보상. 코드에 하드코딩된 현재 값(`PerfectGuardMPRecovery` 등)을 그대로 읽어 문서에 반영한다
- `**/WxCombatAttributeSet.h` — 가드·치명·그로기 관련 스탯(SP/PP/DP/CritRate/CritDMG) 확인. CritRate·CritDMG는 포인트 단위(1포인트 = 1%)

그 외 파일(WeaponBase, ProjectileBase, AnimNotify, HitReact 어빌리티 등)은 읽지 마라.

## 필수 섹션

### 0. 헤더
- 제목, 문서 생성일(YYYY-MM-DD), 한 줄짜리 문서 설명
- 목차

### 1. 데미지 계산식

**이 문서의 심장부.** 데미지 수치 계산의 흐름을 **세로 분기 트리 한 장**으로 그린다. 단순한 수직 박스 나열 금지. 실제 분기가 측면으로 뻗어나가는 모양이어야 기획자가 한눈에 "어떤 조건이면 어떤 경로로 빠지는가"를 파악할 수 있다.

**트리 구성 (상→하 트렁크):**
1. 공격 적중
2. **무적 판정** → YES면 종료 분기로 빠짐
3. **퍼펙트 가드 판정** → YES면 종료 분기로 빠짐
4. 기본 데미지 = `ATK × 계수 × 100 / (100 + DEF)`
5. **치명타 판정** → YES면 배수 분기(배수 곱)로 측면에 갔다가 메인 흐름으로 돌아옴
6. **가드 감소 판정**(가드 중이고 가드 불가 아님) → YES면 배수 분기(× 0.5)로 측면에 갔다가 메인 흐름으로 돌아옴
7. HP 차감 + 부수 효과 적용

**두 종류의 분기를 시각적으로 구분하라:**
- **종료 분기(terminal)**: 무적, 퍼펙트 가드. 메인 흐름에서 측면으로 빠지면 그대로 계산 종료. 측면 카드에 `END`를 표기하고, 각각 고유 색상을 쓴다 (무적=보라/회피 이벤트, 퍼펙트 가드=청록/DP 반사·MP 회복)
- **배수 분기(modifier)**: 치명타, 가드 감소. 측면에서 배수만 곱한 뒤 메인 흐름으로 돌아온다. 측면 카드는 주황 계열. 측면 카드 서브텍스트는 "배수 적용 후 계산 계속" 같은 평이한 표현을 쓴다("트렁크 복귀", "합류" 같은 기술 용어 금지). 메인 흐름 연결선에도 "YES" 라벨을 붙여 복귀 지점을 명시

**시각 요건:**
- 트렁크는 세로, 분기는 오른쪽으로 뻗는 가로 화살표
- 화살표 색을 목적지 카드 색과 맞춰서(보라/청록/주황) 경로를 색으로 따라 읽을 수 있게 한다
- 각 판정 노드에는 질문 한 줄(예: "퍼펙트 가드?", "치명타 발동?")만 적는다. 긴 설명 금지
- 트렁크 사이 연결선에는 `NO` 또는 `YES` 라벨을 붙여 흐름 방향을 명확히 한다
- 순수 HTML+CSS 박스 구조로 구현. 인라인 SVG 금지

**주석 (트리 아래):**
- "치명타 발동 시 (1 + CritDMG × 0.01)배가 추가로 곱해진다. CritRate·CritDMG는 포인트 값이며 1포인트 = 1%"
- "가드 중인 적에게는 위 값에 0.5를 곱한다. 가드 불가 공격은 가드 중이어도 그대로 들어간다"
- 트리에 쓰인 스탯(ATK / DEF / CritRate / CritDMG)의 역할을 한 줄씩 리스트로 정리한다

### 2. 데미지 입력값
기획자가 공격 노티파이에서 직접 조작하는 값들을 모두 정리한다. 이 섹션은 두 개의 하위 블록으로 구성한다.

**2-1. 파라미터 표** — ATK 계수, MP/UP 회복, 가드 불가, 추가 이펙트 같은 수치·토글 값을 **표 한 장**으로 정리한다.

컬럼:
- 파라미터 이름
- 기본값
- 의미 (짧게)

**2-2. HitReact 태그** — HitReact 태그도 노티파이에서 고르는 입력값이지만, 태그 종류가 정해져 있고 각 태그가 주는 체감이 고유하므로 별도 표로 분리한다. 네 종류(Normal / Knockback / Knockdown / Knockup)를 **표 한 장**으로 정리한다.

컬럼:
- 태그
- 플레이 체감 (한 줄)
- 사용 예시 (한 줄)

PP 잔량 분기, 활성화 조건, 내부 이벤트 흐름 등은 전부 금지. "Normal은 강인도로 버티다가 소진 시에만 경직" 정도까지만 허용.

### 3. 상태별 데미지 결과표
방어자·공격자의 리소스가 상황별로 어떻게 움직이는지 **한 행 = 한 상황** 으로 보여주는 표. 기존 "교차 매트릭스"(공격 종류 × 방어 상태)가 아니라, 행에 상황을 나열하고 열에 스탯을 배치한다.

**행 구성 (6행):**
1. 맨몸
2. 가드 / 일반 공격
3. 가드 / 가드 불가 공격
4. 퍼펙트 가드 (모든 공격)
5. 무적 (모든 공격)
6. 그로기 (모든 공격)

*일반 공격과 가드 불가 공격이 동일한 결과를 내는 상황(맨몸/퍼펙트 가드/무적/그로기)은 한 행으로 통합한다. 가드만 두 행으로 쪼갠다.*

**열 구성 (7열, 방어자 스탯은 `<th colspan="4">방어자</th>` 2단 헤더로 묶는다):**
- 상황 (행 라벨)
- 방어자 HP
- 방어자 DP
- 방어자 SP
- 방어자 PP
- 공격자 MP/UP
- 특이사항 (반사, 가드 해제, 회피 이벤트 등)

**각 셀 표기 규칙 (한두 글자 + 짧은 수식어로만. 긴 설명 금지):**
- HP 감소: `▼ 100%` / `▼ 50%` / `0`
- DP/SP/PP/MP·UP: `▲ 누적`, `▲ 회복`, `▼ 차감`, `▼ 데미지만큼`, `↩ 공격자 반사`, `0`, `—`(해당 없음)
- 셀 배경색으로 결과 유형을 구분한다 (빨강=HP 피해/DP 누적, 주황=리소스 차감, 청록=반사·회복, 보라=회피, 회색=변화 없음/해당 없음)

**표 아래에는 범례 한 줄을 둔다** — 각 색상·아이콘이 무엇을 뜻하는지 작은 칩 리스트로 표기. 표와 범례만 있으면 충분하며, 본문 주석(`<ul>`)은 쓰지 않는다. 예외 케이스는 "특이사항" 열에 한 줄로 녹인다.

**코드에서 정확히 읽어 반영할 수치·엣지케이스:**
- 일반 가드 중 일반 공격: 데미지 50% 감소(코드의 `GuardDamageReductionRate`) + **SP가 감소 후 데미지만큼 차감**(`SP -= FinalDamage`). DP는 그로기가 아니면 누적됨
- 가드 중 가드 불가 공격: 데미지 100% + PP 차감 + 가드 즉시 해제
- 비가드 상태 피격(맨몸/그로기): PP가 데미지만큼 차감됨(`PP -= FinalDamage`)
- 퍼펙트 가드: HP 0 + 공격자에게 DP 반사 + 방어자 MP 회복(`PerfectGuardMPRecovery` 하드코딩 값을 읽어 명시). 방어자의 SP/PP/DP/MP·UP 회복은 없음
- **퍼펙트 가드 × 가드 불가 공격 엣지케이스**: 코드상 퍼펙트 가드 판정이 가드 불가 판정보다 먼저 수행되므로, 가드 불가 공격이어도 퍼펙트 가드 윈도우 중이면 완전 방어된다. 행 구성상 퍼펙트 가드 행의 특이사항에 "가드 불가 공격보다 우선 판정"을 명시
- 무적: 전체 early return이므로 HP/DP/SP/PP/MP·UP **모든 스탯 변화가 0**. 방어자에게 **회피 성공 이벤트 발송**(`Event.DodgeSuccess`). 특이사항에 "회피 이벤트 발송"을 명시
- 그로기: HP는 그대로 통과, DP만 누적 없음(`State_Groggy` 태그 체크). PP는 그대로 차감됨

## HTML 스타일

- 다크 테마 (배경 `#0f1117`, 텍스트 `#e2e4ea`)
- `max-width: 960px` 중앙 정렬
- 순수 HTML+CSS. 인라인 SVG 금지. 외부 의존성 금지
- 매트릭스는 `border-collapse: collapse`, 셀 배경색으로 결과 유형 구분
- 수식이 등장할 때는 인라인 코드(`<code>`)로 표시. 별도 공식 블록 스타일도 허용하되 과하게 쓰지 않는다
- 목차는 상단에 배치
