# 데미지 파이프라인 가이드 생성

게임 코드를 분석하여 데미지 파이프라인 가이드 HTML 문서를 `Docs/Guides/damage-guide.html`에 생성하라.

## 분석 대상

파일 경로가 변경되었을 수 있으므로 반드시 Glob으로 찾아서 읽어라.

### 1. 데미지 페이로드

- `Glob("**/WxDamageInfo.h")`, `Glob("**/WxDamageInfo.cpp")` — AnimNotify에서 기획자가 편집하는 데미지 파라미터(공격력 계수, MP/UP 회복량, HitReact 태그, 가드 무시, 추가 이펙트 목록)

### 2. 데미지 트리거 지점 (AnimNotify)

- `Glob("**/AnimNotify/WxAnimNotifyState_WeaponAttack.*")` — 근접 공격이 무기 콜리전을 켜는 구간
- `Glob("**/AnimNotify/WxAnimNotify_SpawnProjectile.*")` — 투사체를 스폰하는 시점
- `Glob("**/AnimNotify/WxAnimNotifyState_PerfectGuard.*")` — 가드 몽타주 위에 놓여 퍼펙트 가드 판정 윈도우를 부여하는 구간

### 3. 데미지 전달 컴포넌트

- `Glob("**/Weapon/WxWeaponBase.*")` — 근접 무기 콜리전 오버랩 → Spec 적용 흐름
- `Glob("**/Weapon/WxProjectileBase.*")` — 투사체 스폰 시 Spec 캐싱 및 적중 시 적용 흐름

### 4. 데미지 GameplayEffect 및 계산

- `Glob("**/Effect/WxEffect_Damage.*")` — 데미지 GE의 구성 (ExecCalc 연결, Modifier 등)
- `Glob("**/WxExecCalc_Damage.*")` — 최종 데미지 계산식 (ATK × 계수, 방어 배율, 치명타, 가드 감소, 퍼펙트 가드 반사, DP 누적, MP/UP 회복, HitRecovery)
- `Glob("**/Effect/WxEffect_RecoverResource.*")` — 공격자 MP/UP 회복 GE
- `Glob("**/Effect/WxEffect_DrainDP.*")` — 그로기 상태에서 DP를 자동 드레인하는 GE (퍼펙트 가드 반사와는 무관. 반사는 계산기 내부에서 처리됨)

### 5. 피격 리액션 및 상호작용

- `Glob("**/WxGameplayTags.*")` — HitReact 태그(Normal/Knockback/Knockdown/Knockup), Damage.Unblockable, GameplayCue.HitStop 등
- `Glob("**/Ability/WxAbility_HitReact.*")` — HitReact 어빌리티 발동 조건과 분기
- `Glob("**/Ability/WxAbility_Guard.*")` — 가드/퍼펙트 가드 판정 및 데미지 차단 로직
- `Glob("**/WxCombatAttributeSet.*")` — HP/MP/UP/DP/ATK/DEF 등 관련 어트리뷰트

## 문서에 포함할 내용

### 대상 독자

이 문서의 대상 독자는 **게임 기획자**이다. 다음 원칙을 지켜라:

- C++ 클래스명, 함수명, 매크로를 노출하지 않는다 (예: `FWxDamageInfo`, `UWxExecCalc_Damage`, `FGameplayEffectSpec`, `SetByCaller`, `AppendDynamicAssetTags`, `TArray<>` 등)
- "Spec", "ExecCalc", "Modifier", "Context", "Cue", "Loose Tag", "SetByCaller", "Dynamic Tag", "ASC" 같은 GAS 내부 용어를 사용하지 않는다. 불가피하게 언급할 땐 "데미지 설계값", "데미지 계산기", "최종 데미지", "적중 이벤트" 등 기획자 언어로 의역하라
- 의사코드(`if/else`, `Clamp()`, `random()`, `for (...)` 등)를 사용하지 않는다. 조건과 흐름은 자연어 문장과 수식 표기로 설명한다
- 각 단계를 설명할 때 **게임 플레이에서의 체감**(예: "막을 수 없는 공격은 가드로도 대미지를 0으로 만들 수 없다")을 먼저 설명하고, 구체적 수치/공식은 그 다음에 배치한다
- 공식은 수학 표기법으로 작성한다 (예: `최종 데미지 = ATK × 계수 × 방어 배율 × 치명타 배율`)

### 필수 섹션

0. **문서 생성일**: 헤더 영역에 문서가 생성된 날짜를 `YYYY-MM-DD` 형식으로 표시하라

1. **목차**: 모든 섹션에 대한 앵커 링크 목차를 문서 상단에 배치하라

2. **한눈에 보는 파이프라인**: 데미지가 만들어져서 체력이 깎이기까지의 전체 흐름을 하이레벨 다이어그램으로 보여라. 다이어그램은 순수 HTML+CSS(또는 인라인 SVG)로 구현한다. 단계는 다음과 같이 구성하라:
   - (1) 애니메이션에서 데미지 값 설계 (AnimNotify 파라미터)
   - (2) 공격 판정 발생 (무기 콜리전 / 투사체 적중)
   - (3) 적에게 데미지 계산기 투입 (공격자 스탯 + 설계값 전달)
   - (4) 데미지 계산 (방어, 치명타, 가드, 반사, DP 누적)
   - (5) 피격 리액션 발생 (HitReact, 역경직, 리소스 회복)
   - 각 단계에 어떤 데이터가 어떤 방향으로 흐르는지 화살표로 표시하라

3. **데미지 설계값 (AnimNotify 파라미터)**: 기획자가 애니메이션 노티파이에서 직접 조작하는 항목을 설명하라. 각 파라미터에 대해 다음을 포함한다:
   - 이름, 기본값, 의미
   - 게임 플레이에서의 체감 (예: "공격력 계수가 2.0이면 일반 공격보다 두 배 아픈 타격이 된다")
   - 연결되는 계산 지점 (어느 단계에서 이 값이 쓰이는지)

4. **공격 판정의 두 경로**: 근접 무기와 투사체가 어떻게 다른지 비교하는 섹션. 각 경로에 대해:
   - 판정 시작 시점 (무기: ANS의 콜리전 켜짐 / 투사체: 스폰 후 비행)
   - 판정 방식 (무기: 캡슐 오버랩, 한 번의 공격에서 동일 대상 중복 타격 방지 / 투사체: 구 오버랩, 적중 즉시 소멸)
   - 한 스윙 / 한 발당 최대 타격 수
   - 시각적 비교 다이어그램

5. **데미지 계산식**: 코드에서 읽은 실제 공식을 단계별로 보여라. 각 단계를 수식 블록으로 표시하고 수치 예시를 동반하라:
   - (1) 기본 데미지 = ATK × 공격력 계수
   - (2) 방어 적용 = 기본 데미지 × 방어 배율 (DEF에서 방어 배율이 계산되는 정확한 공식을 그대로 옮겨라)
   - (3) 치명타 판정 및 배율 적용. 스탯이 %가 아니라 **포인트** 값임을 명시하라. 예: `치명 확률 = CritRate × 0.01`, `치명 배수 = 1 + CritDMG × 0.01` (하드 상한/클램프가 있으면 명시)
   - (4) 가드 감소 (가드 중이면 감소율, 퍼펙트 가드면 완전 차단 + 반사)
   - (5) 막을 수 없는 공격의 가드/퍼펙트 가드 무시 규칙
   - (6) 최종 데미지가 HP에서 차감되는 시점
   - 최소 1개의 **완성 예시**: 구체적 수치(예: ATK=100, 계수=1.5, DEF=50, 가드 중, 치명타 발동)를 대입하여 단계별로 계산 과정을 보여주는 박스

6. **데미지가 만드는 부수 효과**: 데미지 적중 한 번이 어떤 추가 반응을 일으키는지 정리하라:
   - 공격자 MP/UP 회복 (설계값에서 지정한 양, 0이면 회복 없음)
   - 피격자 DP 누적 (DP가 상한에 도달하면 그로기) — 막을 수 없는 공격이 아닌 일반 공격이 그로기 중 적중했을 때의 처리 등 코드에 있는 엣지 케이스를 반영하라
   - 퍼펙트 가드 성공 시 두 가지 보상을 명시하라:
     - 공격자에게 DP 반사 (데미지량만큼)
     - 방어자 MP 회복 (`WxAbility_Guard::PerfectGuardMPRecovery` 하드코딩 값을 코드에서 읽어 정확히 반영)
     - 플로우: 계산기가 퍼펙트 가드 판정을 감지하면 DP를 반사하고, 방어자에게 퍼펙트 가드 이벤트를 보내며, 가드 어빌리티가 이 이벤트를 받아 MP 회복을 적용한다 (기획자 언어로 의역: "퍼펙트 가드에 성공하면 공격자에게 DP가 되돌아가고, 방어자는 일정량의 MP를 회복한다")
   - 피격 경직 (HitRecovery 또는 역경직 효과) — 공격자의 몽타주가 잠시 일시 정지되는 역경직(HitStop)과 피격자의 HitReact를 구분해서 설명. HitStop의 기본 지속 시간(`HitStopDuration`)도 코드에서 읽어 명시하라
   - 추가 이펙트 목록에 등록된 상태이상/드레인이 함께 적용되는 방식

7. **피격 리액션 분기**: HitReact 태그가 어떻게 분기되는지 표로 정리하라:
   - Normal: 기본 동작 (예: 강인도 잔량이 있으면 흔들림만, 소진 시 경직)
   - Knockback / Knockdown / Knockup: 발동 조건과 플레이 체감
   - 각 태그가 플레이어 체감에 주는 차이 (예: Knockdown은 다운, 후속 콤보 가능 여부 등)
   - 코드에서 발견된 실제 분기 조건을 반영하라 (추측 금지)

8. **가드 피격 분기**: 가드 중에 공격을 맞았을 때 가드 어빌리티 내부에서 어떻게 분기되는지 설명하라. 코드에서 발견된 실제 분기를 반영하라:
   - 일반 공격을 가드: 가드 히트 리액션 몽타주 재생 (경직만)
   - Knockback 계열 공격을 가드: 가드 브레이크 몽타주 재생 및 가드 해제 여부
   - 막을 수 없는 공격이 적중: 가드가 즉시 풀리고 일반 HitReact로 전환

9. **상호작용 매트릭스**: 공격 성질(일반 / 막을 수 없는 공격)과 방어 상태(가드 / 퍼펙트 가드 / 무적 / 그로기 / 맨몸)의 교차표를 만들어라. 각 셀에는 결과를 표시한다. 다음 수치는 코드에서 직접 확인하여 정확히 반영하라:
   - 가드 중 일반 공격 피격: 데미지에 가드 감소율 적용 + **SP 소모량 = 감소 후 데미지 값** (코드상 `SP -= FinalDamage`)
   - 퍼펙트 가드 중 일반 공격 피격: 데미지 0 + 공격자에게 DP 반사 + 방어자 MP 회복 (`PerfectGuardMPRecovery` 값을 코드에서 읽어 명시)
   - 무적 중 피격: 코드에서 무적 처리 지점을 찾아 (1) 데미지 적용 여부, (2) MP 회복 여부, (3) 퍼펙트 회피 이벤트 발생 여부를 모두 확인하고 셀에 정확히 반영하라. 추측 금지
   - 그로기 중 피격: 데미지 적용되지만 DP 누적 없음
   - 막을 수 없는 공격: 가드/퍼펙트 가드 효과 무시
   
   셀 배경색으로 결과 유형을 직관적으로 구분한다 (무효/차단=회색, 감소=노랑, 반사=청록, 그대로 통과=빨강 등).

10. **기획자 체크리스트**: 새 공격 애니메이션에 데미지를 붙일 때 기획자가 확인해야 할 항목을 순서대로 정리하라:
   - AnimNotify를 어디에 배치할지
   - 공격력 계수를 어느 범위로 잡을지 (일반/강공격/스킬/궁극기 권장 범위)
   - HitReact 태그를 언제 변경할지
   - 추가 이펙트를 넣는 경우 고려할 점 (중첩, 지속시간)
   - 막을 수 없는 공격으로 설정해야 하는 경우

### 다이어그램 가이드

문서에는 최소 3개의 다이어그램이 포함되어야 한다:

1. **파이프라인 플로우차트** (섹션 2): 박스-화살표 구조. 각 단계의 배경색을 단계별로 다르게 하고, 화살표에는 흐르는 데이터의 이름(예: "데미지 설계값", "적중 이벤트", "최종 데미지")을 명시한다.
2. **근접 vs 투사체 비교** (섹션 4): 두 경로를 나란히 배치한 좌/우 구조.
3. **리소스 & DP 순환도** (섹션 6): 데미지 한 번이 공격자 리소스와 피격자 DP를 어떻게 움직이는지 보여주는 양방향 다이어그램.

다이어그램은 모두 **순수 HTML+CSS** 혹은 **인라인 SVG**로 구현한다. 외부 이미지나 라이브러리를 사용하지 않는다.

### 수치 정확성

- 모든 수치와 공식은 반드시 코드에서 직접 읽어서 작성하라
- 하드코딩된 상수(가드 감소율, 퍼펙트 가드 반사량, MP/UP 회복 기본값, 치명타 배율, DP 상한 등)를 정확히 반영하라
- 추측하지 말고 코드에 있는 값만 사용하라. 코드에 없는 값은 "컨텐츠 데이터에 따라 달라짐"으로 표기하라

### 언어

- 문서의 모든 텍스트는 한국어로 작성하라
- HTML 태그의 `lang` 속성은 `ko`로 설정하라
- 경어체(~합니다)가 아닌 평서체(~한다, ~이다)를 사용하라

## HTML 스타일

- 다크 테마 기반 (배경 #0f1117, 텍스트 #e2e4ea)
- 카드형 레이아웃으로 각 섹션을 구분
- 단계별 색상 구분:
  - 설계값 (AnimNotify): 노랑 (#ffd93d)
  - 판정/전달: 주황 (#ff9f43)
  - 계산: 빨강 (#ff6b6b)
  - 부수 효과: 청록 (#4ecdc4)
  - 리액션: 보라 (#b794f6)
- 공식 블록은 별도 스타일 (연한 배경, 좌측 강조 보더)로 구분한다. 공식 블록도 일반 sans-serif 폰트를 사용한다
- 수치 예시 박스는 연한 배경에 단계별 계산 결과를 `→` 기호로 연결하여 보여준다
- 상호작용 매트릭스는 `border-collapse: collapse`를 적용하고, 셀 배경색으로 결과를 직관적으로 구분한다
- 다이어그램은 flex/grid 기반 박스-화살표 또는 인라인 SVG로 구현한다
- 반응형 레이아웃 (max-width: 960px)
- 외부 의존성 없이 순수 HTML+CSS로 작성
- 중요 수치나 키워드는 `<strong>` 또는 컬러 `<span>`으로 강조한다
- 목차는 문서 상단에 배치하고, 각 항목에 단계별 색상을 적용한다

## 출력

`Docs/Guides/damage-guide.html`에 생성하라. 기존 파일이 있으면 덮어쓴다.
