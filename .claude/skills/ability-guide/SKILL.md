# 어빌리티 가이드 생성

게임 코드를 분석하여 어빌리티 가이드 HTML 문서를 `Docs/Guides/ability-guide.html`에 생성하라.

## 분석 대상

### 어빌리티 클래스 (자동 탐색)

1. `Glob("**/WxAbility.h")`와 `Glob("**/WxAbility.cpp")`로 베이스 클래스를 찾아 읽어라
2. `Glob("**/WxAbility_*.h")`와 `Glob("**/WxAbility_*.cpp")`로 모든 어빌리티 서브클래스를 찾아 읽어라
3. 발견된 모든 어빌리티를 빠짐없이 문서에 포함하라. 새로운 어빌리티가 추가되더라도 이 스킬을 수정할 필요가 없어야 한다

### 어빌리티 태스크 (자동 탐색)

`Glob("**/Task/WxAbilityTask_*.h")`와 `Glob("**/Task/WxAbilityTask_*.cpp")`로 모든 어빌리티 태스크를 찾아 읽어라. 어빌리티의 내부 동작(회전 보정, 락온 카메라, 컷씬 연출 등)을 이해하는 데 필요하다.

### 관련 시스템

다음 파일들도 함께 분석하라. 파일 경로가 변경되었을 수 있으므로 Glob으로 찾아서 읽어라.

- **게임플레이 태그**: `WxGameplayTags.h` — 상태 태그, 이벤트 태그, ANS 태그, 입력 태그, 차지 태그
- **어빌리티 셋**: `WxAbilitySet.h` — 캐릭터에 부여되는 어빌리티/이펙트/어트리뷰트 초기값
- **어빌리티 시스템 컴포넌트**: `WxAbilitySystemComponent.h` / `WxAbilitySystemComponent.cpp` — 입력 처리, 어빌리티 부여
- **대미지 계산**: `WxExecCalc_Damage.h` / `WxExecCalc_Damage.cpp` — 가드 감소, 퍼펙트 가드 반사, DP 누적, 리소스 회복
- **화상 계산**: `WxExecCalc_Burn.h` / `WxExecCalc_Burn.cpp` — 화상 지속 대미지 공식
- **이펙트**: `Glob("**/Effect/WxEffect_*.h")`로 탐색하라 — 비용, 쿨다운, 회복, 버프, 상태이상 등 어빌리티와 관련된 모든 이펙트
- **어트리뷰트 셋**: `WxCombatAttributeSet.h` — PP, DP, SP 등 어빌리티와 관련된 어트리뷰트 이해

## 문서에 포함할 내용

### 대상 독자

이 문서의 대상 독자는 **게임 기획자**이다. 다음 원칙을 지켜라:

- C++ 클래스명, 함수명을 노출하지 않는다 (예: `UWxAbility_Attack`, `ActivateAbility`, `WaitTargetData`, `TMap<>` 등)
- "어빌리티 태스크", "ExecCalc", "SetByCaller", "Loose Tag Count", "AbilitySpec", "TargetData" 같은 GAS 내부 용어를 사용하지 않는다
- 의사코드(`if/else`, `random()`, `Clamp()` 등)를 사용하지 않는다. 조건과 흐름은 자연어 문장으로 설명한다
- 각 어빌리티를 설명할 때 **게임 플레이에서의 체감**을 먼저 설명하고, 구체적 수치/조건은 그 다음에 배치한다

### 필수 섹션

0. **문서 생성일**: 헤더 영역에 문서가 생성된 날짜를 `YYYY-MM-DD` 형식으로 표시하라

1. **목차**: 모든 섹션에 대한 앵커 링크 목차를 문서 상단에 배치하라

2. **어빌리티 총괄표**: 탐색된 모든 어빌리티를 한눈에 볼 수 있는 요약 테이블
   - 컬럼: 어빌리티 이름, 카테고리, 입력 방식(누르기/홀드/토글/자동), 비용(MP/UP/SP), 쿨다운, 차지 수, 한 줄 설명
   - 반응형 어빌리티(자동 발동)는 별도 섹션으로 분리한다

3. **어빌리티 카테고리 분류**: 탐색된 어빌리티를 코드 분석을 통해 아래 4개 카테고리로 분류하라. 분류 기준은 어빌리티의 실제 동작(입력 바인딩 여부, 공격/방어/이동 성격, 자동 발동 여부)을 기반으로 판단한다.
   - **전투**: 적에게 대미지를 주거나 공격 행위를 수행하는 어빌리티
   - **방어**: 대미지를 줄이거나 회피하는 어빌리티
   - **이동**: 캐릭터의 이동 방식을 변경하는 어빌리티
   - **기타**: 위 카테고리에 속하지 않는 어빌리티 (락온 등)
   - **반응형**: 플레이어가 직접 발동하지 않고 게임 상황에 의해 자동 발동되는 어빌리티

4. **카테고리별 어빌리티 상세**: 각 카테고리에 속하는 어빌리티를 개별 카드로 상세 설명한다. 어빌리티마다 다음 항목을 코드에서 분석하여 해당하는 내용만 포함한다:
   - 게임 플레이에서의 구체적인 예시 (첫 번째에 배치)
   - 발동 조건 및 입력 방식
   - 사용 흐름 (활성화 → 진행 → 종료)
   - 주요 수치 (비용, 쿨다운, 감소율, 보너스, 차지 수 등 코드에 있는 것만)
   - 특수 메커니즘 (콤보, 퍼펙트 가드, 무적 구간, 퍼펙트 회피, 컷씬, 차지 충전 등 해당 어빌리티에 고유한 것)

5. **콤보 시스템**: 공격 어빌리티의 콤보 경로 구조를 설명하라
   - 콤보 경로 표기법 (약공격, 강공격의 조합)
   - 콤보 윈도우의 의미 (연결 가능 구간)
   - 콤보 경로와 모션의 매핑 관계

6. **리소스 순환 구조**: MP, UP, SP의 획득과 소비 흐름을 다이어그램으로 정리하라
   - MP: 일반 공격 적중 시 회복량 → 스킬 사용 시 소비량
   - UP: 스킬 적중 시 회복량 → 궁극기 사용 시 소비량
   - SP: 자연 회복 속도/조건 → 가드 피격 시 소비 구조
   - 각 수치는 코드에서 읽은 정확한 값을 사용한다

7. **상태이상 시스템**: 코드에서 발견된 상태이상(화상 등)을 정리하라
   - 발동 조건, 지속 시간, 틱 간격, 대미지 공식
   - 가드/무적과의 상호작용

8. **어빌리티 상호작용 매트릭스**: 어빌리티 간 상호작용을 표로 정리하라
   - 가드 중 피격 → 대미지 감소율, SP 소모
   - 퍼펙트 가드 → DP 반사, MP 회복
   - 무적 구간(회피/궁극기) 중 피격 → 대미지 무효, MP 회복, 퍼펙트 회피 이벤트 발생
   - 막을 수 없는 공격 → 가드/퍼펙트 가드 무시
   - 그로기 상태 → DP 누적 무시

9. **상태 태그 정리**:
   - 게임에서 사용되는 주요 상태(사망, 공중, 그로기, 락온 등)와 판정 구간(무기 충돌, 콤보 윈도우, 무적, 가드, 퍼펙트 가드 등)을 기획자 용어로 정리
   - 각 상태/판정이 게임 플레이에 미치는 영향을 한 줄로 설명

### 수치 정확성

- 모든 수치는 반드시 코드에서 직접 읽어서 작성하라
- 코드에 하드코딩된 상수(비용, 쿨다운, 감소율, 보너스, 지속시간, 회복량, 차지 수 등)를 정확히 반영하라
- 추측하지 말고 코드에 있는 값만 사용하라

### 언어

- 문서의 모든 텍스트는 한국어로 작성하라
- HTML 태그의 `lang` 속성은 `ko`로 설정하라
- 경어체(~합니다)가 아닌 평서체(~한다, ~이다)를 사용하라

## HTML 스타일

- 다크 테마 기반 (배경 #0f1117, 텍스트 #e2e4ea)
- 카드형 레이아웃으로 각 어빌리티를 구분
- 어빌리티 카테고리별 색상 구분:
  - 전투: 빨강 (#ff6b6b)
  - 방어: 청록 (#4ecdc4)
  - 이동: 초록 (#95e86e)
  - 기타: 보라 (#b794f6)
  - 반응형: 노랑 (#ffd93d)
- 각 어빌리티 카드에 카테고리 색상의 좌측 보더를 적용한다
- 리소스 순환 다이어그램은 순수 HTML+CSS (또는 SVG)로 구현한다
- 상호작용 매트릭스는 테이블로, 셀 배경색으로 결과를 직관적으로 구분한다 (무효=회색, 감소=노랑, 반사=청록 등)
- 목차는 문서 상단에 고정하되, 카테고리 색상을 사용하여 시각적으로 구분한다
- 반응형 레이아웃 (max-width: 960px)
- 외부 의존성 없이 순수 HTML+CSS로 작성
- 중요 수치나 키워드는 `<strong>` 또는 컬러 `<span>`으로 강조한다
- 테이블은 `border-collapse: collapse`를 적용하고, 헤더 행은 어두운 배경(#1a1d27)으로 구분한다
