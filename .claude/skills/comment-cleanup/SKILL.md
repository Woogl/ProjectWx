# 주석 정리

지정한 범위의 `.h`/`.cpp` 주석을 정리한다. **간결한 주석이 기본값이고, 자명한 내용은 남기지 않는다** — 이 프로젝트의 확정된 선호다. 코드에서 읽히는 말을 걷어내면 남은 주석은 전부 "코드가 못 하는 말"이 되고, 그때부터 독자가 주석을 믿을 수 있다.

자명한 것에 성역은 없다. 구획 라벨이든 `UPROPERTY` 툴팁이든, 이름을 되풀이할 뿐이면 지운다.

핵심 원칙은 세 가지다.

1. **컨텍스트 폭발 방지** — 오케스트레이터(이 스킬을 실행하는 너)는 소스를 직접 통독하지 않는다. 대상 파일을 폴더 단위로 갈라 **서브에이전트**에 나눠 주고, 각자 자기 몫만 읽고 고치게 한다. 여러 묶음은 한 메시지에서 병렬로 띄운다.
2. **코드 불가침** — 이 스킬은 **주석만** 바꾼다. 코드 라인이 한 줄이라도 바뀌면 실패다(4절 안전 게이트에서 기계적으로 검증한다). 리팩터·이름 변경·`#include` 정리는 전부 범위 밖이며, "정리하다 눈에 띈 버그"도 고치지 않고 보고만 한다.
3. **삭제보다 정정** — 코드와 어긋난 낡은 주석은 이 작업에서 가장 값진 발견이다. 지워서 없애지 말고 사실에 맞게 고친다. 사실을 코드로 확정하지 못하면 손대지 말고 보고에 올린다.

## 1. 대상 결정 (인자 처리)

`Glob("Plugins/*/*.uplugin")`로 플러그인을, `Glob("Source/*/*.Build.cs")`로 소스 모듈(`WxGame` 등)을 동적으로 발견한다. 새 모듈이 추가돼도 이 스킬을 고칠 필요가 없어야 한다.

| 인자 | 대상 |
| --- | --- |
| 없음 | 워킹트리 + `HEAD` 대비 변경된 `.h`/`.cpp` (`git status --porcelain`, `git diff --name-only HEAD`) |
| 모듈명 (`WxInventory`) | 플러그인이면 `Plugins/<Name>`, 소스 모듈이면 `Source/<Name>` 아래 전부 |
| 경로 (`Plugins/WxAI/Source/WxAI/Private`) | 그 경로 아래 전부 |

- **인자 없음**이고 변경분이 0이면 진행하지 말고, 모듈명을 지정해 달라고 한국어로 되묻는다.
- 발견된 모듈 목록에 없는 이름이면 정리하지 말고 유효한 모듈 목록을 한국어로 안내한다.
- 대상에서 **항상 제외**: `Intermediate/`, `Binaries/`, `*.gen.cpp`, `*.generated.h`, `ThirdParty/`.
- 대상 파일이 30개를 넘으면 몇 개인지, 묶음 몇 개로 나눠 몇 차수로 돌릴지 먼저 알리고 진행한다(사용자가 범위를 줄일 기회를 준다). 파일 수가 많으면 오래 걸린다는 사실 자체를 미리 알려 두는 편이 낫다.

**사전 점검** — `git status --porcelain -- <대상경로>`로 대상에 이미 미커밋 변경이 있는지 본다. 있으면 그 파일 목록을 마무리 보고에 명시한다(정리 diff와 기존 작업이 섞여 보이므로 사용자가 알아야 한다). 진행 자체는 막지 않는다.

## 2. 정리 규칙

이 절이 이 스킬의 본체다. 서브에이전트에 **그대로** 전달한다.

### 지운다

- 함수명·변수명·바로 아랫줄에서 읽히는 재서술. 지웠을 때 독자가 잃는 것이 없으면 재서술이다.
- 헤더에 이미 있는 계약을 cpp에서 반복하는 중복 서술. 한 사실은 한 곳에만 적는다 — cpp에는 **그 자리에서만 알 수 있는 것**만 남긴다.
- 코드에 그대로 있는 수식·상수를 다시 적은 주석.
- `UPROPERTY`의 `/** */` 중 프로퍼티 이름을 한국어로 옮긴 것. 에디터 툴팁이라도 이름을 되풀이할 뿐이면 지운다.
- 읽는 사람이 알아서 판단할 몫에 대한 조언·권장. 어떻게 조립하면 좋은지, 언제 쓰면 좋은지, 노드를 여럿 얹으라는 식의 사용법 안내.

```cpp
// Before
// 사망 판정
if (TargetASC->HasMatchingGameplayTag(WxGameplayTags::State_Dead))

// After  (주석 삭제, 코드 그대로)
if (TargetASC->HasMatchingGameplayTag(WxGameplayTags::State_Dead))
```

### 남긴다 — 건드리지 않는다

- **왜** 그렇게 했는지, 전제·제약, 엔진 함정, 순서가 그래야 하는 이유. 이 코드베이스가 이미 잘 하고 있는 쪽이고, 없애면 "불필요해 보이는 코드"로 오판해 건드릴 위험이 생긴다.
- `UPROPERTY`의 `/** */` 중 이름만으로는 모르는 것 — 단위·유효 범위·기획 의도·다른 값과의 관계. 툴팁이라 남기는 게 아니라 **비자명해서** 남긴다.
- `//~ Begin/End <Type>`, `// IInterface` 등 구조 마커. 마커 스타일 통일도 이 스킬이 할 일이 아니다.
- 첫 줄 `// Copyright Woogle. All Rights Reserved.`
- `TODO`/`HACK` — 문구는 다듬되 항목 자체는 유지한다.

### 줄인다

내용이 비자명해도 문단이 됐으면 결론 한 줄로 줄인다. 엔진 호출 순서 추적·소스 인용 같은 **조사 과정은 worklog 몫**이지 주석 몫이 아니다.

### 고친다 — 가장 중요한 작업

주석이 말하는 사실을 **코드로 확인**한다. 어긋나면 지우지 말고 정정한다. 실제로 나온 유형:

- 이미 사라진 Gameplay Tag·클래스·함수를 예시로 든 주석
- 존재하지 않는 처리 단계를 설명하는 주석
- 실제와 다른 에셋·몽타주·변수 이름

확인 방법은 `Grep`이다 — 주석이 인용한 식별자를 저장소에서 검색해 실존하는지, 그 자리에서 그렇게 쓰이는지 본다. **코드로 사실을 확정하지 못하면 그 주석은 손대지 말고 보류로 보고한다.** 추측으로 고쳐 쓴 주석은 원래의 낡은 주석보다 해롭다.

**확인 대상은 파일 밖을 가리키는 주석 전부다.** 다른 클래스·태그·에셋·처리 단계를 인용한 서술은 그것들이 바뀔 때 소리 없이 낡으므로, 의심이 들지 않아도 확인한다. 낡은 주석은 원래 낡아 보이지 않는다 — 그래서 남아 있는 것이다. 반대로 같은 파일 안에서 참·거짓이 드러나는 서술은 읽는 것으로 판정이 끝나니 따로 확인하지 않는다.

**멈추는 기준은 조회 횟수가 아니라 담당 파일로부터의 거리다.** 확인이 담당 파일 밖으로 두 단계 이상 번지면 그 자리에서 보류한다. 파일 A의 주석을 확인하려고 B를 열었는데 B가 다시 C를 봐야 한다면, 그 사실은 C++ 안에 없거나 있어도 이 작업에서 확정할 것이 아니다. 한 단계 안에서라면 몇 번을 찾아보든 상관없다.

**한 주석이 파일 전체를 멈춰 세우지 않게 한다.** 확정이 안 되면 보류로 적고 다음 주석으로 넘어간다. 보류는 실패가 아니라 결과물의 일부다 — 코드로 확정할 수 없는 사실을 사용자에게 넘기는 것이고, 그게 이 스킬이 낼 수 있는 가장 정직한 답이다.

### 형식

- **한 문장 한 줄.** 문장 중간에서 줄바꿈하지 않고, 여러 문장을 한 줄에 몰아쓰지도 않는다. 문단 구분은 빈 주석 줄로 한다.
- 짧은 2문장 한 줄은 허용한다. 3문장 이상이면 줄을 나눈다.
- 한국어 **반말 평서체**(개발자용 내부 주석 기준). 식별자·타입명·태그명은 영문 원문 유지.

### 금지

- **코드 라인 수정 금지.** 로직·이름·`#include`·공백 정렬 전부. 트레일링 주석(`Code(); // 설명`)을 고칠 때도 `//` 앞부분은 한 글자도 바꾸지 않는다.
- **주석 신규 작성 금지.** 이 스킬은 덜어내고 고치는 작업이다. 주석이 없는 코드에 설명을 채워 넣지 않는다(예외: 위 "고친다"에서 정정하는 경우).
- 파일 전체를 `Write`로 다시 쓰지 않는다. 반드시 `Edit`로 해당 주석만 바꾼다.

## 3. 정리 서브에이전트 (병렬)

오케스트레이터가 대상 파일 목록을 확정해 **폴더 단위로 묶어** 나눈다. 한 묶음은 파일 8~12개가 적정이고, 묶음끼리 파일이 겹치면 안 된다(같은 파일을 두 에이전트가 `Edit`하면 충돌한다). 묶음마다 `Agent`(subagent_type: `general-purpose`)를 하나씩 띄운다.

묶음 크기는 파일 수가 아니라 **주석 밀도**로 정한다. 클래스 레벨 doc이 길고 다른 모듈의 식별자를 많이 인용하는 폴더(ViewModel·Experience 같은 배선 코드)는 확인할 주장이 많으니 6개 이하로 줄인다.

**한 번에 띄우는 묶음은 6개까지.** 동시 실행에는 상한이 있어 그 이상 띄우면 초과분은 보이지 않는 대기열에 들어간다. 대기 중인 에이전트도 겉보기엔 "실행 중"이라 정말 느린 묶음과 구별할 수 없어지고, 아래 지연 판정도 같이 망가진다. 파일 4개짜리 묶음이 22분 걸린 적이 있는데 대부분이 대기 시간이었다. 6개를 띄우고, 완료 알림이 올 때마다 남은 묶음을 하나씩 채워 넣는다.

각 서브에이전트에 전달할 것:

- **담당 파일 목록**(절대 경로). 이 목록 밖의 파일은 읽어도 되지만 **고치지 않는다**.
- 2절 **정리 규칙 전문**.
- **진행 상한** — 담당 파일을 순서대로 **한 번씩만** 훑는다. 끝낸 파일로 되돌아가 다시 검토하지 않고, 확인이 막히면 붙들지 말고 즉시 보류로 넘긴다.

서브에이전트가 할 일 — **파일 단위로 끝내고 다음 파일로 넘어간다.** 전체를 조사한 뒤 마지막에 몰아서 고치지 않는다. 중간에 중단돼도 이미 끝낸 파일은 남기 위해서다.

한 파일에서:

1. 파일을 읽고 주석마다 "지운다 / 남긴다 / 줄인다 / 고친다"를 판정한다. 판정이 서지 않으면 **남긴다**가 기본값이다. 어긋나 보이는 주석은 "고친다" 후보로 적어만 둔다.
2. **먼저** 지운다·줄인다를 `Edit`로 적용한다. 이건 확인이 필요 없고 이 작업 성과의 대부분이다. 손댈 이유가 없는 주석은 그대로 둔다 — 전부 다시 쓰려 하지 않는다.
3. **그다음** 1에서 적어 둔 후보를 `Grep`으로 확인해 정정한다. 확정되지 않으면 보류로 적고 다음 주석으로 넘어간다. 이 단계가 이 작업에서 가장 오래 끄는 지점이다 — **후보는 1에서 적어 둔 것으로 닫는다.** 확인하다 새로 떠오른 의심은 이번 파일에서 다루지 않는다.
4. 마지막 메시지에 본문·diff를 반환하지 말고 아래 형식만 반환한다.

```
DONE <담당 파일 수>개 · 삭제 <N>줄 · 압축 <M>건 · 정정 <K>건 · 보류 <J>건
정정: <파일:라인> — <무엇이 틀렸고 무엇으로 고쳤는지 한 줄>
보류: <파일:라인> — <왜 확정 못 했는지 한 줄>
```

정정·보류가 없으면 그 줄은 생략한다. 정리할 것이 없던 파일은 언급하지 않는다.

### 지연 대응

완료 알림을 기다리는 동안 **에이전트의 진행 여부는 파일 수정 시각으로 판정한다.** 서브에이전트는 `Edit`할 때마다 파일을 건드리므로, 최근 쓰기가 곧 살아 있다는 증거다. 마지막 알림 이후 한동안 조용하면 확인한다(해당 묶음의 담당 폴더를 대상으로).

```powershell
Get-ChildItem <묶음 폴더> -Recurse -Include *.h,*.cpp |
  Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, LastWriteTime
```

- 최근 쓰기가 계속 갱신되면 정상이다. 기다린다.
- **10분 넘게 그 묶음 파일에 쓰기가 없으면 지연으로 본다.** `git status --porcelain -- <묶음 경로>`로 어디까지 적용됐는지 확인한 뒤 그 에이전트를 정지시키고, 같은 파일 목록을 **절반 크기로 쪼개** 다시 띄운다. 같은 크기로 다시 띄우면 같은 자리에서 다시 끈다.
- **이미 적용된 편집은 되돌리지 않는다.** 새 에이전트에 "앞선 시도가 중단돼 일부 파일은 이미 정리돼 있을 수 있으니, 현재 파일 상태를 기준으로 남은 주석만 판정하라"를 덧붙인다.

에이전트의 트랜스크립트 출력 파일은 읽지 않는다 — 오케스트레이터 컨텍스트가 터진다. 진행 확인은 위 파일 수정 시각과 `git status`로만 한다.

## 4. 안전 게이트 (코드 불가침 검증)

서브에이전트가 모두 끝나면 오케스트레이터가 **직접** 검증한다. 건너뛰지 않는다.

```bash
git diff -U0 -- <대상경로> \
  | grep -E '^[+-]' \
  | grep -vE '^(\+\+\+|---)' \
  | grep -vE '^[+-][[:space:]]*(//|/\*|\*)' \
  | grep -vE '^[+-][[:space:]]*$'
```

- **출력이 비면 통과.** 전체 줄 주석과 빈 줄만 바뀌었다는 뜻이다.
- **출력이 남으면** 코드 라인이 바뀌었거나, 트레일링 주석이 있는 코드 라인이 바뀐 것이다. 둘은 다르므로 자동 판정하지 말고 해당 파일의 diff를 `git diff -- <파일>`로 직접 읽어 **`//` 앞부분이 동일한지** 확인한다.
  - 앞부분이 같으면 트레일링 주석만 바뀐 것 → 통과.
  - 다르면 **코드 변경**이다 → `Edit`로 코드 부분만 원래대로 되돌리고, 마무리 보고에 어떤 파일에서 무엇이 바뀌었었는지 명시한다.

> `git checkout --`으로 파일을 통째로 되돌리지 않는다. 워킹트리에 사용자의 다른 미커밋 작업이 섞여 있을 수 있어 파괴적이다.

편집 시점에도 같은 기준이 한 번 더 걸린다 — worklog 게이트 훅(`.claude/scripts/check-worklog.py`)이 `Edit`의 전후 코드 잔여물을 비교해 주석만 바뀌면 승인 없이 통과시키고, 코드가 섞이면 그 자리에서 승인을 묻는다. 서브에이전트가 파일마다 멈춰 서지 않는 이유이자, 코드 불가침 위반이 이 게이트까지 오지 않고 그 자리에서 드러나는 경로다.

빌드는 돌리지 않는다 — 주석 전용 변경이라 `CLAUDE.md`의 사소 작업 예외에 해당하고, 위 게이트가 컴파일보다 정확한 검증이다. 커밋도 하지 않는다(`/push`가 담당).

## 5. 마무리 보고

한국어로 짧게 보고한다.

- **집계 한 줄**: 대상 파일 수, 손댄 파일 수, 삭제 줄 수, 압축·정정 건수.
- **보류 목록** — 낡아 보이지만 확정 못 해 남긴 주석. 사용자가 아는 사실로 판단하면 된다.
- **수정 결과** — 통과면 "코드 변경 0 확인", 되돌린 것이 있으면 파일과 내용을 명시.
- 사전 점검에서 잡힌 **기존 미커밋 변경 파일**이 있으면 "정리 diff와 섞여 있음"을 한 줄로.
- 지연으로 **정지·재투입한 묶음**이 있으면 어느 묶음인지 한 줄로.
- 정리하다 눈에 띈 코드 문제는 **고치지 않았다는 점과 함께** 한 줄로만 덧붙인다.
