# 모듈 README 생성·갱신

프로젝트의 각 **플러그인/모듈**을 분석해 개발자·미래 세션이 빠르게 코드를 잡을 수 있는 **오리엔테이션 맵**을 그 모듈 폴더의 `README.md`로 만든다. 플러그인은 `Plugins/<Name>/README.md`, 게임 모듈은 `Source/WxGame/README.md`. 코드 옆에 두어 지역성·이식성을 살린다.

핵심 원칙은 두 가지다.

1. **컨텍스트 폭발 방지** — 오케스트레이터(이 스킬을 실행하는 너)는 소스를 직접 통독하지 않는다. 모듈마다 **서브에이전트 1개**를 띄워 각자 자기 모듈만 읽고 README를 직접 쓰게 한다. 여러 모듈은 한 메시지에서 병렬로 띄운다.
2. **점진적 갱신** — 각 README 끝에 보이는 provenance 라인으로 생성 시점 커밋 SHA를 노출한다. 재실행 시 그 SHA 이후 변경된 모듈만 골라 재생성한다.

---

## 1. 대상 결정 (인자 처리)

`Glob("Plugins/*/*.uplugin")`로 플러그인을 동적으로 발견하고, 게임 모듈 `Source/WxGame`을 더한다. 새 플러그인이 추가돼도 이 스킬을 고칠 필요가 없어야 한다.

모듈 → 경로 / 본문 위치 매핑:

| 종류 | 분석 경로(소스) | 본문 README |
| --- | --- | --- |
| 플러그인 `<Name>` | `Plugins/<Name>` | `Plugins/<Name>/README.md` |
| 게임 모듈 WxGame | `Source/WxGame` | `Source/WxGame/README.md` |

인자에 따라 대상 집합을 정한다.

- **인자 없음** (기본): `git rev-parse --short HEAD`로 현재 SHA를 구한 뒤, 각 모듈의 README 상태를 판정해 **missing 또는 stale인 모듈만** 대상으로 삼는다. fresh면 건너뛴다. 대상이 0개면 "모두 최신"이라고 보고한다.
- **모듈명 1개 이상** (예: `WxCombat`, `WxCombat WxInventory`): 그 모듈만 강제 재생성. 발견된 모듈 목록에 없는 이름이면 생성하지 말고, 유효한 모듈 목록을 한국어로 안내한다.
- **`all`**: 발견된 모든 모듈을 재생성.

### Stale 판정

각 README **끝**에는 다음 형식의 provenance 라인이 있다. 숨기지 않고 렌더링에 그대로 노출한다(독자가 문서가 어느 시점 기준인지 바로 알 수 있게):

```
*문서 기준 커밋 `<short-sha>` · 생성일 <YYYY-MM-DD> · 소스 <N>파일 — `/readme-writer`로 갱신*
```

판정 절차(모듈 경로 = 위 표의 "분석 경로"):

1. README 파일이 없으면 → **missing**.
2. `Grep`으로 `문서 기준 커밋` 라인을 찾아 백틱 안의 `<sha>`를 읽는다. 없으면 → **stale**(구버전 문서).
3. `git diff --name-only <sha> HEAD -- <모듈경로>` 와 `git status --porcelain -- <모듈경로>` 를 확인한다. 둘 중 하나라도 변경이 있으면 → **stale**. 둘 다 비어 있으면 → **fresh**.

> 비교 대상은 소스 디렉터리다. README.md 자체의 수정은 staleness에 영향을 주지 않도록 `<모듈경로>`로 한정해 diff한다.

## 2. 모듈별 서브에이전트 (병렬)

대상 모듈마다 **서브에이전트 1개**를 띄운다(`Agent`, 여러 모듈이면 한 메시지에 여러 호출로 병렬). 각 서브에이전트에 아래를 전달한다.

- 모듈명, 분석 경로, 본문 README 경로
- 문서 끝에 그대로 박을 provenance 라인 — 커밋은 현재 `git rev-parse --short HEAD`, 생성일은 오늘 날짜, 소스 파일 수는 `<모듈경로>` 내 `*.h`/`*.cpp` 개수(서브에이전트가 직접 세도 됨)
- 아래 **README 템플릿**과 **작성 규칙**

서브에이전트가 할 일:

1. `<모듈경로>` 아래 `*.Build.cs`, `*.uplugin`, `Public/`·`Private/` 헤더와 핵심 cpp를 읽어 모듈을 파악한다. 모든 파일을 통독하지 말고 헤더 위주로 구조를 잡는다.
2. 아래 템플릿에 맞춰 README를 **직접 `Write`** 한다(끝의 provenance 라인은 받은 값 그대로).
3. 마지막 메시지에 본문은 반환하지 말고(오케스트레이터 컨텍스트 절약) 한 줄만 반환한다: `DONE <모듈> · 규칙 <준수 | 위반:WxFoo,WxBar>`. 오케스트레이터가 마무리 보고에서 규칙 위반을 모으는 데 쓴다.

서브에이전트 프롬프트에 넣을 **README 템플릿**:

```
# <Module> — <한글 시스템명>

> <1~2문장: 이 모듈이 게임에서 무엇을 책임지는지>

## 책임
- <담당하는 것>
- <담당하지 않는 것 / 경계>

## 의존성
- **주요 의존**: <의존하는 Wx 모듈은 모두 나열 + 특징적인 엔진 서브시스템만(GameplayAbilities/CommonUI/Niagara/AIModule 등). 빌드 기본(Core/CoreUObject/Engine/Slate 등)은 생략>
- 규칙: WxCore 외 Wx 플러그인 참조 <없음 ✅ / 있음 ⚠️ + 목록>

## 핵심 타입 (진입점)
| 타입 | 역할 | 위치 |
| --- | --- | --- |
| `UWxXxx` | <한 줄> | `<저장소 루트 기준 상대경로>` |
<핵심만 5~12개(작은 모듈은 더 적게). 경로는 클릭 가능하도록 루트 기준 상대경로로.>

## Gameplay Tags
<이 모듈이 C++ Native Tag를 선언할 때만 둔다(선언이 없으면 절 전체 생략). 선언 파일과 주요 태그 네임스페이스의 의미를 가리킨다.>
- 선언: `<WxXxxGameplayTags.h 등 경로>`
- 주요 네임스페이스: `<예: State.*, Event.*, Input.* — 각 묶음이 무엇을 뜻하는지>`

## 내부 구조
<Public/ 하위 폴더별 1줄 요약. 폴더가 평평하거나 파일이 적은 작은 모듈이면 절 전체 생략.>
- `<폴더>` — <무엇이 있는지>

## 확장 포인트 / 규약
- <새 X(어빌리티/이펙트/아이템/위젯 등)를 추가하는 법, 구현해야 할 베이스 클래스/인터페이스>
- <데이터 주도 설정이 있으면: 어떤 DataTable Row·애셋·AbilitySet이 이 모듈을 구동하는지>
- <리플리케이션/권한 모델이 중요한 모듈이면 한 줄(최대 4인 멀티)>

## 여기서부터 읽어라
1. `<경로>` — <왜>
2. `<경로>` — <왜>

## 관련
- 상위: <이 모듈을 사용하는 곳 / 함께 보는 모듈, [[다른모듈]] 형식 링크 가능>

---
*문서 기준 커밋 `<SHA>` · 생성일 <DATE> · 소스 <N>파일 — `/readme-writer`로 갱신*
```

**작성 규칙** (서브에이전트에 함께 전달):

- 대상 독자는 **개발자/미래 세션**이다. 코드를 처음 잡을 때 "어디를 읽어야 하는지" 알려주는 **지도**이지, 모든 클래스를 나열하는 레퍼런스가 아니다. 간결하게.
- 코드에서 **검증된 사실만** 쓴다. 추측은 적지 않는다. 파일 경로/타입명은 실제와 정확히 일치해야 한다.
- 끝의 provenance 라인은 받은 값 그대로(숨기지 말 것). 본문은 한국어. 타입명·경로·태그명 등 식별자는 원문(영문) 유지.
- 모든 파일 경로는 저장소 루트(`C:\Wx`) 기준 상대경로로 적어 클릭 가능하게 한다.
- BP/WBP가 본체인 모듈(특히 WxUI)은 핵심 BP/WBP·MVVM ViewModel과 스냅샷 경로(`Plugins/WxBlueprintSnapshot/Snapshots/...`)를 가리켜, C++만으로는 안 보이는 부분을 보완한다.
- 프로젝트 `CLAUDE.md`의 코딩/모듈 규칙(특히 "WxCore 외 상호참조 금지")을 의존성 절에서 실제로 검증해 표기한다.
