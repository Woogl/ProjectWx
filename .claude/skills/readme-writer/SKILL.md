# 모듈 README 생성·갱신

프로젝트의 각 **플러그인/모듈**을 분석해 개발자·미래 세션이 빠르게 코드를 잡을 수 있는 **오리엔테이션 맵**을 그 모듈 폴더의 `README.md`로 만든다. 플러그인은 `Plugins/<Name>/README.md`, 소스 모듈은 `Source/<Name>/README.md`. 코드 옆에 두어 지역성·이식성을 살린다.

핵심 원칙은 세 가지다.

1. **컨텍스트 폭발 방지** — 오케스트레이터(이 스킬을 실행하는 너)는 소스를 직접 통독하지 않는다. 모듈마다 **서브에이전트 1개**를 띄워 각자 자기 모듈만 읽고 README를 직접 쓰게 한다. 여러 모듈은 한 메시지에서 병렬로 띄운다.
2. **점진적 갱신** — 각 README 끝에 보이는 provenance 라인으로 생성 시점 커밋 SHA를 노출한다. 재실행 시 그 SHA 이후 변경된 모듈만 골라 재생성한다.
3. **외부 문서 보존** — provenance 라인이 없는 기존 README는 이 스킬의 산출물이 아니다(수기 문서·다른 도구 결과). **foreign**으로 보고 자동으로 덮어쓰지 않는다.

## 1. 대상 결정 (인자 처리)

`Glob("Plugins/*/*.uplugin")`로 플러그인을, `Glob("Source/*/*.Build.cs")`로 소스 모듈(`WxGame` 등)을 동적으로 발견한다. 새 모듈·플러그인이 추가돼도 이 스킬을 고칠 필요가 없어야 한다. **런타임 모듈만 대상으로 한다** — descriptor의 모듈 `Type`이 `Runtime`이 아니면(예: `WxEditor`·`WxBlueprintSnapshot`의 `Editor`) 대상에서 제외한다(인자로 명시해도 생성하지 않는다). `Type`은 플러그인이면 `.uplugin`, 소스 모듈이면 루트 `.uproject`의 `Modules[]`에 있다.

모듈 → 경로 / 본문 위치 매핑:

| 종류 | 분석 경로(소스) | 본문 README |
| --- | --- | --- |
| 플러그인 `<Name>` | `Plugins/<Name>` | `Plugins/<Name>/README.md` |
| 소스 모듈 `<Name>` | `Source/<Name>` | `Source/<Name>/README.md` |

인자에 따라 대상 집합을 정한다.

- **인자 없음** (기본): `git rev-parse --short HEAD`로 현재 SHA를 구한 뒤, 각 모듈의 README 상태를 판정해 **missing 또는 stale인 모듈만** 대상으로 삼는다. fresh·**foreign**은 건너뛴다(foreign은 마무리 보고에 "외부 문서로 보존"으로 명시). 대상이 0개면 "모두 최신"이라고 보고한다.
- **모듈명 1개 이상** (예: `WxCombat`, `WxCombat WxInventory`): 그 모듈만 재생성한다(stale 여부와 무관하게 다시 씀). 단 대상 README가 **foreign**(provenance 없는 외부 문서)이면 자동으로 덮어쓰지 말고, 그 사실을 경고한 뒤 덮어쓸지 사용자 확인을 받는다. 발견된 모듈 목록에 없는 이름이면 생성하지 말고, 유효한 모듈 목록을 한국어로 안내한다. 비런타임(에디터 전용) 모듈명이면 "에디터 전용이라 대상에서 제외" 한 줄로 안내하고 생성하지 않는다.
- **`all`**: 발견된 모든 모듈을 (stale 여부와 무관하게) 재생성하되, **foreign 문서는 건너뛰고** 보고한다(일괄 실행이 외부 문서를 파괴하지 않도록).

### 상태 판정 (missing / foreign / stale / fresh)

각 README **끝**에는 다음 형식의 provenance 라인이 있다. 숨기지 않고 렌더링에 그대로 노출한다(독자가 문서가 어느 시점 기준인지 바로 알 수 있게):

```
*문서 기준 커밋 `<short-sha>` · 생성일 <YYYY-MM-DD> · 소스 <N>파일 — `/readme-writer`로 갱신*
```

판정 절차(모듈 경로 = 위 표의 "분석 경로"):

1. README 파일이 없으면 → **missing**.
2. `Grep`으로 `문서 기준 커밋` 라인을 찾는다.
   - 라인이 **없으면** → **foreign**. provenance가 없다는 것은 이 스킬의 산출물이 아니라는 뜻이다(수기 문서·다른 도구 결과). **stale로 보지 말고 보존한다**(자동 덮어쓰기 금지).
   - 라인이 있으면 `문서 기준 커밋` 바로 뒤 **첫 백틱 스팬**(`[0-9a-f]{7,40}` 패턴)을 `<sha>`로 읽는다. 같은 줄 끝의 `` `/readme-writer` `` 를 집지 않도록 첫 SHA 스팬만 취한다.
3. (provenance가 있을 때만) 아래 두 명령으로 **소스 변경**을 확인한다. 둘 다 README.md를 제외한다:
   - `git diff --name-only <sha> HEAD -- <모듈경로> ":(exclude)<모듈경로>/README.md"`
   - `git status --porcelain -- <모듈경로> ":(exclude)<모듈경로>/README.md"`
   둘 중 하나라도 변경이 있으면 → **stale**, 둘 다 비어 있으면 → **fresh**.
   - 단, `git diff`가 기록된 SHA를 못 찾아 실패하면(`fatal: bad object` 등 — 히스토리 재작성·squash·shallow clone) 변경 여부를 판정할 수 없으므로 **stale로 간주**해 재생성한다(에러로 중단하지 않는다).

> README.md는 모듈 폴더 *안*에 있으므로 `-- <모듈경로>` 한정만으로는 제외되지 않는다 — diff·status 모두 README 자신의 커밋/수정(생성 직후엔 untracked, 커밋 후엔 provenance SHA 이후의 변경)을 잡아 모든 모듈이 영구히 stale이 된다. 위 `:(exclude)` pathspec으로 README를 명시적으로 빼야 "변경된 모듈만 재생성"이 실제로 작동한다.

> 점진 갱신은 모듈 *소스 디렉터리* 변경만 본다. (1) `WxCore` 공용 정의(태그/Enum) 변경은 이를 인용하는 소비 모듈 경로 diff에 안 잡히고, (2) BP/WBP가 본체인 모듈(WxUI)의 에셋·스냅샷은 게임 루트 `Content/`·`Snapshots/`에 있어 모듈 경로 밖이다. 이런 파급이 의심되면 해당 모듈을 인자로 지정해 강제 재생성한다.

## 2. 모듈별 서브에이전트 (병렬)

대상 모듈마다 **서브에이전트 1개**를 띄운다(`Agent`, 여러 모듈이면 한 메시지에 여러 호출로 병렬). 각 서브에이전트에 아래를 전달한다.

- 모듈명, 분석 경로, 본문 README 경로
- provenance 라인에 박을 **커밋 SHA**(현재 `git rev-parse --short HEAD` 값)와 **생성일**(오늘 날짜). 이 둘은 오케스트레이터가 확정해 넘긴다 — 서브에이전트는 git·날짜를 다시 조회하지 말고 받은 값을 그대로 쓴다. **소스 파일 수 `<N>`** 은 서브에이전트가 직접 센다(아래 작성 규칙의 카운트 기준).
- 아래 **README 템플릿**과 **작성 규칙**

서브에이전트가 할 일:

1. `<모듈경로>` 아래 `*.Build.cs`, `*.uplugin`, `Public/`·`Private/` 헤더와 핵심 cpp를 읽어 모듈을 파악한다. 모든 파일을 통독하지 말고 헤더 위주로 구조를 잡는다.
2. 아래 템플릿에 맞춰 README를 **직접 `Write`** 한다. 끝의 provenance 라인은 받은 SHA·생성일을 그대로 박고 `<N>` 자리만 1에서 센 소스 파일 수로 채운다(라인 형식·문구는 변경 금지).
3. 마지막 메시지에 본문은 반환하지 말고(오케스트레이터 컨텍스트 절약) 한 줄만 반환한다: `DONE <모듈> · 규칙 <준수 | 위반:WxFoo,WxBar | 해당없음>`. 여기서 "규칙 위반"은 의존성 절에서 검증한 **「WxCore 외 다른 Wx 플러그인 참조 금지」 위반만**을 뜻하며, 위반 시 부적절하게 참조한 플러그인명을 콤마로 나열한다. **이 규칙은 플러그인에만 적용된다** — 게임/소스 모듈(WxGame 등)은 플러그인 조립이 정상 역할이므로 `해당없음`으로 보고한다. 오케스트레이터가 마무리 보고에서 이를 모은다.

서브에이전트 프롬프트에 넣을 **README 템플릿**:

```
# <Module> — <한글 시스템명>

> <1~2문장: 이 모듈이 게임에서 무엇을 책임지는지>

## 책임
**담당**
- <담당하는 것>
- <담당하는 것>

**경계 (비담당)**
- <안 하는 것 / 다른 모듈에 위임하는 것 — 어디서 하는지 [[모듈]]로 가리킴. 비담당이 없으면 이 묶음 생략>

- 규칙: <**플러그인일 때만** 「WxCore 외 Wx 플러그인 참조」를 검증 — 없음 ✅ / 있음 ⚠️ + 목록. 게임/소스 모듈(WxGame 등)은 이 규칙이 적용되지 않으므로 "기본 게임 모듈로 여러 플러그인을 조립하는 정상 역할(규칙 무관)"처럼 표기한다.>
```

**작성 규칙** (서브에이전트에 함께 전달):

- 대상 독자는 **개발자/미래 세션**이다. 코드를 처음 잡을 때 "어디를 읽어야 하는지" 알려주는 **지도**이지, 모든 클래스를 나열하는 레퍼런스가 아니다. 간결하게.
- 이 코드베이스는 헤더 doc-comment가 두껍다. **헤더 주석 한 줄을 그대로 옮겨 적지 말 것** — 헤더만 열어도 보이는 설명은 중복이고, 코드 변경 시 두 번째로 틀리는 출처가 된다. README는 *단일 파일이 못 주는* 것에 집중한다: 진입점 트리아지(무엇을 먼저 읽나), 모듈 경계/위임, 파일을 횡단하는 데이터·제어 흐름, 의존성 규칙 검증. 한 타입의 역할을 적을 때도 헤더 요약의 복사가 아니라 *모듈 안에서의 위치/관계*를 한 줄로 준다.
- 코드에서 **검증된 사실만** 쓴다. 추측은 적지 않는다. 파일 경로/타입명은 실제와 정확히 일치해야 한다.
- **책임** 절은 `담당`/`경계 (비담당)` 두 묶음을 굵은 소제목으로 나눈다. `경계`에는 이 모듈이 하지 않고 다른 모듈에 위임하는 것을 적고 위임처를 `[[모듈]]`로 가리킨다. 비담당이 없으면 `경계` 묶음은 통째로 생략한다.
- 끝의 provenance 라인은 숨기지 말 것. SHA·생성일은 받은 값 그대로 쓰고(재계산 금지) `<N>` 자리만 채운다. 본문은 한국어. 타입명·경로·태그명 등 식별자는 원문(영문) 유지.
- provenance의 `<N>`(소스 파일 수)은 `<모듈경로>` 아래의 `*.h`/`*.cpp` 개수만 센다(레이아웃 비의존 — 플러그인은 `Plugins/<Name>/Source/...`, 소스 모듈은 `Source/<Name>/...`에 파일이 있다) — `Intermediate/`·`*.gen.cpp`·`*.generated.h`(빌드 산출물)는 제외한다.
- 모든 파일 경로는 저장소 루트(`C:\Wx`) 기준 상대경로로 적어 클릭 가능하게 한다.
- BP/WBP 내부 구조(위젯 계층·MVVM 바인딩 그래프·스냅샷)는 README 범위 밖이다. 프로젝트 `CLAUDE.md`의 `Blueprint 분석` 절이 스냅샷 위치·용법을 이미 안내하므로, 중복을 피해 README에는 특정 WBP 파일이나 `Plugins/WxBlueprintSnapshot/Snapshots/...` JSON 경로를 나열하지 않는다. BP/WBP가 본체인 모듈(특히 WxUI)도 README는 C++ 타입·모듈 구조에 집중한다.
- 프로젝트 `CLAUDE.md`의 코딩/모듈 규칙(특히 "WxCore 외 상호참조 금지")을 의존성 절에서 실제로 검증해 표기한다.

## 3. 마무리 보고

한국어로 짧게 보고한다.

- **생성**(missing→신규) / **갱신**(stale→재생성) / **건너뜀(fresh)** 모듈을 각각 나열.
- **보존(foreign)** — provenance가 없어 건드리지 않은 외부 README가 있으면 모듈명과 함께 명시(예: `<Module> — 외부 문서로 보존, 덮어쓰려면 모듈명을 직접 지정`). foreign 판정은 *런타임* 모듈에만 의미가 있다(비런타임 모듈은 그 전에 대상에서 제외된다).
- 서브에이전트가 보고한 **「WxCore 외 참조」 위반**이 있으면 모듈·참조 플러그인을 경고로 표기. `WxCore`가 갱신 대상이었으면 "WxCore 변경 — 소비 모듈 README 수동 점검 권장"을 덧붙인다.
- 대상 0개면 "모두 최신", 유효하지 않은 모듈명 입력이 있으면 유효 목록 안내, 서브에이전트가 `DONE`을 반환하지 않은 모듈이 있으면 실패로 표기.
