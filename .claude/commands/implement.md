# 설계 문서 구현

설계 문서(`Docs/Plan_*.md`)를 기반으로 코드를 구현하라.

사용자 입력: $ARGUMENTS

## 절차

### 1단계: 설계 문서 확인

`Docs/Plan_*.md` 파일 목록을 조회한다. `$ARGUMENTS`가 제공된 경우 파일명 또는 문서 제목과 가장 유사한 설계 문서를 선택한다. 제공되지 않거나 매칭되는 문서가 없는 경우 목록을 보여주고 사용자에게 선택을 요청한다.

설계 문서를 읽고 작업 체크리스트를 파악한다. 설계 내용에 의문점이 있으면 구현 전에 질문한다.

### 2단계: 코드베이스 확인

설계 문서에서 참조하는 기존 파일들을 읽어 현재 상태를 확인한다:
- 설계 문서 작성 이후 변경된 부분이 있는지 점검한다
- 수정 대상 파일의 최신 코드를 파악한다
- 신규 파일을 작성해야 하는 경우, 동일 모듈의 유사한 기존 파일을 읽어 구조와 패턴을 파악한다
- 충돌 가능성이 있으면 사용자에게 알린다

### 3단계: 구현

설계 문서의 **코드 작업 체크리스트** 순서대로 구현한다.

#### 구현 규칙

- **설계 문서 준수**: 설계 문서에 명시된 클래스 구조, 프로퍼티, 로직을 그대로 구현한다. 임의로 변경하지 않는다.
- **CLAUDE.md 코딩 규칙 준수**: 프로젝트의 코딩 컨벤션을 반드시 따른다.
- **작업 단위 실행**: 체크리스트 항목을 하나씩 완료하며, 각 항목 완료 시 사용자에게 진행 상황을 보고한다.
- **기존 코드 패턴 유지**: 신규 파일 작성 시, 동일 모듈의 기존 파일 구조와 패턴을 따른다.
- **판단이 필요한 경우 질문**: 설계 문서에 명시되지 않은 세부 구현 사항은 기존 코드 패턴을 따르되, 판단이 어려우면 사용자에게 질문한다.

### 4단계: 빌드 검증

모든 코드 작업 완료 후 빌드를 실행하여 성공 여부를 확인한다.

빌드 실패 시:
1. 에러 메시지를 분석한다
2. 설계 문서의 의도를 벗어나지 않는 범위에서 수정한다
3. 수정 내용을 사용자에게 보고한다
4. 재빌드하여 성공을 확인한다

### 5단계: 결과 보고

구현 결과를 보고한다:
- 생성/수정한 파일 목록
- 설계 대비 변경 사항 (있는 경우)
- 에디터 작업 체크리스트 안내 (에디터 작업이 있는 경우)
