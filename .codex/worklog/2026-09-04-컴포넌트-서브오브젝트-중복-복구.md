# 컴포넌트 서브오브젝트 중복 복구

## 계획

- `ClassRedirects.ValueChanges`를 소유자 `AWxCharacterBase`가 아니라 실제 직렬화 대상인 Projectile·Minion 매니저 컴포넌트 클래스에 연결한다.
- 아직 옛 컴포넌트 클래스를 기록한 에셋과 이미 새 컴포넌트 클래스로 저장된 에셋을 모두 읽도록 옛 클래스→새 클래스와 새 클래스→동일 클래스 경로를 함께 둔다.
- `ProjectileComponent`와 `MinionComponent` 인스턴스 이름을 각각 새 네이티브 서브오브젝트 이름으로 합쳐 설정값과 참조를 보존한다.
- 네이티브 서브오브젝트 이름과 기존 클래스·프로퍼티 리디렉트, 임시 호환 타입은 유지한다.
- 설정 문법과 중복 매핑을 검사하고 UE 5.8 `WxEditor` Win64 Development 빌드로 검증한다.
- 이번 단계는 복구 리디렉트 적용에서 멈추며, 에셋 재리세이브 확인 전에는 제거 단계로 넘어가지 않는다.

## 완료

- 소유자 `AWxCharacterBase`에 잘못 연결돼 있던 Projectile·Minion `ValueChanges`를 제거했다.
- 옛 컴포넌트 클래스→새 클래스 리디렉트에 인스턴스 이름 변경을 결합해 아직 이관되지 않은 에셋을 지원했다.
- 새 컴포넌트 클래스→동일 클래스 리디렉트를 추가해 이미 새 클래스와 옛 인스턴스 이름 조합으로 저장된 에셋도 같은 새 이름으로 수렴시켰다.
- 네이티브 서브오브젝트 이름, 프로퍼티 리디렉트와 임시 호환 타입은 유지했다.
- `git diff --check`를 통과했다. 줄 끝 변환 예정 경고만 있었고 공백 오류는 없었다.
- UE 5.8 `WxEditor Win64 Development` 빌드에 성공했다. 설정 변경만 있어 타깃은 최신 상태였다. 로그: `Saved/Logs/BuildDoctor/build_2026-09-04_235520_288_14612.log`
- 에셋 재리세이브 전 복구 단계에서 멈췄다. 중복 해소 확인 후 제거 단계를 별도로 진행한다.
