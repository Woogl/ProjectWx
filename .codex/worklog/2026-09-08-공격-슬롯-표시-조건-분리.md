# 공격 슬롯 표시 조건 분리

## 계획

- 사용자 승인대로 표시 조건과 발동 가능 여부를 분리한다. 공격 Visibility의 CanActivate 바인딩을 제거하고, 기존 OwnedTags의 Movement.InAir 변환으로 지상/공중 표시를 결정한다.
- 공격 실행·비용 부족·쿨다운으로 CanActivate가 false가 되어도 현재 상황의 아이콘과 슬롯을 유지한다. 재발동 검사는 기존 TryActivateAbility에 맡긴다.
- 겹친 배치와 CommonUI 기본 Heavy Hold 0.35초를 유지한다. 지상의 앞쪽 버튼은 사용자 선택을 반영하며, 별도 입력 주입이나 WxUIData 확장은 하지 않는다.
- 에셋 수정 전 현재 바인딩을 확인하고, 수정 후 저장된 에셋의 바인딩·슬롯 계층·클릭 경로를 재로딩 검증한다. CanActivate가 false여도 공중 표시가 유지되는 회귀 검증과 WxEditor Development 빌드를 수행한다.

## 완료

- WBP_PlayerSkills의 Attack_Light·Attack_Heavy·Attack_Air Visibility에서 CanActivate 의존을 제거했다. VM_PlayerCharacter.AbilitySystem.OwnedTags의 Movement.InAir만 기존 Conv_GameplayTagToSlateVisibility로 변환한다.
- 공중에서는 Air만 표시하고, 지상에서는 기존 Light/Heavy 겹침 순서를 유지한다. 별도 우선순위 선택이 없어 기존 Light 우선으로 마무리했다. 표시되는 버튼은 SelfHitTestInvisible, 다른 상황의 버튼만 Collapsed이다. 초기 지상 위젯도 표시되도록 설정했다.
- 공격 실행 중·비용 부족·쿨다운으로 CanActivate가 false가 되어도 현재 상황의 아이콘과 슬롯은 유지한다. 클릭 시 기존 TryActivateAbility의 GAS 검사가 재발동을 제한한다. IsEnabled 바인딩을 추가하지 않았다.
- Heavy의 CommonUI 기본 HoldData 0.35초 및 기존 OnButtonBaseClicked → TryActivateAbility MVVM 이벤트와 부모 히트 테스트 설정을 유지했다. WxButtonBase·WxUIData 및 런타임 변환 함수의 코드는 변경하지 않았다.
- 에셋 재로딩 검증 성공: Saved/Logs/verify_attack_slot_context.log의 WXSLOT VERIFY SUCCESS. 실제 소스 VM GUID·OwnedTags·변환 핀·클릭 이벤트·Heavy Hold 및 세 HUD Blueprint 컴파일을 확인했다.
- Source/WxEditor/Tests/WxAttackSlotVisibilityTests.cpp에 실제 WBP_PlayerSkills의 컴파일된 변환 함수를 실행하는 회귀 테스트를 추가했다. 지상→공중→지상, CanActivate=true/false 조합에서 각 위젯의 정확한 Visibility와 슬롯이 전부 접히지 않음을 검증한다. 필요한 MVVM/UMG 에디터 의존성은 이 읽기 전용 테스트용이며 에셋 수정 도구는 제거했다.
- 최종 UE 5.8 WxEditor Development 빌드 성공: Saved/Logs/BuildDoctor/build_2026-09-08_005127_515_22872.log.
- Wx.MVVM.Ability.SeparateWidgets 및 Wx.MVVM.Ability.SlotVisibility 모두 성공: Saved/Logs/test_attack_slot_final.log.
- 실제 PIE 마우스 조작은 수행하지 않았다. 검증 범위는 저장 에셋 재로딩·컴파일과 실제 컴파일된 HUD Visibility 바인딩 실행이다.
