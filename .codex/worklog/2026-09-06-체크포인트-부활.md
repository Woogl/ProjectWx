# 체크포인트 부활

## 계획

- 체크포인트 최초 활성화와 휴식 시 기존 RespawnPoint의 위치·방향을 마지막 부활 지점으로 기록한다.
- 추가 지시: 기록은 전용 StateTree 태스크가 담당하며 ST_CheckPoint의 활성화·휴식 상태에 배치한다. Device에는 체크포인트 전용 분기를 추가하지 않는다.
- GameInstanceSubsystem으로 맵 재로딩 동안 기록을 유지하고 GameMode의 플레이어 재시작에 적용한다. 디스크 SaveGame은 도입하지 않는다.
- 기록이 없거나 다른 맵이면 기존 시작 위치를 사용하며 새 게임에서 기록을 초기화한다.
- UE 5.8 WxEditor Development 빌드와 체크포인트 갱신·반복 부활을 검증한다.

## 완료

- `FWxStateTreeTask_RecordCheckpoint`를 추가했다. 기존 `FWxStateTreeComponentName` 드롭다운으로 RespawnPoint를 지정하고, 서버의 플레이어 상호작용으로 발생한 라이브 진입에서만 기록한다. 초기 진입·복원은 기록하지 않는다.
- `ST_CheckPoint`의 Lit 상태에 기록 태스크를 배치했다. Lit의 휴식 전이를 OnDelegate로 연결하여 최초 활성화와 반복 휴식 모두 기록되도록 했다. 기존 회복·스포너 리스폰·아이템 충전·Niagara 태스크의 ID와 설정 및 바인딩을 보존했다. StateTree 컴파일·저장을 확인했다.
- `UWxCheckpointSubsystem`이 맵 패키지명과 부활 Transform을 GameInstance 수명 동안 보관한다. `AWxGameMode::RestartPlayer`가 같은 맵의 기록을 사용하고, 새 게임 이동 직전에 초기화한다. 기록이 없거나 다른 맵이면 기존 시작 경로를 사용한다.
- Device의 체크포인트 전용 분기는 최종 변경에 포함하지 않았다. WxWorld는 다른 도메인 플러그인에 새 의존성을 추가하지 않는다.
- UE 5.8 WxEditor Win64 Development 빌드 성공. 로그: `C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-06_023450_333_30116.log`.
- `Wx.Checkpoint.DeviceAndPlayerRestart`, `Wx.Checkpoint.MapRestartAndNewGame` 자동화 테스트 모두 성공, 종료 코드 0. 실제 BP/ST 로딩·최초 활성화·반복 휴식·초기 진입 무기록·두 지점 갱신·GameMode 반복 생성 및 빙의·위치와 방향 복원·동일 맵의 새 World에서 기록 유지·다른 맵 제외·새 게임 초기화를 검증했다. 로그: `C:/Wx/Saved/Logs/CheckpointFinal.log`.
