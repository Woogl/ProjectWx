# 네임플레이트 바인딩 점검 제한

## 계획

- 승인한 설계에 따라 거리·플레이어 유무·최대 거리 설정을 먼저 판단하고 표시 범위 안에서만 기존 틱으로 0.25초 간격의 바인딩 점검과 재시도를 수행한다.
- 최초 진입·재진입·위젯 교체·재초기화 시 즉시 점검하며 정상 연결 확인과 실제 주입을 분리한다. 소스 탐색 결과는 해당 MVVM 구성에 대해 캐시하고 설정 오류는 반복 탐색하지 않는다.
- 태그 가시성은 바인딩 게이트로 사용하지 않고 거리 밖에서도 공유 VM을 유지한다. Construct 완료를 기다리지 않으며 위젯/MVVM 교체 및 소스 변경은 복구한다.
- 상태·대기/오류 원인·소스 이름·주입 시도 횟수·다음 점검 시간을 읽기 전용 디버깅 정보로 노출하고 상태 변경만 로그로 기록한다.
- 거리 재진입, ASC 지연 준비, 같은 위젯 재구성, 위젯 교체, 잘못된 소스 설정을 회귀 검증하고 런처에서 확인한 UE 5.8로 WxEditor Development를 빌드한다. 기존 공유 팩토리 및 다른 작업의 변경을 보존한다.

## 완료

- UWxNameplateComponent에서 거리·플레이어 유무·최대 거리 게이트를 바인딩보다 먼저 검사한다. 거리 밖에서는 점검 시간을 0으로 대기하고 재진입 시 첫 표시 갱신에서 즉시 확인한다. 최대 거리 0이면 플레이어 조회도 생략한다.
- CheckBinding은 0.25초 간격으로 View/구성과 기존 수동 소스의 유효성만 확인한다. 정상 연결에서는 ASC 조회·소스 전체 순회·VM 획득·주입을 생략한다. 소스 탐색 성공/실패는 View/구성별로 캐시하며 설정 오류 및 주입 실패는 구성 교체나 명시적 InitWidget까지 반복 주입하지 않는다.
- 위젯 교체·InitWidget은 다음 표시 갱신에 지연 없이 점검한다. 일반 Slate 재구성과 거리 이탈은 공유 VM을 유지한다. WBP Hidden/Collapsed는 바인딩 게이트로 쓰지 않는다.
- Wx|Binding Debug에 BindingState(대기/실패 원인 포함), bWithinPresentationRange, CachedSourceName, BoundSourceName, BindingAttemptCount, TimeUntilBindingCheck를 인스턴스 읽기 전용으로 노출했다. 상태 변경만 Verbose로 기록하고 InvalidSource/InjectionFailed는 상태 진입 시 Warning을 남긴다.
- UE 5.8.2 WxEditor Win64 Development 빌드 성공(종료 코드 0). 최종 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-13_193003_742_22848.log. 최초 제한 환경 빌드는 UBT 로그 접근 문제로 종료되어 build-doctor를 통한 승인된 실행으로 검증했다.
- Wx.UI.Nameplate.BindingLifecycle 자동화 테스트 성공 1, 실패 0, 예상 외 경고/오류 0. 실제 WBP로 표시 비활성화·거리 밖·플레이어 부재 시 탐색 생략, ASC 지연 준비와 주입 간격, 정상 120프레임 재주입 없음, Collapsed 상태 소스 복구, 거리 재진입 즉시 복구, Slate 재구성 시 수동 소스 보존, 잘못된 소스 경고 1회, 위젯 교체·명시적 초기화·재등록·해제 후 공유 VM 유지를 검증했다. 결과: C:/Wx/Saved/Automation/NameplateBindingLifecycle/index.json.
- 첫 테스트 실행은 테스트 월드 중복 초기화로 종료되어 테스트 구성만 수정한 뒤 다시 빌드·실행했다. 최종 테스트 프로세스 종료 코드 0. NullRHI 자동화 검증이며 실제 화면 시각 확인과 다수 적의 성능 측정은 수행하지 않았다.
- 기존 공유 Character VM 팩토리 호출과 다른 작업의 변경을 보존했다.
