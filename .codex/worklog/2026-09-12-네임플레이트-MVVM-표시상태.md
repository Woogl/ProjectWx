# 네임플레이트 표시 상태의 MVVM 전환

## 계획

- 사용자 승인에 따라 거리·표시 상태 갱신은 네임플레이트 VM, Scale 계산은 기존 MVVM Conversion Library, Scale·가시성 적용은 WBP 바인딩으로 이동한다.
- 공유 Character VM은 유지하고, 위젯별 표시 상태 VM을 추가해 서로 다른 컴포넌트 설정이 섞이지 않게 한다.
- NameplateComponent의 사용자 TickComponent와 직접 표시·Scale 갱신을 제거한다. 기존 설정값과 이름·초상화 전달은 유지한다.
- Resolver에서 표시 VM을 생성·해제하여 위젯 수명과 갱신 수명을 연결한다. 공용 인터페이스나 WxGame 의존성을 추가하지 않는다.
- 실제 Enemy WBP에 Scale 변환과 가시성 바인딩을 추가하고 기존 수치 바인딩을 유지한다.
- 거리·태그·플레이어 부재·재생성·해제와 실제 WBP 반영, 기존 회귀 테스트를 검증하고 UE 5.8 WxEditor Development 빌드를 수행한다.

## 완료

- UWxViewModel_Nameplate를 WxUI에 추가해 거리·표시 상태를 FieldNotify로 제공한다. 공유 Character VM과 분리하여 컴포넌트별 원근·표시 설정을 유지한다.
- 기존 WxMVVMConversionLibrary에 FWxNameplateScaleInput 및 Conv_NameplateDistanceToScale을 추가했다. 기존 ReferenceDistance / Max(Distance, 1)와 MinScale/MaxScale 제한을 사용한다.
- NameplateComponent의 사용자 TickComponent, 직접 SetVisibility/SetRenderScale, LastRenderScale을 제거했다. 위젯 부착을 위한 엔진 기본 틱, 표시 설정값 및 이름·초상화 전달만 유지한다.
- 기존 Resolver가 위젯별 표시 VM도 생성하고 DestroyInstance에서 갱신 티커를 즉시 해제한다. Collapsed 상태에서도 재표시 조건을 갱신하고 플레이어 부재·거리·태그에 따라 WBP 가시성을 제공한다.
- WBP_Nameplate_Enemy에 VM_Nameplate 소스와 Scale Conversion/가시성 바인딩 2개를 추가했다. 기존 Character 소스·수치 바인딩은 보존했다. 새 바인딩은 Immediate로 갱신한다.
- 공식 C++ MVVM 편집 API로 에셋을 컴파일·저장했다. 임시 편집기 코드와 임시 모듈 의존성은 제거했다. 재현용 편집 코드만 Saved/WxMigrateNameplatePresentation.cpp에 남겼다.
- UE 5.8.2 WxEditor Win64 Development 빌드 성공(종료 코드 0). 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-12_153236_907_28256.log
- 회귀 테스트: Wx.UI.Nameplate.Resolver 및 Wx.UI.AbilitySystem.LazyEffectViewModels 성공 2, 실패 0, 경고 0, 오류 0. 결과: C:/Wx/Saved/Automation/NameplatePresentation/index.json
- 실제 저장된 WBP에서 1500 거리의 Scale 2/3, 근거리 최대값, 먼 거리 최소값, 범위 밖 숨김·범위 안 재등장, 요구 태그 부재, 거리 제한 0, 플레이어 소실, 소스 해제 후 거리 갱신 중단과 Character 공유 유지 등을 확인했다.
