# 보스 HUD 구독 수명 분리

## 계획

- 신규 서브시스템 없이 보스 표시 영역용 뷰모델이 위젯별 교전 이벤트 구독을 소유하게 한다. 리졸버는 생성·연결·해제만 담당한다.
- 보스 액터와 ASC는 게임 상태를 유지하고, 표시 영역 뷰모델은 교전 중인 보스를 약한 참조로 관찰하여 기존 UWxViewModel_Character를 표시 대상으로 제공한다.
- 먼저 관찰한 교전 보스를 유지하고 사망·이탈·소멸하면 남은 보스로 전환한다. 늦은 위젯 생성과 다른 월드의 이벤트를 처리한다.
- 기존 단일 보스 HUD의 이름·초상화·체력 표시를 보존하고 필요한 MVVM 바인딩을 함께 이관한다. 여러 체력바의 동시 표시 UI는 이번 범위에 포함하지 않는다.
- 위젯 둘 중 하나 해제, 보스 두 명의 독립적인 교전 종료, 늦은 생성, 월드 분리를 회귀 테스트로 검증한다.
- UE 5.8 설치 경로를 런처 정보에서 조회하여 WxEditor Win64 Development 빌드를 수행하고, 관련 위젯 컴파일 및 테스트 결과를 기록한다.

## 완료

- `UWxViewModel_BossDisplay`를 추가했다. 위젯별로 교전 델리게이트 핸들을 소유하고, 관찰 월드와 교전 보스들을 약한 참조로 보관한다. 해제 시 자기 핸들만 제거하며 GC 경로도 같은 정리를 수행한다.
- 표시 영역은 기존 `UWxViewModel_Character`를 안정적인 자식으로 제공한다. ASC 기반 자식 데이터는 기존 공유 방식을 유지한다. 처음 관찰한 교전 보스를 표시하고, 새 보스 합류·중복 통지로 표시가 바뀌지 않으며 현재 보스 이탈 시 다음 후보로 전환한다. 늦은 위젯 생성은 월드의 모든 교전 보스를 수집한다.
- `UWxViewModelResolver_BossCharacter`에서 전역 이벤트 구독과 GameState 공유 뷰모델 연결을 제거했다. 위젯마다 표시 영역 모델을 생성하고 해당 인스턴스만 해제한다. 새 서브시스템이나 WxUI의 게임 모듈 의존성은 추가하지 않았다.
- `WBP_Nameplate_Boss`의 뷰모델 타입을 이관하고 기존 이름·효과 목록·표시 여부·HP·GP의 5개 바인딩 경로에 `Character`를 연결했다. 네이티브 MVVM `SetGraphPin`으로 변환 그래프도 함께 갱신했다. 임시 이관 도구와 편집기 모듈 의존성은 제거하여 최종 `Source/WxEditor`의 내용 변경은 없다.
- 새 프로세스에서 보스 위젯의 5개 경로를 다시 확인했고, 보스 위젯과 `WBP_GameHUD` 컴파일을 통과했다. 로그: `Saved/Logs/VerifyBossDisplayWidget.log` (`BOSS_DISPLAY_WIDGET_VERIFIED paths=5`).
- `Wx.MVVM.BossDisplay.Lifecycle` 자동화 테스트를 통과했다. 위젯별 모델·구독 분리, ASC 데이터 공유, 다른 월드 이벤트 제외, 중복 교전 통지, 비선택 보스 이탈, 위젯 해제 후 남은 위젯 갱신, 현재 보스 이탈 후 대체, 전체 이탈 시 비우기, 늦은 생성 시 전체 후보 수집, 실제 EndPlay 통지, 중복 해제, 잘못된 생성 인자를 검증했다. 보고서: `Saved/Automation/BossDisplay/index.json`, 로그: `Saved/Logs/BossDisplayTests.log`.
- 테스트는 `BP_Boss`를 읽을 때 기존 `WxMinionManagerComponent`·`WxProjectileManagerComponent` 클래스 참조가 남은 경고 2건과 함께 성공했다(실패 0). 해당 보스 에셋은 이번 범위에서 변경하지 않았다. 자동화 테스트의 임시 월드는 전투 AI·BP Construction Script를 실행하지 않으며, 렌더링 화면 검증은 수행하지 않았다.
- 최종 UE 5.8.2 `WxEditor Win64 Development` 빌드 성공. 로그: `Saved/Logs/BuildDoctor/build_2026-09-05_225304_303_32716.log`. 테스트 월드 중복 초기화와 컨텍스트 해제 순서를 수정했다. 중간 .NET 실행기 시작 실패는 재시도로 해소됐으며, 임시 도구 정리 과정의 `WxEditor.Build.cs` 손상도 작업 전 내용으로 복원하고 최종 diff가 없는 것을 확인했다.
- `git diff --check`를 통과했다. 별도로 존재하던 리뷰 문서 변경과 `module_review_WxGame_Framework.md`는 이번 구현에서 변경하지 않았다.
