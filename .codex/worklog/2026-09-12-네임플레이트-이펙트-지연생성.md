# 네임플레이트의 미사용 이펙트 뷰모델 지연 생성

## 계획

- ASC 뷰모델 초기화에서 이펙트 이벤트 구독과 목록 생성을 분리한다.
- ActiveEffectViewModels 최초 조회 시 이벤트를 구독하고 기존 활성 이펙트를 반영한다. 기존 MVVM 바인딩 이름을 유지한다.
- 반복 조회의 중복 생성·구독을 방지하며 추가·제거·스택·잔여 시간 갱신과 공유 뷰모델 수명 정책을 유지한다.
- 미사용 시 이펙트 뷰모델·티커 미생성, 최초 조회 및 후속 변경을 회귀 검증하고 런처에서 조회한 UE 5.8로 WxEditor Win64 Development를 빌드한다.
- 사용한 목록을 화면 종료 시 즉시 중단하는 기능은 포함하지 않는다.

## 완료

- ASC 초기화에서 활성 이펙트 추가/제거 구독과 선행 목록 생성을 제거했다. 태그·어빌리티 처리는 유지했다.
- 기존 ActiveEffectViewModels 리플렉션 필드에 native Getter를 연결했다. C++에서도 Getter를 거치도록 저장 배열을 private으로 옮기되 BlueprintReadOnly·FieldNotify와 바인딩 이름은 유지했다.
- 최초 조회 때만 구독·목록 생성을 시작한다. 초기화 플래그를 먼저 설정해 FieldNotify 재진입과 반복 조회의 중복 초기화를 방지한다. 해제 후 조회는 빈 목록을 유지한다.
- Source/WxGame/Tests/WxAbilitySystemViewModelTests.cpp에 실제 GAS와 기존 WxCombat UI 데이터 컴포넌트를 사용하는 통합 회귀 테스트를 추가했다. WxUI 플러그인 의존성은 변경하지 않았다.
- 검증: Character VM 초기화 및 최초 조회 전 이펙트 추가에도 이펙트 VM 0개·이펙트 이벤트 구독 없음, 리플렉션 최초 조회 시 기존 아이콘 이펙트만 반영, 반복 조회 인스턴스 재사용, 추가/제거·스택·유한 잔여 시간 갱신·무한 진행률·해제 후 조회를 확인했다. 미사용 이펙트 VM 자체가 없으므로 해당 VM의 티커도 등록되지 않는다.
- 빌드: UE 5.8.2, WxEditor Win64 Development 성공(종료 코드 0). 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-12_145138_223_30300.log
- 자동화: Wx.UI.AbilitySystem.LazyEffectViewModels 성공 1, 실패 0, 경고 0(프로세스 종료 코드 0). 결과: C:/Wx/Saved/Automation/LazyEffectViewModels/index.json
- 검증 중 테스트 코드의 리플렉션 인수 형식, 엔진 SetStackingType 미export, 임시 월드 컨텍스트 누락을 수정한 뒤 최종 빌드·테스트를 통과했다.
- 실제 WBP 시각 검증과 다수 네임플레이트 성능 측정은 수행하지 않았다. 화면 종료 시 추적 중단은 승인된 범위에서 제외했다.
