# 미니언 BP 인터페이스와 어그로 허용

## 계획

- 사용자 승인: IWxMinion에 어그로 허용 여부를 추가하며, 인터페이스는 BP에서 직접 붙여 사용한다.
- IWxMinion을 WxCore 공용 계약으로 옮겨 WxAI와 WxCombat의 상호 참조를 피하고 기존 클래스 경로는 리다이렉트한다.
- 소환 상한과 어그로 허용 여부를 BlueprintNativeEvent로 제공하고 BP 구현을 Execute 호출로 소비한다. C++ 기본값은 상한 1, 어그로 허용이며 BP에서는 반환값을 명시한다.
- AI 타겟 후보와 기존 타겟 모두 비허용 미니언을 제외한다. 팀과 피해 판정은 유지한다.
- BP_Minion에 인터페이스를 적용해 어그로를 비허용으로 설정한다.
- UE 5.8 WxEditor Development 빌드 및 변경 범위 검증 후 완료 기록을 갱신한다.

## 완료

- IWxMinion을 WxCore로 이동하고 WxCombat의 옛 인터페이스 경로에 ClassRedirect를 추가했다. 도메인 간 모듈 의존성은 추가하지 않았다.
- BP에서 인터페이스를 직접 구현할 수 있도록 Blueprintable 및 BlueprintNativeEvent로 전환했다. CanBeAggroTarget의 BP 반환값은 분신 false, 어그로 허용 미니언 true로 사용한다.
- 소환 시 ImplementsInterface 및 Execute_GetMaxCountPerMaster로 BP 전용 구현을 지원한다. BP 상한 반환값이 0 이하이면 최소 1로 보정한다.
- 타겟 선택 및 유지 경로에서 Execute_CanBeAggroTarget을 검사한다. 비허용으로 바뀐 기존 타겟도 해제하며 Perception이 없는 경우도 비운다.
- 작업 중 에디터에 이미 추가된 BP_Minion의 CanBeAggroTarget=false 구현을 확인하고 보존했다. BP 컴파일 및 해당 에셋 저장을 완료했다. GetMaxCountPerMaster의 현재 반환값 0은 변경하지 않았다.
- UE 5.8 WxEditor Win64 Development 최종 빌드 성공(종료 코드 0). 로그: Saved/Logs/BuildDoctor/build_2026-09-12_055912_917_632.log.
- 새 commandlet 프로세스로 저장된 BP를 로드·컴파일하고 인터페이스 구현 및 CanBeAggroTarget=false 반환값을 assert 검증했다. Saved/Logs/MinionAggroVerify.log에 MINION_AGGRO_VERIFY_SUCCESS 기록. 프로세스 종료 코드 1은 기존 MCP 서버의 8000 포트 점유 오류 때문이며 검증 스크립트 오류는 없다.
- 수정한 코드·설정 범위의 git diff --check 통과. 다른 작업의 변경은 유지했다. 실제 PIE 전투 재현은 미실시.
