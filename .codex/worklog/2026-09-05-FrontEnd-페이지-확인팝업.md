# FrontEnd 페이지와 시작 확인 팝업

## 계획

- WBP_FrontEnd에 WidgetSwitcher로 Main, SelectCharacter, SelectLevel 페이지를 구성한다. 모든 버튼은 WBP_Button을 사용한다.
- Main의 NewGame은 캐릭터 선택으로 이동하며 QuitGame은 게임을 종료한다.
- 캐릭터 클릭 후 레벨 선택으로 이동한다. 레벨 클릭 시 기존 확인 팝업에 캐릭터·레벨 이름과 시작 질문을 표시한다.
- 확인 시 기존 Library로 입장한다. 취소 시 두 선택을 초기화하고 Main으로 복귀한다.
- 페이지 포커스와 팝업/입장 중복 방지를 적용한다. Blueprint 컴파일, 전환·팝업 확인/취소·두 맵 입장·종료 및 WxEditor Development 빌드를 검증한다.

## 완료

- 기존 Root, SelectionButtons, ProjectTitle과 캐릭터/레벨 버튼을 보존하고 PageSwitcher 아래 Main, SelectCharacter, SelectLevel로 재배치했다. NewGame/QuitGame은 WBP_Button을 사용한다.
- 레벨 선택 후 기존 ShowConfirmationPopup(OkCancel)에 캐릭터와 레벨 Title 및 시작 질문을 전달한다. 확인 시에만 입장하며 취소 시 ShowMain에서 두 선택을 초기화한다.
- 페이지별 FocusTarget과 PopupOpen 중복 방지를 연결했다. 이전 Enter 버튼은 확인 팝업으로 대체했다.
- 사용자 추가 지시에 따라 버튼·페이지 제목·선택 이름·질문을 영어로 적용했다. 한글용 팝업 본문 폰트 override는 해제했다.
- 최초 일괄 교체는 자동 승인 검토에서 차단되어 실행되지 않았다. SHA256이 일치하는 복구 사본을 확보하고 기존 위젯을 이동하는 제한된 변경으로 적용했다.
- Blueprint 컴파일 통과. RenderOffscreen PIE에서 페이지 순서, 이름·질문, 팝업 중복 차단, 취소 시 Main 복귀/선택 초기화, 확인 후 두 맵 BP_Player 도착/입력 복원, QuitGame의 PIE 종료를 확인했다.
- 전체 흐름 결과: Saved/FrontEndPageResults.json (SUCCESS). 해당 실행은 기존 보스 네임플레이트 MVVM 오류도 기록되어 프로세스 코드 1로 종료했으나 대상 기능 검증은 통과했다.
