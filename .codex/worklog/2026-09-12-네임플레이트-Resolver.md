# 네임플레이트 Resolver 전환

## 계획

- UWxViewModelResolver_NameplateCharacter를 WxUI 모듈에 추가한다. 공용 인터페이스와 WxGame 의존성을 추가하지 않는다.
- 사용자 추가 지시에 따라 InitWidget·SetWidget 오버라이드와 위젯 확장을 두지 않는다. Resolver 실행 시 해당 위젯을 보유한 네임플레이트 컴포넌트를 역조회해 Owner를 찾는다. 캐릭터는 이름·초상화 데이터만 컴포넌트에 전달한다.
- Resolver가 Owner의 ASC를 조회하고 ASC별 공유 Character VM을 생성·반환한다. NameplateComponent의 수동 VM 생성·주입을 제거한다.
- 실제 네임플레이트 WBP의 MVVM 소스를 새 Resolver로 전환한다.
- 대상별 VM 분리·동일 대상 공유·위젯 재생성과 에셋 바인딩을 검증하고 UE 5.8 WxEditor Development를 빌드한다.

## 완료

- UWxViewModelResolver_NameplateCharacter를 WxUI에 추가했다. 공용 인터페이스나 모듈 의존성 추가 없이 같은 위젯을 보유한 UWxNameplateComponent를 역조회하고 Owner의 ASC를 사용한다.
- 사용자 추가 지시에 맞춰 InitWidget·SetWidget 오버라이드와 위젯 확장을 제거했다. 컴포넌트에는 기존 표시 제어와 SetDisplayData/표시 데이터 조회만 남겼다. 수동 VM 생성·SetViewModelByClass 주입은 제거했다.
- EnemyCharacter는 Super::BeginPlay 전에 이름·초상화만 전달한다. Resolver는 ASC별 Character VM을 재사용하고 신규 VM만 초기화한다.
- WBP_Nameplate_Enemy의 기존 소스 이름·ID를 보존하고 Manual에서 Resolver로 전환했다. 플레이어 컨텍스트가 없어도 MVVM View가 생성되도록 WBP_Nameplate_Enemy 및 하위 HP/GP 표시용 WBP_AttributeBar의 bCanCallInitializedWithoutPlayerContext를 활성화했다. Player/Boss WBP의 기존 전용 Resolver는 유지했다.
- 최초 자동화 실패를 조사해 플레이어 컨텍스트가 없으면 WBP의 NativeOnInitialized가 생략되는 것을 확인했다. 위젯 수명을 유지하는 테스트 픽스처와 에셋 초기화 옵션을 보완한 뒤 통과했다.
- UE 5.8.2 WxEditor Win64 Development 빌드 성공(종료 코드 0). 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-12_151118_380_14596.log
- 실제 저장된 WBP를 사용하는 Wx.UI.Nameplate.Resolver 및 기존 Wx.UI.AbilitySystem.LazyEffectViewModels 자동화 테스트 모두 성공(성공 2, 실패 0, 경고 0, 오류 0, 프로세스 종료 코드 0). 결과: C:/Wx/Saved/Automation/NameplateResolver/index.json
- 검증: 수동 주입 및 OwningPlayer 없이 자동 VM 생성, 대상 ASC·이름·초상화 일치, 동일 대상 공유, 대상별 분리, 위젯 재생성 후 재사용, null·타입 불일치 거부, 기존 이펙트 지연 생성 회귀.
- 에셋 컴파일·저장 성공. 에셋 처리 commandlet은 기존 SourceControl의 Content/Character/Player 경로 경고를 Error로 수집해 종료 코드 1을 반환했으나, 저장 성공을 확인했고 별도 프로세스에서 저장된 WBP를 다시 로드한 자동화 테스트는 통과했다.
- 성능 특성: Resolver 실행마다 네임플레이트 컴포넌트를 선형 탐색한다. 추가 틱·캐시·등록/해제 수명 관리는 두지 않는다. 실제 화면 시각 검증 및 대규모 생성 비용 측정은 수행하지 않았다.
