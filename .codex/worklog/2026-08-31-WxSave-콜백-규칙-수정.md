# WxSave 콜백 규칙 수정

## 계획

- `WxSaveGameSubsystem`의 저장 플러시 델리게이트 콜백 `ContinueSaveToFileToDisk`를 `HandleSaveFlushComplete`로 변경한다.
- 선언, 정의, 델리게이트 바인딩 및 직접 호출부를 함께 갱신해 동작은 보존한다.
- 불필요한 비동기 저장 람다가 이미 `CreateUObject` 기반 멤버 콜백으로 교체된 상태인지 재확인한다.
- 후속 가독성 검토에 따라 `HandleSaveFlushComplete`는 델리게이트 전용 얇은 콜백으로 두고, 실제 비동기 저장 시작은 중립적인 이름의 별도 함수로 분리한다.
- 월드 서브시스템이 없는 경로는 콜백을 가장하지 않고 실제 저장 시작 함수를 직접 호출하며, 기존 저장 순서와 실패 처리를 보존한다.
- 런처 정보에서 UE 5.8 설치 경로를 조회하고 `WxEditor` Development 타겟을 빌드해 컴파일을 검증한다.

## 완료

- `ContinueSaveToFileToDisk`를 `HandleSaveFlushComplete`로 변경하고 선언, 정의, 델리게이트 바인딩 및 월드 서브시스템 부재 시 직접 호출부를 함께 갱신했다.
- `WxSaveGameSubsystem`에 기존 이름과 `CreateLambda`가 남아 있지 않음을 검색으로 확인했다.
- 비동기 파일 저장은 기존의 `CreateUObject(this, &UWxSaveGameSubsystem::HandleAsyncSaveFinished)` 멤버 콜백을 유지해 불필요한 람다가 이미 제거된 상태임을 확인했다.
- UE 5.8(`C:\Program Files\Epic Games\UE_5.8`)의 `Build.bat`으로 `WxEditor Win64 Development` 빌드를 실행해 성공했다(14/14 액션, 종료 코드 0).
- 빌드 로그: `.Codex/skills/build-doctor/logs/build_2026-08-31_015418.log`.
- `HandleSaveFlushComplete`를 `BeginAsyncSaveToDisk` 호출만 담당하는 델리게이트 콜백으로 분리하고, 월드 서브시스템이 없는 경로는 `BeginAsyncSaveToDisk`를 직접 호출하도록 바꿔 이름과 실제 역할을 일치시켰다.
- 후속 변경 후 `WxEditor Win64 Development` 빌드를 다시 실행해 성공했다(5/5 액션, 종료 코드 0). 빌드 로그: `.Codex/skills/build-doctor/logs/build_2026-08-31_015941.log`.
