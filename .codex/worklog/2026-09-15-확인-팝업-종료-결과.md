# 확인 팝업 종료 결과 보장

## 계획

- 뒤로 가기는 Cancelled를 우선하고 Yes/No 구성에서는 Declined로 처리한다. 확인 전용 팝업은 뒤로 가기로 닫지 않는다.
- 외부 비활성화 및 표시 실패에는 Killed를 전달하며, 모든 경로와 재진입에서 요청당 결과를 한 번만 전달한다.
- 바깥 영역 클릭 동작은 추가하지 않는다. 관련 팝업 및 표시 요청 코드만 수정한다.
- 종료 경로를 검증하고 런처 정보에서 조회한 UE 5.8로 WxEditor Development를 빌드한다.

## 완료

- UWxConfirmationPopup에서 CommonUI Back 입력을 처리한다. Cancelled를 우선하고, 취소 없는 Yes/No 구성은 Declined를 전달하며, 확인 전용은 입력만 소비한다.
- NativeOnDeactivated 및 NativeDestruct에서 미처리 결과를 Killed로 완료한다. 부모 이벤트 실행 전에 델리게이트를 분리하여 재진입 시 중복 호출을 막는다.
- 표시 요청과 팝업이 공유하는 1회 완료 델리게이트로 push 실패와 팝업 종료가 겹쳐도 사용자 콜백을 중복 호출하지 않는다.
- 잘못된 서술자, UIManager 없음, 클래스/레이아웃/생성/push 실패에도 Killed를 전달한다. 기존 KillPopup 및 버튼 결과는 유지한다.
- 코드 경로 검토: Ok / OkCancel / YesNo / YesNoCancel 뒤로 가기 분기, 버튼 이후 비활성화·Destruct, 외부 종료, Finish(nullptr), 종료 콜백 재진입에서 언바인딩 순서를 확인했다.
- 검증: git diff --check 통과. 런처에서 UE_5.8 설치 경로를 조회하여 WxEditor Win64 Development -WaitMutex -NoHotReloadFromIDE 빌드 성공(Result: Succeeded, 2026-09-15).
- 한계: PIE의 실제 키 입력, 레이아웃 제거 및 Blueprint 이벤트 조합은 실행하지 않았다. 런타임 자동화 테스트는 추가하지 않았다.
