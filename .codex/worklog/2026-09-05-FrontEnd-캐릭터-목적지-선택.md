# FrontEnd 캐릭터·목적지 선택

## 계획

- 승인된 `Docs/Programmer/FrontEnd_캐릭터선택_월드진입_설계.md`의 1단계를 구현한다. 싱글플레이 우선이며 인벤토리는 제외한다.
- 후속 요청 반영: ScreenWidget C++ 클래스 없이 기존 WBP_FrontEnd와 ViewModel로 두 선택 단계를 구성한다.
- 캐릭터·목적지·FrontEnd 카탈로그를 PrimaryAssetId로 식별하고, 선택 UI와 맵 진입을 기존 CommonUI/Experience에 연결한다.
- GameInstance 수명의 요청 상태와 월드별 Pawn·진입점 결정을 분리한다. 저장 도입을 위해 확정 상태와 진행 중 전환을 구분한다.
- 잘못된 선택·중복 요청·로드 실패·진입점 오류를 처리하고, 직접 PIE의 기존 기본 Pawn을 보존한다.
- 실제 에셋을 구성하고 UE 5.8 WxEditor Development 빌드 및 가능한 실행 검증을 수행한다. 게임 중 이동·SaveGame·인벤토리·World Partition 빠른 이동은 후속 범위다.

## 완료

- ScreenWidget C++ 클래스 없이 1단계 구현 완료. 기존 `WBP_FrontEnd`가 캐릭터 선택 → 목적지 선택을 표시한다. 부모 `UWxHUDLayout`은 유지하고 `UWxSelectionScreen`·`UWxFrontEndHUD`는 제거했다.
- `UWxViewModel_Selection`의 FieldNotify 표시 값·버튼 활성화를 WBP에 바인딩했다. `UWxViewModelResolver_FrontEnd`가 공유 VM을 주입하고, 버튼은 Function Library를 통해 `UWxFrontEndFlowComponent`를 호출한다. 기존 WBP의 기본 포커스도 확인 버튼으로 지정했다.
- 캐릭터·목적지·카탈로그 정의와 GameFlow, GameMode의 선택 Pawn·진입점 연결, RequestId 보호·중복 요청 차단·실패 복구·스트리밍 준비 대기·입력/이동 보류를 구현했다. 인벤토리 파일은 수정하지 않았다.
- 실제 에셋: `/Game/Character/Definitions/DA_Player`, `/Game/World/Destinations/DA_DevCombat`, `DA_OpenWorld`, `/Game/UI/FrontEnd/DA_FrontEnd`. 기존 `BP_Player` 1종과 맵 2개를 사용한다. `EXP_Combat`은 선택을 허용하고 `WAS_FrontEnd`는 흐름 컴포넌트를 주입한다.
- 최종 UE 5.8 WxEditor Development 빌드 성공: `Saved/Logs/BuildDoctor/build_2026-09-05_200549_439_19440.log`.
- `Wx.FrontEnd.Catalog`, `Wx.FrontEnd.SelectionIdentity` 자동화 테스트 2개 성공. 로그 `Saved/Logs/FrontEndTests.log`, 보고서 `Saved/Automation/FrontEnd/`.
- NullRHI PIE에서 WBP의 실제 MVVM 표시, 뒤로 가기 선택 보존, 입장 중 재확정 차단, 두 맵에서 BP_Player 생성·입력 해제, FrontEnd 복귀 후 재입장 성공. 결과 `Saved/FrontEndPlayResults.json`.
- 메모리에만 잘못된 진입점 태그를 주입한 별도 PIE에서 FrontEnd 복귀와 버튼 재활성화 성공. 에셋은 저장하지 않았다. 결과 `Saved/FrontEndRecoveryResult.txt`.
- WBP 최종 컴파일 성공: `Saved/Logs/FrontEndFocus.log`. 새 화면 C++ 타입 참조 잔존 없음, 관련 diff 공백 검사 통과.
- 검증 한계: GPU 화면 렌더링·실제 키보드/게임패드 입력·패키지 Cook 실행은 미검증이다. 플레이 검증 중 기존 보스 네임플레이트의 VM 초기화 오류가 관찰되었으나 이번 범위에서 변경하지 않았다. SaveGame·게임 중 이동·인벤토리·빠른 이동은 후속 범위다.
