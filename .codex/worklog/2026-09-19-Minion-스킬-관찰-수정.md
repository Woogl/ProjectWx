# Minion 스킬 발동 관찰 수정

## 계획

- 승인된 방식에 따라 ObserveAbility의 InstancedPerActor 조건을 실제 PrimaryInstance의 IsActive()로 판정한다. 다른 정책은 기존 Spec.IsActive() 판정을 유지한다.
- 발동 콜백은 종료 콜백과 동일하게 ConditionalFlowAbort로 처리한다. 타이머 및 이벤트 저장 상태는 추가하지 않는다.
- 실제 스킬 에셋 설정과 UE 5.8 발동 순서를 확인하고 WxEditor Win64 Development 빌드로 검증한다.
- 기존 사용자 수정과 BT 에셋은 보존한다. 즉시 종료 스킬을 반드시 한 번 소비하는 동작은 범위 밖이다.

## 완료

- ObserveAbility의 InstancedPerActor 활성 판정을 GetPrimaryInstance()->IsActive()로 변경했다. null 인스턴스는 비활성, 다른 정책은 기존 Spec.IsActive()로 판정한다.
- 발동 콜백도 ConditionalFlowAbort(ConditionResultChanged)를 사용하도록 변경했다.
- MCP로 GA_HGTest_Skill_2 CDO의 instancingPolicy=InstancedPerActor를 확인했다.
- UE 5.8 소스에서 PreActivate의 bIsActive 설정 → 발동 통지 → ActiveCount 증가 순서와 BT 요청의 즉시 조건 재검사를 확인했다. 수정 후에는 해당 콜백 시점에 참인 인스턴스 상태를 읽는다.
- WxEditor Win64 Development 컴파일 및 링크 성공. 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-19_033726_812_29544.log (Result: Succeeded, exit 0).
