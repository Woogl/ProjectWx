# 공격 슬롯 단일 입력

> 후속 사용자 요청으로 UWxAttackButton과 HUD 입력 연결은 제거했다. 최종 상태는 `2026-09-08-AttackButton-제거.md`를 참조한다.

## 계획

- 후속 사용자 제약: 신규 WBP와 WBP 이벤트 그래프를 선호하지 않는다. 생성했던 WBP_AttackSlot은 제거하고, 공격 전용 네이티브 UWxAttackButton을 기존 WBP_PlayerSkills에 배치한다. 공용 WxButtonBase는 변경하지 않는다.
- 승인된 방식으로 입력 버튼을 하나로 통합한다. 누르기 시작 시 지상 Light 또는 공중 Air를 발동 시도하고, CommonUI 기본 0.35초 Hold 완료 시 Heavy를 발동 시도한다. 길게 눌러도 Light가 먼저 나가는 기존 게임 입력 의미를 유지한다.
- WxButtonBase 기반의 공격 전용 C++ 버튼으로 기존 아이콘 Overlay를 감싼다. 아이콘 위젯은 MVVM 표시 전용으로 만들고 히트 테스트를 끈다. 슬롯의 입력 버튼 자체는 공격 상황·CanActivate로 숨기지 않는다.
- 기존 어빌리티 ViewModel과 TryActivateAbility를 재사용하고 공용 ButtonBase·WxUIData·Enhanced Input 주입·사용자 타이머 코드를 추가하지 않는다.
- 실제 네이티브 버튼 입력과 CommonUI Hold 경로, 상황별 표시 및 짧은 누름/길게 누름/해제를 검증한다. WxEditor Development 빌드와 기존 회귀 테스트를 수행하고 수정용 임시 도구는 제거한다.

## 완료

- 기존 WBP_PlayerSkills의 AttackSlot을 UWxAttackButton 네이티브 위젯으로 교체했다. 원래 AttackVariants Overlay와 아이콘 3개, 기존 배치를 유지하고 MVVM 목적지를 LightAbility/AirAbility/HeavyAbility로 연결했다.
- NativeOnPressed에서 Light/Air 발동을 시도하고, CommonUI 기본 Hold 완료로 호출되는 NativeOnClicked에서 Heavy를 시도한다. HUD 인스턴스의 HoldData_AttackHeavy가 0.35초를 제공한다. 공용 WxButtonBase는 변경하지 않았다.
- 이번 작업에서 생성했던 WBP_AttackSlot은 참조가 없음을 확인한 뒤 삭제했다. 해당 WBP의 BP_OnPressed/BP_OnClicked 이벤트 그래프도 함께 제거했다. 에셋 교체용 임시 C++ 도구는 제거했다.
- WxEditor Win64 Development 빌드 성공: Saved/Logs/BuildDoctor/build_2026-09-08_015131_760_27784.log.
- 자동화 3종 SeparateWidgets / SlotInput / SlotVisibility 모두 성공: Saved/Logs/test_native_attack_final.log. 저장된 HUD 버튼 템플릿을 복제하여 CommonUI Hold 0.35초, 짧은 누름, Hold 완료, 해제 중복 방지, 공중 공격과 Heavy 차단을 테스트 어빌리티로 검증했다. 실제 MVVM 변환 함수로 CanActivate=false에서도 슬롯 표시가 유지됨을 확인했다.
- 에셋 바인딩 검증 및 불필요 WBP 삭제 성공: Saved/Logs/remove_obsolete_attack_wbp.log. 실제 게임에서 커서로 조작하는 PIE 검증은 수행하지 않았다.
