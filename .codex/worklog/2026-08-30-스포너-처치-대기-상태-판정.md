# 스포너 처치 대기 상태 판정 전환

## 계획

- `FWxStateTreeTask_WaitSpawnersKilled`를 일회성 통보 등록 방식에서 즉시 판정 + 저주기 Scheduled Tick 상태 판정 방식으로 전환한다.
- 로케이터별 해석 결과를 약참조로 캐시하고, 캐시가 무효일 때는 로드된 `AWxSpawner`를 실제 해석 컨텍스트로 사용해 월드 파티션 대상까지 다시 찾는다.
- 다른 태스크 때문에 StateTree가 자주 틱하더라도 처치 조건 판정은 설정한 주기로 제한하고, 상태 이탈 시 Scheduled Tick 요청을 정리한다.
- `AWxSpawner`에서 특정 StateTree 대기 태스크로 향하는 include와 직접 통보를 제거한다. 상호작용처럼 실제 순간 이벤트를 기다리는 기존 대기 등록부는 유지한다.
- 관련 회귀 경로를 점검하고 UE 5.8 `WxEditor` Development 타겟을 빌드해 컴파일을 검증한다.

## 완료

- `WaitSpawnersKilled`가 진입 시 즉시 판정하고 0.25초 간격의 Scheduled Tick 으로 지속 상태를 재판정하도록 전환했다.
- 다른 활성 태스크 때문에 StateTree가 더 자주 틱해도 남은 검사 시간으로 실제 조건 판정을 제한하고, 성공·상태 이탈 시 예약 요청을 정리하도록 했다.
- 해석된 스포너를 약참조로 캐시하고, 캐시 미스에는 현재 월드의 로드된 스포너를 실제 UOL 컨텍스트로 사용해 월드 파티션 런타임 셀 대상을 다시 찾도록 했다.
- `AWxSpawner`의 `WaitSpawnersKilled` 헤더 의존과 `MarkKilled()` 직접 통보를 제거했다. 기존 상호작용 대기 등록부는 유지했다.
- 직접 통보 심볼 잔존 여부와 `git diff --check`를 확인했다. WxWorld에는 기존 자동화 테스트 기반이 없어 별도 테스트 프레임워크는 추가하지 않았다.
- UE 5.8.2의 `WxEditor Win64 Development` 빌드 성공. 로그: `.Codex/skills/build-doctor/logs/build_2026-08-30_170734.log`.
