# 히트스톱 중 이동 네트워크 시간 유지

## 계획

- 승인된 수정: 히트스톱이 CharacterMovement 틱과 클라이언트 이동 타임스탬프를 중단하지 않게 한다.
- 기존 UWxCharacterMovementComponent의 PerformMovement에서 Effect.HitStop 태그가 있는 동안 실제 이동 시뮬레이션만 건너뛴다. 속도·이동 모드·대기 중인 넉업을 지우지 않고, 태그 해제 후 정상 이동을 재개한다.
- WxHitStopComponent는 애니메이션 정지만 맡고 이동 틱 제어를 제거한다. 시뮬레이티드 프록시의 복제·스무딩 경로는 유지한다.
- 변경 경로를 점검하고 UE 5.8 WxEditor Win64 Development 빌드 및 가능한 집중 회귀 검증을 수행한다. 네트워크 실측 범위와 한계를 기록한다.

## 완료

- WxHitStopComponent에서 이동 컴포넌트 틱 중단을 제거했다. 기존 공용 UWxCharacterMovementComponent::PerformMovement에서 Effect.HitStop 동안 실제 이동만 건너뛰고 해제 후 Super 경로를 재개한다. 게임 모듈이 WxCore의 태그를 참조하며 플러그인 역참조는 추가하지 않았다.
- 사용자 추가 증상인 방향키 유지 중 적중 후 위치 어긋남도 이동 네트워크 시간 중단과 관련될 수 있어 함께 고려했다. 서버와 클라이언트의 PerformMovement가 동일 태그를 사용하며, 틱·이동 전송·타임스탬프를 정지시키지 않는다.
- Wx.Combat.HitStop.MovementContinuity 자동화 테스트 추가 및 성공(1건). 이동 틱 유지, 입력을 추가하는 동안 정지 위치·상승 속도·낙하 모드 보존, 중첩 태그 일부 해제 시 정지 유지, 최종 해제 후 상승 재개를 확인했다. 보고서: C:/Wx/Saved/Automation/HitStopMovement/index.json.
- 테스트 준비 코드에서 CreateWorld 뒤 InitializeNewWorld를 중복 호출해 두 차례 테스트 프로세스가 종료됐다. 엔진 CreateWorld에 초기화 값을 직접 전달하도록 고친 뒤 통과했다. 게임 실행 프로세스는 종료하지 않았다.
- UE 5.8 WxEditor Win64 Development 빌드 성공(종료 코드 0). 최종 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-14_234858_823_35144.log. git diff --check 통과.
- 네트워크 소켓을 사용하는 2인 PIE·루트모션 몽타주·서버 위치 보정은 미실측이다. 테스트는 이동 컴포넌트 직접 호출을 검증하며 실제 방향키 전송을 재현하지 않는다. 태그 복제 지연에 따른 잔여 위치 보정까지 없어졌다고 단정하지 않는다. Development만 빌드했으므로 DebugGame 실행에는 해당 구성 재빌드가 필요하다.
