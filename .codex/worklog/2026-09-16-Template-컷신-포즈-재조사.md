# Template 클라이언트 시전자 포즈 재조사

## 계획

- 사용자 확인: Template 클라이언트 시전자의 컷신 애니메이션이 서버에서 여전히 보이지 않는다.
- 기존 플래그 테스트를 원인 확정의 근거로 삼지 않고 실제 Template 시퀀스와 캐릭터를 로드해 바인딩 대상과 뼈 포즈 변화를 확인한다.
- 이동 패킷 기반 포즈 갱신 전후 결과를 비교한다. 확인된 원인에 한해서 수정하고 UE 5.8 빌드·컷신 회귀 테스트를 수행한다.

## 완료

- 사용자 증상: Template 클라이언트 시전자는 칼을 든 컷신 자세인데 서버에서는 직립 대기 자세로 보임. 스크린샷에서도 두 자세의 차이를 확인했다.
- 기존 코드의 실제 Template 단독 평가 및 높은 프레임률의 2인 PIE에서는 뼈 변화가 있었으나, 15 FPS의 2인 PIE에서는 최대 변화가 0.493cm로 포즈 검사가 실패했다. 로그: `Saved/Logs/NetworkTemplatePose15FPS.log`. 따라서 기존의 틱 허용 플래그 수정만으로 해결됐다는 판단은 불충분했다.
- 기존 재생은 `ABP_Unarmed` 인스턴스를 유지했다. Player와 그 하위 바인딩의 애니메이션 섹션에만 `bForceCustomMode`를 적용하여 `AnimSequencerInstance`가 컷신 포즈를 직접 제어하게 했다. 매 로컬 재생마다 시퀀스를 고유 이름으로 복제하므로 공유 원본 에셋의 섹션 설정을 수정하지 않는다. 기존 시전자 바인딩 및 개별 재생 흐름을 유지한다.
- 실제 Template 단독 테스트에서 시퀀서 인스턴스 사용, 시전자 바인딩, 뼈 변화, 종료 시 원래 AnimBP 인스턴스 복원을 확인했다. 최종 컷신 회귀 검사 5개 모두 통과: `Saved/Logs/SkillCutsceneCustomFinal.log`.
- 수정 후 같은 15 FPS의 2인 PIE에서 서버 포즈 변화가 최대 80.433cm이며 포즈 검사가 통과했다. 로그: `Saved/Logs/NetworkTemplateCustom15FPS.log`. 다만 테스트 전체는 기존 보스 이름표 MVVM 초기화 오류 4건 때문에 Fail로 기록된다. 네트워크 검사는 별도 `Wx.Combat.Network.TemplateCutscenePose`로 분리하고 LV_DevCombat 맵 선행 조건을 명시했다.
- 검증 한계: NullRHI 자동화로 뼈 포즈를 검증했으며 실제 렌더링 화면에서 동일 증상이 해소됐는지는 사용자 재확인이 필요하다. 낮은 프레임률에서 AnimBP 경로가 포즈를 유지하는 세부 엔진 실행 순서까지 원인으로 확정하지 않는다. 초기에 같은 GFrameCounter로 여러 번 평가한 단독 실험은 캐시 때문에 유효하지 않아 증거에서 제외했다.
- UE 5.8 WxEditor Win64 Development 최종 빌드 성공 (`Saved/Logs/BuildDoctor/build_2026-09-16_022637_775_30572.log`). 사용자 실행 구성인 Win64 DebugGame도 추가 빌드 성공. 에디터 재실행은 수행하지 않았다.
