# 플레이어 LSP 영속화 정렬

## 계획

- `UWxPlayerSpawnComponent`가 직접 `StartSpot`과 컨트롤러 위치를 조작하던 경로를 제거하고, `UWxSaveWorldSubsystem`이 저장 로드 초기에 `APlayerStartPIE`를 배치하여 기존 `AWxGameMode`와 엔진 `ChoosePlayerStart`/`RestartPlayer` 흐름이 플레이어를 생성하게 한다.
- `IWxSavable`과 `FWxSaveModule`을 LSP의 pre-persist/post-restore 객체 훅 구조로 확장하고, 기존 `AWxDevice`와 `AWxSpawner`의 복원 동작을 보존한다.
- `UWxCombatAttributeSet`의 비메타 어트리뷰트를 LSP 저장 대상으로 등록하고, 복원 후 Max 계열과 현재값 순서로 ASC setter를 다시 호출해 aggregator와 변경 델리게이트를 동기화한다.
- `Effect.Savable` 태그가 지정된 활성 GameplayEffect의 클래스, 시전자 참조, 남은 시간, 레벨, 스택, SetByCaller 값을 보존하는 ASC 영속 상태를 샘플 구조에 맞춰 이식한다.
- GameMode가 생성하는 플레이어 폰을 LSP 런타임 재생성 대상으로 삼지 않고, 맵마다 안정적으로 존재하는 `AWxWorldSettings`가 플레이어 Attribute/ASC 상태를 LSP 프로퍼티로 보관한 뒤 AbilitySet 초기화가 끝난 새 플레이어에게 전달하게 한다.
- 기존 v3 `PlayerStats`는 신규 LSP 상태가 없는 경우에만 읽는 호환 경로로 유지하고, 신규 저장 작성은 LSP 상태로 전환한다. 기존 LSP/IAM/Mass 데이터와 저장 포맷 호환성을 보존한다.
- `WAS_CoreGameplay`의 컴포넌트 주입을 제거한 뒤 `UWxPlayerSpawnComponent` 소스와 전용 우회 API, 불필요해진 `WxSave` 의존성을 정리하고 관련 문서를 갱신한다.
- 신규 게임, 저장 위치 스폰, Attribute/GameplayEffect 복원, 구 v3 저장 이관, 단일 폰 생성, LSP/IAM/Mass 회귀 여부를 확인하고 UE 5.8 `WxEditor Development` 타겟을 빌드한다.

## 완료

- `UWxPlayerSpawnComponent`와 `WAS_CoreGameplay`의 컴포넌트 주입을 제거하고, 저장 위치에 임시 `APlayerStartPIE`를 준비한 뒤 엔진 `ChoosePlayerStart`/`RestartPlayer` 흐름으로 스폰하도록 전환했다.
- LSP pre-persist/post-restore 훅을 `IWxSavable`에 연결하고, `AWxWorldSettings`가 플레이어 Attribute 및 persistable GameplayEffect 상태를 보관해 새 플레이어의 AbilitySet 초기화 뒤 복원하도록 구성했다.
- `UWxCombatAttributeSet`은 Max 계열을 먼저 복원하고 ASC setter로 aggregator와 델리게이트를 동기화한다. `Effect.Savable` 효과는 클래스, 시전자 안정 참조, 남은 시간, 레벨, 스택, SetByCaller 값을 저장·복원한다.
- 구 v3 `PlayerStats`는 신규 LSP 상태가 없는 저장 파일에 한해 한 번 소비하는 읽기 호환 경로로 유지했다.
- UE 5.8 `WxEditor Win64 Development` 빌드 성공과 `/Game/Framework/WAS_CoreGameplay` ResavePackages 검증 성공을 확인했다. 삭제된 컴포넌트 참조와 LSP 프로퍼티 경고는 남지 않았다.
- 이후 동시에 진행된 전투 `ActivationGroup` 축 분리 변경 때문에 일시적으로 통합 빌드가 실패했으나 해당 작업이 정리된 뒤 UE 5.8 `WxEditor Win64 Development` 전체 빌드 성공을 다시 확인했다.
