# 네임플레이트 컴포넌트 단순화

## 계획

- 사용자 승인 및 추가 요청에 따라 NameplateComponent의 MVVM Extension 직접 접근과 수동 바인딩을 제거한다. 상태 열거형·진단 카운터·소스/View 캐시·점검 타이머·바인딩 수명주기 오버라이드를 제거하고 거리·스케일 처리만 남긴다.
- WxUI의 Character 리졸버가 해당 위젯을 보유한 네임플레이트 컴포넌트를 찾아 Owner의 ASC별 공유 Character VM을 반환한다. WBP_Nameplate_Enemy의 기존 소스 이름·ID·내용/태그 바인딩을 보존하며 소스 생성 방식을 Manual에서 Resolver로 바꾼다.
- 캐릭터 생성자에서 ASC를 생성하는 실제 프로젝트 초기화 순서를 따른다. ASC를 런타임에 뒤늦게 붙이는 임의 액터의 재시도와 외부의 수동 소스 덮어쓰기 복구는 제거하며, 일반 위젯 재구성은 MVVM의 수명주기에 맡긴다.
- 실제 WBP로 자동 VM 생성·공유, 거리/스케일·플레이어 부재, 태그 숨김 보존, 위젯 교체·재구성 및 해제 후 공유 VM 수명을 검증한다. UE 5.8 WxEditor Development 빌드와 에셋 컴파일·재로드를 확인한다.

## 완료

- NameplateComponent를 생성자·TickComponent·UpdatePresentation만 있는 54줄 구현으로 축소했다. Extension 조회, Get/SetViewModel, InitWidget/SetWidget/EndPlay 오버라이드, 바인딩 상태 열거형·타이머·카운터·View/소스 캐시를 제거했다. 거리·스케일 설정과 계산, 태그 가시성 역할 분리는 유지했다.
- UWxViewModelResolver_NameplateCharacter는 MVVM 생성 시에만 해당 위젯을 보유한 컴포넌트를 역조회하고 Owner의 ASC로 기존 GetOrCreate 팩토리를 호출한다. 대상 누락·ASC 누락은 해당 위치에서 경고한다. 프로젝트 캐릭터가 생성자에서 ASC를 만드는 초기화 순서가 전제이며, 지연 ASC 추가 폴링과 수동 소스 덮어쓰기 복구는 의도적으로 제거했다.
- WBP_Nameplate_Enemy의 기존 Character 소스 ID/이름과 내용·태그 바인딩을 유지하고 CreationType=Resolver, bOptional=false, bCreateSetterFunction=false로 컴파일·저장했다. 이전 Saved/MigrateNameplateResolver.py를 재사용했다. 에셋 저장 명령렛은 기존 소스 제어의 존재하지 않는 Content/Character/Player 경로 경고를 Error로 집계해 코드 1로 종료했으나 WBP 컴파일/저장 성공을 확인했고, 별도 프로세스 테스트에서 저장본 재로드와 자동 바인딩 성공을 확인했다.
- UE 5.8.2 WxEditor Win64 Development 빌드 성공, 종료 코드 0. 로그: C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-13_194041_927_26948.log. 최초 빌드에서 테스트의 float/double 비교 모호성을 수정했다.
- 기존 수동 주입 테스트를 새 역할 분담에 맞는 Wx.UI.Nameplate.ResolverAndPresentation으로 갱신했다. 실제 WBP의 MVVM 초기화/자동 소스 획득, 소유자별 VM 분리·동일 소유자 공유, 최대 거리 0·거리 경계·플레이어 소실/복귀·최소/최대 스케일, Collapsed 보존, 120회 표시 갱신 후 동일 VM, Slate 재구성·위젯 교체·재등록·해제 후 공유 VM 수명, 리졸버 null/잘못된 타입 입력을 검증했다.
