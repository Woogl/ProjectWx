# 인벤토리 뷰모델 재연결 수명 규약

> 후속 승인으로 Available 신호와 조회 범위를 단순화했다. 현재 구현과 최종 검증은 [수명 신호 단순화](2026-09-05-인벤토리-수명-신호-단순화.md)를 따른다. 아래는 최초 구현 당시 기록이다.

## 계획

- Experience 실행 순서를 강제하거나 새 전역 서브시스템을 추가하지 않고 인벤토리의 조회·등장·제거 규약을 정리한다. 사용 불가능하거나 제거 중인 공급자는 연결 대상에서 제외한다.
- 고정 아이템 및 인벤토리 뷰모델에서 관찰 수명(StartObserving/StopObserving)과 소스 연결 수명(BindSource/UnbindSource)을 분리한다. 이미 존재하는 소스, 늦은 등장, 제거, 재생성, 관찰 종료를 같은 규약으로 처리한다.
- 리졸버는 위젯별 뷰모델을 생성하고 해제한다. 부모가 만드는 아이템 뷰모델은 부모가 연결하며 다른 뷰모델의 초기화 순서를 기다리지 않는다.
- 고정 아이템 정의의 이름·기본 아이콘 등은 인벤토리 연결 전에도 제공한다. 미연결과 보유량 0을 구분하고, 소스 제거 시 표시 변경을 FieldNotify로 전달하며 사용 요청을 차단한다.
- 재연결 시 현재 상태를 읽고 이후 변경을 구독한다. 인벤토리 컴포넌트 준비와 아이템 복제 완료를 동일시하지 않으며, 기존 슬롯/합계·획득 알림 동작을 보존한다.
- 생성 순서 양쪽, 소스 제거 및 재생성, 동일 소스 중복 알림, 다른 소유자, 위젯 해제, 이후 데이터 도착과 필드 초기화를 회귀 테스트로 검증한다. 관련 위젯 컴파일과 UE 5.8 WxEditor Win64 Development 빌드를 수행한다.

## 완료

- `UWxInventoryComponent`에 `FindAvailableInventory`, `IsAvailable`, 등장·제거 통지를 추가했다. BeginPlay/EndPlay 및 등록 해제·재등록을 반영하며, 제거 중인 기존 컴포넌트가 새 컴포넌트 탐색을 가리지 않는다. 기존 시작 아이템 지급용 `OnAnyInventoryReady`는 재등록 시 재발행하지 않는다.
- 고정 아이템/인벤토리 뷰모델은 플레이어 관찰과 현재 소스 연결을 분리했다. 리졸버는 위젯별 인스턴스를 생성하고 자신의 인스턴스만 해제한다. 자식 슬롯 뷰모델은 부모가 직접 연결한다.
- 고정 아이템의 정의를 유지해 연결 전과 소스 제거 후에도 이름·기본 아이콘을 제공한다. `bIsInventoryAvailable`을 FieldNotify로 노출하고, 소스 제거 시 수량·충전량·목록·변경 이력을 초기화하여 알린다. 해제 시 델리게이트와 이미지 요청을 정리한다.
- FastArray 수신 후 스냅샷 통지와 ItemDef RepNotify를 추가했다. 지연된 참조/정의의 도착을 수량 Delta 없이 반영하며 스냅샷 갱신으로 획득 토스트를 생성하지 않는다. 복제 제거 중 수량이 0인 슬롯은 목록에서 제외한다.
