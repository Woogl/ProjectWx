# 이펙트 억제 해제 VM 중복 수정

## 계획

- 승인받은 범위: 공통 추가 함수에서 유효 핸들별 기존 VM을 조회하고, 이미 등록된 핸들은 VM 생성 및 목록 변경 알림을 생략한다. 기존 VM의 스택 변경 구독을 유지한다.
- 기존 최초 조회 알림 수정과 다른 핸들의 독립 표시 동작을 보존한다.
- 활성 → 억제 → 재활성 반복 → 제거 회귀 테스트로 VM 개수, 객체 동일성, 목록 알림 및 최종 빈 목록을 확인하고 스택 변경 갱신을 검증한다.
- 런처 정보에서 확인한 UE 5.8로 WxEditor Development 빌드와 관련 자동화 테스트를 실행한다.

## 완료

- `AddActiveEffectViewModel`에서 유효하지 않은 핸들을 거부하고 같은 핸들의 기존 VM이 있으면 추가하지 않는다. 기존 VM의 스택 구독과 객체 참조를 유지하며 목록이 바뀌지 않은 재통지는 FieldNotify를 발생시키지 않는다. 기존 최초 조회 알림 수정 및 제거 경로는 보존했다.
- 기존 `Wx.UI.AbilitySystem.EffectListNotifications` 테스트를 확장했다. 아이콘과 ongoing 태그 요건을 가진 실제 GE 두 개의 태그를 3회 제거·복원해 VM 배열과 객체 동일성, 불필요한 알림 없음, 실제 제거 후 빈 목록 및 해제된 VM 핸들을 검증한다.
- 스택 정책을 가진 GE의 재활성 후 재적용이 같은 핸들·VM을 유지하고, 스택 1→2→1 및 스택 배지 상태를 갱신하는지 검증했다. StackCount FieldNotify에 바인딩한 콜백도 각 변경당 1회 호출되고 최신 값을 조회한다.
- 수정 전 테스트 실패로 재현을 확인했다. 초기 VM 2개에서 억제·해제 3회 후 8개로 증가하고 실제 제거 후 6개가 남았다. 로그: `C:/Wx/Saved/Logs/EffectInhibitionBefore.log`. 테스트 프로세스 종료 코드는 0이었지만 자동화 결과의 `Result={Fail}`과 검증 실패 메시지로 실패를 판정했다.
- 병행 ActionPhase 작업에서 `WxViewModel_Ability.h`가 FGameplayEventData 타입을 인식하지 못해 빌드가 실패했다. 해당 헤더에 `struct FGameplayEventData;` 전방 선언 1줄을 추가해 빌드 장애를 보완했다. 다른 병행 변경은 보존했다.
- 런처에서 조회한 UE 5.8.2로 `WxEditor Win64 Development` 빌드 성공(종료 코드 0). 로그: `C:/Wx/Saved/Logs/BuildDoctor/build_2026-09-15_010525_801_16800.log`.
- 수정 후 자동화 테스트 `Wx.UI.AbilitySystem.EffectListNotifications`의 `Result={Success}` 및 종료 코드 0을 확인했다. 로그: `C:/Wx/Saved/Logs/EffectInhibitionAfter.log`. 기존 최초·반복 Getter 무통지, 독립 핸들 표시, 실제 추가·제거 통지 및 비표시 효과 필터 검증도 통과했다.
- 수정 소스 `git diff --check` 통과. 헤드리스 실제 GAS 및 FieldNotify 자동화 검증이며 WBP 화면의 시각적 검증은 수행하지 않았다.
