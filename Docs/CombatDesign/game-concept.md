## Elevator Pitch

> 스텔라블레이드의 전투 시스템을 충실 재현한 1스테이지 프로토 타이핑. 퍼즐, 몬스터 배치등을 통한 어드벤처 파트와 평타 콤보, 퍼펙트 패링, 퍼펙트 닷지, 스킬, 궁극기, 적 스태거 등 전투 파트를 제작 한 스테이지에 담아 내는 것이 목적이다.

---

## Core Identity

| Aspect | Detail |
| ---- | ---- |
| **Genre** | 3D Action, Boss-Focused Combat  |
| **Platform** | PC (Steam / Itch — 키보드/마우스 + 게임패드) |
| **Player Count** | Single-player |
| **Session Length** | 15분~30분 |
| **Monetization** | None — 학습·검증 프로토타입, 출시 게임 아님 |
| **Estimated Scope** | Small (4~8주, solo) — 프로토타입 검증 빌드 |
| **Comparable Titles** | Stellar Blade, Sekiro: Shadows Die Twice, Furi |

---

## Core Fantasy

플레이어 판타지: **"부드러운공방의 전환- 패링으로 빈틈을 만들고 자연스럽게 공격으로 전환"**

수동적 전투(소울라이크)에서 벗어나, 방어를 잘 할수록 공격권을 더 자주, 많이 가질 수 있다.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| 타격감 |2|스냅·펀치 임팩트 피드백, 시네마틱 라이팅, 게이지 UI 반응 |
| 전투조작감|1|콤보윈도우정확도스 패턴 학습 곡선, 페이즈 2 강도 |
| 탐험요소 | 4| 탐험 있음 |
| 전투완성|3|콤보 시퀀스, 베타 스킬 선택, 패링·회피 비중 결정 |

### Key Dynamics
- 조작학습 → 패링 이후 부드럽게 이어지는 공격 발견(패링 후 이 순간에 공격 할 수 있구나) +
- 보스 패턴 학습 → 반복 시도 → 점진적 깊이 발견 ("이 패턴은 이렇게도 받을 수 있구나")
- 패링·회피 성공 → 카운터 윈도우 → 콤보·베타 폭딜 → 보스 스태거 → 추가 폭딜 윈도우
- Self-imposed mastery challenges (노 데미지 / 시간 단축 / 베타 무사용 / 패링 100%)

### Core Mechanics
1. **평타 콤보** — Light/Heavy 평타 시퀀스 (3종류)
2. **퍼펙트 패링** — 좁은 윈도우, 적 스태거 누적 + mp 충전
3. **퍼펙트 회피** — 회피 윈도우, 슬로우모션 + 회피 반격 연계
4. **MP** — 충전 → 베타 스킬 4종 소비
5. **적 스태거 게이지** — 누적 → 프리딜 타이밍
6. **위험 신호 시스템** — 빨강(연속공격) / 노랑(가드 불가)

## Player Motivation Profile


### Flow State Design

- **첫 시도**: 첫 10분에 보스 1회 시도, 사인 인식 학습, 첫 시도는 높은 확률로 패배
- **게임 방식 학습**: 게이지 UI, 시각·청각·햅틱 임팩트, 보스 그로기 등
- **난이도 학습**: 보스 패턴이 결정적 시퀀스로 학습 가능 + 페이즈 2 진입으로 강도·복잡도 상승
- **공략**: 즉시 재시도 (로딩 ≤ 2초), 패배가 학습으로 전환되는 페이싱

## 디자인 중요점

### 중요점 1: 빠른 조작감
모션간 전환이 빠르게 일어나야 한다.


### 중요점 2: 실력 성장 체감
플레이어의 성장에 따른 쾌감이 크게 증가할 수 있는 구조

### 중요점 3: 부정적 경험 관리
카메라나, 이펙트로 전투 과정이 가려지지 않는 구조

### 중요점 4: 깊이 파는 시스템
새 시스템을 추가하기 전에 기존 시스템의 깊이를 더 판다.

## 비주얼 정책 - 아직 미정


> **One-line rule**: 스텔라블레이드의 사실적 SF 모더니즘을 그대로 — 단일 아레나 + 단일 보스에 응축한다.

### Visual Principles

1. **사실적 PBR 머티리얼이 기본값**
   *Design test*: 머티리얼 결정 시 항상 사실 PBR 우선. 스타일라이즈드/셀셰이딩으로 우회하지 않는다.

2. **시네마틱 키 라이팅 + 강한 림 라이트**
   *Design test*: 라이팅 셋업은 시네마틱 카메라 기준으로 잡는다. 게임플레이 카메라가 시네마틱과 충돌하면 게임플레이를 우선하되 시네마틱 톤 유지.

3. **위험 큐(빨강/노랑) 절대 가독성**
   *Design test*: 환경 색상이 위험 큐와 충돌하면 환경을 양보한다. 빨강/노랑은 화면에서 가장 밝은 단일 색.

### Color Philosophy
어두운 환경 베이스 + 캐릭터는 채도 높은 디테일 + 위험 큐는 화면 최강 색. 시네마틱 톤이지만 게임플레이 가독성이 항상 우선.

## 제작하며 생각할 것

### 조작감, 재미
- **조작감 검증 → 불쾌하지 않고 적절하게**: 패링 윈도우·캔슬·피드백 지연이 정확하지 않으면 전투 경험이 나빠진다.
- **밸런싱, 재미 검증**: 제작자 이외에 다른 사람들에게도 플레이하며 재미 검증

### 에셋 주의점
- **PC, 적·애니메이션 비용 폭증**: 너무 많은 애니메이션을 사용하지 않기

### 우선순위 정하기
- 아트 에셋, 장비 시스템 등 뒤에 미뤄야 할 요소는 미루고 먼저 만들 것 정하기

## 최소 기능 검증 정의

**핵심 목표**: 단일 보스 vs 플레이어의 5~15분 전투가 **공방 연계의 재미**를 만들어내는가.

**최소  기능 검증에서 요구되는 것**:
1. 조작감 구현 (패링의 응답속도와, 캔슬 기능 등)
2. 패링·회피·자원·스킬·스태거 등 전투 시스템 작동
3. 보스 1체 페이즈 1~2 BT의 정상 작동
4. 위험 신호 시스템 가독성 (빨강/노랑/일반)
5. 보스 재도전 기능
6. 1 스테이지 제작하기(레벨, 일반 몬스터, 기믹 등)

**추후에 작업할 것**:
- 다중 보스, 스테이지
- 인벤토리·장비·강화·진행 시스템
- 메타 진행·언락
- 사운드트랙 풀 작곡 (placeholder OK)
- 시네마틱 인트로/아웃트로
