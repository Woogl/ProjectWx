# Project WX 기능 문의사항 정리

> 본 문서는 기존 `기능 문의사항`에 작성된 내용만 기준으로 정리한 개발 전달용 문서입니다.  
> 문의 범위는 **경직 Abort**, **자연스러운 Wait**, **고속 이동 기능** 3가지입니다.

---

## 1. 경직으로 인한 BT Abort 현상

### 문의 배경

`BT_Boss` 샘플 데이터에서 의도와 다르게 Behavior Tree가 중단되는 현상이 있습니다.

### 원하는 동작

| 상황 | 원하는 처리 |
|---|---|
| 패턴 1을 패링한 경우 | Abort되지 않고 다음 공격이 패턴 2로 이어짐 |
| 패턴 1을 스킬로 경직시킨 경우 | Abort되어 현재 패턴이 중단됨 |

### 현재 동작

| 상황 | 현재 처리 |
|---|---|
| 패턴 1을 패링한 경우 | Abort가 발생함 |
| Abort 이후 | Move To 이후 다시 패턴 1을 사용함 |

### 기획 의도

몬스터 패턴은 공격 후 일정 시간의 대기 구간을 가지도록 설계하고자 합니다.  
PC가 피격되거나 패링에 성공한 뒤에는 잠깐의 딜타임이 필요합니다.

다만 패링 성공만으로 BT가 Abort되면, 패턴 흐름이 끊기고 의도한 다음 패턴으로 이어지지 않습니다.  
반대로 스킬로 인한 경직은 강한 개입이므로 현재 상태를 유지하는 것, Abort되는 것이 의도입니다.

### 프로그래머 확인 요청

- 패링 성공과 스킬 경직을 서로 다른 중단 조건으로 분리할 수 있는지 확인이 필요합니다.
- 패링 성공 시에는 현재 패턴 흐름이 유지되고, 시퀀스의 다음 노드로 이어질 수 있어야 합니다.

---

## 2. 자연스러운 Wait 기능

### 문의 배경

패턴 종료 후 잠깐의 Wait 구간에서 적이 가만히 서 있는 상태가 되어 전투 흐름이 어색해 보입니다.

### 원하는 동작

| 상황 | 원하는 처리 |
|---|---|
| 패턴 종료 후 대기 시간 | 적이 PC와 거리를 유지하며 자연스럽게 좌우로 움직임 |
| 딜타임 구간 | 완전히 정지하지 않고, 전투 중인 느낌을 유지함 |

### 현재 동작

| 상황 | 현재 처리 |
|---|---|
| 패턴 후 대기 시간 | 적이 가만히 서 있음 |
| 거리 유지 움직임 | 별도 기능 없음 |

### 기획 의도

레퍼런스 게임에서도 몬스터는 패턴 후 잠깐의 딜타임 동안 완전히 정지하지 않고, 거리를 유지하거나 좌우로 움직이는 경우가 많았습니다.

따라서 대기 시간에도 적이 전투를 이어가고 있다는 느낌을 주기 위해, 단순 Wait이 아니라 거리 유지용 움직임이 포함된 Wait 기능이 필요합니다.

### 프로그래머 확인 요청

- Wait 중 적이 PC를 기준으로 일정 거리를 유지하며 좌우 이동할 수 있는 기능이 가능한지 확인이 필요합니다.
- 이 기능을 BT의 Wait 대체 노드 또는 별도 이동 태스크로 만들 수 있는지 확인이 필요합니다.
- 패턴 후딜레이와 자연스러운 거리 유지 이동을 함께 처리할 수 있는 구조가 필요합니다.

## 3. ANS 고속 이동 기능

### 문의 배경

첫 보스의 추적 패턴과 관련하여, PC가 있는 위치로 빠르게 이동하는 기능이 필요합니다.

### 원하는 동작

| 상황 | 원하는 처리 |
|---|---|
| 추적 패턴 사용 시 | PC가 있는 위치로 빠르게 이동함 |
| 돌진 또는 점프 공격 | 애니메이션의 고정 이동거리만 따르지 않고 목표 위치를 향해 이동함 |

### 현재 동작

| 상황 | 현재 처리 |
|---|---|
| 돌진기 사용 시 | 애니메이션 루트모션의 최대 거리까지만 이동함 |
| PC 위치 추적 | PC가 있는 위치까지 이동하기 어려움 |

### 기획 의도

보스가 멀리 떨어진 PC를 추적하거나, 특정 패턴에서 PC 위치를 향해 빠르게 접근하는 상황을 만들고자 합니다.

현재처럼 루트모션 거리만큼만 이동하면 PC의 실제 위치를 따라가기 어렵기 때문에, 패턴 연출과 실전 기능을 함께 만족시키기 어렵습니다.

### 프로그래머 확인 요청

- ANS를 통해 특정 구간에서 PC 위치를 향해 고속 이동할 수 있는지 확인이 필요합니다.
- 루트모션과 별개로 목표 위치 보정 또는 이동 보조 기능을 넣을 수 있는지 확인이 필요합니다.
- 이동 목표를 “ANS 발동 시점의 PC 위치”로 고정할지, “이동 중 특정 프레임까지 PC를 추적”할지 선택 가능한지 확인이 필요합니다.

## 개발 전달용 요약

| 구분 | 핵심 문제 | 필요한 기능 |
|---|---|---|
| 경직 Abort | 패링 성공까지 Abort되어 패턴 흐름이 끊김 | 패링과 스킬 경직의 Abort 조건 분리 |
| 자연스러운 Wait | 패턴 후 적이 가만히 서 있어 어색함 | Wait 중 거리 유지 및 좌우 이동 기능 |
| 고속 이동 기능 | 루트모션 거리 한계로 PC 위치까지 이동하기 어려움 | ANS 기반 목표 위치 고속 이동 기능 |
