# WX 오픈월드 초반 구간 사양서

> 문서 목적: 기술 사양서. 초반 구간(마을 → 첫 화포건물) 제작에 필요한 시스템을 정리한다.
> 게임 디자인 및 흐름은 별도 문서 `WX_초반구간_개요.md`를 참조한다.
> 세계관은 `WX_scenario_background_intro.md`를 참조한다.

---

## 우선순위 표기 방식

각 항목마다 우선순위를 표기한다. 회의 전/후로 자유롭게 조정한다.

- **상** — 필수. 없으면 초반 구간 자체가 성립되지 않는다.
- **중** — 중요. 있어야 초반 구간의 완성도가 확보된다.
- **하** — 후순위. 없어도 진행 가능하지만 있으면 좋다.
- **?** — 논의 필요. 우선순위 결정 전.

## 1. 프로젝트 컨텍스트 요약

- 초반 구간 크기: 60,000 × 40,000 유닛 (약 600 × 400m)
- 전체 오픈월드 컨셉: 엘든링 참고, 약간 일직선형
- 전체 목표 구조: 오픈월드 전역의 화포 3개 작동 → 최종 적 거점 방어막 파괴 (젤다 야숨 참고)
- 초반 구간 톤: 자연적 현대 시골 (산/풀숲/나무)
- 엔진: 언리얼 (Blueprint 기반 구현 가능성 고려)

## 2. 환경 시스템 요구사항

### 2.1 PCG - 나무 배치

**우선순위:** [ 상 ]

- 절차적 재생성으로 나무 자동 배치
- 배치 밀도/종류/규칙은 지역별로 조정 가능해야 함

### 2.2 PCG - 풀 / 덤불 / 꽃 (잔디 시스템)

**우선순위:** [ 상 ]

- 잔디성 폴리지 절차적 배치
- 지형 머티리얼과 연동되어 자연스러운 분포

### 2.3 PCG - 작은 돌 / 자갈

**우선순위:** [ 상 ]

- 작은 돌, 자갈 계열 절차적 배치

### 2.4 강 / 물 시스템

**우선순위:** [ 하 ]

- 초반 구간에 강/물 표현 필요
- 우선순위는 후순위. 환경/게임플레이 우선 구축 후 진행 가능

### 2.5 지형 머티리얼 페인팅

**우선순위:** [ 상 ]

- 지형에 풀/흙/자갈 등 여러 머티리얼을 붓 툴로 페인팅할 수 있는 시스템
- 지역별로 자연스러운 이질감 표현

### 2.6 길 페인팅

**우선순위:** [ 상 ]

- 플레이어 유도용 흙길 표현
- 지형 페인팅과 별도 취급 (경로 표현 목적이 명확하므로 분리 관리)
- 마을 → 언덕 → 불타는 마을 → 양갈래 → 합류점 → 화포건물 흐름을 따라 배치

### 2.7 스카이 & 라이팅

**우선순위:** [ 하 ]

- **각 지역마다 시간대를 고정한다.**
- 낮/밤 순환 시스템은 필요하지 않다.
- 지역별로 어떤 시간대를 배정할지는 이후 지도 검토와 함께 결정한다.

### 2.8 HLOD (원거리 랜드마크 가시성) (1차 추가)

**우선순위:** [ 중 ]

- World Partition 환경에서 **원거리 랜드마크가 멀리서도 보이도록** HLOD를 세팅한다.
- 핵심 대상:
  - **최종 적 기지**: 초반 구간에서도 맵 끝의 부양 거점이 멀리 보여야 한다. (최종 목표를 시각적으로 인지)
- 원거리 실루엣이 뭉개지지 않게 HLOD 메시 / 드로 디스턴스 조정.

## 3. 게임플레이 시스템 요구사항

### 3.1 화포 발사 시스템 (연출용) — 기획자 BP 직접 구현

**우선순위:** [ 중 ]

- 상호작용키로 인벤토리의 화포 코드를 자동 인증 후 발사 연출로 연결한다.
- 실제 데미지 판정이나 물리적 궤적은 필요 없음.
- 별도 UI 창은 없다. (상호작용 → 자동 인증 → 발사)
- **기획자가 Blueprint로 직접 구현 예정.**

### 3.2 드론발사기 (거점 시스템)

**우선순위:** [ 중 ]

- 어쌔신 크리드 시리즈의 뷰포인트/거점과 유사한 역할
- 요구 동작:
  1. 드론발사기와 상호작용
  2. 오브젝트가 빛나는 연출
  3. 주변 맵이 켜짐 (해당 지역의 안개 걷힘 / 맵 데이터 활성화)
- 상호작용 → 연출 → 맵 활성화가 하나의 흐름으로 연결되어야 함.
- 이 구간에는 합류점 지점에 1개 배치 예정.

### 3.3 월드맵 시스템

**우선순위:** [ 하 ]

- 드론발사기의 "맵을 켠다" 동작이 성립하려면 대상이 되는 월드맵이 필요하다.
- **방향 (1차 추가):** 정교한 월드맵 UI는 만들지 않고, **임시로 '그냥 지도만 뜨는' 최소 형태**로 간다.
- 세부 표현/렌더 수준은 구현 시 조정.

### 3.4 스토리 책 (읽을거리)

**우선순위:** [ 하 ]

- 폐연구소 등에 배치되는 **스토리 책**: 상호작용 시 텍스트가 표시된다.
- 표시는 3.7 대화 다이얼로그 시스템을 재사용한다. (1차 추가)

### 3.5 체크포인트 시스템

**우선순위:** [ 하 ]

- 죽었을 때 부활 지점 지정 로직 필요.
- 사용할 액터(체크포인트 오브젝트 모양) 에셋은 검토 중.

### 3.6 상호작용 오브젝트 (문/버튼/트리거 등)

**우선순위:** [ 중 ]

- 화포건물 진행에 필요한 상호작용 오브젝트 전반. (구체 시스템은 3.8~3.9 참조)
- **변경 (1차 추가):** 오른쪽 길은 밀폐형 던전이 아니라 **야외 보급기지(전투 거점)** 로 확정 → 던전형 상호작용 요소 불필요.
- 화포건물 내부 '소규모 던전'도 3.8(하부 기어 구동계)·3.9(상부 발사/웨이브)로 구체화됨.

### 3.7 대화 다이얼로그 시스템

**우선순위:** [ 중 ]

- 불타는 마을 생존자와의 대화에 사용.
- **(1차 추가)** 시작 지점 **촌장과의 대화**에도 사용. (대화 완료가 첫 목표 마커의 트리거 → 3.11)
- **(1차 추가)** 폐연구소 **스토리 책**(상호작용 시 텍스트 표시)도 이 시스템을 재사용.
- 선택지/분기 없음. 쭉 읽는 방식.
- 표시 형식(하단 말풍선 / 풀스크린 등)은 논의 예정.

### 3.8 화포건물 하부 — 기어 구동계 시스템 (1차 추가)

**우선순위:** [ 중 ]

- 하부에 **기어(구동계 브레이크) 3개** 배치. 각각 상호작용으로 작동.
- **순서 무관** — 3개 전부 작동 시 구동계 연결 → 상부 발사 버튼 활성화.
- 각 기어 작동 시 **연결된 파이프의 머티리얼이 전환**된다. (꺼짐 → 증기 흐르는 가동 상태) 3개 진행도의 시각 피드백.

### 3.9 화포건물 상부 — 발사 시퀀스 & 웨이브 (1차 추가)

**우선순위:** [ 중 ]

- 구동계 활성화 시 **발사 버튼** 활성화.
- **화포 코드로 발사 버튼 무장** (3.1 화포 발사 시스템과 연계).
- 발사 버튼 → 발사 시퀀스 개시 + **적 웨이브 스폰** (3.10).
- 웨이브 격퇴 → **화포 발사 컷신** 재생 (3.12) → 초반 구간 종료.

### 3.10 웨이브 스포너 시스템 (1차 추가)

**우선순위:** [ 중 ]

- 지정 지점/타이밍으로 적 웨이브를 스폰. (화포건물 상부 피날레에 사용)
- **[토론]** 웨이브 구성(적 종류/수/타이밍)을 **기획자가 데이터로 직접 설정** 가능하게 할지. (→ 6. 토론 목록)

### 3.11 퀘스트 / 오브젝티브 마커 시스템 (1차 추가)

**우선순위:** [ 중 ]

- 목표를 플레이어에게 안내하는 시스템. 목표가 계속 추가/갱신되므로 **확장 가능한 구조**로 설계한다.
- 첫 사용 예: **촌장과 대화 완료 → 목표 갱신**
  1. 화면 상단에 목표 스크립트 텍스트 표시 (예: "XX에 가서 XX를 작동시키십시오")
  2. 대상(화포)에 **월드 핑** 표시
- 구성 요소: 목표 등록/해제, 대상별 핑(월드 스페이스 마커), 상단 스크립트 텍스트(데이터화 권장).
- **[토론]** 핑을 **어떤 비주얼/느낌**으로 만들지 플머와 논의. (→ 6. 토론 목록)

### 3.12 컷신 / 시퀀스 재생 (1차 추가)

**우선순위:** [ 하 ]

- 화포 발사 컷신 등 스크립트성 연출 재생. (Level Sequence 등)
- 초반 구간에선 화포 발사 컷신 1건 필요.

## 6. 플머 토론 목록 (1차 추가)

플머와 구현 방식을 협의해야 하는 항목.

1. **오브젝티브 마커 핑의 비주얼/느낌** — 화포 등 목표 대상에 뜨는 월드 핑을 어떤 스타일로 만들지. (3.11)
2. **웨이브 구성의 기획자 직접 설정(데이터화) 가능 여부** — 적 종류/수/타이밍을 데이터로 편집 가능하게 할지. (3.10)
3. **화포 코드의 보관/처리 방식** — 인벤토리에 편입할지, 별도 플래그로 처리할지 등. (3.1 화포 발사 시스템 전제)

## 7. 후속 작업

1. 이 사양서에 우선순위 기재
2. 회의에서 공유 후 논의 필요 사항 결정
3. 결정 결과에 따라 사양서 업데이트
4. 지도와 함께 각 시스템 배치 지점 확정
