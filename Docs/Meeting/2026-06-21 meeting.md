# ✅ 구현 진행 사항 공유

> 기획자 입장에서 체감될 수 있는 게임플레이에 대한 부분만 설명했습니다.

## 1. 기믹 상호작용 개선

* 상호작용 UI의 출력 위치를 원신처럼 캐릭터 옆에 나오게 했습니다.
* 여러개의 상호작용 대상이 겹쳐있을 때 대상을 마우스 휠로 선택할 수 있게 개선했습니다.
* 선택된 상호작용 대상에 외곽선 추가했습니다. 

## 2. 기믹에 State Tree 적용

* 기믹의 내부 구조를 State Tree 기반으로 전환하고 있습니다.
* 전환 작업이 진행되는 동안 일부 Gimmick에서 일시적으로 버그가 발생할 수 있으니 참고 부탁드립니다.

  * 완료: `BP_Door`
  * 진행 중: `BP_Elevator`, `BP_TreasureChest`

# 💬 논의 주제

## 1. 프로젝트 방향성

* 프로젝트를 시작할 때 말씀드렸듯이, 본 프로젝트는 출시보다는 학습을 목적으로 하는 사이드 프로젝트입니다.
* 저는 창영님과 민석님께서 이 프로젝트를 통해 많은 것을 배우고, 게임 개발에 대한 성취감도 느끼시길 기대합니디.
* 저의 경우에는 회사에서 못해본 플밍 구현이나, 신기술 도입에 큰 가치를 두고 있습니다.
* 다만, 여러분이 저에게 세부적인 업무 지시를 내리는 리더 역할을 기대하거나, 제 지시가 있을 때까지 수동적으로 작업하는 것은 지양했으면 합니다. 
* 이유는 제 업무 분야(플밍)을 벗어나는 부분은 제가 지시할 수 있는 영역이 아니며, 사이드 프로젝트에서 플밍 구현 작업만으로도 시간이 모자르기 때문입니다.
* 자율적인 분위기 속에서 모두에게 이익이 될 수 있도록 협조해주신다면 감사하겠습니다.

## 2. 주간 회의 시간에 학습 브리핑 시간 제안

* 프로젝트 시작 전과 현재를 비교했을 때, 두 분의 성장 속도가 기대보다 조금 더디게 느껴지는 부분이 있습니다.
* 이에 대해 제가 생각한 원인과 개선 방향을 공유드리고자 합니다.

### 원인 1. 순수 작업 시간 부족

* 현재까지의 작업 결과물만 보았을 때, 실질적인 작업량이 다소 적어 보입니다.
* 본업무 외적인 부분에 시간이 많이 소요되고 있거나, 실제 작업에 투입되는 순수 시간(낭비되는 시간 제외)이 충분하지 않은 상황일 수 있다고 생각합니다.

### 원인 2. 학습 방향성 부재

* 사용하는 도구나 기본 개념에 대한 이해가 부족한 상태에서 작업을 진행하는 경우가 있는 것으로 보입니다.
* 기본 개념을 먼저 숙지하고, 작업 과정에서 “왜 이 도구를 사용하는지”, “이 방식이 어떤 장단점을 가지는지”를 함께 고민해야 실무자로서 더 빠르게 성장할 수 있다고 생각합니다.
* 이러한 과정을 통해 스스로의 이해도를 점검하는 메타인지도 함께 강화될 수 있습니다.

### 개선 방향. 학습 자료 브리핑

* 평소에 `Today I Learned`처럼 학습한 내용을 간단히 기록해두는 것을 추천합니다.
* 이를 바탕으로 **주간 회의 때마다 서로 10분씩 브리핑하는 시간**을 가지는 것을 제안드려봅니다.
* 적합한 공식 도큐먼트나 학습 자료를 Notebook LM에 넣으면 브리핑 자료를 더 효율적으로 만들 수 있을 것으로 기대합니다.
* 저 또한 함께 참여하여, 매주 기획자 눈높이에 맞는 주제와 자료를 준비해 공유드리겠습니다.
* 예시 주제는 다음과 같습니다.
  1. 스텔라 블레이드의 전투 자원 분석
  2. UE에서 애니메이션 시퀀스와 애니메이션 몽타주의 차이점
  3. 레벨 디자인용 랜드스케이프를 생성하는 다양한 방법과 도구
  4. State Machine, Behavior Tree, State Tree의 장단점 비교
