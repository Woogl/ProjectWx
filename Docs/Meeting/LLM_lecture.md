# LLM 기본 개념 잡기

## 1. 등장 배경

컴퓨터에게 일을 시키는 방식이 이렇게 진화해 왔다.

- **전통적 프로그래밍** : 사람이 규칙을 일일이 만든다. 규칙으로 딱 떨어지지 않는 문제(예: "이 사진에 고양이가 있어?")에 약하고, 코딩 문법 학습에 진입 장벽이 있다.
- **Machine Learning (ML)** : 사람이 규칙을 짜는 대신, 데이터에서 규칙(패턴)을 스스로 찾아낸다. 예시를 잔뜩 보여주면 알아서 학습한다.
- **Large Language Model (LLM)** : 그 학습을 자연어에 대해 대규모로 한 것. 단어를 기계적으로 매칭하는 게 아니라 문장의 흐름과 맥락까지 파악한다. 

> "사람이 규칙을 만든다" → "데이터에서 규칙을 도출한다" → "자연어를 이해한다"로 발전!

## 2. 동작 방식

**앞의 말을 보고, 다음에 올 가장 그럴듯한 단어를 확률로 골라 이어붙이는 것.** 이걸 계속 반복하면 문장이 되고 문단이 된다.

- "오늘 아침엔 커피를 ___" → '마셨다'가 확률이 높다.
- 이 "다음 단어 맞히기"를 방대한 글로 훈련하다 보니, 번역·요약·질문답변까지 다 하게 된 것.

이 예측을 잘하기 위해 안에서 벌어지는 과정은 다음과 같다.

- **토큰화** : 문장을 작은 조각(Token)으로 쪼갠다. 
- **임베딩** : 각 조각을 "의미 좌표(Vector)"로 바꾼다. 뜻이 비슷한 말은 좌표상 가까이 놓인다. **단어를 지도 위의 한 점으로 찍는다**고 생각하면 편하다.
- **트랜스포머** : 다음 과정을 담은 구조로, 문장을 앞에서부터 차례로가 아니라 병렬로 처리한다. (multi layer)
  - **어텐션** : 주변 단어들을 보고 어디에 집중할지 가중치(Weight)에 따라 벡터를 조정한다. 그래서 '눈'이 옆의 '내린다'를 참고해 눈(雪)이라는 맥락을 얻는다.
  - **피드포워드** : 어텐션이 맥락을 채워넣은 벡터를 받아, 학습해둔 지식 중 맞는 것을 꺼내 표현에 더한다.

> 즉 LLM 이란 [문장을 조각내서] → [의미 좌표로 바꾸고] → [서로 맥락을 따져] → [다음 단어 예측] 하는 행위를 초고속·초대량으로 하는 것!

## 3. 한계점

"다음 단어를 그럴듯하게 잇는" 방식이라서 본질적인 한계가 존재한다.

- **환각 (Hallucination)** : 가끔 자신 있게 틀린 답을 지어낸다. LLM은 사실을 "아는" 게 아니라 "그럴듯한 말"을 만들 뿐이라, 틀린 정보도 매끄럽게 술술 나온다. → 중요한 건 반드시 사실 확인.
- **비결정적** : 똑같이 물어도 답이 매번 달라진다. 확률로 다음 단어를 고르는 방식이라 매번 주사위를 살짝 다르게 굴리는 셈. 
- **맥락에 이끌림** : "핑크 코끼리를 생각하지 마"라고 하면 오히려 코끼리가 떠오르듯, LLM은 주어진 맥락·전제에 강하게 이끌린다. 잘못된 전제로 물으면 그걸 그대로 받아들이고, 사용자의 프레임에 맞장구치기 쉽다.

> LLM은 유능하지만, 검증은 사람의 몫이다!

## 4. 활용 방법

같은 AI라도 어떻게 쓰느냐에 따라 결과가 크게 차이난다.

- **프롬프트 엔지니어링** : 한 번의 질문을 잘하는 기술. 상황에 대한 맥락을 주고, 구체적으로 지시하고, 원하는 결과물 예시를 준다. 
- **하네스 엔지니어링** : AI가 잘 일할 수 있는 환경을 갖추는 기술. 역할을 부여하고, 참고 자료(AGENT.md)를 주고, 자주 쓰는 지시는 메뉴얼화(Skills)한다.
- **MCP (Model Context Protocol)** : AI가 외부 도구를 쓸 수 있도록 연결하는 통신 프로토콜. 대화를 넘어 실제 행동까지 한다.
