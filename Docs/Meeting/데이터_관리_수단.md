# 언리얼 데이터 관리 수단 — 기획자용

> **로직은 프로그래머가 만들고, 값은 기획자가 채운다.**

## 0. 왜 데이터로 빼는가

수치가 코드 안에 하드코딩되어 있으면, 하나 바꿀 때마다 프로그래머와 빌드가 필요해서 테스트 iteration이 느리다.

이러한 수치 같은 **데이터를 코드에서 분리**해두면 기획자가 직접, 빌드 없이, 대량으로, 즉시 조정할 수 있다.

이러한 방법론을 **데이터 주도 개발(Data-Driven Development)**이라고 부른다.

## 1. 언리얼 엔진의 데이터 컨테이너

데이터는 형식(Type)을 갖춘 값(Value)을 말한다.

언리얼 엔진에서는 데이터 관리를 위해 다음과 같이 다양한 컨테이너를 제공한다.

- **Data Table** — 같은 형식의 항목을 표로
- **Curve Table** — 축을 따라 변하는 곡선 값
- **Data Asset** — 애셋 참조·복합 구조를 담는 낱개 파일
- **Blueprint Variables** — 블루프린트 클래스에 포함된 값을 직접 편집
- **Chooser Table** — 조건을 보고 후보 중 하나를 선택

## 2. Data Table

### 개념

엑셀 같은 표.

**열 = 형식(스키마), 행 = 개별 데이터**이며, 각 행은 이름(RowName)으로 찾는다.

csv 나 json 형식으로 export 및 import 할 수 있다.

> 에셋 참조에는 적합하지 않다.
> 에셋 경로(Soft Ptr)로 참조하기 때문에 가독성이 나쁘고, 에셋 위치를 옮기면 조용히 깨지기 때문이다.  

### 예시

캐릭터 스탯, 대미지 계수, 상점 판매 아이템 목록 등.

같은 형식의 항목이 많을 때, 대량 편집이 필요할 때 유용하다.

## 3. Curve Table

### 개념

Data Table과 비슷하나, 한 칸에 단일 값이 아니라 **X축에 따라 변하는 float 곡선**을 담는다.

보간(Interpolation) 타입도 설정 가능: Constant / Linear / Cubic

Data Table과 마찬가지로 csv 나 json 형식으로 export 및 import 가능.

### 예시

레벨업 요구 경험치, 거리별 대미지 감쇄 등.

"단일 값이 아니라 변화량 추이"가 필요할 때 유용하다.

## 4. Data Asset

### 개념

하나의 데이터를 담은 애셋 파일 하나다.

표의 한 행(Row) 마다 독립된 파일로 저장하는 것이다. (분산 관리)

> 대량의 데이터를 일괄 편집해야할 때는 사용성이 좋지 않다.
> 대신에 여러명이 각자 에셋을 나눠서 다중 편집할 때는 좋다.

### 예시

캐릭터 ABS, 아이템 정의 등.

Data Table 한 칸엔 담기 어려운 것을 담을 때 유용하다.
* 애셋 참조가 많은 데이터 (메시, 아이콘, 사운드)
* 항목마다 개성이 강해서 테이블 항목으로 규격을 통일하기 어려운 데이터
* 테이블 2차원으로 평탄화하기 어려운 데이터 (중첩 구조, 동적 배열 등)

## 5. Blueprint Variable

### 개념

앞의 셋은 클래스에서 데이터만 분리해서 담은 컨테이너다.

하지만 굳이 클래스를 분리하지 않고, 멤버 데이터를 직접 편집할 수도 있다.

프로그래머가 블루프린트에서 "노출(Editable)"한 변수만 기획자가 편집할 수 있으며, 블루프린트 컴파일 시 반영된다.

> BP도 클래스의 일종이다.
> 클래스 = 멤버 변수(데이터) + 멤버 함수(로직)

### 예시

캐릭터 BP의 외형 정보, 투사체 BP의 이동 속도 등

## 6. Chooser Table

### 개념

데이터만 있는 표가 아닌, "어떤 데이터를 쓸 지 선택하는 규칙까지 들어있는 표"다. 

if/else 분기를 코드가 아니라 데이터로 옮긴 것이다.

### 예시

절차적 애니메이션 선택, BGM 선택

상황(컨텍스트)에 따라 다른 데이터를 골라야 할 때 쓴다.

## 7. 정리

데이터의 성격에 따라 적합한 데이터 컨테이너를 선택하면 된다.

실무에서는 여러 수단이 함께 조합해서 쓰는 경우도 많다.

예를 들어, Data Table을 통해서 Data Asset을 참조해서 쓰기도 한다.

| 도구 | 한마디 | 우리 게임에서 예시 |
| --- | --- | --- |
| Data Table | 형식이 정해진 표 | 캐릭터 스탯 |
| Curve Table | 곡선 형태의 표 | 레벨업 요구 경험치 |
| Data Asset | 개성 강한 낱개 파일 | 아이템 정의 |
| Blueprint Variable | 블루프린트 클래스의 변수를 직접 편집 | 캐릭터 외형 |
| Chooser Table | 데이터 선택 규칙이 포함된 표 | 상황별 BGM |

## 부록 — 다른 데이터 (심화과정)

기획자가 직접 수정할 일은 드물지만, 이런 것들이 있다는 것만 알고 있으면 좋다.

- **Config** : 설정(프로젝트 세팅, 플러그인 세팅, 빌드 세팅, 클래스 리디렉션 등)을 관리하는 텍스트 파일(.ini).
- **Save Game** : 런타임 게임 진행 상태를 로컬 디바이스에 저장. 로드 후 값을 복원해서 사용 가능. 
- **Server DB** : 유저의 계정이나 결제 등 중요한 정보를 외부 데이터베이스 서버(MySQL)에 저장.

> 더 궁금하면 프로그래머에게 물어보면 된다.
