# 언리얼 데이터 관리 수단 — 기획자용

> 대상: 기획자/디자이너. 코드 없이 "이게 뭔지 → 언제 쓰는지 → 에디터에서 어떻게 채우는지"에 집중한다.

관통하는 원칙은 하나다.

> **동작은 프로그래머가 만들고, 값은 기획자가 채운다.**

## 0. 왜 데이터로 빼는가

수치가 코드 안에 박혀 있으면, 하나 바꿀 때마다 프로그래머와 빌드가 필요해서 반복(iteration)이 느리다. 그 수치를 **데이터로 분리**해두면 기획자가 직접, 빌드 없이, 대량으로, 즉시 조정할 수 있다.

오늘 배울 수단은 크게 두 부류다.

- **저장** : Data Table · Curve Table · Data Asset · 블루프린트 기본값
- **선택** : Chooser Table

> 데이터를 "어디에 담을지"가 저장, 담아둔 것 중 "무엇을 쓸지"가 선택이다.

## 1. Data Table — 가장 많이 쓰는 "표"

### 개념

엑셀 같은 표다. **열 = 정해진 항목 형식(스키마), 행 = 개별 데이터**이며, 각 행은 이름(RowName)으로 찾는다.

### 언제 쓰나

**같은 형식의 항목이 많을 때** 쓴다. 무기 목록, 몬스터 스펙, 대미지 계수, 대사 테이블, 상점 목록 등. "엑셀 한 장에 정리할 수 있겠다" 싶으면 Data Table이다.

### 사용법

1. 프로그래머가 먼저 **Row 구조체(열 형식)**를 정의한다.
2. 우클릭 → Miscellaneous → **Data Table** 생성, Row 구조체를 선택한다.
3. 행을 추가하고 RowName을 지정한 뒤 각 칸의 값을 입력한다.
4. 엑셀/구글시트로 관리하다가 **CSV로 내보내 Reimport**하면 표 전체를 한 번에 갱신할 수 있다.

> 열(스키마)을 바꾸는 건 프로그래머, 값을 채우는 건 기획자의 몫이다.

**예시 — 무기 테이블**

| RowName | 대미지 | 사거리 | 아이콘 | 설명 |
| --- | --- | --- | --- | --- |
| Sword_01 | 25 | 150 | (아이콘) | 기본 검 |
| Bow_01 | 15 | 800 | (아이콘) | 기본 활 |

## 2. Curve Table — 값이 "곡선"일 때

### 개념

Data Table의 형제다. 한 칸에 단일 값이 아니라 **X축에 따라 변하는 곡선**을 담는다.

### 언제 & 사용법

레벨별 경험치, 성장 곡선, 시간에 따른 감소처럼 "단일 값이 아니라 추이"가 필요할 때 쓴다. Curve 애셋 또는 Curve Table을 만들고 **커브 에디터에서 점(키)을 찍어 곡선을 조정**한다. CSV 임포트도 된다.

> 한 칸이 값이면 Data Table, 한 칸이 곡선이면 Curve Table.

## 3. Data Asset — 개성 있는 "낱개 파일"

### 개념

데이터를 담은 **애셋 파일 하나**다. 표의 한 행이 아니라 독립된 파일이다.

### Data Table과 뭐가 다른가

Data Table 한 칸엔 담기 어려운 것을 담는다. **메시·아이콘·사운드 같은 애셋 참조, 배열, 중첩 구조** 등. 즉 **항목 하나하나가 개성이 강하고 여러 요소를 묶어야 할 때** 쓴다.

> Data Table이 "명단"이라면, Data Asset은 "개인 프로필 카드"다.

### 언제 쓰나

스킬 정의, 캐릭터/적 프리셋, 복잡한 아이템 정의처럼 비주얼·사운드·능력 참조가 얽힌 데이터에 적합하다.

### 사용법

1. 프로그래머가 Data Asset 클래스(필드)를 정의한다.
2. 우클릭 → Miscellaneous → **Data Asset**, 클래스를 선택한다.
3. **디테일 패널**에서 값을 입력하고, 다른 애셋을 드래그해 연결한다.

## 4. 블루프린트 기본값 — 로직 애셋에 직접 얹는 데이터

### 개념

앞의 셋이 데이터를 **별도 통(표·애셋)**에 담았다면, 이번엔 반대로 **그 기능을 실행하는 BP 자신**에 값을 얹는다. 예를 들어 `GA_Dash`(대시 능력 BP) 안에 "대시 거리 · 쿨타임 · 재생 몽타주" 변수가 있고, 그걸 그 BP에서 바로 편집한다.

> BP는 클래스이므로, 멤버 변수와 멤버 함수를 가진다. 이 중에서 멤버 변수에 대한 편집이 바로 이것.
> 프로그래머가 **"노출(Editable)"한 변수만** 기획자가 만질 수 있다.

### Class Defaults — 어디서 바꾸나

BP를 열고 상단 **Class Defaults** 버튼(또는 변수의 기본값 칸)에서 편집한다. 여기서 바꾼 값은 **이 BP를 쓰는 모든 경우의 기본값**이 된다. GameplayAbility에서 자주 만지는 값은 쿨타임/코스트, 대미지 계수·넉백 세기, 재생할 몽타주, 부여·차단할 게임플레이 태그 등이다.

### 세 계층 — 어디서 바꾸느냐가 다르다

기획자가 꼭 구분해야 하는 지점이다.

| 어디서 바꾸나 | 영향 범위 |
| --- | --- |
| **Class Defaults** | 이 BP 전체(모든 사용처) |
| **자식 BP** | 원본을 물려받은 변형본만 (예: `GA_Dash` → `GA_Dash_Boss`) |
| **레벨에 배치된 인스턴스** | 그 배치된 하나만 |

값을 바꾸면 옆에 **노란 되돌리기 화살표**가 뜬다. 누르면 부모(기본)값으로 복귀하며, "내가 이 값을 덮어썼다"는 신호다.

### 언제 BP 기본값 vs 별도 데이터통

- **BP 기본값이 낫다** : 값이 그 능력/액터에 **1:1로 밀착**되고 개수가 적을 때. "이 대시 능력의 쿨타임"처럼.
- **Data Table이 낫다** : 여러 유사 항목을 **한 표에서 나란히 밸런싱**하거나 엑셀로 왕복할 때.
- **실무에선 섞어 쓴다** : BP엔 *"어떤 데이터를 쓸지"*만 지정하고, 실제 수치는 Data Table에 둔다. 예를 들어 능력 BP는 참조할 대미지 행 이름만 가리키고, 대미지 숫자는 대미지 테이블에서 관리하면 밸런싱을 표에서 한 번에 할 수 있다.

> BP 기본값을 바꾸고 저장하면 **`.uasset` 자체가 바뀐다**. 다른 사람 작업과 충돌날 수 있는 버전관리 대상이다. (우리 프로젝트는 저장 시 스냅샷이 자동 갱신되어 변경 추적은 된다.)

## 5. Chooser Table — "저장"이 아니라 "선택"

### 개념

지금까지가 *"데이터를 어디에 담나"*였다면, Chooser는 *"그 중 무엇을 쓸지 상황을 보고 골라주는 규칙 표"*다. if/else 분기를 코드가 아니라 데이터로 옮긴 것이다.

### 언제 & 사용법

상황(입력·컨텍스트)에 따라 **다른 데이터/애셋/애니메이션을 골라야** 할 때 쓴다. Chooser 애셋을 만들고 입력(컨텍스트)을 정의한 뒤, **각 행 = 조건 + 결과**로 채운다. 위에서부터 첫 매칭을 채택한다.

**우리 프로젝트 예시** — BGM 선택. "전투 중인가 / 지역이 어디인가"를 보고 곡을 고른다.

> 데이터는 Table·Asset에 저장하고, 그 중 무엇을 쓸지는 Chooser가 결정한다.

## 6. 정리 — 언제 뭘 쓰나

### 대표적인 사용 예시

정답이 하나로 딱 떨어지진 않는다. 실무에서 각 수단이 흔히 쓰이는 상황을 예시로 모았다.

- **Data Table** — 무기·방어구 목록, 몬스터 스탯표, 대미지 계수, 상점 판매 목록, 대사/자막 테이블처럼 같은 형식이 줄줄이 반복되는 데이터.
- **Curve Table** — 레벨별 요구 경험치, 시간에 따른 버프 감쇠, 거리별 대미지 감소처럼 값이 축을 따라 변하는 데이터.
- **Data Asset** — 스킬 하나의 정의, 적 캐릭터 프리셋, 무기 스킨 세트처럼 애셋 참조와 여러 요소가 얽힌 개성 강한 데이터.
- **Blueprint Variable** — 특정 능력의 쿨타임·몽타주, 이 문 기믹의 열림 속도처럼 그 BP·액터 하나에만 붙는 소수의 값.
- **Chooser Table** — 상황별 BGM, 무기 종류별 피격 리액션, 지역별 앰비언트처럼 조건을 보고 후보 중 하나를 고르는 경우.

실제로는 한 컨텐츠에 여러 수단이 함께 쓰이는 경우가 많다. 예를 들어 적 캐릭터 하나를 만들 때 — 기본 스탯은 Data Table, 외형·사운드 묶음은 Data Asset, 개별 능력의 쿨타임은 그 능력 BP의 기본값, 전투 BGM은 Chooser로 고르는 식이다.

### 비교표

| 도구 | 한마디 | 우리 게임에서 예시 |
| --- | --- | --- |
| Data Table | 같은 형식 대량 표 | 캐릭터 별 스탯 수치 |
| Curve Table | 값의 곡선 | 레벨업 경험치 (미구현) |
| Data Asset | 개성 강한 낱개 파일 | 아이템 정의 |
| 블루프린트 기본값 | 로직 애셋에 직접 얹은 값 | 어빌리티의 아이콘 |
| Chooser Table | 조건으로 선택 | 상황별 BGM |

## 부록 — 다른 데이터 (심화과정)

저장한 데이터는 결국 로딩·저장·설정 계층으로 흘러간다. 기획자가 지금 몰라도 되지만, 이런 것들이 있다는 것만 알아두면 좋다.

- **Config (.ini)** : 프로젝트 전역 설정(프로젝트 이름, 입력, 애셋 규칙 등)을 관리하는 텍스트 파일.
- **Data Registry / Asset Manager** : 흩어진 데이터를 통합 조회하고 필요할 때 로드하는 계층.
- **Save Game** : 진행도·인벤토리 등 런타임 저장.
- **GameUserSettings** : 해상도·볼륨 등 플레이어 환경 설정.

> 더 궁금하면 프로그래머에게 물어보면 된다.
