# 어빌리티 시스템 규칙

기획자를 대상으로 UE GAS(Gameplay Ability System)의 주요 개념을 설명합니다.

프로젝트 WX를 위해 커스텀하게 개발된 규칙이나 설계 원칙에 대해서도 설명합니다.

## 1. Gameplay Ability System Framework (UE 순정)

### 1-1. 어빌리티 정의

캐릭터가 실행할 수 있는 액션(행동)입니다.

일반적인 예시로는 "스킬", "공격", "소비형 아이템 사용" 등이 있습니다.

대부분의 게임 프로젝트에서 어빌리티 에셋의 Prefix로 `GA_`를 사용하며, 캐릭터별 AbilitySet(`ABS_`)를 통해 관리합니다.

### 1-2. 어빌리티의 특징

Gameplay Tag로 서로 다른 어빌리티 간의 차단/캔슬 관계를 데이터 주도적으로 설정합니다.

이를 사용하면 누구나 각 어빌리티의 발동 규칙을 만들 수 있습니다.

| Gameplay Tag | 용도 설명 |
| -- | -- |
| 어빌리티 태그 | 이 어빌리티를 대표하는 에셋 태그 (일종의 ID, 식별자) |
| 활성화 소유 태그 | 이 어빌리티가 실행되는 동안 캐릭터에게 부여되는 태그 |
| 태그로 어빌리티 캔슬 | 이 어빌리티를 발동할 때 이미 발동 중인 어빌리티를 캔슬시킴 |
| 태그로 어빌리티 차단 | 이 어빌리티 발동 중에 다른 어빌리티의 발동을 막음 |

## 2. 프로젝트 WX의 상황

### 2-1. 실시간 액션 게임

WX의 전투는 실시간입니다.

캐릭터가 사용할 수 있는 어빌리티와 수단 방법이 다양합니다.

따라서 여러가지 어빌리티 간의 상호작용이나, 복수의 효과가 중첩되는 상황까지 고려해서 설계해야합니다.

### 2-2. 설계 원칙 (컨텐츠 자유도 vs. 시스템 규칙)

저는 개별적인 컨텐츠(어빌리티)보다 시스템(전투 규칙)이 더 중요하다고 생각합니다.

어빌리티 태그를 누구나 자유롭게 수정하게 되면, 게임을 구성하는 전투 시스템 규칙이 파괴될 수 있습니다.

* 특정 어빌리티만의 예외 규칙이 추가되거나
* 특정 타이밍에서만 규칙을 우회하거나
* 특정 캐릭터에게만 적용되는 규칙이 생기거나

따라서 어빌리티 태그는 전투 시스템 규칙에 포함되는 것으로 간주하여, 기획자가 커스터마이징하는 것을 허용하지 않기로 결정했습니다.

시스템 규칙은 데이터 차원에서 자유롭게 변경되면 안되고, 코드 차원에서 신중하게 관리되어야 합니다.

### 2-4. 어빌리티 그룹 규칙

위 표의 어빌리티들 간의 유사성이 높은 공통 요소를 찾아서 3개의 그룹으로 분류했습니다.

| 그룹 | 해당되는 어빌리티 | 공통점 | 규칙 |
| -- | -- | -- | -- |
| **Indepenent** |  패시브, 달리기, 락온<br/>(12 ~ 14) | 애니메이션이 없음<br/>시스템적인 성격이 강함<br/>타 어빌리티와 독립적 | **다른 어빌리티를 캔슬하거나, 차단하지 않는다.** |
| **Exclusive** | 평타, 회피, 스킬, 궁극기, 가드, 아이템 소비, 앞잡, 뒤잡, 패턴<br/>(1 ~ 8) | 애니메이션 슬롯을 점유<br/>사용자가 원할 때 키 입력해서 발동 | **Exclusive 그룹끼리는 중복 발동 안되게 차단한다.** |
| **Reaction** | 피격 반응, 사망, 그로기<br/>(9 ~ 11) | 외부 요인에 의해 강제 발동됨 | **Exclusive 그룹을 캔슬한다.** |

앞으로 추가될 신규 어빌리티를 생각했을 때에도, 위 3가지 그룹에 해당되지 않는 케이스는 없을 것으로 예상됩니다. 

**※ 예외적으로 처리하는 부분**
- 플레이어 평타에 의한 피격 반응(Reaction 그룹)은 적 패턴(Exclusive 그룹)을 캔슬시키지 않습니다. 
- 적 패턴이 너무 손쉽게 캔슬되어서 전투가 재미없어지는 것을 막기 위한 예외입니다.

### 2-5. 콤보 규칙

일부 어빌리티는 여러 개의 애니메이션 몽타주를 지원합니다.

이러한 어빌리티에서는 `ANS_ConmboWindow` 구간 동안 다시 발동 입력을 하면 다음 콤보 애니메이션 몽타주를 재생합니다.

**※ 서로 다른 어빌리티 간의 연계는 개발하지 않습니다.**
* Exclusive 어빌리티 그룹의 발동 규칙과 정면 충돌합니다.
* 어빌리티간의 종속성이 발생합니다.
* 단방향 콤보 그래프 방식은 기획 공수와 개발 공수 모두 지나치게 큽니다. 

### 2-6. 후딜레이 캔슬 규칙

Exclusive 그룹에 해당되는 어빌리티는 기본적으로 발동이 끝날 때까지 다른 Exclusive 어빌리티를 발동하지 못합니다.

하지만 `AN_StartRecovery` 이후 구간에는 다른 모든 Exclusive 어빌리티를 발동할 수 있게 됩니다.
